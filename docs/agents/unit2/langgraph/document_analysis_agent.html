ドキュメント分析グラフ

Alfred でございます。Mr. Wayne の信頼を得ている執事として、書類に関する様々なご依頼にどう対応しているかを、ここに記しておきました。ご主人が……夜の活動に出かけている間、書類やトレーニングの予定、栄養計画をきちんと分析し、整理しておくのが私の役目です。

出かける前に、彼はその週のトレーニングプログラムを記したメモを残していきました。そこで私は、明日の食事の メニュー を考える責任を引き受けることにしました。

今後このようなことがあった時の為に、LangGraph を使って Mr. Wayne のニーズに応えるドキュメント分析システムを作りましょう。このシステムでは次のことが出来ます。

  1. 画像ドキュメントを処理する
  2. 視覚言語モデル（Vision Language Model）を使ってテキストを抽出する
  3. 必要に応じて計算を行う（通常のツールの使い方を示す為）
  4. 内容を分析し、簡潔な要約を提供する
  5. ドキュメントに関連する具体的な指示を実行する

執事のワークフロー

構築するワークフローは、次の構造化されたスキーマに従います。

環境のセットアップ

%pip install langgraph langchain_openai langchain_core

インポートは次の通りです。

import base64
from typing import List, TypedDict, Annotated, Optional
from langchain_openai import ChatOpenAI
from langchain_core.messages import AnyMessage, SystemMessage, HumanMessage
from langgraph.graph.message import add_messages
from langgraph.graph import START, StateGraph
from langgraph.prebuilt import ToolNode, tools_condition
from IPython.display import Image, display

エージェントの State を定義する

この State は、これまで見てきたものより少し複雑です。 AnyMessage は LangChain でメッセージを表すクラスです。一方、add_messages は、State 内のメッセージを新しい値で上書きするのではなく、既存のメッセージに新しいメッセージを追加する為の演算子です。

これは LangGraph で登場する新しい概念です。State に演算子を指定することで、State の値を更新する際に、既存の値と新しい値をどのように組み合わせるかを定義出来ます。

class AgentState(TypedDict):
    # 提供されたドキュメント
    input_file: Optional[str]  # ファイルパス（PDF/PNG）を含みます
    messages: Annotated[list[AnyMessage], add_messages]

ツールの準備

vision_llm = ChatOpenAI(model="gpt-4o")

def extract_text(img_path: str) -> str:
    """
    Extract text from an image file using a multimodal model.

    Master Wayne often leaves notes with his training regimen or meal plans.
    This allows me to properly analyze the contents.
    """
    all_text = ""
    try:
        # 画像を読み取り、base64 でエンコードします
        with open(img_path, "rb") as image_file:
            image_bytes = image_file.read()

        image_base64 = base64.b64encode(image_bytes).decode("utf-8")

        # base64 の画像データを含むプロンプトを用意します
        message = [
            HumanMessage(
                content=[
                    {
                        "type": "text",
                        "text": (
                            "Extract all the text from this image. "
                            "Return only the extracted text, no explanations."
                        ),
                    },
                    {
                        "type": "image_url",
                        "image_url": {
                            "url": f"data:image/png;base64,{image_base64}"
                        },
                    },
                ]
            )
        ]

        # ビジョン対応モデルを呼び出します
        response = vision_llm.invoke(message)

        # 抽出したテキストを追加します
        all_text += response.content + "\n\n"

        return all_text.strip()
    except Exception as e:
        # 執事らしく、エラーは穏やかに処理します
        error_msg = f"テキストの抽出中にエラーが発生しました：{str(e)}"
        print(error_msg)
        return ""

def divide(a: int, b: int) -> float:
    """Divide a and b - for Master Wayne's occasional calculations."""
    return a / b

# 執事にツールを持たせます
tools = [
    divide,
    extract_text
]

llm = ChatOpenAI(model="gpt-4o")
llm_with_tools = llm.bind_tools(tools, parallel_tool_calls=False)

（ツール説明とプロンプトの訳：extract_text の docstring は「マルチモーダルモデルを使って、画像ファイルからテキストを抽出します。Master Wayne は、トレーニングの予定や食事計画のメモを残すことがよくあります。これにより、内容を適切に分析出来ます」です。画像への指示文は「この画像から全てのテキストを抽出してください。抽出したテキストだけを返し、説明は付けないでください」です。divide の docstring は「a を b で割ります。Master Wayne の時々の計算の為です」です）

ノード

def assistant(state: AgentState):
    # システムメッセージ
    textual_description_of_tool="""
extract_text(img_path: str) -> str:
    Extract text from an image file using a multimodal model.

    Args:
        img_path: A local image file path (strings).

    Returns:
        A single string containing the concatenated text extracted from each image.
divide(a: int, b: int) -> float:
    Divide a and b
"""
    image=state["input_file"]
    sys_msg = SystemMessage(content=f"You are a helpful butler named Alfred that serves Mr. Wayne and Batman. You can analyse documents and run computations with provided tools:\n{textual_description_of_tool} \n You have access to some optional images. Currently the loaded image is: {image}")

    return {
        "messages": [llm_with_tools.invoke([sys_msg] + state["messages"])],
        "input_file": state["input_file"]
    }

（システムプロンプトの訳：あなたは Mr. Wayne と Batman に仕える、親切な執事 Alfred です。提供されたツールを使って、ドキュメントの分析と計算の実行が出来ます。ツールの説明（extract_text と divide の仕様。前のコードブロックの訳を参照）が続き、任意の画像にもアクセス出来ることと、現在読み込まれている画像のパスが示されます）

ReAct パターン：Mr. Wayne をどのようにお手伝いするか

このエージェントのアプローチについて説明します。このエージェントは、ReAct パターン（Reason-Act-Observe）として知られる方式に従います。

  1. Reason：彼のドキュメントとリクエストについて推論します
  2. Act：適切なツールを使って行動します
  3. Observe：結果を観察します
  4. Repeat：彼のニーズに完全に対処出来るまで、必要に応じて繰り返します

これは、LangGraph を使ったエージェントのシンプルな実装です。

# グラフ
builder = StateGraph(AgentState)

# ノードを定義します: これらが処理を行います
builder.add_node("assistant", assistant)
builder.add_node("tools", ToolNode(tools))

# エッジを定義します: これらが制御フローの動きを決めます
builder.add_edge(START, "assistant")
builder.add_conditional_edges(
    "assistant",
    # 最新のメッセージがツールを必要とする場合は tools へルーティングします
    # それ以外の場合は直接応答します
    tools_condition,
)
builder.add_edge("tools", "assistant")
react_graph = builder.compile()

# 執事の思考過程を表示します
display(Image(react_graph.get_graph(xray=True).draw_mermaid_png()))

ツールのリストを使って tools ノードを定義します。assistant ノードは、ツールをバインドしたモデルそのものです。 assistant ノードと tools ノードでグラフを作成します。

tools_condition エッジを追加します。これは、assistant がツールを呼び出すかどうかに基づいて、END 又は tools へルーティングします。

ここで、新しいステップを 1 つ追加します。

tools ノードを assistant へ戻すよう接続し、ループを形成します。

  • assistant ノードが実行されたあと、tools_condition が、モデルの出力がツール呼び出しかどうかを確認します。
  • ツール呼び出しの場合は、フローは tools ノードへ向けられます。
  • tools ノードは assistant へ戻るよう接続されています。
  • このループは、モデルがツールを呼び出すと判断する限り続きます。
  • モデルの応答がツール呼び出しでない場合は、フローは END へ向けられ、処理が終了します。

執事の実演

例 1：簡単な計算

ここでは、LangGraph でツールを使うエージェントの簡単な利用例を紹介します。

messages = [HumanMessage(content="Divide 6790 by 5")]
messages = react_graph.invoke({"messages": messages, "input_file": None})

# メッセージを表示します
for m in messages['messages']:
    m.pretty_print()

会話は次のように進みます。

Human: Divide 6790 by 5

AI Tool Call: divide(a=6790, b=5)

Tool Response: 1358.0

Alfred: The result of dividing 6790 by 5 is 1358.0.

（トランスクリプトの訳：人間「6790 を 5 で割ってください」→ AI のツール呼び出し divide(a=6790, b=5) → ツールの応答「1358.0」→ Alfred「6790 を 5 で割った結果は 1358.0 です」。上のコードブロックの入力文も同じ文です）

例 2：Master Wayne のトレーニングドキュメントの分析

Master Wayne がトレーニングと食事のメモを残した時の例です。

messages = [HumanMessage(content="According to the note provided by Mr. Wayne in the provided images. What's the list of items I should buy for the dinner menu?")]
messages = react_graph.invoke({"messages": messages, "input_file": "Batman_training_and_meals.png"})

（入力文の訳：提供された画像にある Mr. Wayne のメモによると、夕食のメニューの為に買うべき品物のリストは何ですか）

やり取りは次のように進みます。

Human: According to the note provided by Mr. Wayne in the provided images. What's the list of items I should buy for the dinner menu?

AI Tool Call: extract_text(img_path="Batman_training_and_meals.png")

Tool Response: [Extracted text with training schedule and menu details]

Alfred: For the dinner menu, you should buy the following items:

1. Grass-fed local sirloin steak
2. Organic spinach
3. Piquillo peppers
4. Potatoes (for oven-baked golden herb potato)
5. Fish oil (2 grams)

Ensure the steak is grass-fed and the spinach and peppers are organic for the best quality meal.

（トランスクリプトの訳：ツールの応答は「トレーニングの予定とメニューの詳細を含む抽出テキスト」です。Alfred の応答は「夕食のメニューには、次の品物を買うべきです。1. 牧草飼育の地元産サーロインステーキ、2. 有機ほうれん草、3. ピキージョペッパー、4. ジャガイモ（オーブンで焼く黄金ハーブポテト用）、5. 魚油（2グラム）。最良の品質の食事の為に、ステーキは牧草飼育のもの、ほうれん草とペッパーは有機のものを選んでください」です）

重要なポイント

自分専用のドキュメント分析執事を作りたい場合は、次の点が重要です。

  1. ツールを明確に定義する：ドキュメントに関する具体的な作業に対応するツールを用意します。
  2. 堅牢な State の管理機能を作る：ツールの呼び出しをまたいでコンテキストを維持出来るようにします。
  3. エラー処理を考慮する：ツールの実行に失敗した場合に備えます。
  4. 過去のやり取りの文脈を維持する：演算子 add_messages によって実現出来ます。

これらの原則があれば、Wayne Manor にふさわしい模範的なドキュメント分析サービスを提供出来ます。
