前のセクションでは、各エージェントには **中核となる AI モデル** が必要であり、LLM がこの目的で最も一般的な AI モデルのタイプであることを学びました。

ここでは、LLM とは何か、そして LLM がエージェントをどう動かしているかを学びます。

このセクションでは、LLM の使い方を技術的な観点から簡単に説明します。さらに詳しく学びたい場合は、<a href="https://huggingface.co/learn/nlp-course/chapter1/1" target="_blank">無料の自然言語処理コース</a> をご覧ください。

## 大規模言語モデルとは何か？

LLM は、**人間の言語を理解し生成すること** に長けた AI モデルの一種です。膨大な量のテキストデータで訓練されており、言語のパターン、構造、さらにはニュアンスまで学ぶことができます。これらのモデルは通常、数百万規模のパラメータで構成されます。

現在の LLM のほとんどは、**Transformer アーキテクチャ** を基盤としています。Transformer は "Attention" アルゴリズムに基づく深層学習アーキテクチャで、2018 年に Google が BERT を発表して以来、大きな注目を集めています。

Transformer には3つのタイプがあります。

1. **エンコーダ（Encoders）**  
   エンコーダベースの Transformer は、テキスト（またはその他のデータ）を入力として受け取り、そのテキストの密な表現（埋め込み）を出力します。

   - **例**: Google の BERT
   - **ユースケース**: テキスト分類、セマンティック検索、固有表現認識
   - **典型的なサイズ**: 数百万のパラメータ

2. **デコーダ（Decoders）**  
   デコーダベースの Transformer は、**新しいトークンを1つずつ生成し、シーケンスの続きを完成させること** を主な目的とします。

   - **例**: Meta の Llama 
   - **ユースケース**: テキスト生成、チャットボット、コード生成
   - **典型的なサイズ**: 数十億（10^9）のパラメータ

3. **Seq2Seq（エンコーダ–デコーダ）**  
   シーケンス・ツー・シーケンスの Transformer は、エンコーダとデコーダを _組み合わせた_ ものです。まずエンコーダが入力シーケンスを処理してコンテキスト表現に変換し、次にデコーダが出力シーケンスを生成します。

   - **例**: T5、BART 
   - **ユースケース**:  翻訳、要約、パラフレーズ
   - **典型的なサイズ**: 数百万のパラメータ

大規模言語モデルにはさまざまな形式がありますが、LLM は通常、数十億のパラメータを持つデコーダベースのモデルです。よく知られた LLM をいくつか挙げます。

| **モデル**                          | **提供元**                              |
|-----------------------------------|-------------------------------------------|
| **Deepseek-R1**                    | DeepSeek                                  |
| **GPT4**                           | OpenAI                                    |
| **Llama 3**                        | Meta (Facebook AI Research)               |
| **SmolLM2**                       | Hugging Face     |
| **Gemma**                          | Google                                    |
| **Mistral**                        | Mistral                                |

LLM の根底にある原理はシンプルでありながら非常に効果的です。**その目的は、前のトークンのシーケンスが与えられたときに、次のトークンを予測すること** です。「トークン」は LLM が扱う情報の単位です。「トークン」は「単語」のようなものと考えることができますが、効率上の理由から LLM は単語全体を使いません。

たとえば、英語には推定60万語の単語がありますが、LLM の語彙は約32,000トークン程度かもしれません（Llama 2 がその例です）。トークン化は、組み合わせ可能なサブワード単位で行われることがよくあります。

たとえば、トークン "interest" と "ing" を組み合わせて "interesting" を作ったり、"ed" を追加して "interested" を作ったりできることを考えてみてください。

LLM にはそれぞれ、モデル固有の **特殊トークン** があります。これらのトークンは、生成するテキストの構造を区切るために使われます。たとえば、シーケンス、メッセージ、応答がどこで始まり、どこで終わるかを示します。さらに、モデルに渡す入力プロンプトも特殊トークンで構造化されています。その中で最も重要なのが **シーケンス終了トークン（End of sequence token、EOS）** です。

## 次トークン予測を理解する

LLM は **自己回帰的（autoregressive）** にテキストを生成します。これは、あるステップで生成した出力を次のステップの入力に加えながら、順に生成を進めるという意味です。この処理は、モデルが次に EOS トークンを予測するまで続き、その時点でモデルは停止できます。

<img src="https://huggingface.co/datasets/agents-course/course-images/resolve/main/en/unit1/AutoregressionSchema.gif" alt="生成したトークンを次の入力に加えながら文章を伸ばす、自己回帰生成のアニメーション" width="60%">

言い換えれば、LLM は EOS に到達するまでテキストをデコードします。では、1回のデコーディングループでは何が起こるのでしょうか？

処理の仕組みをすべて説明すると、エージェントの学習には少し専門的すぎる内容になるため、ここでは概要だけを紹介します。

- 入力テキストが **トークン化** されると、モデルは、入力シーケンス内の各トークンの意味や位置に関する情報を反映した表現を計算します。
- この表現がモデルに入力され、モデルは、語彙内の各トークンがシーケンスの次のトークンになる尤度をランク付けするスコアを出力します。

<img src="https://huggingface.co/datasets/agents-course/course-images/resolve/main/en/unit1/DecodingFinal.gif" alt="次のトークンの候補にスコアを付け、生成するトークンを選択する過程を示すアニメーション" width="60%">

これらのスコアに基づいて、文を完成させるトークンを選択する戦略が複数あります。

- 最も簡単なデコーディング戦略は、常に最大スコアのトークンを取ることです。

この Space で SmolLM2 を使って、デコーディングプロセスを自分で操作できます（このモデルでは、**EOS** トークンである **<|im_end|>** に到達するまでデコードすることを覚えておいてください）。

## Attention is all you need（必要なのはアテンションだけ）

Transformer アーキテクチャの重要な側面は **Attention（アテンション）** です。次の単語を予測する際、文中のすべての単語が等しく重要なわけではありません。*"The capital of France is ..."* という文では、"France" や "capital" のような単語が最も大きな意味を持ちます。

<img src="https://huggingface.co/datasets/agents-course/course-images/resolve/main/en/unit1/AttentionSceneFinal.gif" alt="次のトークンを予測する際に、文中の単語に異なる度合いで注意を向ける仕組みを示すアニメーション" width="60%">
次のトークンを予測するために最も関連性の高い単語を特定するこのプロセスは、非常に効果的であることが証明されています。

LLM の基本原理である「次のトークンを予測する」ことは GPT-2 以来一貫していますが、ニューラルネットワークのスケーリングや、ますます長いシーケンスでアテンション機構を機能させる点では、大きな進歩がありました。

LLM を使ったことがあれば、*context length（コンテキスト長）* という用語を聞いたことがあるでしょう。これは、LLM が一度に処理できるトークン数の上限、つまり _attention span（注意の範囲）_ のことです。

## LLM へのプロンプトが重要である

LLM は入力されたすべてのトークンを参照し、どのトークンが「重要」かを判断しながら次のトークンを予測します。そのため、入力シーケンスをどのような言葉で記述するかが非常に重要になります。

LLM に提供する入力シーケンスは _プロンプト_ と呼ばれます。プロンプトを注意深く設計することで、**LLM の生成を望ましい出力へと導きやすく** なります。

## LLM はどう訓練されるのか？

LLM は大規模なテキストデータセットで訓練され、自己教師あり学習またはマスク言語モデリングの目的を通じて、シーケンス内の次の単語を予測することを学びます。

この教師なし学習から、モデルは言語の構造と **テキストの根底にあるパターンを学び、未知のデータへ汎化できるように** なります。

最初の _事前学習（pre-training）_ のあと、LLM は教師あり学習によってファインチューニングされ、特定のタスクを実行できるようになります。たとえば、会話形式やツールの使用に対応するよう訓練されたモデルもあれば、分類やコード生成に焦点を当てるモデルもあります。

## LLM はどう使えるのか？

主に2つの選択肢があります。

1. **ローカルで実行する**（十分なハードウェアがある場合）。

2. **クラウド/API を使う**（例: Hugging Face Serverless Inference API 経由）。

このコースを通じて、主に Hugging Face Hub 上の API 経由でモデルを使います。後ほど、自分のハードウェア上でこれらのモデルをローカルで実行する方法も探ります。


## LLM は AI エージェントでどう使われるのか？

LLM は AI エージェントの重要なコンポーネントであり、**人間の言語を理解し生成するための基盤を提供します**。

ユーザーの指示を解釈し、会話のコンテキストを維持し、計画を定義し、使うツールを決めることができます。

これらのステップはこのユニットでさらに詳しく探りますが、今のところ理解すべきなのは、LLM が **エージェントの頭脳** であるということです。
