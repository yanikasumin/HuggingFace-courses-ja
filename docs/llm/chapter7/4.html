では、翻訳に入りましょう。翻訳もシーケンス・ツー・シーケンスのタスクの1つです。つまり、あるシーケンスから別のシーケンスへ移る問題として定式化出来ます。その意味で、この問題は要約にかなり近く、ここで学ぶ内容は次のような他のシーケンス・ツー・シーケンスの問題にも応用出来ます。

  • 文体変換（Style transfer）：或る文体で書かれたテキストを別の文体に翻訳するモデルを作る（例: 丁寧な文体からくだけた文体へ、シェイクスピア風の英語から現代英語へ）
  • 生成型質問応答（Generative question answering）：文脈を与えて、質問への回答を生成するモデルを作る

2つ（又はそれ以上）の言語のテキストからなる十分大きなコーパスがあれば、因果言語モデリングのセクションで行うように、新しい翻訳モデルをゼロから学習出来ます。但し、既存の翻訳モデルをファインチューニングする方が速く済みます。多言語モデルの mT5 や mBART を特定の言語ペア向けにファインチューニングする場合でも、ある言語から別の言語への翻訳に特化したモデルを自分のコーパス向けにファインチューニングする場合でも構いません。

このセクションでは、英語からフランス語への翻訳で事前学習された Marian モデルを、KDE4 データセットでファインチューニングします（Hugging Face の社員の多くがこの2言語を話す為です）。KDE4 は KDE アプリのローカライズ用ファイルのデータセットです。使うモデルは、Opus データセットから取得したフランス語と英語の大規模コーパスで事前学習されています。Opus には KDE4 データセット自体も含まれています。但し、使う事前学習モデルが事前学習の段階でそのデータを見ていたとしても、ファインチューニング後にはより良いモデルが得られることが分かるはずです。

完成すると、次のような予測が出来るモデルが得られます。

前のセクションまでと同様に、実際に学習して Hub にアップロードするモデルは以下のコードで得られ、その予測はこちらで確認出来ます。

翻訳モデルをファインチューニングしたりゼロから学習したりするには、タスクに適したデータセットが必要です。前述の通り、このセクションでは KDE4 データセット を使いますが、翻訳元と翻訳先の2言語の文ペアさえあれば、自分のデータに合わせるのも簡単です。自前のデータを Dataset に読み込む方法を思い出したい場合は、Chapter 5 を参照してください。

### データの処理








もう手順はお分かりでしょう。モデルが理解出来るよう、テキストは全てトークン ID の集合に変換する必要があります。このタスクでは、入力とターゲットの両方をトークン化しなければなりません。

まず `tokenizer` オブジェクトを作成します。前述の通り、英語からフランス語への Marian 事前学習モデルを使います。別の言語ペアでこのコードを試す場合は、モデルのチェックポイントをそれに合わせて変更してください。[Helsinki-NLP](https://huggingface.co/Helsinki-NLP) 組織は、複数言語で1,000を超えるモデルを提供しています。

```python
from transformers import AutoTokenizer

model_checkpoint = "Helsinki-NLP/opus-mt-en-fr"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint, return_tensors="pt")

model_checkpoint は、Hub にある好みのモデルや、事前学習済みモデルとトークナイザを保存したローカルフォルダに置き換えることも出来ます。

💡 ヒント

💡 mBART、mBART-50、M2M100 のような多言語トークナイザを使う場合は、tokenizer.src_lang と tokenizer.tgt_lang に適切な値を設定して、入力とターゲットの言語コードをトークナイザに設定する必要があります。

データの準備はかなり単純です。覚えておくべきことは1つだけです。トークナイザがターゲットを出力言語（ここではフランス語）として処理するようにしなければなりません。これには、トークナイザの __call__ メソッドの text_targets 引数にターゲットを渡します。

仕組みを確認する為、学習セットから各言語のサンプルを1つずつ処理してみましょう。

en_sentence = split_datasets["train"][1]["translation"]["en"]
fr_sentence = split_datasets["train"][1]["translation"]["fr"]

inputs = tokenizer(en_sentence, text_target=fr_sentence)
inputs

```python out

見ての通り、出力には英語の文に対応する入力 ID が含まれ、フランス語の文に対応する ID は `labels` フィールドに格納されています。ラベルをトークン化していることを指定し忘れると、ラベルは入力用トークナイザでトークン化されてしまいます。Marian モデルの場合、これはまったくうまくいきません。

```python
wrong_targets = tokenizer(fr_sentence)
print(tokenizer.convert_ids_to_tokens(wrong_targets["input_ids"]))
print(tokenizer.convert_ids_to_tokens(inputs["labels"]))

```python out ['▁Par', '▁dé', 'f', 'aut', ',', '▁dé', 've', 'lop', 'per', '▁les', '▁fil', 's', '▁de', '▁discussion', ''] ['▁Par', '▁défaut', ',', '▁développer', '▁les', '▁fils', '▁de', '▁discussion', '']

見ての通り、英語のトークナイザでフランス語の文を前処理すると、トークン数がずっと多くなります。トークナイザがフランス語の単語を知らない為です（"discussion" のように英語にも現れる単語は除きます）。

`inputs` は通常のキー（入力 ID、アテンションマスクなど）を持つ辞書なので、最後のステップは、データセットに適用する前処理関数を定義することです。

```python
max_length = 128


def preprocess_function(examples):
    inputs = [ex["en"] for ex in examples["translation"]]
    targets = [ex["fr"] for ex in examples["translation"]]
    model_inputs = tokenizer(
        inputs, text_target=targets, max_length=max_length, truncation=True
    )
    return model_inputs

入力と出力に同じ最大長を設定していることに注意してください。扱うテキストはかなり短いようなので、128 を使います。

💡 ヒント

💡 T5 モデル（具体的には t5-xxx チェックポイントのいずれか）を使う場合、モデルはテキスト入力に translate: English to French: のような、タスクを示す接頭辞が付いていることを想定します。

⚠️ 注意

⚠️ ターゲットのアテンションマスクには注意を払いません。モデルはそれを想定していない為です。その代わり、パディングトークンに対応するラベルは、損失の計算で無視されるよう -100 に設定すべきです。ここでは動的パディングを適用するので、この処理は後でデータコレータが行います。但し、ここでパディングを行う場合は、パディングトークンに対応するラベルを全て -100 に設定するよう前処理関数を適応させてください。

これで、データセットの全てのスプリットに前処理を一括で適用出来ます。

tokenized_datasets = split_datasets.map(
    preprocess_function,
    batched=True,
    remove_columns=split_datasets["train"].column_names,
)

データの前処理が終わったので、事前学習済みモデルをファインチューニングする準備が出来ました！

データコレータ

動的バッチ処理のパディングを扱うには、データコレータが必要です。このケースでは、Chapter 3 のような DataCollatorWithPadding をそのまま使うことはできません。これは入力（入力 ID、アテンションマスク、トークンタイプ ID）しかパディングしない為です。ラベルも、ラベル内で遭遇する最大長までパディングしなければなりません。また、前述の通り、ラベルのパディングに使う値はトークナイザのパディングトークンではなく -100 にすべきです。そうすれば、パディングされた値が損失の計算で確実に無視されます。

これらを全て行うのが DataCollatorForSeq2Seq です。DataCollatorWithPadding と同様に、入力の前処理に使った tokenizer を受け取りますが、model も受け取ります。これは、このデータコレータがデコーダ入力 ID の準備も担当する為です。デコーダ入力 ID は、ラベルをシフトし、先頭に特殊トークンを置いたものです。このシフトの方法はアーキテクチャによって少し異なる為、DataCollatorForSeq2Seq は model オブジェクトを知る必要があります。

{#if fw === 'pt'}

from transformers import DataCollatorForSeq2Seq

data_collator = DataCollatorForSeq2Seq(tokenizer, model=model)

{:else}

from transformers import DataCollatorForSeq2Seq

data_collator = DataCollatorForSeq2Seq(tokenizer, model=model, return_tensors="tf")

Seq2SeqTrainer がスーパークラスの Trainer に追加する機能は、評価や予測の際に generate() メソッドを使えることです。学習中、モデルは decoder_input_ids と、予測しようとしているトークンより後のトークンを使わないようにするアテンションマスクを使って学習を高速化します。推論時にはラベルがない為、それらを使うことはできません。その為、モデルを同じ設定で評価するのは良い考えです。

翻訳で伝統的に使われる指標は、Kishore Papineni らによる 2002年の論文 で導入された BLEU スコア です。BLEU スコアは、翻訳がラベルにどれだけ近いかを評価します。モデルが生成した出力の分かりやすさや文法的な正しさは測りません。その代わり、統計的な規則を用いて、生成された出力に含まれる単語が全てターゲットにも現れることを保証します。更に、ターゲットでも繰り返されていないのに同じ単語が繰り返される場合（モデルが "the the the the the" のような文を出力するのを避けるため）と、ターゲットより短い文を出力する場合（モデルが "the" のような文を出力するのを避けるため）にペナルティを与える規則もあります。

BLEU の弱点の1つは、テキストが既にトークン化されていることを前提とする点です。その為、異なるトークナイザを使うモデル同士でスコアを比較するのが難しくなります。そこで、今日の翻訳モデルのベンチマークで最もよく使われる指標は SacreBLEU です。これは、トークン化のステップを標準化することで、この弱点（や他の弱点）に対処しています。この指標を使うには、まず SacreBLEU ライブラリをインストールする必要があります。

!pip install sacrebleu

その後、Chapter 3 で行ったように evaluate.load() で読み込むことが出来ます。

この指標は、テキストを入力とターゲットとして受け取ります。同じ文に対して許容出来る翻訳は複数あることが多い為、許容出来るターゲットを複数受け取れるよう設計されています。使うデータセットでは1つしか提供されませんが、NLP ではラベルとして複数の文を与えるデータセットも珍しくありません。その為、予測は文のリストにしなければならず、参照は文のリストのリストでなければなりません。

モデルの出力から指標が使えるテキストに変換するには、`tokenizer.batch_decode()` メソッドを使います。ラベル内の `-100` を全て除去するだけです。トークナイザはパディングトークンについても自動的に同じことを行います。モデルとデータセットを受け取り、その指標を計算する関数を定義しましょう。

更に、劇的にパフォーマンスを高める工夫も使います。生成コードを TensorFlow の高速化線形代数コンパイラである [XLA](https://www.tensorflow.org/xla) でコンパイルします。XLA はモデルの計算グラフに様々な最適化を適用し、速度とメモリ使用量を大きく改善します。Hugging Face の[ブログ](https://huggingface.co/blog/tf-xla-generate)で説明されているように、XLA は入力の形状があまり変化しない時に最も効果を発揮します。これに対応する為、入力を128の倍数までパディングし、パディング用コレータで新しいデータセットを作り、生成関数に `@tf.function(jit_compile=True)` デコレータを適用して、関数全体を XLA でコンパイルするようマークします。

```py
import numpy as np
import tensorflow as tf
from tqdm import tqdm

generation_data_collator = DataCollatorForSeq2Seq(
    tokenizer, model=model, return_tensors="tf", pad_to_multiple_of=128
)

tf_generate_dataset = model.prepare_tf_dataset(
    tokenized_datasets["validation"],
    collate_fn=generation_data_collator,
    shuffle=False,
    batch_size=8,
)


@tf.function(jit_compile=True)
def generate_with_xla(batch):
    return model.generate(
        input_ids=batch["input_ids"],
        attention_mask=batch["attention_mask"],
        max_new_tokens=128,
    )


def compute_metrics():
    all_preds = []
    all_labels = []

    for batch, labels in tqdm(tf_generate_dataset):
        predictions = generate_with_xla(batch)
        decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)
        labels = labels.numpy()
        labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
        decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)
        decoded_preds = [pred.strip() for pred in decoded_preds]
        decoded_labels = [[label.strip()] for label in decoded_labels]
        all_preds.extend(decoded_preds)
        all_labels.extend(decoded_labels)

    result = metric.compute(predictions=all_preds, references=all_labels)
    return {"bleu": result["score"]}

num_train_epochs = 3
num_update_steps_per_epoch = len(train_dataloader)
num_training_steps = num_train_epochs * num_update_steps_per_epoch

lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)

学習ループ

これで、完全な学習ループを書く準備が出来ました。その評価部分を単純化する為、予測とラベルを受け取り、metric オブジェクトが期待する文字列のリストに変換する postprocess() 関数を定義します。

def postprocess(predictions, labels):
    predictions = predictions.cpu().numpy()
    labels = labels.cpu().numpy()

    decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)

    # ラベル内の -100 はデコードできないので置き換えます
    labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
    decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)

    # 簡単な後処理
    decoded_preds = [pred.strip() for pred in decoded_preds]
    decoded_labels = [[label.strip()] for label in decoded_labels]
    return decoded_preds, decoded_labels

学習ループは、セクション2 や Chapter 3 のものによく似ていますが、評価部分にいくつかの違いがあります。そこに焦点を当てましょう！

まず注意すべき点は、予測の計算に generate() メソッドを使いますが、これは prepare() メソッドで Accelerate が作成したラップされたモデルではなく、ベースモデルのメソッドであることです。その為、まずモデルをアンラップしてから、このメソッドを呼び出します。

2つ目は、トークン分類 の場合と同様に、2つのプロセスが入力とラベルを異なる形状にパディングしている可能性があることです。その為、gather() メソッドを呼び出す前に、accelerator.pad_across_processes() を使って予測とラベルを同じ形状にします。これを行わないと、評価でエラーになるか、永遠にハングします。

from tqdm.auto import tqdm
import torch

progress_bar = tqdm(range(num_training_steps))

for epoch in range(num_train_epochs):
    # 学習
    model.train()
    for batch in train_dataloader:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

    # 評価
    model.eval()
    for batch in tqdm(eval_dataloader):
        with torch.no_grad():
            generated_tokens = accelerator.unwrap_model(model).generate(
                batch["input_ids"],
                attention_mask=batch["attention_mask"],
                max_length=128,
            )
        labels = batch["labels"]

        # gather するために予測とラベルをパディングする必要があります
        generated_tokens = accelerator.pad_across_processes(
            generated_tokens, dim=1, pad_index=tokenizer.pad_token_id
        )
        labels = accelerator.pad_across_processes(labels, dim=1, pad_index=-100)

        predictions_gathered = accelerator.gather(generated_tokens)
        labels_gathered = accelerator.gather(labels)

        decoded_preds, decoded_labels = postprocess(predictions_gathered, labels_gathered)
        metric.add_batch(predictions=decoded_preds, references=decoded_labels)

    results = metric.compute()
    print(f"エポック {epoch}, BLEU スコア: {results['score']:.2f}")

    # 保存とアップロード
    accelerator.wait_for_everyone()
    unwrapped_model = accelerator.unwrap_model(model)
    unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
    if accelerator.is_main_process:
        tokenizer.save_pretrained(output_dir)
        repo.push_to_hub(
            commit_message=f"Training in progress epoch {epoch}", blocking=False
        )
