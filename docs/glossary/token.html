トークン

言語モデルが文章を扱う際の単位となる、文章を区切った断片である。1つのトークンは、単語全体の場合もあれば、単語の一部、1文字、記号の場合もある。モデルは文章をそのまま扱うのではなく、トークンの並びとして読み取り、トークンの並びとして書き出す。

関係するコース: LLM コース

前提となる用語

  • NLP（自然言語処理）

トークンとは

トークンは、言語モデルが文章を扱うときの単位である。モデルは文章をそのまま読み取るのではない。文章はまずトークンと呼ばれる断片に分割され、各トークンは語彙（ボキャブラリー）に登録された番号（ID）に置き換えられる。モデルが実際に読み取るのは番号の並びであり、モデルが書き出すのも番号の並びである。それを再び文章に戻すところまで含めて、分割と変換を担当するのがトークナイザである。

1つのトークンが表す長さは一定しない。英語では単語全体が1トークンになることもあれば、単語の一部、1文字、空白や句読点が1トークンになることもある。どの断片をトークンとするかは、そのモデルの語彙に何が登録されているかで決まる。

なぜ単語でも文字でもないのか

単位を単語にすると、二つの問題が出る。第一に、世の中の単語を全て登録すると語彙が膨大になる。第二に、登録されていない単語（新しい造語、固有名詞、入力ミスなど）が現れたときに扱えない。逆に、単位を1文字にすると語彙は小さくて済むが、文章が非常に長い並びになり、意味のまとまりも捉えにくくなる。

そこで現在の主流は、単語より細かい断片（サブワード）を単位にする方式である。よく現れる文字列は長い断片として登録し、珍しい単語は細かい断片の組み合わせで表す。こうすると語彙の大きさを抑えたまま、未知の単語にも対応できる。断片の決め方には BPE（バイトペア符号化）などの方法があり、大量の文章の中で頻繁に現れる文字列の組を優先して1つのトークンにまとめていく。

トークンの数え方の目安

トークン数は文字数とも単語数とも一致しないが、英語については「1トークンはおよそ4文字、単語の4分の3程度」という目安がよく使われる。ただしこれは代表的なトークナイザでの概算であり、正確な値はモデルごとに異なる。日本語は英語に比べて、同じ内容でもトークン数が多くなりやすい。漢字1文字が1トークン以上に分かれることも珍しくない。正確なトークン数を知りたい場合は、そのモデルのトークナイザで実際に数える必要がある。

実務で効いてくる場面

トークンは学習の内部だけの概念ではなく、モデルを使う側の制約にも直結する。第一に、モデルが一度に目を通せる量（コンテキストウィンドウ）はトークン数で数える。入力と出力を合わせた長さが上限を超えると、超えた部分は処理の対象にならない。第二に、多くの API の料金はトークン数に応じて決まる。文字数ではなくトークン数で課金されるため、言語やモデルによって同じ文章でも費用が変わる。第三に、生成できる長さの上限もトークン数で指定される。

よくある誤解

トークンは単語ではない。意味の切れ目とトークンの切れ目も一致しないことがあり、人間から見て不自然な位置で分かれることもある。また、同じ文章でもモデルが違えば分割のされ方は違う。「この文章は何トークンか」という問いには、どのモデルのトークナイザで数えるかを決めなければ答えられない。
