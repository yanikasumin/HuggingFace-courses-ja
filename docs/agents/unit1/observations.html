観察（Observe）：フィードバックを取り入れて振り返り、適応する

観察（Observation）は エージェントが自分のアクションの結果をどう知覚するか です。

エージェントの思考プロセスを支え、将来のアクションを導く重要な情報を提供します。

観察は 環境からのシグナル であり、API からのデータ、エラーメッセージ、システムログなど、次の思考サイクルを導くものです。

観察フェーズでは、エージェントは次のことを行います。

  • フィードバックを集める: アクションが成功した（しなかった）というデータや確認を受け取る。
  • 結果を追加する: 新しい情報を既存のコンテキストに統合し、事実上メモリを更新する。
  • 戦略を適応させる: 更新されたコンテキストを使って、その後の思考とアクションを改善する。

たとえば、天気 API が "partly cloudy, 15°C, 60% humidity"（ところどころ曇り、15°C、湿度60%）というデータを返した場合、この観察はエージェントのメモリ（プロンプトの末尾）に追加されます。

そしてエージェントはそれを使って、追加情報が必要か、最終回答を提供する準備ができているかを判断します。

この フィードバックを反復的に取り入れる仕組みにより、エージェントは目標と動的に整合し続け、現実の結果に基づいて常に学び、調整します。

これらの観察は、Web ページのテキストを読むことからロボットアームの位置を監視することまで、さまざまな形を取り得ます。アクションの実行に関するテキストフィードバックを提供する、ツールの「ログ」のようなものと見ることができます。

観察の種類 例
システムフィードバック エラーメッセージ、成功通知、ステータスコード
データの変化 データベースの更新、ファイルシステムの変更、状態の変化
環境データ センサーの読み取り値、システムメトリクス、リソース使用量
応答の分析 API レスポンス、クエリ結果、計算出力
時間ベースのイベント 到達した締め切り、完了したスケジュール済みタスク

結果はどうやって追加されるのか？

アクションを実行したあと、フレームワークは次の手順を順に行います。

  1. アクションを解析し、呼び出す関数と使う引数を特定する。
  2. アクションを実行する。
  3. 結果を観察（Observation）として追加する。

これでエージェントの思考・アクション・観察のサイクルを学びました。

まだ少し曖昧に感じる部分があっても心配いりません。これらの概念は今後のユニットで再び取り上げ、深めていきます。

さあ、初めてのエージェントをコーディングして、知識を実践に移しましょう！
