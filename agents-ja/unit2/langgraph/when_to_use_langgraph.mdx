# `LangGraph` とは？ [[what-is-langgraph]]

`LangGraph` は [LangChain](https://www.langchain.com/) が開発したフレームワークで、**LLM を組み込んだアプリケーションの制御フローを管理する** 為のものです。

## `LangGraph` は `LangChain` と違うのですか？

LangChain は、モデルやその他のコンポーネントとやり取りする為の標準インターフェースを提供し、検索、LLM の呼び出し、ツールの呼び出しなどに役立ちます。LangChain のクラスは LangGraph で使うことも出来ますが、必ず使わなければならない訳ではありません。

この2つは別々のパッケージで、単独でも使えます。但し、オンラインで見つかる資料では、どれも両方のパッケージを組み合わせて使っています。

## `LangGraph` はいつ使うべきですか？
### 制御と自由

AI アプリケーションを設計する際には、**制御** と **自由** の間にある根本的なトレードオフに直面します。

- **自由** があれば、LLM はより創造的に振る舞い、予期しない問題にも取り組めます。
- **制御** があれば、予測可能な動作を確保し、ガードレールを維持出来ます。

*smolagents* で見られるような Code Agent は、非常に自由度が高いのが特徴です。1 回のアクションステップで複数のツールを呼び出したり、自分でツールを作成したり出来ます。但し、その分、JSON を使って動作する通常の Agent と比べて予測しにくく、制御もしにくくなります。

`LangGraph` はその対極にあります。エージェントの実行を **自分で制御したい** 場面で真価を発揮します。

LangGraph は、**アプリケーションに対する制御** が必要な場合に特に役立ちます。LLM の力を活かしながら、予測可能なプロセスに従うアプリケーションを構築する為のツールを提供します。

簡単に言えば、アプリケーションに一連の処理ステップがあり、それらを決まった方法で組み合わせ、各分岐点で次の処理を判断する必要があるなら、**LangGraph がその為の構造を提供します**。

例として、ドキュメントに関する質問に答えられる LLM アシスタントを構築する場合を考えてみましょう。

LLM が最も得意とするのはテキストの理解です。その為、グラフや表など、テキスト以外の複雑な情報形式（モダリティ）は、質問に答える前にテキストへ変換する必要があります。但し、変換方法は扱うドキュメントの種類によって異なります。

LangGraph が真価を発揮する主なシナリオは次の通りです。

- フローに対する明示的な制御が必要な **多段階の推論プロセス**
- ステップ間で **状態の永続化が必要なアプリケーション**
- **決定論的なロジックと AI の機能を組み合わせたシステム**
- **人間が途中で介入する仕組み（human-in-the-loop）が必要なワークフロー**
- 複数のコンポーネントが連携する **複雑なエージェントアーキテクチャ**

要するに、出来る限り **人間の側で**、各アクションの出力に基づいて処理の流れを設計し、その結果に応じて次に実行するアクションを決めるようにしてください。そのようなアプリケーションには、LangGraph が最適です！

私見では、`LangGraph` は市場で最も本番環境に対応したエージェントフレームワークです。

## LangGraph の仕組み

LangGraph の核となるのは、有向グラフ構造を使ってアプリケーションのフローを定義することです。

- **ノード** は個々の処理ステップを表します（LLM の呼び出し、ツールの使用、意思決定など）。
- **エッジ** はステップ間の遷移の可能性を定義します。
- **状態（State）** はユーザーが定義し、保持され、実行中にノード間で受け渡されます。次にどのノードへ進むかを決める際には、この現在の状態を参照します。

これらの基本的な構成要素については、次の章で詳しく見ていきます！

## 通常の Python とどう違うのですか？ 何故 LangGraph が必要なのですか？

「if-else 文を使った通常の Python コードで、これらのフローを全て処理出来るのではないか」と思うかもしれません。

技術的にはその通りです。しかし、複雑なシステムを作る際には、通常の Python だけで実装する場合と比べて、LangGraph には **いくつかの利点** があります。LangGraph を使わずに同じアプリケーションを作ることも出来ますが、LangGraph には開発を容易にするツールや抽象化が用意されています。

状態管理、可視化、ログ（トレース）、人間が途中で確認・介入出来る組み込みの仕組み（human-in-the-loop）など、様々な機能が含まれています。
