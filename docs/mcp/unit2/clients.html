MCP クライアントを構築する

このセクションでは、異なるプログラミング言語を使って MCP サーバーとやり取りできるクライアントを作成します。HuggingFace.js を使った JavaScript クライアントと、smolagents を使った Python クライアントの両方を実装します。

MCP クライアントを設定する

MCP サーバーとクライアントを効果的にデプロイするには、適切な設定が必要です。MCP の仕様はまだ進化の途上にあるため、設定方法も変わっていく可能性があります。ここでは、現在のベストプラクティスに焦点を当てます。

MCP 設定ファイル

MCP ホストは設定ファイルを使ってサーバー接続を管理します。これらのファイルは、どのサーバーが利用可能で、どのように接続するかを定義します。

設定ファイルは非常にシンプルで理解しやすく、主要な MCP ホスト間で一貫しています。

mcp.json の構造

MCP の標準設定ファイルは mcp.json という名前です。基本構造は次のとおりです。

{
  "servers": [
    {
      "name": "MCP Server",
      "transport": {
        "type": "sse",
        "url": "http://localhost:7860/gradio_api/mcp/sse"
      }
    }
  ]
}

この例では、SSE トランスポートを使う単一のサーバーが設定されており、ポート 7860 で動作するローカルの Gradio サーバーに接続します。

💡 ヒント

Gradio アプリがリモートサーバーで動作していることを前提とするため、SSE トランスポートで Gradio アプリに接続しました。ただし、ローカルのスクリプトに接続したい場合は、sse トランスポートではなく stdio トランスポートのほうが適しています。

HTTP+SSE トランスポートの設定

HTTP+SSE トランスポートを使うリモートサーバーでは、設定にサーバーの URL を含めます。

{
  "servers": [
    {
      "name": "Remote MCP Server",
      "transport": {
        "type": "sse",
        "url": "https://example.com/gradio_api/mcp/sse"
      }
    }
  ]
}

この設定により、UI クライアントは MCP プロトコルを使って Gradio MCP サーバーと通信でき、フロントエンドと MCP サービスのシームレスな統合が可能になります。

UI MCP クライアントを設定する

Gradio MCP サーバーを使う場合、MCP プロトコルを使ってサーバーに接続するよう UI クライアントを設定できます。設定方法は次のとおりです。

基本設定

config.json という新しいファイルを作成し、次の設定を記述します。

{
  "mcpServers": {
    "mcp": {
      "url": "http://localhost:7860/gradio_api/mcp/sse"
    }
  }
}

この設定により、UI クライアントは MCP プロトコルを使って Gradio MCP サーバーと通信でき、フロントエンドと MCP サービスのシームレスな統合が可能になります。

Cursor IDE 内で MCP クライアントを設定する

Cursor には MCP サポートが組み込まれており、デプロイした MCP サーバーを開発環境に直接接続できます。

設定

Cursor の設定を開き（Ctrl + Shift + J / Cmd + Shift + J）、Tools & Integrations タブ → Add Custom MCP を選択します。

macOS:

{
  "mcpServers": {
    "sentiment-analysis": {
      "command": "npx",
      "args": [
        "-y", 
        "mcp-remote", 
        "https://YOURUSENAME-mcp-sentiment.hf.space/gradio_api/mcp/sse", 
        "--transport", 
        "sse-only"
      ]
    }
  }
}

Windows:

{
  "mcpServers": {
    "sentiment-analysis": {
      "command": "cmd",
      "args": [
        "/c", 
        "npx", 
        "-y", 
        "mcp-remote", 
        "https://YOURUSENAME-mcp-sentiment.hf.space/gradio_api/mcp/sse", 
        "--transport", 
        "sse-only"
      ]
    }
  }
}

mcp-remote を使う理由

Note: 2025年半ば時点で、Cursor は HTTP+SSE と OAuth によるリモート MCP 接続を直接サポートしています。レガシーなセットアップを使う場合や、特定の互換性の問題に遭遇した場合を除き、mcp-remote は不要かもしれません。

Cursor を含む初期の MCP クライアントは、stdio トランスポートによるローカルサーバーのみをサポートし、認証を伴うリモートサーバーをサポートしていませんでした。mcp-remote ツールは、その回避策として導入されたもので、次の特徴があります。

  • ローカルマシン上で動作する
  • Cursor とリモート MCP サーバーを橋渡しする
  • トランスポートと認証を暗黙的に処理する
  • おなじみの設定ファイル形式を使う

これは一部のエッジケースでは今でも有用ですが、Cursor は現在ネイティブのリモート MCP 統合をサポートしています。リモートサーバーは次のように直接設定できます。

{
  "mcpServers": {
    "my-server": {
      "url": "https://your-mcp-server.hf.space/gradio_api/mcp/sse"
    }
  }
}

最新のセットアップ手順については Cursor の公式ドキュメント を参照してください。

設定が完了すれば、コードコメントやユーザーフィードバック、プルリクエストの説明の分析といったタスクに、感情分析ツールを使うよう Cursor に依頼できます。
