# Module 3：Slack 通知

## コミュニケーションの溝の危機

CodeCraft Studios での3週目。あなたの自動化システムは、既にチームの働き方を変えつつあります。

- **PR Agent**（Module 1）：開発者が明確で役立つプルリクエストの説明を書くようになった
- **CI/CD Monitor**（Module 2）：チームがテストの失敗を即座に捕え、バグが本番環境に到達するのを防いでいる

チームはすっかり自信をつけていました…月曜の朝、新たな危機が訪れるまでは。

フロントエンドチーム（Emma と Jake）は、厄介な API 連携の問題のデバッグに週末を丸ごと費やしました。ネットワーク呼び出しの確認、リクエスト形式の検証、エラーハンドリングの書き直しまで、あらゆることを試しました。

そして日曜の午前2時、ついに原因が判明します。バックエンドチームが金曜日にまさにこの問題を修正し、修正したコードをステージング環境にデプロイしていたのに、そのことを知らせるのを忘れていたのです。

「既に修正済みの問題の解決に12時間も無駄にした！」Emma は苛立って言います。

一方、デザインチームは先週、新しいユーザーオンボーディングフローのイラストを完成させていましたが、フロントエンドチームは準備が出来ていることを知りませんでした。その美しいアセットは使われないまま置かれ、チームは暫定的なデザインをリリースしています。

チームは、情報のサイロ問題を抱えていることに気づきます。全員が一生懸命働いているのに、いつ何が起きているのかを効果的に伝え合えていないのです。

**あなたのミッション**：重要な進展をチーム全員に自動で知らせる、インテリジェントな Slack 通知で自動化システムを完成させることです。

## 主要概念

### MCP 連携パターン

このモジュールでは、完全なワークフローを示します。

1. **Events** → GitHub Actions の webhook（Module 2 より）
2. **Prompts** → イベントを読み易いメッセージに整形する
3. **Tools** → 整形したメッセージを Slack へ送信する
4. **Result** → プロフェッショナルなチーム通知

### Slack の Markdown 書式

装飾付きのメッセージを作るには、[Slack の Markdown 書式](https://api.slack.com/reference/surfaces/formatting)を使います。

- 強調には [`*bold text*`](https://api.slack.com/reference/surfaces/formatting#visual-styles)
- 詳細には [`_italic text_`](https://api.slack.com/reference/surfaces/formatting#visual-styles)
- 技術情報には [`` `code blocks` ``](https://api.slack.com/reference/surfaces/formatting#inline-code)
- 要約には [`> quoted text`](https://api.slack.com/reference/surfaces/formatting#quotes)
- [絵文字](https://api.slack.com/reference/surfaces/formatting#emoji)：✅ ❌ 🚀 ⚠️
- [リンク](https://api.slack.com/reference/surfaces/formatting#linking-urls)： `<https://github.com/user/repo|Repository>`

## 実装ステップ

### ステップ1：Slack 連携のセットアップ（10分）

1. Slack の webhook を作成する：
   - [Slack API Apps](https://api.slack.com/apps) にアクセスする
   - 新しいアプリを作成し、「From scratch」（最初から作成）を選ぶ（[アプリ作成ガイド](https://api.slack.com/authentication/basics#creating)）
   - アプリ名：「MCP Course Notifications」
   - ワークスペースを選ぶ
   - 「Features（機能）」→「[Incoming Webhooks（着信 Webhook）](https://api.slack.com/messaging/webhooks)」へ進む
   - [着信 webhook を有効化する](https://api.slack.com/messaging/webhooks#enable_webhooks)
   - 「Add New Webhook to Workspace」（ワークスペースに新しい Webhook を追加）をクリックする
   - チャンネルを選んで承認する（[Webhook セットアップガイド](https://api.slack.com/messaging/webhooks#getting_started)）
   - webhook URL をコピーする

2. webhook が動作するかテストする（[webhook 投稿の例](https://api.slack.com/messaging/webhooks#posting_with_webhooks) に従う）：
   ```bash
   curl -X POST -H 'Content-type: application/json' \
     --data '{"text":"Hello from MCP Course!"}' \
     YOUR_WEBHOOK_URL
   ```

3. 環境変数を設定する：
   ```bash
   export SLACK_WEBHOOK_URL="https://hooks.slack.com/services/YOUR/WEBHOOK/URL"
   ```

   **⚠️ セキュリティに関する注意**：webhook URL は、Slack チャンネルへのメッセージ投稿権限を与える機密情報です。必ず次のようにしてください。

   - 環境変数として保存し、コードにハードコードしない
   - webhook URL をバージョン管理にコミットしない（`.gitignore` に追加する）
   - パスワードと同じように厳重に扱う。この URL を知る人は誰でもチャンネルにメッセージを送信出来る

> [!WARNING]
> **セキュリティ警告**：webhook URL は機密性の高い認証情報です！webhook URL を知る人は誰でも、あなたの Slack チャンネルにメッセージを送信出来ます。必ず環境変数として保存し、バージョン管理には決してコミットしないでください。

### ステップ3：整形プロンプトを作成する（15分）

次に、サーバーへ MCP Prompts を追加します。ここからが重要な部分です。これらのプロンプトを Claude と組み合わせることで、GitHub の webhook データを、情報が整理された Slack メッセージに自動で変換出来ます。

Module 1 で学んだように、Prompts は Claude が一貫して使える再利用可能な指示を提供します。

Slack 形式のメッセージを生成する、2つのプロンプトを実装します。

1. **`format_ci_failure_alert`**：
   ```python
   @mcp.prompt()
   def format_ci_failure_alert() -> str:
       """Create a Slack alert for CI/CD failures."""
       return """Format this GitHub Actions failure as a Slack message:

   Use this template:
   :rotating_light: *CI Failure Alert* :rotating_light:
   
   A CI workflow has failed:
   *Workflow*: workflow_name
   *Branch*: branch_name
   *Status*: Failed
   *View Details*: <LOGS_LINK|View Logs>
   
   Please check the logs and address any issues.
   
   Use Slack markdown formatting and keep it concise for quick team scanning."""
   ```

2. **`format_ci_success_summary`**：
   ```python
   @mcp.prompt()
   def format_ci_success_summary() -> str:
       """Create a Slack message celebrating successful deployments."""

   Use this template:
   :white_check_mark: *Deployment Successful* :white_check_mark:
   
   Deployment completed successfully for [Repository Name]

   - Key feature or fix 1
   - Key feature or fix 2
   
   *Links:*
   <PR_LINK|View Changes>
   ```

**webhook イベントの流れの理解：**

- webhook サーバー（Module 2 より）が GitHub イベントを捕捉し、`github_events.json` に保存する

**クイックテストのワークフロー：**

1. curl でテスト用の模擬 GitHub イベントを webhook サーバーへ送信する
2. Claude に最近のイベントの確認と整形を依頼する
3. 整形済みメッセージを Slack へ送信する
4. 全てがエンドツーエンドで動作することを確認する

## よくある問題

### Webhook URL の問題
- 環境変数が正しく設定されているか確認する
- 連携前に、curl で webhook を直接テストする
- Slack アプリに適切な権限が有るか確認する

### メッセージの書式
- [Slack の Markdown](https://api.slack.com/reference/surfaces/formatting) は GitHub の Markdown とは異なる
- **重要**：太字には `*text*` を使う（`**text**` ではない）
- 適切な書式の為、webhook ペイロードに `"mrkdwn": true` を含める
- 自動化の前に、メッセージの書式を手動でテストする
- コミットメッセージ内の特殊文字を適切に処理する（[書式リファレンス](https://api.slack.com/reference/surfaces/formatting#escaping)）

### ネットワークエラー
- webhook リクエストに基本的なタイムアウト処理を追加する（[webhook のエラーハンドリング](https://api.slack.com/messaging/webhooks#handling_errors)）
- ツールから意味の有るエラーメッセージを返す
- リクエストが失敗する場合はインターネット接続を確認する
