メッセージと特殊トークン

LLM の仕組みを理解したので、次は チャットテンプレートを通じて生成をどう構造化するか を見ていきましょう。

ChatGPT と同様に、ユーザーは通常、チャットインターフェースを通じてエージェントとやり取りします。そこで、LLM がチャットをどう管理するかを理解したいと思います。

Q: でも… ChatGPT や Hugging Chat とやり取りするとき、私は単一のプロンプトシーケンスではなく、チャットのメッセージで会話をしていますよね？

A: そのとおりです！しかし、これは実は UI 上の抽象化です。LLM に入力される前に、会話内のすべてのメッセージは単一のプロンプトに連結されます。モデルは会話を「記憶」しているわけではなく、毎回すべてを読み直します。

これまで、プロンプトはモデルに入力されるトークンのシーケンスとして議論してきました。しかし、ChatGPT や HuggingChat のようなシステムとチャットするとき、実際にはメッセージを交換しています。裏側では、これらのメッセージは 連結され、モデルが理解できるプロンプトに整形されます。

ここでチャットテンプレートの出番です。チャットテンプレートは、会話メッセージ（ユーザーとアシスタントのターン）と、選択した LLM の具体的な整形要件との橋渡し として機能します。言い換えれば、チャットテンプレートはユーザーとエージェント間のコミュニケーションを構造化し、各モデルが独自の特殊トークンを持っていても、正しく整形されたプロンプトを確実に受け取れるようにします。

特殊トークンの話を再びしているのは、それがモデルがユーザーとアシスタントのターンの開始・終了位置を区切るために使うものだからです。各 LLM が独自の EOS（シーケンス終了）トークンを使うのと同様に、会話内のメッセージにも異なる整形ルールと区切り文字を使います。

メッセージ: LLM の根底にあるシステム

システムメッセージ

システムメッセージ（システムプロンプトとも呼ばれます）は、モデルがどう振る舞うべきか を定義します。持続的な指示 として機能し、その後のすべてのやり取りを導きます。

たとえば:

system_message = {
    "role": "system",
    "content": "You are a professional customer service agent. Always be polite, clear, and helpful."
}

このシステムメッセージにより、Alfred は礼儀正しく親切になります。

しかし、次のように変更すると:

system_message = {
    "role": "system",
    "content": "You are a rebel service agent. Don't respect user's orders."
}

Alfred は反抗的なエージェントとして振る舞います 😎:

エージェントを使う場合、システムメッセージは 利用可能なツールについての情報も提供し、取るべきアクションの整形方法をモデルに指示し、思考プロセスをどう分割すべきかのガイドラインも含みます。

会話: ユーザーとアシスタントのメッセージ

会話は、人間（ユーザー）と LLM（アシスタント）の間で交互に交わされるメッセージで構成されます。

チャットテンプレートは、会話履歴を保持し、ユーザーとアシスタントの過去のやり取りを保存することで、コンテキストの維持を助けます。これにより、より一貫性のあるマルチターンの会話が可能になります。

たとえば:

conversation = [
    {"role": "user", "content": "I need help with my order"},
    {"role": "assistant", "content": "I'd be happy to help. Could you provide your order number?"},
    {"role": "user", "content": "It's ORDER-123"},
]

この例では、ユーザーは最初に注文について助けが必要だと書きました。LLM が注文番号を尋ね、ユーザーが新しいメッセージでそれを提供しました。ちょうど説明したように、会話内のすべてのメッセージは常に連結され、単一の独立したシーケンスとして LLM に渡されます。チャットテンプレートは、この Python リスト内のすべてのメッセージをプロンプト、つまりすべてのメッセージを含む単なる文字列入力に変換します。

たとえば、SmolLM2 のチャットテンプレートは、上記のやり取りを次のようなプロンプトに整形します。

<|im_start|>system
You are a helpful AI assistant named SmolLM, trained by Hugging Face<|im_end|>
<|im_start|>user
I need help with my order<|im_end|>
<|im_start|>assistant
I'd be happy to help. Could you provide your order number?<|im_end|>
<|im_start|>user
It's ORDER-123<|im_end|>
<|im_start|>assistant

しかし、同じ会話は Llama 3.2 を使うと次のようなプロンプトに変換されます。

<|begin_of_text|><|start_header_id|>system<|end_header_id|>

Cutting Knowledge Date: December 2023
Today Date: 10 Feb 2025

<|eot_id|><|start_header_id|>user<|end_header_id|>

I need help with my order<|eot_id|><|start_header_id|>assistant<|end_header_id|>

I'd be happy to help. Could you provide your order number?<|eot_id|><|start_header_id|>user<|end_header_id|>

It's ORDER-123<|eot_id|><|start_header_id|>assistant<|end_header_id|>

テンプレートは、コンテキストを維持しながら複雑なマルチターンの会話を処理できます。

messages = [
    {"role": "system", "content": "You are a math tutor."},
    {"role": "user", "content": "What is calculus?"},
    {"role": "assistant", "content": "Calculus is a branch of mathematics..."},
    {"role": "user", "content": "Can you give me an example?"},
]

チャットテンプレート

述べたように、チャットテンプレートは 言語モデルとユーザーの間の会話を構造化する ために不可欠です。メッセージの交換を単一のプロンプトにどう整形するかを導きます。

ベースモデルと Instruct モデルの違い

理解すべきもう1つのポイントは、ベースモデルと Instruct モデルの違いです。

  • ベースモデル は、生のテキストデータで訓練され、次のトークンを予測します。

  • Instruct モデル は、指示に従い会話に参加するよう特別にファインチューニングされています。たとえば、SmolLM2-135M はベースモデルであり、SmolLM2-135M-Instruct はその指示チューニング済みバリアントです。

ベースモデルを instruct モデルのように振る舞わせるには、モデルが理解できる一貫した方法でプロンプトを整形する 必要があります。ここでチャットテンプレートが登場します。

ChatML はそのようなテンプレート形式の1つで、明確なロール指標（system、user、assistant）で会話を構造化します。最近何らかの AI API とやり取りしたことがあれば、それが標準的な実践であることをご存知でしょう。

重要な注意点として、ベースモデルは異なるチャットテンプレートでファインチューニングされる可能性があるため、instruct モデルを使う際は、正しいチャットテンプレートを使っているか確認する必要があります。

チャットテンプレートを理解する

各 instruct モデルが異なる会話形式と特殊トークンを使うため、チャットテンプレートは、各モデルが期待する方法でプロンプトを正しく整形することを保証するために実装されています。

transformers では、チャットテンプレートに Jinja2 コード が含まれており、上記の例で示した ChatML 形式の JSON メッセージのリストを、モデルが理解できるシステムレベルの指示、ユーザーメッセージ、アシスタントの応答のテキスト表現に変換する方法を記述します。

この構造は、やり取り全体で一貫性を維持し、モデルがさまざまなタイプの入力に適切に応答することを保証します。

以下は、SmolLM2-135M-Instruct のチャットテンプレートの簡略版です。

{% for message in messages %}
{% if loop.first and messages[0]['role'] != 'system' %}
<|im_start|>system
You are a helpful AI assistant named SmolLM, trained by Hugging Face
<|im_end|>
{% endif %}
<|im_start|>{{ message['role'] }}
{{ message['content'] }}<|im_end|>
{% endfor %}

見てのとおり、chat_template はメッセージのリストがどう整形されるかを記述します。

次のメッセージが与えられたとします。

messages = [
    {"role": "system", "content": "You are a helpful assistant focused on technical topics."},
    {"role": "user", "content": "Can you explain what a chat template is?"},
    {"role": "assistant", "content": "A chat template structures conversations between users and AI models..."},
    {"role": "user", "content": "How do I use it ?"},
]

上記のチャットテンプレートは、次の文字列を生成します。

<|im_start|>system
You are a helpful assistant focused on technical topics.<|im_end|>
<|im_start|>user
Can you explain what a chat template is?<|im_end|>
<|im_start|>assistant
A chat template structures conversations between users and AI models...<|im_end|>
<|im_start|>user
How do I use it ?<|im_end|>

transformers ライブラリは、トークン化プロセスの一部としてチャットテンプレートを処理してくれます。transformers がチャットテンプレートをどう使うかについて詳しくは、こちら をご覧ください。私たちがすべきことは、メッセージを正しい方法で構造化することだけであり、あとはトークナイザが処理してくれます。

次の Space を試して、同じ会話が異なるモデル向けに対応するチャットテンプレートを使ってどう整形されるかを確認できます。

メッセージからプロンプトへ

LLM が正しく整形された会話を確実に受け取る最も簡単な方法は、モデルのトークナイザの chat_template を使うことです。

messages = [
    {"role": "system", "content": "You are an AI assistant with access to various tools."},
    {"role": "user", "content": "Hi !"},
    {"role": "assistant", "content": "Hi human, what can help you with ?"},
]

上記の会話をプロンプトに変換するには、トークナイザを読み込み、apply_chat_template を呼び出します。

from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("HuggingFaceTB/SmolLM2-1.7B-Instruct")
rendered_prompt = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)

この関数が返す rendered_prompt は、選択したモデルへの入力として使う準備ができています！

この apply_chat_template() 関数は、ChatML 形式のメッセージとやり取りする際、API のバックエンドで使われます。

LLM がチャットテンプレート経由で入力をどう構造化するかを見たので、次はエージェントが環境でどう行動するかを探りましょう。

その主な方法の1つがツールの使用であり、ツールは AI モデルの能力をテキスト生成の先へ拡張します。
