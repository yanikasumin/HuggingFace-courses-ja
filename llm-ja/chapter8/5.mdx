## 最小再現例を作る[[creating-a-minimal-reproducible-example]]

バグを生むコードの切り分けは、とても重要です。Hugging Face のチームのだれも魔法使いではないので（今のところは）、見えないものは直せません。最小再現例は、その名前の通り、再現可能でなければなりません。手元の外部ファイルやデータには依存しない形にします。使っているデータは、実物に似ていて同じエラーを出すダミーの値に置き換えてください。

> [!TIP]
> 🚨 🤗 Transformers リポジトリの Issue の多くは、再現に使うデータにアクセス出来ない為に未解決のままになっています。

自己完結したものが出来たら、更に行数を減らし、いわゆる_最小再現例_に仕上げます。報告する側には多少の手間がかかりますが、きれいで短い再現コードを用意すれば、助けと修正がほぼ確実に得られます。

余裕があれば、バグが起きている場所のソースコードを自分で調べてみてください。問題の解決策が見つかるかもしれません。その場合は、修正のプルリクエストを提案することさえ出来ます。解決策が見つからなくても、報告を読むメンテナが原因を理解する助けになります。

## Issue テンプレートを埋める[[filling-out-the-issue-template]]

Issue を起票すると、テンプレートを埋める形式になっています。ここでは [Transformers の Issue](https://github.com/huggingface/transformers/issues/new/choose) 用のテンプレートに沿って進めますが、他のリポジトリで Issue を報告する場合も、求められる情報の種類は同じです。テンプレートは空欄のままにしないでください。時間をかけて埋めることで、回答が得られ、問題が解決する可能性が最大になります。

一般に、Issue を起票する時は常に礼儀正しくしてください。これはオープンソースプロジェクトです。無料のソフトウェアを使っているのであり、だれにも助ける義務はありません。正当だと感じる批判を Issue に含めることも出来ますが、メンテナに悪い印象を与え、対応を後回しにされる可能性が有ります。プロジェクトの [行動規範](https://github.com/huggingface/transformers/blob/master/CODE_OF_CONDUCT.md) を必ず読んでください。

### 環境情報を含める[[including-your-environment-information]]

Transformers には、環境について必要な情報を全て取得するユーティリティが用意されています。ターミナルで次のように入力するだけです。

```
transformers-cli env
```

すると、次のような出力が得られるはずです。

```out

- `transformers` version: 4.12.0.dev0
- Platform: Linux-5.10.61-1-MANJARO-x86_64-with-arch-Manjaro-Linux
- Python version: 3.7.9
- PyTorch version (GPU?): 1.8.1+cu111 (True)
- Tensorflow version (GPU?): 2.5.0 (True)
- Flax version (CPU?/GPU?/TPU?): 0.3.4 (cpu)

- JaxLib version: 0.1.65

```

`transformers-cli env` コマンドの先頭に `!` を付ければノートブックのセルから実行することも出来ます。その結果をコピーして、Issue の冒頭に貼り付けてください。

### 人をタグ付けする[[tagging-people]]

`@` の後に GitHub のハンドルを入力して人をタグ付けすると、その人に通知が届きます。Issue に気づき、早めに返信してくれるかもしれません。但し、控えめに使ってください。直接関係しないことで通知されるのを好まない人もいます。

バグに関係するソースファイルを見たのであれば、問題の原因だと思う行を最後に変更した人をタグ付けするとよいでしょう。この情報は、その行を GitHub 上で選択して「View git blame」をクリックすると分かります。

そうでない場合は、テンプレートがタグ付けする人の候補を提示してくれます。一般に、タグ付けは3人までにしてください。

```

その後に最小再現例を貼り付け、最後に3つのバッククォートだけの新しい行を入力します。これでコードが適切に整形されます。

再現例が作れなかった場合は、エラーが発生するまでに行った操作を、順を追って分かり易く説明してください。エラーが出た Google Colab ノートブックへのリンクがあれば、含めてください。共有する情報が多いほど、メンテナは返信し易くなります。

いずれの場合も、表示されているエラーメッセージは全部コピーして貼り付けてください。Colab で作業している場合は、スタックトレースの一部のフレームが自動で折りたたまれていることがあります。コピーする前に展開しておきましょう。コードのサンプルと同じように、エラーメッセージも3つのバッククォートの行同士の間に置き、適切に整形してください。

### 期待する動作を説明する[[describing-the-expected-behavior]]

何が得られると期待していたのかを数行で説明し、メンテナが問題を完全に把握出来るようにします。この部分はたいてい自明なので1文で済むはずですが、場合によっては沢山書くこともあります。

## そのあとは？[[and-then-what]]

Issue を起票したら、全て問題なく表示されているかを手早く確認してください。間違えた場合は Issue を編集出来ます。問題が当初の想定と違うと気づいたら、タイトルを変更することも出来ます。

回答がないからといって、メンテナに何度も催促の通知を送っても効果はありません。数日たってもだれも助けてくれないなら、おそらく問題をだれも理解出来なかったのでしょう。再現例に戻ることをためらわないでください。もっと短く、要点を絞れないでしょうか。1週間たっても回答がなければ、問題についての情報を追記して Issue を編集した上で、助けを求めるメッセージを丁寧に残すことも出来ます。
