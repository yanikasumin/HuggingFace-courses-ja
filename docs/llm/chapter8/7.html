章末クイズ

この章で学んだことをテストしましょう。

1. Python のトレースバックはどの順序で読むべきですか？

もう一度考えてみましょう。他の多くのプログラミング言語は例外を先頭に出力しますが、Python はこの点で特殊です。
正解です。Python のトレースバックは例外が一番下に表示されるため、ターミナルで作業しているときに最後の行として目に入り、デバッグしやすいという利点があります。

2. 最小再現例とは何ですか？

Transformer モデルを自分でゼロから実装するのはとても勉強になりますが、ここで話題にしているのはそれではありません。
正解です。最小再現例は、ライブラリのメンテナがあなたの問題を再現する助けになり、解決策をより早く見つけられます。
もう一度考えてみましょう。Issue を起票するときに、直面しているエラーのスクリーンショットを添えたくなるものですが、そうすると他の人がエラーを再現するのが非常に難しくなります。
惜しいです。エラーを示す Google Colab ノートブックを共有するのは役に立つこともありますが、短く、関係するコードだけを含むものにしてください。

助けを求めるフォーラムトピックのタイトルとして、よい選択肢はどれですか？

トレースバックの最後の行を含めるのは説明的ではありますが、これはトピックの本文に回すほうがよいでしょう。もう一度考えてみましょう！
もう一度考えてみましょう。これも有益な情報ではありますが、おそらく本文に回すのが最適です。
よい選択です。このタイトルは簡潔で、何が問題なのか（つまり、GPT-3 が 🤗 Transformers でサポートされていないこと）について読み手に手がかりを与えます。
よい選択です。質問形式のトピックタイトルは、問題をコミュニティに伝える優れた方法です。

4. trainer.train() を実行しようとしたところ、エラーの発生箇所を正確に教えてくれない不可解なエラーに直面したとします。学習パイプラインでエラーを最初に探すべき場所は次のどれですか？

オプティマイザにバグがある可能性はありますが、これは通常、学習パイプラインのかなり後のステップなので、まず先に確認すべきことが他にあります。もう一度考えてみましょう！
評価は通常、1エポック分の学習が終わった後に行うものなので、まず学習パイプラインのもっと早い場所を確認すべきです。
正解です。データを調べることはほぼ常に最初にすべきことです。テキストが適切にエンコードされているか、期待する特徴を持っているかなどを確認します。
もう一度考えてみましょう。これは最初に確認すべきことに非常に近いです。データローダに渡すオブジェクトは何でしたか？

5. CUDA エラーをデバッグする最良の方法は何ですか？

CUDA のエラーメッセージは通常あまり有益な情報を含まないので、それではだれの助けにもなりません。
そのとおりです。そうすれば、よりよいエラーメッセージが得られるはずです。
それは他のエラーの場合にすることです。CUDA の操作の多くは非同期で実行されるため、原因となった処理とは別の箇所でエラーが報告されることがあります。
バッチサイズを減らすのは、CUDA のメモリ不足エラーに対処するのには通常よい戦略ですが、この問題には当てはまりません。もう一度考えてみましょう！
もう一度考えてみましょう。カーネルを再起動しても、エラーが魔法のように消えたりはしません。

6. GitHub の Issue で報告したバグを修正してもらうには、どうするのが最善ですか？

はい、それがメンテナにあなたのバグを見つけてもらう最良の方法です。他にもすべきことはありますか？
それで助けが得られる可能性は低く、むしろ無視されるようになるでしょう。
それは間違いなくメンテナの助けになります。バグの発生源と修正方法が見つかれば、プルリクエストを作成することさえできます。他にもすべきことはありますか？

7. 1つのバッチへの過学習が通常よいデバッグ手法なのはなぜですか？

データセット全体で学習する場合、過学習は確かに、モデルが新しいサンプルに汎化しない兆候になりえます。しかしデバッグでは、通常はデータセット全体で学習するわけではありません。もう一度考えてみましょう！
正解です。サンプルが2つしかないような小さなバッチでも、モデルに学習能力があるかどうかをすばやく確認できます。
もう一度考えてみましょう。テンソルの形状がずれていれば、1つのバッチでも学習は確実にできません。

8. 🤗 Transformers リポジトリで新しい Issue を作成するとき、transformers-cli env で計算環境の詳細を含めるのがよい考えなのはなぜですか？

正解です。ライブラリのメジャーバージョンごとに API に変更がある場合があるため、使っている具体的なバージョンが分かると問題の絞り込みに役立ちます。他の利点は何ですか？
正解です。エラーは使用している特定のオペレーティングシステムが原因で発生することがあり、それが分かるとメンテナがローカルで再現する助けになります。ただし、それだけが理由ではありません。
正解です。この章で見たように、GPU や CPU で実行されるコードは異なる結果やエラーを生むことがあり、使っているハードウェアが分かるとメンテナの注意を集中させる助けになります。ただし、これだけが利点ではありません。
