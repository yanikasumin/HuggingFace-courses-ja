TRL で GRPO を実装する

このページでは、Transformer Reinforcement Learning（TRL）ライブラリを使って Group Relative Policy Optimization（GRPO）を実装する方法を学びます。最小限のコードで実践的な実装に焦点を当てます。

TRL の GRPOTrainer が GRPO の主要な概念をどのように実装しているのか、TRL の公式ドキュメントに掲載されているコード例を使って解説します。

💡 ヒント

この章は TRL の初心者を対象としています。すでに TRL に馴染みがある方は、GRPO の Open R1 による実装もチェックするとよいでしょう。

まず、GRPO アルゴリズムの重要な概念を思い出しましょう。

  • グループの形成： モデルは各プロンプトに対して複数の補完を生成します。
  • 選好の学習： モデルは、補完のグループを比較する報酬関数から学びます。
  • 学習の設定： モデルは、学習プロセスを制御するための設定を使います。

GRPO を実装するために必要なことは何でしょうか？

  • プロンプトのデータセットを定義する。
  • 補完のリストを受け取り、報酬のリストを返す報酬関数を定義する。
  • GRPOConfig で学習プロセスを設定する。
  • GRPOTrainer を使ってモデルを学習する。

GRPO 学習を始めるための最小限の例はこちらです。

from trl import GRPOTrainer, GRPOConfig
from datasets import load_dataset

# 1. データセットを読み込む
dataset = load_dataset("your_dataset", split="train")


# 2. 簡単な報酬関数を定義する
def reward_func(completions, **kwargs):
    """例: 長い補完に報酬を与える"""
    return [float(len(completion)) for completion in completions]


# 3. 学習を設定する
training_args = GRPOConfig(
    output_dir="output",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=2,
    logging_steps=10,
)

# 4. 初期化して学習する
trainer = GRPOTrainer(
    model="your_model",  # 例: "Qwen/Qwen2-0.5B-Instruct"
    args=training_args,
    train_dataset=dataset,
    reward_funcs=reward_func,
)
trainer.train()

主要な構成要素

1. データセットの形式

データセットには、モデルが応答するプロンプトが含まれている必要があります。GRPO トレーナーは、各プロンプトに対して複数の補完を生成し、報酬関数を使ってそれらを比較します。

2. 報酬関数

報酬関数は決定的に重要です。モデルがどう学ぶかを決めるためです。実践的な例を2つ示します。

# 例1: 補完の長さに基づく報酬
def reward_length(completions, **kwargs):
    return [float(len(completion)) for completion in completions]


# 例2: パターンへの一致に基づく報酬
import re


def reward_format(completions, **kwargs):
    pattern = r"^<think>.*?</think><answer>.*?</answer>$"
    return [1.0 if re.match(pattern, c) else 0.0 for c in completions]

3. 学習の設定

GRPOConfig で考慮すべき主要なパラメータ：

training_args = GRPOConfig(
    # 必須パラメータ
    output_dir="output",
    num_train_epochs=3,
    num_generation=4,  # 各プロンプトに対して生成する補完の数
    per_device_train_batch_size=4,  # すべての生成を1つのデバイスバッチで取得したい
    # 任意だが便利
    gradient_accumulation_steps=2,
    learning_rate=1e-5,
    logging_steps=10,
    # GRPO 固有（任意）
    use_vllm=True,  # 生成を高速化
)

num_generation パラメータは、グループサイズ、すなわちモデルが各プロンプトに対して何件の異なる補完を生成するかを定義するため、GRPO にとって特に重要です。これは他の RL 手法との重要な差別化要因です。

  • 小さすぎる場合（例： 2〜3）： 意味のある比較のための多様性が十分に得られない場合があります
  • 推奨（4〜16）： 多様性と計算効率の良いバランスが得られます
  • より大きな値： 学習が改善する可能性がありますが、計算コストが大幅に増加します

グループサイズは、計算リソースとタスクの複雑さに基づいて選ぶべきです。簡単なタスクでは、より小さなグループ（4〜8）で十分な場合があり、より複雑な推論タスクでは、より大きなグループ（8〜16）の恩恵を受けられます。

成功のためのヒント

  1. メモリ管理： GPU メモリに基づいて per_device_train_batch_size と gradient_accumulation_steps を調整してください。
  2. 速度： モデルがサポートされている場合は、use_vllm=True を有効にして生成を高速化してください。
  3. 監視： 学習中に記録されるメトリクスを注視してください。 - reward： 補完全体の平均報酬 - reward_std： 報酬グループ内の標準偏差 - kl： 参照モデルからの KL ダイバージェンス

報酬関数の設計

DeepSeek R1 論文は、報酬関数の設計について、皆さん自身の GRPO 実装に適応できる効果的なアプローチをいくつか示しています。

1. 長さベースの報酬

実装が最も簡単な報酬の一つが、長さベースの報酬です。より長い補完に報酬を与えることができます。

def reward_len(completions, **kwargs):
    ideal_length = 20
    return [-abs(ideal_length - len(completion)) for completion in completions]

この報酬関数は、短すぎる補完や長すぎる補完にペナルティを与え、理想的な長さである20トークンに近い補完を生成するようモデルを促します。

2. 検証可能なタスクのためのルールベースの報酬

客観的に正しい答えを持つタスク（数学やコーディングなど）については、ルールベースの報酬関数を実装できます。

def problem_reward(completions, answers, **kwargs):
    """検証可能な答えを持つ数学問題のための報酬関数
    completions: 評価する補完のリスト
    answers: データセットの問題に対する答えのリスト
    """

    rewards = []
    for completion, correct_answer in zip(completions, answers):
        # 補完から答えを取り出す
        try:
            # これは簡略化した例です。適切な解析が必要になります
            answer = extract_final_answer(completion)
            # 二値報酬: 正しければ1、誤っていれば0
            reward = 1.0 if answer == correct_answer else 0.0
            rewards.append(reward)
        except:
            # 答えを解析できない場合は、低い報酬を与える
            rewards.append(0.0)

    return rewards

3. 形式ベースの報酬

適切な形式に報酬を与えることもできます。これは DeepSeek R1 の学習において重要でした。

def format_reward(completions, **kwargs):
    """望ましい形式に従った補完に報酬を与える"""
    # 例: 補完が think の後に answer が続く形式に従っているかをチェックする
    pattern = r"<think>(.*?)</think>\s*<answer>(.*?)</answer>"

    rewards = []
    for completion in completions:
        match = re.search(pattern, completion, re.DOTALL)
        if match:
            # 両方のセクションに十分な内容があるかをチェックする
            think_content = match.group(1).strip()
            answer_content = match.group(2).strip()

            if len(think_content) > 20 and len(answer_content) > 0:
                rewards.append(1.0)
            else:
                rewards.append(
                    0.5
                )  # 形式は正しいが内容が乏しい場合の部分的な報酬
        else:
            rewards.append(0.0)  # 形式が正しくない場合は報酬なし

    return rewards

これらの例は、正しさ、形式、組み合わされた信号に焦点を当て、DeepSeek R1 の学習プロセスに着想を得た報酬関数をどう実装できるかを示しています。
