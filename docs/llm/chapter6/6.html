WordPiece によるトークン化

WordPiece は、Google が BERT の事前学習のために開発したトークン化アルゴリズムです。その後、DistilBERT、MobileBERT、Funnel Transformers、MPNET など、BERT をベースにした数多くの Transformer モデルで再利用されてきました。学習方法の面では BPE とよく似ていますが、実際のトークン化のやり方は異なります。

💡 ヒント

💡 この節では WordPiece を深く掘り下げ、完全な実装を示すところまで扱います。トークン化アルゴリズムの概要だけ知りたい場合は、最後まで読み飛ばしても構いません。

学習アルゴリズム

⚠️ 注意

⚠️ Google は WordPiece の学習アルゴリズムの実装をオープンソース化したことがないため、以下は公開文献に基づいた私たちの最善の推測です。100% 正確ではない可能性があります。

BPE と同様に、WordPiece も、モデルが使う特殊トークンと初期アルファベットを含む小さな語彙から始まります。WordPiece はプレフィックス（BERT の場合は ## のようなもの）を付けることでサブワードを識別するため、各単語はまず、単語内のすべての文字にそのプレフィックスを付けて分割されます。たとえば "word" は次のように分割されます。

w ##o ##r ##d

したがって、初期アルファベットには、単語の先頭に現れるすべての文字と、WordPiece のプレフィックスを前に付けた形で単語の中に現れる文字が含まれます。

次に、やはり BPE と同様に、WordPiece はマージルールを学習します。主な違いは、マージするペアの選び方です。最も頻繁なペアを選ぶ代わりに、WordPiece は次の式で各ペアのスコアを計算します。

$$\mathrm{score} = (\mathrm{freq_of_pair}) / (\mathrm{freq_of_first_element} \times \mathrm{freq_of_second_element})$$

ペアの頻度を、その構成要素それぞれの頻度の積で割ることで、このアルゴリズムは、各トークンのコーパス内での出現頻度が比較的低いペアの結合を優先する傾向があります。たとえば ("un", "##able") というペアは、コーパスの中で非常に頻繁に現れたとしても、必ずしもマージされません。"un" と "##able" はそれぞれ他の多くの単語にも現れる可能性が高く、頻度が高いためです。対照的に ("hu", "##gging") のようなペアは、おそらくより速くマージされます（"hugging" という単語がコーパスに頻繁に現れると仮定すれば）。"hu" と "##gging" は個々にはあまり頻繁でない可能性が高いためです。

BPE の学習例で使ったのと同じ語彙を見てみましょう。

("hug", 10), ("pug", 5), ("pun", 12), ("bun", 4), ("hugs", 5)

この場合の分割は次のようになります。

("h" "##u" "##g", 10), ("p" "##u" "##g", 5), ("p" "##u" "##n", 12), ("b" "##u" "##n", 4), ("h" "##u" "##g" "##s", 5)

したがって初期語彙は ["b", "h", "p", "##g", "##n", "##s", "##u"] になります（ここでは特殊トークンのことは忘れておきます）。最も頻繁なペアは ("##u", "##g")（20回出現）ですが、"##u" 自体の頻度が非常に高いため、そのスコアは最高にはなりません（1 / 36 です）。"##u" を含むペアはすべて同じスコア（1 / 36）になるので、最高スコアは "##u" を含まない唯一のペア ("##g", "##s") の 1 / 20 となり、最初に学ぶマージは ("##g", "##s") -> ("##gs") です。

マージの際には、2つのトークンの間にある ## を取り除く点に注意してください。そのため "##gs" を語彙に追加し、コーパスの単語にマージを適用します。

Vocabulary: ["b", "h", "p", "##g", "##n", "##s", "##u", "##gs"]
Corpus: ("h" "##u" "##g", 10), ("p" "##u" "##g", 5), ("p" "##u" "##n", 12), ("b" "##u" "##n", 4), ("h" "##u" "##gs", 5)

この時点で "##u" は考えられるすべてのペアに含まれているため、すべてのペアが同じスコアになります。ここでは最初のペアがマージされたとして、("h", "##u") -> "hu" とします。すると次のようになります。

Vocabulary: ["b", "h", "p", "##g", "##n", "##s", "##u", "##gs", "hu"]
Corpus: ("hu" "##g", 10), ("p" "##u" "##g", 5), ("p" "##u" "##n", 12), ("b" "##u" "##n", 4), ("hu" "##gs", 5)

次に良いスコアは ("hu", "##g") と ("hu", "##gs") が分け合います（他のすべてのペアの 1/21 に対して 1/15）。そこで、最大のスコアを持つ最初のペアがマージされます。

Vocabulary: ["b", "h", "p", "##g", "##n", "##s", "##u", "##gs", "hu", "hug"]
Corpus: ("hug", 10), ("p" "##u" "##g", 5), ("p" "##u" "##n", 12), ("b" "##u" "##n", 4), ("hu" "##gs", 5)

この調子で、目的の語彙サイズに到達するまで続けます。

トークン化アルゴリズム

トークン化の方法は WordPiece と BPE で異なります。WordPiece は、学習したマージルールではなく最終的な語彙だけを保存します。トークン化したい単語から始めて、WordPiece は語彙に含まれる最長のサブワードを見つけ、そこで分割します。たとえば、先ほどの例で学んだ語彙を使うと、単語 "hugs" について、先頭から始まるサブワードのうち語彙に含まれる最長のものは "hug" です。そこで分割すると ["hug", "##s"] が得られます。次に "##s" を見ると、これも語彙に含まれているので、"hugs" のトークン化は ["hug", "##s"] となります。

BPE の場合、学んだマージを順番に適用して ["hu", "##gs"] とトークン化したはずです。このように符号化の結果が異なります。

別の例として、単語 "bugs" がどうトークン化されるか見てみましょう。"b" は単語の先頭から始まるサブワードのうち語彙に含まれる最長のものなので、そこで分割して ["b", "##ugs"] を得ます。次に "##u" は "##ugs" の先頭から始まるサブワードのうち語彙に含まれる最長のものなので、そこで分割して ["b", "##u, "##gs"] を得ます。最後に "##gs" が語彙に含まれているので、この最後のリストが "bugs" のトークン化結果となります。

トークン化の途中で語彙に含まれるサブワードが見つからなくなった場合、単語全体が未知語としてトークン化されます。たとえば "mug" は ["[UNK]"] とトークン化され、"bum" も同様です（"b" と "##u" から始められても、"##m" は語彙に含まれていないため、結果のトークン化は ["b", "##u", "[UNK]"] ではなく ["[UNK]"] になります）。これも BPE との違いの1つです。BPE は語彙に含まれていない個々の文字だけを未知語として分類します。

学習の準備ができました。各ペアのスコアを計算する関数を書きましょう。学習の各ステップで必要になります。

def compute_pair_scores(splits):
    letter_freqs = defaultdict(int)
    pair_freqs = defaultdict(int)
    for word, freq in word_freqs.items():
        split = splits[word]
        if len(split) == 1:
            letter_freqs[split[0]] += freq
            continue
        for i in range(len(split) - 1):
            pair = (split[i], split[i + 1])
            letter_freqs[split[i]] += freq
            pair_freqs[pair] += freq
        letter_freqs[split[-1]] += freq

    scores = {
        pair: freq / (letter_freqs[pair[0]] * letter_freqs[pair[1]])
        for pair, freq in pair_freqs.items()
    }
    return scores

続けるには、このマージを splits 辞書に適用する必要があります。そのための関数も書きましょう。

def merge_pair(a, b, splits):
    for word in word_freqs:
        split = splits[word]
        if len(split) == 1:
            continue
        i = 0
        while i < len(split) - 1:
            if split[i] == a and split[i + 1] == b:
                merge = a + b[2:] if b.startswith("##") else a + b
                split = split[:i] + [merge] + split[i + 2 :]
            else:
                i += 1
        splits[word] = split
    return splits

新しいテキストをトークン化するには、事前トークン化して分割し、各単語にトークン化アルゴリズムを適用します。つまり、最初の単語の先頭から始まる最大のサブワードを探して分割し、2番目の部分に対して同じ処理を繰り返します。これを、その単語の残りと、テキスト内の後続の単語についても続けます。

```python
def encode_word(word):
    tokens = []
    while len(word) > 0:
        i = len(word)
        while i > 0 and word[:i] not in vocab:
            i -= 1
        if i == 0:
            return ["[UNK]"]
        tokens.append(word[:i])
        word = word[i:]
        if len(word) > 0:
            word = f"##{word}"
    return tokens

```python
def tokenize(text):
    pre_tokenize_result = tokenizer._tokenizer.pre_tokenizer.pre_tokenize_str(text)
    pre_tokenized_text = [word for word, offset in pre_tokenize_result]
    encoded_words = [encode_word(word) for word in pre_tokenized_text]
    return sum(encoded_words, [])
