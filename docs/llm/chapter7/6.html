これまでは主に、事前学習済みモデルを使い、事前学習の重みを再利用して新しい用途向けにファインチューニングしてきました。Chapter 1 で見たように、これは一般に 転移学習 と呼ばれ、ラベル付きデータが少ない現実の用途の殆どで Transformer モデルを活用する上で非常に有効な戦略です。

この章では別のアプローチを取り、新しいモデルを完全にゼロから学習します。データが大量にあり、利用可能なモデルの事前学習データとは大きく異なる場合には、この方法が適しています。但し、言語モデルの事前学習には、既存モデルのファインチューニングと比べてかなり多くの計算リソースが必要です。

新しいモデルの学習が意味を持つ例としては、楽譜のデータ、DNA のような分子配列、プログラミング言語のデータセットなどがあります。プログラミング言語は近年、OpenAI の Codex モデルを基盤とする TabNine や GitHub の Copilot のような、長いコード列を生成出来るツールによって注目を集めています。このテキスト生成のタスクに最も適しているのは、GPT-2 のような自己回帰型の言語モデル、つまり因果言語モデルです。

このセクションでは、コード生成モデルの縮小版を作ります。完全な関数やクラスではなく、1行の補完に焦点を当て、Python コードの一部を使います。Python でデータを扱う作業では、matplotlib、seaborn、pandas、scikit-learn といったライブラリからなる Python のデータサイエンススタックに頻繁に触れます。これらのフレームワークを使う時は特定のコマンドを調べる必要がよくあるので、モデルにこれらの呼び出しを補完してもらえると便利です。

Chapter 6 では、Python のソースコードを処理する為の効率的なトークナイザを作りました。しかし、モデルの事前学習に使う大規模なデータセットはまだ用意出来ていません。ここでは、GitHub のリポジトリから集めた Python コードのコーパスにこのトークナイザを適用します。その後、Trainer API と 🤗 Accelerate を使ってモデルを学習します。早速始めましょう！

これは、このセクションで示すコードを使って実際に学習し、Hub にアップロードしたモデルを紹介するものです。こちら で確認出来ます。テキスト生成にはランダム性がある為、得られる結果は少し異なるはずです。

データを集める

Python のコードは、GitHub のようなコードリポジトリに大量に存在します。全ての Python リポジトリをスクレイピングすれば、データセットを作ることが出来ます。これは、大規模な GPT-2 モデルを事前学習する為に Transformers の教科書 で採用されたアプローチです。著者らは、約2,000万件の Python ファイルを含む約180 GB の GitHub ダンプ codeparrot からデータセットを構築し、Hugging Face Hub で共有しました。

但し、コーパス全体で学習すると時間と計算リソースを大量に消費します。また、必要なのは Python のデータサイエンススタックに関係するデータセットの部分だけです。そこで、先ず codeparrot データセットを、このスタックのライブラリのいずれかを含むファイルだけに絞り込みます。

データセットが大きい為、ダウンロードは避けたい所です。代わりに、ストリーミング機能を使ってその場で絞り込みます。先程挙げたライブラリを使っているコードサンプルを絞り込む為に、次の関数を使います。

def any_keyword_in_string(string, keywords):
    for keyword in keywords:
        if keyword in string:
            return True
    return False

2つの例で試してみましょう。

filters = ["pandas", "sklearn", "matplotlib", "seaborn"]
example_1 = "import numpy as np"
example_2 = "import pandas as pd"

print(
    any_keyword_in_string(example_1, filters), any_keyword_in_string(example_2, filters)
)

```python out False True

これを使って、データセットをストリーミングしながら目的の要素を絞り込む関数を作れます。

```py
from collections import defaultdict
from tqdm import tqdm
from datasets import Dataset


def filter_streaming_dataset(dataset, filters):
    filtered_dict = defaultdict(list)
    total = 0
    for sample in tqdm(iter(dataset)):
        total += 1
        if any_keyword_in_string(sample["content"], filters):
            for k, v in sample.items():
                filtered_dict[k].append(v)
    print(f"フィルタリング後のデータの割合: {len(filtered_dict['content'])/total:.2%}")
    return Dataset.from_dict(filtered_dict)

あとは、この関数をストリーミングデータセットに適用するだけです。

## データセットを準備する








最初のステップは、データをトークン化して学習に使えるようにすることです。主な目的は短い関数呼び出しの自動補完なので、コンテキストサイズは比較的小さく出来ます。そうすると、モデルをはるかに速く学習でき、必要なメモリも大幅に少なくて済みます。アプリケーションでより多くのコンテキストが必要な場合（例えば、関数定義のあるファイルをもとにモデルにユニットテストを書かせたい場合）は、この数値を大きくして下さい。但し、その分 GPU メモリの使用量も増える点に注意して下さい。

ここでは、GPT-2 の 1,024 や GPT-3 の 2,048 とは異なり、コンテキストサイズを128トークンに固定します。

殆どのドキュメントは128トークンよりはるかに長い為、入力を最大長で単純に切り捨てると、データセットの大部分を失ってしまいます。代わりに、`return_overflowing_tokens` オプションを使って入力全体をトークン化し、[Chapter 6](/course/chapter6/4) で行ったように複数のチャンクに分割します。また、`return_length` オプションも使って、作成された各チャンクの長さを自動的に取得します。最後のチャンクはコンテキストサイズより小さくなることが多く、パディングの問題を避ける為にこれらの断片は除去します。データは十分にあるので、除去しても問題ありません。

この2つの例からは、合計34個のセグメントが得られたことが分かります。チャンクの長さを見ると、両ドキュメントの末尾のチャンクは128トークン未満（それぞれ117と41）です。これらは全チャンクのごく一部なので、安心して除去出来ます。`overflow_to_sample_mapping` フィールドを使えば、どのチャンクがどの入力サンプルに属していたかも復元出来ます。

この操作では、Datasets の `Dataset.map()` 関数の便利な特徴を使っています。1対1の対応を必要としない点です。[section 3](/course/chapter7/3) で見たように、入力バッチより多い、又は少ない要素を持つバッチを作成出来ます。これは、データ拡張やデータの絞り込みなど、要素数を変える操作を行う時に便利です。今回のケースでは、各要素を指定したコンテキストサイズのチャンクにトークン化することで、各ドキュメントから多くのサンプルを作成しています。既存の列はサイズが競合するので、削除するのを忘れないようにして下さい。保持したい場合は、適切に複製して `Dataset.map()` の呼び出しの中で返すことも出来ます。

```py
def tokenize(element):
    outputs = tokenizer(
        element["content"],
        truncation=True,
        max_length=context_length,
        return_overflowing_tokens=True,
        return_length=True,
    )
    input_batch = []
    for length, input_ids in zip(outputs["length"], outputs["input_ids"]):
        if length == context_length:
            input_batch.append(input_ids)
    return {"input_ids": input_batch}


tokenized_datasets = raw_datasets.map(
    tokenize, batched=True, remove_columns=raw_datasets["train"].column_names
)
tokenized_datasets

## 🤗 Accelerate で学習する

`Trainer` を使ったモデルの学習方法は見てきました。ある程度のカスタマイズは可能です。しかし、学習ループを完全に制御したい場合や、標準的な学習処理にはない特殊な処理を組み込みたい場合もあります。そのような場合には Accelerate が最適です。このセクションでは、それを使ってモデルを学習する手順を順に追っていきます。更に面白くする為に、学習ループに一工夫も加えます。








関心があるのは主にデータサイエンスライブラリに対する的確な自動補完なので、これらのライブラリを多く使う学習サンプルにより大きな重みを与えるのが理にかなっています。こうしたサンプルは、`plt`、`pd`、`sk`、`fit`、`predict` といったキーワードで簡単に識別出来ます。これらは `matplotlib.pyplot`、`pandas`、`sklearn` の最も頻繁なインポート名であり、後者の fit/predict パターンでもあります。これらがそれぞれ単一のトークンとして表現されるなら、入力シーケンスに含まれているかを簡単に確認出来ます。トークンには空白の接頭辞が付く場合もあるので、トークナイザの語彙ではそのバージョンも確認します。動作を検証する為に、複数のトークンに分割されるはずのテスト用トークンを1つ追加します。

うまく動いているようです！入力シーケンス、ロジット、先程選んだキートークンを入力として受け取るカスタム損失関数を書くことが出来ます。

先ず、ロジットと入力を揃える必要があります。次のトークンが現在のトークンのラベルになる為、入力シーケンスを右に1つずらしたものがラベルになります。モデルは最初のトークンについては予測を行わないので、ラベルを入力シーケンスの2番目のトークンから始めることでこれを実現出来ます。次に、入力シーケンス全体の後に続くトークンのラベルは存在しない為、最後のロジットを切り取ります。これで、サンプルごとの損失を計算し、各サンプル内の全てのキーワードの出現回数を数えることが出来ます。最後に、出現回数を重みとして、全てのサンプルの重み付き平均を計算します。キーワードを含まないサンプルを全て捨ててしまわないよう、重みには1を加えます。

```py
from torch.nn import CrossEntropyLoss
import torch


def keytoken_weighted_loss(inputs, logits, keytoken_ids, alpha=1.0):
    # トークン < n が n を予測するようにシフトする
    shift_labels = inputs[..., 1:].contiguous()
    shift_logits = logits[..., :-1, :].contiguous()
    # トークンごとの損失を計算する
    loss_fct = CrossEntropyLoss(reduce=False)
    loss = loss_fct(shift_logits.view(-1, shift_logits.size(-1)), shift_labels.view(-1))
    # 形状を変えて、サンプルごとに損失を平均する
    loss_per_sample = loss.view(shift_logits.size(0), shift_logits.size(1)).mean(axis=1)
    # 重み付けを計算してスケールする
    weights = torch.stack([(inputs == kt).float() for kt in keytoken_ids]).sum(
        axis=[0, 2]
    )
    weights = alpha * (1.0 + weights)
    # 重み付き平均を計算する
    weighted_loss = (loss_per_sample * weights).mean()
    return weighted_loss

この素晴らしい新しい損失関数で学習を始める前に、いくつか準備が必要です。

  • データをバッチ単位で読み込むデータローダが必要です。
  • 重み減衰のパラメータを設定する必要があります。
  • 定期的に評価したいので、評価コードを関数にまとめておくのがよいでしょう。

データローダから始めましょう。データセットの形式を "torch" に設定し、適切なバッチサイズで PyTorch の DataLoader に渡すだけです。

次に、オプティマイザがどのパラメータに追加の重み減衰を適用するか分かるように、パラメータをグループ化します。通常、全てのバイアスと LayerNorm の重みはこの対象から外れます。その方法は次の通りです。

weight_decay = 0.1


def get_grouped_params(model, no_decay=["bias", "LayerNorm.weight"]):
    params_with_wd, params_without_wd = [], []
    for n, p in model.named_parameters():
        if any(nd in n for nd in no_decay):
            params_without_wd.append(p)
        else:
            params_with_wd.append(p)
    return [
        {"params": params_with_wd, "weight_decay": weight_decay},
        {"params": params_without_wd, "weight_decay": 0.0},
    ]

学習中に検証セットでモデルを定期的に評価したいので、その為の関数も書きましょう。評価用データローダを一巡し、全てのプロセスにわたって損失を集めるだけです。

def evaluate():
    model.eval()
    losses = []
    for step, batch in enumerate(eval_dataloader):
        with torch.no_grad():
            outputs = model(batch["input_ids"], labels=batch["input_ids"])

        losses.append(accelerator.gather(outputs.loss))
    loss = torch.mean(torch.cat(losses))
    try:
        perplexity = torch.exp(loss)
    except OverflowError:
        perplexity = float("inf")
    return loss.item(), perplexity.item()

損失とパープレキシティは非常に高い値ですが、まだモデルを学習していないので驚くことではありません。これで、学習スクリプトの中核である学習ループを書く準備が整いました。学習ループでは、データローダを反復し、バッチをモデルに渡します。得られたロジットでカスタム損失関数を評価出来ます。ステップを集約した時に損失が大きくならないよう、損失は勾配累積のステップ数で割ってスケールします。最適化の前に、収束を良くする為に勾配もクリッピングします。最後に、数ステップごとに新しい `evaluate()` 関数で評価セットに対するモデルの評価を行います。

```py
from tqdm.notebook import tqdm

gradient_accumulation_steps = 8
eval_steps = 5_000

model.train()
completed_steps = 0
for epoch in range(num_train_epochs):
    for step, batch in tqdm(
        enumerate(train_dataloader, start=1), total=num_training_steps
    ):
        logits = model(batch["input_ids"]).logits
        loss = keytoken_weighted_loss(batch["input_ids"], logits, keytoken_ids)
        if step % 100 == 0:
            accelerator.print(
                {
                    "samples": step * samples_per_step,
                    "steps": completed_steps,
                    "loss/train": loss.item() * gradient_accumulation_steps,
                }
            )
        loss = loss / gradient_accumulation_steps
        accelerator.backward(loss)
        if step % gradient_accumulation_steps == 0:
            accelerator.clip_grad_norm_(model.parameters(), 1.0)
            optimizer.step()
            lr_scheduler.step()
            optimizer.zero_grad()
            completed_steps += 1
        if (step % (eval_steps * gradient_accumulation_steps)) == 0:
            eval_loss, perplexity = evaluate()
            accelerator.print({"loss/eval": eval_loss, "perplexity": perplexity})
            model.train()
            accelerator.wait_for_everyone()
            unwrapped_model = accelerator.unwrap_model(model)
            unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
            if accelerator.is_main_process:
                tokenizer.save_pretrained(output_dir)
                repo.push_to_hub(
                    commit_message=f"Training in progress step {step}", blocking=False
                )
