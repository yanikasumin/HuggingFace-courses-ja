トークナイザは、テキストを（そのモデルに応じて）サブトークンに分割する前に、_正規化_ と _事前トークン化_ という2つのステップを実行します。

## 正規化[[normalization]]

<Youtube id="4IIC2jI9CaU"/>

正規化ステップでは、不要な空白の除去、小文字化、アクセント記号の除去など、一般的なクリーンアップを行います。[Unicode 正規化](http://www.unicode.org/reports/tr15/)（NFC や NFKC など）に馴染みがある方もいるかもしれませんが、これもトークナイザが適用する場合があります。

🤗 Transformers の `tokenizer` には `backend_tokenizer` という属性があり、背後にある 🤗 Tokenizers ライブラリのトークナイザにアクセスできます。

```py
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
print(type(tokenizer.backend_tokenizer))
```

```python out
<class 'tokenizers.Tokenizer'>
```

`tokenizer` オブジェクトの `normalizer` 属性には `normalize_str()` メソッドがあり、正規化がどのように行われるかを確認できます。

```py
print(tokenizer.backend_tokenizer.normalizer.normalize_str("Héllò hôw are ü?"))
```

```python out
'hello how are u?'
```

この例では `bert-base-uncased` チェックポイントを選んだため、正規化では小文字化が行われ、アクセント記号が除去されました。

> ✏️ **試してみましょう！** `bert-base-cased` チェックポイントからトークナイザを読み込み、同じ例を渡してみてください。cased 版と uncased 版のトークナイザの主な違いは何でしょうか。

## 事前トークン化[[pre-tokenization]]

<Youtube id="grlLV8AIXug"/>

次のセクションで見るとおり、トークナイザは生のテキストだけでは学習できません。まず、テキストを単語のような小さな単位に分割する必要があります。そこで事前トークン化ステップの出番です。[Chapter 2](/course/chapter2) で見たように、単語ベースのトークナイザは、生のテキストを空白と句読点で単に単語に分割できます。それらの単語が、トークナイザが学習中に学べるサブトークンの境界となります。

高速トークナイザが事前トークン化をどのように行うかを見るには、`tokenizer` オブジェクトの `pre_tokenizer` 属性の `pre_tokenize_str()` メソッドを使えます。

```py
tokenizer.backend_tokenizer.pre_tokenizer.pre_tokenize_str("Hello, how are  you?")
```

```python out
[('Hello', (0, 5)), (',', (5, 6)), ('how', (7, 10)), ('are', (11, 14)), ('you', (16, 19)), ('?', (19, 20))]
```

トークナイザがすでにオフセットを追跡していることに注目してください。これにより、前のセクションで使ったオフセットマッピングが得られます。ここでは、トークナイザは2つの空白を無視して1つに置き換えていますが、それを反映して `are` と `you` の間でオフセットがジャンプしています。

BERT トークナイザを使っているため、事前トークン化では空白と句読点で分割します。他のトークナイザでは、このステップのルールが異なる場合があります。たとえば、GPT-2 トークナイザを使うと次のようになります。

```py
tokenizer = AutoTokenizer.from_pretrained("gpt2")
tokenizer.backend_tokenizer.pre_tokenizer.pre_tokenize_str("Hello, how are  you?")
```

こちらも空白と句読点で分割しますが、空白を保持して `Ġ` 記号に置き換えるため、トークンをデコードすれば元の空白を復元できます。

```python out
[('Hello', (0, 5)), (',', (5, 6)), ('Ġhow', (6, 10)), ('Ġare', (10, 14)), ('Ġ', (14, 15)), ('Ġyou', (15, 19)),
 ('?', (19, 20))]
```

また、BERT トークナイザとは異なり、このトークナイザは二重の空白を無視しないことにも注意してください。

最後の例として、SentencePiece アルゴリズムに基づく T5 トークナイザを見てみましょう。

```py
tokenizer = AutoTokenizer.from_pretrained("t5-small")
tokenizer.backend_tokenizer.pre_tokenizer.pre_tokenize_str("Hello, how are  you?")
```

```python out
[('▁Hello,', (0, 6)), ('▁how', (7, 10)), ('▁are', (11, 14)), ('▁you?', (16, 20))]
```

GPT-2 トークナイザと同様に、このトークナイザも空白を保持して特定のトークン（`_`）に置き換えますが、T5 トークナイザは空白でのみ分割し、句読点では分割しません。また、文の先頭（`Hello` の前）にデフォルトで空白が追加され、`are` と `you` の間の二重の空白が無視されていることにも注意してください。

いくつかの異なるトークナイザがテキストをどう処理するかを見てきたので、次は背後にあるアルゴリズム自体を探っていきます。まず、幅広く適用できる SentencePiece を簡単に見てから、次の3つのセクションで、サブワードトークン化に使われる3つの主要なアルゴリズムの仕組みを調べます。

## SentencePiece[[sentencepiece]]

[SentencePiece](https://github.com/google/sentencepiece) はテキストの前処理のためのトークン化アルゴリズムで、次の3つのセクションで見るどのモデルとも併用できます。テキストを Unicode 文字のシーケンスとして扱い、空白を特殊文字 `▁` に置き換えます。Unigram アルゴリズムと組み合わせて使う場合（[第7節](/course/chapter6/7) を参照）、事前トークン化ステップすら不要であり、空白文字を使わない言語（中国語や日本語など）でとても役立ちます。

SentencePiece のもう1つの主な特徴は、*可逆なトークン化*（reversible tokenization）です。空白に特別な処理をしないため、トークンのデコードは、単にトークンを連結し、`_` を空白に置き換えるだけで行えます。その結果、正規化されたテキストが得られます。先に見たとおり、BERT トークナイザは繰り返しの空白を除去するため、そのトークン化は可逆ではありません。

## アルゴリズムの概要[[algorithm-overview]]

以降のセクションでは、3つの主要なサブワードトークン化アルゴリズム、すなわち BPE（GPT-2 などで使用）、WordPiece（BERT などで使用）、Unigram（T5 などで使用）を詳しく見ていきます。始める前に、それぞれの仕組みの簡単な概要を示します。今は意味が分からなくても、次の各セクションを読んだ後にこの表に戻ってきてください。


モデル | BPE | WordPiece | Unigram
:----:|:---:|:---------:|:------:
学習 | 小さな語彙から始めて、トークンをマージするルールを学習する | 小さな語彙から始めて、トークンをマージするルールを学習する | 大きな語彙から始めて、トークンを除去するルールを学習する
学習ステップ | 最も一般的なペアに対応するトークンをマージする | ペアの頻度に基づく最良のスコアを持つペアに対応するトークンをマージし、個々のトークンの頻度が低いペアを優先する | コーパス全体で計算した損失を最小化するようなトークンを語彙からすべて除去する
学習するもの | マージルールと語彙 | 語彙のみ | 各トークンのスコアを伴う語彙
エンコーディング | 単語を文字に分割し、学習で得たマージを適用する | 先頭から始まる、語彙に含まれる最長のサブワードを見つけ、単語の残りについても同様に行う | 学習で得たスコアを使い、最も可能性の高いトークンへの分割を見つける

では、BPE に入っていきましょう！
