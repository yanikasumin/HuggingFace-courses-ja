# LoRA（低ランク適応）

大規模言語モデルのファインチューニングには、多くの計算資源が必要です。LoRA は、学習するパラメータを少数に絞って大規模言語モデルをファインチューニングする手法です。アテンションの重みに小さな行列を追加して学習することで、学習可能なパラメータを約90%削減出来ます。

## LoRA の理解

LoRA（低ランク適応）は、パラメータ効率のよいファインチューニング手法です。事前学習済みモデルの重みを凍結し、学習可能なランク分解行列をモデルの層に挿入します。ファインチューニングで全パラメータを学習する代わりに、重みの更新を低ランク分解で小さな行列に分けます。これにより、モデルの性能を維持しながら、学習可能なパラメータ数を大幅に削減出来ます。

例えば、GPT-3 175B に適用した場合、LoRA は全パラメータのファインチューニングと比べて学習可能なパラメータを 10,000 分の 1 にし、GPU メモリ要件を 3 分の 1 にしました。LoRA の詳細は [LoRA の論文](https://arxiv.org/pdf/2106.09685)で読むことが出来ます。

LoRA は、Transformer の層にランク分解行列のペアを追加することで動作します。対象は通常、アテンションの重みです。推論時にはアダプタの重みをベースモデルにマージ出来るため、推論のレイテンシは増えません。LoRA は、リソース要件を扱い易い範囲に保ちながら、大規模言語モデルを特定のタスクやドメインに適応させる場合に特に役立ちます。

## LoRA の主な利点

1. **メモリ効率**：
   - GPU メモリに保存されるのはアダプタのパラメータのみ
   - ベースモデルの重みは凍結されたままで、より低い精度で読み込める
   - コンシューマ向け GPU でも大規模モデルのファインチューニングが可能

2. **学習時の利点**：
   - 少ない設定で PEFT/LoRA を学習処理に組み込める
   - 更にメモリ効率のよい QLoRA（量子化 LoRA）に対応

3. **アダプタの管理**：
   - チェックポイント時にアダプタの重みを保存
   - アダプタをベースモデルにマージし直す機能

## PEFT で LoRA アダプタを読み込む

[PEFT](https://github.com/huggingface/peft) は、LoRA を含む PEFT 手法の読み込みと管理に統一されたインターフェースを提供するライブラリです。異なる PEFT 手法を簡単に読み込んで切り替えられる為、様々なファインチューニング手法の実験がし易くなります。 

重みをマージしていないアダプタを試したい場合は、`load_adapter()` で事前学習済みモデルにアダプタを読み込みます。使うアダプタの重みは `set_adapter()` 関数で設定します。ベースモデルだけに戻す場合は、unload() を使って LoRA モジュールを全てアンロードします。タスク固有の重みを、このように簡単に切り替えられます。  

```python
from peft import PeftModel, PeftConfig

config = PeftConfig.from_pretrained("ybelkada/opt-350m-lora")
model = AutoModelForCausalLM.from_pretrained(config.base_model_name_or_path)
lora_model = PeftModel.from_pretrained(model, "ybelkada/opt-350m-lora")
```

## `trl` の `SFTTrainer` と LoRA で LLM をファインチューニングする

`trl` の [SFTTrainer](https://huggingface.co/docs/trl/sft_trainer) は、[PEFT](https://huggingface.co/docs/peft/en/index) ライブラリと連携して LoRA アダプタを使えます。そのため、手順は SFT と同じままで、学習が必要なパラメータの数だけを LoRA で減らせます。

この例では PEFT の `LoRAConfig` クラスを使います。設定は数ステップで済みます。

1. LoRA の設定（ランク、アルファ、ドロップアウト）を定義する
2. PEFT の設定で SFTTrainer を作成する
3. 学習してアダプタの重みを保存する

## LoRA の設定

LoRA の設定と主要なパラメータを順に見ていきましょう。

| パラメータ | 説明 |
|-----------|-------------|
| `r`（ランク） | 重みの更新に使う低ランク行列の次元。通常は 4〜32 の間。値が小さい程圧縮率は高くなるが、表現力が落ちる可能性が有る。 |
| `lora_alpha` | LoRA 層のスケーリング係数。通常はランク値の 2 倍に設定する。値が大きい程適応の効果が強くなる。 |
| `lora_dropout` | LoRA 層のドロップアウト確率。通常は 0.05〜0.1。値が大きい程学習中の過学習を防ぐのに役立つ。 |
| `bias` | バイアス項の学習を制御する。選択肢は "none"、"all"、"lora_only"。"none" がメモリ効率の面で最も一般的。 |
| `target_modules` | LoRA を適用するモデルのモジュールを指定する。"all-linear" や "q_proj,v_proj" のような特定のモジュールを指定出来る。モジュールが多い程適応の自由度は上がるが、メモリ使用量も増える。 |

> [!TIP]
> PEFT 手法を導入する時は、まず LoRA のランクを小さい値（4〜8）に設定し、学習損失の推移を監視してください。過学習を防ぐ為に検証セットを使い、可能であれば全パラメータのファインチューニングのベースラインと比較しましょう。どの手法が効くかはタスクによって変わる為、実際に試して比べることが重要です。

## TRL と PEFT の併用

TRL と組み合わせれば、PEFT の手法を使ってメモリ要件を抑えながらファインチューニング出来ます。モデルの読み込み時に `LoraConfig` を渡します。  

```python
from peft import LoraConfig

# r: LoRA の更新行列のランク次元（小さいほど圧縮率が高い）
rank_dimension = 6
# lora_alpha: LoRA 層のスケーリング係数（大きいほど適応が強い）
lora_alpha = 8
# lora_dropout: LoRA 層のドロップアウト確率（過学習の防止に役立つ）
lora_dropout = 0.05

peft_config = LoraConfig(
    r=rank_dimension,  # ランク次元 - 通常は 4〜32 の間
    lora_alpha=lora_alpha,  # LoRA のスケーリング係数 - 通常はランクの 2 倍
    lora_dropout=lora_dropout,  # LoRA 層のドロップアウト確率
    bias="none",  # LoRA のバイアスの種類。対応するバイアスが学習中に更新されます。
    target_modules="all-linear",  # LoRA を適用するモジュール
    task_type="CAUSAL_LM",  # モデルアーキテクチャのタスクの種類
)
```

上の例では、`device_map="auto"` を使ってモデルを正しいデバイスに自動的に割り当てています。モデルを特定のデバイスに手動で割り当てる場合は、`device_map={"": device_index}` のように書きます。 

次に、LoRA の設定を渡して `SFTTrainer` を定義します。

```python
# LoRA の設定で SFTTrainer を作成
trainer = SFTTrainer(
    model=model,
    args=args,
    train_dataset=dataset["train"],
    peft_config=peft_config,  # LoRA の設定
    max_seq_length=max_seq_length,  # シーケンス長の最大値
    processing_class=tokenizer,
)
```

## LoRA アダプタのマージ

LoRA で学習した後は、アダプタの重みをベースモデルにマージし直すとデプロイが簡単になります。重みが統合された単一のモデルになる為、推論時にアダプタを別々に読み込む必要がなくなります。

マージでは、メモリ管理と精度の扱いに注意が必要です。ベースモデルとアダプタの重みの両方を同時に読み込む為、十分な GPU/CPU メモリを確保してください。`transformers` で `device_map="auto"` を使うと、ハードウェアに応じてモデルに正しいデバイスが割り当てられます。 

精度は工程を通して統一してください。学習時に使った精度（例：float16）に合わせ、マージしたモデルをデプロイ用に同じ形式で保存します。 

## マージの実装

学習済みの LoRA アダプタの重みをベースモデルにマージし直す手順は、次の通りです。

```python
import torch
from transformers import AutoModelForCausalLM
from peft import PeftModel

# 1. ベースモデルを読み込む
base_model = AutoModelForCausalLM.from_pretrained(
    "base_model_name", torch_dtype=torch.float16, device_map="auto"
)

# 2. アダプタ付きの PEFT モデルを読み込む
peft_model = PeftModel.from_pretrained(
    base_model, "path/to/adapter", torch_dtype=torch.float16
)

# 3. アダプタの重みをベースモデルにマージする
merged_model = peft_model.merge_and_unload()
```

保存したモデルのサイズが想定と異なる場合は、トークナイザも併せて保存しているか確認してください。

```python
# モデルとトークナイザの両方を保存する
tokenizer = AutoTokenizer.from_pretrained("base_model_name")
merged_model.save_pretrained("path/to/save/merged_model")
tokenizer.save_pretrained("path/to/save/merged_model")
```

> ✏️ **試してみましょう！** アダプタの重みをベースモデルにマージし直してみましょう。上で定義した LoRA の設定を使い、`HuggingFaceTB/smoltalk` データセットで `deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B` モデルをファインチューニングしてください。
