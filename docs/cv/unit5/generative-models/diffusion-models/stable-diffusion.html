Stable Diffusion 入門

この章では、テキストプロンプトや画像プロンプトからユニークでフォトリアルな画像を生成する生成 AI モデルである Stable Diffusion の構成要素を紹介します。Stable Diffusion はもともと 2022 年に公開され、論文に続く Stability AI、RunwayML、ミュンヘン大学（LMU）の CompVis グループとの協力によって実現しました。

この章で学ぶこと: - Stable Diffusion の基本的な構成要素 - text-to-image、image2image、インペインティングパイプラインの使い方

Stable Diffusion が動作するために必要なもの

このセクションを面白くするために、Stable Diffusion のプロセスの基本的な構成要素を理解するためのいくつかの質問に答えていきましょう。 各構成要素はすでに Diffusers コースで取り上げられているため、ここでは簡潔に議論します。また、GAN と拡散モデルについて詳しく述べた前のセクションも参照できます。

  • Stable Diffusion は新しい情報を学習するためにどのような戦略を使いますか。
    • 拡散モデルの順方向プロセスと逆方向プロセスを使います。順方向プロセスでは、画像にガウスノイズを加えていき、最後にはランダムノイズだけが残ります。通常、ノイズが加わった最終的な画像を見分けることはできません。
    • 逆方向プロセスでは、純粋なノイズから始めて画像を徐々にノイズ除去するよう学習したニューラルネットワークがあり、最終的に実際の画像が得られます。

これらのプロセスはどちらも有限のステップ数 T の間行われます（DDPM の論文では T=1000）。プロセスは時刻 \(t_0\) に、データ分布から実際の画像をサンプリングすることから始まります。順方向プロセスでは、各時刻 t にガウス分布からノイズをサンプリングし、前の時刻の画像に加えます。より数学的な直感を得るには、拡散モデルに関する Hugging Face Blog を読んでください。

  • 画像が巨大になりうる中で、どうやって圧縮するのでしょうか。

大きな画像は、処理により多くの計算能力を必要とします。これは self-attention と呼ばれる特定の操作で非常に顕著になります。画像が大きいほど必要な計算が増え、その計算は画像のサイズに対して非常に急速に（数学者が「二次的に（quadratically）」と呼ぶ形で）増加します。 例えば、幅と高さが 128 ピクセルの画像は、幅と高さが 64 ピクセルの画像の4倍のピクセルを持ちます。self-attention の仕組み上、この大きな画像を扱うには単に4倍のメモリと計算能力で済むのではなく、実際には16倍（4×4=16）が必要になります。このため、処理に多くのリソースを必要とする非常に高解像度の画像を扱うことは困難です。 潜在拡散モデルは、変分オートエンコーダ（VAE）を使って画像を扱いやすいサイズに縮小することで、大きな画像の処理にかかる高い計算需要に対処します。アイデアは、多くの画像には繰り返しの情報や不要な情報が含まれているというものです。大量のデータで学習した VAE は、画像をはるかに小さく凝縮した形に圧縮できます。この小さいバージョンでも、元の画像の本質的な特徴は保持されます。

  • プロンプトを使っている以上、テキストと画像をどうやって融合するのでしょうか。

推論時には、見たい画像の説明と開始点としての純粋なノイズを入力でき、モデルはキャプションに合うものへとランダムな入力を「ノイズ除去」しようと最善を尽くすことが分かっています。 SD は、CLIP と呼ばれるものに基づく、事前学習済みの Transformer モデルを活用します。CLIP のテキストエンコーダは、画像キャプションを、画像とテキストを比較するために使える形に処理するよう設計されているため、画像の説明から有用な表現を作るタスクに適しています。入力プロンプトはまずトークン化され（大きな語彙に基づいて、各単語やサブワードに特定のトークンが割り当てられます）、次に CLIP のテキストエンコーダに通され、トークンごとに 768 次元（SD 1.X の場合）または 1024 次元（SD 2.X）のベクトルが得られます。一貫性を保つため、プロンプトは常時 77 トークンの長さにパディング／切り詰めされ、そのため条件付けとして使う最終表現は、プロンプトごとに 77×1024 の形状のテンソルとなります。

  • 優れた帰納バイアスをどうやって組み込むのでしょうか。

新しいもの（例えば現実的なポケモン）を生成しようとしている以上、これまで見たことのある画像（例えばアニメのポケモン）を超えていく方法が必要です。そこで U-Net と self-attention の出番です。ノイズの加わった画像が与えられたとき、モデルは画像のテキスト説明といった追加の手がかりに基づいて、ノイズ除去されたバージョンを予測するタスクを担います。では、この条件付け情報を、予測に使えるよう実際に U-Net にどうやって与えるのでしょうか。その答えは cross-attention と呼ばれるものです。U-Net の至る所に cross-attention 層が散りばめられています。 U-Net の各空間位置は、テキストの条件付けの中の異なるトークンに「注意を向ける（attend）」ことができ、プロンプトから関連情報を取り込むことができます。

Diffusers で text-to-image、image-to-image、インペインティングモデルを使う方法

このセクションでは、役立つユースケースと、Diffusers ライブラリを使ってこれらのタスクを実行する方法を紹介します。 - text-to-image 推論のステップ アイデアは、テキストプロンプトを渡し、それを出力画像に変換することです。

diffusers ライブラリを使えば、2ステップで text-to-image を動作させることができます。

まず diffusers ライブラリをインストールしましょう。

pip install diffusers

次に、パイプラインを初期化し、プロンプトを渡して推論します。

from diffusers import AutoPipelineForText2Image
import torch

pipeline = AutoPipelineForText2Image.from_pretrained(
    "runwayml/stable-diffusion-v1-5", torch_dtype=torch.float16, variant="fp16"
).to("cuda")
generator = torch.Generator(device="cuda").manual_seed(31)
image = pipeline(
    "Astronaut in a jungle, cold color palette, muted colors, detailed, 8k",
    generator=generator,
).images[0]
  • image-to-image 推論のステップ 同様のやり方でパイプラインを初期化できますが、その代わりに画像とテキストプロンプトを渡します。
import torch
from diffusers import AutoPipelineForImage2Image
from diffusers.utils import load_image, make_image_grid

pipeline = AutoPipelineForImage2Image.from_pretrained(
    "kandinsky-community/kandinsky-2-2-decoder",
    torch_dtype=torch.float16,
    use_safetensors=True,
)
pipeline.enable_model_cpu_offload()
# xFormers がインストールされていない場合、または PyTorch 2.0 以上がインストールされている場合は次の行を削除してください
pipeline.enable_xformers_memory_efficient_attention()

# パイプラインに渡す画像を読み込む:
init_image = load_image(
    "https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/cat.png"
)

# プロンプトと画像をパイプラインに渡して画像を生成する:
prompt = "cat wizard, gandalf, lord of the rings, detailed, fantasy, cute, adorable, Pixar, Disney, 8k"
image = pipeline(prompt, image=init_image).images[0]
make_image_grid([init_image, image], rows=1, cols=2)
  • インペインティングのステップ インペインティングパイプラインでは、画像、テキストプロンプト、そしてその画像内のオブジェクトに基づくマスクを渡す必要があります。マスクは画像のどこをインペインティングするかを示します。 この例では、避けたいものに影響を与えるためにネガティブプロンプトも渡します。
# パイプラインを読み込む
import torch
from diffusers import AutoPipelineForInpainting
from diffusers.utils import load_image, make_image_grid

pipeline = AutoPipelineForInpainting.from_pretrained(
    "kandinsky-community/kandinsky-2-2-decoder-inpaint", torch_dtype=torch.float16
)
pipeline.enable_model_cpu_offload()
# xFormers がインストールされていない場合、または PyTorch 2.0 以上がインストールされている場合は次の行を削除してください
pipeline.enable_xformers_memory_efficient_attention()

# ベース画像とマスク画像を読み込む:
init_image = load_image(
    "https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/inpaint.png"
)
mask_image = load_image(
    "https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/inpaint_mask.png"
)

# 画像をインペインティングするためのプロンプトを作成し、ベース画像とマスク画像とともにパイプラインに渡す:
prompt = (
    "a black cat with glowing eyes, cute, adorable, disney, pixar, highly detailed, 8k"
)
negative_prompt = "bad anatomy, deformed, ugly, disfigured"
image = pipeline(
    prompt=prompt,
    negative_prompt=negative_prompt,
    image=init_image,
    mask_image=mask_image,
).images[0]
make_image_grid([init_image, mask_image, image], rows=1, cols=3)
