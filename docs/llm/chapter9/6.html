Interface の高度な機能

基本的なインターフェースを作って共有出来るようになったので、状態（state）や解釈（interpretation）といった、より高度な機能を見ていきましょう。

状態を使ってデータを保持する

Gradio は セッション状態 をサポートしています。これは、ページが読み込まれてから再読み込みされるまでの間、複数回の送信をまたいでデータが保持される仕組みです。セッション状態は、例えば、ユーザーがモデルとやり取りする間データを保持したいチャットボットのようなデモを作る時に便利です。

なお、セッション状態では、モデルのユーザー間でデータが共有されることはありません。

セッション状態にデータを保存するには、次の3つが必要です:

  1. 関数に、インターフェースの状態を表す 追加のパラメータ を渡します。
  2. 関数の最後に、状態の更新後の値を 追加の戻り値 として返します。
  3. Interface を作成する際に、'state' 入力コンポーネントと 'state' 出力コンポーネントを追加します。

下のチャットボットの例を見てください:

import random

import gradio as gr


def chat(message, history):
    history = history or []
    if message.startswith("How many"):
        response = random.randint(1, 10)
    elif message.startswith("How"):
        response = random.choice(["Great", "Good", "Okay", "Bad"])
    elif message.startswith("Where"):
        response = random.choice(["Here", "There", "Somewhere"])
    else:
        response = "I don't know"
    history.append((message, response))
    return history, history


iface = gr.Interface(
    chat,
    ["text", "state"],
    ["chatbot", "state"],
    allow_screenshot=False,
    allow_flagging="never",
)
iface.launch()

出力コンポーネントの状態が送信をまたいで保持されていることに注目してください。なお、状態パラメータにはデフォルト値を渡すことが出来、それが状態の初期値として使われます。

解釈を使って予測を理解する

殆どの機械学習モデルはブラックボックスであり、関数の内部ロジックはエンドユーザーには見えません。透明性を高める為、Interface クラスの interpretation 引数に "default" を指定するだけで、予測結果の解釈機能を追加出来ます。これにより、ユーザーは入力のどの部分が出力に影響しているかを理解出来ます。解釈も含まれた画像分類器のシンプルなインターフェースを、下で見てみましょう:

import requests
import tensorflow as tf

import gradio as gr

inception_net = tf.keras.applications.MobileNetV2()  # モデルを読み込む

# 人間が読める ImageNet のラベルをダウンロードします。
response = requests.get("https://git.io/JJkYN")
labels = response.text.split("\n")


def classify_image(inp):
    inp = inp.reshape((-1, 224, 224, 3))
    inp = tf.keras.applications.mobilenet_v2.preprocess_input(inp)
    prediction = inception_net.predict(inp).flatten()
    return {labels[i]: float(prediction[i]) for i in range(1000)}


image = gr.Image(shape=(224, 224))
label = gr.Label(num_top_classes=3)

title = "Gradio Image Classifiction + Interpretation Example"
gr.Interface(
    fn=classify_image, inputs=image, outputs=label, interpretation="default", title=title
).launch()

入力を送信し、出力コンポーネントの下に在る Interpret をクリックして、解釈機能をテストしてみてください。

Gradio が提供するデフォルトの解釈方法の他、interpretation パラメータに shap を指定し、num_shap パラメータを設定することも出来ます。これは Shapley 値に基づく解釈で、詳しくはこちらで読めます。

最後に、独自の解釈関数を interpretation パラメータに渡すことも出来ます。例は Gradio の getting started ページのこちらにあります。

これで Gradio の Interface クラスの深掘りは終わりです。見てきたように、このクラスを使えば数行の Python コードで機械学習デモを簡単に作れます。

しかし、レイアウトを変更したり、複数の予測関数をつなげたりして、デモをカスタマイズしたくなることもあるでしょう。Interface をカスタマイズ可能な「ブロック」に分割出来たら便利だと思いませんか？幸い、その方法が有ります！それが最終セクションのテーマです。
