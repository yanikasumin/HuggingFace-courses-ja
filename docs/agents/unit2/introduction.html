エージェントフレームワークを使うべきとき

LLM を中心にしたアプリケーションを作るとき、エージェントフレームワークが常に必要とは限りません。フレームワークは、特定のタスクを効率よく解くためのワークフローの柔軟性を提供してくれますが、必須ではない場合もあります。

ユーザーのリクエストに応えるには、事前に決められたワークフローで十分なこともあり、エージェントフレームワークが本当に必要とは限りません。プロンプトを連鎖させるようなシンプルなエージェントであれば、素のコードで十分な場合もあります。その利点は、抽象化に頼らず、開発者がシステムを完全に制御し、理解できることです。

一方で、LLM に関数を呼び出させたり、複数のエージェントを使ったりしてワークフローが複雑になってくると、こうした抽象化が役に立ち始めます。

これらを踏まえると、必要になる機能が見えてきます。

  • システムを動かす LLM エンジン
  • エージェントがアクセスできるツールのリスト
  • LLM の出力からツール呼び出しを抽出するパーサー
  • パーサーと同期したシステムプロンプト
  • メモリシステム
  • LLM のミスを制御するためのエラーログとリトライの仕組み

これらのテーマが、smolagents、LlamaIndex、LangGraph などの各種フレームワークでどう解決されているかを見ていきます。
