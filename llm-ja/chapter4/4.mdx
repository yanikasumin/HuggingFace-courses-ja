# モデルカードを作る[[building-a-model-card]]

<CourseFloatingBanner
    chapter={4}
    classNames="absolute z-10 right-0 top-0"
/>

モデルカードは、モデルリポジトリの中で、モデルやトークナイザのファイルと同じくらい重要なファイルです。モデルを定義する中心の文書であり、コミュニティの他のメンバーによる再利用と、結果の再現を支えます。他のメンバーが成果物を作る際の土台にもなります。

学習と評価の過程を記録すると、モデルに何を期待出来るかを他の人が理解出来ます。使ったデータと、前処理・後処理について十分な情報を示せば、モデルの制限とバイアスも明らかになります。モデルが役立つ文脈と、役立たない文脈も特定出来ます。

その為、モデルを明確に定義するモデルカードの作成は、非常に重要な手順です。ここでは、作成に役立つポイントを示します。モデルカードは、先程見た Markdown ファイルの *README.md* に作成します。

「モデルカード」の考え方は、Google の研究の方向性に由来します。Margaret Mitchell らの論文 ["Model Cards for Model Reporting"](https://arxiv.org/abs/1810.03993) で初めて示されました。ここで述べる情報の多くは、この論文に基づきます。再現性、再利用性、公平性を重視する世界でモデルカードが重要である理由を理解する為に、この論文の一読をお勧めします。

モデルカードは通常、モデルの用途を示す短い概要から始まります。詳細は、続く各セクションに分けて述べます。

- モデルの説明
- 想定される用途と制限
- 使い方
- 制限とバイアス
- 学習データ
- 学習手順
- 評価結果

各セクションに何を含めるべきかを、順に見ていきます。

### モデルの説明[[model-description]]

モデルの説明には、モデルの基本的な詳細を記載します。対象は、アーキテクチャ、バージョン、論文で紹介されたモデルかどうか、元の実装が利用出来るかどうか、著者、モデルに関する一般情報です。著作権の帰属もここに明記します。学習手順やパラメータに関する一般情報と、重要な免責事項も、このセクションに記載出来ます。

### 想定される用途と制限[[intended-uses-limitations]]

ここでは、モデルの想定用途を説明します。適用出来る言語、分野、領域も対象です。このセクションには、モデルの適用範囲外であることが分かっている領域や、性能が十分でない可能性が高い領域も記録出来ます。

### 使い方[[how-to-use]]

ここには、モデルの使い方の例を含めます。`pipeline()` 関数の使い方、モデルとトークナイザのクラスの使い方の他、役立つと思われるコードを示します。

### 学習データ[[training-data]]

ここでは、モデルの学習に使ったデータセットを示します。データセットの簡単な説明も併せて記載するとよいでしょう。

### 学習手順[[training-procedure]]

ここでは、学習を再現する上で関係する事項を全て説明します。対象には、データに行った前処理と後処理が含まれます。モデルを学習させたエポック数、バッチサイズ、学習率などの詳細も含みます。

### 変数と評価指標[[variable-and-metrics]]

ここでは、評価に使う評価指標と、測定する要因を説明します。どの評価指標を、どのデータセットの、どの分割に対して使ったかを示すと、他のモデルとの性能比較が容易になります。これらは、想定ユーザーや用途など、前のセクションの内容を踏まえて決めます。

### 評価結果[[evaluation-results]]

最後に、評価用データセットでモデルがどの程度の性能を示すかを示します。モデルが決定しきい値を使う場合は、評価で使った決定しきい値を示します。あるいは、想定用途ごとに異なるしきい値で評価した詳細を示します。

## 例[[example]]

よく作られたモデルカードの例を、次に示します。

- [`bert-base-cased`](https://huggingface.co/bert-base-cased)
- [`gpt2`](https://huggingface.co/gpt2)
- [`distilbert`](https://huggingface.co/distilbert-base-uncased)

様々な組織や企業による例は、[こちら](https://github.com/huggingface/model_card/blob/master/examples.md) でも確認出来ます。

## 注意[[note]]

モデルを公開する際に、モデルカードは必須ではありません。モデルカードを作る場合も、上で説明したセクションを全て含める必要はありません。

但し、モデルを明示的に文書化することは、将来の利用者の利益にしかなりません。知識と能力の及ぶ範囲で、出来るだけ多くのセクションを埋めることをお勧めします。

## モデルカードのメタデータ[[model-card-metadata]]

Hugging Face Hub を少し探索したことがあれば、一部のモデルが特定のカテゴリに属していることに気付いたはずです。タスク、言語、ライブラリなどで絞り込むことが出来ます。モデルが属するカテゴリは、モデルカードのヘッダーに加えたメタデータに従って識別されます。

例えば、[`camembert-base` のモデルカード](https://huggingface.co/camembert-base/blob/main/README.md) を見ると、モデルカードのヘッダーに次の行が有ります。

```
---
language: fr
license: mit
datasets:
- oscar
---
```

このメタデータは Hugging Face Hub が解析します。Hub はこのモデルを、フランス語のモデルであり、MIT ライセンスを持ち、Oscar データセットで学習されたモデルであると識別します。

[モデルカードの完全な仕様](https://github.com/huggingface/hub-docs/blame/main/modelcard.md) では、言語、ライセンス、タグ、データセット、評価指標を指定出来ます。モデルが学習時に得た評価結果も指定出来ます。
