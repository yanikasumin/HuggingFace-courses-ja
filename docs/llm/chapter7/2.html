トークン分類

{:else}

{/if}

最初に取り上げる応用はトークン分類です。この汎用的なタスクは、「文中の各トークンにラベルを割り当てる」問題として定式化出来るもの全てを包含します。例として次のようなものがあります。

  • 固有表現認識（NER）：文中のエンティティ（人名、地名、組織名など）を見つけます。エンティティの種類ごとに1つのクラスと、「エンティティではない」場合の1つのクラスを用意することで、各トークンへのラベル割り当てとして定式化出来ます。
  • 品詞タグ付け（POS）：文中の各単語が、特定の品詞（名詞、動詞、形容詞など）のどれに対応するかを付けます。
  • チャンキング：同じエンティティに属するトークンを見つけます。このタスクは POS や NER と組み合わせて使うことも出来ます。通常、チャンクの先頭に在るトークンには1つのラベル（通常は B-）、チャンクの内部に在るトークンには別のラベル（通常は I-）、どのチャンクにも属さないトークンには3つ目のラベル（通常は O）を割り当てる形で定式化出来ます。

勿論、トークン分類の問題は他にも数多くの種類があり、ここに挙げたのは代表的な例の一部に過ぎません。このセクションでは、NER タスクでモデル（BERT）をファインチューニングし、次のような予測が出来るようにします。

学習して Hub にアップロードするモデルは、こちらで確認でき、その予測をチェック出来ます。

データの処理

通常通り、テキストは、モデルが理解出来るようトークン ID に変換する必要があります。Chapter 6 で見たように、トークン分類タスクの場合に大きく異なるのは、入力が事前にトークン化されていることです。幸い、トークナイザ API はこれに簡単に対応出来ます。特別なフラグで tokenizer に知らせるだけです。

まず、tokenizer オブジェクトを作成しましょう。先に述べたように BERT の事前学習済みモデルを使うので、関連するトークナイザをダウンロードしてキャッシュすることから始めます。

from transformers import AutoTokenizer

model_checkpoint = "bert-base-cased"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint)

model_checkpoint は、Hub にある好みのモデルに置き換えることも、事前学習済みモデルとトークナイザを保存したローカルフォルダに置き換えることも出来ます。唯一の制約は、Tokenizers ライブラリを利用した高速トークナイザが使えることです。高速バージョンを持つ全てのアーキテクチャは、この大きな表で確認出来ます。使用している tokenizer オブジェクトが本当に Tokenizers に支えられているかどうかは、その is_fast 属性を見れば確認出来ます。

tokenizer.is_fast

```python out True

事前にトークン化された入力をトークン化するには、通常通り `tokenizer` を使い、`is_split_into_words=True` を追加するだけです。

```py
inputs = tokenizer(raw_datasets["train"][0]["tokens"], is_split_into_words=True)
inputs.tokens()

```python out ['[CLS]', 'EU', 'rejects', 'German', 'call', 'to', 'boycott', 'British', 'la', '##mb', '.', '[SEP]']

見ての通り、トークナイザはモデルが使う特殊トークン（先頭の `[CLS]` と末尾の `[SEP]`）を追加し、殆どの単語はそのままにしました。但し、単語 `lamb` は2つのサブワード、`la` と `##mb` にトークン化されました。これにより、入力とラベルの間に不一致が生じます。ラベルのリストは9要素しかないのに、入力は12トークンになっています。

特殊トークンへの対応は簡単です（先頭と末尾にあることが分かっているため）。しかし、全てのラベルが適切な単語に対応するよう揃える必要もあります。

幸い、高速トークナイザを使っている為、Tokenizers の強力な機能を利用出来ます。つまり、各トークンを対応する単語へ簡単にマッピング出来ます（[Chapter 6](/course/chapter6/3) で見た通りです）。

```py
inputs.word_ids()

```python out [None, 0, 1, 2, 3, 4, 5, 6, 7, 7, 8, None]

少し作業すれば、ラベルのリストをトークンに合わせて拡張出来ます。適用する1つ目のルールは、特殊トークンに `-100` というラベルを付けることです。これは、デフォルトでは `-100` が、使用する損失関数（交差エントロピー）で無視されるインデックスだからです。

次に、各トークンには、それが含まれる単語を開始したトークンと同じラベルを付けます。同じエンティティの一部だからです。単語の内部にあって先頭ではないトークンについては、`B-` を `I-` に置き換えます（そのトークンはエンティティを開始しないため）。

```python
def align_labels_with_tokens(labels, word_ids):
    new_labels = []
    current_word = None
    for word_id in word_ids:
        if word_id != current_word:
            # 新しい単語の先頭
            current_word = word_id
            label = -100 if word_id is None else labels[word_id]
            new_labels.append(label)
        elif word_id is None:
            # 特殊トークン
            new_labels.append(-100)
        else:
            # 前のトークンと同じ単語
            label = labels[word_id]
            # ラベルが B-XXX なら I-XXX に変更する
            if label % 2 == 1:
                label += 1
            new_labels.append(label)

    return new_labels

最初の文で試してみましょう。

labels = raw_datasets["train"][0]["ner_tags"]
word_ids = inputs.word_ids()
print(labels)
print(align_labels_with_tokens(labels, word_ids))

```python out [3, 0, 7, 0, 0, 0, 7, 0, 0] [-100, 3, 0, 7, 0, 0, 0, 7, 0, 0, 0, -100]

見ての通り、この関数は、先頭と末尾の2つの特殊トークンに `-100` を追加し、2つのトークンに分割された単語の為に新しい `0` を追加しました。

データセット全体を前処理するには、全ての入力をトークン化し、全てのラベルに `align_labels_with_tokens()` を適用する必要があります。

高速トークナイザの速度を活かすには、多数のテキストを同時にトークン化するのが最適です。そこで、サンプルのリストを処理する関数を書き、`batched=True` オプションを指定して `Dataset.map()` メソッドを使います。前の例と唯一異なる点は、トークナイザへの入力がテキストのリスト（この場合は単語のリストのリスト）の場合、`word_ids()` 関数に、単語 ID が欲しいサンプルのインデックスを渡す必要があることです。その為、それも追加しています。

```py
def tokenize_and_align_labels(examples):
    tokenized_inputs = tokenizer(
        examples["tokens"], truncation=True, is_split_into_words=True
    )
    all_labels = examples["ner_tags"]
    new_labels = []
    for i, labels in enumerate(all_labels):
        word_ids = tokenized_inputs.word_ids(i)
        new_labels.append(align_labels_with_tokens(labels, word_ids))

    tokenized_inputs["labels"] = new_labels
    return tokenized_inputs

入力へのパディングはまだ行っていません。バッチを作成する時にデータコレータで行います。

これで、データセットの他の分割に対しても、全ての前処理を一度に適用出来ます。

tokenized_datasets = raw_datasets.map(
    tokenize_and_align_labels,
    batched=True,
    remove_columns=raw_datasets["train"].column_names,
)

一番大変な部分は終わりました！データの前処理が済んだので、実際の学習は Chapter 3 で行ったことと非常によく似たものになります。

学習ループ

これで完全な学習ループを書く準備が出来ました。評価部分を単純化する為に、予測とラベルを受け取り、metric オブジェクトが期待するように文字列のリストに変換する postprocess() 関数を定義します。

def postprocess(predictions, labels):
    predictions = predictions.detach().cpu().clone().numpy()
    labels = labels.detach().cpu().clone().numpy()

    # 無視されるインデックス（特殊トークン）を取り除き、ラベルに変換する
    true_labels = [[label_names[l] for l in label if l != -100] for label in labels]
    true_predictions = [
        [label_names[p] for (p, l) in zip(prediction, label) if l != -100]
        for prediction, label in zip(predictions, labels)
    ]
    return true_labels, true_predictions

次に学習ループを書くことが出来ます。学習の進み具合を追うプログレスバーを定義した後、ループは3つの部分で構成されます。

  • 学習そのもの。train_dataloader への古典的なイテレーションで、モデルへの順伝播を行い、次に逆伝播とオプティマイザのステップを行います。
  • 評価。モデルからバッチの出力を得た後に、目新しい点があります。2つのプロセスが入力とラベルを異なる形状にパディングしている可能性がある為、gather() メソッドを呼び出す前に、accelerator.pad_across_processes() を使って予測とラベルを同じ形状にする必要があります。これを行わないと、評価はエラーになるか、永遠にハングしてしまいます。その後、結果を metric.add_batch() に送り、評価ループが終わったら metric.compute() を呼び出します。
  • 保存とアップロード。まずモデルとトークナイザを保存し、次に repo.push_to_hub() を呼び出します。blocking=False 引数を使って、Hub ライブラリに非同期プロセスで push するよう指示している点に注意してください。これにより、学習は通常通り継続し、この（時間のかかる）命令はバックグラウンドで実行されます。

学習ループの完全なコードは次の通りです。

from tqdm.auto import tqdm
import torch

progress_bar = tqdm(range(num_training_steps))

for epoch in range(num_train_epochs):
    # 学習
    model.train()
    for batch in train_dataloader:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

    # 評価
    model.eval()
    for batch in eval_dataloader:
        with torch.no_grad():
            outputs = model(**batch)

        predictions = outputs.logits.argmax(dim=-1)
        labels = batch["labels"]

        # gather のためには予測とラベルのパディングが必要
        predictions = accelerator.pad_across_processes(predictions, dim=1, pad_index=-100)
        labels = accelerator.pad_across_processes(labels, dim=1, pad_index=-100)

        predictions_gathered = accelerator.gather(predictions)
        labels_gathered = accelerator.gather(labels)

        true_predictions, true_labels = postprocess(predictions_gathered, labels_gathered)
        metric.add_batch(predictions=true_predictions, references=true_labels)

    results = metric.compute()
    print(
        f"エポック {epoch}:",
        {
            key: results[f"overall_{key}"]
            for key in ["precision", "recall", "f1", "accuracy"]
        },
    )

    # 保存とアップロード
    accelerator.wait_for_everyone()
    unwrapped_model = accelerator.unwrap_model(model)
    unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
    if accelerator.is_main_process:
        tokenizer.save_pretrained(output_dir)
        repo.push_to_hub(
            commit_message=f"Training in progress epoch {epoch}", blocking=False
        )

Accelerate で保存されたモデルを初めて見る場合の為に、それに付随する3行のコードを少し見てみましょう。

accelerator.wait_for_everyone()
unwrapped_model = accelerator.unwrap_model(model)
unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)

1行目は自明です。全てのプロセスに、続行する前に全員がその段階に到達するまで待つよう指示します。これは、保存する前に全てのプロセスで同じモデルが存在することを確実にする為です。

次に unwrapped_model を取得します。これは定義したベースモデルです。accelerator.prepare() メソッドはモデルを分散学習用に変更する為、save_pretrained() メソッドはもう存在しません。accelerator.unwrap_model() メソッドはその手順を元に戻します。最後に、save_pretrained() を呼び出しますが、そのメソッドに torch.save() の代わりに accelerator.save() を使うよう指示します。
