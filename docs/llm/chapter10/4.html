データセットにアノテーションを付ける

ここからは、Argilla の UI を使ってデータセットにアノテーションを付けていきます。

アノテーションガイドラインでチームの認識を揃える

アノテーションを始める前に、ガイドラインを用意しておくことをお勧めします。特にチームで作業する場合は欠かせません。ガイドラインがあれば、タスクの進め方や各ラベルの使い方について認識を揃えられます。作業中に疑問や判断の食い違いが生じた時も、ガイドラインに立ち返って解決出来ます。

Argilla では、UI のデータセット設定ページでガイドラインと各質問の説明を編集出来ます。ここを整えておくと、チーム内の認識を揃える助けになります。

ガイドラインの書き方を更に詳しく知りたい場合は、このブログ記事 と、記事中で挙げられている参考文献をお読みください。

アノテーション作業を割り当てる

データセット設定ページでは、データセットの割り当て設定（distribution settings）も変更出来ます。チームで作業する場合に、アノテーションを効率よく進める為の設定です。

送信済みレスポンスの最小数の初期値は 1 です。レコードに送信済みレスポンスが 1 件付いた時点で、そのレコードは完了とみなされ、データセットの進捗に反映されます。

レコードごとに複数の送信済みレスポンスが必要な場合もあります。例えば、アノテーター同士の一致度を分析したい場合です。その場合は、この値を大きくしてください。但し、アノテーターの総数を超えないようにします。一人で作業する場合は、1 のままにしてください。

レコードにアノテーションを付ける

💡 ヒント

💡 Argilla を Hugging Face Space にデプロイしている場合、チームメンバーは Hugging Face の OAuth でログイン出来ます。それ以外の場合は、このガイド に従ってユーザーを作成する必要がある場合があります。

データセットを開くと、最初の質問には提案ラベルが既に入力されています。前のセクションで label という質問をデータセットの label_text 列に対応付けた為です。既存のラベルを確認し、必要に応じて修正するだけで済みます。

トークン分類では、提案を用意していない為、ラベルは全て手作業で付ける必要があります。スパンへのアノテーションを行うと、次のような表示になるかもしれません。

レコードを確認していく中で、次の操作を選べます。

  • レスポンスを送信する（そのレコードのアノテーションが終わったら）。
  • 下書きとして保存する（後で戻って続きをしたい場合）。
  • 破棄する（そのレコードをデータセットに含めるべきでない場合や、レスポンスを付けない場合）。

次のセクションでは、それらのアノテーションをエクスポートして使う方法を学びます。
