Unit 1 のまとめ

Model Context Protocol（MCP）

MCP は、AI モデルを外部のツール、データソース、環境に接続するために設計された標準化されたプロトコルです。相互運用性とリアルタイム情報へのアクセスを可能にすることで、既存の AI システムの制約を解消します。

主要な概念

クライアント・サーバーアーキテクチャ

MCP は、クライアントがユーザーとサーバー間の通信を管理するクライアント・サーバーモデルに従います。このアーキテクチャはモジュール性を促進し、既存のホストに変更を加えることなく新しいサーバーを簡単に追加できます。

コンポーネント

ホスト（Host）

エンドユーザーが操作する、ユーザー向けの AI アプリケーションです。

クライアント（Client）

ホストアプリケーション内のコンポーネントで、特定の MCP サーバーとの通信を管理します。クライアントはサーバーと 1:1 の接続を維持し、プロトコルレベルの詳細を処理します。

サーバー（Server）

MCP プロトコルを通じてツール、データソース、サービスへのアクセスを提供する外部のプログラムまたはサービスです。サーバーは既存の機能を軽量にラップするラッパーとして動作します。

機能（Capabilities）

ツール（Tools）

アクションを実行できる関数です（例: メッセージの送信、API のクエリ）。ツールは通常モデル制御であり、副作用を伴うアクションを実行できるため、ユーザーの承認が必要です。

リソース（Resources）

大きな計算を伴わずにコンテキストを取得するための読み取り専用データソースです。リソースはアプリケーション制御であり、REST API の GET エンドポイントと同様のデータ取得のために設計されています。

プロンプト（Prompts）

ユーザー、AI モデル、利用可能な機能の間のやり取りをガイドする、事前に定義されたテンプレートやワークフローです。プロンプトはユーザー制御であり、やり取りのコンテキストを設定します。

サンプリング（Sampling）

サーバーから開始される LLM 処理へのリクエストです。サーバー駆動のエージェント的な振る舞いや、再帰的・複数ステップのやり取りを可能にします。サンプリング操作には通常、ユーザーの承認が必要です。

通信プロトコル

MCP プロトコルは、クライアントとサーバー間の通信のメッセージフォーマットとして JSON-RPC 2.0 を使用します。2つの主要なトランスポート機構がサポートされています。stdio（ローカル通信用）と HTTP+SSE（リモート通信用）です。メッセージにはリクエスト、レスポンス、通知が含まれます。

ディスカバリプロセス

MCP では、クライアントが list メソッド（例: tools/list）を通じて利用可能なツール、リソース、プロンプトを動的に発見できます。この動的ディスカバリの仕組みにより、クライアントはサーバーの機能に関するハードコードされた知識を必要とせずに、各サーバーが提供する具体的な機能に適応できます。

MCP SDK

MCP クライアントとサーバーを実装するための公式 SDK が、さまざまなプログラミング言語で提供されています。これらの SDK はプロトコルレベルの通信、機能の登録、エラーハンドリングを処理し、開発プロセスを簡素化します。

Gradio との統合

Gradio を使えば、機能を MCP プロトコルに公開する Web インターフェースを簡単に作成でき、人間と AI モデルの両方からアクセス可能になります。この統合により、最小限のコードで、人間に優しいインターフェースと AI からアクセス可能なツールを併せて提供できます。

Hugging Face の MCP 拡張

  • Hosted MCP Server がより多くのクライアント（VS Code、Cursor、Zed、Claude Desktop）と統合されるようになりました。
  • モデル、データセット、Spaces、論文を検索するための厳選された組み込みツール。
  • https://huggingface.co/settings/mcp からワンクリックで設定スニペットを取得できます。
  • 設定から MCP 対応の Gradio Spaces を追加し、アシスタントから直接利用できます。
