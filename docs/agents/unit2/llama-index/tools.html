LlamaIndex でツールを使う

明確なツールのセットを定義することは、性能を左右する重要な要素です。 ユニット 1 で述べたように、ツールのインターフェースが分かりやすければ、LLM にとっても使いやすくなります。人間のエンジニア向けのソフトウェア API と同じように、LLM も仕組みが分かり易いツール程、その機能を効果的に活用出来ます。

LlamaIndex のツールには、主に次の 4 種類が有ります。

  1. FunctionTool：任意の Python 関数を、エージェントが使えるツールに変換します。関数の動作を自動的に解析します。
  2. QueryEngineTool：エージェントがクエリエンジンを使えるようにするツールです。エージェントはクエリエンジンを土台に構築される為、他のエージェントをツールとして使うことも出来ます。
  3. Toolspecs：コミュニティが作成したツールのセットで、Gmail のような特定のサービス向けのツールを含むことがよくあります。
  4. Utility Tools：他のツールから得られる大量のデータを扱うのに役立つ、特殊なツールです。

以下では、それぞれを詳しく見ていきます。

FunctionTool を作成する

💡 ヒント

コードは、Google Colab で実行出来る このノートブック で確認出来ます。

FunctionTool を使えば、任意の Python 関数を簡単にラップして、エージェントから利用出来るように出来ます。ツールには同期関数・非同期関数のどちらでも渡せます。任意で name パラメータと description パラメータも指定出来ます。

名前と説明は特に重要です。エージェントが、ツールをいつ、どのように使えばよいかを理解する手がかりになるからです。以下で FunctionTool の作成方法を見てから、実際に呼び出してみましょう。

from llama_index.core.tools import FunctionTool

def get_weather(location: str) -> str:
    """Useful for getting the weather for a given location."""
    print(f"{location} の天気を取得しています")
    return f"The weather in {location} is sunny"

tool = FunctionTool.from_defaults(
    get_weather,
    name="my_weather_tool",
    description="Useful for getting the weather for a given location.",
)
tool.call("New York")

（ツール説明と出力の訳：docstring と説明は「指定された場所の天気を取得するのに役立ちます」です。戻り値は「{location} の天気は晴れです」という形式の文で、呼び出し例の場所は New York です）

💡 ヒント

関数呼び出しに対応したエージェントや LLM を使う場合、どのツールが選ばれるか、また、そのツールにどのような引数が渡されるかは、ツールの名前や、ツールの用途・引数についての説明に大きく左右されます。関数呼び出しの詳細は Function Calling Guide を参照してください。

QueryEngineTool を作成する

前のユニットで定義した QueryEngine は、QueryEngineTool クラスを使えば簡単にツールへ変換出来ます。以下の例で、QueryEngine から QueryEngineTool を作成する方法を見てみましょう。

from llama_index.core import VectorStoreIndex
from llama_index.core.tools import QueryEngineTool
from llama_index.llms.huggingface_api import HuggingFaceInferenceAPI
from llama_index.embeddings.huggingface import HuggingFaceEmbedding
from llama_index.vector_stores.chroma import ChromaVectorStore

embed_model = HuggingFaceEmbedding("BAAI/bge-small-en-v1.5")

db = chromadb.PersistentClient(path="./alfred_chroma_db")
chroma_collection = db.get_or_create_collection("alfred")
vector_store = ChromaVectorStore(chroma_collection=chroma_collection)

index = VectorStoreIndex.from_vector_store(vector_store, embed_model=embed_model)

llm = HuggingFaceInferenceAPI(model_name="Qwen/Qwen2.5-Coder-32B-Instruct")
query_engine = index.as_query_engine(llm=llm)
tool = QueryEngineTool.from_defaults(query_engine, name="some useful name", description="some useful description")

Toolspecs を作成する

ToolSpecs は、複数のツールをうまく連携させた集合だと考えてください。専門家が使う、よく整理された道具箱のようなものです。整備士の道具箱に、車の修理で互いの役割を補い合う道具がそろっているように、ToolSpec は特定の目的に合わせて関連するツールを組み合わせます。例えば、経理エージェントの ToolSpec であれば、表計算の機能、メールの機能、計算ツールをうまく統合し、財務タスクを正確且つ効率的に処理出来るでしょう。

Google Toolspec をインストールする LlamaHub に関するセクション で紹介したように、Google のツールスペックは次のコマンドでインストール出来ます。 
pip install llama-index-tools-google

これでツールスペックを読み込み、ツールのリストへ変換出来ます。

from llama_index.tools.google import GmailToolSpec

tool_spec = GmailToolSpec()
tool_spec_list = tool_spec.to_tool_list()

ツールをより詳しく確認するには、各ツールの metadata を見ます。

[(tool.metadata.name, tool.metadata.description) for tool in tool_spec_list]

LlamaIndex における Model Context Protocol（MCP）

LlamaIndex では、LlamaHub 上の ToolSpec を通じて MCP ツールも使えます。MCP サーバーを起動すれば、以下のコードを使ってそのまま利用を開始出来ます。

MCP について更に深く知りたい場合は、無料の MCP コース を確認してください。

MCP Toolspec をインストールする LlamaHub に関するセクション で紹介したように、MCP のツールスペックは次のコマンドでインストール出来ます。 
pip install llama-index-tools-mcp

from llama_index.tools.mcp import BasicMCPClient, McpToolSpec

# 127.0.0.1:8000 で MCP サーバーが動作しているものとします。MCP クライアントを使って、自分の MCP サーバーに接続することもできます。
mcp_client = BasicMCPClient("http://127.0.0.1:8000/sse")
mcp_tool = McpToolSpec(client=mcp_client)

# エージェントを取得する
agent = await get_agent(mcp_tool)

# エージェントのコンテキストを作成する
agent_context = Context(agent)

ユーティリティツール

API に直接クエリを実行すると、必要以上に大量のデータが返ってくることがよくあります。その中には無関係な情報が含まれることもあれば、データ量が LLM のコンテキストウィンドウを超えてしまうことも有ります。また、使用するトークン数が不必要に増える場合も有ります。

以下では、主要な 2 つのユーティリティツールを確認します。

  1. OnDemandToolLoader：既存の任意の LlamaIndex データローダー（BaseReader クラス）を、エージェントが使えるツールに変換するツールです。このツールは、データローダーの load_data を実行する為に必要なパラメータ全てと、自然言語のクエリ文字列を使って呼び出せます。実行時には、まずデータローダーからデータを読み込み、インデックス化し（例えばベクトルストアを使って）、その上で「オンデマンド」にクエリします。これら 3 つのステップは全て、1 回のツール呼び出しの中で行われます。
  2. LoadAndSearchToolSpec：LoadAndSearchToolSpec は、既存の任意のツールを入力として受け取ります。ツールスペックとして to_tool_list を実装しており、この関数を呼び出すと、読み込み用ツールと検索用ツールの 2 つが返されます。読み込み用ツールを実行すると、内部のツールが呼び出され、その出力がインデックス化されます（デフォルトではベクトルインデックスを使います）。検索用ツールを実行すると、クエリ文字列を入力として受け取り、内部のインデックスを呼び出します。

💡 ヒント

ツールスペックとユーティリティツールは LlamaHub で見つけられます。
