# 評価

SFT または LoRA を使った SFT でファインチューニングしたモデルは、標準的なベンチマークで評価すべきです。機械学習エンジニアとしては、対象分野に適した評価項目やベンチマークを体系的に整備し、継続的に管理することが重要です。このページでは、代表的なベンチマークと、それらを使ってモデルを評価する方法を見ていきます。特定のユースケースに合わせたカスタムベンチマークの作り方も扱います。

## 自動ベンチマーク

自動ベンチマークは、言語モデルがさまざまなタスクをどの程度こなせるかを、標準化された方法で評価する仕組みです。モデルの性能を理解する出発点として有用ですが、包括的な評価戦略の一部にすぎないことを認識しておくことが大切です。

## 自動ベンチマークの理解

自動ベンチマークは通常、あらかじめ定義されたタスクと評価メトリクスを持つ、厳選されたデータセットで構成されます。これらのベンチマークは、基本的な言語理解から複雑な推論まで、モデル能力のさまざまな側面を評価することを目的としています。自動ベンチマークを使う主な利点は標準化です。異なるモデル間での一貫した比較ができ、再現可能な結果が得られます。

ただし、ベンチマークの性能が実世界での有効性にそのまま結びつくとは限らないことを理解しておく必要があります。学術的なベンチマークで優れたモデルでも、特定のドメインの用途や実践的なユースケースでは苦戦することがあります。

## 汎用知識のベンチマーク

[MMLU](https://huggingface.co/datasets/cais/mmlu)（Massive Multitask Language Understanding）は、科学から人文科学まで57の科目にわたる知識をテストします。包括的ではありますが、特定のドメインで必要となる専門性の深さを反映しているとは限りません。TruthfulQA は、モデルが一般的な誤解を再生産する傾向を評価しますが、あらゆる形の誤情報を捉えられるわけではありません。

## 推論のベンチマーク

[BBH](https://huggingface.co/datasets/lukaemon/bbh)（Big Bench Hard）と [GSM8K](https://huggingface.co/datasets/openai/gsm8k) は、複雑な推論タスクに焦点を当てています。BBH は論理的思考と計画をテストし、GSM8K は特に数学の問題解決を対象とします。これらのベンチマークは分析能力の評価に役立ちますが、実世界のシナリオで求められる、細部にわたる推論を捉えきれないことがあります。

## 言語理解

[HELM](https://github.com/stanford-crfm/helm) は、全体論的な評価フレームワークを提供します。HELM のようなベンチマークは、常識、世界知識、推論といった側面から、モデルの言語処理能力を把握できます。ただし、自然な会話の複雑さやドメイン固有の専門用語を完全には表せないことがあります。

## ドメイン固有のベンチマーク

数学、コーディング、チャットといった特定のドメインに焦点を当てたベンチマークをいくつか見てみましょう。

[MATH ベンチマーク](https://huggingface.co/papers/2103.03874) は、数学的推論のもう1つの重要な評価ツールです。代数、幾何、数論、数え上げ、確率などを含む数学コンペティションからの 12,500 問で構成されます。MATH が特に難しいのは、多段階の推論、形式的な数学表記の理解、段階的な解法の生成能力が必要な点です。単純な算術タスクとは異なり、MATH の問題は高度な問題解決戦略と数学概念の応用を求めることが多くあります。

[HumanEval ベンチマーク](https://github.com/openai/human-eval) は、164 のプログラミング問題で構成される、コーディングに焦点を当てた評価データセットです。このベンチマークは、与えられたプログラミングタスクを解く、機能的に正しい Python コードを生成するモデルの能力をテストします。HumanEval の特徴は、参照解との表面的な類似度だけでなく、生成されたコードに対して実際にテストケースを実行し、コードが正しく動作するかを評価する点です。問題は、基本的な文字列操作から、より複雑なアルゴリズムやデータ構造まで多岐にわたります。

[Alpaca Eval](https://tatsu-lab.github.io/alpaca_eval/) は、指示に従う言語モデルの品質を評価するために設計された自動評価フレームワークです。GPT-4 を判定者として使い、有用性、正直さ、無害性といったさまざまな観点でモデルの出力を評価します。このフレームワークは 805 件の厳選されたプロンプトのデータセットを含み、Claude、GPT-4 など複数の参照モデルに対して応答を評価できます。Alpaca Eval が特に便利なのは、人間のアノテータを必要とせずに一貫性のあるスケーラブルな評価を提供しながら、従来の評価指標では捉えにくい、モデル性能の細かな違いも評価できる点です。

## 代替の評価アプローチ

標準ベンチマークの限界に対処するため、多くの組織が代替の評価方法を開発してきました。

### LLM-as-Judge

ある言語モデルを使って別のモデルの出力を評価する方法が、ますます普及しています。このアプローチは、従来の指標では捉えにくい応答品質の違いを評価できますが、評価に用いるモデル自体にも偏りや限界があります。

### 評価アリーナ

[Chatbot Arena](https://lmarena.ai/) のような評価アリーナは、クラウドソーシングされたフィードバックを通じて LLM を評価する独自のアプローチを提供します。これらのプラットフォームでは、ユーザーが2つの LLM の匿名の「対決」に参加し、質問をして、どちらのモデルがより良い応答をするかに投票します。このアプローチは、多様で挑戦的な質問を通じて実際の使用パターンと好みを捉え、クラウドソーシングされた投票と専門家の評価の間に強い一致があることが研究で示されています。強力な一方で、これらのプラットフォームには、ユーザーベースの偏り、プロンプト分布の偏り、安全性への配慮よりも有用性に主眼が置かれるといった限界があります。

### カスタムベンチマークスイート

組織は、自社の具体的なニーズとユースケースに合わせた内製のベンチマークスイートを開発することがよくあります。ドメイン固有の知識テストや、実際のデプロイ条件を反映した評価シナリオが含まれることもあります。

## カスタム評価

標準ベンチマークは有用なベースラインを提供しますが、それだけを評価方法にすべきではありません。より包括的なアプローチの作り方は次のとおりです。

1. 関連する標準ベンチマークから始めてベースラインを確立し、他のモデルと比較できるようにする

2. そのユースケース特有の要件と課題を特定する。モデルは実際にどんなタスクを行うのか。どんな種類のエラーが最も問題になるのか

3. 実際のユースケースを反映したカスタム評価データセットを開発する。たとえば次のようなものを含められます:
   - ドメインにおける実際のユーザーのクエリ
   - 遭遇したことのある一般的なエッジケース
   - 特に難しいシナリオの例

4. 多層的な評価戦略の実装を検討する:
   - 素早いフィードバックのための自動メトリクス
   - 微妙な違いを捉えるための人間による評価
   - 専門的な用途のためのドメイン専門家によるレビュー
   - 管理された環境での A/B テスト

## カスタム評価の実装

このセクションでは、ファインチューニングしたモデルの評価を実装します。[`lighteval`](https://github.com/huggingface/lighteval) を使って、標準ベンチマークでファインチューニングしたモデルを評価できます。このライブラリには幅広いタスクが組み込まれています。評価したいタスクと評価のパラメータを定義するだけです。  

LightEval のタスクは、特定の形式で定義されます。

```
{suite}|{task}|{num_few_shot}|{auto_reduce}
```

| パラメータ | 説明 |
|-----------|-------------|
| `suite` | ベンチマークスイート（例: 'mmlu'、'truthfulqa'） |
| `task` | スイート内の特定のタスク（例: 'abstract_algebra'） |
| `num_few_shot` | プロンプトに含める例の数（ゼロショットの場合は 0） |
| `auto_reduce` | プロンプトが長すぎる場合に Few-shot の例を自動で減らすかどうか（0 または 1） |

例: `"mmlu|abstract_algebra|0|0"` は、MMLU の abstract algebra タスクをゼロショット推論で評価します。

## 評価パイプラインの例

ファインチューニングしたモデルの評価パイプラインを構築してみましょう。医療ドメインに関連するサブタスクのセットでモデルを評価します。 

Lighteval と VLLM バックエンドを使って、特定の1ドメインに関連する自動ベンチマークで評価する完全な例がこちらです。

```bash
lighteval accelerate \
    "pretrained=your-model-name" \
    "mmlu|anatomy|0|0" \
    "mmlu|high_school_biology|0|0" \
    "mmlu|high_school_chemistry|0|0" \
    "mmlu|professional_medicine|0|0" \
    --max_samples 40 \
    --batch_size 1 \
    --output_path "./results" \
    --save_generations true
```

結果は表形式で表示されます。

```
|                  Task                  |Version|Metric|Value |   |Stderr|
|----------------------------------------|------:|------|-----:|---|-----:|
|all                                     |       |acc   |0.3333|±  |0.1169|
|leaderboard:mmlu:_average:5             |       |acc   |0.3400|±  |0.1121|
|leaderboard:mmlu:anatomy:5              |      0|acc   |0.4500|±  |0.1141|
|leaderboard:mmlu:high_school_biology:5  |      0|acc   |0.1500|±  |0.0819|
```

Lighteval には、より詳細な評価タスクのための Python API も含まれており、結果をより柔軟に扱うのに便利です。詳細は [Lighteval のドキュメント](https://huggingface.co/docs/lighteval/using-the-python-api)を確認してください。

> [!TIP]
> ✏️ **試してみましょう！** lighteval で、ファインチューニングしたモデルを特定のタスクで評価してみましょう。
