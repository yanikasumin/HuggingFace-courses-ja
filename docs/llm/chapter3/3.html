Trainer API でモデルをファインチューニングする

🤗 Transformers には、事前学習済みモデルのファインチューニングを助ける Trainer クラスが用意されています。Transformers が提供するモデルであれば、現在の推奨手法に沿って、自分のデータセットでファインチューニング出来ます。前のセクションでデータの前処理を終えていれば、Trainer を定義する作業はあとわずかです。

定義そのものより手間が掛かるのは、むしろ Trainer.train() を動かす環境の準備でしょう。CPU では学習が非常に遅くなる為です。GPU を用意出来ない場合は、Google Colab で無料の GPU や TPU を利用出来ます。

💡 ヒント

📚 学習リソース：学習に入る前に、まず包括的な Transformers 学習ガイド に目を通してください。ファインチューニングのクックブック には実践的な例がまとまっています。

以下のコード例は、前のセクションの例を既に実行済みであることを前提としています。必要なものは次の通りです。

from datasets import load_dataset
from transformers import AutoTokenizer, DataCollatorWithPadding

raw_datasets = load_dataset("glue", "mrpc")
checkpoint = "bert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(checkpoint)


def tokenize_function(example):
    return tokenizer(example["sentence1"], example["sentence2"], truncation=True)


tokenized_datasets = raw_datasets.map(tokenize_function, batched=True)
data_collator = DataCollatorWithPadding(tokenizer=tokenizer)

学習

Trainer を定義する前の最初のステップは、TrainingArguments クラスの定義です。ここには、Trainer が学習と評価に使うハイパーパラメータを全てまとめます。必ず渡す必要が有るのは、学習したモデルの保存先ディレクトリだけです。途中のチェックポイントも同じ場所に保存されます。残りの引数は既定のままで構いません。基本的なファインチューニングであれば、それで十分なはずです。

from transformers import TrainingArguments

training_args = TrainingArguments("test-trainer")

学習中にモデルを Hub へ自動でアップロードしたい場合は、TrainingArguments で push_to_hub=True を指定します。この仕組みは 第4章 で改めて説明します。

💡 ヒント

🚀 高度な設定：指定出来る学習引数の全てと、最適化の進め方を詳しく知りたい場合は、TrainingArguments ドキュメント と 学習設定のクックブック を確認してください。

2つ目のステップではモデルを定義します。前の章 と同じく AutoModelForSequenceClassification クラスを使い、ラベルの数は2とします。

from transformers import AutoModelForSequenceClassification

model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)

第2章 の時と違い、この事前学習済みモデルを作ると警告が出ます。BERT は文のペアを分類する学習をしていない為です。その為、事前学習済みモデルのヘッドは捨てられ、代わりにシーケンス分類用の新しいヘッドが付いています。警告の内容は、一部の重みが使われなかったこと（捨てられた事前学習ヘッドの重み）と、別の重みがランダムに初期化されたこと（新しいヘッドの重み）です。そして最後に、モデルを学習させるよう促されます。まさにそれをこれから行います。

渡すのは model、training_args、学習用と検証用のデータセット、data_collator、それに processing_class で、これらを使って Trainer を定義します。processing_class パラメータは比較的新しく追加されたもので、どのトークナイザで処理するかを Trainer に伝えます。

from transformers import Trainer

trainer = Trainer(
    model,
    training_args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    data_collator=data_collator,
    processing_class=tokenizer,
)

トークナイザを processing_class として渡した場合、Trainer が既定で使う data_collator は DataCollatorWithPadding です。従って data_collator=data_collator の行は省略出来ますが、処理の流れの中で重要な部分なので、ここではあえて残しています。

💡 ヒント

📖 更に学ぶ：Trainer クラスとそのパラメータの詳細は Trainer API ドキュメント に有ります。高度な使い方のパターンは 学習クックブックのレシピ も参考になります。

モデルをデータセットでファインチューニングするには、Trainer の train() メソッドを呼び出すだけです。

trainer.train()

これでファインチューニングが始まります。GPU であれば数分で終わり、学習損失は500ステップごとに報告されます。但し、モデルの出来が良いのか悪いのかは、これだけでは分かりません。その理由は次の通りです。

  1. TrainingArguments の eval_strategy を "steps"（eval_steps ごとに評価）か "epoch"（各エポックの終わりに評価）に設定しておらず、学習中に評価するよう Trainer に指示していない為です。
  2. 評価の際に指標を計算する compute_metrics() 関数を Trainer に渡していない為です。関数が無ければ、評価で出るのは損失だけになります。損失は、性能を直感的に掴むには向かない数値です。

評価

次は、役に立つ compute_metrics() 関数を作り、次の学習で使えるようにします。この関数が受け取るのは、predictions フィールドと label_ids フィールドを持つ名前付きタプル EvalPrediction です。返すのは、指標の名前をキー、その値を浮動小数点数とする辞書です。モデルの予測は Trainer.predict() メソッドで得られます。

predictions = trainer.predict(tokenized_datasets["validation"])
print(predictions.predictions.shape, predictions.label_ids.shape)

```python out (408, 2) (408,)

`predict()` の出力も名前付きタプルで、フィールドは `predictions`、`label_ids`、`metrics` の3つです。このうち `metrics` に入るのは、渡したデータセットに対する損失と、予測に掛かった時間に関する指標（合計と平均）だけです。`compute_metrics()` 関数を仕上げて `Trainer` に渡せば、ここに `compute_metrics()` が返した指標も加わります。

`predictions` は 408 x 2 の二次元配列です。408 は、渡したデータセットの要素数に当たります。中身は、`predict()` に渡した各要素に対するロジットです（[前の章](/course/chapter2) で見た通り、Transformer モデルは全てロジットを返します）。ラベルと比較出来る予測に直すには、2番目の軸に沿って最大値のインデックスを取ります。

```py
import numpy as np

preds = np.argmax(predictions.predictions, axis=-1)

これで preds とラベルを比較出来ます。compute_metric() 関数を作るに当たっては、Evaluate ライブラリの指標を使います。MRPC データセットに対応する指標は、データセットと同じ要領で evaluate.load() 関数から読み込めます。返ってきたオブジェクトの compute() メソッドで、指標を計算します。

import evaluate

metric = evaluate.load("glue", "mrpc")
metric.compute(predictions=preds, references=predictions.label_ids)

```python out

得られる結果は、実行のたびに少し変わる場合が有ります。モデルのヘッドの初期値がランダムだからです。ここでの結果を見ると、検証データセットに対する正解率は85.78%、F1 スコアは89.97でした。MRPC データセットの結果を GLUE ベンチマークで評価する際は、この2つの指標を使います。

[BERT 論文](https://arxiv.org/pdf/1810.04805.pdf) の表では、ベースモデルの F1 スコアは88.9と報告されています。そちらは `uncased` モデルの値で、こちらで使っているのは `cased` モデルです。今回の方が良い結果になったのは、その違いで説明出来ます。

総てをまとめると、`compute_metrics()` 関数は次のようになります。

```py
def compute_metrics(eval_preds):
    metric = evaluate.load("glue", "mrpc")
    logits, labels = eval_preds
    predictions = np.argmax(logits, axis=-1)
    return metric.compute(predictions=predictions, references=labels)

この compute_metrics() 関数を使い、各エポックの終わりに指標を報告させるには、新しい Trainer を次のように定義します。

training_args = TrainingArguments("test-trainer", eval_strategy="epoch")
model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)

trainer = Trainer(
    model,
    training_args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    data_collator=data_collator,
    processing_class=tokenizer,
    compute_metrics=compute_metrics,
)

ここでは、eval_strategy を "epoch" にした新しい TrainingArguments と、新しいモデルを作り直している点に注意してください。作り直さなければ、既に学習したモデルの学習をそのまま続けることになります。新しい学習を始めるには、次を実行します。

trainer.train()

今度は、学習損失に加え、各エポックの終わりに検証損失と指標も報告されます。モデルのヘッドの初期値がランダムな為、正解率と F1 スコアは先程と多少異なる場合が有りますが、大凡同じ範囲に収まるはずです。

高度な学習機能

Trainer には、現在の深層学習で推奨される手法を取り入れる為の機能が数多く用意されています。

混合精度学習：学習引数に fp16=True を指定すると、学習が速くなり、メモリ使用量も減ります。

training_args = TrainingArguments(
    "test-trainer",
    eval_strategy="epoch",
    fp16=True,  # 混合精度を有効化
)

勾配累積：GPU メモリが限られている場合に、実効的なバッチサイズを大きく出来ます。

training_args = TrainingArguments(
    "test-trainer",
    eval_strategy="epoch",
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,  # 実効的なバッチサイズ = 4 * 4 = 16
)

学習率スケジューリング：Trainer は既定では学習率を線形に減衰させますが、この設定は変更出来ます。

training_args = TrainingArguments(
    "test-trainer",
    eval_strategy="epoch",
    learning_rate=2e-5,
    lr_scheduler_type="cosine",  # 異なるスケジューラを試してみてください
)

セクションクイズ

Trainer API とファインチューニングの概念について、理解度を確認します。

1. Trainer の processing_class パラメータの目的は何ですか？

モデルアーキテクチャは、モデルを読み込む際に指定するものであり、Trainer で指定するものではありません。
比較的最近追加された processing_class パラメータは、Trainer がデータ処理に使用するトークナイザを指定するためのものです。
バッチサイズは TrainingArguments で設定するものであり、processing_class で設定するものではありません。
評価の頻度は、TrainingArguments の eval_strategy で制御します。

2. 学習中の評価の頻度を制御する TrainingArguments パラメータはどれですか？

TrainingArguments に eval_frequency パラメータは存在しません。
eval_strategy は 'epoch'、'steps'、'no' に設定でき、評価のタイミングを制御します。
eval_steps は評価間のステップ数を設定しますが、評価を行うかどうか、いつ行うかを決定するのは eval_strategy です。
現在の TrainingArguments に do_eval パラメータは有りません。

3. TrainingArguments の fp16=True は何を有効にしますか？

fp16 は浮動小数点精度を指し、整数精度ではありません。
混合精度学習では、順伝播に16ビット浮動小数点数、勾配に32ビット浮動小数点数を使用し、速度の向上とメモリ使用量の削減を実現します。
fp16 はエポック数とは何の関係もありません。
GPU の数は fp16 パラメータで制御されるものではありません。

4. Trainer における compute_metrics 関数の役割は何ですか？

損失はモデルが自動的に計算するため、compute_metrics では計算しません。
compute_metrics は予測とラベルを受け取り、評価用のメトリクスを返します。
オプティマイザを選ぶのは compute_metrics の役割ではありません。
データの前処理は学習前に行うため、評価中に compute_metrics が前処理を行うことはありません。

5. Trainer に eval_dataset を提供しないとどうなりますか？

eval_dataset がなくても学習は実行できますが、評価メトリクスは得られません。
Trainer は検証用の分割を自動的には作成しません。
評価は任意です。評価なしで学習することもできますが、検証メトリクスは表示されません。
Trainer が学習データを自動的に評価に使用することはありません。単に評価を行わないだけです。

6. 勾配累積とは何ですか？また、どのように有効にしますか？

勾配累積に、勾配をディスクに保存することは含まれません。
これにより、複数の順伝播にわたって勾配を累積することで、より大きなバッチサイズをシミュレートできます。
fp16 は学習を高速化できますが、勾配累積は別のテクニックです。
それは勾配クリッピングの説明であり、勾配累積ではありません。

💡 ヒント

💡 重要なポイント： - Trainer API は、学習に必要な複雑な処理の多くを引き受ける高レベルのインターフェースを提供します - 適切なデータ処理の為に、processing_class でトークナイザを指定します - TrainingArguments は、学習率、バッチサイズ、評価戦略、最適化など、学習の全ての側面を制御します - compute_metrics を使うと、学習損失に加えて独自の評価メトリクスも計算出来ます - 混合精度（fp16=True）や勾配累積などの機能を使うと、学習効率が大幅に向上する場合があります
