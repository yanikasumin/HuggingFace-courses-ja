次に、翻訳を扱います。翻訳はシーケンス・ツー・シーケンスのタスクの1つです。あるシーケンスから別のシーケンスへ移る問題として定式化出来ます。この問題は要約にかなり近く、ここで学ぶ内容は次のような他のシーケンス・ツー・シーケンスの問題にも応用出来ます。

  • 文体変換（Style transfer）：或る文体で書かれたテキストを別の文体に翻訳するモデルを作る（例: 丁寧な文体からくだけた文体へ、シェイクスピア風の英語から現代英語へ）
  • 生成型質問応答（Generative question answering）：文脈を与えて、質問への回答を生成するモデルを作る

2つ（又はそれ以上）の言語のテキストからなる十分大きなコーパスがあれば、因果言語モデリングのセクションと同様に、新しい翻訳モデルをゼロから学習出来ます。但し、既存の翻訳モデルをファインチューニングする方が速く済みます。多言語モデルの mT5 や mBART を特定の言語ペア向けにファインチューニングする場合も、特定の言語ペアに特化したモデルを自分のコーパス向けにファインチューニングする場合も、対象になります。

このセクションでは、英語からフランス語への翻訳で事前学習された Marian モデルを、KDE4 データセットでファインチューニングします。KDE4 は KDE アプリのローカライズ用ファイルのデータセットです。Hugging Face の社員の多くが英語とフランス語の2言語を話す為、この言語ペアを選びます。使うモデルは、Opus データセットから取得したフランス語と英語の大規模コーパスで事前学習されています。Opus には KDE4 データセット自体も含まれます。但し、事前学習モデルが事前学習の段階でそのデータを見ていたとしても、ファインチューニング後にはより良いモデルが得られます。

### データの処理








手順はこれまでと同じです。モデルが理解出来るよう、テキストは全てトークン ID の集合に変換します。このタスクでは、入力とターゲットの両方をトークン化します。

まず `tokenizer` オブジェクトを作成します。前述の通り、英語からフランス語への Marian 事前学習モデルを使います。別の言語ペアでこのコードを試す場合は、モデルのチェックポイントを合わせて変更してください。[Helsinki-NLP](https://huggingface.co/Helsinki-NLP) 組織は、複数言語で1,000を超えるモデルを提供しています。

```python
from transformers import AutoTokenizer

model_checkpoint = "Helsinki-NLP/opus-mt-en-fr"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint, return_tensors="pt")

model_checkpoint は、Hub にある別のモデルや、事前学習済みモデルとトークナイザを保存したローカルフォルダに置き換えることも出来ます。

💡 ヒント

💡 mBART、mBART-50、M2M100 のような多言語トークナイザを使う場合は、入力とターゲットの言語コードをトークナイザに設定する必要があります。設定には、tokenizer.src_lang と tokenizer.tgt_lang に適切な値を入れます。

データの準備はかなり単純です。注意点は1つだけです。トークナイザには、ターゲットを出力言語（ここではフランス語）として処理させる必要があります。その為には、トークナイザの __call__ メソッドの text_targets 引数にターゲットを渡します。

仕組みを確認する為、学習セットから各言語のサンプルを1つずつ処理します。

en_sentence = split_datasets["train"][1]["translation"]["en"]
fr_sentence = split_datasets["train"][1]["translation"]["fr"]

inputs = tokenizer(en_sentence, text_target=fr_sentence)
inputs

```python out

出力には、英語の文に対応する入力 ID が含まれます。フランス語の文に対応する ID は `labels` フィールドに格納されます。ラベルをトークン化していることを指定し忘れると、ラベルは入力用トークナイザでトークン化されます。Marian モデルの場合、これは全くうまくいきません。

```python
wrong_targets = tokenizer(fr_sentence)
print(tokenizer.convert_ids_to_tokens(wrong_targets["input_ids"]))

```python out ['▁Par', '▁dé', 'f', 'aut', ',', '▁dé', 've', 'lop', 'per', '▁les', '▁fil', 's', '▁de', '▁discussion', ''] ['▁Par', '▁défaut', ',', '▁développer', '▁les', '▁fils', '▁de', '▁discussion', '']

英語のトークナイザでフランス語の文を前処理すると、トークン数がずっと多くなります。トークナイザがフランス語の単語を知らない為です。"discussion" のように英語にも現れる単語は除きます。

`inputs` は通常のキー（入力 ID、アテンションマスクなど）を持つ辞書です。最後のステップとして、データセットに適用する前処理関数を定義します。

```python
max_length = 128


def preprocess_function(examples):
    inputs = [ex["en"] for ex in examples["translation"]]
    targets = [ex["fr"] for ex in examples["translation"]]
    model_inputs = tokenizer(
        inputs, text_target=targets, max_length=max_length, truncation=True
    )
    return model_inputs

入力と出力には、同じ最大長を設定しています。扱うテキストはかなり短い為、128 を使います。

💡 ヒント

💡 T5 モデル（具体的には t5-xxx チェックポイントのいずれか）を使う場合、モデルはテキスト入力にタスクを示す接頭辞が付いていることを想定します。接頭辞の例は translate: English to French: です。

⚠️ 注意

⚠️ ターゲットのアテンションマスクは使いません。モデルが想定していない為です。代わりに、パディングトークンに対応するラベルは -100 に設定します。損失の計算で無視する為です。ここでは動的パディングを適用する為、この処理は後でデータコレータが行います。但し、ここでパディングを行う場合は、パディングトークンに対応するラベルを全て -100 に設定するよう、前処理関数を適応させてください。

これで、データセットの全てのスプリットに前処理を一括で適用します。

tokenized_datasets = split_datasets.map(
    preprocess_function,
    batched=True,
    remove_columns=split_datasets["train"].column_names,
)

データコレータ

動的バッチ処理のパディングには、データコレータが必要です。このケースでは、Chapter 3 で使った DataCollatorWithPadding をそのまま使えません。このコレータは、入力（入力 ID、アテンションマスク、トークンタイプ ID）しかパディングしない為です。ラベルも、バッチ内の最大長までパディングする必要があります。また、前述の通り、ラベルのパディングに使う値は、トークナイザのパディングトークンではなく -100 とします。パディングされた値を損失の計算で無視する為です。

これらを全て行うのは DataCollatorForSeq2Seq です。DataCollatorWithPadding と同様に、入力の前処理に使った tokenizer を受け取りますが、model も受け取ります。これは、このデータコレータがデコーダ入力 ID の準備も担当する為です。デコーダ入力 ID は、ラベルをシフトし、先頭に特殊トークンを置いたものです。このシフトの方法はアーキテクチャによって少し異なります。その為、DataCollatorForSeq2Seq は model オブジェクトを必要とします。

{#if fw === 'pt'}

from transformers import DataCollatorForSeq2Seq

data_collator = DataCollatorForSeq2Seq(tokenizer, model=model)

{:else}

from transformers import DataCollatorForSeq2Seq

data_collator = DataCollatorForSeq2Seq(tokenizer, model=model, return_tensors="tf")

{/if}

翻訳で伝統的に使われる指標は、Kishore Papineni らによる 2002年の論文 で導入された BLEU スコア です。BLEU スコアは、翻訳がラベルにどれだけ近いかを評価します。モデルが生成した出力の分かりやすさや文法的な正しさは測りません。代わりに、統計的な規則を用いて、生成された出力に含まれる単語が全てターゲットにも現れることを確認します。更に、同じ単語の繰り返しと短い出力にはペナルティを与える規則もあります。ターゲットでも繰り返されていないのに同じ単語が繰り返される場合（モデルが "the the the the the" のような文を出力するのを避ける為）と、ターゲットより短い文を出力する場合（モデルが "the" のような文を出力するのを避ける為）が対象です。

BLEU の弱点は1つあります。テキストが既にトークン化されていることを前提とする点です。その為、異なるトークナイザを使うモデル同士では、スコアを比較しにくくなります。今日の翻訳モデルのベンチマークで最もよく使われる指標は SacreBLEU です。SacreBLEU は、トークン化のステップを標準化することで、この弱点（や他の弱点）に対処しています。この指標を使うには、まず SacreBLEU ライブラリをインストールします。

!pip install sacrebleu

その後、Chapter 3 で行ったように、evaluate.load() で読み込めます。

この指標は、テキストを入力とターゲットとして受け取ります。同じ文に対して許容出来る翻訳は複数あることが多い為、許容出来るターゲットを複数受け取れるよう設計されています。使うデータセットが提供するターゲットは1つだけです。但し、NLP ではラベルとして複数の文を与えるデータセットも珍しくありません。その為、予測は文のリストとし、参照は文のリストのリストとします。

モデルの出力から指標が使えるテキストに変換するには、`tokenizer.batch_decode()` メソッドを使います。ラベル内の `-100` を全て除去します。トークナイザはパディングトークンについても自動的に同じことを行います。モデルとデータセットを受け取り、その指標を計算する関数を定義します。

併せて、性能を大きく高める工夫も使います。生成コードを、TensorFlow の高速化線形代数コンパイラである [XLA](https://www.tensorflow.org/xla) でコンパイルする工夫です。XLA はモデルの計算グラフに様々な最適化を適用し、速度とメモリ使用量を大きく改善します。Hugging Face の[ブログ](https://huggingface.co/blog/tf-xla-generate)で説明されているように、XLA は入力の形状があまり変化しない時に最も効果を発揮します。これに対応する為、入力を128の倍数までパディングし、パディング用コレータで新しいデータセットを作ります。生成関数には `@tf.function(jit_compile=True)` デコレータを適用し、関数全体を XLA でコンパイルするようマークします。

```py
import numpy as np
import tensorflow as tf
from tqdm import tqdm

generation_data_collator = DataCollatorForSeq2Seq(
    tokenizer, model=model, return_tensors="tf", pad_to_multiple_of=128
)

tf_generate_dataset = model.prepare_tf_dataset(
    tokenized_datasets["validation"],
    collate_fn=generation_data_collator,
    shuffle=False,
    batch_size=8,
)


@tf.function(jit_compile=True)
def generate_with_xla(batch):
    return model.generate(
        input_ids=batch["input_ids"],
        attention_mask=batch["attention_mask"],
        max_new_tokens=128,
    )


def compute_metrics():
    all_preds = []
    all_labels = []

    for batch, labels in tqdm(tf_generate_dataset):
        predictions = generate_with_xla(batch)
        decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)
        labels = labels.numpy()
        labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
        decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)
        decoded_preds = [pred.strip() for pred in decoded_preds]
        decoded_labels = [[label.strip()] for label in decoded_labels]
        all_preds.extend(decoded_preds)
        all_labels.extend(decoded_labels)

    result = metric.compute(predictions=all_preds, references=all_labels)
    return {"bleu": result["score"]}

モデルの出力から指標が使えるテキストへ変換するには、tokenizer.batch_decode() メソッドを使います。ラベル内の -100 を全て除去します。トークナイザは、パディングトークンについても自動的に同じ処理を行います。

import numpy as np


def compute_metrics(eval_preds):
    preds, labels = eval_preds
    # モデルが予測ロジット以上のものを返す場合に備えます
    if isinstance(preds, tuple):
        preds = preds[0]

    decoded_preds = tokenizer.batch_decode(preds, skip_special_tokens=True)

    # ラベル内の -100 はデコードできないので置き換えます
    labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
    decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)

    # 簡単な後処理
    decoded_preds = [pred.strip() for pred in decoded_preds]
    decoded_labels = [[label.strip()] for label in decoded_labels]

    result = metric.compute(predictions=decoded_preds, references=decoded_labels)
    return {"bleu": result["score"]}

学習ループ

これで、完全な学習ループを書く準備が出来ました。評価部分を単純化する為、予測とラベルを受け取り、metric オブジェクトが期待する文字列のリストへ変換する postprocess() 関数を定義します。

def postprocess(predictions, labels):
    predictions = predictions.cpu().numpy()
    labels = labels.cpu().numpy()

    decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)

    # ラベル内の -100 はデコードできないので置き換えます
    labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
    decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)

    # 簡単な後処理
    decoded_preds = [pred.strip() for pred in decoded_preds]
    decoded_labels = [[label.strip()] for label in decoded_labels]
    return decoded_preds, decoded_labels

学習ループは、セクション2 や Chapter 3 のものによく似ています。但し、評価部分にいくつかの違いがあります。以下では評価部分を中心に説明します。

まず注意すべき点は、予測の計算に使う generate() メソッドです。このメソッドは、prepare() メソッドで Accelerate が作成したラップ済みモデルではなく、ベースモデルのメソッドです。その為、まずモデルをアンラップしてから呼び出します。

2つ目は、パディングの形状です。トークン分類 の場合と同様に、2つのプロセスが入力とラベルを異なる形状にパディングしている可能性があります。その為、gather() メソッドを呼ぶ前に、accelerator.pad_across_processes() を使って予測とラベルを同じ形状に揃えます。これを行わないと、評価でエラーになるか、処理が止まったままになります。

from tqdm.auto import tqdm
import torch

progress_bar = tqdm(range(num_training_steps))

for epoch in range(num_train_epochs):
    # 学習
    model.train()
    for batch in train_dataloader:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

    # 評価
    model.eval()
    for batch in tqdm(eval_dataloader):
        with torch.no_grad():
            generated_tokens = accelerator.unwrap_model(model).generate(
                batch["input_ids"],
                attention_mask=batch["attention_mask"],
                max_length=128,
            )
        labels = batch["labels"]

        # gather するために予測とラベルをパディングする必要があります
        generated_tokens = accelerator.pad_across_processes(
            generated_tokens, dim=1, pad_index=tokenizer.pad_token_id
        )
        labels = accelerator.pad_across_processes(labels, dim=1, pad_index=-100)

        predictions_gathered = accelerator.gather(generated_tokens)
        labels_gathered = accelerator.gather(labels)

        decoded_preds, decoded_labels = postprocess(predictions_gathered, labels_gathered)
        metric.add_batch(predictions=decoded_preds, references=decoded_labels)

    results = metric.compute()
    print(f"エポック {epoch}, BLEU スコア: {results['score']:.2f}")

    # 保存とアップロード
    accelerator.wait_for_everyone()
    unwrapped_model = accelerator.unwrap_model(model)
    unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
    if accelerator.is_main_process:
        tokenizer.save_pretrained(output_dir)
        repo.push_to_hub(
            commit_message=f"Training in progress epoch {epoch}", blocking=False
        )
