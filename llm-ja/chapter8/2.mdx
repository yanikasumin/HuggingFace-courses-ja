するとユーザー名とパスワードの入力を求められ、トークンが *~/.cache/huggingface/* の下に保存されます。ログインしたら、次の関数でテンプレートリポジトリをコピーできます。

```python
from distutils.dir_util import copy_tree
from huggingface_hub import Repository, snapshot_download, create_repo, get_full_repo_name


def copy_repository_template():
    # リポジトリをクローンし、ローカルパスを取り出す
    template_repo_id = "lewtun/distilbert-base-uncased-finetuned-squad-d5716d28"
    commit_hash = "be3eaffc28669d7932492681cd5f3e8905e358b4"
    template_repo_dir = snapshot_download(template_repo_id, revision=commit_hash)
    # Hub 上に空のリポジトリを作成する
    model_name = template_repo_id.split("/")[1]
    create_repo(model_name, exist_ok=True)
    # 空のリポジトリをクローンする
    new_repo_id = get_full_repo_name(model_name)
    new_repo_dir = model_name
    repo = Repository(local_dir=new_repo_dir, clone_from=new_repo_id)
    # ファイルをコピーする
    copy_tree(template_repo_dir, new_repo_dir)
    # Hub にプッシュする
    repo.push_to_hub()
```

これで、`copy_repository_template()` を呼び出すと、テンプレートリポジトリのコピーが自分のアカウントの下に作成されます。

## 🤗 Transformers の pipeline をデバッグする[[debugging-the-pipeline-from-transformers]]

Transformer モデルのデバッグを学ぶ第一歩として、次のような場面を考えてみましょう。あなたは同僚と、eコマースサイトの顧客が消費財についての答えを見つけられるよう支援する、質問応答プロジェクトに取り組んでいます。同僚から次のようなメッセージが届きます。

> やあ！Hugging Face コースの [Chapter 7](/course/chapter7/7) のテクニックを使って実験してみたら、SQuAD でかなり良い結果が出たよ！このモデルをプロジェクトの出発点にできると思う。Hub 上のモデル ID は "lewtun/distillbert-base-uncased-finetuned-squad-d5716d28" だよ。気軽に試してみて :)

これらのレポートには大量の情報が含まれているので、重要な部分を一緒にたどっていきましょう。まず注意すべきは、トレースバックは_下から上へ_読むということです。英語のテキストを上から下へ読むのに慣れていると奇妙に聞こえるかもしれませんが、これは、トレースバックが `pipeline` がモデルとトークナイザをダウンロードするときに行う関数呼び出しの順序を示しているためです（`pipeline` が裏側でどう動くかの詳細は [Chapter 2](/course/chapter2) を参照してください）。

> [!TIP]
> 🚨 Google Colab のトレースバックで "6 frames" の周りにある青いボックスが見えますか？これは Colab の特殊な機能で、トレースバックを「フレーム」に圧縮します。エラーの発生源が見つからない場合は、小さな2つの矢印をクリックしてトレースバック全体を展開してください。

つまり、トレースバックの最後の行が、最後のエラーメッセージを示し、発生した例外の名前を与えてくれます。今回の場合、例外の種類は `OSError` で、システム関連のエラーを示しています。付随するエラーメッセージを読むと、モデルの *config.json* ファイルに問題があるようで、修正方法として2つの提案が示されています。

やりました、うまくいきました。ここで学んだことをまとめましょう。

- Python のエラーメッセージは_トレースバック_と呼ばれ、下から上へ読みます。エラーメッセージの最後の行には通常、問題の発生源を特定するのに必要な情報が含まれています。
- 最後の行に十分な情報がない場合は、トレースバックを上にたどって、ソースコードのどこでエラーが起きているか特定できないか見てみましょう。
- どのエラーメッセージも問題のデバッグに役立たない場合は、似た問題への解決策をオンラインで探してみましょう。
- `huggingface_hub` ライブラリには、Hub 上のリポジトリを操作したりデバッグしたりするために使えるツールが一式そろっています。

pipeline のデバッグ方法が分かったところで、モデル自体のフォワードパスという、より厄介な例を見てみましょう。

## モデルのフォワードパスをデバッグする[[debugging-the-forward-pass-of-your-model]]

`pipeline` は、予測を手早く生成したいほとんどの用途には最適ですが、モデルのロジットにアクセスしたい場合もあります（たとえば、適用したいカスタムの後処理がある場合など）。この場合に何がうまくいかないかを見るために、まず `pipeline` からモデルとトークナイザを取り出しましょう。

```python
tokenizer = reader.tokenizer
model = reader.model
```

次は質問文を用意します。お気に入りのフレームワークがサポートされているか尋ねてみましょう。

```python
question = "Which frameworks can I use?"
```

[Chapter 7](/course/chapter7) で見たように、通常必要な手順は、入力をトークン化し、開始トークンと終了トークンのロジットを取り出し、答えの範囲をデコードすることです。

```python
import torch

inputs = tokenizer(question, context, add_special_tokens=True)
input_ids = inputs["input_ids"][0]
outputs = model(**inputs)
answer_start_scores = outputs.start_logits
answer_end_scores = outputs.end_logits
# スコアが最大になる位置を、回答の開始位置として選ぶ
answer_start = torch.argmax(answer_start_scores)
# スコアが最大になる位置を基に、回答の終了位置を求める
answer_end = torch.argmax(answer_end_scores) + 1
answer = tokenizer.convert_tokens_to_string(
    tokenizer.convert_ids_to_tokens(input_ids[answer_start:answer_end])
)
print(f"質問: {question}")
print(f"回答: {answer}")
```
