前のセクションでは、最も単純なケース、すなわち短いシーケンス1つに対する推論を見てきました。但し、この段階でも既にいくつか疑問が生じます。

- 複数のシーケンスをどう扱えばよいのでしょうか？
- 長さの *異なる* 複数のシーケンスをどう扱えばよいのでしょうか？

これらの疑問がどのような問題を生むのか、そして 🤗 Transformers API を使ってどう解決出来るのかを見ていきます。

## モデルはバッチ入力を想定している[[models-expect-a-batch-of-inputs]]

前の演習では、シーケンスが数値のリストへ変換される様子を見ました。では、その数値のリストをテンソルへ変換してモデルへ送ってみましょう。

```py
import torch
from transformers import AutoTokenizer, AutoModelForSequenceClassification

checkpoint = "distilbert-base-uncased-finetuned-sst-2-english"
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
model = AutoModelForSequenceClassification.from_pretrained(checkpoint)

sequence = "I've been waiting for a HuggingFace course my whole life."

tokens = tokenizer.tokenize(sequence)
ids = tokenizer.convert_tokens_to_ids(tokens)
input_ids = torch.tensor(ids)
# この行は失敗します。
model(input_ids)
```

（入力文の訳：ずっと Hugging Face のコースを待ち望んでいました）

```python out
IndexError: Dimension out of range (expected to be in range of [-1, 0], but got 1)
```

失敗しました。理由は何でしょうか。セクション2のパイプラインの手順に従ったはずです。

問題は、シーケンスを1つだけモデルへ送ったことにあります。Transformers のモデルは、既定では複数の文を想定しています。

ここでは、トークナイザを `sequence` に適用した時に裏側で行われていた処理を、全て自分で再現しようとしました。但し、注意深く見ると、トークナイザは入力 ID のリストをテンソルへ変換しただけではありません。その上に次元を1つ追加していました。

```py
tokenized_inputs = tokenizer(sequence, return_tensors="pt")
print(tokenized_inputs["input_ids"])
```

```python out
tensor([[  101,  1045,  1005,  2310,  2042,  3403,  2005,  1037, 17662, 12172,
          2607,  2026,  2878,  2166,  1012,   102]])
```

新しい次元を追加して、改めて試してみましょう。

```py
import torch
from transformers import AutoTokenizer, AutoModelForSequenceClassification

checkpoint = "distilbert-base-uncased-finetuned-sst-2-english"
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
model = AutoModelForSequenceClassification.from_pretrained(checkpoint)

sequence = "I've been waiting for a HuggingFace course my whole life."

tokens = tokenizer.tokenize(sequence)
ids = tokenizer.convert_tokens_to_ids(tokens)

input_ids = torch.tensor([ids])
print("入力 ID:", input_ids)

output = model(input_ids)
print("ロジット:", output.logits)
```

入力 ID と結果のロジットを出力すると、次のようになります。

```python out
入力 ID: [[ 1045,  1005,  2310,  2042,  3403,  2005,  1037, 17662, 12172,  2607, 2026,  2878,  2166,  1012]]
ロジット: [[-2.7276,  2.8789]]
```

*バッチ処理* とは、複数の文をまとめて一度にモデルへ通す処理です。文が1つしか無い場合でも、シーケンス1つだけのバッチを作れば対応出来ます。

```
batched_ids = [ids, ids]
```

同一のシーケンスを2つ並べたバッチです。

> [!TIP]
> **試してみましょう！** この `batched_ids` リストをテンソルに変換して、モデルに通してみてください。前に得たのと同じロジットが（但し2つ分）得られることを確認しましょう！

バッチ処理により、モデルへ複数の文を入力出来るようになります。複数のシーケンスを使う場合も、バッチの作り方はシーケンス1つの場合と同じくらい簡単です。但し、2つ目の問題があります。2つ以上の文をバッチにまとめようとすると、文の長さが異なる場合があるのです。テンソルは長方形の形状でなければならない為、入力 ID のリストをそのままテンソルへ変換することは出来ません。この問題への対処として、通常は入力を *パディング* します。

## 入力をパディングする[[padding-the-inputs]]

次のリストのリストは、テンソルへ変換出来ません。

```py no-format
batched_ids = [
    [200, 200, 200],
    [200, 200]
]
```

この問題を回避する為に、*パディング* を使ってテンソルの形状を長方形にします。パディングでは、値の少ない文に *パディングトークン* と呼ばれる特殊な語を追加し、全ての文の長さを揃えます。例えば、10単語の文が10文と、20単語の文が1文有る場合、パディングにより全ての文が20単語の長さになります。上の例に適用すると、結果のテンソルは次のようになります。

```py no-format
padding_id = 100

batched_ids = [
    [200, 200, 200],
    [200, 200, padding_id],
]
```

パディングトークンの ID は、`tokenizer.pad_token_id` で分かります。これを使って、2つの文を個別にモデルへ通した場合と、バッチにまとめて通した場合を比べてみましょう。

```py no-format
model = AutoModelForSequenceClassification.from_pretrained(checkpoint)

sequence1_ids = [[200, 200, 200]]
sequence2_ids = [[200, 200]]
batched_ids = [
    [200, 200, 200],
    [200, 200, tokenizer.pad_token_id],
]

print(model(torch.tensor(sequence1_ids)).logits)
print(model(torch.tensor(sequence2_ids)).logits)
print(model(torch.tensor(batched_ids)).logits)
```

```python out
tensor([[ 1.5694, -1.3895]], grad_fn=<AddmmBackward>)
tensor([[ 0.5803, -0.4125]], grad_fn=<AddmmBackward>)
tensor([[ 1.5694, -1.3895],
        [ 1.3373, -1.2163]], grad_fn=<AddmmBackward>)
```

バッチ予測のロジットには、何か問題があります。2行目は、2番目の文だけを入力した場合のロジットと同じになるはずです。ところが、得られた値は全く異なるものになっています。

原因は、Transformer モデルの中核であるアテンション層にあります。アテンション層は、各トークンを周囲のトークンとの関係で捉え直します（*文脈化* します）。アテンション層はシーケンス内の全トークンに注意を向ける為、パディングトークンも対象に含まれてしまいます。長さの異なる文を個別に通した場合と、パディングを適用してバッチで通した場合とで同じ結果を得るには、アテンション層にパディングトークンを無視させる必要があります。その為に使うのがアテンションマスクです。

## アテンションマスク[[attention-masks]]

*アテンションマスク* は、入力 ID テンソルと全く同じ形状のテンソルで、0 と 1 で埋められています。1 は、対応するトークンに注意を向けることを示します。0 は、対応するトークンに注意を向けないこと、すなわちモデルのアテンション層がそのトークンを無視することを示します。

アテンションマスクを使って、前の例を完成させましょう。

```py no-format
batched_ids = [
    [200, 200, 200],
    [200, 200, tokenizer.pad_token_id],
]

attention_mask = [
    [1, 1, 1],
    [1, 1, 0],
]

outputs = model(torch.tensor(batched_ids), attention_mask=torch.tensor(attention_mask))
print(outputs.logits)
```

```python out
tensor([[ 1.5694, -1.3895],
        [ 0.5803, -0.4125]], grad_fn=<AddmmBackward>)
```

今度は、バッチ内の2番目の文についても、個別に処理した場合と同じロジットが得られました。

2番目のシーケンスの最後の値はパディング ID であり、対応するアテンションマスクの値は 0 である点に注意してください。

> [!TIP]
> **試してみましょう！** セクション2で使った2つの文（"I've been waiting for a HuggingFace course my whole life." と "I hate this so much!"）に対して、手動でトークン化を適用してみてください。モデルに通して、セクション2と同じロジットが得られることを確認しましょう。次に、パディングトークンを使って2つをバッチにまとめ、適切なアテンションマスクを作成してください。モデルに通した時に同じ結果が得られることを確認しましょう！

## より長いシーケンス[[longer-sequences]]

Transformer モデルには、渡せるシーケンスの長さに上限があります。殆どのモデルが扱えるのは 512 トークン又は 1024 トークンまでであり、それより長いシーケンスを処理させようとすると失敗します。この問題への対処法は2つあります。

- サポートされるシーケンス長がより長いモデルを使う。
- シーケンスを切り捨てる。

対応するシーケンス長はモデルごとに異なります。中には、非常に長いシーケンスの処理に特化したモデルもあります。例として [Longformer](https://huggingface.co/docs/transformers/model_doc/longformer) と [LED](https://huggingface.co/docs/transformers/model_doc/led) が挙げられます。非常に長いシーケンスを必要とするタスクに取り組む場合は、これらのモデルを確認することをお勧めします。

それ以外の場合は、シーケンスを切り捨てることをお勧めします。切り捨ては `max_sequence_length` パラメータを指定して行います。

```py
sequence = sequence[:max_sequence_length]
```
