最初に取り上げる応用はトークン分類です。トークン分類とは、文中の各トークンにラベルを割り当てるタスクです。この形に定式化出来る問題は数多くあります。代表的な例は次の通りです。

- **固有表現認識（NER）**：文中のエンティティ（人名、地名、組織名など）を見つけます。エンティティの種類ごとに1つのクラスと、「エンティティではない」場合の1つのクラスを用意することで、各トークンへのラベル割り当てとして定式化出来ます。
- **品詞タグ付け（POS）**：文中の各単語が、特定の品詞（名詞、動詞、形容詞など）のどれに対応するかを付けます。
- **チャンキング**：同じエンティティに属するトークンを見つけます。このタスクは POS や NER と組み合わせて使うことも出来ます。通常、チャンクの先頭に在るトークンには1つのラベル（通常は `B-`）、チャンクの内部に在るトークンには別のラベル（通常は `I-`）、どのチャンクにも属さないトークンには3つ目のラベル（通常は `O`）を割り当てる形で定式化出来ます。

## データの準備[[preparing-the-data]]

トークン分類には、まず適したデータセットが必要です。このセクションでは、Reuters のニュース記事を含む [CoNLL-2003 データセット](https://huggingface.co/datasets/conll2003)を使います。

> [!TIP]
> 💡 データセットが、対応するラベルと共に単語に分割されたテキストで構成されている限り、ここで説明するデータ処理の手順を自分のデータセットにも適用出来ます。`Dataset` に独自のカスタムデータを読み込む方法を復習したい場合は、[Chapter 5](/course/chapter5)を参照してください。

### データの処理[[processing-the-data]]

<Youtube id="iY2AZYdZAr0"/>

テキストは、これまでと同様にトークン ID へ変換してからモデルへ渡します。トークン分類で異なるのは、入力が事前に単語へ分割されている点です（[Chapter 6](/course/chapter6/) 参照）。トークナイザ API はこの形式にも対応しています。特別なフラグで `tokenizer` に知らせるだけです。

まず、`tokenizer` オブジェクトを作成します。使うモデルは BERT の事前学習済みモデルです。対応するトークナイザをダウンロードし、キャッシュします。

```python
from transformers import AutoTokenizer

model_checkpoint = "bert-base-cased"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint)
```

`model_checkpoint` は、[Hub](https://huggingface.co/models) にある別のモデルや、事前学習済みモデルとトークナイザを保存したローカルフォルダに置き換えることも出来ます。制約は次の点だけです。Tokenizers ライブラリによる高速トークナイザが使える必要があります。高速バージョンを持つアーキテクチャの一覧は、[この大きな表](https://huggingface.co/transformers/#supported-frameworks)で確認出来ます。使用している `tokenizer` オブジェクトが Tokenizers によるものかどうかは、`is_fast` 属性で確認出来ます。

```py
tokenizer.is_fast
```

```python out
True
```

事前にトークン化された入力をトークン化するには、通常通り `tokenizer` を使い、`is_split_into_words=True` を追加するだけです。

```py
inputs = tokenizer(raw_datasets["train"][0]["tokens"], is_split_into_words=True)
inputs.tokens()
```

```python out
['[CLS]', 'EU', 'rejects', 'German', 'call', 'to', 'boycott', 'British', 'la', '##mb', '.', '[SEP]']
```

トークナイザは、モデルが使う特殊トークン（先頭の `[CLS]` と末尾の `[SEP]`）を追加し、殆どの単語はそのまま残しました。一方、単語 `lamb` は `la` と `##mb` の2つのサブワードに分かれました。その結果、入力とラベルの数が合いません。ラベルは9要素ですが、入力は12トークンあります。

特殊トークンへの対応は簡単です。位置が先頭と末尾に決まっている為です。残る問題は、全てのラベルを適切な単語に対応させることです。

高速トークナイザには、各トークンを対応する単語へ対応付ける機能があります（[Chapter 6](/course/chapter6/3) で見た機能です）。これを使います。

```py
inputs.word_ids()
```

```python out
[None, 0, 1, 2, 3, 4, 5, 6, 7, 7, 8, None]
```

ラベルのリストは、トークンに合わせて拡張出来ます。拡張のルールは次の通りです。1つ目は、特殊トークンに `-100` というラベルを付けることです。`-100` は、既定で損失関数（交差エントロピー）において無視されるインデックスである為です。単語内の各トークンには、その単語の先頭のトークンと同じラベルを付けます。同じエンティティの一部である為です。但し、単語の内部にあって先頭ではないトークンでは、`B-` を `I-` に置き換えます。エンティティを開始するトークンではない為です。

```python
def align_labels_with_tokens(labels, word_ids):
    new_labels = []
    current_word = None
    for word_id in word_ids:
        if word_id != current_word:
            # 新しい単語の先頭
            current_word = word_id
            label = -100 if word_id is None else labels[word_id]
            new_labels.append(label)
        elif word_id is None:
            # 特殊トークン
            new_labels.append(-100)
        else:
            # 前のトークンと同じ単語
            label = labels[word_id]
            # ラベルが B-XXX なら I-XXX に変更する
            if label % 2 == 1:
                label += 1
            new_labels.append(label)

    return new_labels
```

最初の文で試してみましょう。

```py
labels = raw_datasets["train"][0]["ner_tags"]
word_ids = inputs.word_ids()
print(labels)
print(align_labels_with_tokens(labels, word_ids))
```

```python out
[3, 0, 7, 0, 0, 0, 7, 0, 0]
[-100, 3, 0, 7, 0, 0, 0, 7, 0, 0, 0, -100]
```

この関数は、先頭と末尾の2つの特殊トークンに `-100` を追加しています。更に、2つのトークンに分割された単語には、新しい `0` を追加しています。

> [!TIP]
> ✏️ **試してみましょう！** 単語ごとに1つのラベルだけを割り当て、或る単語に属する他のサブトークンには `-100` を割り当てる方法もあります。多くのサブトークンに分割される長い単語が、損失に大きく寄与するのを避ける為です。このルールに従って先程の関数を変更し、ラベルを入力 ID に揃えてください。

データセット全体を前処理するには、全ての入力をトークン化し、全てのラベルに `align_labels_with_tokens()` を適用します。

高速トークナイザの速度を活かす為、多数のテキストを同時にトークン化します。サンプルのリストを処理する関数を書き、`batched=True` オプションを指定して `Dataset.map()` メソッドを使います。前の例との違いは次の点だけです。トークナイザへの入力がテキストのリスト（この場合は単語のリストのリスト）の場合、`word_ids()` 関数には、単語 ID が欲しいサンプルのインデックスを渡す必要があります。その処理も追加しています。

```py
def tokenize_and_align_labels(examples):
    tokenized_inputs = tokenizer(
        examples["tokens"], truncation=True, is_split_into_words=True
    )
    all_labels = examples["ner_tags"]
    new_labels = []
    for i, labels in enumerate(all_labels):
        word_ids = tokenized_inputs.word_ids(i)
        new_labels.append(align_labels_with_tokens(labels, word_ids))

    tokenized_inputs["labels"] = new_labels
    return tokenized_inputs
```

入力へのパディングはまだ行っていません。バッチを作成する時にデータコレータで行います。

これで、データセットの他の分割に対しても、全ての前処理を一度に適用出来ます。

```py
tokenized_datasets = raw_datasets.map(
    tokenize_and_align_labels,
    batched=True,
    remove_columns=raw_datasets["train"].column_names,
)
```

難しい部分はここまでです。データの前処理が済んだので、実際の学習は [Chapter 3](/course/chapter3) で行った手順とよく似ています。

### モデルの定義[[defining-the-model]]

トークン分類の問題では、`TFAutoModelForTokenClassification` クラスを使います。モデルを定義する際には、ラベルの数に関する情報を渡す必要があります。最も簡単な方法は `num_labels` 引数で数を渡す方法です。但し、このセクションの冒頭で紹介した推論ウィジェットを正しく動作させるには、正しいラベルの対応を設定する方が適しています。

ラベルの対応は、`id2label` と `label2id` の2つの辞書で設定します。ID からラベルへの対応と、その逆の対応を表す辞書です。

```py
id2label = {i: label for i, label in enumerate(label_names)}
label2id = {v: k for k, v in id2label.items()}
```

これらを `TFAutoModelForTokenClassification.from_pretrained()` メソッドに渡すと、モデルの設定に組み込まれ、保存と Hub へのアップロードが正しく行われます。

```py
from transformers import TFAutoModelForTokenClassification

model = TFAutoModelForTokenClassification.from_pretrained(
    model_checkpoint,
    id2label=id2label,
    label2id=label2id,
)
```

### モデルのファインチューニング[[fine-tuning-the-model]]

モデルの学習を始める前に、残りの準備を行います。Hugging Face へのログインと、学習のハイパーパラメータの定義です。ノートブックで作業している場合は、ログインに便利な関数があります。

```python
from huggingface_hub import notebook_login

notebook_login()
```

Hugging Face のログイン認証情報を入力するウィジェットが表示されます。

ノートブックで作業していない場合は、ターミナルで次の行を入力してください。

```bash
huggingface-cli login
```

ログイン後、モデルをコンパイルする為に必要なものを全て準備出来ます。Transformers には便利な `create_optimizer()` 関数があり、重み減衰と学習率減衰の適切な設定を備えた `AdamW` オプティマイザが得られます。どちらも、組み込みの `Adam` オプティマイザと比べてモデルの性能を向上させます。

```python
from transformers import create_optimizer
import tensorflow as tf

# 混合精度 float16 で学習する
# これによる恩恵を受けない GPU を使っている場合は、この行をコメントアウトする
tf.keras.mixed_precision.set_global_policy("mixed_float16")

# 学習ステップ数は、データセットのサンプル数をバッチサイズで割ってから、
# 総エポック数を掛けたもの。ここでの tf_train_dataset はバッチ化済みの tf.data.Dataset であり、
# 元の Hugging Face の Dataset ではないため、その len() はすでに num_samples // batch_size になっている。
num_epochs = 3
num_train_steps = len(tf_train_dataset) * num_epochs

optimizer, schedule = create_optimizer(
    init_lr=2e-5,
    num_warmup_steps=0,
    num_train_steps=num_train_steps,
    weight_decay_rate=0.01,
)
model.compile(optimizer=optimizer)
```

`compile()` に `loss` 引数を渡していない点に注意してください。モデルは内部で損失を計算出来る為です。損失を指定せずにコンパイルし、入力辞書の中にラベルを含めて渡す（データセットでもそのようにしています）と、モデルは内部の損失を使って学習します。この損失は、選択したタスクとモデルの種類に適したものです。

次に、`PushToHubCallback` を定義します。学習中にモデルを Hub にアップロードするコールバックです。そのコールバックを指定してモデルを fit します。

```python
from transformers.keras_callbacks import PushToHubCallback

callback = PushToHubCallback(output_dir="bert-finetuned-ner", tokenizer=tokenizer)

model.fit(
    tf_train_dataset,
    validation_data=tf_eval_dataset,
    callbacks=[callback],
    epochs=num_epochs,
)
```

`hub_model_id` 引数で、push 先のリポジトリの完全な名前を指定出来ます（特に、組織に push する場合はこの引数を使う必要があります）。例えば、モデルを [`huggingface-course` 組織](https://huggingface.co/huggingface-course)に push した際には、`hub_model_id="huggingface-course/bert-finetuned-ner"` を追加しました。既定では、使用されるリポジトリは自分の名前空間にあり、設定した出力ディレクトリにちなんだ名前になります（例: `"cool_huggingface_user/bert-finetuned-ner"`）。

> [!TIP]
> 💡 使用している出力ディレクトリが既に存在する場合、それは push 先リポジトリのローカルクローンである必要があります。そうでない場合、`model.fit()` を呼び出した時にエラーが発生し、新しい名前を設定する必要があります。

学習中は、モデルが保存されるたびに（ここではエポックごと）、バックグラウンドで Hub にアップロードされます。必要に応じて、別のマシンで学習を再開出来ます。

この段階では、Model Hub の推論ウィジェットを使ってモデルをテストし、友人と共有出来ます。トークン分類タスクでのファインチューニングは完了です。但し、モデルの出来はまだ確認していません。いくつかの指標を評価して確認します。

この `compute_metrics()` 関数は、まずロジットの argmax を取って予測に変換します。ロジットと確率は同じ順序にある為、softmax を適用する必要はありません。次に、ラベルと予測の両方を整数から文字列に変換し、ラベルが `-100` の値を取り除いて、結果を `metric.compute()` メソッドに渡します。

```py
import numpy as np


def compute_metrics(eval_preds):
    logits, labels = eval_preds
    predictions = np.argmax(logits, axis=-1)

    # 無視されるインデックス（特殊トークン）を取り除き、ラベルに変換する
    true_labels = [[label_names[l] for l in label if l != -100] for label in labels]
    true_predictions = [
        [label_names[p] for (p, l) in zip(prediction, label) if l != -100]
        for prediction, label in zip(predictions, labels)
    ]
    all_metrics = metric.compute(predictions=true_predictions, references=true_labels)
    return {
        "precision": all_metrics["overall_precision"],
        "recall": all_metrics["overall_recall"],
        "f1": all_metrics["overall_f1"],
        "accuracy": all_metrics["overall_accuracy"],
    }
```

### モデルの定義[[defining-the-model]]

トークン分類の問題では、`AutoModelForTokenClassification` クラスを使います。モデルを定義する際には、ラベルの数に関する情報を渡す必要があります。最も簡単な方法は `num_labels` 引数で数を渡す方法です。但し、このセクションの冒頭で紹介した推論ウィジェットを正しく動作させるには、正しいラベルの対応を設定する方が適しています。

id2label = {i: label for i, label in enumerate(label_names)}

## カスタム学習ループ[[a-custom-training-loop]]

次に、完全な学習ループを見ていきます。学習ループを直接書けば、必要な部分をカスタマイズ出来ます。評価にいくつか変更点はありますが、全体は [Chapter 3](/course/chapter3/4) で行った内容とよく似ています。

### 学習のための準備[[preparing-everything-for-training]]

まず、データセットから `DataLoader` を構築します。`data_collator` は `collate_fn` として再利用します。学習セットはシャッフルし、検証セットはシャッフルしません。

```py
from torch.utils.data import DataLoader

train_dataloader = DataLoader(
    tokenized_datasets["train"],
    shuffle=True,
    collate_fn=data_collator,
    batch_size=8,
)
eval_dataloader = DataLoader(
    tokenized_datasets["validation"], collate_fn=data_collator, batch_size=8
)
```

次に、モデルを再びインスタンス化します。前のファインチューニングの続きからではなく、BERT の事前学習済みモデルから開始する為です。

```py
model = AutoModelForTokenClassification.from_pretrained(
    model_checkpoint,
    id2label=id2label,
    label2id=label2id,
)
```

次にオプティマイザが必要です。古典的な `AdamW` を使います。これは `Adam` に似ていますが、重み減衰の適用方法に修正が加えられたものです。

```py
from torch.optim import AdamW

optimizer = AdamW(model.parameters(), lr=2e-5)
```

これらのオブジェクトが全て揃ったら、`accelerator.prepare()` メソッドに渡すことが出来ます。

```py
from accelerate import Accelerator

accelerator = Accelerator()
model, optimizer, train_dataloader, eval_dataloader = accelerator.prepare(
    model, optimizer, train_dataloader, eval_dataloader
)
```

> [!TIP]
> 🚨 TPU で学習する場合は、このセルより上にあるコードを全て、専用の学習関数の中に移動する必要があります。詳細は [Chapter 3](/course/chapter3) を参照してください。

`train_dataloader` を `accelerator.prepare()` に渡した後は、その長さを使って学習ステップ数を計算出来ます。データローダの長さはこのメソッドで変わる為、計算は必ず準備の後に行います。スケジュールには、学習率から 0 まで下げる古典的な線形スケジュールを使います。

```py
from transformers import get_scheduler

num_train_epochs = 3
num_update_steps_per_epoch = len(train_dataloader)
num_training_steps = num_train_epochs * num_update_steps_per_epoch

lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)
```

最後に、モデルを Hub に push する為の準備をします。作業フォルダに `Repository` オブジェクトを作成します。まだログインしていない場合は、先に Hugging Face にログインしてください。リポジトリ名は、モデルに付けたいモデル ID から決めます。`repo_name` は自由に置き換えてかまいませんが、ユーザー名を含む必要があります。ユーザー名の付加は `get_full_repo_name()` 関数が行います。

```py
from huggingface_hub import Repository, get_full_repo_name

model_name = "bert-finetuned-ner-accelerate"
repo_name = get_full_repo_name(model_name)
repo_name
```

```python out
'sgugger/bert-finetuned-ner-accelerate'
```

次に、そのリポジトリをローカルフォルダにクローンします。フォルダが既に存在する場合は、作業中のリポジトリの既存のクローンである必要があります。

```py
output_dir = "bert-finetuned-ner-accelerate"
repo = Repository(output_dir, clone_from=repo_name)
```

これで、`repo.push_to_hub()` メソッドを呼び出せば、`output_dir` に保存したものを何でもアップロード出来ます。これにより、各エポックの終了時に中間のモデルをアップロード出来ます。

### 学習ループ[[training-loop]]

これで完全な学習ループを書く準備が出来ました。評価部分を単純化する為に、予測とラベルを受け取り、`metric` オブジェクトが期待する形式である文字列のリストに変換する `postprocess()` 関数を定義します。

```py
def postprocess(predictions, labels):
    predictions = predictions.detach().cpu().clone().numpy()
    labels = labels.detach().cpu().clone().numpy()

    # 無視されるインデックス（特殊トークン）を取り除き、ラベルに変換する
    true_labels = [[label_names[l] for l in label if l != -100] for label in labels]
    true_predictions = [
        [label_names[p] for (p, l) in zip(prediction, label) if l != -100]
        for prediction, label in zip(predictions, labels)
    ]
    return true_labels, true_predictions
```

次に学習ループを書きます。学習の進み具合を追うプログレスバーを定義した後、ループ本体は3つの部分で構成されます。

- 学習そのもの。`train_dataloader` への古典的なイテレーションで、モデルへの順伝播を行い、次に逆伝播とオプティマイザのステップを行います。
- 評価。バッチの出力をモデルから得た後の処理に注意点があります。2つのプロセスが入力とラベルを異なる形状にパディングしている可能性がある為、`gather()` メソッドを呼び出す前に、`accelerator.pad_across_processes()` を使って予測とラベルを同じ形状に揃えます。これを行わないと、評価はエラーになるか、ハングしたままになります。その後、結果を `metric.add_batch()` に送り、評価ループが終わったら `metric.compute()` を呼び出します。
- 保存とアップロード。まずモデルとトークナイザを保存し、次に `repo.push_to_hub()` を呼び出します。`blocking=False` 引数を使って、Hub ライブラリに非同期プロセスで push するよう指示している点に注意してください。これにより、学習は通常通り継続し、この（時間のかかる）命令はバックグラウンドで実行されます。

学習ループの完全なコードは次の通りです。

```py
from tqdm.auto import tqdm
import torch

progress_bar = tqdm(range(num_training_steps))

for epoch in range(num_train_epochs):
    # 学習
    model.train()
    for batch in train_dataloader:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

    # 評価
    model.eval()
    for batch in eval_dataloader:
        with torch.no_grad():
            outputs = model(**batch)

        predictions = outputs.logits.argmax(dim=-1)
        labels = batch["labels"]

        # gather のためには予測とラベルのパディングが必要
        predictions = accelerator.pad_across_processes(predictions, dim=1, pad_index=-100)
        labels = accelerator.pad_across_processes(labels, dim=1, pad_index=-100)

        predictions_gathered = accelerator.gather(predictions)
        labels_gathered = accelerator.gather(labels)

        true_predictions, true_labels = postprocess(predictions_gathered, labels_gathered)
        metric.add_batch(predictions=true_predictions, references=true_labels)

    results = metric.compute()
    print(
        f"エポック {epoch}:",
        {
            key: results[f"overall_{key}"]
            for key in ["precision", "recall", "f1", "accuracy"]
        },
    )

    # 保存とアップロード
    accelerator.wait_for_everyone()
    unwrapped_model = accelerator.unwrap_model(model)
    unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
    if accelerator.is_main_process:
        tokenizer.save_pretrained(output_dir)
        repo.push_to_hub(
            commit_message=f"Training in progress epoch {epoch}", blocking=False
        )
```

Accelerate で保存されたモデルを初めて見る場合の為に、それに付随する3行のコードを少し見てみましょう。

```py
accelerator.wait_for_everyone()
unwrapped_model = accelerator.unwrap_model(model)
unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
```

1行目は、全てのプロセスに、続行する前に全員がその段階に到達するまで待つよう指示します。保存する前に、全てのプロセスで同じモデルが存在することを確実にする為です。

次に `unwrapped_model` を取得します。これは定義したベースモデルです。`accelerator.prepare()` メソッドはモデルを分散学習用に変更する為、`save_pretrained()` メソッドは使えなくなります。`accelerator.unwrap_model()` メソッドでその変更を元に戻します。最後に、`save_pretrained()` を呼び出します。その際、`torch.save()` の代わりに `accelerator.save()` を使うよう指示します。

これで、`Trainer` で学習したモデルとかなり似た結果を出すモデルが得られるはずです。このコードで学習したモデルは、[*huggingface-course/bert-finetuned-ner-accelerate*](https://huggingface.co/huggingface-course/bert-finetuned-ner-accelerate)で確認出来ます。学習ループを調整したい場合は、上に示したコードを直接編集して試すことが出来ます。

## ファインチューニング済みモデルの使用[[using-the-fine-tuned-model]]

ファインチューニングしたモデルを Model Hub の推論ウィジェットで使う方法は、既に紹介しました。ローカルで `pipeline` を使って実行する場合は、適切なモデル識別子を指定します。

```py
from transformers import pipeline

# これは自分のチェックポイントに置き換える
model_checkpoint = "huggingface-course/bert-finetuned-ner"
token_classifier = pipeline(
    "token-classification", model=model_checkpoint, aggregation_strategy="simple"
)
token_classifier("My name is Sylvain and I work at Hugging Face in Brooklyn.")
```
