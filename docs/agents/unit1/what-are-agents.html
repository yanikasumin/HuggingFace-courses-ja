エージェントとは何か？

このセクションを終えるころには、エージェントという概念と、その AI におけるさまざまな応用に慣れているはずです。

エージェントとは何かを説明するために、まず例え話から始めましょう。

全体像：エージェント Alfred

Alfred を紹介します。Alfred は エージェント です。

Alfred が 命令を受ける ところを想像してください。たとえば「Alfred、コーヒーをお願い」といった命令です。

Alfred は 自然言語を理解できる ので、私たちの依頼をすぐに把握します。

注文を果たす前に、Alfred は 推論と計画 を行い、必要な手順とツールを考えます。

  1. キッチンへ行く
  2. コーヒーマシンを使う
  3. コーヒーを淹れる
  4. コーヒーを持って戻る

計画ができたら、行動しなければなりません。計画を実行するために、自分が知っているツールの一覧からツールを使うことができます。

この場合、コーヒーを作るためにコーヒーマシンを使います。コーヒーマシンを起動してコーヒーを淹れます。

最後に、Alfred は淹れたてのコーヒーを私たちのところへ持ってきます。

これがエージェントです。推論し、計画し、環境とやり取りできる AI モデル です。

エージェントと呼ばれるのは、agency（主体性）、つまり環境とやり取りする能力を持っているからです。

もう少し形式的に

全体像をつかんだところで、より正確な定義を見てみましょう。

エージェントとは、ユーザーが定義した目的を達成するために、AI モデルを活用して環境とやり取りするシステムです。推論、計画、アクションの実行（多くの場合、外部ツール経由）を組み合わせてタスクを果たします。

エージェントは主に2つの部分から成ると考えてください。

  1. 頭脳（AI モデル）

思考がすべて行われる場所です。AI モデルが 推論と計画を担います。 状況に基づいて どのアクションを取るかを決定します。

  1. 身体（能力とツール）

エージェントが実行できることのすべてを表す部分です。

可能なアクションの範囲 は、エージェントが 何を備えているか に依存します。たとえば、人間には翼がないため「飛ぶ」という アクション は実行できませんが、「歩く」「走る」「跳ぶ」「掴む」といった アクション は実行できます。

「主体性（Agency）」のスペクトラム

この定義に従うと、エージェントは主体性が高まる連続的なスペクトラム上に存在します。

主体性レベル 説明 呼び名 パターンの例
☆☆☆ エージェントの出力がプログラムの流れに影響しない Simple processor process_llm_output(llm_response)
★☆☆ エージェントの出力が基本的な制御フローを決める Router if llm_decision(): path_a() else: path_b()
★★☆ エージェントの出力が関数の実行を決める Tool caller run_function(llm_chosen_tool, llm_chosen_args)
★★★ エージェントの出力が反復とプログラムの継続を制御する Multi-step Agent while llm_should_continue(): execute_next_step()
★★★ あるエージェンティックなワークフローが別のワークフローを開始できる Multi-Agent if llm_trigger(): execute_agent()

smolagents の概念ガイド の表より。

エージェントにはどんな AI モデルを使うのか？

エージェントで最もよく使われる AI モデルは LLM（大規模言語モデル）です。テキスト を入力として受け取り、テキスト を出力します。

よく知られた例として、OpenAI の GPT-4、Meta の Llama、Google の Gemini などがあります。これらのモデルは膨大な量のテキストで訓練されており、高い汎化能力を持ちます。LLM については 次のセクション で詳しく学びます。

💡 ヒント

エージェントの中核モデルとして、他の入力を受け付けるモデルを使うこともできます。たとえば Vision Language Model（VLM）は、LLM のようなものですが、画像も入力として理解できます。今は LLM に集中し、他の選択肢は後で議論します。

AI はどうやって環境に働きかけるのか？

LLM は素晴らしいモデルですが、テキストしか生成できません。

しかし、HuggingChat や ChatGPT のような有名なチャットアプリに画像の生成を頼むと、実際に生成できます。これはどういうことでしょうか？

答えは、HuggingChat や ChatGPT などの開発者が、LLM が画像を作成するために使える追加機能（ツール と呼びます）を実装したからです。

ツールについては ツール のセクションで詳しく学びます。

エージェントはどんなタスクを実行できるのか？

エージェントは、ツール を通じて アクション を完了することで、私たちが実装したあらゆるタスクを実行できます。

たとえば、コンピュータ上でパーソナルアシスタント（Siri のようなもの）として動作するエージェントを書き、「マネージャーにメールを送って、今日の会議を延期してもらえるよう頼んで」と依頼したとします。このとき、メールを送信するコードを渡すことができます。これが、メールを送る必要があるときにエージェントが使える新しいツールになります。Python で書くと次のようになります。

def send_message_to(recipient, message):
    """宛先にメールメッセージを送るために使う"""
    ...

後で見るように、LLM は必要に応じてツールを実行するコードを生成し、望んだタスクを果たします。

send_message_to("Manager", "Can we postpone today's meeting?")

ツールの設計は非常に重要で、エージェントの品質に大きな影響を与えます。タスクによっては非常に特殊なツールを仕立てる必要がありますが、"web_search" のような汎用ツールで解決できるものもあります。

なお、アクションとツールは同じものではありません。たとえば、1つのアクションを完了するために複数のツールを使う場合があります。

エージェントが環境とやり取りできるようにすることで、企業や個人の実生活での利用が可能になります。

例1: パーソナル仮想アシスタント

Siri、Alexa、Google アシスタントのような仮想アシスタントは、ユーザーのデジタル環境を使ってユーザーに代わってやり取りするとき、エージェントとして動作します。

ユーザーのクエリを受け取り、コンテキストを分析し、データベースから情報を取得して、応答を提供したりアクションを開始したりします（リマインダーの設定、メッセージの送信、スマートデバイスの制御など）。

例2: カスタマーサービスチャットボット

多くの企業は、自然言語で顧客とやり取りするエージェントとしてチャットボットを導入しています。

これらのエージェントは、質問に答えたり、トラブルシューティングの手順にユーザーを案内したり、内部データベースに課題を登録したり、取引を完了させたりできます。

あらかじめ定義された目的には、ユーザー満足度の向上、待ち時間の短縮、売上コンバージョン率の向上などが含まれます。顧客と直接やり取りし、対話から学び、応答を時間とともに適応させることで、エージェントの核となる原則を実践しています。

例3: ビデオゲームの AI ノンプレイヤーキャラクター

LLM を活用した AI エージェントは、ノンプレイヤーキャラクター（NPC）をより動的で予測不能なものにできます。

硬直したビヘイビアツリーに従う代わりに、文脈に応じて応答し、プレイヤーとのやり取りに適応し、よりニュアンスのある対話を生成できます。この柔軟性により、プレイヤーの行動とともに進化する、より生き生きとした魅力的なキャラクターを作り出せます。

まとめると、エージェントとは、中核の推論エンジンとして AI モデル（通常は LLM）を使うシステムで、次のことを行います。

  • 自然言語を理解する: 人間の指示を意味のある形で解釈し、応答する。
  • 推論し計画する: 情報を分析し、意思決定を行い、問題を解決する戦略を立てる。
  • 環境とやり取りする: 情報を集め、アクションを取り、そのアクションの結果を観察する。

エージェントとは何かをしっかりつかめたので、短い採点なしクイズで理解を固めましょう。そのあとは、エージェントの「頭脳」である LLM に踏み込みます。
