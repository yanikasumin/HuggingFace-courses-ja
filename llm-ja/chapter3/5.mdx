ここまで、`Trainer` API を使う方法と、カスタム学習ループを自分で書く方法の両方で、ファインチューニングの進め方を学びました。次に必要になるのは、学習の結果を正しく読み取る力です。

学習曲線を使えば、学習中のモデルの性能を確かめられます。性能が落ちる前に、問題の兆候に気づくこともできます。

このセクションでは、損失曲線と正解率曲線の読み方を学びます。併せて、曲線の形からモデルの状態を判断する方法と、学習でよく起こる問題への対処法も学びます。

## 学習曲線とは[[what-are-learning-curves]]

学習曲線とは、学習の進行に伴ってモデルの性能指標がどう変わるかを図で表したものです。特に重要なのは、次の2つです。

- **損失曲線**：学習ステップやエポックの経過と共に、モデルの誤差（損失）がどう変化するかを示します
- **正解率曲線**：学習ステップやエポックの経過と共に、正しく予測出来た割合がどう変化するかを示します

この2つの曲線を見れば、モデルが順調に学習しているかどうかが分かります。性能を上げる為の調整が必要かどうかを判断する材料にもなります。Transformers では、これらの指標はバッチごとに計算され、ログとしてディスクに記録されます。記録したログは、[Weights & Biases](https://wandb.ai/) のようなライブラリで可視化出来ます。可視化すれば、学習中の性能の変化を追いやすくなります。

### 損失曲線[[loss-curves]]

損失曲線は、時間の経過と共にモデルの誤差がどう減っていくかを示します。学習が順調に進んだ場合、典型的には下のような曲線になります。

![損失曲線](https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter3/1.png)

- **初期の損失が高い**：モデルは最適化されていない状態から始まる為、最初のうちは予測がよくありません
- **損失の減少**：学習が進むにつれて、損失は概ね減少していくはずです
- **収束**：やがて損失は低い値で安定し、モデルがデータのパターンを学習したことを示します

前の章までと同様に、`Trainer` API でこれらの指標を記録し、ダッシュボードで確認出来ます。次に、Weights & Biases を使う例を示します。

```python
# Trainer で学習中の損失を追跡する例
from transformers import Trainer, TrainingArguments
import wandb

# 実験追跡のために Weights & Biases を初期化
wandb.init(project="transformer-fine-tuning", name="bert-mrpc-analysis")

training_args = TrainingArguments(
    output_dir="./results",
    eval_strategy="steps",
    eval_steps=50,
    save_steps=100,
    logging_steps=10,  # 10ステップごとに指標をログに記録
    num_train_epochs=3,
    per_device_train_batch_size=16,
    per_device_eval_batch_size=16,
    report_to="wandb",  # ログを Weights & Biases に送信
)

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    data_collator=data_collator,
    processing_class=tokenizer,
    compute_metrics=compute_metrics,
)

# 学習し、指標を自動でログに記録
trainer.train()
```

### 正解率曲線[[accuracy-curves]]

正解率曲線は、時間の経過と共に正しい予測の割合がどう変わるかを示します。損失曲線と違い、正解率は学習が進むにつれて上がっていきます。記録されるステップの数が、損失曲線より多くなることもあります。

![正解率曲線](https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter3/2.png)

- **低く始まる**：学習を始めた時点では、モデルはまだデータのパターンを身につけていない為、正解率は低くなります
- **学習と共に上昇**：モデルがデータのパターンを学習出来る場合は、正解率は学習が進むにつれて概ね向上します
- **横ばいの部分（プラトー）が現れることが有る**：正解率は滑らかには上がりません。階段状に上がることがよくあります。モデルが正解ラベルに近い予測を出すようになっても、予測自体が正解に変わるまでは正解率に反映されない為です

> [!TIP]
> **正解率曲線が「階段状」になる理由**：損失は連続した値ですが、正解率は予測と正解ラベルを比べた結果で決まる離散的な指標です。モデルの確信度が少し上がっただけでは最終的な予測は変わらないことがあります。その為、しきい値を超えるまでは正解率は横ばいのままになります。

### 収束[[convergence]]

収束とは、モデルの性能が安定し、損失曲線と正解率曲線がどちらも横ばいになる状態です。収束は、モデルがデータのパターンを学習し終え、実際に使える状態になったことを示します。言い換えると、学習を行うたびにモデルが安定した性能に落ち着くことが、目指す姿です。

![収束](https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter3/4.png)

モデルが収束したら、そのモデルで新しいデータに対する予測を行えます。性能の良し悪しは、評価指標で確認します。

## 学習曲線のパターンを解釈する[[interpreting-learning-curve-patterns]]

曲線の形が違えば、そこから読み取れる学習の様子も違います。ここでは、よく現れるパターンと、その意味を見ていきます。

### 健全な学習曲線[[healthy-learning-curves]]

順調に進んだ学習では、典型的には下のような曲線になります。

![健全な損失曲線](https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter3/5.png)

上の図には、損失曲線（左）と、それに対応する正解率曲線（右）が描かれています。2つの曲線には、それぞれ異なる特徴があります。

損失曲線は、モデルの損失が時間と共にどう変わるかを示します。損失は、最初は大きく、学習が進むにつれて徐々に小さくなります。これは、モデルの予測が良くなっていることを示します。損失とは、モデルの出力と正解の出力との誤差です。損失が小さくなることは、予測が正解に近づいていることに対応します。

正解率曲線は、モデルの正解率が時間と共にどう変わるかを示します。正解率は、低い値から始まり、学習が進むにつれて上がっていきます。正解率とは、正しく分類出来た事例の割合です。正解率が上がることは、正しい予測の数が増えていることを意味します。

2つの曲線で大きく違うのは、滑らかさです。損失は滑らかに減っていくのに対し、正解率曲線には横ばいの部分（プラトー）が現れます。正解率は連続的には増えず、階段状に上がります。この違いは、指標の測り方から生まれます。損失は、最終的な予測がまだ間違っていても、出力が正解に近づけば小さくなります。一方、正解率は、予測がしきい値を超えて正解に変わった時にしか上がりません。

例えば、猫（0）と犬（1）を区別する二値分類器を考えます。犬の画像（正解は1）に対してモデルが 0.3 と予測すると、0 に丸められる為、不正解です。次のステップで予測が 0.4 になっても、まだ不正解です。但し、0.4 は 0.3 より 1 に近い為、損失は小さくなっています。正解率は変わらない為、プラトーが生まれます。正解率が上がるのは、モデルが 0.5 より大きな値を予測し、それが 1 に丸められる時だけです。

> [!TIP]
> **健全な曲線の特徴：**
> - **損失の滑らかな低下**：学習損失と検証損失の両方が着実に減少する
> - **学習データと検証データでの性能が近い**：両方のデータで計算した評価指標の差が小さい
> - **収束**：曲線が横ばいになり、モデルがパターンを学習したことを示す

### 実践例[[practical-examples]]

ここからは、学習曲線の実例を見ていきます。まず、学習の最中に曲線を確認する観点を紹介します。その後、曲線に現れる代表的なパターンを順に説明します。

#### 学習中[[during-training]]

学習の実行中（`trainer.train()` を呼び出した後）は、次の指標を確認します。

1. **損失の収束**：損失はまだ減少していますか、それとも横ばいですか？
2. **過学習の兆候**：学習損失が減少する一方で、検証損失が増え始めていませんか？
3. **学習率**：曲線が激しく変動していませんか（学習率が高過ぎる可能性）？ あるいは、殆ど変化していませんか（学習率が低過ぎる可能性）？
4. **安定性**：問題を示す急なスパイクや落ち込みはありませんか？

#### 学習後[[after-training]]

学習が完了したら、曲線全体を分析してモデルの性能を把握します。

1. **最終性能**：モデルは許容出来る性能レベルに到達しましたか？
2. **効率**：より少ないエポックでも同じ性能を達成出来たでしょうか？
3. **汎化**：学習性能と検証性能はどの程度近いですか？
4. **傾向**：追加の学習で性能が改善しそうですか？

> [!TIP]
> **W&B ダッシュボードの機能**：Weights & Biases は、見やすく、操作も出来る学習曲線のグラフを自動で作成します。次のことが出来ます。
> - 複数の実行を並べて比較する
> - カスタム指標と可視化を追加する  
> - 異常な振る舞いに対するアラートを設定する
> - 結果をチームと共有する
>
> 詳しくは [Weights & Biases のドキュメント](https://docs.wandb.ai/) を参照してください。

#### 過学習[[overfitting]]

過学習とは、モデルが学習データに合わせ過ぎてしまい、学習に使っていないデータ（検証セットがその代表です）にうまく対応出来なくなる状態です。

![過学習](https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter3/10.png)

**症状：**

- 学習損失が減少し続ける一方で、検証損失が増加するか横ばいになる
- 学習正解率と検証正解率の差が大きい
- 学習正解率が検証正解率よりはるかに高い

**過学習への対処法：**

- **正則化**：ドロップアウト、重み減衰、その他の正則化手法を追加する
- **早期終了**：検証性能の改善が止まったら学習を止める
- **データ拡張**：学習データの多様性を増やす
- **モデルの複雑さを下げる**：より小さいモデルを使うか、パラメータ数を減らす

次の例では、過学習を防ぐ為に早期終了を使います。`early_stopping_patience` を 3 に設定すると、検証損失が3エポック続けて改善しない場合に、学習が止まります。

```python
# 早期終了で過学習を検出する例
from transformers import EarlyStoppingCallback

training_args = TrainingArguments(
    output_dir="./results",
    eval_strategy="steps",
    eval_steps=100,
    save_strategy="steps",
    save_steps=100,
    load_best_model_at_end=True,
    metric_for_best_model="eval_loss",
    greater_is_better=False,
    num_train_epochs=10,  # 大きく設定するが、早期に停止する
)

# 過学習を防ぐために早期終了を追加
trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    data_collator=data_collator,
    processing_class=tokenizer,
    compute_metrics=compute_metrics,
    callbacks=[EarlyStoppingCallback(early_stopping_patience=3)],
)
```

#### 2. 過小適合[[underfitting]]

過小適合は、モデルが単純過ぎて、データに含まれるパターンを捉えられない時に起こります。これにはいくつかの原因があります。

- モデルが小さ過ぎるか、パターンを学習する能力が不足している
- 学習率が低過ぎて、学習が遅い
- データセットが小さ過ぎるか、解こうとしている問題の特徴を十分に反映していない
- モデルが適切に正則化されていない

![過小適合](https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter3/7.png)

**症状：**

- 学習損失と検証損失の両方が高いまま
- モデルの性能が学習の早い段階で横ばいになる
- 学習正解率が期待より低い

**過小適合への対処法：**

- **モデルの表現能力を高める**：より大きいモデルを使うか、パラメータ数を増やす
- **長く学習する**：エポック数を増やす
- **学習率を調整する**：異なる学習率を試す
- **データ品質を確認する**：データが適切に前処理されているか確認する

下のサンプルでは、モデルがデータのパターンを学習出来るか確認する為に、より多くのエポックで学習します。

```python
from transformers import TrainingArguments

training_args = TrainingArguments(
    output_dir="./results",
    -num_train_epochs=5,
    +num_train_epochs=10,
)
```

#### 3. 乱れた学習曲線[[erratic-learning-curves]]

乱れた学習曲線は、モデルが効果的に学習出来ていない時に現れます。これにはいくつかの原因があります。

- 学習率が高過ぎて、パラメータを更新する時に最適値を飛び越えてしまう
- バッチサイズが小さ過ぎて、モデルの学習が遅い
- モデルが適切に正則化されておらず、学習データに過学習してしまう
- データセットが適切に前処理されておらず、モデルがノイズを学習してしまう

![乱れた学習曲線](https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter3/3.png)

**症状：**

- 損失や正解率の頻繁な変動
- 曲線のばらつきが大きいか、不規則に変動する
- 性能が一定の傾向を示さず、上下を繰り返す

学習データと検証データの両方の曲線に、不安定な変動が見られます。

![乱れた学習曲線](https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter3/9.png)

**乱れた曲線への対処法：**

- **学習率を下げる**：ステップサイズを小さくして学習を安定させる
- **バッチサイズを増やす**：より大きなバッチを使って勾配のばらつきを抑える
- **勾配クリッピング**：勾配爆発を防ぐ
- **データ前処理の改善**：一貫したデータ品質を確保する

下のサンプルでは、学習率を下げ、バッチサイズを増やします。

```python
from transformers import TrainingArguments

training_args = TrainingArguments(
    output_dir="./results",
    -learning_rate=1e-5,
    +learning_rate=1e-4,
    -per_device_train_batch_size=16,
    +per_device_train_batch_size=32,
)
```

## 要点[[key-takeaways]]

学習曲線を理解することは、機械学習を実践する上で欠かせません。学習曲線は、モデルの学習がどこまで進んだかを直ぐに教えてくれます。その情報は、学習をいつ止めるか、ハイパーパラメータをどう調整するか、別の方法を試すかといった判断の材料になります。経験を積むうちに、順調な学習曲線の形が直感的に分かるようになり、問題が起きた時の対処法も身についていきます。

> [!TIP]
> **要点：**
> - 学習曲線は、モデルの学習進捗を理解する為の不可欠なツールです
> - 損失曲線と正解率曲線の両方を監視してください。但し、両者には異なる特徴があることを忘れないでください
> - 過学習は、学習性能と検証性能が乖離していく形で現れます
> - 過小適合では、学習データと検証データの両方で性能が低くなります
> - Weights & Biases のようなツールを使えば、学習曲線の追跡と分析が簡単になります
> - 早期終了と適切な正則化で、よくある学習の問題の殆どに対処出来ます
>
> **次のステップ**：自分でファインチューニングを行い、学習曲線を分析してみましょう。異なるハイパーパラメータを試し、曲線の形がどう変わるか観察してください。こうした実践を重ねることが、学習の進み具合を直感的に読み取る力を身につける最良の方法です。
