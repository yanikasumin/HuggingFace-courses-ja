`Trainer` API とカスタム学習ループの両方でファインチューニングを実装する方法を学んだところで、次は結果の解釈が重要になります。学習曲線は、学習中のモデルの性能を評価し、潜在的な問題が性能を低下させる前に見つけるための、非常に有用なツールです。

## 学習曲線とは[[what-are-learning-curves]]

学習曲線は、学習中のモデルの性能指標を時間の経過とともに可視化したものです。監視すべき最も重要な曲線は次の2つです。

- **損失曲線**: 学習ステップやエポックごとに、モデルの誤差（損失）がどう変化するかを示します
- **正解率曲線**: 学習ステップやエポックごとの、正しい予測の割合を示します

これらの曲線は、モデルが効果的に学習しているかどうかを理解する助けになり、性能を改善するための調整の指針にもなります。Transformers では、これらの指標はバッチごとに計算され、ディスクにログとして記録されます。その後、[Weights & Biases](https://wandb.ai/) のようなライブラリを使って曲線を可視化し、時間の経過に伴うモデルの性能を追跡できます。

### 損失曲線[[loss-curves]]

損失曲線は、モデルの誤差が時間とともにどう減少するかを示します。学習がうまくいった場合の典型的な例では、下のような曲線が見られます。

![損失曲線](https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter3/1.png)

- **初期の損失が高い**: モデルは最適化されていない状態から始まるため、最初のうちは予測がよくありません
- **損失の減少**: 学習が進むにつれて、損失は概ね減少していくはずです
- **収束**: やがて損失は低い値で安定し、モデルがデータのパターンを学習したことを示します

前の章と同様に、`Trainer` API を使ってこれらの指標を追跡し、ダッシュボードで可視化できます。以下は Weights & Biases でそれを行う例です。

```python
# Trainer で学習中の損失を追跡する例
from transformers import Trainer, TrainingArguments
import wandb

# 実験追跡のために Weights & Biases を初期化
wandb.init(project="transformer-fine-tuning", name="bert-mrpc-analysis")

training_args = TrainingArguments(
    output_dir="./results",
    eval_strategy="steps",
    eval_steps=50,
    save_steps=100,
    logging_steps=10,  # 10ステップごとに指標をログに記録
    num_train_epochs=3,
    per_device_train_batch_size=16,
    per_device_eval_batch_size=16,
    report_to="wandb",  # ログを Weights & Biases に送信
)

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    data_collator=data_collator,
    processing_class=tokenizer,
    compute_metrics=compute_metrics,
)

# 学習し、指標を自動でログに記録
trainer.train()
```

### 正解率曲線[[accuracy-curves]]

正解率曲線は、時間の経過に伴う正しい予測の割合を示します。損失曲線とは異なり、正解率曲線はモデルが学習するにつれて概ね上昇し、通常は損失曲線よりも多くのステップを含みます。

![正解率曲線](https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter3/2.png)

- **低く始まる**: モデルはまだデータのパターンを学習していないため、初期の正解率は低いはずです
- **学習とともに上昇**: モデルがデータのパターンを学習できるなら、正解率は学習が進むにつれて概ね向上するはずです
- **プラトーが現れることがある**: 正解率は滑らかではなく、段階的に上昇することがよくあります。モデルの予測が真のラベルに近づいていく過程で起こります

> [!TIP]
> 💡 **正解率曲線が「階段状」になる理由**: 連続的な損失とは異なり、正解率は離散的な予測と真のラベルを比較して計算されます。モデルの確信度の小さな改善では最終的な予測が変わらないことがあり、しきい値を超えるまで正解率は横ばいのままになります。

### 収束[[convergence]]

収束とは、モデルの性能が安定し、損失曲線と正解率曲線が横ばいになることです。これは、モデルがデータのパターンを学習し、使用できる状態になった兆候です。簡単に言えば、学習のたびにモデルが安定した性能に収束することが目標です。

![収束](https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter3/4.png)

モデルが収束したら、新しいデータで予測を行い、評価指標を参照してモデルの性能がどの程度か把握できます。

## 学習曲線のパターンを解釈する[[interpreting-learning-curve-patterns]]

曲線の形の違いからは、モデルの学習におけるさまざまな側面がわかります。最も一般的なパターンとその意味を見ていきましょう。

### 健全な学習曲線[[healthy-learning-curves]]

うまくいった学習では、通常、下のような形の曲線が見られます。

![健全な損失曲線](https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter3/5.png)

上の図を見てみましょう。損失曲線（左）とそれに対応する正解率曲線（右）の両方が描かれています。これらの曲線にはそれぞれ異なる特徴があります。

損失曲線は、時間の経過に伴うモデルの損失の値を示します。最初は損失が高く、その後徐々に減少していきます。これはモデルが改善していることを示します。損失は予測出力と真の出力の間の誤差を表すため、損失の値の減少は、モデルがよりよい予測を行っていることを示唆します。

次に正解率曲線に目を向けましょう。これは時間の経過に伴うモデルの正解率を表します。正解率曲線は低い値から始まり、学習が進むにつれて上昇します。正解率は、正しく分類された事例の割合を測るものです。したがって、正解率曲線の上昇は、モデルがより多くの正しい予測を行っていることを意味します。

曲線同士の顕著な違いの1つは、滑らかさと、正解率曲線に現れる「プラトー」の存在です。損失は滑らかに減少しますが、正解率曲線のプラトーは、正解率が連続的に増えるのではなく離散的にジャンプすることを示しています。この振る舞いは、正解率の測り方によるものです。損失は、最終的な予測がまだ間違っていても、モデルの出力がターゲットに近づけば改善します。一方、正解率は、予測が正解となるしきい値を超えたときにのみ改善します。

たとえば、猫（0）と犬（1）を区別する二値分類器で、モデルが犬の画像（真の値は1）に対して 0.3 と予測した場合、これは 0 に丸められ、不正解の分類となります。次のステップで 0.4 と予測しても、まだ不正解です。0.4 は 0.3 よりも 1 に近いため損失は減少していますが、正解率は変わらず、プラトーが生まれます。正解率がジャンプするのは、モデルが 0.5 より大きな値を予測し、それが 1 に丸められるときだけです。

> [!TIP]
> **健全な曲線の特徴:**
> - **損失の滑らかな低下**: 学習損失と検証損失の両方が着実に減少する
> - **学習性能と検証性能が近い**: 学習指標と検証指標の差が小さい
> - **収束**: 曲線が横ばいになり、モデルがパターンを学習したことを示す

### 実践例[[practical-examples]]

学習曲線の実践例をいくつか見ていきましょう。まず、学習中に学習曲線を監視するアプローチを紹介します。その後、学習曲線に現れるさまざまなパターンを詳しく見ていきます。

#### 学習中[[during-training]]

学習プロセスの間（`trainer.train()` を実行している間）は、次の主要な指標を監視できます。

1. **損失の収束**: 損失はまだ減少していますか、それとも横ばいですか？
2. **過学習の兆候**: 学習損失が減少する一方で、検証損失が増え始めていませんか？
3. **学習率**: 曲線が乱れすぎていませんか（学習率が高すぎ）、あるいはほとんど変化していませんか（学習率が低すぎ）？
4. **安定性**: 問題を示す急なスパイクや落ち込みはありませんか？

#### 学習後[[after-training]]

学習プロセスが完了したら、曲線全体を分析してモデルの性能を把握できます。

1. **最終性能**: モデルは許容できる性能レベルに到達しましたか？
2. **効率**: より少ないエポックでも同じ性能を達成できたでしょうか？
3. **汎化**: 学習性能と検証性能はどの程度近いですか？
4. **傾向**: 追加の学習で性能が改善しそうですか？

> [!TIP]
> 🔍 **W&B ダッシュボードの機能**: Weights & Biases は、学習曲線の美しくインタラクティブなプロットを自動で作成します。次のことができます。
> - 複数の実行を並べて比較する
> - カスタム指標と可視化を追加する  
> - 異常な振る舞いに対するアラートを設定する
> - 結果をチームと共有する
>
> 詳しくは [Weights & Biases のドキュメント](https://docs.wandb.ai/) を参照してください。

#### 過学習[[overfitting]]

過学習は、モデルが学習データに過度に適合して、異なるデータ（検証セットに代表されます）に汎化できなくなったときに起こります。

![過学習](https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter3/10.png)

**症状:**

- 学習損失が減少し続ける一方で、検証損失が増加するか横ばいになる
- 学習正解率と検証正解率の差が大きい
- 学習正解率が検証正解率よりはるかに高い

**過学習への対処法:**
- **正則化**: ドロップアウト、重み減衰、その他の正則化テクニックを追加する
- **早期終了**: 検証性能の改善が止まったら学習を止める
- **データ拡張**: 学習データの多様性を増やす
- **モデルの複雑さを下げる**: より小さいモデルを使うか、パラメータ数を減らす

下のサンプルでは、過学習を防ぐために早期終了を使います。`early_stopping_patience` を 3 に設定しています。これは、検証損失が3エポック連続で改善しなければ、学習が停止されるという意味です。

```python
# 早期終了で過学習を検出する例
from transformers import EarlyStoppingCallback

training_args = TrainingArguments(
    output_dir="./results",
    eval_strategy="steps",
    eval_steps=100,
    save_strategy="steps",
    save_steps=100,
    load_best_model_at_end=True,
    metric_for_best_model="eval_loss",
    greater_is_better=False,
    num_train_epochs=10,  # 大きく設定するが、早期に停止する
)

# 過学習を防ぐために早期終了を追加
trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    data_collator=data_collator,
    processing_class=tokenizer,
    compute_metrics=compute_metrics,
    callbacks=[EarlyStoppingCallback(early_stopping_patience=3)],
)
```

#### 2. 過小適合[[underfitting]]

過小適合は、モデルが単純すぎてデータの根底にあるパターンを捉えられないときに起こります。これにはいくつかの原因があります。

- モデルが小さすぎるか、パターンを学習する能力が不足している
- 学習率が低すぎて、学習が遅い
- データセットが小さすぎるか、問題を代表していない
- モデルが適切に正則化されていない

![過小適合](https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter3/7.png)

**症状:**
- 学習損失と検証損失の両方が高いまま
- モデルの性能が学習の早い段階で横ばいになる
- 学習正解率が期待より低い

**過小適合への対処法:**
- **モデルの表現能力を高める**: より大きいモデルを使うか、パラメータ数を増やす
- **長く学習する**: エポック数を増やす
- **学習率を調整する**: 異なる学習率を試す
- **データ品質を確認する**: データが適切に前処理されているか確認する

下のサンプルでは、モデルがデータのパターンを学習できるか確認するために、より多くのエポックで学習します。

```python
from transformers import TrainingArguments

training_args = TrainingArguments(
    output_dir="./results",
    -num_train_epochs=5,
    +num_train_epochs=10,
)
```

#### 3. 乱れた学習曲線[[erratic-learning-curves]]

乱れた学習曲線は、モデルが効果的に学習できていないときに現れます。これにはいくつかの原因があります。

- 学習率が高すぎて、モデルが最適なパラメータを通り過ぎてしまう
- バッチサイズが小さすぎて、モデルの学習が遅い
- モデルが適切に正則化されておらず、学習データに過学習してしまう
- データセットが適切に前処理されておらず、モデルがノイズを学習してしまう

![乱れた学習曲線](https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter3/3.png)

**症状:**
- 損失や正解率の頻繁な変動
- 曲線のばらつきが大きい、または不安定
- 明確な傾向なく性能が振動する

学習と検証の両方の曲線に、乱れた振る舞いが見られます。

![乱れた学習曲線](https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter3/9.png)

**乱れた曲線への対処法:**
- **学習率を下げる**: ステップサイズを小さくして学習を安定させる
- **バッチサイズを増やす**: 大きなバッチはより安定した勾配をもたらします
- **勾配クリッピング**: 勾配爆発を防ぐ
- **データ前処理の改善**: 一貫したデータ品質を確保する

下のサンプルでは、学習率を下げ、バッチサイズを増やします。

```python
from transformers import TrainingArguments

training_args = TrainingArguments(
    output_dir="./results",
    -learning_rate=1e-5,
    +learning_rate=1e-4,
    -per_device_train_batch_size=16,
    +per_device_train_batch_size=32,
)
```

## 要点[[key-takeaways]]

学習曲線を理解することは、機械学習を効果的に実践できるようになるうえで欠かせません。これらの視覚的なツールは、モデルの学習進捗について即座のフィードバックを与え、いつ学習を止めるべきか、ハイパーパラメータをどう調整すべきか、別のアプローチを試すべきかといった判断の助けになります。練習を重ねれば、健全な学習曲線がどのようなものか、問題が起きたときにどう対処すべきかについて、直感的な理解が身につきます。

> [!TIP]
> 💡 **要点:**
> - 学習曲線は、モデルの学習進捗を理解するための不可欠なツールです
> - 損失曲線と正解率曲線の両方を監視してください。ただし、両者には異なる特徴があることを忘れないでください
> - 過学習は、学習性能と検証性能が乖離していく形で現れます
> - 過小適合は、学習データと検証データの両方で性能が悪い形で現れます
> - Weights & Biases のようなツールを使えば、学習曲線の追跡と分析が簡単になります
> - 早期終了と適切な正則化で、よくある学習の問題のほとんどに対処できます
>
> 🔬 **次のステップ**: 自分のファインチューニング実験で学習曲線を分析する練習をしてください。異なるハイパーパラメータを試し、曲線の形にどう影響するか観察しましょう。この実践経験が、学習進捗を読み取る直感を養う最良の方法です。
