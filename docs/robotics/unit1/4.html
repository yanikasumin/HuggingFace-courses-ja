コード例: データセットを実際に扱う

このセクションでは、LeRobotDataset クラスを使い、Hugging Face のロボティクスデータセットを扱う方法を紹介します。簡単な例から始め、徐々に複雑な例へと進みます。自分のプロジェクトに合った方法を選び、コードをコピーして応用してください。

ここで重要なのは、表形式データ、視覚データ、メタデータを含む LeRobot 形式に準拠したデータセットなら、Hugging Face Hub 上にあるものをどれでも、わずか1行のコードで読み込めるということです。

ロボティクスデータを扱う際には、ある時点のデータだけでなく、複数の時点のデータをまとめて参照することがよくあります。なぜなら、多くのロボット学習アルゴリズムでは、時間の経過に伴う状態の変化を捉える必要があるからです。例えば、物体をつかむ際には、直前の数時点で何が起きたかを確認することで、現在の状況をより正確に把握できます。また、多くのアルゴリズムは、その瞬間の行動だけを決めるよりも、先の数ステップまで行動を計画できるほうがうまく機能します。

LeRobotDataset では「時間窓（temporal windowing）」という仕組みにより、複数時点のデータを簡単に取得できます。必要な時間オフセット（例: 現在のフレームとその前の2フレーム）を指定するだけで、対応するフレームを自動的に取得できます。エピソードの開始時や終了時に一部のフレームが存在しない場合も、自動的に処理されます。

💡 ヒント

時間窓の説明: - 観測の履歴: [-0.2, -0.1, 0.0] で、200ms 前、100ms 前、現在の観測が得られます - 行動シーケンス: [0.0, 0.1, 0.2] で、現在の行動と次の2つの行動（100ms 間隔）が得られます - 自動パディング: エピソードの境界で欠けたフレームは自動的に処理されます。データセットは常に、要求した数のフレームを返し、必要なところではパディングを適用します - マスク情報: どのフレームが実際のデータで、どれがパディングなのかを判別できるため、適切に訓練できます

LeRobotDataset は PyTorch の DataLoader と組み合わせて利用でき、各サンプルを表す辞書を、訓練や推論に使えるバッチ化されたテンソルの辞書へ自動的にまとめる（collate）ことができます。また、データセットのストリーミングにも標準で対応しています。実装を1行変更するだけで、Hugging Face Hub 上の大規模なデータセットをストリーミングで利用できます。ストリーミングデータセットは、高速なバッチ処理（接続状況によりおよそ 80-100 it/s）と、フレームの十分なランダム化をサポートしています。これらは実用的な BC アルゴリズムにとって重要です。こうした機能がなければ、処理が遅くなったり、データの時間的な偏りが強く、独立同一分布（i.i.d.）の仮定から大きく外れた状態で学習することになったりします。この仕組みは、大量のメモリやストレージを用意しなくても大規模なデータセットを扱えるようにし、より多くの人が利用できる環境を提供するものです。

用途に応じた時間窓の設定例をいくつか紹介します。まずは全体をざっと確認し、1つ選んで試してみてください。後から別の設定に切り替える場合も、設定用の辞書を書き換えるだけで済みます。

basic-bc

**基本的な行動クローニング**（現在の観測から現在の行動を学ぶ）: 
# シンプル: 現在の観測 → 現在の行動
delta_timestamps = {
    "observation.images.up": [0.0],  # 現在のフレームのみ
    "action": [0.0]  # 現在の行動のみ
}

dataset = LeRobotDataset(
    "lerobot/svla_so101_pickplace", 
    delta_timestamps=delta_timestamps
)

history-bc

**履歴ベースの BC**（より良い判断のために観測の履歴を使う）: 
# コンテキストとして観測の履歴を使う
delta_timestamps = {
    "observation.images.up": [-0.2, -0.1, 0.0],  # 200ms 分の履歴
    "action": [0.0]  # 現在の行動
}

dataset = LeRobotDataset(
    "lerobot/svla_so101_pickplace",
    delta_timestamps=delta_timestamps
)

sample = dataset[100]
# 画像の shape: [3, C, H, W] - 3つの過去フレーム
# 行動の shape: [action_dim] - 単一の現在の行動

action-chunking

**アクションチャンキング**（より滑らかな制御のために行動シーケンスを予測する）: 
# 複数の未来の行動を一度に予測する
delta_timestamps = {
    "observation.images.up": [-0.1, 0.0],  # 直前 + 現在
    "action": [0.0, 0.1, 0.2, 0.3]  # 現在 + 3つの未来の行動
}

dataset = LeRobotDataset(
    "lerobot/svla_so101_pickplace",
    delta_timestamps=delta_timestamps
)

sample = dataset[100] 
# 画像の shape: [2, C, H, W] - 2つの観測フレーム
# 行動の shape: [4, action_dim] - 4つの行動予測

大規模データセットのストリーミング

💡 ヒント

ストリーミングを使う場面: - データセットの容量がストレージ容量を超える場合 - ディスクに収まらないデータセットをストリーミングする - 実験 - ダウンロードせずに、さまざまなデータセットを手早く試す - クラウドでの訓練 - Hugging Face Hub からストリーミングして起動時間を短縮する - 安定したネット接続がある場合 - 訓練中は安定したインターネット接続が必要

性能: ネットワーク接続が良好な場合、ストリーミングでも 80-100 it/s の処理速度を実現できます！ 初期化にかかる時間を除けば、平均的な処理性能はローカルに保存したデータセットと同程度です。

download

**データセットのダウンロード**（訓練が高速、ストレージが必要）: 
from lerobot.datasets.lerobot_dataset import LeRobotDataset

# データセットをローカルキャッシュにダウンロードする
dataset = LeRobotDataset("lerobot/svla_so101_pickplace")

# ダウンロード後は最も高速にアクセスできる
sample = dataset[100]

streaming

**データセットのストリーミング**（ストレージ不要、インターネットが必要）: 
from lerobot.datasets.streaming_dataset import StreamingLeRobotDataset

# ダウンロードせずにデータをストリーミングする
streaming_dataset = StreamingLeRobotDataset(
    "lerobot/svla_so101_pickplace",
    delta_timestamps=delta_timestamps
)

# 通常のデータセットとまったく同じように動作する
sample = streaming_dataset[100]

訓練への統合

通常のデータセットもストリーミングデータセットも、PyTorch のデータローダーと簡単に組み合わせられます。そのため、どの LeRobotDataset でも、自分で作成した torch の訓練ループに容易に組み込めます。データセットから各フレームをテンソルとして取得できるので、データローダーからバッチを取り出してモデルを訓練する処理も簡単に実装できます。

PyTorch DataLoader

通常のデータセットもストリーミングデータセットも、PyTorch のデータローダーと簡単に組み合わせられます。そのため、どの LeRobotDataset でも、自分で作成した torch の訓練ループに容易に組み込めます。データセットから各フレームをテンソルとして取得できるので、データローダーからバッチを取り出してモデルを訓練する処理も簡単に実装できます。

import torch
from torch.utils.data import DataLoader
# 訓練用の DataLoader を作成する
dataloader = DataLoader(
    dataset,
    batch_size=16,
    shuffle=True,
    num_workers=4
)

# 訓練ループ
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

for batch in dataloader:
    # デバイスへ移動する
    observations = batch["observation.state"].to(device)
    actions = batch["action"].to(device)
    images = batch["observation.images.up"].to(device)

    # ここにモデルの訓練を書く
    # loss = model(observations, images, actions)
    # loss.backward()
    # optimizer.step()

これが重要な理由

このシンプルな API の裏側では、多くの複雑な処理が行われています。 - ✅ マルチモーダルの同期 - 画像データとセンサーデータのタイミングが正確に同期している - ✅ 効率的な保存 - 圧縮された動画、メモリマップされた配列 - ✅ 時系列データの処理 - 観測／行動シーケンスへの簡単なアクセス
- ✅ スケーラビリティ - 小規模なデータセットでも大規模なデータセットでも、同じコードが動作する

これに対して、従来のロボティクスのデータ処理では、たいてい次のものが必要でした。 - 各データ形式のためのカスタムパーサー - モダリティ間での手作業の同期 - 時間窓のための複雑なバッファリング - プラットフォーム固有の読み込みコード

LeRobotDataset は、これらすべてを標準化し、単純化します！

セクションクイズ

LeRobot と、そのロボット学習における役割について、理解度を確認してみましょう。

1. LeRobot が従来のロボティクスライブラリと違う点は何ですか？

LeRobot は主に実機のロボットを対象としており、さまざまなロボットプラットフォームに対応しています。
LeRobot の重要な革新は、ハードウェア制御、データ処理、学習アルゴリズムを1つの統一ライブラリに組み合わせたことです。
LeRobot は、ロボティクスをより多くの人が利用できるようにするため、安価で導入しやすいロボットを重視しています。
LeRobot は、古典的な制御ではなく、学習ベースのアプローチに特化しています。

2. 次のうち、LeRobot のアプローチの重要な構成要素ではないものはどれですか？

これは、異なるロボットプラットフォーム間での互換性を確保するための重要な機能です。
LeRobotDataset はこのライブラリの中心的な革新です。
むしろ LeRobot は、ロボットごとに高度な専門知識が必要となる状況を改善し、導入のハードルを下げることを目指しています。
最先端（SOTA）のアルゴリズムは LeRobot の中核機能です。

3. LeRobot の最適化された推論スタックの主な利点は何ですか？

推論スタックはデプロイに関するものであり、訓練速度ではありません。
メモリの削減はデータセット形式が担うものであり、推論スタックではありません。
この分離は、ミリ秒単位の遅れが問題になるリアルタイムのロボット制御にとって非常に重要です。
データ生成は推論スタックでは扱いません。

4. LeRobot は、どのような種類のロボットプラットフォームに対応していますか？

LeRobot は、ロボットアームなどのマニピュレーション用ロボットだけでなく、さまざまな種類のロボットに対応しています。
LeRobot は、シンプルなロボットアームから複雑なヒューマノイドまで、幅広い種類のロボットに対応しています。
LeRobot は、ロボティクスをより多くの人が利用できるようにするため、安価で導入しやすいロボットプラットフォームを重視しています。
LeRobot は、さまざまな開発元が提供する、オープンソースで導入しやすいロボットに対応しています。

5. LeRobot の文脈で「ロボティクススタックとのエンドツーエンド統合」とは何を意味しますか？

エンドツーエンドとは、低レベルの制御から高レベルのアルゴリズムまで、すべてをカバーすることを意味します。
必要な機能を幅広く備えているため、別々のツールを複数組み合わせる必要がなくなります。
エンドツーエンド統合では、必要な機能が1つのライブラリにまとめられるため、複数のツールを別々に組み合わせる必要がありません。
プラットフォーム統合とは、オペレーティングシステムではなく、ロボティクスの構成要素を指します。

6. LeRobotDataset の delta_timestamps パラメータの主な目的は何ですか？

フレームレートはメタデータに保存されるものであり、delta_timestamps で制御するものではありません。
delta_timestamps を使うと、含める時間オフセットを指定でき、過去の観測や未来の行動にアクセスできるようになります。
ロボット間の同期は delta_timestamps では扱いません。
動画の圧縮は delta_timestamps とは関係なく、データセットの保存形式に応じて別途行われます。

7. LeRobotDataset の3つの主要な構成要素を最もよく表しているのはどれですか？

これらは重要なデータ型ではありますが、構造的な構成要素を表してはいません。
これらがデータセットの保存構造を構成する3つの要素です。センサーデータを効率よく保存する表形式データ、圧縮された動画データ、JSON 形式のメタデータに分かれます。
これらはデータの分割であり、形式の構造的な構成要素ではありません。
これらはデータの出どころを表すものであり、保存のアーキテクチャではありません。

8. LeRobotDataset の代わりに StreamingLeRobotDataset を使うとどうなりますか？

ストリーミングにデータ拡張は含まれません。それは別の前処理ステップです。
ストリーミングでは、データセット全体を事前にダウンロードする必要がありません。
StreamingLeRobotDataset を使うと、大規模なデータセットをローカルにダウンロードせずに処理できます。
データの分割は、ストリーミングかダウンロードかの選択とは独立しています。

9. ロボット学習の文脈で、「temporal windowing（時間窓）」とは何を指しますか？

モデルの訓練にかかる時間は、ここでいう時間窓とは関係ありません。
時間窓により、アルゴリズムは観測の履歴と行動シーケンスを使えるようになります。これはロボット学習にとって非常に重要です。
センサーがデータを収集する頻度は、データセットの時間窓とは別の概念です。
エピソードの長さは、エピソード内での時間窓とは異なります。

10. LeRobotDataset の動画データの保存方法の主な利点は何ですか？

ここで重視しているのは最高画質ではなく、保存効率と大規模データへの対応です。
これは実際には非効率です。LeRobotDataset はその逆を行います。
この方法によりファイルの数が大幅に減り、大規模なデータセットでも保存が効率的になります。
AI ベースの圧縮ではなく、標準的な動画圧縮が使われます。

11. LeRobotDataset の互換性について、正しい記述はどれですか？

LeRobotDataset は、多くの異なるロボットプラットフォームで動作するよう設計されています。
統一された形式により、プラットフォームごとのカスタムコードの必要性が減ります。
この連携により、既存の ML ワークフローでロボティクスデータを簡単に使えるようになります。
LeRobotDataset は、シミュレーションと実ロボットの両方のデータに対応しています。
