これまでは主に、事前学習済みモデルを使い、事前学習の重みを再利用して新しい用途向けにファインチューニングしてきました。Chapter 1 で見たように、これは一般に 転移学習 と呼ばれ、ラベル付きデータが少ない現実の用途のほとんどで Transformer モデルを活用するうえで非常に有効な戦略です。この章では別のアプローチを取り、新しいモデルを完全にゼロから学習します。データが大量にあり、利用可能なモデルの事前学習データとは大きく異なる場合には、この方法が適しています。ただし、言語モデルの事前学習には、既存モデルのファインチューニングと比べてかなり多くの計算リソースが必要です。新しいモデルの学習が意味を持つ例としては、楽譜のデータ、DNA のような分子配列、プログラミング言語のデータセットなどがあります。プログラミング言語は近年、OpenAI の Codex モデルを基盤とする TabNine や GitHub の Copilot のような、長いコード列を生成できるツールによって注目を集めています。このテキスト生成のタスクに最も適しているのは、GPT-2 のような自己回帰型の言語モデル、つまり因果言語モデルです。

このセクションでは、コード生成モデルの縮小版を作ります。完全な関数やクラスではなく、1行の補完に焦点を当て、Python コードの一部を使います。Python でデータを扱う作業では、matplotlib、seaborn、pandas、scikit-learn といったライブラリからなる Python のデータサイエンススタックに頻繁に触れます。これらのフレームワークを使うときは特定のコマンドを調べる必要がよくあるので、モデルにこれらの呼び出しを補完してもらえると便利です。

Chapter 6 では、Python のソースコードを処理するための効率的なトークナイザを作りました。しかし、モデルの事前学習に使う大規模なデータセットはまだ用意できていません。ここでは、GitHub のリポジトリから集めた Python コードのコーパスにこのトークナイザを適用します。その後、Trainer API と 🤗 Accelerate を使ってモデルを学習します。さっそく始めましょう！

これは、このセクションで示すコードを使って実際に学習し、Hub にアップロードしたモデルを紹介するものです。こちら で確認できます。テキスト生成にはランダム性があるため、得られる結果は少し異なるはずです。

データを集める

Python のコードは、GitHub のようなコードリポジトリに大量に存在します。すべての Python リポジトリをスクレイピングすれば、データセットを作ることができます。これは、大規模な GPT-2 モデルを事前学習するために Transformers の教科書 で採用されたアプローチです。著者らは、約2,000万件の Python ファイルを含む約180 GB の GitHub ダンプ codeparrot からデータセットを構築し、Hugging Face Hub で共有しました。

ただし、コーパス全体で学習すると時間と計算リソースを大量に消費します。また、必要なのは Python のデータサイエンススタックに関係するデータセットの部分だけです。そこで、まず codeparrot データセットを、このスタックのライブラリのいずれかを含むファイルだけに絞り込みます。データセットが大きいため、ダウンロードは避けたいところです。代わりに、ストリーミング機能を使ってその場で絞り込みます。先ほど挙げたライブラリを使っているコードサンプルを絞り込むために、次の関数を使います。

def any_keyword_in_string(string, keywords):
    for keyword in keywords:
        if keyword in string:
            return True
    return False

これを使って、データセットをストリーミングしながら目的の要素を絞り込む関数を作れます。

```py
from collections import defaultdict
from tqdm import tqdm
from datasets import Dataset


def filter_streaming_dataset(dataset, filters):
    filtered_dict = defaultdict(list)
    total = 0
    for sample in tqdm(iter(dataset)):
        total += 1
        if any_keyword_in_string(sample["content"], filters):
            for k, v in sample.items():
                filtered_dict[k].append(v)
    print(f"フィルタリング後のデータの割合: {len(filtered_dict['content'])/total:.2%}")
    return Dataset.from_dict(filtered_dict)

## データセットを準備する








最初のステップは、データをトークン化して学習に使えるようにすることです。主な目的は短い関数呼び出しの自動補完なので、コンテキストサイズは比較的小さくできます。そうすると、モデルをはるかに速く学習でき、必要なメモリも大幅に少なくて済みます。アプリケーションでより多くのコンテキストが必要な場合（たとえば、関数定義のあるファイルをもとにモデルにユニットテストを書かせたい場合）は、この数値を大きくしてください。ただし、その分 GPU メモリの使用量も増える点に注意してください。ここでは、GPT-2 の 1,024 や GPT-3 の 2,048 とは異なり、コンテキストサイズを128トークンに固定します。

ほとんどのドキュメントは128トークンよりはるかに長いため、入力を最大長で単純に切り捨てると、データセットの大部分を失ってしまいます。代わりに、`return_overflowing_tokens` オプションを使って入力全体をトークン化し、[Chapter 6](/course/chapter6/4) で行ったように複数のチャンクに分割します。また、`return_length` オプションも使って、作成された各チャンクの長さを自動的に取得します。最後のチャンクはコンテキストサイズより小さくなることが多く、パディングの問題を避けるためにこれらの断片は除去します。データは十分にあるので、除去しても問題ありません。

この操作では、🤗 Datasets の `Dataset.map()` 関数の便利な特徴を使っています。1対1の対応を必要としない点です。[section 3](/course/chapter7/3) で見たように、入力バッチより多い、または少ない要素を持つバッチを作成できます。これは、データ拡張やデータの絞り込みなど、要素数を変える操作を行うときに便利です。今回のケースでは、各要素を指定したコンテキストサイズのチャンクにトークン化することで、各ドキュメントから多くのサンプルを作成しています。既存の列はサイズが競合するので、削除するのを忘れないようにしてください。保持したい場合は、適切に複製して `Dataset.map()` の呼び出しの中で返すこともできます。

```py
def tokenize(element):
    outputs = tokenizer(
        element["content"],
        truncation=True,
        max_length=context_length,
        return_overflowing_tokens=True,
        return_length=True,
    )
    input_batch = []
    for length, input_ids in zip(outputs["length"], outputs["input_ids"]):
        if length == context_length:
            input_batch.append(input_ids)
    return {"input_ids": input_batch}


tokenized_datasets = raw_datasets.map(
    tokenize, batched=True, remove_columns=raw_datasets["train"].column_names
)
tokenized_datasets

## 🤗 Accelerate で学習する

`Trainer` を使ったモデルの学習方法は見てきました。ある程度のカスタマイズは可能です。しかし、学習ループを完全に制御したい場合や、標準的な学習処理にはない特殊な処理を組み込みたい場合もあります。そのような場合には 🤗 Accelerate が最適です。このセクションでは、それを使ってモデルを学習する手順を順に追っていきます。さらに面白くするために、学習ループに一工夫も加えます。








関心があるのは主にデータサイエンスライブラリに対する的確な自動補完なので、これらのライブラリを多く使う学習サンプルにより大きな重みを与えるのが理にかなっています。こうしたサンプルは、`plt`、`pd`、`sk`、`fit`、`predict` といったキーワードで簡単に識別できます。これらは `matplotlib.pyplot`、`pandas`、`sklearn` の最も頻繁なインポート名であり、後者の fit/predict パターンでもあります。これらがそれぞれ単一のトークンとして表現されるなら、入力シーケンスに含まれているかを簡単に確認できます。トークンには空白の接頭辞が付く場合もあるので、トークナイザの語彙ではそのバージョンも確認します。動作を検証するために、複数のトークンに分割されるはずのテスト用トークンを1つ追加します。

うまく動いているようです！入力シーケンス、ロジット、先ほど選んだキートークンを入力として受け取るカスタム損失関数を書くことができます。まず、ロジットと入力を揃える必要があります。次のトークンが現在のトークンのラベルになるため、入力シーケンスを右に1つずらしたものがラベルになります。モデルは最初のトークンについては予測を行わないので、ラベルを入力シーケンスの2番目のトークンから始めることでこれを実現できます。次に、入力シーケンス全体の後に続くトークンのラベルは存在しないため、最後のロジットを切り取ります。これで、サンプルごとの損失を計算し、各サンプル内のすべてのキーワードの出現回数を数えることができます。最後に、出現回数を重みとして、すべてのサンプルの重み付き平均を計算します。キーワードを含まないサンプルをすべて捨ててしまわないよう、重みには1を加えます。

```py
from torch.nn import CrossEntropyLoss
import torch


def keytoken_weighted_loss(inputs, logits, keytoken_ids, alpha=1.0):
    # トークン < n が n を予測するようにシフトする
    shift_labels = inputs[..., 1:].contiguous()
    shift_logits = logits[..., :-1, :].contiguous()
    # トークンごとの損失を計算する
    loss_fct = CrossEntropyLoss(reduce=False)
    loss = loss_fct(shift_logits.view(-1, shift_logits.size(-1)), shift_labels.view(-1))
    # 形状を変えて、サンプルごとに損失を平均する
    loss_per_sample = loss.view(shift_logits.size(0), shift_logits.size(1)).mean(axis=1)
    # 重み付けを計算してスケールする
    weights = torch.stack([(inputs == kt).float() for kt in keytoken_ids]).sum(
        axis=[0, 2]
    )
    weights = alpha * (1.0 + weights)
    # 重み付き平均を計算する
    weighted_loss = (loss_per_sample * weights).mean()
    return weighted_loss

この素晴らしい新しい損失関数で学習を始める前に、いくつか準備が必要です。

  • データをバッチ単位で読み込むデータローダが必要です。
  • 重み減衰のパラメータを設定する必要があります。
  • 定期的に評価したいので、評価コードを関数にまとめておくのがよいでしょう。

データローダから始めましょう。データセットの形式を "torch" に設定し、適切なバッチサイズで PyTorch の DataLoader に渡すだけです。

次に、オプティマイザがどのパラメータに追加の重み減衰を適用するか分かるように、パラメータをグループ化します。通常、すべてのバイアスと LayerNorm の重みはこの対象から外れます。その方法は次のとおりです。

weight_decay = 0.1


def get_grouped_params(model, no_decay=["bias", "LayerNorm.weight"]):
    params_with_wd, params_without_wd = [], []
    for n, p in model.named_parameters():
        if any(nd in n for nd in no_decay):
            params_without_wd.append(p)
        else:
            params_with_wd.append(p)
    return [
        {"params": params_with_wd, "weight_decay": weight_decay},
        {"params": params_without_wd, "weight_decay": 0.0},
    ]

学習中に検証セットでモデルを定期的に評価したいので、そのための関数も書きましょう。評価用データローダを一巡し、すべてのプロセスにわたって損失を集めるだけです。

def evaluate():
    model.eval()
    losses = []
    for step, batch in enumerate(eval_dataloader):
        with torch.no_grad():
            outputs = model(batch["input_ids"], labels=batch["input_ids"])

        losses.append(accelerator.gather(outputs.loss))
    loss = torch.mean(torch.cat(losses))
    try:
        perplexity = torch.exp(loss)
    except OverflowError:
        perplexity = float("inf")
    return loss.item(), perplexity.item()

        if step % 100 == 0:

                    "steps": completed_steps,

        accelerator.backward(loss)
        if step % gradient_accumulation_steps == 0:

            optimizer.step()
