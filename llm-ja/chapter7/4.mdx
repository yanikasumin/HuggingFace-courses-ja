では、翻訳に入りましょう。翻訳も[シーケンス・ツー・シーケンスのタスク](/course/chapter1/7)の1つです。つまり、あるシーケンスから別のシーケンスへ移る問題として定式化できます。その意味で、この問題は[要約](/course/chapter7/6)にかなり近く、ここで学ぶ内容は次のような他のシーケンス・ツー・シーケンスの問題にも応用できます。

- **文体変換（Style transfer）**: ある文体で書かれたテキストを別の文体に*翻訳*するモデルを作る（例: 丁寧な文体からくだけた文体へ、シェイクスピア風の英語から現代英語へ）
- **生成型質問応答（Generative question answering）**: 文脈を与えて、質問への回答を生成するモデルを作る

<Youtube id="1JvfrvZgi6c"/>

2つ（またはそれ以上）の言語のテキストからなる十分大きなコーパスがあれば、[因果言語モデリング](/course/chapter7/6)のセクションで行うように、新しい翻訳モデルをゼロから学習できます。ただし、既存の翻訳モデルをファインチューニングする方が速く済みます。多言語モデルの mT5 や mBART を特定の言語ペア向けにファインチューニングする場合でも、ある言語から別の言語への翻訳に特化したモデルを自分のコーパス向けにファインチューニングする場合でも構いません。

このセクションでは、英語からフランス語への翻訳で事前学習された Marian モデルを、[KDE4 データセット](https://huggingface.co/datasets/kde4)でファインチューニングします（Hugging Face の社員の多くがこの2言語を話すためです）。KDE4 は [KDE アプリ](https://apps.kde.org/)のローカライズ用ファイルのデータセットです。使うモデルは、[Opus データセット](https://opus.nlpl.eu/)から取得したフランス語と英語の大規模コーパスで事前学習されています。Opus には KDE4 データセット自体も含まれています。ただし、使う事前学習モデルが事前学習の段階でそのデータを見ていたとしても、ファインチューニング後にはより良いモデルが得られることが分かるはずです。

## データの準備[[preparing-the-data]]

翻訳モデルをファインチューニングしたりゼロから学習したりするには、タスクに適したデータセットが必要です。前述のとおり、このセクションでは [KDE4 データセット](https://huggingface.co/datasets/kde4) を使いますが、翻訳元と翻訳先の2言語の文ペアさえあれば、自分のデータに合わせるのも簡単です。自前のデータを `Dataset` に読み込む方法を思い出したい場合は、[Chapter 5](/course/chapter5) を参照してください。

### KDE4 データセット[[the-kde4-dataset]]

いつものように、`load_dataset()` 関数でデータセットをダウンロードします。

```py
from datasets import load_dataset

raw_datasets = load_dataset("kde4", lang1="en", lang2="fr")
```

別の言語ペアで作業したい場合は、言語コードで指定できます。このデータセットでは合計92言語が利用できます。[データセットカード](https://huggingface.co/datasets/kde4)の言語タグを展開すると、すべて確認できます。

### データの処理[[processing-the-data]]

<Youtube id="XAR8jnZZuUs"/>

もう手順はお分かりでしょう。モデルが理解できるよう、テキストはすべてトークン ID の集合に変換する必要があります。このタスクでは、入力とターゲットの両方をトークン化しなければなりません。まず `tokenizer` オブジェクトを作成します。前述のとおり、英語からフランス語への Marian 事前学習モデルを使います。別の言語ペアでこのコードを試す場合は、モデルのチェックポイントをそれに合わせて変更してください。[Helsinki-NLP](https://huggingface.co/Helsinki-NLP) 組織は、複数言語で1,000を超えるモデルを提供しています。

```python
from transformers import AutoTokenizer

model_checkpoint = "Helsinki-NLP/opus-mt-en-fr"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint, return_tensors="pt")
```

`model_checkpoint` は、[Hub](https://huggingface.co/models) にある好みのモデルや、事前学習済みモデルとトークナイザを保存したローカルフォルダに置き換えることもできます。

> [!TIP]
> 💡 mBART、mBART-50、M2M100 のような多言語トークナイザを使う場合は、`tokenizer.src_lang` と `tokenizer.tgt_lang` に適切な値を設定して、入力とターゲットの言語コードをトークナイザに設定する必要があります。

データの準備はかなり単純です。覚えておくべきことは1つだけです。トークナイザがターゲットを出力言語（ここではフランス語）として処理するようにしなければなりません。これには、トークナイザの `__call__` メソッドの `text_targets` 引数にターゲットを渡します。

仕組みを確認するため、学習セットから各言語のサンプルを1つずつ処理してみましょう。

```python
en_sentence = split_datasets["train"][1]["translation"]["en"]
fr_sentence = split_datasets["train"][1]["translation"]["fr"]

inputs = tokenizer(en_sentence, text_target=fr_sentence)
inputs
```

```python out
{'input_ids': [47591, 12, 9842, 19634, 9, 0], 'attention_mask': [1, 1, 1, 1, 1, 1], 'labels': [577, 5891, 2, 3184, 16, 2542, 5, 1710, 0]}
```

見てのとおり、出力には英語の文に対応する入力 ID が含まれ、フランス語の文に対応する ID は `labels` フィールドに格納されています。ラベルをトークン化していることを指定し忘れると、ラベルは入力用トークナイザでトークン化されてしまいます。Marian モデルの場合、これはまったくうまくいきません。

```python
wrong_targets = tokenizer(fr_sentence)
print(tokenizer.convert_ids_to_tokens(wrong_targets["input_ids"]))
print(tokenizer.convert_ids_to_tokens(inputs["labels"]))
```

```python out
['▁Par', '▁dé', 'f', 'aut', ',', '▁dé', 've', 'lop', 'per', '▁les', '▁fil', 's', '▁de', '▁discussion', '</s>']
['▁Par', '▁défaut', ',', '▁développer', '▁les', '▁fils', '▁de', '▁discussion', '</s>']
```

見てのとおり、英語のトークナイザでフランス語の文を前処理すると、トークン数がずっと多くなります。トークナイザがフランス語の単語を知らないためです（"discussion" のように英語にも現れる単語は除きます）。

`inputs` は通常のキー（入力 ID、アテンションマスクなど）を持つ辞書なので、最後のステップは、データセットに適用する前処理関数を定義することです。

```python
max_length = 128


def preprocess_function(examples):
    inputs = [ex["en"] for ex in examples["translation"]]
    targets = [ex["fr"] for ex in examples["translation"]]
    model_inputs = tokenizer(
        inputs, text_target=targets, max_length=max_length, truncation=True
    )
    return model_inputs
```

入力と出力に同じ最大長を設定していることに注意してください。扱うテキストはかなり短いようなので、128 を使います。

> [!TIP]
> 💡 T5 モデル（具体的には `t5-xxx` チェックポイントのいずれか）を使う場合、モデルはテキスト入力に `translate: English to French:` のような、タスクを示す接頭辞が付いていることを想定します。

> [!WARNING]
> ⚠️ ターゲットのアテンションマスクには注意を払いません。モデルはそれを想定していないためです。その代わり、パディングトークンに対応するラベルは、損失の計算で無視されるよう `-100` に設定すべきです。ここでは動的パディングを適用するので、この処理は後でデータコレータが行います。ただし、ここでパディングを行う場合は、パディングトークンに対応するラベルをすべて `-100` に設定するよう前処理関数を適応させてください。

これで、データセットのすべてのスプリットに前処理を一括で適用できます。

```py
tokenized_datasets = split_datasets.map(
    preprocess_function,
    batched=True,
    remove_columns=split_datasets["train"].column_names,
)
```

データの前処理が終わったので、事前学習済みモデルをファインチューニングする準備ができました！

## `Trainer` API でモデルをファインチューニングする[[fine-tuning-the-model-with-the-trainer-api]]

`Trainer` を使う実際のコードはこれまでと同じで、変更は1つだけです。ここでは [`Seq2SeqTrainer`](https://huggingface.co/transformers/main_classes/trainer.html#seq2seqtrainer) を使います。これは `Trainer` のサブクラスで、`generate()` メソッドを使って入力から出力を予測し、評価を適切に扱えるようにします。詳しくは、指標の計算について説明するときに見ていきます。

何よりもまず、ファインチューニングする実物のモデルが必要です。いつもの `AutoModel` API を使います。

```py
from transformers import AutoModelForSeq2SeqLM

model = AutoModelForSeq2SeqLM.from_pretrained(model_checkpoint)
```

### データコレータ[[data-collation]]

動的バッチ処理のパディングを扱うには、データコレータが必要です。このケースでは、[Chapter 3](/course/chapter3) のような `DataCollatorWithPadding` をそのまま使うことはできません。これは入力（入力 ID、アテンションマスク、トークンタイプ ID）しかパディングしないためです。ラベルも、ラベル内で遭遇する最大長までパディングしなければなりません。また、前述のとおり、ラベルのパディングに使う値はトークナイザのパディングトークンではなく `-100` にすべきです。そうすれば、パディングされた値が損失の計算で確実に無視されます。

これらをすべて行うのが [`DataCollatorForSeq2Seq`](https://huggingface.co/transformers/main_classes/data_collator.html#datacollatorforseq2seq) です。`DataCollatorWithPadding` と同様に、入力の前処理に使った `tokenizer` を受け取りますが、`model` も受け取ります。これは、このデータコレータがデコーダ入力 ID の準備も担当するためです。デコーダ入力 ID は、ラベルをシフトし、先頭に特殊トークンを置いたものです。このシフトの方法はアーキテクチャによって少し異なるため、`DataCollatorForSeq2Seq` は `model` オブジェクトを知る必要があります。

{#if fw === 'pt'}

```py
from transformers import DataCollatorForSeq2Seq

data_collator = DataCollatorForSeq2Seq(tokenizer, model=model)
```

{:else}

```py
from transformers import DataCollatorForSeq2Seq

data_collator = DataCollatorForSeq2Seq(tokenizer, model=model, return_tensors="tf")
```

### 指標[[metrics]]

<Youtube id="M05L1DhFqcw"/>

{#if fw === 'pt'}

`Seq2SeqTrainer` がスーパークラスの `Trainer` に追加する機能は、評価や予測の際に `generate()` メソッドを使えることです。学習中、モデルは `decoder_input_ids` と、予測しようとしているトークンより後のトークンを使わないようにするアテンションマスクを使って学習を高速化します。推論時にはラベルがないため、それらを使うことはできません。そのため、モデルを同じ設定で評価するのは良い考えです。

[Chapter 1](/course/chapter1/6) で見たように、デコーダはトークンを1つずつ予測して推論を行います。これは 🤗 Transformers では `generate()` メソッドによって裏側で実装されています。`predict_with_generate=True` と設定すれば、`Seq2SeqTrainer` でそのメソッドを評価に使うことができます。

翻訳で伝統的に使われる指標は、Kishore Papineni らによる [2002年の論文](https://aclanthology.org/P02-1040.pdf) で導入された [BLEU スコア](https://en.wikipedia.org/wiki/BLEU) です。BLEU スコアは、翻訳がラベルにどれだけ近いかを評価します。モデルが生成した出力の分かりやすさや文法的な正しさは測りません。その代わり、統計的な規則を用いて、生成された出力に含まれる単語がすべてターゲットにも現れることを保証します。さらに、ターゲットでも繰り返されていないのに同じ単語が繰り返される場合（モデルが `"the the the the the"` のような文を出力するのを避けるため）と、ターゲットより短い文を出力する場合（モデルが `"the"` のような文を出力するのを避けるため）にペナルティを与える規則もあります。

BLEU の弱点の1つは、テキストがすでにトークン化されていることを前提とする点です。そのため、異なるトークナイザを使うモデル同士でスコアを比較するのが難しくなります。そこで、今日の翻訳モデルのベンチマークで最もよく使われる指標は [SacreBLEU](https://github.com/mjpost/sacrebleu) です。これは、トークン化のステップを標準化することで、この弱点（や他の弱点）に対処しています。この指標を使うには、まず SacreBLEU ライブラリをインストールする必要があります。

```py
!pip install sacrebleu
```

その後、[Chapter 3](/course/chapter3) で行ったように `evaluate.load()` で読み込むことができます。

```py

```

この指標は、テキストを入力とターゲットとして受け取ります。同じ文に対して許容できる翻訳は複数あることが多いため、許容できるターゲットを複数受け取れるよう設計されています。使うデータセットでは1つしか提供されませんが、NLP ではラベルとして複数の文を与えるデータセットも珍しくありません。そのため、予測は文のリストにしなければならず、参照は文のリストのリストでなければなりません。

モデルの出力から指標が使えるテキストに変換するには、`tokenizer.batch_decode()` メソッドを使います。ラベル内の `-100` をすべて除去するだけです。トークナイザはパディングトークンについても自動的に同じことを行います。モデルとデータセットを受け取り、その指標を計算する関数を定義しましょう。さらに、劇的にパフォーマンスを高める工夫も使います。生成コードを TensorFlow の高速化線形代数コンパイラである [XLA](https://www.tensorflow.org/xla) でコンパイルします。XLA はモデルの計算グラフにさまざまな最適化を適用し、速度とメモリ使用量を大きく改善します。Hugging Face の[ブログ](https://huggingface.co/blog/tf-xla-generate)で説明されているように、XLA は入力の形状があまり変化しないときに最も効果を発揮します。これに対応するため、入力を128の倍数までパディングし、パディング用コレータで新しいデータセットを作り、生成関数に `@tf.function(jit_compile=True)` デコレータを適用して、関数全体を XLA でコンパイルするようマークします。

```py
import numpy as np
import tensorflow as tf
from tqdm import tqdm

generation_data_collator = DataCollatorForSeq2Seq(
    tokenizer, model=model, return_tensors="tf", pad_to_multiple_of=128
)

tf_generate_dataset = model.prepare_tf_dataset(
    tokenized_datasets["validation"],
    collate_fn=generation_data_collator,
    shuffle=False,
    batch_size=8,
)


@tf.function(jit_compile=True)
def generate_with_xla(batch):
    return model.generate(
        input_ids=batch["input_ids"],
        attention_mask=batch["attention_mask"],
        max_new_tokens=128,
    )


def compute_metrics():
    all_preds = []
    all_labels = []

    for batch, labels in tqdm(tf_generate_dataset):
        predictions = generate_with_xla(batch)
        decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)
        labels = labels.numpy()
        labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
        decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)
        decoded_preds = [pred.strip() for pred in decoded_preds]
        decoded_labels = [[label.strip()] for label in decoded_labels]
        all_preds.extend(decoded_preds)
        all_labels.extend(decoded_labels)

    result = metric.compute(predictions=all_preds, references=all_labels)
    return {"bleu": result["score"]}
```

モデルの出力から指標が使えるテキストに変換するには、`tokenizer.batch_decode()` メソッドを使います。ラベル内の `-100` をすべて除去するだけです（トークナイザはパディングトークンについても自動的に同じことを行います）。

```py
import numpy as np


def compute_metrics(eval_preds):
    preds, labels = eval_preds
    # モデルが予測ロジット以上のものを返す場合に備えます
    if isinstance(preds, tuple):
        preds = preds[0]

    decoded_preds = tokenizer.batch_decode(preds, skip_special_tokens=True)

    # ラベル内の -100 はデコードできないので置き換えます
    labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
    decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)

    # 簡単な後処理
    decoded_preds = [pred.strip() for pred in decoded_preds]
    decoded_labels = [[label.strip()] for label in decoded_labels]

    result = metric.compute(predictions=decoded_preds, references=decoded_labels)
    return {"bleu": result["score"]}
```

これが終わったら、モデルをコンパイルして学習するために必要なものをすべて準備できます。`tf.keras.mixed_precision.set_global_policy("mixed_float16")` の使用に注意してください。これは Keras に float16 で学習するよう指示し、対応する GPU（Nvidia 20xx/V100 以降）では大幅な高速化が得られます。

```python
from transformers import create_optimizer
from transformers.keras_callbacks import PushToHubCallback
import tensorflow as tf

# 学習ステップ数は、データセットのサンプル数をバッチサイズで割り、総エポック数を掛けたものです。
# ここでの tf_train_dataset はバッチ化された tf.data.Dataset であり、元の Hugging Face Dataset ではないため、
# その len() はすでに num_samples // batch_size になっています。
num_epochs = 3
num_train_steps = len(tf_train_dataset) * num_epochs

optimizer, schedule = create_optimizer(
    init_lr=5e-5,
    num_warmup_steps=0,
    num_train_steps=num_train_steps,
    weight_decay_rate=0.01,
)
model.compile(optimizer=optimizer)

# 混合精度 float16 で学習します
tf.keras.mixed_precision.set_global_policy("mixed_float16")
```

次に、[セクション2](/course/chapter7/2) で見たように、学習中にモデルを Hub にアップロードするための `PushToHubCallback` を定義し、そのコールバックを使ってモデルを fit するだけです。

```python
from transformers.keras_callbacks import PushToHubCallback

callback = PushToHubCallback(
    output_dir="marian-finetuned-kde4-en-to-fr", tokenizer=tokenizer
)

model.fit(
    tf_train_dataset,
    validation_data=tf_eval_dataset,
    callbacks=[callback],
    epochs=num_epochs,
)
```

プッシュ先のリポジトリ名は `hub_model_id` 引数で指定できることに注意してください（特に、組織にプッシュする場合はこの引数を使う必要があります）。たとえば、モデルを [`huggingface-course` 組織](https://huggingface.co/huggingface-course) にプッシュした際には、`Seq2SeqTrainingArguments` に `hub_model_id="huggingface-course/marian-finetuned-kde4-en-to-fr"` を追加しました。デフォルトでは、使用されるリポジトリは自分の名前空間内にあり、設定した出力ディレクトリにちなんだ名前になるため、ここでは `"sgugger/marian-finetuned-kde4-en-to-fr"` になります（これは、このセクションの冒頭でリンクしたモデルです）。

これが終わったら、`Seq2SeqTrainingArguments` を定義できます。`Trainer` と同様に、フィールドが少し増えた `TrainingArguments` のサブクラスを使います。

```python
from transformers import Seq2SeqTrainingArguments

args = Seq2SeqTrainingArguments(
    f"marian-finetuned-kde4-en-to-fr",
    evaluation_strategy="no",
    save_strategy="epoch",
    learning_rate=2e-5,
    per_device_train_batch_size=32,
    per_device_eval_batch_size=64,
    weight_decay=0.01,
    save_total_limit=3,
    num_train_epochs=3,
    predict_with_generate=True,
    fp16=True,
    push_to_hub=True,
)
```

通常のハイパーパラメータ（学習率、エポック数、バッチサイズ、多少のウェイト減衰など）のほか、前のセクションで見たものと比べて変更点がいくつかあります。

- 定期的な評価は設定しません。評価には時間がかかるためです。代わりに、学習前と学習後に1回ずつモデルを評価します。
- `fp16=True` と設定し、最新の GPU での学習を高速化します。
- 前述のとおり、`predict_with_generate=True` と設定します。
- `push_to_hub=True` を使い、各エポックの終わりにモデルを Hub にアップロードします。

プッシュ先リポジトリの完全な名前は `hub_model_id` 引数で指定できることに注意してください（特に、組織にプッシュする場合はこの引数を使う必要があります）。たとえば、モデルを [`huggingface-course` 組織](https://huggingface.co/huggingface-course) にプッシュした際には、`Seq2SeqTrainingArguments` に `hub_model_id="huggingface-course/marian-finetuned-kde4-en-to-fr"` を追加しました。デフォルトでは、使用されるリポジトリは自分の名前空間内にあり、設定した出力ディレクトリにちなんだ名前になるため、私たちの場合 `"sgugger/marian-finetuned-kde4-en-to-fr"` になります（これは、このセクションの冒頭でリンクしたモデルです）。

## カスタム学習ループ[[a-custom-training-loop]]

では、完全な学習ループを見ていきましょう。必要な部分を簡単にカスタマイズできます。見た目は、[セクション2](/course/chapter7/2) や [Chapter 3](/course/chapter3/4) で行ったものによく似ています。

### 学習に必要なものをすべて準備する[[preparing-everything-for-training]]

これらは何度も見てきたので、コードはかなり速く進めていきます。まず、データセットを `"torch"` 形式に設定して PyTorch テンソルが得られるようにし、データセットから `DataLoader` を構築します。

```py
from torch.utils.data import DataLoader

tokenized_datasets.set_format("torch")
train_dataloader = DataLoader(
    tokenized_datasets["train"],
    shuffle=True,
    collate_fn=data_collator,
    batch_size=8,
)
eval_dataloader = DataLoader(
    tokenized_datasets["validation"], collate_fn=data_collator, batch_size=8
)
```

次に、モデルを再インスタンス化します。これにより、前のファインチューニングを続けるのではなく、事前学習済みモデルから再び開始することを確実にします。

```py
model = AutoModelForSeq2SeqLM.from_pretrained(model_checkpoint)
```

次にオプティマイザが必要です。

```py
from torch.optim import AdamW

optimizer = AdamW(model.parameters(), lr=2e-5)
```

これらのオブジェクトがすべてそろったら、`accelerator.prepare()` メソッドに渡すことができます。Colab ノートブックで TPU 上で学習したい場合は、このコードをすべて学習関数の中に移動する必要があること、そして `Accelerator` をインスタンス化するセルは実行すべきでないことを覚えておいてください。

```py
from accelerate import Accelerator

accelerator = Accelerator()
model, optimizer, train_dataloader, eval_dataloader = accelerator.prepare(
    model, optimizer, train_dataloader, eval_dataloader
)
```

`train_dataloader` を `accelerator.prepare()` に渡したので、その長さを使って学習ステップ数を計算できます。このメソッドは `DataLoader` の長さを変更するため、必ず準備の後にこれを行うべきであることを覚えておいてください。学習率から0までの古典的な線形スケジュールを使います。

```py
from transformers import get_scheduler

num_train_epochs = 3
num_update_steps_per_epoch = len(train_dataloader)
num_training_steps = num_train_epochs * num_update_steps_per_epoch

lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)
```

最後に、モデルを Hub にプッシュするには、作業フォルダ内に `Repository` オブジェクトを作成する必要があります。まず、まだログインしていない場合は Hugging Face Hub にログインしてください。リポジトリ名は、モデルに付けたいモデル ID から決定します（`repo_name` は自由に自分の選択に置き換えて構いません。ユーザー名を含む必要があるだけで、それは `get_full_repo_name()` 関数が行います）。

```py
from huggingface_hub import Repository, get_full_repo_name
```

### 学習ループ[[training-loop]]

これで、完全な学習ループを書く準備ができました。その評価部分を単純化するため、予測とラベルを受け取り、`metric` オブジェクトが期待する文字列のリストに変換する `postprocess()` 関数を定義します。

```py
def postprocess(predictions, labels):
    predictions = predictions.cpu().numpy()
    labels = labels.cpu().numpy()

    decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)

    # ラベル内の -100 はデコードできないので置き換えます
    labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
    decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)

    # 簡単な後処理
    decoded_preds = [pred.strip() for pred in decoded_preds]
    decoded_labels = [[label.strip()] for label in decoded_labels]
    return decoded_preds, decoded_labels
```

学習ループは、[セクション2](/course/chapter7/2) や [Chapter 3](/course/chapter3) のものによく似ていますが、評価部分にいくつかの違いがあります。そこに焦点を当てましょう！

まず注意すべき点は、予測の計算に `generate()` メソッドを使いますが、これは `prepare()` メソッドで 🤗 Accelerate が作成したラップされたモデルではなく、ベースモデルのメソッドであることです。そのため、まずモデルをアンラップしてから、このメソッドを呼び出します。

2つ目は、[トークン分類](/course/chapter7/2) の場合と同様に、2つのプロセスが入力とラベルを異なる形状にパディングしている可能性があることです。そのため、`gather()` メソッドを呼び出す前に、`accelerator.pad_across_processes()` を使って予測とラベルを同じ形状にします。これを行わないと、評価でエラーになるか、永遠にハングします。

```py
from tqdm.auto import tqdm
import torch

progress_bar = tqdm(range(num_training_steps))

for epoch in range(num_train_epochs):
    # 学習
    model.train()
    for batch in train_dataloader:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

    # 評価
    model.eval()
    for batch in tqdm(eval_dataloader):
        with torch.no_grad():
            generated_tokens = accelerator.unwrap_model(model).generate(
                batch["input_ids"],
                attention_mask=batch["attention_mask"],
                max_length=128,
            )
        labels = batch["labels"]

        # gather するために予測とラベルをパディングする必要があります
        generated_tokens = accelerator.pad_across_processes(
            generated_tokens, dim=1, pad_index=tokenizer.pad_token_id
        )
        labels = accelerator.pad_across_processes(labels, dim=1, pad_index=-100)

        predictions_gathered = accelerator.gather(generated_tokens)
        labels_gathered = accelerator.gather(labels)

        decoded_preds, decoded_labels = postprocess(predictions_gathered, labels_gathered)
        metric.add_batch(predictions=decoded_preds, references=decoded_labels)

    results = metric.compute()
    print(f"epoch {epoch}, BLEU score: {results['score']:.2f}")

    # 保存とアップロード
    accelerator.wait_for_everyone()
    unwrapped_model = accelerator.unwrap_model(model)
    unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
    if accelerator.is_main_process:
        tokenizer.save_pretrained(output_dir)
        repo.push_to_hub(
            commit_message=f"Training in progress epoch {epoch}", blocking=False
        )
```

## ファインチューニングしたモデルを使う[[using-the-fine-tuned-model]]

Model Hub でファインチューニングしたモデルを推論ウィジェットで使う方法はすでに示しました。ローカルで `pipeline` で使うには、適切なモデルの識別子を指定するだけです。

```py
from transformers import pipeline

# これは自分のチェックポイントに置き換えてください
model_checkpoint = "huggingface-course/marian-finetuned-kde4-en-to-fr"
translator = pipeline("translation", model=model_checkpoint)
translator("Default to expanded threads")
```

```python out
[{'translation_text': 'Par défaut, développer les fils de discussion'}]
```

期待どおり、事前学習済みモデルはファインチューニングしたコーパスに知識を適応させ、英語の単語 "threads" をそのままにする代わりに、フランス語の公式版に翻訳するようになりました。"plugin" についても同じです。

```py
translator(
    "Unable to import %1 using the OFX importer plugin. This file is not the correct format."
)
```
