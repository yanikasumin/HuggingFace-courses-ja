次に、翻訳を扱います。翻訳は[シーケンス・ツー・シーケンスのタスク](/course/chapter1/7)の1つです。あるシーケンスから別のシーケンスへ移る問題として定式化出来ます。この問題は[要約](/course/chapter7/6)にかなり近く、ここで学ぶ内容は次のような他のシーケンス・ツー・シーケンスの問題にも応用出来ます。

- **文体変換（Style transfer）**：或る文体で書かれたテキストを別の文体に*翻訳*するモデルを作る（例: 丁寧な文体からくだけた文体へ、シェイクスピア風の英語から現代英語へ）
- **生成型質問応答（Generative question answering）**：文脈を与えて、質問への回答を生成するモデルを作る

<Youtube id="1JvfrvZgi6c"/>

2つ（又はそれ以上）の言語のテキストからなる十分大きなコーパスがあれば、[因果言語モデリング](/course/chapter7/6)のセクションと同様に、新しい翻訳モデルをゼロから学習出来ます。但し、既存の翻訳モデルをファインチューニングする方が速く済みます。多言語モデルの mT5 や mBART を特定の言語ペア向けにファインチューニングする場合も、特定の言語ペアに特化したモデルを自分のコーパス向けにファインチューニングする場合も、対象になります。

このセクションでは、英語からフランス語への翻訳で事前学習された Marian モデルを、[KDE4 データセット](https://huggingface.co/datasets/kde4)でファインチューニングします。KDE4 は [KDE アプリ](https://apps.kde.org/)のローカライズ用ファイルのデータセットです。Hugging Face の社員の多くが英語とフランス語の2言語を話す為、この言語ペアを選びます。使うモデルは、[Opus データセット](https://opus.nlpl.eu/)から取得したフランス語と英語の大規模コーパスで事前学習されています。Opus には KDE4 データセット自体も含まれます。但し、事前学習モデルが事前学習の段階でそのデータを見ていたとしても、ファインチューニング後にはより良いモデルが得られます。

## データの準備[[preparing-the-data]]

翻訳モデルをファインチューニングする場合も、ゼロから学習する場合も、タスクに適したデータセットが必要です。このセクションでは [KDE4 データセット](https://huggingface.co/datasets/kde4) を使います。但し、翻訳元と翻訳先の2言語の文ペアさえあれば、自分のデータに合わせることも出来ます。自前のデータを `Dataset` に読み込む方法は、[Chapter 5](/course/chapter5) を参照してください。

### KDE4 データセット[[the-kde4-dataset]]

いつものように、`load_dataset()` 関数でデータセットをダウンロードします。

```py
from datasets import load_dataset

raw_datasets = load_dataset("kde4", lang1="en", lang2="fr")
```

### データの処理[[processing-the-data]]

<Youtube id="XAR8jnZZuUs"/>

手順はこれまでと同じです。モデルが理解出来るよう、テキストは全てトークン ID の集合に変換します。このタスクでは、入力とターゲットの両方をトークン化します。

まず `tokenizer` オブジェクトを作成します。前述の通り、英語からフランス語への Marian 事前学習モデルを使います。別の言語ペアでこのコードを試す場合は、モデルのチェックポイントを合わせて変更してください。[Helsinki-NLP](https://huggingface.co/Helsinki-NLP) 組織は、複数言語で1,000を超えるモデルを提供しています。

```python
from transformers import AutoTokenizer

model_checkpoint = "Helsinki-NLP/opus-mt-en-fr"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint, return_tensors="pt")
```

`model_checkpoint` は、[Hub](https://huggingface.co/models) にある別のモデルや、事前学習済みモデルとトークナイザを保存したローカルフォルダに置き換えることも出来ます。

> [!TIP]
> 💡 mBART、mBART-50、M2M100 のような多言語トークナイザを使う場合は、入力とターゲットの言語コードをトークナイザに設定する必要があります。設定には、`tokenizer.src_lang` と `tokenizer.tgt_lang` に適切な値を入れます。

データの準備はかなり単純です。注意点は1つだけです。トークナイザには、ターゲットを出力言語（ここではフランス語）として処理させる必要があります。その為には、トークナイザの `__call__` メソッドの `text_targets` 引数にターゲットを渡します。

仕組みを確認する為、学習セットから各言語のサンプルを1つずつ処理します。

```python
en_sentence = split_datasets["train"][1]["translation"]["en"]
fr_sentence = split_datasets["train"][1]["translation"]["fr"]

inputs = tokenizer(en_sentence, text_target=fr_sentence)
inputs
```

```python out
{'input_ids': [47591, 12, 9842, 19634, 9, 0], 'attention_mask': [1, 1, 1, 1, 1, 1], 'labels': [577, 5891, 2, 3184, 16, 2542, 5, 1710, 0]}
```

出力には、英語の文に対応する入力 ID が含まれます。フランス語の文に対応する ID は `labels` フィールドに格納されます。ラベルをトークン化していることを指定し忘れると、ラベルは入力用トークナイザでトークン化されます。Marian モデルの場合、これは全くうまくいきません。

```python
wrong_targets = tokenizer(fr_sentence)
print(tokenizer.convert_ids_to_tokens(wrong_targets["input_ids"]))
print(tokenizer.convert_ids_to_tokens(inputs["labels"]))
```

```python out
['▁Par', '▁dé', 'f', 'aut', ',', '▁dé', 've', 'lop', 'per', '▁les', '▁fil', 's', '▁de', '▁discussion', '</s>']
['▁Par', '▁défaut', ',', '▁développer', '▁les', '▁fils', '▁de', '▁discussion', '</s>']
```

英語のトークナイザでフランス語の文を前処理すると、トークン数がずっと多くなります。トークナイザがフランス語の単語を知らない為です。"discussion" のように英語にも現れる単語は除きます。

`inputs` は通常のキー（入力 ID、アテンションマスクなど）を持つ辞書です。最後のステップとして、データセットに適用する前処理関数を定義します。

```python
max_length = 128


def preprocess_function(examples):
    inputs = [ex["en"] for ex in examples["translation"]]
    targets = [ex["fr"] for ex in examples["translation"]]
    model_inputs = tokenizer(
        inputs, text_target=targets, max_length=max_length, truncation=True
    )
    return model_inputs
```

入力と出力には、同じ最大長を設定しています。扱うテキストはかなり短い為、128 を使います。

> [!TIP]
> 💡 T5 モデル（具体的には `t5-xxx` チェックポイントのいずれか）を使う場合、モデルはテキスト入力にタスクを示す接頭辞が付いていることを想定します。接頭辞の例は `translate: English to French:` です。

> [!WARNING]
> ⚠️ ターゲットのアテンションマスクは使いません。モデルが想定していない為です。代わりに、パディングトークンに対応するラベルは `-100` に設定します。損失の計算で無視する為です。ここでは動的パディングを適用する為、この処理は後でデータコレータが行います。但し、ここでパディングを行う場合は、パディングトークンに対応するラベルを全て `-100` に設定するよう、前処理関数を適応させてください。

これで、データセットの全てのスプリットに前処理を一括で適用します。

```py
tokenized_datasets = split_datasets.map(
    preprocess_function,
    batched=True,
    remove_columns=split_datasets["train"].column_names,
)
```

データの前処理が終わりました。事前学習済みモデルをファインチューニングする準備が出来ました。

### データコレータ[[data-collation]]

動的バッチ処理のパディングには、データコレータが必要です。このケースでは、[Chapter 3](/course/chapter3) で使った `DataCollatorWithPadding` をそのまま使えません。このコレータは、入力（入力 ID、アテンションマスク、トークンタイプ ID）しかパディングしない為です。ラベルも、バッチ内の最大長までパディングする必要があります。また、前述の通り、ラベルのパディングに使う値は、トークナイザのパディングトークンではなく `-100` とします。パディングされた値を損失の計算で無視する為です。

これらを全て行うのは [`DataCollatorForSeq2Seq`](https://huggingface.co/transformers/main_classes/data_collator.html#datacollatorforseq2seq) です。`DataCollatorWithPadding` と同様に、入力の前処理に使った `tokenizer` を受け取りますが、`model` も受け取ります。これは、このデータコレータがデコーダ入力 ID の準備も担当する為です。デコーダ入力 ID は、ラベルをシフトし、先頭に特殊トークンを置いたものです。このシフトの方法はアーキテクチャによって少し異なります。その為、`DataCollatorForSeq2Seq` は `model` オブジェクトを必要とします。

{#if fw === 'pt'}

```py
from transformers import DataCollatorForSeq2Seq

data_collator = DataCollatorForSeq2Seq(tokenizer, model=model)
```

{:else}

```py
from transformers import DataCollatorForSeq2Seq

data_collator = DataCollatorForSeq2Seq(tokenizer, model=model, return_tensors="tf")
```

{/if}

{#if fw === 'pt'}

`Seq2SeqTrainer` がスーパークラスの `Trainer` に追加する機能は、評価や予測の際に `generate()` メソッドを使えることです。学習中、モデルは `decoder_input_ids` を使います。併せて、予測対象のトークンより後のトークンを使わないようにするアテンションマスクで、学習を高速化します。推論時にはラベルがない為、これらを使うことはできません。その為、モデルは同じ設定で評価します。

[Chapter 1](/course/chapter1/6) で見たように、デコーダはトークンを1つずつ予測して推論を行います。この処理は、Transformers では `generate()` メソッドが裏側で実装しています。`predict_with_generate=True` と設定すれば、`Seq2SeqTrainer` はそのメソッドを評価に使います。

{/if}

翻訳で伝統的に使われる指標は、Kishore Papineni らによる [2002年の論文](https://aclanthology.org/P02-1040.pdf) で導入された [BLEU スコア](https://en.wikipedia.org/wiki/BLEU) です。BLEU スコアは、翻訳がラベルにどれだけ近いかを評価します。モデルが生成した出力の分かりやすさや文法的な正しさは測りません。代わりに、統計的な規則を用いて、生成された出力に含まれる単語が全てターゲットにも現れることを確認します。更に、同じ単語の繰り返しと短い出力にはペナルティを与える規則もあります。ターゲットでも繰り返されていないのに同じ単語が繰り返される場合（モデルが `"the the the the the"` のような文を出力するのを避ける為）と、ターゲットより短い文を出力する場合（モデルが `"the"` のような文を出力するのを避ける為）が対象です。

BLEU の弱点は1つあります。テキストが既にトークン化されていることを前提とする点です。その為、異なるトークナイザを使うモデル同士では、スコアを比較しにくくなります。今日の翻訳モデルのベンチマークで最もよく使われる指標は [SacreBLEU](https://github.com/mjpost/sacrebleu) です。SacreBLEU は、トークン化のステップを標準化することで、この弱点（や他の弱点）に対処しています。この指標を使うには、まず SacreBLEU ライブラリをインストールします。

```py
!pip install sacrebleu
```

その後、[Chapter 3](/course/chapter3) で行ったように、`evaluate.load()` で読み込めます。

```py
import evaluate

metric = evaluate.load("sacrebleu")
```

この指標は、テキストを入力とターゲットとして受け取ります。同じ文に対して許容出来る翻訳は複数あることが多い為、許容出来るターゲットを複数受け取れるよう設計されています。使うデータセットが提供するターゲットは1つだけです。但し、NLP ではラベルとして複数の文を与えるデータセットも珍しくありません。その為、予測は文のリストとし、参照は文のリストのリストとします。

モデルの出力から指標が使えるテキストに変換するには、`tokenizer.batch_decode()` メソッドを使います。ラベル内の `-100` を全て除去します。トークナイザはパディングトークンについても自動的に同じことを行います。モデルとデータセットを受け取り、その指標を計算する関数を定義します。

併せて、性能を大きく高める工夫も使います。生成コードを、TensorFlow の高速化線形代数コンパイラである [XLA](https://www.tensorflow.org/xla) でコンパイルする工夫です。XLA はモデルの計算グラフに様々な最適化を適用し、速度とメモリ使用量を大きく改善します。Hugging Face の[ブログ](https://huggingface.co/blog/tf-xla-generate)で説明されているように、XLA は入力の形状があまり変化しない時に最も効果を発揮します。これに対応する為、入力を128の倍数までパディングし、パディング用コレータで新しいデータセットを作ります。生成関数には `@tf.function(jit_compile=True)` デコレータを適用し、関数全体を XLA でコンパイルするようマークします。

```py
import numpy as np
import tensorflow as tf
from tqdm import tqdm

generation_data_collator = DataCollatorForSeq2Seq(
    tokenizer, model=model, return_tensors="tf", pad_to_multiple_of=128
)

tf_generate_dataset = model.prepare_tf_dataset(
    tokenized_datasets["validation"],
    collate_fn=generation_data_collator,
    shuffle=False,
    batch_size=8,
)


@tf.function(jit_compile=True)
def generate_with_xla(batch):
    return model.generate(
        input_ids=batch["input_ids"],
        attention_mask=batch["attention_mask"],
        max_new_tokens=128,
    )


def compute_metrics():
    all_preds = []
    all_labels = []

    for batch, labels in tqdm(tf_generate_dataset):
        predictions = generate_with_xla(batch)
        decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)
        labels = labels.numpy()
        labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
        decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)
        decoded_preds = [pred.strip() for pred in decoded_preds]
        decoded_labels = [[label.strip()] for label in decoded_labels]
        all_preds.extend(decoded_preds)
        all_labels.extend(decoded_labels)

    result = metric.compute(predictions=all_preds, references=all_labels)
    return {"bleu": result["score"]}
```

{:else}

モデルの出力から指標が使えるテキストへ変換するには、`tokenizer.batch_decode()` メソッドを使います。ラベル内の `-100` を全て除去します。トークナイザは、パディングトークンについても自動的に同じ処理を行います。

```py
import numpy as np


def compute_metrics(eval_preds):
    preds, labels = eval_preds
    # モデルが予測ロジット以上のものを返す場合に備えます
    if isinstance(preds, tuple):
        preds = preds[0]

    decoded_preds = tokenizer.batch_decode(preds, skip_special_tokens=True)

    # ラベル内の -100 はデコードできないので置き換えます
    labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
    decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)

    # 簡単な後処理
    decoded_preds = [pred.strip() for pred in decoded_preds]
    decoded_labels = [[label.strip()] for label in decoded_labels]

    result = metric.compute(predictions=decoded_preds, references=decoded_labels)
    return {"bleu": result["score"]}
```

次に、モデルをコンパイルして学習する為に必要なものを準備します。`tf.keras.mixed_precision.set_global_policy("mixed_float16")` の使用に注意してください。この設定は Keras に float16 で学習するよう指示するもので、対応する GPU（Nvidia 20xx/V100 以降）では大幅な高速化が得られます。

```python
from transformers import create_optimizer
from transformers.keras_callbacks import PushToHubCallback
import tensorflow as tf

# 学習ステップ数は、データセットのサンプル数をバッチサイズで割り、総エポック数を掛けたものです。
# ここでの tf_train_dataset はバッチ化された tf.data.Dataset であり、元の Hugging Face Dataset ではないため、
# その len() はすでに num_samples // batch_size になっています。
num_epochs = 3
num_train_steps = len(tf_train_dataset) * num_epochs

optimizer, schedule = create_optimizer(
    init_lr=5e-5,
    num_warmup_steps=0,
    num_train_steps=num_train_steps,
    weight_decay_rate=0.01,
)
model.compile(optimizer=optimizer)

# 混合精度 float16 で学習します
tf.keras.mixed_precision.set_global_policy("mixed_float16")
```

次に、`PushToHubCallback` を定義します。[セクション2](/course/chapter7/2) で見たように、学習中にモデルを Hub へアップロードする為のコールバックです。最後に、このコールバックを使ってモデルを fit します。

```python
from transformers.keras_callbacks import PushToHubCallback

callback = PushToHubCallback(
    output_dir="marian-finetuned-kde4-en-to-fr", tokenizer=tokenizer
)

model.fit(
    tf_train_dataset,
    validation_data=tf_eval_dataset,
    callbacks=[callback],
    epochs=num_epochs,
)
```

push 先のリポジトリ名は `hub_model_id` 引数で指定出来ます。組織へ push する場合は、この引数が必要です。例えば、[`huggingface-course` 組織](https://huggingface.co/huggingface-course) へ push した際には、`Seq2SeqTrainingArguments` に `hub_model_id="huggingface-course/marian-finetuned-kde4-en-to-fr"` を追加しました。既定では、リポジトリは自分の名前空間内に作られ、名前は設定した出力ディレクトリに由来します。ここでは `"sgugger/marian-finetuned-kde4-en-to-fr"` になります。このセクションの冒頭でリンクしたモデルです。

> [!TIP]
> 💡 使っている出力ディレクトリが既に存在する場合、そのディレクトリは push 先リポジトリのローカルクローンでなければなりません。そうでない場合は、`model.fit()` を呼び出す時にエラーになります。新しい名前を設定してください。

次に、`Seq2SeqTrainingArguments` を定義します。`Trainer` と同様に、フィールドが少し増えた `TrainingArguments` のサブクラスを使います。

```python
from transformers import Seq2SeqTrainingArguments

args = Seq2SeqTrainingArguments(
    f"marian-finetuned-kde4-en-to-fr",
    evaluation_strategy="no",
    save_strategy="epoch",
    learning_rate=2e-5,
    per_device_train_batch_size=32,
    per_device_eval_batch_size=64,
    weight_decay=0.01,
    save_total_limit=3,
    num_train_epochs=3,
    predict_with_generate=True,
    fp16=True,
    push_to_hub=True,
)
```

通常のハイパーパラメータ（学習率、エポック数、バッチサイズ、多少のウェイト減衰など）のほか、前のセクションで見たものと比べて変更点がいくつかあります。

- 定期的な評価は設定しません。評価には時間がかかる為です。代わりに、学習前と学習後に1回ずつモデルを評価します。
- `fp16=True` と設定し、最新の GPU での学習を高速化します。
- 前述の通り、`predict_with_generate=True` と設定します。
- `push_to_hub=True` を使い、各エポックの終わりにモデルを Hub にアップロードします。

push 先リポジトリの完全な名前は `hub_model_id` 引数で指定出来ます。組織へ push する場合は、この引数が必要です。例えば、[`huggingface-course` 組織](https://huggingface.co/huggingface-course) へ push した際には、`Seq2SeqTrainingArguments` に `hub_model_id="huggingface-course/marian-finetuned-kde4-en-to-fr"` を追加しました。既定では、リポジトリは自分の名前空間内に作られ、名前は設定した出力ディレクトリに由来します。ここでは `"sgugger/marian-finetuned-kde4-en-to-fr"` になります。このセクションの冒頭でリンクしたモデルです。

> [!TIP]
> 💡 使っている出力ディレクトリが既に存在する場合、そのディレクトリは push 先リポジトリのローカルクローンでなければなりません。そうでない場合は、`Seq2SeqTrainer` を定義する時にエラーになります。新しい名前を設定してください。

## カスタム学習ループ[[a-custom-training-loop]]

次に、完全な学習ループを示します。必要な部分は簡単にカスタマイズ出来ます。全体の形は、[セクション2](/course/chapter7/2) や [Chapter 3](/course/chapter3/4) で行ったものによく似ています。

### 学習に必要なものをすべて準備する[[preparing-everything-for-training]]

これらは何度も見てきた内容です。まず、データセットを `"torch"` 形式に設定して PyTorch テンソルが得られるようにし、データセットから `DataLoader` を構築します。

```py
from torch.utils.data import DataLoader

tokenized_datasets.set_format("torch")
train_dataloader = DataLoader(
    tokenized_datasets["train"],
    shuffle=True,
    collate_fn=data_collator,
    batch_size=8,
)
eval_dataloader = DataLoader(
    tokenized_datasets["validation"], collate_fn=data_collator, batch_size=8
)
```

次に、モデルを再インスタンス化します。前のファインチューニングを続けるのではなく、事前学習済みモデルから再び開始する為です。

```py
model = AutoModelForSeq2SeqLM.from_pretrained(model_checkpoint)
```

次に、オプティマイザを用意します。

```py
from torch.optim import AdamW

optimizer = AdamW(model.parameters(), lr=2e-5)
```

これらのオブジェクトが全て揃ったら、`accelerator.prepare()` メソッドに渡します。Colab ノートブックで TPU 上で学習する場合は、このコードを全て学習関数の中へ移動する必要があります。また、`Accelerator` をインスタンス化するセルは実行しないでください。

```py
from accelerate import Accelerator

accelerator = Accelerator()
model, optimizer, train_dataloader, eval_dataloader = accelerator.prepare(
    model, optimizer, train_dataloader, eval_dataloader
)
```

`train_dataloader` を `accelerator.prepare()` に渡したので、その長さを使って学習ステップ数を計算出来ます。このメソッドは `DataLoader` の長さを変更します。その為、計算は必ず準備の後に行います。スケジュールには、学習率から0までの古典的な線形スケジュールを使います。

```py
from transformers import get_scheduler

num_train_epochs = 3
num_update_steps_per_epoch = len(train_dataloader)
num_training_steps = num_train_epochs * num_update_steps_per_epoch

lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)
```

最後に、モデルを Hub にプッシュする為、作業フォルダ内に `Repository` オブジェクトを作成します。まだログインしていない場合は、先に Hugging Face Hub にログインしてください。リポジトリ名は、モデルに付けたいモデル ID から決めます。`repo_name` は自由に置き換えて構いません。但し、ユーザー名を含む必要があります。ユーザー名の付与は `get_full_repo_name()` 関数が行います。

```py
from huggingface_hub import Repository, get_full_repo_name

model_name = "marian-finetuned-kde4-en-to-fr-accelerate"
repo_name = get_full_repo_name(model_name)
repo_name
```

### 学習ループ[[training-loop]]

これで、完全な学習ループを書く準備が出来ました。評価部分を単純化する為、予測とラベルを受け取り、`metric` オブジェクトが期待する文字列のリストへ変換する `postprocess()` 関数を定義します。

```py
def postprocess(predictions, labels):
    predictions = predictions.cpu().numpy()
    labels = labels.cpu().numpy()

    decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)

    # ラベル内の -100 はデコードできないので置き換えます
    labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
    decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)

    # 簡単な後処理
    decoded_preds = [pred.strip() for pred in decoded_preds]
    decoded_labels = [[label.strip()] for label in decoded_labels]
    return decoded_preds, decoded_labels
```

学習ループは、[セクション2](/course/chapter7/2) や [Chapter 3](/course/chapter3) のものによく似ています。但し、評価部分にいくつかの違いがあります。以下では評価部分を中心に説明します。

まず注意すべき点は、予測の計算に使う `generate()` メソッドです。このメソッドは、`prepare()` メソッドで Accelerate が作成したラップ済みモデルではなく、ベースモデルのメソッドです。その為、まずモデルをアンラップしてから呼び出します。

2つ目は、パディングの形状です。[トークン分類](/course/chapter7/2) の場合と同様に、2つのプロセスが入力とラベルを異なる形状にパディングしている可能性があります。その為、`gather()` メソッドを呼ぶ前に、`accelerator.pad_across_processes()` を使って予測とラベルを同じ形状に揃えます。これを行わないと、評価でエラーになるか、処理が止まったままになります。

```py
from tqdm.auto import tqdm
import torch

progress_bar = tqdm(range(num_training_steps))

for epoch in range(num_train_epochs):
    # 学習
    model.train()
    for batch in train_dataloader:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

    # 評価
    model.eval()
    for batch in tqdm(eval_dataloader):
        with torch.no_grad():
            generated_tokens = accelerator.unwrap_model(model).generate(
                batch["input_ids"],
                attention_mask=batch["attention_mask"],
                max_length=128,
            )
        labels = batch["labels"]

        # gather するために予測とラベルをパディングする必要があります
        generated_tokens = accelerator.pad_across_processes(
            generated_tokens, dim=1, pad_index=tokenizer.pad_token_id
        )
        labels = accelerator.pad_across_processes(labels, dim=1, pad_index=-100)

        predictions_gathered = accelerator.gather(generated_tokens)
        labels_gathered = accelerator.gather(labels)

        decoded_preds, decoded_labels = postprocess(predictions_gathered, labels_gathered)
        metric.add_batch(predictions=decoded_preds, references=decoded_labels)

    results = metric.compute()
    print(f"エポック {epoch}, BLEU スコア: {results['score']:.2f}")

    # 保存とアップロード
    accelerator.wait_for_everyone()
    unwrapped_model = accelerator.unwrap_model(model)
    unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
    if accelerator.is_main_process:
        tokenizer.save_pretrained(output_dir)
        repo.push_to_hub(
            commit_message=f"Training in progress epoch {epoch}", blocking=False
        )
```

```python out
エポック 1, BLEU スコア: 54.24
エポック 2, BLEU スコア: 54.44
```

## ファインチューニングしたモデルを使う[[using-the-fine-tuned-model]]

Model Hub でファインチューニングしたモデルを推論ウィジェットで使う方法は、既に示しました。ローカルで `pipeline` を使って実行するには、適切なモデル識別子を指定します。

```py
from transformers import pipeline

# これは自分のチェックポイントに置き換えてください
model_checkpoint = "huggingface-course/marian-finetuned-kde4-en-to-fr"
translator = pipeline("translation", model=model_checkpoint)
translator("Default to expanded threads")
```

```python out
[{'translation_text': 'Par défaut, développer les fils de discussion'}]
```

（出力の訳：ファインチューニング済みモデルの出力は、データセットのフランス語訳と同じ「既定では、議論のスレッドを展開する」という意味です。）

期待通り、モデルはファインチューニングによって対象コーパスの用語に適応しました。英語の単語 "threads" をそのままにする代わりに、フランス語の公式な表現へ翻訳します。"plugin" についても同じです。

```py
translator(

)
```
