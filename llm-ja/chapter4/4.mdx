# モデルカードを作る[[building-a-model-card]]

<CourseFloatingBanner
    chapter={4}
    classNames="absolute z-10 right-0 top-0"
/>

モデルカードは、モデルリポジトリ内のモデルやトークナイザのファイルと同じくらい重要といえるでしょう。モデルについて説明する基本的な文書で、コミュニティのほかの人がモデルを再利用したり、結果を再現したり、そのモデルを土台に新しい成果物を作ったりする際に役立ちます。

モデルの学習方法と評価方法を記録すると、どのような結果が期待できるかをほかの人が理解しやすくなります。また、使ったデータや前処理・後処理についても十分に説明すれば、モデルの制限やバイアスに加え、どのような場面で役立ち、どのような場面では役立たないのかも把握できます。

そのため、モデルについて明確に説明するモデルカードの作成は、とても重要です。ここでは、作成時に役立つポイントを紹介します。モデルカードは、先ほど紹介した Markdown 形式の *README.md* ファイルに記述します。

「モデルカード」という考え方は Google の研究から生まれ、Margaret Mitchell らの論文 ["Model Cards for Model Reporting"](https://arxiv.org/abs/1810.03993) で初めて発表されました。ここで説明する内容の多くも、この論文に基づいています。再現性、再利用性、公平性が重視される中で、モデルカードが重要な理由を理解するためにも、ぜひ読んでみてください。

モデルカードは通常、モデルの用途についてのごく簡単な概要から始まり、その後のセクションで詳細を述べます。

- モデルの説明
- 想定される用途と制限
- 使い方
- 制限とバイアス
- 学習データ
- 学習手順
- 評価結果

各セクションに何を書くべきかを見ていきましょう。

### モデルの説明[[model-description]]

ここには、モデルの基本情報を記載します。たとえば、アーキテクチャ、バージョン、論文で発表されたモデルかどうか、元の実装が利用できるかどうか、開発者などです。著作権の帰属先もここに明記します。学習手順やパラメータの概要、重要な免責事項を載せることもできます。

### 想定される用途と制限[[intended-uses-limitations]]

ここでは、モデルの想定用途と、利用できる言語・分野・領域を説明します。また、適用範囲外と分かっている領域や、十分な性能を発揮できない可能性が高い領域も記載できます。

### 使い方[[how-to-use]]

ここでは、モデルの使い方を例とともに紹介します。`pipeline()` 関数を使う方法、モデルやトークナイザのクラスを使う方法のほか、利用者の参考になるコードを載せてもかまいません。

### 学習データ[[training-data]]

このパートでは、モデルの学習に使ったデータセットを示します。データセットの概要も併せて説明するとよいでしょう。

### 学習手順[[training-procedure]]

ここでは、ほかのユーザーが学習を再現できるように、必要な手順や条件を詳しく記録します。たとえば、データの前処理と後処理、学習したエポック数、バッチサイズ、学習率などです。

### 変数と評価指標[[variable-and-metrics]]

ここでは、評価に使う指標と、何を測定するかを説明します。どの評価指標を使い、どのデータセットのどの分割（検証用やテスト用など）で評価したかを示すと、ほかのモデルと性能を比較しやすくなります。評価指標や測定対象は、前のセクションで説明した想定ユーザーや用途を踏まえて決めます。

### 評価結果[[evaluation-results]]

最後に、評価用データセットでモデルがどの程度の性能を発揮するかを示します。モデルが決定しきい値を使う場合は、評価時に使ったしきい値を示すか、想定される用途に応じてしきい値を変えた場合の評価結果を詳しく記載してください。

## 例[[example]]

よくできたモデルカードの例をいくつか紹介します。

- [`bert-base-cased`](https://huggingface.co/bert-base-cased)
- [`gpt2`](https://huggingface.co/gpt2)
- [`distilbert`](https://huggingface.co/distilbert-base-uncased)

様々な組織や企業が作成したモデルカードの例も、[こちら](https://github.com/huggingface/model_card/blob/master/examples.md) で確認できます。

## 注意[[note]]

モデルを公開するとき、モデルカードは必須ではありません。また、作成する場合でも、ここで紹介したすべてのセクションを含める必要はありません。但し、モデルについて詳しい説明を残しておけば、あとから利用する人の助けになります。自分が把握していて記載できる範囲で、できるだけ多くのセクションを埋めることをおすすめします。

## モデルカードのメタデータ[[model-card-metadata]]

Hugging Face Hub を少し探索したことがあれば、モデルが特定のカテゴリに属していることに気づいたはずです。タスク、言語、ライブラリなどで絞り込むことができます。モデルが属するカテゴリは、モデルカードのヘッダーに加えるメタデータに基づいて判定されます。

たとえば、[`camembert-base` のモデルカード](https://huggingface.co/camembert-base/blob/main/README.md) のヘッダーには、次のような行があります。

```
---
language: fr
license: mit
datasets:
- oscar
---
```

Hugging Face Hub はこのメタデータを読み取り、フランス語に対応し、MIT ライセンスで提供され、Oscar データセットで学習されたモデルだと判別します。

[モデルカードの完全な仕様](https://github.com/huggingface/hub-docs/blame/main/modelcard.md) に従って、言語、ライセンス、タグ、データセット、評価指標に加え、学習中に得られた評価結果も指定できます。
