Transformer はどのように動作するのか？

このセクションでは、Transformer モデルのアーキテクチャを見ていきます。アテンションやエンコーダ・デコーダアーキテクチャといった概念も、更に掘り下げます。

⚠️ 注意

🚀 ここからは、一段階レベルが上がります。このセクションは詳しくて専門的なので、最初から全て理解出来なくても心配いりません。これらの概念は、コースの中で改めて扱います。

Transformer の簡単な歴史

Transformer モデルの（短い）歴史から、いくつかの節目を紹介します。

Transformer アーキテクチャは、2017年6月に発表されました。元の研究の焦点は翻訳タスクでした。その後、影響力の大きなモデルが幾つも登場しました。例えば、次のモデルです。

  • 2018年6月：GPT。最初の事前学習済み Transformer モデルで、様々な NLP タスクへのファインチューニングに使われ、最先端の結果を得ました

  • 2018年10月：BERT。こちらも大規模な事前学習済みモデルで、文をより良く要約出来るよう設計されました（詳しくは次の章で扱います）

  • 2019年2月：GPT-2。GPT を改良し、大型化したバージョンです。倫理的な懸念の為、当初は直ぐには公開されませんでした

  • 2019年10月：T5。sequence-to-sequence 型 Transformer アーキテクチャを、マルチタスクに焦点を当てて実装したものです

  • 2020年5月：GPT-3。GPT-2 を更に大型化したバージョンで、ファインチューニングをしなくても様々なタスクを上手くこなせます（zero-shot learning：ゼロショット学習と呼ばれます）

  • 2022年1月：InstructGPT。指示により良く従えるよう学習された、GPT-3 のバージョンです

  • 2023年1月：Llama。様々な言語でテキストを生成出来る大規模言語モデルです

  • 2023年3月：Mistral。70億パラメータの言語モデルで、評価された全てのベンチマークで Llama 2 13B を上回ります。推論を高速化する grouped-query attention と、任意の長さのシーケンスを扱うスライディングウィンドウ・アテンションを活用しています

  • 2024年5月：Gemma 2。パラメータ数が 2B から 27B までの、軽量で最先端のオープンモデルのファミリーです。ローカルアテンションとグローバルアテンションを交互に配置する構成と group-query attention を取り入れ、小さいモデルは知識蒸留で学習されており、2〜3倍大きいモデルに匹敵する性能を発揮します

  • 2024年11月：SmolLM2。最先端の小型言語モデル（1億3500万〜17億パラメータ）で、コンパクトなサイズにもかかわらず優れた性能を発揮し、モバイルデバイスやエッジデバイスに新たな可能性を開きます

このリストは網羅的なものには程遠く、様々な種類の Transformer モデルの一部を挙げたに過ぎません。大まかには、次の3つのカテゴリに分けられます。

  • GPT 系（auto-regressive Transformer モデルとも呼ばれます）
  • BERT 系（auto-encoding Transformer モデルとも呼ばれます）
  • T5 系（sequence-to-sequence Transformer モデルとも呼ばれます）

これらのファミリーについては、後程更に詳しく見ていきます。

Transformer は言語モデル

上で挙げた Transformer モデル（GPT、BERT、T5 など）は、全て 言語モデル として学習されています。つまり、大量の生テキストを使い、自己教師あり学習という方法で学習されているのです。

自己教師あり学習とは、学習の目標がモデルの入力から自動的に計算される学習方法のことです。人間がデータにラベルを付ける必要はありません。

この種のモデルは、学習に使われた言語についての統計的な理解を身に付けますが、特定の実用的なタスクにはあまり役立ちません。その為、汎用の事前学習済みモデルは、転移学習（又は ファインチューニング）と呼ばれる過程を通ります。この過程では、人間が注釈を付けたラベルを使い、教師ありの方法で、モデルを与えられたタスク向けにファインチューニングします。

タスクの例として、前の n 個の単語を読んだ上で、文の次の単語を予測するものが有ります。これは causal language modeling（因果言語モデリング）と呼ばれます。出力が、過去と現在の入力には依存し、未来の入力には依存しない為です。

もう1つの例は masked language modeling（マスク言語モデリング）で、モデルが文中のマスクされた単語を予測します。

Transformer は巨大なモデル

幾つかの例外（DistilBERT など）を除けば、より良い性能を得る為の一般的な戦略は、モデルのサイズを大きくし、事前学習に使うデータの量を増やすことです。

残念ながら、モデルの学習、とりわけ大きなモデルの学習には大量のデータが必要です。その為、時間と計算リソースの両面で、非常に大きなコストが掛かります。次のグラフが示す通り、環境への影響にもつながります。

しかも、このグラフが示しているのは、事前学習の環境負荷を意識的に減らそうとしたチームが率いた、（非常に大きな）モデルのプロジェクトです。最適なハイパーパラメータを得る為に多数の試行を繰り返せば、負荷は更に大きくなります。

研究チームや学生団体、企業がモデルを学習させようとする度に、毎回ゼロから学習していたらどうなるでしょうか。世界全体で、膨大で不必要なコストが発生してしまいます。

だからこそ、言語モデルの共有が最も重要なのです。学習済みの重みを共有し、学習済みの重みの上に構築すれば、コミュニティ全体の計算コストとカーボンフットプリントを下げられます。

ちなみに、自分のモデルの学習によるカーボンフットプリントは、幾つかのツールで評価出来ます。例えば ML CO2 Impact や、🤗 Transformers に統合されている Code Carbon です。詳しくは、学習のフットプリントの推定値を記録した emissions.csv ファイルの生成方法を紹介するブログ記事や、この話題を扱う 🤗 Transformers のドキュメントを参照してください。

転移学習

事前学習 とは、モデルをゼロから学習させることです。重みはランダムに初期化され、事前の知識が無い状態から学習が始まります。

この事前学習は通常、非常に大量のデータで行われます。その為、巨大なデータのコーパスが必要となり、学習には数週間掛かることもあります。

一方、ファインチューニング は、モデルが事前学習を終えた後に行う学習です。ファインチューニングを行うには、まず事前学習済みの言語モデルを用意し、次に、自分のタスクに固有のデータセットで追加の学習を行います。では、何故最終的な用途に合わせて、最初からモデルを学習（スクラッチ）しないのでしょうか。理由は幾つか有ります。

  • 事前学習済みモデルは、ファインチューニング用データセットと幾らか似たデータセットで、既に学習を終えています。その為、ファインチューニングでは、事前学習の間に元のモデルが獲得した知識を活用出来ます（例えば NLP の問題であれば、事前学習済みモデルは、そのタスクで使う言語についての何らかの統計的な理解を持っています）。
  • 事前学習済みモデルは既に大量のデータで学習されている為、ファインチューニングで十分な結果を得るのに必要なデータは、はるかに少なくて済みます。
  • 同じ理由で、良い結果を得るのに必要な時間とリソースも、はるかに少なくて済みます。

例えば、英語で学習された事前学習済みモデルを活用し、arXiv コーパスでファインチューニングすれば、科学・研究分野のモデルが得られます。ファインチューニングに必要なデータは限られた量で済みます。事前学習済みモデルが獲得した知識が「転移」するからです。これが、転移学習 という用語の由来です。

このように、モデルのファインチューニングは、時間、データ、金銭、環境の各面でコストが低くなります。完全な事前学習ほど学習の制約が大きくない為、様々なファインチューニングの方式を繰り返し試す作業も、より速く、より簡単です。

更に、この方法は、ゼロから学習するよりも良い結果をもたらします（大量のデータを持っている場合は別です）。その為、手元のタスクに出来るだけ近い事前学習済みモデルを常に活用し、それをファインチューニングすべきなのです。

Transformer アーキテクチャの全体像

このセクションでは、Transformer モデルの一般的なアーキテクチャを見ていきます。幾つかの概念が理解出来なくても心配いりません。各コンポーネントを扱う詳しいセクションが、後に用意されています。

このモデルは、主に2つのブロックで構成されます。

  • エンコーダ（左）：エンコーダは入力を受け取り、その表現（特徴）を構築します。つまり、このモデルは入力から理解を得るように最適化されています。
  • デコーダ（右）：デコーダは、エンコーダの表現（特徴）とその他の入力を使い、ターゲットとなるシーケンスを生成します。つまり、このモデルは出力を生成するように最適化されています。

これらの部分は、タスクに応じて、それぞれ独立して使うことが出来ます。

  • エンコーダのみのモデル：文分類や固有表現認識など、入力の理解が必要なタスクに向いています。
  • デコーダのみのモデル：テキスト生成などの生成タスクに向いています。
  • エンコーダ・デコーダモデル、又は sequence-to-sequence モデル：翻訳や要約など、入力を必要とする生成タスクに向いています。

これらのアーキテクチャについては、後のセクションでそれぞれ独立に掘り下げていきます。

アテンション層

Transformer モデルの重要な特徴は、アテンション層 と呼ばれる特殊な層を使って構築されていることです。実際、Transformer アーキテクチャを提案した論文のタイトルは「Attention Is All You Need」でした。アテンション層の詳細は、コースの後半で探っていきます。ここでは、この層が、各単語の表現を扱う際に、渡された文の中の特定の単語へ特に注意を向けさせ（それ以外への注意は多少弱めさせ）るものだ、と押さえておけば十分です。

文脈を掴む為に、英語からフランス語への翻訳というタスクを考えてみましょう。入力が "You like this course" の場合、単語 "like" の適切な訳を得るには、翻訳モデルは隣の単語 "You" にも注意を払う必要があります。フランス語では、動詞 "like" の活用が主語によって異なる為です。但し、文の残りの部分は、その単語の翻訳には役立ちません。同様に、"this" を翻訳する際にも、モデルは単語 "course" に注意を払う必要があります。"this" の訳は、対応する名詞が男性名詞か女性名詞かによって異なる為です。繰り返しますが、文中の他の単語は "course" の翻訳には関係しません。もっと複雑な文（そして、もっと複雑な文法規則）では、各単語を適切に翻訳する為に、モデルは文の中で遠く離れた位置に現れる単語にも、特に注意を払う必要が有るでしょう。

同じ概念は、自然言語に関わるあらゆるタスクに当てはまります。単語はそれ自体で意味を持ちますが、その意味は文脈によって深く影響されます。文脈とは、注目している単語の前後に有る、別の単語（又は単語のまとまり）のことです。

アテンション層とは何かが見えてきた所で、Transformer アーキテクチャを更に詳しく見ていきましょう。

オリジナルのアーキテクチャ

Transformer アーキテクチャは、元々翻訳の為に設計されました。学習の間、エンコーダは或る言語の入力（文）を受け取り、デコーダは同じ文を、望むターゲット言語で受け取ります。エンコーダでは、アテンション層は文中の全ての単語を使うことが出来ます（先程見たように、或る単語の翻訳は、文中でその単語より前に有るものだけでなく、後に有るものにも依存し得る為です）。一方、デコーダは逐次的に動作し、既に翻訳した単語（つまり、現在生成している単語より前に有る単語だけ）にしか注意を払えません。例えば、翻訳されたターゲットの最初の3単語を予測したら、それらをデコーダに渡します。デコーダは、エンコーダの入力を全て使い、4番目の単語を予測しようとします。

学習を高速化する為（モデルがターゲット文にアクセス出来る場合）、デコーダにはターゲット全体が与えられますが、未来の単語を使うことは許可されません（2番目の位置の単語を予測しようとする時に、その位置の単語自体にアクセス出来てしまえば、課題は全く難しくなくなってしまいます）。例えば、4番目の単語を予測しようとする時、アテンション層がアクセス出来るのは、位置1から3までの単語だけです。

オリジナルの Transformer アーキテクチャは、左にエンコーダ、右にデコーダを置いた、次のようなものでした。

デコーダブロックの1つ目のアテンション層は、デコーダへの（過去の）入力の全てに注意を払いますが、2つ目のアテンション層はエンコーダの出力を使います。その為、現在の単語を最も良く予測する為に、入力文全体へアクセス出来ます。これは非常に便利です。言語が異なれば、文法規則によって単語の置かれる順序も異なりますし、文の後方で与えられる文脈が、或る単語の最適な翻訳を決める助けになることも有る為です。

アテンションマスク は、モデルが一部の特殊な単語に注意を払わないようにする為に、エンコーダやデコーダで使うことも出来ます。例えば、文をまとめてバッチ処理する際に、全ての入力の長さを同じにする為に使われる、特殊なパディング単語です。

アーキテクチャとチェックポイント

このコースで Transformer モデルを掘り下げていくと、アーキテクチャ と チェックポイント、そして モデル という用語が登場します。これらの用語は、いずれも少しずつ意味が異なります。

  • アーキテクチャ：モデルの骨格、即ち、モデル内の各層と、各層の中で行われる各演算の定義です。
  • チェックポイント：或るアーキテクチャに読み込まれる重みのことです。
  • モデル：「アーキテクチャ」や「チェックポイント」ほど正確ではない総称で、どちらの意味にもなり得ます。このコースでは、曖昧さを減らす為、重要になる場面では アーキテクチャ 又は チェックポイント と明示します。

例えば、BERT はアーキテクチャであり、bert-base-cased は、BERT の最初のリリースの際に Google のチームによって学習された重みの集合、つまりチェックポイントです。もっとも、「BERT モデル」と言ったり、「bert-base-cased モデル」と言ったりもします。
