教師ありファインチューニング

教師ありファインチューニング（SFT）は、事前学習済みの言語モデルを、指示に従い、対話し、決まった形式で出力出来るモデルへと仕上げる為の手法です。事前学習済みモデルには既に高い汎用能力がありますが、SFT を施すと、ユーザーのプロンプトの意図を汲んで応答する、アシスタント型のモデルになります。学習には通常、人間が書いた会話や指示を集めたデータセットを使います。

このページでは、SFTTrainer を使って deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B モデルをファインチューニングする手順を、順を追って解説します。手順どおりに進めれば、モデルを特定のタスクにより適した形へ調整出来ます。

SFT を使うべき場面

実装に入る前に、SFT が自分のプロジェクトに合った手法かどうかを見極めておくことが大切です。まず検討すべきなのは、既存の指示チューニング済みモデルに、工夫したプロンプトを与えるだけで目的を達成出来ないかという点です。SFT には相応の計算リソースと実装の手間が掛かります。既存のモデルへのプロンプトでは不十分だと分かった場合に限って、取り組むべき手法です。

💡 ヒント

SFT を検討するのは次のような場合だけにしましょう： - プロンプトの工夫だけでは達成出来ない性能が必要 - 大規模な汎用モデルを使うコストが、小規模なモデルをファインチューニングするコストを上回る具体的な用途が有る - 既存のモデルが苦手とする、特殊な出力形式やドメイン固有の知識が必要

SFT が必要だと判断したら、進めるかどうかは主に次の2つの要素で決まります。

テンプレートの制御

SFT を使うと、モデルの出力構造を細部まで制御出来ます。次のような応答をモデルに求める場合に、特に有効です。

  1. 特定のチャットテンプレート形式で応答を生成する
  2. 厳密な出力スキーマに従う
  3. 応答全体で一貫したスタイルを保つ

ドメインへの適応

専門的なドメインで作業する場合、SFT によって、モデルをドメイン固有の要件に沿うよう調整出来ます。例えば、次のような点です。

  1. ドメインの専門用語や概念を教える
  2. 専門職としての基準を守らせる
  3. 技術的な問い合わせに適切に対応させる
  4. 業界固有のガイドラインに従わせる

💡 ヒント

SFT を始める前に、そのユースケースが次を必要とするか評価してください： - 精密な出力形式 - ドメイン固有の知識 - 一貫した応答パターン - 特定のガイドラインへの準拠

この評価により、SFT が自分のニーズに合ったアプローチかどうかを判断出来ます。

データセットの準備

教師ありファインチューニングには、タスクに合わせたデータセットが必要です。データセットは、入力と出力のペアで構成します。各ペアには、次の要素を含めます。

  1. 入力プロンプト
  2. 期待されるモデルの応答
  3. 追加の文脈やメタデータ

学習データの品質は、ファインチューニングを成功させる上で極めて重要です。データセットの準備と検証の方法を見てみましょう。

学習の設定

ファインチューニングの成功は、適切な学習パラメータの選択に大きく依存します。重要なパラメータと、それらを効果的に設定する方法を見ていきましょう。

SFTTrainer の設定では、学習の進め方を制御するパラメータを幾つか決める必要があります。以下では、各パラメータの役割を順に見ていきます。

  1. 学習時間のパラメータ： - num_train_epochs：学習全体の時間を制御する - max_steps：エポックの代替で、学習ステップの最大数を設定する - エポック数が多い程学習は進むが、過学習のリスクが有る

  2. バッチサイズのパラメータ： - per_device_train_batch_size：メモリ使用量と学習の安定性を左右する - gradient_accumulation_steps：実効的なバッチサイズを大きく出来る - バッチが大きい程勾配が安定するが、より多くのメモリを必要とする

  3. 学習率のパラメータ： - learning_rate：重みの更新の大きさを制御する - warmup_ratio：学習率のウォームアップに使う学習の割合 - 高過ぎると不安定になり、低過ぎると学習が遅くなる

  4. モニタリングのパラメータ： - logging_steps：メトリクスの記録頻度 - eval_steps：検証データで評価する頻度 - save_steps：モデルのチェックポイントを保存する頻度

💡 ヒント

控えめな値から始めて、モニタリングしながら調整しましょう： - まずは 1〜3 エポックから始める - 最初は小さめのバッチサイズを使う - 検証メトリクスを注意深く監視する - 学習が不安定なら学習率を調整する

TRL での実装

主要な要素を押さえた所で、検証とモニタリングの仕組みを備えた学習を実装してみましょう。使うのは、transformers ライブラリの上に構築された Transformers Reinforcement Learning（TRL）ライブラリの SFTTrainer クラスです。以下に、TRL を使った一通りの実装例を示します。

from datasets import load_dataset
from trl import SFTConfig, SFTTrainer
import torch

# デバイスを設定
device = "cuda" if torch.cuda.is_available() else "cpu"

# データセットを読み込む
dataset = load_dataset("HuggingFaceTB/smoltalk", "all")

# モデルとトークナイザを設定
model_name = "HuggingFaceTB/SmolLM2-135M"
model = AutoModelForCausalLM.from_pretrained(pretrained_model_name_or_path=model_name).to(
    device
)
tokenizer = AutoTokenizer.from_pretrained(pretrained_model_name_or_path=model_name)
# チャットテンプレートをセットアップ
model, tokenizer = setup_chat_format(model=model, tokenizer=tokenizer)

# トレーナーを設定
training_args = SFTConfig(
    output_dir="./sft_output",
    max_steps=1000,
    per_device_train_batch_size=4,
    learning_rate=5e-5,
    logging_steps=10,
    save_steps=100,
    eval_strategy="steps",
    eval_steps=50,
)

# トレーナーを初期化
trainer = SFTTrainer(
    model=model,
    args=training_args,
    train_dataset=dataset["train"],
    eval_dataset=dataset["test"],
    processing_class=tokenizer,
)

# 学習を開始
trainer.train()

💡 ヒント

上の例のように "messages" フィールドを持つデータセットを使う場合、SFTTrainer はモデルのチャットテンプレートを自動で適用します。テンプレートは Hub から取得される為、チャット形式の会話を扱う為の追加設定は要りません。メッセージは、モデルが想定するテンプレート形式に合わせてトレーナーが整形します。

データセットのパッキング

SFTTrainer は、学習効率を高める為のサンプルのパッキング（example packing）に対応しています。パッキングとは、複数の短いサンプルを同じ入力シーケンスに詰め込む仕組みです。これにより、学習中の GPU 使用率を高く保てます。有効にするには、SFTConfig のコンストラクタで packing=True を設定します。

パッキングしたデータセットを max_steps と併用する場合は注意が必要です。パッキングの設定次第では、想定より多くのエポックを学習することになります。サンプルをどう組み合わせるかは、整形用関数（formatting function）でカスタマイズ出来ます。質疑応答ペアのように複数のフィールドを持つデータセットでは、特に便利です。

評価用データセットでは、SFTConfig で eval_packing=False を設定すればパッキングを無効に出来ます。パッキング設定をカスタマイズする基本的な例を、以下に示します。

# パッキングを設定
training_args = SFTConfig(packing=True)

trainer = SFTTrainer(model=model, train_dataset=dataset, args=training_args)

trainer.train()

複数のフィールドを持つデータセットをパッキングする場合は、カスタムの整形用関数を定義し、フィールド同士を1つの入力シーケンスに組み合わせます。この関数はサンプルのリストを受け取り、パッキング済みの入力シーケンスを持つ辞書を返す想定です。カスタム整形用関数の例を、以下に示します。

def formatting_func(example):
    text = f"### Question: {example['question']}\n ### Answer: {example['answer']}"
    return text


training_args = SFTConfig(packing=True)
trainer = SFTTrainer(
    "facebook/opt-350m",
    train_dataset=dataset,
    args=training_args,
    formatting_func=formatting_func,
)

（テンプレートの訳：「### 質問：（質問文）／### 回答：（回答文）」という形式のテキストを作ります）

学習状況のモニタリング

効果的なモニタリングは、ファインチューニングを成功させる上で極めて重要です。学習中に何に注目すべきかを見ていきましょう。

損失パターンの理解

学習損失は通常、次の3つの明確なフェーズをたどります。

  1. 初期の急激な低下：新しいデータ分布への急速な適応
  2. 緩やかな安定化：モデルのファインチューニングが進むにつれて学習速度が緩やかになる
  3. 収束：損失の値が安定し、学習の完了を示す

監視すべきメトリクス

効果的なモニタリングでは、定量的な指標を追跡し、あわせて定性的な観点からも評価します。利用出来るメトリクスは次の通りです。

  • 学習損失
  • 検証損失
  • 学習率の推移
  • 勾配ノルム

⚠️ 注意

学習中は次の警告サインに注意してください： 1. 学習損失が下がり続けるのに検証損失が上がる（過学習） 2. 損失の値に大きな改善が見られない（学習不足） 3. 損失の値が極端に低い（暗記している可能性） 4. 出力形式が一貫しない（テンプレートの学習に問題）

収束への道のり

学習が進むにつれて、損失曲線は徐々に安定していきます。健全に学習出来ているかどうかは、学習損失と検証損失の差が小さいかどうかで判断出来ます。差が小さいということは、モデルが特定のサンプルを暗記しているのではなく、汎化出来るパターンを学習している証拠です。なお、損失の絶対値はタスクやデータセットによって異なります。

学習状況のモニタリング

上のグラフは、典型的な学習の推移を示したものです。学習損失と検証損失は、どちらも最初は急激に下がり、その後徐々に落ち着いていきます。このパターンは、モデルが汎化能力を保ちながら効果的に学習出来ていることを示します。

注意すべき警告サイン

損失曲線に現れるパターンの中には、問題の兆候を示すものがあります。以下では、よくある警告サインと、検討出来る対処法を紹介します。

検証損失の下がり方が学習損失より著しく遅い場合、モデルは学習データに過学習している可能性が高いと考えられます。次の対処を検討してください。

  • 学習ステップを減らす
  • データセットのサイズを増やす
  • データセットの品質と多様性を検証する

損失に大きな改善が見られない場合、モデルは次の状態かもしれません。

  • 学習が遅過ぎる（学習率を上げてみる）
  • タスクに苦戦している（データの品質とタスクの複雑さを確認する）
  • アーキテクチャの限界に当たっている（別のモデルを検討する）

損失の値が極端に低い場合は、学習ではなく暗記を示している可能性があります。特に次の場合は懸念されます。

  • 新しい類似のサンプルに対する性能が悪い
  • 出力に多様性が無い
  • 応答が学習サンプルに似過ぎている

⚠️ 注意

学習中は、損失の値とモデルの実際の出力の両方を監視してください。損失が良好に見えても、モデルに望ましくない振る舞いが生まれることがあります。モデルの応答を定期的に定性評価することで、メトリクスだけでは見逃しがちな問題を捉えられます。

なお、ここで述べた損失の値の解釈は、最も一般的なケースを想定したものです。実際には、損失の値はモデルやデータセット、学習パラメータなどによって様々な振る舞いを見せます。ここで挙げたパターンについて詳しく知りたい場合は、Fast AI のブログ記事も参考にしてください。

SFT 後の評価

セクション 11.4 では、ベンチマークデータセットを使ってモデルを評価する方法を学びます。本節では、モデルの定性評価に焦点を当てます。

SFT が完了したら、次の作業を検討してください。

  1. ホールドアウトしたテストデータでモデルを十分に評価する
  2. 様々な入力でテンプレートへの準拠を検証する
  3. ドメイン固有の知識が保持されているかをテストする
  4. 実際の利用場面での性能メトリクスを監視する

学習プロセスを文書化してください。含めるべき項目： - データセットの特徴 - 学習パラメータ - 性能メトリクス - 既知の制限事項 このドキュメントは、今後モデルを改良する際に役立ちます。

クイズ

1. SFT で学習時間を制御するパラメータはどれですか？

正解です！これらのパラメータは、エポック数又は総ステップ数によって、モデルがどれだけ長く学習するかを決めます。
これらは学習に影響しますが、学習時間を直接制御するものではありません。
これらのパラメータは学習の効率と安定性に影響するもので、時間ではありません。

2. 損失曲線のどのパターンが過学習の可能性を示しますか？

正解です！学習損失と検証損失のこの乖離は、過学習の典型的なサインです。
このパターンは実際には健全な学習を示します。
これは珍しいパターンであり、過学習を示すものではありません。

3. gradient_accumulation_steps は何に使われますか？

正解です！複数の順伝播にわたって勾配を累積してから重みを更新します。
これは save_steps と save_strategy パラメータが担います。
学習率のスケジュールは learning_rate と warmup_ratio で制御します。

4. SFT の学習中に監視すべきなのは何ですか？

正解です！両方の種類のメトリクスを監視することで、潜在的な問題を全て捉えられます。
学習損失だけでは、モデルの良好な振る舞いを保証するには不十分です。
重要ではありますが、定性評価だけでは学習の重要な動きを見逃してしまいます。

5. 学習中の健全な収束を示すのは何ですか？

正解です！これは、モデルが汎化出来るパターンを学習していることを示します。
損失の値が極端に低い場合は、学習ではなく暗記を示している可能性があります。
これは珍しいことであり、検証セットに問題が有る可能性を示します。

💐 お疲れさまでした

SFT を使ったモデルのファインチューニングの方法を学びました。学習を続けるには：

  1. ノートブックでパラメータを変えて試してみましょう
  2. 他のデータセットでも実験してみましょう
  3. コース教材の改善に貢献しましょう
