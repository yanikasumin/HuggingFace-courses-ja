はじめに

第1章 で見たように、Transformer モデルは通常とても大きなモデルです。パラメータ数は数百万から数百億にものぼり、これらのモデルを学習・デプロイするには、多くの手間が掛かります。更に、新しいモデルがほぼ毎日のように公開され、それぞれ実装も異なる為、全てを試してみるのは簡単なことではありません。

🤗 Transformers ライブラリは、この問題を解決する為に作られました。その目標は、あらゆる Transformer モデルを読み込み、学習し、保存出来る単一の API を提供することです。ライブラリの主な特徴は次の通りです。

  • 使いやすさ：最先端の NLP モデルをダウンロードして読み込み、推論に使うまでが、わずか2行のコードで済みます。
  • 柔軟性：全てのモデルは本質的にシンプルな PyTorch の nn.Module クラスであり、それぞれの機械学習（ML）フレームワークにおける他のモデルと同じように扱えます。
  • シンプルさ：ライブラリ全体を通して、抽象化は殆ど行われていません。「All in one file（全て1つのファイルに）」が核となる考え方で、モデルのフォワードパスは1つのファイルの中に完全に定義されます。その為、コード自体が理解し易く、改変もし易くなっています。

この最後の特徴により、Transformers は他の ML ライブラリとはかなり異なります。モデルはファイル間で共有されるモジュールを組み合わせて構築されるのではなく、各モデルが独自の層を持っています。モデルが扱い易く理解し易くなるだけでなく、他のモデルに影響を与えずに、1つのモデルで簡単に実験出来ます。

この章ではまず、モデルとトークナイザを組み合わせて、第1章 で紹介した pipeline() 関数の処理を最初から最後まで再現する例を見ていきます。次にモデル API を取り上げます。モデルクラスと設定クラスを詳しく見て、モデルの読み込み方と、モデルが数値入力を処理して予測を出力する仕組みを紹介します。

続いて、pipeline() 関数のもう1つの主要な構成要素であるトークナイザ API を見ていきます。トークナイザは処理の最初と最後を担います。テキストをニューラルネットワークが扱える数値に変換し、必要に応じて、その数値をテキストに戻します。

最後に、複数の文をまとめたバッチをモデルに送る方法を紹介し、高レベルな tokenizer() 関数を詳しく見て締めくくります。
