Module 3：Slack 通知

コミュニケーションの溝の危機

CodeCraft Studios での3週目。あなたの自動化システムは、既にチームの働き方を変えつつあります。

  • PR Agent（Module 1）：開発者が明確で役立つプルリクエストの説明を書くようになった
  • CI/CD Monitor（Module 2）：チームがテストの失敗を即座に捕え、バグが本番環境に到達するのを防いでいる

チームはすっかり自信をつけていました…月曜の朝、新たな危機が訪れるまでは。

フロントエンドチーム（Emma と Jake）は、厄介な API 連携の問題のデバッグに週末を丸ごと費やしました。ネットワーク呼び出しの確認、リクエスト形式の検証、エラーハンドリングの書き直しまで、あらゆることを試しました。

そして日曜の午前2時、ついに原因が判明します。バックエンドチームが金曜日にまさにこの問題を修正し、修正したコードをステージング環境にデプロイしていたのに、そのことを知らせるのを忘れていたのです。

「既に修正済みの問題の解決に12時間も無駄にした！」Emma は苛立って言います。

一方、デザインチームは先週、新しいユーザーオンボーディングフローのイラストを完成させていましたが、フロントエンドチームは準備が出来ていることを知りませんでした。その美しいアセットは使われないまま置かれ、チームは暫定的なデザインをリリースしています。

チームは、情報のサイロ問題を抱えていることに気づきます。全員が一生懸命働いているのに、いつ何が起きているのかを効果的に伝え合えていないのです。

あなたのミッション：重要な進展をチーム全員に自動で知らせる、インテリジェントな Slack 通知で自動化システムを完成させることです。

構築するもの

この最終モジュールで、CodeCraft Studios の変革が完結します。Tools と Prompts を組み合わせ、CI/CD イベントの情報を整理して Slack に送信する通知システムを作成します。これを通して、実際の開発現場で MCP の全てのプリミティブがどのように連携するかを学びます。

Module 1 と Module 2 の基盤の上に、パズルの最後のピースを追加します。

  • チームチャンネルへメッセージを送る Slack webhook ツール
  • CI イベントを賢く整形する2つの通知プロンプト
  • 全 MCP プリミティブの連携を示す完全な統合

スクリーンキャスト：完全な自動化システム！

最後のピース：完成した自動化システムが、Emma と Jake を悩ませたような月曜朝の突然のトラブルをどう防ぐかをご覧ください！

見どころ：

  • Claude のインテリジェントなワークフロー：Claude がタスクを分解する様子に注目： ☐ イベントを確認 → ☐ 通知を送信
  • リアルタイム MCP ツールの実演：get_recent_actions_events が最新の CI データを取得し、send_slack_notification がアラートを送信する
  • 並行デモンストレーション：Slack チャンネルを並べて開き、Claude が送信した整形済みメッセージが表示される様子を示す

スマートな通知：Claude はチームに通知をむやみに送りつけるのではなく、必要な情報を整理した分かり易いアラートを作成します。

  • 🚨 明確な緊急性の指標と絵文字
  • 失敗の詳細な内訳（test-auth-service ❌、test-api ❌、test-frontend ⏳）
  • パイプラインの実行とプルリクエストへの実用的なリンク
  • 全員が必要とする文脈：リポジトリ、PR #1「various improvements」、コミットハッシュ

何故重要か：コミュニケーションの溝の危機を覚えていますか？もう終わりです！このシステムにより、demo-bad-pr ブランチで CI が失敗すれば、チーム全員が即座に知ることが出来ます。修正済みの問題に対する週末のデバッグ作業は、もうありません！

取り組みの完了：Module 1 で取り組んだ PR の混乱から、Module 3 のスマートなチーム通知まで、CodeCraft Studios のチームワークを変えるシステムを構築しました。週末まで問題対応に追われていたメンバーも、これからは必要な情報を共有しながら仕事を進められます。

学習目標

このモジュールの終わりには、以下を理解出来るようになります。

  1. MCP Tools を使って外部 API と連携する方法
  2. 完全なワークフローの為に Tools と Prompts を組み合わせる方法
  3. Slack の Markdown 書式を使って、装飾付きのメッセージを作成する方法
  4. 全 MCP プリミティブが実際にどう連携するか

前提条件

これまでのモジュールの全てに加えて、以下が必要です。

  • Module 1 と Module 2 の完了：このモジュールは既存の MCP サーバーを直接拡張します
  • Slack ワークスペース：着信 webhook を作成出来るもの（個人のワークスペースで可）
  • REST API の基本的な理解：Slack の webhook エンドポイントへ HTTP リクエストを送信します

主要概念

MCP 連携パターン

このモジュールでは、完全なワークフローを示します。

  1. Events → GitHub Actions の webhook（Module 2 より）
  2. Prompts → イベントを読み易いメッセージに整形する
  3. Tools → 整形したメッセージを Slack へ送信する
  4. Result → プロフェッショナルなチーム通知

Slack の Markdown 書式

装飾付きのメッセージを作るには、Slack の Markdown 書式を使います。

  • 強調には *bold text*
  • 詳細には _italic text_
  • 技術情報には `code blocks`
  • 要約には > quoted text
  • 絵文字：✅ ❌ 🚀 ⚠️
  • リンク： <https://github.com/user/repo|Repository>

実装ステップ

ステップ1：Slack 連携のセットアップ（10分）

  1. Slack の webhook を作成する： - Slack API Apps にアクセスする - 新しいアプリを作成し、「From scratch」（最初から作成）を選ぶ（アプリ作成ガイド） - アプリ名：「MCP Course Notifications」 - ワークスペースを選ぶ - 「Features（機能）」→「Incoming Webhooks（着信 Webhook）」へ進む - 着信 webhook を有効化する - 「Add New Webhook to Workspace」（ワークスペースに新しい Webhook を追加）をクリックする - チャンネルを選んで承認する（Webhook セットアップガイド） - webhook URL をコピーする

  2. webhook が動作するかテストする（webhook 投稿の例 に従う）： bash curl -X POST -H 'Content-type: application/json' \ --data '{"text":"Hello from MCP Course!"}' \ YOUR_WEBHOOK_URL

  3. 環境変数を設定する： bash export SLACK_WEBHOOK_URL="https://hooks.slack.com/services/YOUR/WEBHOOK/URL"

⚠️ セキュリティに関する注意：webhook URL は、Slack チャンネルへのメッセージ投稿権限を与える機密情報です。必ず次のようにしてください。

  • 環境変数として保存し、コードにハードコードしない
  • webhook URL をバージョン管理にコミットしない（.gitignore に追加する）
  • パスワードと同じように厳重に扱う。この URL を知る人は誰でもチャンネルにメッセージを送信出来る

⚠️ 注意

セキュリティ警告：webhook URL は機密性の高い認証情報です！webhook URL を知る人は誰でも、あなたの Slack チャンネルにメッセージを送信出来ます。必ず環境変数として保存し、バージョン管理には決してコミットしないでください。

ステップ3：整形プロンプトを作成する（15分）

次に、サーバーへ MCP Prompts を追加します。ここからが重要な部分です。これらのプロンプトを Claude と組み合わせることで、GitHub の webhook データを、情報が整理された Slack メッセージに自動で変換出来ます。

Module 1 で学んだように、Prompts は Claude が一貫して使える再利用可能な指示を提供します。

Slack 形式のメッセージを生成する、2つのプロンプトを実装します。

  1. format_ci_failure_alert： ```python @mcp.prompt() def format_ci_failure_alert() -> str: """Create a Slack alert for CI/CD failures.""" return """Format this GitHub Actions failure as a Slack message:

Use this template: :rotating_light: CI Failure Alert :rotating_light:

A CI workflow has failed: Workflow: workflow_name Branch: branch_name Status: Failed View Details:

Please check the logs and address any issues.

Use Slack markdown formatting and keep it concise for quick team scanning.""" ```

  1. format_ci_success_summary： ```python @mcp.prompt() def format_ci_success_summary() -> str: """Create a Slack message celebrating successful deployments.""" return """Format this successful GitHub Actions run as a Slack message:

Use this template: :white_check_mark: Deployment Successful :white_check_mark:

Deployment completed successfully for [Repository Name]

Changes: - Key feature or fix 1 - Key feature or fix 2

Links:

Keep it celebratory but informative. Use Slack markdown formatting.""" ```

ステップ5：連携を確認する（5分）

実際の GitHub リポジトリをセットアップしなくても、実装をテスト出来ます。GitHub の webhook イベントをシミュレートする curl コマンドは manual_test.md を見てください。

webhook イベントの流れの理解：

  • webhook サーバー（Module 2 より）が GitHub イベントを捕捉し、github_events.json に保存する
  • MCP ツールがこのファイルから最近の CI/CD アクティビティを取得する
  • Claude が整形プロンプトを使って読み易いメッセージを作成する
  • Slack ツールが整形済みメッセージをチームチャンネルへ送信する
  • これにより、次の一連の処理が完成します：GitHub → ローカルストレージ → Claude の分析 → Slack 通知

クイックテストのワークフロー：

  1. curl でテスト用の模擬 GitHub イベントを webhook サーバーへ送信する
  2. Claude に最近のイベントの確認と整形を依頼する
  3. 整形済みメッセージを Slack へ送信する
  4. 全てがエンドツーエンドで動作することを確認する

手動テストの代替手段： GitHub をセットアップせずに一連の動作を全てテストしたい場合は、manual_test.md に記載された curl コマンドを順番に実行してください。

よくある問題

Webhook URL の問題

  • 環境変数が正しく設定されているか確認する
  • 連携前に、curl で webhook を直接テストする
  • Slack アプリに適切な権限が有るか確認する

メッセージの書式

  • Slack の Markdown は GitHub の Markdown とは異なる
  • 重要：太字には *text* を使う（**text** ではない）
  • 適切な書式の為、webhook ペイロードに "mrkdwn": true を含める
  • 自動化の前に、メッセージの書式を手動でテストする
  • コミットメッセージ内の特殊文字を適切に処理する（書式リファレンス）

ネットワークエラー

  • webhook リクエストに基本的なタイムアウト処理を追加する（webhook のエラーハンドリング）
  • ツールから意味の有るエラーメッセージを返す
  • リクエストが失敗する場合はインターネット接続を確認する
