Transformer のアーキテクチャ

前のセクションでは、Transformer の全体的なアーキテクチャを紹介し、これらのモデルが様々なタスクをどう解くのかを見てきました。ここでは、Transformer モデルの3つの主要なアーキテクチャのバリエーションを詳しく見て、それぞれをいつ使うべきかを理解しましょう。その上で、それらのアーキテクチャが様々な言語タスクにどう応用されるかを見ていきます。

このセクションでは、Transformer モデルの3つの主要なアーキテクチャのバリエーションを更に掘り下げ、それぞれをいつ使うべきかを理解していきます。

💡 ヒント

殆どの Transformer モデルは、エンコーダのみ、デコーダのみ、エンコーダ・デコーダ（シーケンス・ツー・シーケンス）という3つのアーキテクチャのいずれかを使っていることを思い出してください。これらの違いを理解すると、自分のタスクに合ったモデルを選べるようになります。

エンコーダモデル

エンコーダモデルは、Transformer モデルのエンコーダだけを使うモデルです。各ステージで、アテンション層は入力文の全ての単語にアクセス出来ます。これらのモデルは「双方向」のアテンションを持つとよく説明され、オートエンコーディングモデルとも呼ばれます。

これらのモデルの事前学習は、通常、与えられた文を何らかの形で加工し（例えばランダムな単語をマスクするなど）、元の文を見つけたり再構成したりするタスクをモデルに課す、という形で行われます。

エンコーダモデルは、文全体の理解が必要なタスクに最も向いています。例えば、文の分類、固有表現抽出（より一般的には単語の分類）、抽出型質問応答などです。

💡 ヒント

🤗 Transformers がタスクを解く仕組みで見たように、BERT のようなエンコーダモデルは、文脈全体を両方向から見ることが出来る為、テキストの理解に優れています。その為、入力全体の理解が重要なタスクに最適です。

この系統の代表的なモデルには次のものがあります。

  • BERT
  • DistilBERT
  • ModernBERT

デコーダモデル

デコーダモデルは、Transformer モデルのデコーダだけを使うモデルです。各ステージで、アテンション層は、或る単語について、その単語より前に位置する単語にしかアクセス出来ません。これらのモデルは自己回帰モデルとよく呼ばれます。

デコーダモデルの事前学習は、通常、文の次の単語を予測することを中心に行われます。

これらのモデルは、テキスト生成を伴うタスクに最も向いています。

💡 ヒント

GPT のようなデコーダモデルは、トークンを1つずつ予測してテキストを生成するよう設計されています。Transformers がタスクを解く仕組みで見たように、デコーダモデルは前のトークンしか見ることができません。その為、創造的なテキスト生成には優れていますが、双方向の理解が必要なタスクにはあまり向いていません。

この系統の代表的なモデルには次のものがあります。

  • Hugging Face の SmolLM シリーズ
  • Meta の Llama シリーズ
  • Google の Gemma シリーズ
  • DeepSeek V3

現代の大規模言語モデル（LLM）

現代の大規模言語モデル（LLM）の殆どは、デコーダのみのアーキテクチャを採用しています。これらのモデルは過去数年で規模と能力が劇的に拡大し、最大級のモデルは数千億のパラメータを持っています。

現代の LLM は通常、2つのフェーズで学習されます。 1. 事前学習：膨大なテキストデータで、次のトークンを予測することを学習する 2. インストラクションチューニング：指示に従い、役に立つ応答を生成出来るようにファインチューニングする

このアプローチによって、幅広いトピックやタスクにわたって、人間のようなテキストを理解し生成出来るモデルが生まれました。

現代の LLM の主な能力

現代のデコーダベースの LLM は、印象的な能力を示してきました。

能力 説明 例
テキスト生成 一貫性があり文脈に合ったテキストを作成する エッセイ、物語、メールを書く
要約 長い文書を短く凝縮する レポートのエグゼクティブサマリーを作成する
翻訳 テキストを別の言語に変換する 英語をスペイン語に翻訳する
質問応答 事実に関する質問に答える 「フランスの首都はどこですか？」
コード生成 コードスニペットを書いたり補完したりする 説明に基づいて関数を作成する
推論 問題を段階的に解いていく 数学の問題や論理パズルを解く
Few-shot 学習 プロンプト内の少数の例から学習する 2〜3個の例を見ただけでテキストを分類する

デコーダベースの LLM は、Hub のモデルリポジトリのページから、ブラウザ上で直接試すことが出来ます。例として、定番の GPT-2（OpenAI の最高のオープンソースモデル！）を見てみましょう。

シーケンス・ツー・シーケンスモデル

エンコーダ・デコーダモデル（シーケンス・ツー・シーケンスモデルとも呼ばれます）は、Transformer アーキテクチャの両方の部分を使います。各ステージで、エンコーダのアテンション層は入力文の全ての単語にアクセス出来る一方、デコーダのアテンション層は、入力中の或る単語より前に位置する単語にしかアクセス出来ません。

これらのモデルの事前学習には様々な方法があります。よく使われるのは、単語をランダムにマスクするなどして加工した文を与え、元の文を復元させる方法です。T5 モデルの事前学習では、テキストのランダムなスパン（複数の単語を含むこともあります）を1つのマスク用の特殊トークンで置き換え、そのマスクトークンが置き換えたテキストを予測するタスクを行います。

シーケンス・ツー・シーケンスモデルは、与えられた入力に応じて新しい文を生成するタスクに最も向いています。例えば、要約、翻訳、生成型質問応答などです。

💡 ヒント

Transformers がタスクを解く仕組みで見たように、BART や T5 のようなエンコーダ・デコーダモデルは、両方のアーキテクチャの長所を兼ね備えています。エンコーダが入力の前後の文脈を詳しく捉え、デコーダがそれに基づいて適切な出力テキストを生成します。その為、翻訳や要約のように、或るシーケンスを別のシーケンスに変換するタスクに最適です。

実践的な応用例

シーケンス・ツー・シーケンスモデルは、意味を保ちながら、或る形式のテキストを別の形式に変換するタスクに優れています。実践的な応用例には次のようなものがあります。

アプリケーション 説明 モデル例
機械翻訳 テキストを別の言語に変換する Marian, T5
テキスト要約 長いテキストの簡潔な要約を作成する BART, T5
データからテキストへの生成 構造化データを自然言語に変換する T5
文法訂正 テキストの文法的な誤りを修正する T5
質問応答 文脈に基づいて答えを生成する BART, T5

翻訳用のシーケンス・ツー・シーケンスモデルのインタラクティブなデモです。

この系統の代表的なモデルには次のものがあります。

  • BART
  • mBART
  • Marian
  • T5

適切なアーキテクチャの選び方

特定の NLP タスクに取り組む時、どのアーキテクチャを使えばいいのでしょうか。簡単なガイドを示します。

タスク 推奨アーキテクチャ 例
テキスト分類（感情分析、トピック） エンコーダ BERT, RoBERTa
テキスト生成（創作） デコーダ GPT, LLaMA
翻訳 エンコーダ・デコーダ T5, BART
要約 エンコーダ・デコーダ BART, T5
固有表現抽出 エンコーダ BERT, RoBERTa
質問応答（抽出型） エンコーダ BERT, RoBERTa
質問応答（生成型） エンコーダ・デコーダ又はデコーダ T5, GPT
対話型 AI デコーダ GPT, LLaMA

💡 ヒント

どのモデルを使うか迷ったら、次の点を考えてみてください。

  1. タスクにはどんな理解が必要か（双方向か単方向か）
  2. 新しいテキストを生成するのか、既存のテキストを分析するのか
  3. 或るシーケンスを別のシーケンスに変換する必要が有るか

これらの答えが、適切なアーキテクチャへと導いてくれます。

LLM の進化

大規模言語モデルは近年急速に進化しており、世代ごとに能力が大きく向上しています。

アテンション機構

殆どの Transformer モデルは、アテンション行列が正方行列になるという意味でフルアテンションを使っています。長いテキストでは、これが計算上の大きなボトルネックになることがあります。Longformer や Reformer は、より効率的になるよう工夫されたモデルで、アテンション行列の疎（スパース）なバージョンを使って学習を高速化します。

💡 ヒント

標準的なアテンション機構の計算量は O(n²) で、n はシーケンス長です。これは、非常に長いシーケンスでは問題になります。以下で紹介する特殊なアテンション機構は、この制限の解消に役立ちます。

LSHアテンション

Reformer は LSHアテンションを使います。softmax(QK^t) では、行列 QK^t の要素の内、値が大きいもの程計算結果への寄与が大きくなります。そこで、Q の各クエリ q に対して、q に近い K のキー k だけを考えればよくなります。q と k が近いかどうかは、ハッシュ関数を使って判定します。

アテンションマスクは、現在のトークンをマスクするように変更されます（先頭の位置を除く）。現在のトークンはクエリとキーが等しくなり（つまり非常によく似て）しまう為です。

ハッシュには多少のランダム性が有る為、実際には複数のハッシュ関数を使い（n_rounds パラメータで決まります）、その結果を平均します。

ローカルアテンション

Longformer はローカルアテンションを使います。多くの場合、或るトークンについて判断するには、ローカルな文脈（例えば左右2つのトークン）で十分です。また、小さなウィンドウを持つアテンション層を積み重ねることで、最後の層ではウィンドウ内のトークンだけにとどまらない受容野が得られ、文全体の表現を構築出来ます。

予め選ばれた一部の入力トークンには、グローバルアテンションも与えられます。グローバルアテンションを与えられたトークンは、入力中の全てのトークンを参照出来ます。また、他のトークンからも参照されます。つまり、ローカルな範囲を超えて、双方向に情報をやり取り出来ます。

軸方向の位置エンコーディング

Reformer は軸方向の位置エンコーディングを使います。従来の Transformer モデルでは、位置エンコーディング E は \(l\) × \(d\) の行列で、\(l\) はシーケンス長、\(d\) は隠れ状態の次元です。テキストが非常に長いと、この行列は巨大になり、GPU 上の容量を取り過ぎてしまいます。

これを緩和する為、軸方向の位置エンコーディングでは、その大きな行列 E を、次元が \(l_{1} \times d_{1}\) と \(l_{2} \times d_{2}\) の2つの小さな行列 E1 と E2 に分解します。ここで \(l_{1} \times l_{2} = l\) 且つ \(d_{1} + d_{2} = d\) です（長さ同士の積になる為、全体としてずっと小さくなります）。E におけるタイムステップ \(j\) の埋め込みは、E1 のタイムステップ \(j \% l1\) の埋め込みと、E2 のタイムステップ \(j // l1\) の埋め込みを連結して得られます。

まとめ

このセクションでは、Transformer の3つの主要なアーキテクチャと、いくつかの特殊なアテンション機構を学びました。これらのアーキテクチャの違いを理解することは、自分の NLP タスクに合ったモデルを選ぶ上で非常に重要です。

コースを進めていくと、これらの様々なアーキテクチャを実際に使って体験し、自分のニーズに合わせてファインチューニングする方法を学んでいきます。次のセクションでは、これらのモデルを導入する際に知っておくべき、モデルに存在する制限やバイアスについて見ていきます。
