特徴マッチング（Feature Matching）

検出された特徴を、ある画像から別の画像へどうマッチングすればよいでしょうか？特徴マッチングでは、異なる画像の主要な属性を比較して類似点を見つけます。特徴マッチングは、シーン理解、画像スティッチング、物体追跡、パターン認識など、多くのコンピュータビジョン応用で役立ちます。

ブルートフォース探索

パズルのピースが入った巨大な箱があり、パズルにぴったり合う特定のピースを探していると想像してください。これは、画像内のマッチする特徴を探すのと似ています。特別な戦略はなく、正しいピースが見つかるまで、ピースを1つずつ確認することにしたとします。この素直な方法がブルートフォース探索です。ブルートフォースの利点はシンプルさです。特別な工夫は必要なく、忍耐だけが必要です。ただし、チェックするピースが多いと時間がかかる場合があります。特徴マッチングの文脈では、このブルートフォースアプローチは、ある画像のすべてのピクセルを別の画像のすべてのピクセルと比較してマッチするかどうかを確認するようなものです。徹底的ですが、特に大きな画像では多くの時間がかかる可能性があります。

ブルートフォースでマッチがどう見つかるか直感的に理解できたので、アルゴリズムに踏み込みましょう。前の章で学んだ記述子を使って、2つの画像のマッチする特徴を見つけます。

まずライブラリをインストールして読み込みます。

!pip install opencv-python

import cv2
import numpy as np

SIFT によるブルートフォース

まず SIFT 検出器を初期化します。

sift = cv2.SIFT_create()

SIFT でキーポイントと記述子を見つけます。

kp1, des1 = sift.detectAndCompute(img1, None)
kp2, des2 = sift.detectAndCompute(img2, None)

k 近傍を使ってマッチを見つけます。

bf = cv2.BFMatcher()
matches = bf.knnMatch(des1, des2, k=2)

比率テストを適用して、最適なマッチにしきい値をかけます。

good = []
for m, n in matches:
    if m.distance < 0.75 * n.distance:
        good.append([m])

マッチを描画します。

img3 = cv2.drawMatchesKnn(
    img1, kp1, img2, kp2, good, None, flags=cv2.DrawMatchesFlags_NOT_DRAW_SINGLE_POINTS
)

ORB（バイナリ）記述子によるブルートフォース

ORB 記述子を初期化します。

orb = cv2.ORB_create()

キーポイントと記述子を見つけます。

kp1, des1 = orb.detectAndCompute(img1, None)
kp2, des2 = orb.detectAndCompute(img2, None)

ORB はバイナリ記述子なので、同じ長さの2つの文字列の違いを測る尺度であるハミング距離を使ってマッチを見つけます。

bf = cv2.BFMatcher(cv2.NORM_HAMMING, crossCheck=True)

マッチを見つけます。

matches = bf.match(des1, des2)

次のように、距離の順に並べ替えできます。

matches = sorted(matches, key=lambda x: x.distance)

最初の n 個のマッチを描画します。

img3 = cv2.drawMatches(
    img1,
    kp1,
    img2,
    kp2,
    matches[:n],
    None,
    flags=cv2.DrawMatchesFlags_NOT_DRAW_SINGLE_POINTS,
)

Fast Library for Approximate Nearest Neighbors（FLANN）

FLANN は Muja と Lowe による Fast Approximate Nearest Neighbors With Automatic Algorithm Configuration で提案されました。FLANN を説明するために、パズルを解く例を引き続き使います。何百ものピースが散らばった巨大なパズルを思い浮かべてください。目標は、それらがどれだけよく合うかに基づいてピースを整理することです。ランダムにピースをマッチさせようとする代わりに、 FLANN は賢い工夫を使って、どのピースが一緒に合いそうかを素早く把握します。すべてのピースを他のすべてのピースと試す代わりに、FLANN は近似的に似ているピースを見つけることでプロセスを効率化します。つまり、完全なマッチでなくても、どのピースがよく合う可能性があるかについて、根拠のある推測ができます。内部では、FLANN は k-d 木と呼ばれるものを使います。パズルのピースを特別な方法で整理することだと考えてください。すべてのピースを他のすべてのピースと照合する代わりに、FLANN はそれらを木のような構造に配置し、マッチをより速く見つけられるようにします。k-d 木の各ノードでは、FLANN は似た特徴を持つピースをまとめます。似た形や色のパズルのピースを山に分けるようなものです。こうすることで、マッチを探すときに、似たピースが最もありそうな山を素早く確認できます。「空」のピースを探しているとしましょう。すべてのピースを探し回る代わりに、FLANN は空色のピースが分類されている k-d 木の正しい場所へ案内します。FLANN は、パズルのピースの特徴に基づいて戦略も調整します。色が多いパズルなら色の特徴に焦点を当てます。複雑な形のパズルなら、その形に注意を払います。マッチする特徴を見つける際に速度と精度のバランスを取ることで、FLANN はクエリ時間を大幅に改善します。

まず、使用するアルゴリズムを指定する辞書を作成します。SIFT や SURF の場合は次のようになります。

FLANN_INDEX_KDTREE = 1
index_params = dict(algorithm=FLANN_INDEX_KDTREE, trees=5)

ORB の場合は、論文のパラメータを使います。

FLANN_INDEX_LSH = 6
index_params = dict(
    algorithm=FLANN_INDEX_LSH, table_number=12, key_size=20, multi_probe_level=2
)

訪れる最大のリーフ数を指定する辞書も、次のように作成します。

search_params = dict(checks=50)

SIFT 検出器を初期化します。

sift = cv2.SIFT_create()

SIFT でキーポイントと記述子を見つけます。

kp1, des1 = sift.detectAndCompute(img1, None)
kp2, des2 = sift.detectAndCompute(img2, None)

ここで FLANN パラメータを定義します。trees は欲しいビンの数です。

FLANN_INDEX_KDTREE = 1
index_params = dict(algorithm=FLANN_INDEX_KDTREE, trees=5)
search_params = dict(checks=50)
flann = cv2.FlannBasedMatcher(index_params, search_params)

matches = flann.knnMatch(des1, des2, k=2)

良いマッチだけを描画するので、マスクを作成します。

matchesMask = [[0, 0] for i in range(len(matches))]

比率テストを実行して、良いマッチを判定できます。

for i, (m, n) in enumerate(matches):
    if m.distance < 0.7 * n.distance:
        matchesMask[i] = [1, 0]

マッチを可視化しましょう。

draw_params = dict(
    matchColor=(0, 255, 0),
    singlePointColor=(255, 0, 0),
    matchesMask=matchesMask,
    flags=cv2.DrawMatchesFlags_DEFAULT,
)

img3 = cv2.drawMatchesKnn(img1, kp1, img2, kp2, matches, None, **draw_params)

Transformers による局所特徴マッチング（LoFTR）

LoFTR は Sun らによる LoFTR: Detector-Free Local Feature Matching with Transformers で提案されました。 特徴検出器を使う代わりに、LoFTR は学習ベースのアプローチで特徴マッチングを行います。

シンプルにするために、パズルの例をもう一度使いましょう。画像をピクセルごとに単純に比較する代わりに、LoFTR は各画像の特定のキーポイント、つまり特徴を探します。各パズルピースの角やエッジを特定するようなものです。パズルを組み立てるのが本当に上手な人が特徴的な目印に注目するように、LoFTR はある画像におけるこれらの固有の点を特定します。これらは目立つ主要なランドマークや構造でありえます。すでに学んだように、マッチングアルゴリズムが回転やスケールの変化を扱えることは重要です。特徴が回転したりリサイズされたりしても、LoFTR はそれを認識します。ピースが反転したり調整されたりするパズルを解くようなものです。LoFTR は特徴をマッチングする際、特徴がどれだけよく揃うかを示す類似度スコアを割り当てます。スコアが高いほど、より良いマッチです。あるパズルピースが別のピースにどれだけよく合うかを採点するようなものです。 LoFTR は特定の変換に対しても不変であり、照明、角度、遠近法の変動を扱えます。これは、異なる条件下で撮影された可能性のある画像を扱うときに重要です。LoFTR の特徴をロバストにマッチングする能力は、共通の特徴を特定して接続することで複数の画像をシームレスに組み合わせる画像スティッチングのようなタスクで価値があります。

Kornia を使って、LoFTR で2つの画像のマッチする特徴を見つけられます。

!pip install kornia  kornia-rs  kornia_moons opencv-python --upgrade

必要なライブラリをインポートします。

import cv2
import kornia as K
import kornia.feature as KF
import matplotlib.pyplot as plt
import numpy as np
import torch
from kornia_moons.viz import draw_LAF_matches

画像を読み込んでリサイズします。

from kornia.feature import LoFTR

img1 = K.io.load_image(image1.jpg, K.io.ImageLoadType.RGB32)[None, ...]
img2 = K.io.load_image(image2.jpg, K.io.ImageLoadType.RGB32)[None, ...]

img1 = K.geometry.resize(img1, (512, 512), antialias=True)
img2 = K.geometry.resize(img2, (512, 512), antialias=True)

画像が「屋内」か「屋外」かを示します。

matcher = LoFTR(pretrained="outdoor")

LoFTR はグレースケール画像でのみ動作するので、画像をグレースケールに変換します。

input_dict = {
    "image0": K.color.rgb_to_grayscale(img1),
    "image1": K.color.rgb_to_grayscale(img2),
}

推論を実行しましょう。

with torch.inference_mode():
    correspondences = matcher(input_dict)

Random Sample Consensus（RANSAC）を使って対応を整理します。これにより、データ内のノイズや外れ値に対処できます。

mkpts0 = correspondences["keypoints0"].cpu().numpy()
mkpts1 = correspondences["keypoints1"].cpu().numpy()
Fm, inliers = cv2.findFundamentalMat(mkpts0, mkpts1, cv2.USAC_MAGSAC, 0.5, 0.999, 100000)
inliers = inliers > 0

最後に、マッチを可視化できます。

draw_LAF_matches(
    KF.laf_from_center_scale_ori(
        torch.from_numpy(mkpts0).view(1, -1, 2),
        torch.ones(mkpts0.shape[0]).view(1, -1, 1, 1),
        torch.ones(mkpts0.shape[0]).view(1, -1, 1),
    ),
    KF.laf_from_center_scale_ori(
        torch.from_numpy(mkpts1).view(1, -1, 2),
        torch.ones(mkpts1.shape[0]).view(1, -1, 1, 1),
        torch.ones(mkpts1.shape[0]).view(1, -1, 1),
    ),
    torch.arange(mkpts0.shape[0]).view(-1, 1).repeat(1, 2),
    K.tensor_to_image(img1),
    K.tensor_to_image(img2),
    inliers,
    draw_dict={
        "inlier_color": (0.1, 1, 0.1, 0.5),
        "tentative_color": None,
        "feature_color": (0.2, 0.2, 1, 0.5),
        "vertical": False,
    },
)

最も良いマッチは緑色で可視化され、確実性が低いマッチは青色です。
