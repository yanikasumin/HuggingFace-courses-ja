MCP クライアントを構築する

このセクションでは、異なるプログラミング言語を使って MCP サーバーとやり取り出来るクライアントを作成します。HuggingFace.js を使った JavaScript クライアントと、smolagents を使った Python クライアントの両方を実装します。

MCP クライアントを設定する

MCP サーバーとクライアントを効果的にデプロイするには、適切な設定が必要です。MCP の仕様は未だ進化の途上に在る為、設定方法も変わっていく可能性があります。ここでは、現在のベストプラクティスに焦点を当てます。

MCP 設定ファイル

MCP ホストは、設定ファイルを使ってサーバーへの接続を管理します。設定ファイルには、利用出来るサーバーと、それぞれへの接続方法が定義されています。

設定ファイルは非常にシンプルで理解しやすく、主要な MCP ホスト間で一貫しています。

mcp.json の構造

MCP の標準設定ファイルは mcp.json という名前です。基本構造は次の通りです。

{
  "servers": [
    {
      "name": "MCP Server",
      "transport": {
        "type": "sse",
        "url": "http://localhost:7860/gradio_api/mcp/sse"
      }
    }
  ]
}

この例では、SSE トランスポートを使う単一のサーバーが設定されており、ポート 7860 で動作するローカルの Gradio サーバーに接続します。

💡 ヒント

Gradio アプリがリモートサーバーで動作していることを前提とする為、SSE トランスポートで Gradio アプリに接続しました。但し、ローカルのスクリプトに接続したい場合は、sse トランスポートではなく stdio トランスポートのほうが適しています。

HTTP+SSE トランスポートの設定

HTTP+SSE トランスポートを使うリモートサーバーでは、設定にサーバーの URL を含めます。

{
  "servers": [
    {
      "name": "Remote MCP Server",
      "transport": {
        "type": "sse",
        "url": "https://example.com/gradio_api/mcp/sse"
      }
    }
  ]
}

この設定により、UI クライアントは MCP プロトコルを使って Gradio MCP サーバーと通信出来、フロントエンドと MCP サービスのシームレスな統合が可能になります。

UI MCP クライアントを設定する

Gradio MCP サーバーを利用する場合は、MCP プロトコルでサーバーに接続するように UI クライアントを設定出来ます。具体的な設定方法は次の通りです。

基本設定

config.json という新しいファイルを作成し、次の設定を記述します。

{
  "mcpServers": {
    "mcp": {
      "url": "http://localhost:7860/gradio_api/mcp/sse"
    }
  }
}

この設定により、UI クライアントは MCP プロトコルを使って Gradio MCP サーバーと通信出来、フロントエンドと MCP サービスのシームレスな統合が可能になります。

Cursor IDE 内で MCP クライアントを設定する

Cursor には MCP サポートが組み込まれており、デプロイした MCP サーバーを開発環境に直接接続出来ます。

設定

Cursor の設定を開きます（Windows・Linux では Ctrl + Shift + J、macOS では Cmd + Shift + J）。次に、Tools & Integrations タブから Add Custom MCP を選択します。

macOS：

{
  "mcpServers": {
    "sentiment-analysis": {
      "command": "npx",
      "args": [
        "-y", 
        "mcp-remote", 
        "https://YOURUSENAME-mcp-sentiment.hf.space/gradio_api/mcp/sse", 
        "--transport", 
        "sse-only"
      ]
    }
  }
}

Windows：

{
  "mcpServers": {
    "sentiment-analysis": {
      "command": "cmd",
      "args": [
        "/c", 
        "npx", 
        "-y", 
        "mcp-remote", 
        "https://YOURUSENAME-mcp-sentiment.hf.space/gradio_api/mcp/sse", 
        "--transport", 
        "sse-only"
      ]
    }
  }
}

mcp-remote を使う理由

注：2025年半ば時点で、Cursor は HTTP+SSE と OAuth を使ったリモート MCP 接続に直接対応しています。古い構成を使っている場合や、互換性の問題が発生した場合を除き、mcp-remote は必要無いことがあります。

Cursor を含む初期の MCP クライアントは、stdio トランスポートによるローカルサーバーのみをサポートし、認証を伴うリモートサーバーをサポートしていませんでした。mcp-remote ツールは、その回避策として導入されたもので、次の特徴があります。

  • ローカルマシン上で動作する
  • Cursor とリモート MCP サーバーを橋渡しする
  • トランスポートと認証を暗黙的に処理する
  • おなじみの設定ファイル形式を使う

mcp-remote は例外的なケースでは現在も役立ちますが、Cursor はリモート MCP サーバーへの直接接続に対応しています。その為、次のようにリモートサーバーを直接設定出来ます。

{
  "mcpServers": {
    "my-server": {
      "url": "https://your-mcp-server.hf.space/gradio_api/mcp/sse"
    }
  }
}

最新のセットアップ手順については Cursor の公式ドキュメント を参照してください。

設定が完了したら、感情分析ツールを使ってコードのコメント、ユーザーからのフィードバック、プルリクエストの説明文などを分析するよう Cursor に依頼出来ます。
