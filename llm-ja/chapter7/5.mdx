このセクションでは、Transformer モデルを使って長い文書を要約に凝縮する方法、すなわち*テキスト要約*と呼ばれるタスクを見ていきます。これは最も難しい NLP タスクの1つです。長い文章を理解し、文書の主要な話題を捉えた一貫性のあるテキストを生成するなど、幅広い能力が求められるためです。しかし、うまくできればテキスト要約は強力なツールになります。ドメインの専門家が長い文書を細部まで読む負担を軽減し、さまざまな業務プロセスを高速化できます。

## 多言語コーパスを準備する[[preparing-a-multilingual-corpus]]

```python
        print(f"'>> Review: {example['review_body']}'")


show_samples(english_dataset)
```

```python
def filter_books(example):
    return (
        example["product_category"] == "book"
        or example["product_category"] == "digital_ebook_purchase"
    )
```

レビューは厳密には本に関するものではなく、カレンダーや OneNote のような電子アプリケーションを指している場合もあることが分かります。それでも、このドメインは要約モデルを学習するのにだいたい適切なようです。このタスクに適したさまざまなモデルを見る前に、データ準備の最後の1つを行います。英語とスペイン語のレビューを単一の `DatasetDict` オブジェクトに結合することです。🤗 Datasets は便利な `concatenate_datasets()` 関数を提供しており、（名前のとおり）2つの `Dataset` オブジェクトを積み重ねることができます。そこで、バイリンガルデータセットを作るため、各スプリットについてループし、そのスプリットのデータセットを連結し、結果をシャッフルして、モデルが単一言語に過学習しないようにします。

```python
from datasets import concatenate_datasets, DatasetDict

books_dataset = DatasetDict()

for split in english_books.keys():
    books_dataset[split] = concatenate_datasets(
        [english_books[split], spanish_books[split]]
    )
    books_dataset[split] = books_dataset[split].shuffle(seed=42)

# 例をいくつか確認します
show_samples(books_dataset)
```

## テキスト要約のためのモデル[[models-for-text-summarization]]

考えてみると、テキスト要約は機械翻訳と似た種類のタスクです。レビューのようなテキストがあり、それを入力の顕著な特徴を捉えた短い版に「翻訳」したいわけです。そのため、要約のための Transformer モデルのほとんどは、[Chapter 1](/course/chapter1) で最初に出会ったエンコーダ・デコーダアーキテクチャを採用しています。ただし、few-shot 設定でも要約に使える GPT ファミリーのモデルのような例外もあります。次の表は、要約用にファインチューニングできる人気の事前学習済みモデルの一部です。

| Transformer モデル | 説明                                                                                                                                                                                                    | 多言語対応？ |
| :---------: | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-----------: |
|    [GPT-2](https://huggingface.co/gpt2-xl)    | 自己回帰型の言語モデルとして学習されていますが、入力テキストの末尾に "TL;DR" を追加することで GPT-2 に要約を生成させることができます。                                                                          |      ❌       |
|   [PEGASUS](https://huggingface.co/google/pegasus-large)   | 複数文のテキストでマスクされた文を予測する事前学習目的を使います。この事前学習目的はバニラな言語モデリングよりも要約に近く、人気のベンチマークで高いスコアを出しています。 |      ❌       |
|     [T5](https://huggingface.co/t5-base)      | すべてのタスクを text-to-text フレームワークで定式化する汎用的な Transformer アーキテクチャです。たとえば、モデルが文書を要約するための入力形式は `summarize: ARTICLE` です。                              |      ❌       |
|     [mT5](https://huggingface.co/google/mt5-base)     | T5 の多言語版で、101言語をカバーする多言語 Common Crawl コーパス（mC4）で事前学習されています。                                                                                                |      ✅       |
|    [BART](https://huggingface.co/facebook/bart-base)     | BERT と GPT-2 の事前学習方式を組み合わせ、変形した入力を復元するよう学習された、エンコーダとデコーダの両スタックを持つ新しい Transformer アーキテクチャです。                                    |      ❌       |
|  [mBART-50](https://huggingface.co/facebook/mbart-large-50)   | BART の多言語版で、50言語で事前学習されています。                                                                                                                                                     |      ✅       |

この表から分かるように、要約のための Transformer モデル（そして実際、ほとんどの NLP タスク）の大部分は単一言語用です。タスクが英語やドイツ語のような「高リソース」言語であれば便利ですが、世界中で使われている何千もの他の言語にはあまり向いていません。幸い、mT5 や mBART のような多言語 Transformer モデルのクラスが救ってくれます。これらのモデルは言語モデリングを使って事前学習されていますが、ひねりがあります。1つの言語のコーパスで学習するのではなく、50を超える言語のテキストで共同で学習されているのです！

ここでは mT5 に焦点を当てます。これは T5 をベースにした興味深いアーキテクチャで、text-to-text フレームワークで事前学習されています。T5 では、すべての NLP タスクが `summarize:` のようなプロンプト接頭辞で定式化され、これによりモデルは生成するテキストをプロンプトに適応させます。下の図に示すように、これにより T5 は非常に汎用的になり、単一のモデルで多くのタスクを解決できます！

## データの前処理[[preprocessing-the-data]]

<Youtube id="1m7BerpSq8A"/>

次のタスクは、レビューとそのタイトルをトークン化してエンコードすることです。いつものように、事前学習済みモデルのチェックポイントに関連付けられたトークナイザを読み込むことから始めます。妥当な時間でモデルをファインチューニングできるよう、チェックポイントとして `mt5-small` を使います。

```python
from transformers import AutoTokenizer

model_checkpoint = "google/mt5-small"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint)
```

> [!TIP]
> 💡 NLP プロジェクトの初期段階では、小さなデータサンプルで「小さい」モデルのクラスを学習するのが良い実践です。これにより、エンドツーエンドのワークフローに向けてより速くデバッグと反復ができます。結果に自信が持てたら、モデルのチェックポイントを変更するだけでいつでもモデルをスケールアップできます！

mT5 トークナイザを小さな例で試してみましょう。

```python
inputs = tokenizer("I loved reading the Hunger Games!")
inputs
```


ここでは、[Chapter 3](/course/chapter3) の最初のファインチューニング実験で出会った、お馴染みの `input_ids` と `attention_mask` が見えます。これらの入力 ID を、トークナイザの `convert_ids_to_tokens()` 関数でデコードし、どのような種類のトークナイザを扱っているか見てみましょう。

```python

```

```python out
['▁I', '▁', 'loved', '▁reading', '▁the', '▁Hung', 'er', '▁Games', '</s>']
```

特殊な Unicode 文字 `▁` とシーケンス終端トークン `</s>` は、SentencePiece トークナイザを扱っていることを示しています。これは、[Chapter 6](/course/chapter6) で議論した Unigram セグメンテーションアルゴリズムに基づいています。Unigram は、SentencePiece がアクセント、句読点、そして日本語のように空白文字を持たない言語が多いという事実に依存しないため、多言語コーパスで特に有用です。

コーパスをトークン化するには、要約に関連する微妙な点に対処しなければなりません。ラベルもテキストであるため、モデルの最大コンテキストサイズを超える可能性があります。そのため、レビューとタイトルの両方に切り捨てを適用し、モデルに過度に長い入力を渡さないようにする必要があります。🤗 Transformers のトークナイザは便利な `text_target` 引数を提供しており、入力と並行してラベルをトークン化できます。mT5 で入力とターゲットがどのように処理されるかの例は次のとおりです。

```python
max_input_length = 512
max_target_length = 30


def preprocess_function(examples):
    model_inputs = tokenizer(
        examples["review_body"],
        max_length=max_input_length,
        truncation=True,
    )
    labels = tokenizer(
        examples["review_title"], max_length=max_target_length, truncation=True
    )
    model_inputs["labels"] = labels["input_ids"]
    return model_inputs
```

このコードを順に見て、何が起きているか理解しましょう。まず行ったのは、`max_input_length` と `max_target_length` の値を定義することです。これらは、レビューとタイトルがどれだけ長くなれるかの上限を設定します。レビュー本文は通常タイトルよりずっと大きいため、それに応じてこれらの値をスケーリングしました。

`preprocess_function()` を使えば、コース全体で広範に使ってきた便利な `Dataset.map()` 関数を使ってコーパス全体をトークン化するのは簡単です。

```python
tokenized_datasets = books_dataset.map(preprocess_function, batched=True)
```

コーパスの前処理が終わったので、要約によく使われる指標をいくつか見ていきましょう。見ていくように、機械生成テキストの品質を測ることに関しては、特効薬はありません。

> [!TIP]
> 💡 上の `Dataset.map()` 関数で `batched=True` を使ったことに気づいたかもしれません。これは例を1,000件（デフォルト）のバッチでエンコードし、🤗 Transformers の高速トークナイザのマルチスレッド機能を活用できるようにします。可能な場合は、前処理を最大限に活用するため `batched=True` を使うようにしてください！


## テキスト要約の指標[[metrics-for-text-summarization]]

<Youtube id="TMshhnrEXlg"/>

このコースで扱った他のほとんどのタスクと比べて、要約や翻訳のようなテキスト生成タスクのパフォーマンスを測るのは、それほど単純ではありません。たとえば、"I loved reading the Hunger Games" のようなレビューに対しては、"I loved the Hunger Games" や "Hunger Games is a great read" のような、複数の妥当な要約があります。明らかに、生成された要約とラベルの間の何らかの完全一致を適用するのは良い解決策ではありません。人間でさえ、そのような指標ではうまくいかないでしょう。私たちは皆、自分の文体を持っているためです。

要約で最もよく使われる指標の1つは、[ROUGE スコア](https://en.wikipedia.org/wiki/ROUGE_(metric)) です（Recall-Oriented Understudy for Gisting Evaluation の略）。この指標の背後にある基本的な考え方は、生成された要約を、通常は人間が作成した参照要約の集合と比較することです。これをより正確にするため、次の2つの要約を比較したいとします。

```python
generated_summary = "I absolutely loved reading the Hunger Games"
reference_summary = "I loved reading the Hunger Games"
```

比較する1つの方法は、重複する単語の数を数えることです。このケースでは6になります。しかし、これは少し粗い方法です。そのため、代わりに ROUGE は重複に対する*適合率*と*再現率*のスコアを計算することに基づいています。

> [!TIP]
> 🙋 適合率と再現率を初めて聞いた場合でも心配いりません。明確な例を一緒に見て、すべてを明らかにしていきます。これらの指標は通常、分類タスクで遭遇します。その文脈で適合率と再現率がどのように定義されているかを理解したい場合は、`scikit-learn` の[ガイド](https://scikit-learn.org/stable/auto_examples/model_selection/plot_precision_recall.html)をチェックすることをお勧めします。

ROUGE については、再現率は、参照要約のどれだけが生成された要約で捉えられているかを測ります。単語だけを比較する場合、再現率は次の式で計算できます。

$$ \mathrm{Recall} = \frac{\mathrm{Number\,of\,overlapping\, words}}{\mathrm{Total\, number\, of\, words\, in\, reference\, summary}} $$

上の単純な例では、この式は6/6 = 1という完璧な再現率を与えます。つまり、参照要約のすべての単語がモデルによって生成されています。これは素晴らしいことに聞こえるかもしれませんが、生成された要約が "I really really loved reading the Hunger Games all night" だった場合を想像してみてください。これも完璧な再現率になりますが、冗長であるため、おそらくより悪い要約です。このようなシナリオに対処するため、適合率も計算します。ROUGE の文脈では、適合率は、生成された要約のどれだけが関連していたかを測ります。

$$ \mathrm{Precision} = \frac{\mathrm{Number\,of\,overlapping\, words}}{\mathrm{Total\, number\, of\, words\, in\, generated\, summary}} $$

これを冗長な要約に適用すると、適合率は 6/10 = 0.6 となり、より短い要約で得られる適合率 6/7 = 0.86 よりかなり悪くなります。実際には、適合率と再現率の両方が通常計算され、その後 F1 スコア（適合率と再現率の調和平均）が報告されます。これは、`rouge_score` パッケージをまずインストールすることで、🤗 Datasets で簡単に行えます。

### 強力なベースラインを作る[[creating-a-strong-baseline]]

テキスト要約の一般的なベースラインは、記事の最初の3文をそのまま使うことです。これはしばしば *lead-3* ベースラインと呼ばれます。ピリオドを使って文の境界を追跡することもできますが、これは "U.S." や "U.N." のような頭字語で失敗します。そのため代わりに、これらのケースを扱うためのより良いアルゴリズムを含む `nltk` ライブラリを使います。パッケージは `pip` を使って次のようにインストールできます。

```python

```

次に、`nltk` から文トークナイザをインポートし、レビューの最初の3文を抽出する単純な関数を作成します。テキスト要約の慣例では、各要約を改行で区切るため、これも含めて学習例でテストしましょう。

```python
from nltk.tokenize import sent_tokenize

    return "\n".join(sent_tokenize(text)[:3])


print(three_sentence_summary(books_dataset["train"][1]["review_body"]))
```

これはうまくいっているように見えます。では、データセットからこれらの「要約」を抽出し、ベースラインの ROUGE スコアを計算する関数を実装しましょう。

学習中に ROUGE スコアを計算するには、要約を生成する必要があります。幸い、🤗 Transformers は専用の `Seq2SeqTrainingArguments` と `Seq2SeqTrainer` クラスを提供しており、これらを自動的に行うことができます！仕組みを確認するため、まず実験のハイパーパラメータやその他の引数を定義しましょう。

```python
from transformers import Seq2SeqTrainingArguments

batch_size = 8
num_train_epochs = 8
# エポックごとに学習損失を表示します
logging_steps = len(tokenized_datasets["train"]) // batch_size
model_name = model_checkpoint.split("/")[-1]

args = Seq2SeqTrainingArguments(
    output_dir=f"{model_name}-finetuned-amazon-en-es",
    evaluation_strategy="epoch",
    learning_rate=5.6e-5,
    per_device_train_batch_size=batch_size,
    per_device_eval_batch_size=batch_size,
    weight_decay=0.01,
    save_total_limit=3,
    num_train_epochs=num_train_epochs,
    predict_with_generate=True,
    logging_steps=logging_steps,
    push_to_hub=True,
)
```

ここでは、`predict_with_generate` 引数を設定して、評価中に要約を生成し、各エポックの ROUGE スコアを計算できるようにしました。[Chapter 1](/course/chapter1) で議論したように、デコーダはトークンを1つずつ予測して推論を行い、これはモデルの `generate()` メソッドによって実装されています。`predict_with_generate=True` と設定すると、`Seq2SeqTrainer` に評価にそのメソッドを使うよう指示します。また、学習率、エポック数、ウェイト減衰のようなデフォルトのハイパーパラメータの一部を調整し、`save_total_limit` オプションを設定して、学習中に最大3つのチェックポイントだけを保存するようにしました。これは、mT5 の「小さい」版でも約1 GB のハードドライブ容量を使うため、保存するコピーの数を制限することで少し節約できるためです。

`push_to_hub=True` 引数により、学習後にモデルを Hub にプッシュできます。リポジトリは、`output_dir` で定義された場所のユーザープロファイルの下にあります。プッシュ先リポジトリの名前は `hub_model_id` 引数で指定できることに注意してください（特に、組織にプッシュする場合はこの引数を使う必要があります）。たとえば、モデルを [`huggingface-course` 組織](https://huggingface.co/huggingface-course) にプッシュした際には、`Seq2SeqTrainingArguments` に `hub_model_id="huggingface-course/mt5-finetuned-amazon-en-es"` を追加しました。

次に行う必要があるのは、学習中にモデルを評価できるよう、Trainer に `compute_metrics()` 関数を提供することです。要約については、モデルの予測に対して `rouge_score.compute()` を呼び出すだけよりも少し複雑です。ROUGE スコアを計算する前に、出力とラベルをテキストに*デコード*する必要があるためです。次の関数はまさにそれを行い、`nltk` の `sent_tokenize()` 関数も使って、要約の文を改行で区切ります。

```python
import numpy as np


def compute_metrics(eval_pred):
    predictions, labels = eval_pred
    # 生成された要約をテキストにデコードします
    decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)
    # ラベル内の -100 はデコードできないので置き換えます
    labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
    # 参照要約をテキストにデコードします
    decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)
    # ROUGE は各文の後に改行を想定します
    decoded_preds = ["\n".join(sent_tokenize(pred.strip())) for pred in decoded_preds]
    decoded_labels = ["\n".join(sent_tokenize(label.strip())) for label in decoded_labels]
    # ROUGE スコアを計算します
    result = rouge_score.compute(
        predictions=decoded_preds, references=decoded_labels, use_stemmer=True
    )
    # 中央値のスコアを取り出します
    result = {key: value.mid.fmeasure * 100 for key, value in result.items()}
    return {k: round(v, 4) for k, v in result.items()}
```

学習中に損失値はいくつか得られましたが、本来見たいのは先ほど計算した ROUGE 指標です。その指標を得るには、モデルから出力を生成し、文字列に変換する必要があります。ROUGE 指標が比較するためのラベルと予測のリストを構築しましょう（このセクションでインポートエラーが出る場合は、`!pip install tqdm` が必要になるかもしれません）。さらに、劇的にパフォーマンスを高める工夫も使います。生成コードを TensorFlow の高速化線形代数コンパイラである [XLA](https://www.tensorflow.org/xla) でコンパイルします。XLA はモデルの計算グラフにさまざまな最適化を適用し、速度とメモリ使用量を大きく改善します。Hugging Face の[ブログ](https://huggingface.co/blog/tf-xla-generate)で説明されているように、XLA は入力の形状があまり変化しないときに最も効果を発揮します。これに対応するため、入力を128の倍数までパディングし、パディング用コレータで新しいデータセットを作り、生成関数に `@tf.function(jit_compile=True)` デコレータを適用して、関数全体を XLA でコンパイルするようマークします。

```python
from tqdm import tqdm
import numpy as np

generation_data_collator = DataCollatorForSeq2Seq(
    tokenizer, model=model, return_tensors="tf", pad_to_multiple_of=320
)

tf_generate_dataset = model.prepare_tf_dataset(
    tokenized_datasets["validation"],
    collate_fn=generation_data_collator,
    shuffle=False,
    batch_size=8,
    drop_remainder=True,
)


@tf.function(jit_compile=True)
def generate_with_xla(batch):
    return model.generate(
        input_ids=batch["input_ids"],
        attention_mask=batch["attention_mask"],
        max_new_tokens=32,
    )


all_preds = []
all_labels = []
for batch, labels in tqdm(tf_generate_dataset):
    predictions = generate_with_xla(batch)
    decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)
    labels = labels.numpy()
    labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
    decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)
    decoded_preds = ["\n".join(sent_tokenize(pred.strip())) for pred in decoded_preds]
    decoded_labels = ["\n".join(sent_tokenize(label.strip())) for label in decoded_labels]
    all_preds.extend(decoded_preds)
    all_labels.extend(decoded_labels)
```

ラベルと予測の文字列のリストが得られたら、ROUGE スコアの計算は簡単です。

```python
result = rouge_score.compute(

)
result = {key: value.mid.fmeasure * 100 for key, value in result.items()}
{k: round(v, 4) for k, v in result.items()}
```

## 🤗 Accelerate で mT5 をファインチューニングする[[fine-tuning-mt5-with-accelerate]]

🤗 Accelerate でモデルをファインチューニングするのは、[Chapter 3](/course/chapter3) で出会ったテキスト分類の例と非常によく似ています。主な違いは、学習中に要約を明示的に生成する必要があることと、ROUGE スコアの計算方法を定義する必要があることです（`Seq2SeqTrainer` は生成を代わりに行ってくれたことを思い出してください）。これら2つの要件を 🤗 Accelerate の中でどのように実装できるか見ていきましょう！

### 学習に必要なものをすべて準備する[[preparing-everything-for-training]]

まず行う必要があるのは、各スプリットの `DataLoader` を作成することです。PyTorch のデータローダはテンソルのバッチを想定するため、データセットの形式を `"torch"` に設定する必要があります。

```python
tokenized_datasets.set_format("torch")
```

テンソルだけで構成されたデータセットが得られたので、次に行うのは `DataCollatorForSeq2Seq` を再びインスタンス化することです。そのためにはモデルの新しい版が必要なので、キャッシュから再び読み込みましょう。

```python
model = AutoModelForSeq2SeqLM.from_pretrained(model_checkpoint)
```

その後、データコレータをインスタンス化し、これを使ってデータローダを定義できます。

```python

batch_size = 8

    tokenized_datasets["train"],
    shuffle=True,
    collate_fn=data_collator,
```

次に行うのは、使いたいオプティマイザを定義することです。他の例と同様に、ほとんどの問題でうまく機能する `AdamW` を使います。

```python
    model, optimizer, train_dataloader, eval_dataloader

```

> [!TIP]
> 🚨 TPU で学習する場合は、上のコードをすべて専用の学習関数の中に移動する必要があります。詳細は [Chapter 3](/course/chapter3) を参照してください。

オブジェクトを準備したので、残りは3つです。

* 学習率スケジュールを定義すること。
* 評価のために要約を後処理する関数を実装すること。
* モデルをプッシュできるリポジトリを Hub に作成すること。

学習率スケジュールについては、前のセクションの標準的な線形のものを使います。

```python
from transformers import get_scheduler

num_update_steps_per_epoch = len(train_dataloader)
num_training_steps = num_train_epochs * num_update_steps_per_epoch

    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)
```

後処理については、生成された要約を改行で区切られた文に分割する関数が必要です。これは ROUGE 指標が想定する形式であり、次のコードスニペットで実現できます。

```python
def postprocess_text(preds, labels):
    preds = [pred.strip() for pred in preds]
    labels = [label.strip() for label in labels]

    # ROUGE は各文の後に改行を想定します
    preds = ["\n".join(nltk.sent_tokenize(pred)) for pred in preds]
    labels = ["\n".join(nltk.sent_tokenize(label)) for label in labels]

    return preds, labels
```

### 学習ループ[[training-loop]]

要約の学習ループは、これまでに出会った他の 🤗 Accelerate の例とかなり似ており、大まかに4つの主要なステップに分かれています。

1. 各エポックで `train_dataloader` のすべての例を反復してモデルを学習する。
2. 各エポックの終わりにモデルの要約を生成する。まずトークンを生成し、その後それら（および参照要約）をテキストにデコードする。
3. 先ほど見たのと同じ手法で ROUGE スコアを計算する。
4. チェックポイントを保存し、すべてを Hub にプッシュする。ここでは `Repository` オブジェクトの便利な `blocking=False` 引数に依存し、エポックごとのチェックポイントを*非同期*にプッシュします。これにより、GB サイズのモデルに関連するやや遅いアップロードを待つことなく、学習を続けることができます！

これらのステップは、次のコードブロックで確認できます。

```python
from tqdm.auto import tqdm
import torch
import numpy as np

progress_bar = tqdm(range(num_training_steps))

for epoch in range(num_train_epochs):
    # 学習
    model.train()
    for step, batch in enumerate(train_dataloader):
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

    # 評価
    model.eval()
    for step, batch in enumerate(eval_dataloader):
        with torch.no_grad():
            generated_tokens = accelerator.unwrap_model(model).generate(
                batch["input_ids"],
                attention_mask=batch["attention_mask"],
            )

            generated_tokens = accelerator.pad_across_processes(
                generated_tokens, dim=1, pad_index=tokenizer.pad_token_id
            )
            labels = batch["labels"]

            # 最大長までパディングしていない場合は、ラベルもパディングする必要があります
            labels = accelerator.pad_across_processes(
                batch["labels"], dim=1, pad_index=tokenizer.pad_token_id
            )

            generated_tokens = accelerator.gather(generated_tokens).cpu().numpy()
            labels = accelerator.gather(labels).cpu().numpy()

            # ラベル内の -100 はデコードできないので置き換えます
            labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
            if isinstance(generated_tokens, tuple):
                generated_tokens = generated_tokens[0]
            decoded_preds = tokenizer.batch_decode(
                generated_tokens, skip_special_tokens=True
            )
            decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)

            decoded_preds, decoded_labels = postprocess_text(
                decoded_preds, decoded_labels
            )

            rouge_score.add_batch(predictions=decoded_preds, references=decoded_labels)

    # 指標を計算します
    result = rouge_score.compute()
    # ROUGE スコアの中央値を取り出します
    result = {key: value.mid.fmeasure * 100 for key, value in result.items()}
    result = {k: round(v, 4) for k, v in result.items()}
    print(f"Epoch {epoch}:", result)

    # 保存とアップロード
    accelerator.wait_for_everyone()
    unwrapped_model = accelerator.unwrap_model(model)
    unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
    if accelerator.is_main_process:
        tokenizer.save_pretrained(output_dir)
        repo.push_to_hub(
            commit_message=f"Training in progress epoch {epoch}", blocking=False
        )
```
