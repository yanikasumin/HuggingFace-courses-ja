このセクションでは、🤗 Transformers のトークナイザの能力を詳しく見ていきます。これまでは入力のトークン化や ID のテキストへのデコードにしか使ってきませんでしたが、トークナイザ、特に Tokenizers ライブラリに裏付けられたものは、もっと多くのことが出来ます。これらの追加機能を説明する為に、Chapter 1 で初めて出会った token-classification（ner と呼んでいたもの）と question-answering の各パイプラインの結果を再現する方法を探ります。

以降の説明では、「低速」トークナイザと「高速」トークナイザをしばしば区別します。低速トークナイザは Transformers ライブラリ内部で Python で書かれたもので、高速版は Rust で書かれた Tokenizers が提供するものです。Chapter 5 の、高速トークナイザと低速トークナイザが Drug Review Dataset をトークン化するのにかかった時間を示した表を覚えていれば、何故高速・低速と呼ぶのか分かるでしょう。

高速トークナイザ 低速トークナイザ
batched=True 10.8s 4min41s
batched=False 59.2s 5min3s

⚠️ 注意

⚠️ 1つの文をトークン化する場合、低速版と高速版で速度の違いが常に見られるとは限りません。実際、高速版の方が遅いこともあります！多数のテキストを同時に並列でトークン化する時に初めて、違いがはっきりと分かります。

バッチエンコーディング

トークナイザの出力は単なる Python の辞書ではありません。実際には、特別な BatchEncoding オブジェクトが得られます。これは辞書のサブクラスであり（その為、以前も問題なくその結果にインデックスでアクセス出来ました）、高速トークナイザで主に使われる追加のメソッドを持っています。

並列化能力に加えて、高速トークナイザの重要な機能は、最終的なトークンの由来となった元のテキストの範囲を常に追跡することです。この機能をオフセットマッピングと呼びます。これにより、各単語をそれが生成したトークンにマッピングしたり、元のテキストの各文字をそれを含むトークンにマッピングしたり、その逆を行ったり出来るようになります。

例を見てみましょう。

from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-cased")
example = "My name is Sylvain and I work at Hugging Face in Brooklyn."
encoding = tokenizer(example)
print(type(encoding))

前述の通り、トークナイザの出力として BatchEncoding オブジェクトが得られます。

```python out <class 'transformers.tokenization_utils_base.BatchEncoding'>

`AutoTokenizer` クラスはデフォルトで高速トークナイザを選択する為、この `BatchEncoding` オブジェクトが提供する追加のメソッドを使えます。トークナイザが高速か低速かを確認する方法は2つあります。まず、`tokenizer` の `is_fast` 属性を確認する方法です。

```python
tokenizer.is_fast

```python out True

もう1つは、`encoding` の同じ属性を確認する方法です。

```python
encoding.is_fast

```python out True

高速トークナイザで何が出来るか見てみましょう。まず、ID をトークンに戻す変換をしなくても、トークンにアクセス出来ます。

```py
encoding.tokens()

```python out ['[CLS]', 'My', 'name', 'is', 'S', '##yl', '##va', '##in', 'and', 'I', 'work', 'at', 'Hu', '##gging', 'Face', 'in', 'Brooklyn', '.', '[SEP]']

この場合、インデックス5のトークンは `##yl` で、元の文の単語 "Sylvain" の一部です。`word_ids()` メソッドを使えば、各トークンの由来となった単語のインデックスも取得出来ます。

```py
encoding.word_ids()

```python out [None, 0, 1, 2, 3, 3, 3, 3, 4, 5, 6, 7, 8, 8, 9, 10, 11, 12, None]

トークナイザの特殊トークン `[CLS]` と `[SEP]` は `None` にマッピングされ、その後、各トークンは由来となった単語にマッピングされていることが分かります。これは、トークンが単語の先頭に在るかどうかや、2つのトークンが同じ単語内にあるかどうかを判定するのに特に役立ちます。その判定に `##` 接頭辞を使うことも出来ますが、それは BERT のようなトークナイザでしか機能しません。

このメソッドは、高速トークナイザであればどの種類のトークナイザでも機能します。次の章では、この能力を使って、固有表現認識（NER）や品詞タグ付け（POS tagging）のようなタスクで、単語ごとのラベルをトークンに適切に適用する方法を見ます。また、マスク言語モデリングで同じ単語に由来する全てのトークンをマスクする（単語全体マスキング、whole word masking）為にも使えます。

<div class="callout callout-tip" markdown="block">
<p class="callout-title">💡 ヒント</p>
単語とは何かという概念は複雑です。例えば、"I'll"（"I will" の短縮形）は1つの単語として数えるのでしょうか、それとも2つでしょうか。実際には、トークナイザとそれが適用する事前トークン化の操作によって異なります。空白で分割するだけのトークナイザは、これを1つの単語と見なします。空白に加えて句読点も使うトークナイザは、2つの単語と見なします。

**試してみましょう！** `bert-base-cased` と `roberta-base` のチェックポイントからトークナイザを作成し、"81s" をトークン化してみてください。何が観察出来ますか。単語 ID はどうなっていますか。
</div>


同様に、`sentence_ids()` メソッドを使えば、トークンを由来となった文にマッピング出来ます（但し、この場合はトークナイザが返す `token_type_ids` からも同じ情報が得られます）。

最後に、`word_to_chars()` や `token_to_chars()`、`char_to_word()` や `char_to_token()` の各メソッドを使えば、任意の単語やトークンを元のテキストの文字にマッピングしたり、その逆を行ったり出来ます。例えば、`word_ids()` メソッドにより `##yl` がインデックス3の単語の一部であることは分かりましたが、文中のどの単語でしょうか。次のようにすれば分かります。

```py
start, end = encoding.word_to_chars(3)
example[start:end]

```python out Sylvain

### パイプラインで基本的な結果を得る

まず、手動の結果と比較出来るよう、トークン分類パイプラインを用意しましょう。デフォルトで使われるモデルは [`dbmdz/bert-large-cased-finetuned-conll03-english`](https://huggingface.co/dbmdz/bert-large-cased-finetuned-conll03-english) で、文に対して NER を実行します。

```py
from transformers import pipeline

token_classifier = pipeline("token-classification")
token_classifier("My name is Sylvain and I work at Hugging Face in Brooklyn.")

```python out [{'entity': 'I-PER', 'score': 0.9993828, 'index': 4, 'word': 'S', 'start': 11, 'end': 12}, {'entity': 'I-PER', 'score': 0.99815476, 'index': 5, 'word': '##yl', 'start': 12, 'end': 14}, {'entity': 'I-PER', 'score': 0.99590725, 'index': 6, 'word': '##va', 'start': 14, 'end': 16}, {'entity': 'I-PER', 'score': 0.9992327, 'index': 7, 'word': '##in', 'start': 16, 'end': 18}, {'entity': 'I-ORG', 'score': 0.97389334, 'index': 12, 'word': 'Hu', 'start': 33, 'end': 35}, {'entity': 'I-ORG', 'score': 0.976115, 'index': 13, 'word': '##gging', 'start': 35, 'end': 40}, {'entity': 'I-ORG', 'score': 0.98879766, 'index': 14, 'word': 'Face', 'start': 41, 'end': 45}, {'entity': 'I-LOC', 'score': 0.99321055, 'index': 16, 'word': 'Brooklyn', 'start': 49, 'end': 57}]

モデルは、"Sylvain" から生成された各トークンを人物として、"Hugging Face" から生成された各トークンを組織として、トークン "Brooklyn" を場所として正しく特定しました。同じエンティティに対応するトークンをグループ化するようパイプラインに求めることも出来ます。

```py
from transformers import pipeline

token_classifier = pipeline("token-classification", aggregation_strategy="simple")
token_classifier("My name is Sylvain and I work at Hugging Face in Brooklyn.")

```python out [{'entity_group': 'PER', 'score': 0.9981694, 'word': 'Sylvain', 'start': 11, 'end': 18}, {'entity_group': 'ORG', 'score': 0.97960204, 'word': 'Hugging Face', 'start': 33, 'end': 45}, {'entity_group': 'LOC', 'score': 0.99321055, 'word': 'Brooklyn', 'start': 49, 'end': 57}]

選択した `aggregation_strategy` によって、グループ化された各エンティティについて計算されるスコアが変わります。`"simple"` では、スコアは対象エンティティ内の各トークンのスコアの平均です。例えば、"Sylvain" のスコアは、前の例で見たトークン `S`、`##yl`、`##va`、`##in` のスコアの平均です。他に利用出来る戦略は次の通りです。

- `"first"`、各エンティティのスコアが、そのエンティティの最初のトークンのスコアになるもの（"Sylvain" の場合は、トークン `S` のスコアである 0.993828 になります）
- `"max"`、各エンティティのスコアが、そのエンティティ内のトークンの最大スコアになるもの（"Hugging Face" の場合は、"Face" のスコアである 0.98879766 になります）
- `"average"`、各エンティティのスコアが、そのエンティティを構成する単語のスコアの平均になるもの（"Sylvain" の場合は `"simple"` 戦略と差はありませんが、"Hugging Face" のスコアは、"Hugging" のスコア 0.975 と "Face" のスコア 0.98879 の平均である 0.9819 になります）

では、`pipeline()` 関数を使わずにこれらの結果を得る方法を見てみましょう！

### 入力から予測へ

print(predictions)

```python out [0, 0, 0, 0, 4, 4, 4, 4, 0, 0, 0, 0, 6, 6, 6, 0, 8, 0, 0]

`model.config.id2label` 属性には、予測を解釈する為に使える、インデックスからラベルへのマッピングが含まれています。

```py
model.config.id2label

```python out {0: 'O', 1: 'B-MISC', 2: 'I-MISC', 3: 'B-PER', 4: 'I-PER', 5: 'B-ORG', 6: 'I-ORG', 7: 'B-LOC', 8: 'I-LOC'}

先に見た通り、ラベルは9つあります。`O` はどの固有表現にも属さないトークン用のラベルで（"outside" の略）、エンティティの種類（その他、人物、組織、場所）ごとに2つのラベルがあります。ラベル `B-XXX` はトークンがエンティティ `XXX` の先頭に在ることを示し、ラベル `I-XXX` はトークンがエンティティ `XXX` の内部に在ることを示します。例えば、現在の例では、モデルがトークン `S` を `B-PER`（人物エンティティの開始）、トークン `##yl`、`##va`、`##in` を `I-PER`（人物エンティティの内部）と分類すると予想されます。

この場合、モデルが4つのトークン全てに `I-PER` ラベルを与えたのは誤りだと思うかもしれませんが、それは完全には正しくありません。これらの `B-` と `I-` のラベルには、実は *IOB1* と *IOB2* という2つの形式があります。IOB2 形式（下図のピンク）が私たちが紹介したものですが、IOB1 形式（下図の青）では、`B-` で始まるラベルは、同じ種類の隣接する2つのエンティティを区切る場合にのみ使われます。使用しているモデルはその形式を使ったデータセットでファインチューニングされている為、`S` トークンに `I-PER` ラベルを割り当てます。

### エンティティのグループ化

オフセットを使って各エンティティの start キーと end キーを決めるのは便利ですが、その情報は厳密には必須ではありません。しかし、エンティティをグループ化したい場合、オフセットがあれば煩雑なコードを大量に書かずに済みます。

例えば、トークン `Hu`、`##gging`、`Face` をグループ化したい場合、最初の2つは `##` を取り除いて連結し、`Face` は `##` で始まらない為空白を付けて追加する、といった特別なルールを作ることも出来ます。しかし、それはこの特定の種類のトークナイザでしか機能しません。SentencePiece や Byte-Pair-Encoding のトークナイザ（この章の後半で説明）には、別のルール一式を書かなければならなくなります。

オフセットがあれば、そのようなカスタムコードは全て不要になります。元のテキストの中で、最初のトークンから始まり最後のトークンで終わる範囲を取るだけです。トークン `Hu`、`##gging`、`Face` の場合、文字33（`Hu` の開始）から始めて文字45（`Face` の終了）の前で終わることになります。

```py
example[33:45]

```python out Hugging Face

エンティティをグループ化しながら予測を後処理するコードを書く為に、連続していて `I-XXX` とラベル付けされたエンティティをグループ化します。但し最初のものは `B-XXX` 又は `I-XXX` のどちらのラベルでも構いません（つまり、`O`、新しい種類のエンティティ、又は同じ種類のエンティティの開始を示す `B-XXX` が現れたら、エンティティのグループ化を終了します）。

```py
import numpy as np

results = []
inputs_with_offsets = tokenizer(example, return_offsets_mapping=True)
tokens = inputs_with_offsets.tokens()
offsets = inputs_with_offsets["offset_mapping"]

idx = 0
while idx < len(predictions):
    pred = predictions[idx]
    label = model.config.id2label[pred]
    if label != "O":
        # B- または I- を取り除く
        label = label[2:]
        start, _ = offsets[idx]

        # I-label とラベル付けされたすべてのトークンを取得する
        all_scores = []
        while (
            idx < len(predictions)
            and model.config.id2label[predictions[idx]] == f"I-{label}"
        ):
            all_scores.append(probabilities[idx][pred])
            _, end = offsets[idx]
            idx += 1

        # スコアは、グループ化されたエンティティ内のすべてのトークンのスコアの平均
        score = np.mean(all_scores).item()
        word = example[start:end]
        results.append(
            {
                "entity_group": label,
                "score": score,
                "word": word,
                "start": start,
                "end": end,
            }
        )
    idx += 1

print(results)
