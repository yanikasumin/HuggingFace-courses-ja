[Chapter 1](/course/chapter1) で見たように、Transformer モデルは通常とても大きなモデルです。パラメータ数は数百万から数百億にものぼり、その学習とデプロイは複雑な取り組みになります。さらに、新しいモデルがほぼ毎日のように公開され、それぞれ実装も異なるため、すべてを試してみるのは簡単なことではありません。

🤗 Transformers ライブラリは、この問題を解決するために作られました。その目標は、あらゆる Transformer モデルを読み込み、学習し、保存できる単一の API を提供することです。ライブラリの主な特徴は次のとおりです。

- **使いやすさ**: 最先端の NLP モデルをダウンロードして読み込み、推論に使うまでが、わずか2行のコードで済みます。
- **柔軟性**: すべてのモデルは本質的にシンプルな PyTorch の `nn.Module` クラスであり、それぞれの機械学習（ML）フレームワークにおける他のモデルと同じように扱えます。
- **シンプルさ**: ライブラリ全体を通して、抽象化はほとんど行われていません。「All in one file（すべて1つのファイルに）」が核となる考え方で、モデルのフォワードパスは1つのファイルの中に完全に定義されます。そのため、コード自体が理解しやすく、改変もしやすくなっています。

この最後の特徴により、🤗 Transformers は他の ML ライブラリとはかなり異なります。モデルはファイル間で共有されるモジュールを組み合わせて構築されるのではなく、各モデルが独自の層を持っています。モデルが扱いやすく理解しやすくなるだけでなく、他のモデルに影響を与えずに、1つのモデルで簡単に実験できます。

この章ではまず、モデルとトークナイザを一緒に使い、[Chapter 1](/course/chapter1) で紹介した `pipeline()` 関数を再現する、エンドツーエンドの例から始めます。次にモデル API を取り上げます。モデルクラスと設定クラスを詳しく見て、モデルの読み込み方と、モデルが数値入力を処理して予測を出力する仕組みを紹介します。

続いて、`pipeline()` 関数のもう1つの主要な構成要素であるトークナイザ API を見ていきます。トークナイザは処理の最初と最後のステップを担い、テキストからニューラルネットワーク向けの数値入力への変換と、必要に応じてテキストに戻す変換を処理します。最後に、複数の文をまとめたバッチをモデルに送る方法を紹介し、高レベルな `tokenizer()` 関数を詳しく見て締めくくります。
