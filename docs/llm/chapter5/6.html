埋め込みを用いたセマンティック検索

Chapter 1 で見たように、Transformer ベースの言語モデルは、テキストに含まれる各トークンを埋め込みベクトルとして表現します。個々の埋め込みを「プーリング」することで、文全体、段落、あるいは（場合によっては）ドキュメント全体のベクトル表現を作れることが分かっています。これらの埋め込みを使えば、各埋め込みとの内積類似度（または他の類似度指標）を計算し、類似度が最も高いドキュメントを返すことで、コーパス内の類似ドキュメントを見つけることができます。

このセクションでは、埋め込みを使ってセマンティック検索エンジンを開発します。これらの検索エンジンには、クエリ内のキーワードとドキュメントをマッチさせる従来のアプローチに比べていくつかの利点があります。

ここでは `load_dataset()` でデフォルトの `train` 分割を指定したため、`DatasetDict` ではなく `Dataset` が返ります。最初に行うべきことは、プルリクエストを除外することです。プルリクエストはユーザーのクエリへの回答にはあまり使われず、検索エンジンにノイズを持ち込む傾向があるためです。既におなじみのはずですが、`Dataset.filter()` 関数を使えば、データセット内のこれらの行を除外できます。ついでに、コメントのない行も除外しましょう。これらはユーザーのクエリへの回答を提供しないためです。

```py

テキスト埋め込みの作成

Chapter 2 で見たように、AutoModel クラスを使えばトークン埋め込みを取得できます。必要なのは、モデルを読み込むのに適したチェックポイントを選ぶことだけです。幸い、埋め込みの作成に特化した sentence-transformers というライブラリがあります。ライブラリのドキュメントに記載されているように、私たちのユースケースは非対称セマンティック検索の例です。短いクエリがあり、その答えを issue のコメントのような長めのドキュメントの中から見つけたいためです。ドキュメントの便利なモデル概要表によれば、multi-qa-mpnet-base-dot-v1 チェックポイントがセマンティック検索で最良の性能を持つため、アプリケーションにはこれを使います。同じチェックポイントを使ってトークナイザも読み込みます。

前に述べたように、GitHub issues コーパスの各エントリを1つのベクトルとして表現したいので、トークン埋め込みを何らかの方法でプーリング（集約）する必要があります。平均化もその方法の1つです。人気のあるアプローチの1つは、モデルの出力に対して CLS プーリング を行うものです。これは、特殊トークン [CLS] の最後の隠れ状態を単に集める方法です。次の関数がその処理を行ってくれます。

def cls_pooling(model_output):
    return model_output.last_hidden_state[:, 0]

次に、ドキュメントのリストをトークナイズし、テンソルを GPU に配置して、モデルに入力し、最後に出力に CLS プーリングを適用するヘルパー関数を作成します。

def get_embeddings(text_list):
    encoded_input = tokenizer(

    )
    encoded_input = {k: v.to(device) for k, v in encoded_input.items()}
    model_output = model(**encoded_input)
    return cls_pooling(model_output)

FAISS による効率的な類似検索

埋め込みのデータセットが用意できたので、それらを検索する方法が必要です。そのために、🤗 Datasets の FAISS インデックスと呼ばれる特殊なデータ構造を使います。FAISS（Facebook AI Similarity Search の略）は、埋め込みベクトルをすばやく検索・クラスタリングするための効率的なアルゴリズムを提供するライブラリです。

FAISS の基本的な考え方は、インデックスと呼ばれる特殊なデータ構造を作成し、入力した埋め込みに類似する埋め込みを見つけられるようにすることです。🤗 Datasets で FAISS インデックスを作成するのは簡単です。Dataset.add_faiss_index() 関数を使い、データセットのどの列をインデックス化するかを指定します。

embeddings_dataset.add_faiss_index(column="embeddings")

これで、Dataset.get_nearest_examples() 関数による最近傍検索で、このインデックスに対してクエリを実行できます。まず、次のように質問を埋め込みにしてテストしてみましょう。
