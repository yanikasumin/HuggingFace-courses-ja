# 画像

コンピュータビジョンのコースで画像とは何かを説明するのは奇妙に思えるかもしれません。そもそもここにいるのは、画像や動画フォーマットの処理についてもっと知りたかったからでしょう。一見すると当たり前の話ですが、実は画像には意外と知られていない性質があります。文字どおり、見た目以上のものがあるのです（少し言葉遊びをしています）。

## 画像の定義

画像は、物体、シーン、人物、あるいは概念の視覚的な表現です。写真、絵画、ドローイング、図式、スキャンなどです！より驚くべきことの1つは、画像は関数でもあるということです。より正確には、画像は n 次元関数です。まず2次元 \\(n=2\\) として考えましょう。これを \\(F(X,Y)\\) と呼びます。ここで \\(X\\) と \\(Y\\) は空間座標です。仰々しい名前に惑わされないでください。空間座標とは、物理空間の中で物体がどこにあるかを表すためのものです。代表的な表し方は、2次元の直交座標系です。座標の組 \\(x_i, y_i\\) における F の振幅は、その点における画像の強度またはグレイレベルです。強度こそが、明暗の知覚を与えます。通常、座標の組 \\(x_1\\) と \\(y_1\\) を指すとき、それらをピクセル（picture element）と呼びます。

画像は離散的であり、それらを組み立てるプロセスは連続的です。画像生成プロセスについては次の章で議論します。いま重要なのは、特定の座標における \\(F\\) の値が物理的な意味を持つということです。関数 \\(F(X,Y)\\) は、光源からの照射量と、シーン内の物体が反射する照射量という2つの要素で特徴付けられます。画像は強度にも制約があります。関数は通常非負であり、その値は有限だからです。

画像を作る方法はそれだけではありません。コンピュータによって、AI の助けを借りて、あるいは借りずに作られることもあります。AI の助けを少し借りた画像については専用の章があります。ここで紹介する用語のほとんどは、そちらにも適用できます。

別のタイプの画像として、ボリューム画像や3D画像があります。3D画像の次元数は3です。その結果、\\(F(X,Y,Z)\\) 関数が得られます。私たちの議論のほとんどはそのまま当てはまります。唯一の違いは、3つ組 \\(x_i,y_i,z_i\\) がボクセル（volume element）と呼ばれることです。こうした画像は、取得したデータから3D空間内の構造を再構成できるように撮影することもできます。そのような画像の例には、医療スキャン、磁気共鳴、特定のタイプの顕微鏡が含まれます。2D画像から3D画像を再構成することも可能です。再構成は困難なタスクであり、これにも専用の章があります。

空間について議論したので、次は色について話しましょう。幸い、画像チャンネルについても聞いたことがあるでしょう。意味はわからなくても、心配いりません！画像チャンネルは、画像を構成するさまざまな色成分のことです。\\(F(X,Y)\\) に関連付ければ、色成分ごとに \\(F\\) を持つことになります。各色には独自の強度レベルがあります。赤色を取り込むチャンネルでは、強度が高いほどその色は非常に赤く、強度が低いほどそこには赤がほとんどないか、まったくないことを意味します。

1つの色だけに注目した \\(F(x,y)\\) は0から255の範囲で、0は強度なし、255は最大の強度を表します。異なる色体系では、これらの値の組み合わせ方が異なる場合があります。したがって、これらの値を解釈する際には、データの出所を理解することが重要です。

座標 \\(F(x_i,y_i)\\) が強度値を表すのではなく、ピクセルにラベルを付ける特殊なタイプの画像もあります。そのような画像を生む操作の最も単純な例は、前景と背景の分離です。前景であるものはすべてラベル1を、背景であるものはすべてラベル0を受け取ります。これらの画像は一般にラベル付き画像と呼ばれます。私たちの例のようにラベルが2つしかない場合、それらを二値画像またはマスクと呼びます。

4D画像や5D画像という言葉を聞いたことがあるかもしれません。この用語は主に生物医学分野の人々や顕微鏡の専門家によって使われます。ここでも心配いりません！この命名は、ボリュームデータを時間軸で、異なるチャンネルで、あるいは異なるイメージングモダリティ（写真と X 線など）で撮影する人々から生まれました。新しい情報源が加わるごとに、余分な次元になるという考え方です。したがって、5D画像は、時間軸で撮影され（4D）、異なるチャンネルを使った（5D）ボリューム画像（3D）です。

では、画像はコンピュータではどう表現されるのでしょうか？最も一般的なのは行列です。画像を2次元の数値配列としてイメージするのは簡単です。コンピュータは配列の扱いが非常に得意なので、これは利点です。行列を画像として見ることで、畳み込みニューラルネットワークや画像前処理におけるいくつかのプロセスを理解しやすくなります。詳細は後ほど見ていきます。

また、画像をグラフとして表現することもできます。この場合、各ノードは画像上の位置を表し、隣り合う位置のノード同士をエッジ（辺）で結びます。少し時間を取って、これを咀嚼してみてください。つまり、グラフに使うアルゴリズムやモデルを画像にも使えるということです！その逆も成り立ちます。グラフを画像に変換して、絵のように分析できます。

ここまで、画像についてかなり柔軟な定義を提案してきました。この定義は視覚データを取得するさまざまな方法に対応できますが、いずれも同じ重要な側面を浮き彫りにします。画像は、多くの空間情報を含むデータポイントだということです。主な違いは、空間解像度（2Dか3Dか）、色体系（RGB かその他か）、時間成分が付随するかどうかです。


## 画像と他のデータタイプ

### 画像と動画の違い

ここまでの説明を注意深く読んでいれば、動画は時間の経過とともに変化する画像の連続だと気付いたかもしれません。2D画像の取得については、時間次元を加えて \\(F(X,Y,T)\\) をイメージング関数にできます。

静止画像にも、暗黙の時間情報が含まれている場合があります。結局のところ、画像は特定の時点に撮影されたものであり、異なる画像同士が時間的に関連していることもあります。しかし、画像と動画では、この時間情報をサンプリングする方法が異なります。画像は単一時点における静的な表現であり、動画は動きの錯覚を生む速度で再生される画像の連続です。この速度が、フレーム毎秒と呼ばれるものです。

これは非常に基本的なことなので、このコースには動画専用の章があります。そこでは、この余分な次元に対処するために必要な適応を見ていきます。

### 画像と表形式データ

表形式データでは、次元数は通常、1つのデータポイントを記述する特徴量（列）の数で定義されます。視覚データでは、次元数は通常、データを記述する次元の数を指します。2D画像では、横方向と縦方向の画素数を画像サイズと呼びます。各画素の位置は、それぞれの方向の座標 \\(x_i\\) と \\(y_i\\) で表します。

 もう1つの側面は、視覚データを記述する特徴の生成です。それらは従来の前処理で生成されるか、深層学習の手法で学習されます。私たちはこれを特徴抽出と呼びます。これには、特徴抽出の章で詳しく議論されるさまざまなアルゴリズムが関わります。これは、既存の特徴の上に新しい特徴を構築する表形式データの特徴エンジニアリングとは対照的です。

表形式データでは、欠損値の処理、カテゴリ変数のエンコーディング、数値特徴の再スケーリングが必要なことがよくあります。画像データにおける類似のプロセスは、画像のリサイズと強度値の正規化です。私たちはこれらのプロセスを前処理と呼び、「コンピュータビジョンのための前処理」の章で詳しく議論します。
