数ギガバイト規模のデータセットを扱う場面は、近年では珍しくありません。BERT や GPT-2 のような Transformer をゼロから事前学習する場合が、その典型です。この規模になると、データを読み込む作業そのものが難しくなります。例えば、GPT-2 の事前学習に使われた WebText コーパスは、ドキュメントが800万件を超え、テキストの量は40 GB に達します。これをノートパソコンの RAM に丸ごと読み込もうとすれば、ノートパソコンが悲鳴を上げるでしょう。

幸い、🤗 Datasets はこの制約を避ける為に設計されています。方法は大きく分けて二通りあります。データセットをメモリマップドファイルとして扱い、メモリ管理の負担を取り除く方法と、コーパスの要素をストリーミングで読み取り、ハードドライブの容量に縛られない方法です。

## メモリマッピングの魔法[[the-magic-of-memory-mapping]]

Python でメモリ使用量を測るには、[`psutil`](https://psutil.readthedocs.io/en/latest/) ライブラリが手軽です。インストールは `pip` で次のように行います。

```python
!pip install psutil
```

このライブラリの `Process` クラスを使うと、現在のプロセスのメモリ使用量を次のように確認出来ます。

```py
import psutil

# Process.memory_info はバイト単位で表されるので、メガバイトに変換します
print(f"RAM 使用量: {psutil.Process().memory_info().rss / (1024 * 1024):.2f} MB")
```

```python out
RAM 使用量: 5678.33 MB
```

`rss` 属性は resident set size（常駐セットサイズ）のことです。これは、プロセスが RAM 上で占有しているメモリ量を表します。測定値には Python インタプリタや読み込んだライブラリの使用量も含まれる為、データセット自体が使う量はこれより少し小さくなります。比較として、ディスク上での大きさも見ておきます。`dataset_size` 属性で取得出来ます。こちらもバイト単位で返る為、ギガバイトへの変換は手動で行います。

```py
print(f"データセットのサイズ（バイト）: {pubmed_dataset.dataset_size}")
size_gb = pubmed_dataset.dataset_size / (1024**3)
print(f"データセットのサイズ（キャッシュファイル）: {size_gb:.2f} GB")
```

```python out
データセットのサイズ（バイト）: 20979437051
データセットのサイズ（キャッシュファイル）: 19.54 GB
```

データセットの大きさは 20 GB 近くあります。それでも、読み込みとアクセスに必要な RAM は、それを大幅に下回ります。

> [!TIP]
> ✏️ **やってみよう！** Pile の[サブセット](https://the-eye.eu/public/AI/pile_preliminary_components/)から、自分のノートパソコンやデスクトップの RAM より大きいものを1つ選び、Datasets で読み込んで RAM の使用量を測ってみましょう。正確な測定には、新しいプロセスで実行してください。各サブセットの解凍後のサイズは、[the Pile の論文](https://arxiv.org/abs/2101.00027)の表1に載っています。

Pandas に慣れている人には、この結果は意外に映るかもしれません。Wes Kinney の有名な[経験則](https://wesmckinney.com/blog/apache-arrow-pandas-internals/)によれば、必要な RAM は通常、データセットのサイズの5倍から10倍とされるからです。Datasets はこの問題を、メモリ管理の方法で解決しています。各データセットを[メモリマップドファイル](https://en.wikipedia.org/wiki/Memory-mapped_file)として扱うのです。メモリマップドファイルは RAM とファイルシステム上のストレージを対応付ける仕組みです。データセット全体をメモリに読み込まなくても、要素にアクセスして操作出来ます。

メモリマップドファイルは、複数のプロセスで共有することも出来ます。その為、`Dataset.map()` のようなメソッドを並列化する際に、データセットを移動したりコピーしたりする必要がありません。基盤になっているのは、[Apache Arrow](https://arrow.apache.org) のメモリ形式と [`pyarrow`](https://arrow.apache.org/docs/python/index.html) ライブラリです。これにより、データの読み込みと処理は非常に高速になります。Apache Arrow の詳細や Pandas との比較は、[Dejan Simic のブログ記事](https://towardsdatascience.com/apache-arrow-read-dataframe-with-zero-memory-69634092b1a)を参照してください。実際の速度を確かめる為、PubMed Abstracts データセットの全要素をたどる簡単なテストを行います。

```py
import timeit

code_snippet = """batch_size = 1000

for idx in range(0, len(pubmed_dataset), batch_size):
    _ = pubmed_dataset[idx:idx + batch_size]
"""

time = timeit.timeit(stmt=code_snippet, number=1, globals=globals())
print(
    f"{len(pubmed_dataset)} 件のサンプル（約 {size_gb:.1f} GB）を "
    f"{time:.1f} 秒で走査しました。処理速度: {size_gb/time:.3f} GB/秒"
)
```

```python out
'15518009 件のサンプル（約 19.5 GB）を 64.2 秒で走査しました。処理速度: 0.304 GB/秒'
```

ここでは Python の `timeit` モジュールで、`code_snippet` の実行時間を測っています。走査の速度は通常、1秒あたり数百 MB から数 GB です。大半の用途ではこの速度で十分です。但し、データセットが更に大きくなると、別の問題が出てきます。ノートパソコンのハードドライブにすら保存出来ない場合があるのです。

例えば、Pile 全体をダウンロードするには、825 GB の空きディスク容量が必要です。こうしたケースの為に用意されているのが、ストリーミング機能です。データセット全体をダウンロードせず、要素をその都度取得して使えます。次に、その仕組みを見ていきます。

> [!TIP]
> 💡 Jupyter ノートブックでは、[`%%timeit` マジック関数](https://ipython.readthedocs.io/en/stable/interactive/magics.html#magic-timeit)を使ってセルの時間を測ることも出来ます。

## データセットのストリーミング[[streaming-datasets]]

ストリーミングを有効にする方法は簡単です。`load_dataset()` 関数に `streaming=True` 引数を渡すだけです。例として、PubMed Abstracts データセットをストリーミングモードで読み込み直してみましょう。

```py
pubmed_dataset_streamed = load_dataset(
    "json", data_files=data_files, split="train", streaming=True
)
```

戻り値は、この章で見てきた `Dataset` とは異なります。`streaming=True` を指定すると、`IterableDataset` オブジェクトが返されます。名前の通り、`IterableDataset` の要素へは反復処理でアクセスします。最初の要素は、次のように取得出来ます。


```py
next(iter(pubmed_dataset_streamed))
```

```python out
{'meta': {'pmid': 11409574, 'language': 'eng'},
 'text': 'Epidemiology of hypoxaemia in children with acute lower respiratory infection.\nTo determine the prevalence of hypoxaemia in children aged under 5 years suffering acute lower respiratory infections (ALRI), the risk factors for hypoxaemia in children under 5 years of age with ALRI, and the association of hypoxaemia with an increased risk of dying in children of the same age ...'}
```

ストリーミングしたデータセットの要素は、`IterableDataset.map()` でその場で処理出来ます。訓練時に入力をトークナイズする場合等に便利です。手順は[第3章](/course/chapter3) でトークナイズした時と全く同じで、異なるのは出力が1つずつ返される点だけです。

```py
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("distilbert-base-uncased")
tokenized_dataset = pubmed_dataset_streamed.map(lambda x: tokenizer(x["text"]))
next(iter(tokenized_dataset))
```

```python out
{'input_ids': [101, 4958, 5178, 4328, 6779, ...], 'attention_mask': [1, 1, 1, 1, 1, ...]}
```

> [!TIP]
> 💡 トークナイズを高速化するには、前のセクションと同様に `batched=True` を渡します。処理はバッチ単位で行われます。バッチサイズの既定値は1,000で、`batch_size` 引数で変更出来ます。

シャッフルも可能です。ストリーミングしたデータセットでは `IterableDataset.shuffle()` を使います。但し、`Dataset.shuffle()` とは違い、シャッフルの範囲は `buffer_size` で指定したバッファ内の要素に限られます。

```py
shuffled_dataset = pubmed_dataset_streamed.shuffle(buffer_size=10_000, seed=42)
next(iter(shuffled_dataset))
```

```python out
{'meta': {'pmid': 11410799, 'language': 'eng'},
 'text': 'Randomized study of dose or schedule modification of granulocyte colony-stimulating factor in platinum-based chemotherapy for elderly patients with lung cancer ...'}
```

（サンプル文の訳：「高齢の肺がん患者に対する白金製剤ベースの化学療法における顆粒球コロニー刺激因子の用量又はスケジュール変更に関する無作為化研究…」という途中までです）

この例では、バッファの先頭10,000件の中からランダムに1件を選んでいます。選んだサンプルの場所は空きますが、そこにはコーパスの次のサンプル、つまり10,001番目のサンプルが補充されます。要素の選択には、`Dataset.select()` に似た `IterableDataset.take()` と `IterableDataset.skip()` も使えます。例えば、PubMed Abstracts データセットの最初の5件を選ぶ場合は、次のようにします。

```py
dataset_head = pubmed_dataset_streamed.take(5)
list(dataset_head)
```

同じ要領で、`IterableDataset.skip()` 関数を使えば、シャッフル済みのデータセットを訓練用と検証用に分割出来ます。

```py
# 最初の1,000件のサンプルをスキップし、残りを訓練セットに含めます
train_dataset = shuffled_dataset.skip(1000)
# 最初の1,000件のサンプルを検証セット用に取得します
validation_dataset = shuffled_dataset.take(1000)
```

最後に、複数のデータセットを組み合わせて1つのコーパスにする方法を見ます。これはよくある使い方です。Datasets の `interleave_datasets()` 関数は、`IterableDataset` オブジェクトのリストを受け取り、1つの `IterableDataset` に変換します。新しいデータセットの要素は、元のデータセットから交互に取り出されます。大きなデータセット同士の組み合わせで特に便利な関数です。例として、Pile の FreeLaw サブセットをストリーミングします。これは米国の裁判所の判決文を集めた51 GB のデータセットです。

> [!TIP]
> ✏️ **やってみよう！** [`mc4`](https://huggingface.co/datasets/mc4) や [`oscar`](https://huggingface.co/datasets/oscar) のような大規模な Common Crawl コーパスの1つを使って、選んだ国における各言語の話者比率を反映したストリーミング多言語データセットを作ってみましょう。例えば、スイスにはドイツ語、フランス語、イタリア語、ロマンシュ語という4つの国語（国家言語）があるので、Oscar のサブセットを各言語の話者割合に応じてサンプリングし、スイスのコーパスを作ってみることが出来ます。

これで、形や大きさの異なるあらゆるデータセットを読み込み、処理する手段が揃いました。但し、NLP に取り組む中では、自分でデータセットを作成しなければならない場面が必ず訪れます。よ程幸運な場合を除けば、避けては通れません。それが次のセクションのテーマです。
