Transformer モデルを使う多くの NLP アプリケーションでは、Hugging Face Hub から事前学習済みモデルを持ってきて、手元のタスクのために自分のデータで直接ファインチューニングできます。事前学習に使われたコーパスとファインチューニングに使うコーパスが大きく異ならなければ、転移学習によって通常は良い結果が得られます。

しかし、タスク固有のヘッドを学習する前に、まず自分のデータで言語モデルをファインチューニングしたい場合もいくつかあります。たとえば、データセットに法律契約書や科学論文が含まれている場合、BERT のような素の Transformer モデルは、コーパス中のドメイン固有の単語を通常、珍しいトークンとして扱うため、得られる性能は満足のいくものにならないかもしれません。ドメイン内のデータで言語モデルをファインチューニングすれば、多くの下流タスクの性能を向上させることができ、しかもこのステップは通常一度だけ行えば済みます！

事前学習済みの言語モデルをドメイン内のデータでファインチューニングするこのプロセスは、一般にドメイン適応と呼ばれます。これは 2018 年に ULMFiT によって広められました。ULMFiT は、NLP で転移学習を実際に機能させた最初期のニューラルアーキテクチャ（LSTM ベース）の1つです。ULMFiT によるドメイン適応の例を下の画像に示します。このセクションでは似たようなことを行いますが、LSTM の代わりに Transformer を使います！

まず、マスク言語モデリングに適した事前学習済みモデルを選びましょう。次のスクリーンショットに示すように、Hugging Face Hub で「Fill-Mask」フィルタを適用すれば、候補の一覧が見つかります。

BERT と RoBERTa のファミリーのモデルが最も多くダウンロードされていますが、ここでは DistilBERT というモデルを使います。下流の性能をほとんど落とすことなく、はるかに速く学習できるためです。このモデルは、知識蒸留と呼ばれる特殊な手法で学習されました。これは、BERT のような大きな「教師モデル」を使って、はるかにパラメータの少ない「生徒モデル」の学習を導く手法です。知識蒸留の詳細を説明するとこのセクションの範囲をはるかに超えてしまうため、興味のある方は Natural Language Processing with Transformers（通称 Transformers の教科書）で詳しく読んでください。

## データの前処理








因果言語モデリングとマスク言語モデリングのどちらでも、一般的な前処理のステップは、すべてのサンプルを連結してから、コーパス全体を等しいサイズのチャンクに分割することです。これは、個々のサンプルを単にトークン化する通常のアプローチとはかなり異なります。なぜすべてを連結するのでしょうか？個々のサンプルが長すぎると切り捨てられる可能性があり、言語モデリングタスクに役立つかもしれない情報が失われてしまうためです！

そこでまず、通常どおりコーパスをトークン化しますが、トークナイザで `truncation=True` オプションを*設定しません*。また、単語 ID が利用可能であれば（[Chapter 6](/course/chapter6/3) で説明したように、高速トークナイザを使っていれば利用可能です）取得しておきます。後で全単語マスキングを行う際に必要になるためです。これをシンプルな関数にまとめ、ついでに、もう必要のない `text` 列と `label` 列を取り除きます。

```python
def tokenize_function(examples):
    result = tokenizer(examples["text"])
    if tokenizer.is_fast:
        result["word_ids"] = [result.word_ids(i) for i in range(len(result["input_ids"]))]
    return result


# batched=True を使って高速なマルチスレッディングを有効化！
tokenized_datasets = imdb_dataset.map(
    tokenize_function, batched=True, remove_columns=["text", "label"]
)
tokenized_datasets

```python out DatasetDict({ train: Dataset({ features: ['attention_mask', 'input_ids', 'word_ids'], num_rows: 25000 }) test: Dataset({ features: ['attention_mask', 'input_ids', 'word_ids'], num_rows: 25000 }) unsupervised: Dataset({ features: ['attention_mask', 'input_ids', 'word_ids'], num_rows: 50000 }) })

DistilBERT は BERT 系のモデルなので、エンコードされたテキストは、他の章で見てきた `input_ids` と `attention_mask` に、追加した `word_ids` を加えたもので構成されていることが分かります。

映画レビューをトークン化したので、次のステップは、それらをすべてまとめて、結果をチャンクに分割することです。しかし、これらのチャンクはどれくらいの大きさにすべきでしょうか？これは最終的には利用可能な GPU メモリの量で決まりますが、良い出発点は、モデルの最大コンテキストサイズを確認することです。これは、トークナイザの `model_max_length` 属性を調べれば推測できます。

```python
tokenizer.model_max_length

```python out 512

この値は、チェックポイントに関連付けられた *tokenizer_config.json* ファイルから導出されます。この場合、コンテキストサイズは BERT と同じく512トークンであることが分かります。

この例で分かるように、最後のチャンクは一般に最大のチャンクサイズより小さくなります。これに対処する主な戦略は2つあります。

* 最後のチャンクが `chunk_size` より小さい場合は破棄する。
* 最後のチャンクを、その長さが `chunk_size` と等しくなるまでパディングする。

ここでは1つ目のアプローチを取ります。そこで、上記のすべてのロジックを、トークン化したデータセットに適用できる単一の関数にまとめましょう。

```python
def group_texts(examples):
    # すべてのテキストを連結する
    concatenated_examples = {k: sum(examples[k], []) for k in examples.keys()}
    # 連結したテキストの長さを計算する
    total_length = len(concatenated_examples[list(examples.keys())[0]])
    # 最後のチャンクが chunk_size より小さい場合は破棄する
    total_length = (total_length // chunk_size) * chunk_size
    # max_len のチャンクに分割する
    result = {
        k: [t[i : i + chunk_size] for i in range(0, total_length, chunk_size)]
        for k, t in concatenated_examples.items()
    }
    # 新しい labels 列を作成する
    result["labels"] = result["input_ids"].copy()
    return result

group_texts() の最後のステップでは、input_ids 列のコピーである新しい labels 列を作成していることに注意してください。すぐに分かるように、これは、マスク言語モデリングの目的が入力バッチ内のランダムにマスクされたトークンを予測することであり、labels 列を作成することで、言語モデルが学習するための正解データを提供するためです。

マスク言語モデルの学習の際には、個々のトークンだけでなく単語全体をまとめてマスクする手法も使えます。このアプローチは*全単語マスキング*と呼ばれます。全単語マスキングを使いたい場合は、データコレータを自分で構築する必要があります。データコレータは、サンプルのリストを受け取ってバッチに変換する単なる関数なので、早速作ってみましょう！先に計算した単語 ID を使って、単語のインデックスと対応するトークンの間のマップを作成し、次にどの単語をマスクするかをランダムに決めて、そのマスクを入力に適用します。ラベルはすべて `-100` で、マスクする単語に対応するものだけが例外であることに注意してください。

{#if fw === 'pt'}

```py
import collections
import numpy as np

from transformers import default_data_collator

wwm_probability = 0.2


def whole_word_masking_data_collator(features):
    for feature in features:
        word_ids = feature.pop("word_ids")

        # 単語と対応するトークンのインデックスの間のマップを作成する
        mapping = collections.defaultdict(list)
        current_word_index = -1
        current_word = None
        for idx, word_id in enumerate(word_ids):
            if word_id is not None:
                if word_id != current_word:
                    current_word = word_id
                    current_word_index += 1
                mapping[current_word_index].append(idx)

        # 単語をランダムにマスクする
        mask = np.random.binomial(1, wwm_probability, (len(mapping),))
        input_ids = feature["input_ids"]
        labels = feature["labels"]
        new_labels = [-100] * len(labels)
        for word_id in np.where(mask)[0]:
            word_id = word_id.item()
            for idx in mapping[word_id]:
                new_labels[idx] = labels[idx]
                input_ids[idx] = tokenizer.mask_token_id
        feature["labels"] = new_labels

    return default_data_collator(features)

言語モデルのパープレキシティ

テキスト分類や質問応答のような他のタスクでは、学習用のラベル付きコーパスが与えられますが、言語モデリングには明示的なラベルがありません。では、良い言語モデルとは何によって決まるのでしょうか？スマートフォンの自動修正機能のように、良い言語モデルは、文法的に正しい文には高い確率を、意味をなさない文には低い確率を割り当てます。これがどのようなものかよりよく分かるように、オンラインでは「autocorrect fails」のコレクション全体が見つかります。そこでは、ある人のスマートフォンのモデルが、かなり面白い（そしてしばしば不適切な）補完を生み出しています！

{#if fw === 'pt'}

テストセットが主に文法的に正しい文で構成されていると仮定すると、言語モデルの品質を測る1つの方法は、テストセットのすべての文における次の単語にモデルが割り当てる確率を計算することです。確率が高いことは、モデルが見たことのないサンプルに「驚いて」おらず、つまり「困惑（perplexed）」しておらず、その言語の文法の基本パターンを学習したことを示唆します。パープレキシティにはさまざまな数学的定義がありますが、ここで使うものは、交差エントロピー損失の指数として定義します。したがって、事前学習済みモデルのパープレキシティは、Trainer.evaluate() 関数を使ってテストセットの交差エントロピー損失を計算し、その結果の指数を取ることで計算できます。

import math

eval_results = trainer.evaluate()
print(f">>> パープレキシティ: {math.exp(eval_results['eval_loss']):.2f}")

DistilBERT を 🤗 Accelerate でファインチューニングする

Trainer で見たように、マスク言語モデルのファインチューニングは、Chapter 3 のテキスト分類の例と非常によく似ています。実際、唯一の注意点は専用のデータコレータの使用であり、それはこのセクションですでに扱いました！

しかし、DataCollatorForLanguageModeling は評価のたびにもランダムマスキングを適用するため、学習を実行するたびにパープレキシティのスコアに変動が見られます。このランダム性の源を取り除く1つの方法は、テストセット全体にマスキングを一度だけ適用し、評価の際には 🤗 Transformers のデフォルトのデータコレータを使ってバッチを集めることです。これがどのように機能するかを見るため、DataCollatorForLanguageModeling との最初の出会いと同様に、バッチにマスキングを適用するシンプルな関数を実装しましょう。

def insert_random_mask(batch):
    features = [dict(zip(batch, t)) for t in zip(*batch.values())]
    masked_inputs = data_collator(features)
    # データセットの各列について、新しい「masked」列を作成する
    return {"masked_" + k: v.numpy() for k, v in masked_inputs.items()}

次に、この関数をテストセットに適用し、マスクされていない列を取り除いて、マスクされた列に置き換えられるようにします。上の data_collator を適切なものに置き換えれば全単語マスキングも使えます。その場合は、ここの最初の行を取り除いてください。

downsampled_dataset = downsampled_dataset.remove_columns(["word_ids"])
eval_dataset = downsampled_dataset["test"].map(
    insert_random_mask,
    batched=True,
    remove_columns=downsampled_dataset["test"].column_names,
)
eval_dataset = eval_dataset.rename_columns(
    {
        "masked_input_ids": "input_ids",
        "masked_attention_mask": "attention_mask",
        "masked_labels": "labels",
    }
)

次に、通常どおりデータローダを設定できますが、評価セットには 🤗 Transformers の default_data_collator を使います。

from torch.utils.data import DataLoader
from transformers import default_data_collator

batch_size = 64
train_dataloader = DataLoader(
    downsampled_dataset["train"],
    shuffle=True,
    batch_size=batch_size,
    collate_fn=data_collator,
)
eval_dataloader = DataLoader(
    eval_dataset, batch_size=batch_size, collate_fn=default_data_collator
)

ここからは、🤗 Accelerate の標準的な手順に従います。まず最初に行うのは、事前学習済みモデルの新しいコピーを読み込むことです。

model = AutoModelForMaskedLM.from_pretrained(model_checkpoint)

次にオプティマイザを指定する必要があります。標準の AdamW を使います。

from torch.optim import AdamW

optimizer = AdamW(model.parameters(), lr=5e-5)

これらのオブジェクトを使って、Accelerator オブジェクトで学習の準備ができます。

from accelerate import Accelerator

accelerator = Accelerator()
model, optimizer, train_dataloader, eval_dataloader = accelerator.prepare(
    model, optimizer, train_dataloader, eval_dataloader
)

モデル、オプティマイザ、データローダが設定できたので、学習率スケジューラを次のように指定できます。

from transformers import get_scheduler

num_train_epochs = 3
num_update_steps_per_epoch = len(train_dataloader)
num_training_steps = num_train_epochs * num_update_steps_per_epoch

lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)

from huggingface_hub import get_full_repo_name

これで、あとは完全な学習ループと評価ループを書き出すだけです。

from tqdm.auto import tqdm
import torch
import math

progress_bar = tqdm(range(num_training_steps))

for epoch in range(num_train_epochs):
    # 学習
    model.train()
    for batch in train_dataloader:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

    # 評価
    model.eval()
    losses = []
    for step, batch in enumerate(eval_dataloader):
        with torch.no_grad():
            outputs = model(**batch)

        loss = outputs.loss
        losses.append(accelerator.gather(loss.repeat(batch_size)))

    losses = torch.cat(losses)
    losses = losses[: len(eval_dataset)]
    try:
        perplexity = math.exp(torch.mean(losses))
    except OverflowError:
        perplexity = float("inf")

    print(f">>> エポック {epoch}: パープレキシティ: {perplexity}")

    # 保存とアップロード
    accelerator.wait_for_everyone()
    unwrapped_model = accelerator.unwrap_model(model)
    unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
    if accelerator.is_main_process:
        tokenizer.save_pretrained(output_dir)
        repo.push_to_hub(
            commit_message=f"Training in progress epoch {epoch}", blocking=False
        )
