DeepSeek R1 論文を理解する

このセクションでは、DeepSeek R1 の論文を短時間で読み解きます。まず論文の内容を平易な言葉で説明し、その後、重要な概念とポイントを詳しく見ていきます。

DeepSeek R1 は、言語モデルの学習における大きな進歩を表しており、特に強化学習を通じた推論能力の開発で顕著です。この論文は、Group Relative Policy Optimization（GRPO）と呼ばれる新しい強化学習アルゴリズムを導入しています。

次の章では、この知識をもとに、GRPO を実践で実装します。

この論文の当初の目的は、純粋な強化学習が、教師ありファインチューニングなしに推論能力を発達させることができるかを探ることでした。

💡 ヒント

その時点までは、人気のある LLM はすべて何らかの教師ありファインチューニングを必要としていました。第11章で探ったとおりです。

画期的な「Aha モーメント」

R1-Zero の学習における最も注目すべき発見の一つは、「Aha モーメント」として知られる現象の出現でした。この現象は、人間が問題を解くときに突然ひらめく感覚とやや似ています。その仕組みは次のとおりです。

  1. 初期の試行： モデルが問題を解くための最初の試みを行う
  2. 気づき： 潜在的な誤りや不整合に気づく
  3. 自己修正： この気づきに基づいてアプローチを調整する
  4. 説明： 新しいアプローチがなぜ優れているかを説明できる

この現象は、人間が問題を解くときに突然答えをひらめく「ユーレカ！」の瞬間を思い起こさせます。単に学習データを暗記しているのではなく、モデルが学習を通じて新たな問題解決の振る舞いを獲得していることを示す例として注目されています。少し立ち止まって、「Aha」モーメントとはどんな感覚か、想像してみましょう。

たとえば、パズルを解こうとしていると想像してください。 - 最初の試み： 「色からすると、このピースはここに入るはず」 - 気づき： 「でも待って、形がぴったり合わない」 - 修正： 「ああ、実際はあちらに入るんだ」 - 説明： 「この位置では、色も形のパターンも両方一致するから」

この能力は、明示的にプログラムされたわけではなく、RL 学習から自然に出現しました。これは、学習データからのプロセスの単なる暗記ではなく、学習が起きていることを示しています。

「Aha モーメント」を理解する最も簡単な方法は、実際に動作しているところを見ることです。例を見てみましょう。以下のチャットでは、モデルに問題を解くよう依頼し、UI が問題を解く過程でのモデルの思考プロセスを表示します。

Deepseek の R1 を試したい方は、Hugging Chat もチェックできます。

学習プロセス

R1 の学習は複数フェーズのプロセスでした。各フェーズと、そのフェーズにおける主要な革新を分解してみましょう。

最終的なプロセスからは、2つのモデルが生まれます。 - DeepSeek-R1-Zero： 純粋に強化学習を使って学習されたモデル。 - DeepSeek-R1： DeepSeek-R1-Zero の基盤の上に構築され、教師ありファインチューニングを追加したモデル。

特徴 DeepSeek-R1-Zero DeepSeek-R1
学習アプローチ 純粋な RL 複数フェーズ（SFT + RL）
ファインチューニング なし 教師ありファインチューニング
推論能力 創発的 強化済み
AIME の性能 71.0% 79.8%
主な特徴 強い推論能力だが可読性に課題 言語の一貫性と可読性が向上

DeepSeek-R1-Zero は、推論能力の開発における純粋な強化学習の可能性を示しています。一方 DeepSeek-R1 は、この基盤の上に、推論性能と使いやすさの両方を優先する、よりバランスの取れたアプローチで構築されています。

学習プロセスは4つのフェーズから構成されます。

  1. Cold Start フェーズ
  2. Reasoning RL フェーズ
  3. Rejection Sampling フェーズ
  4. Diverse RL フェーズ

各フェーズを分解してみましょう。

Cold Start フェーズ（品質の基盤）

このフェーズは、モデルの可読性と応答品質のための強固な基盤を確立するために設計されています。R1-Zero からの高品質なサンプルの小規模なデータセットを使って、V3-Base モデルをファインチューニングします。DeepSeek-V3-Base モデルを出発点として、チームは R1-Zero からの検証済みの高品質サンプル数千件を教師ありファインチューニングに使いました。この革新的なアプローチは、小規模だが高品質なデータセットを使って、強固なベースラインの可読性と応答品質を確立します。

Reasoning RL フェーズ（能力の構築）

Reasoning RL フェーズは、数学、コーディング、科学、論理などの分野にわたる中核的な推論能力の開発に焦点を当てます。このフェーズではルールベースの強化学習が用いられ、報酬は解の正しさに直接結び付けられています。

重要なことに、このフェーズのタスクはすべて「検証可能」であり、モデルの答えが正しいかどうかを確認できます。たとえば数学の場合、数式ソルバーを使ってモデルの答えが正しいかを確認できます。

このフェーズが特に革新的なのは、直接的な最適化アプローチにより、別の報酬モデルが不要になり、学習プロセスが効率化される点です。

Rejection Sampling フェーズ（品質管理）

Rejection Sampling フェーズでは、モデルがサンプルを生成し、それらが品質管理プロセスでフィルタリングされます。DeepSeek-V3 が品質の審査役を務め、純粋な推論タスクを超えた幅広い範囲で出力を評価します。フィルタリングされたデータは、その後、教師ありファインチューニングに使われます。このフェーズの革新は、複数の品質信号を組み合わせて、高水準の出力を保証できる点にあります。

Diverse RL フェーズ（幅広いアライメント）

最後の Diverse RL フェーズは、洗練されたハイブリッドアプローチを使って、複数のタスクタイプに取り組みます。決定論的なタスクにはルールベースの報酬を用い、主観的なタスクは LLM のフィードバックで評価します。このフェーズは、ルールベースシステムの正確さと、言語モデルによる評価の柔軟性を組み合わせた革新的なハイブリッド報酬アプローチを通じて、人間の選好へのアライメントの達成を目指します。

アルゴリズム： Group Relative Policy Optimization（GRPO）

学習プロセスについて良い理解が得られたところで、モデルの学習に使われたアルゴリズムを見てみましょう。

著者らは、GRPO をモデルのファインチューニングにおけるブレークスルーと述べています。

GRPO の新規性は、選好の修正を目的として、方策を直接最適化できる点にあります。これは、PPO のような従来の強化学習アルゴリズムと比べて、より直接的で効率的な、モデルを望ましい出力に合わせるための経路を意味します。GRPO の仕組みを、その3つの主要な構成要素に分解してみましょう。

グループの形成： 複数の解を作る

GRPO の最初のステップは驚くほど直感的です。難しい問題を解くときに、学生が複数のアプローチを試すのと似ています。プロンプトが与えられると、モデルは1つの応答だけを生成するのではありません。代わりに、同じ問題を解く複数の試行（通常は4、8、または16通りの異なる試行）を作成します。

モデルに数学の問題を解くことを教えていると想像してください。農場のニワトリを数える質問について、モデルは次のようないくつかの異なる解を生成するかもしれません。 - ある解は、問題を段階的に分解するかもしれません。まずニワトリの総数を数え、次に雄鶏を引き、最後に産卵しない雌鶏を考慮する、といった具合です - 別の解は、異なるが同様に有効なアプローチを使うかもしれません - 一部の試行には、誤りや非効率な解が含まれているかもしれません

これらすべての試行はグループとしてまとめられます。複数の学生の解答を比較し、そこから学ぶようなものです。

選好の学習： 良い解とは何かを理解する

ここが、GRPO がそのシンプルさで真価を発揮するところです。別の報酬モデルを常に必要として、解がどれだけ優れているかを予測する他の RLHF 手法とは異なり、GRPO は任意の関数やモデルを使って解の品質を評価できます。たとえば、長さの関数を使って短い応答に報酬を与えたり、数式ソルバーを使って正確な数学の解に報酬を与えたりできます。

評価プロセスでは、各解のさまざまな側面を見ます。 - 最終的な答えは正しいか？ - 解は適切な形式に従っているか（適切な XML タグを使うなど）？ - 推論は提示された答えと一致しているか？

このアプローチが特に巧妙なのは、スコア付けの扱い方です。単に絶対的なスコアを与えるのではなく、GRPO は各グループ内で報酬を正規化します。グループ相対アドバンテージの推定には、シンプルだが効果的な次の式を使います。

Advantage = (reward - mean(group_rewards)) / std(group_rewards)

この正規化は、AI のための相対評価のようなものです。絶対的なスコアだけを見るのではなく、グループ内の解が仲間と比較して優れていたのか劣っていたのかをモデルが理解する助けになります。

最適化： 経験から学ぶ

最後のステップでは、GRPO が、解のグループの評価から学んだことをもとに、モデルに改善方法を教えます。このプロセスは強力であり、かつ安定しており、2つの主要な原則を使います。

  1. 成功した解のようなものをより多く生成し、効果の低いアプローチから離れるよう、モデルを促す
  2. モデルが一度に大きく変化しすぎることを防ぐ安全機構（KL ダイバージェンスのペナルティと呼ばれる）を含む

このアプローチが従来の手法より安定しているのは、以下の理由によります。 - 2つずつ比較するのではなく、複数の解を一緒に見る - グループベースの正規化により、報酬のスケーリングの問題を防ぎやすい - KL ペナルティが安全網として働き、モデルが新しいことを学ぶ間に、すでに知っていることを忘れないようにする

💡 ヒント

GRPO の主要な革新は次のとおりです。 - 任意の関数やモデルから直接学習し、別の報酬モデルへの依存を排除する。 - グループベースの学習であり、ペアワイズ比較のような従来の手法よりも安定し、効率的である。

この分解は複雑ですが、重要なポイントは、GRPO がモデルに推論を学習させるための、より効率的で安定した方法であるということです。

GRPO アルゴリズムの疑似コード

GRPO の主要な構成要素を理解したところで、アルゴリズムを疑似コードで見てみましょう。これは簡略化したバージョンですが、重要な考え方は捉えています。

入力:
- initial_policy: 学習対象となる初期モデル
- reward_function: 出力を評価する関数
- training_prompts: 学習用プロンプトの集合
- group_size: プロンプトごとの生成数（通常 4〜16）

アルゴリズム GRPO:
1. 学習の各反復について:
   a. reference_policy = initial_policy とする（現在の方策のスナップショット）
   b. バッチ内の各プロンプトについて:
      i. initial_policy を使って group_size 件の異なる出力を生成する
      ii. reward_function を使って各出力の報酬を計算する
      iii. グループ内で報酬を正規化する:
           normalized_advantage = (reward - mean(rewards)) / std(rewards)
      iv. クリップした比を最大化するように方策を更新する:
          min(prob_ratio * normalized_advantage,
              clip(prob_ratio, 1-epsilon, 1+epsilon) * normalized_advantage)
          - kl_weight * KL(initial_policy || reference_policy)

          ここで prob_ratio は current_prob / reference_prob

出力: 最適化された方策モデル

このアルゴリズムは、GRPO がグループベースのアドバンテージ推定と方策最適化を組み合わせ、クリッピングと KL ダイバージェンスの制約によって安定性を維持する様子を示しています。

GRPO の限界と課題

GRPO は言語モデルのための強化学習における大きな進歩を表していますが、その限界と課題を理解することも重要です。

  • 生成コスト： 各プロンプトに対して複数の補完（4〜16件）を生成すると、1〜2件しか生成しない手法と比較して、必要な計算量が増えます。
  • バッチサイズの制約： 補完のグループをまとめて処理する必要性が、実効的なバッチサイズを制限し、学習プロセスを複雑にし、学習が遅くなる可能性があります。
  • 報酬関数の設計： 学習の質は、適切に設計された報酬関数に大きく依存します。設計が不十分な報酬は、意図しない振る舞いや、誤った目的への最適化につながることがあります。
  • グループサイズのトレードオフ： 最適なグループサイズの選択には、解の多様性と計算コストのバランスを取る必要があります。サンプルが少なすぎると十分な多様性が得られないかもしれませんし、多すぎると学習時間とリソースの要求が増えます。
  • KL ダイバージェンスの調整： KL ダイバージェンスのペナルティの適切なバランスを見つけるには、慎重な調整が必要です。高すぎるとモデルは効果的に学習できず、低すぎると当初の能力から乖離しすぎるかもしれません。

結論

DeepSeek R1 論文は、言語モデルの開発における重要なマイルストーンです。Group Relative Policy Optimization（GRPO）アルゴリズムは、純粋な強化学習でも実際に強い推論能力を発達させることができることを示し、教師ありファインチューニングの必要性に関する従来の前提に疑問を投げかけました。

おそらく最も重要なのは、DeepSeek R1 が、高い性能と、費用対効果やアクセスしやすさといった実用的な配慮とのバランスを取り得ることを示したことです。パラメータ数1.5Bから70Bまで、異なるサイズへの能力の蒸留が成功したことは、高度な AI の能力をより広く利用可能にするための道を示しています。

次のセクションでは、これらの概念の実践的な実装を探り、皆さん自身の言語モデル開発プロジェクトで GRPO と RFTrans をどう活用するかに焦点を当てます。

クイズ

1. DeepSeek R1 論文の主な革新は何ですか？

正解です！GRPO の主要な革新は、選好の修正を目的として方策を直接最適化できる点であり、従来の RL 手法より効率的です。
この論文の革新は、使われた計算リソースではなく、アルゴリズムのアプローチ（GRPO）にあります。
革新はモデルの大きさではなく、学習方法と GRPO アルゴリズムにあります。

2. DeepSeek R1 の学習プロセスの4つのフェーズは何ですか？

正解です！これらは論文で説明された正確な4つのフェーズであり、それぞれが学習パイプラインで特定の目的を果たします。
この論文では、異なる4つのフェーズを具体的に述べています。Cold Start（品質の基盤）、Reasoning RL（能力の構築）、Rejection Sampling（品質管理）、Diverse RL（幅広いアライメント）です。
この論文では、Cold Start、Reasoning RL、Rejection Sampling、Diverse RL のフェーズを含む、特定の4フェーズのプロセスを説明しています。

3. R1-Zero の学習における「Aha モーメント」現象とは何ですか？

正解です！論文では、これを4ステップのプロセスとして説明しています。初期の試行、誤りの認識、自己修正、改善の説明です。
「Aha モーメント」は、人間の問題解決におけるひらめきと同様に、モデルが自らの誤りに気づき、正す能力を指します。
「Aha モーメント」は学習の完了ではなく、問題解決の最中にモデルが誤りに気づき、自己修正する創発的な能力に関するものです。

4. GRPO のグループ形成はどのように機能しますか？

正解です！GRPO は同じ問題を解く複数の試行（通常は4、8、または16通り）を生成し、それらをグループとして評価します。
GRPO は複数の異なるモデルのアンサンブルではなく、1つのモデルを使って複数の解の試行を生成します。
GRPO のグループ形成は、学習データを分割することではなく、同じ問題に対する複数の解を生成することです。

5. DeepSeek-R1-Zero と DeepSeek-R1 の主な違いは何ですか？

正解です！比較表のとおり、R1-Zero は純粋な RL 学習を使い、R1 は教師ありファインチューニングと RL を組み合わせた複数フェーズのアプローチを使い、その結果、言語の一貫性が向上しています。
違いはモデルの大きさではなく、学習アプローチ（純粋な RL 対 複数フェーズ）にあります。
主な違いは学習方法です。R1-Zero は純粋な RL、R1 は SFT と RL を組み合わせたアプローチです。
