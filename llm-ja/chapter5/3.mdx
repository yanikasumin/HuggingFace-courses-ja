## データを切り分けて加工する[[slicing-and-dicing-our-data]]

Pandas と同様に、Datasets には `Dataset` オブジェクトや `DatasetDict` オブジェクトの内容を操作する関数がいくつも用意されています。`Dataset.map()` メソッドは [Chapter 3](/course/chapter3) で既に紹介しました。このセクションでは、それ以外に使える関数を見ていきます。

この例では、[UC Irvine Machine Learning Repository](https://archive.ics.uci.edu/ml/index.php) で公開されている [Drug Review Dataset](https://archive.ics.uci.edu/ml/datasets/Drug+Review+Dataset+%28Drugs.com%29) を使います。これは、様々な薬に対する患者のレビューと、治療対象の症状、患者の満足度を示す10点満点の星評価を収めたデータセットです。

まず、`wget` コマンドと `unzip` コマンドでデータをダウンロードして展開する必要があります。

```py
!wget "https://archive.ics.uci.edu/ml/machine-learning-databases/00462/drugsCom_raw.zip"
!unzip drugsCom_raw.zip
```

TSV は、区切り文字にカンマではなくタブを使う CSV の一種に過ぎません。その為、`load_dataset()` 関数で `csv` ローディングスクリプトを使い、`delimiter` 引数を指定することで、これらのファイルを次のように読み込めます。

```py
from datasets import load_dataset

data_files = {"train": "drugsComTrain_raw.tsv", "test": "drugsComTest_raw.tsv"}
# \t は Python におけるタブ文字です
drug_dataset = load_dataset("csv", data_files=data_files, delimiter="\t")
```

データ分析では、まず小さなランダムサンプルを取り出して、扱っているデータの傾向を手早く把握するのが一般的です。Datasets では、`Dataset.shuffle()` 関数と `Dataset.select()` 関数をつなげることでランダムサンプルを作れます。

```py
drug_sample = drug_dataset["train"].shuffle(seed=42).select(range(1000))
# 最初の数件のサンプルをのぞいてみます
drug_sample[:3]
```

再現性を確保する為、`Dataset.shuffle()` ではシードを固定しています。`Dataset.select()` は、インデックスを順次取得出来る反復可能オブジェクト（iterable）を引数として受け取ります。そこで、シャッフルしたデータセットから最初の1,000件を取得する為に、`range(1000)` を渡しています。

このサンプルを見るだけでも、データセットにいくつかの特徴が有ることが分かります。

* `Unnamed: 0` 列は、各患者の匿名化された ID のように見えます。
* `condition` 列には、大文字と小文字のラベルが混在しています。
* レビューは長さがまちまちで、改行コード（`\r\n`）や、`&\#039;` のような HTML 文字参照が混ざっています。

Datasets を使ってこれらの問題にどう対処出来るか見ていきましょう。`Unnamed: 0` 列が患者 ID を表しているという仮説を検証するには、`Dataset.unique()` 関数を使って、ID の数が各分割の行数と一致するかを確認出来ます。

```py
for split in drug_dataset.keys():
    assert len(drug_dataset[split]) == len(drug_dataset[split].unique("Unnamed: 0"))
```

仮説は正しそうです。では、`Unnamed: 0` 列の名前をもう少し解釈し易いものに変えて、データセットを少し整えましょう。`DatasetDict.rename_column()` 関数を使えば、両方の分割にわたって一度に列名を変更出来ます。

```py
drug_dataset = drug_dataset.rename_column(
    original_column_name="Unnamed: 0", new_column_name="patient_id"
)
drug_dataset
```

```python out

    train: Dataset({
        features: ['patient_id', 'drugName', 'condition', 'review', 'rating', 'date', 'usefulCount'],
        num_rows: 161297
    })

        features: ['patient_id', 'drugName', 'condition', 'review', 'rating', 'date', 'usefulCount'],

```

> [!TIP]
> **やってみよう！** `Dataset.unique()` 関数を使って、訓練セットとテストセットに含まれる薬と症状が、それぞれ何種類あるか調べてみましょう。

次に、`Dataset.map()` を使って `condition` ラベルを全て正規化します。[Chapter 3](/course/chapter3) でトークナイズを行った時と同様に、`drug_dataset` の各分割の全ての行に適用出来る単純な関数を定義出来ます。

```py
def lowercase_condition(example):
    return {"condition": example["condition"].lower()}


drug_dataset.map(lowercase_condition)
```

```python out
AttributeError: 'NoneType' object has no attribute 'lower'
```

おっと、`Dataset.map()` でエラーが発生しました！このエラーから、`condition` 列には `None` が含まれていることが分かります。`None` は文字列ではない為、小文字に変換出来ません。そこで、`Dataset.filter()` を使って該当する行を取り除きましょう。`Dataset.filter()` は `Dataset.map()` と似た仕組みで、データセットのサンプルを1件ずつ受け取る関数を引数として指定します。例えば、次のような関数を定義出来ます。

```py
def filter_nones(x):
    return x["condition"] is not None
```

この関数を `drug_dataset.filter(filter_nones)` で実行することも出来ますが、ラムダ関数を使えば1行で書けます。Python のラムダ関数は、明示的に名前を付けずに定義出来る小さな関数です。一般形は次の通りです。

```
lambda <arguments> : <expression>
```

ここで `lambda` は Python の特殊な[キーワード](https://docs.python.org/3/reference/lexical_analysis.html#keywords)の1つです。`<arguments>` は関数が受け取る引数を表し、複数ある場合はカンマで区切って並べます。`<expression>` は実行したい計算や処理を表します。

例えば、数を2乗する単純なラムダ関数は、次のように定義出来ます。

```
lambda x : x * x
```

この関数を入力に適用するには、関数と入力を括弧で囲む必要があります。

```py
(lambda x: x * x)(3)
```

```python out
9
```

同様に、引数をカンマで区切ることで、複数の引数を取るラムダ関数も定義出来ます。例えば、三角形の面積は次のように計算出来ます。

```py
(lambda base, height: 0.5 * base * height)(4, 8)
```

```python out
16.0
```

ラムダ関数は、小さくて使い捨ての関数を定義したい場合に便利です（詳細については、Andre Burgaud による素晴らしい [Real Python のチュートリアル](https://realpython.com/python-lambda/) を読むことをお勧めします）。Datasets では、ラムダ関数を使って `map()` や `filter()` の簡単な処理を定義出来ます。この方法を使って、データセット内の `None` エントリを取り除きましょう。

```py
drug_dataset = drug_dataset.filter(lambda x: x["condition"] is not None)
```

`None` エントリが取り除けたので、`condition` 列を正規化出来ます。

```py
drug_dataset = drug_dataset.map(lowercase_condition)
# 小文字化が効いているか確認します
drug_dataset["train"]["condition"][:3]
```

```python out
['left ventricular dysfunction', 'adhd', 'birth control']
```

うまくいきました！ラベルが整ったところで、次はレビュー自体のクリーニングを見ていきましょう。

## 新しい列の作成[[creating-new-columns]]

顧客レビューを扱う時は、まず各レビューの単語数を調べておくとよいでしょう。レビューには \"Great!\" のように1語だけのものもあれば、数千語に及ぶ長文もあります。こうした極端に短いレビューや長いレビューへの対処方法は、用途によって異なります。ここでは、テキストを空白文字で区切り、おおよその単語数を数える簡単な方法を使います。

各レビューの単語数を数える単純な関数を定義しましょう。

```py
def compute_review_length(example):
    return {"review_length": len(example["review"].split())}
```

`lowercase_condition()` 関数とは違い、`compute_review_length()` は既存の列名には無い `review_length` というキーを持つ辞書を返します。この関数を `Dataset.map()` に渡すと、データセットの全ての行に適用され、新しい `review_length` 列が作られます。

```py
drug_dataset = drug_dataset.map(compute_review_length)
# 最初の訓練サンプルを確認します
drug_dataset["train"][0]
```

```python out
{'patient_id': 206461,
 'drugName': 'Valsartan',
 'condition': 'left ventricular dysfunction',
 'review': '"It has no side effect, I take it in combination of Bystolic 5 Mg and Fish Oil"',
 'rating': 9.0,
 'date': 'May 20, 2012',
 'usefulCount': 27,
 'review_length': 17}
```

（レビューの訳：「副作用はありません。バイストリック 5 Mg とフィッシュオイルと併せて服用しています」）

期待通り、訓練セットに `review_length` 列が追加されています。この列を基準に `Dataset.sort()` でデータセットを並べ替えると、単語数が最も少ないレビューを確認出来ます。


予想通り、1語だけのレビューも含まれています。感情分析ならそれでも構いませんが、症状を予測するには、十分な手掛かりが得られません。

> [!TIP]
> データセットに新しい列を追加する別の方法として、`Dataset.add_column()` 関数があります。列を Python のリストや NumPy 配列として渡すことが出来、`Dataset.map()` が分析に適さない場面で便利です。

`Dataset.filter()` 関数を使って、単語数が30未満のレビューを取り除きましょう。`condition` 列を処理した時と同じように、レビューの単語数がこのしきい値を超えるという条件を指定すれば、非常に短いレビューを除外出来ます。

```py
drug_dataset = drug_dataset.filter(lambda x: x["review_length"] > 30)
print(drug_dataset.num_rows)
```

```python out
{'train': 138514, 'test': 46108}
```

見ての通り、元の訓練セットとテストセットからレビューの約15%が取り除かれました。

> [!TIP]
> **やってみよう！** `Dataset.sort()` 関数を使って、単語数が最も多いレビューを確認してみましょう。レビューを単語数の降順に並べ替える為に必要な引数は、[ドキュメント](https://huggingface.co/docs/datasets/package_reference/main_classes#datasets.Dataset.sort)で確認してください。

最後に、レビューに含まれる HTML 文字参照を処理しましょう。Python の `html` モジュールを使えば、次のように HTML 文字参照を元の文字に変換出来ます。

```py
import html

text = "I&#039;m a transformer called BERT"
html.unescape(text)
```

```python out
"I'm a transformer called BERT"
```

（出力の訳：「私は BERT という名前の Transformer です」）

`Dataset.map()` を使って、コーパス内の全ての HTML 文字参照を元の文字に戻しましょう。

```python
drug_dataset = drug_dataset.map(lambda x: {"review": html.unescape(x["review"])})
```

見ての通り、`Dataset.map()` メソッドはデータ処理にかなり役立ちます。しかも、その能力のほんの一部に触れただけです。

## `map()` メソッドのスーパーパワー[[the-map-methods-superpowers]]

`Dataset.map()` メソッドには `batched` 引数があり、`True` に設定すると、複数のサンプルがまとめてマッピング関数に渡されます（バッチサイズは変更出来ますが、デフォルトは1,000です）。例えば、先程 HTML 文字参照を変換した処理には、少し時間がかかりました（所要時間は進捗バーで確認出来ます）。リスト内包表記を使って複数の要素をまとめて処理すれば、この処理を高速化出来ます。

`batched=True` を指定すると、関数はデータセットの各フィールドをキーとする辞書を受け取ります。但し、各キーに対応する値は単一の値ではなく、値のリストになります。戻り値も同様に、更新又は追加したいフィールドをキーとし、それぞれの値がリストになっている辞書にする必要があります。

例えば、`batched=True` を使って全ての HTML 文字参照を変換するには、次のように書けます。

```python
new_drug_dataset = drug_dataset.map(
    lambda x: {"review": [html.unescape(o) for o in x["review"]]}, batched=True
)
```

このコードをノートブックで実行すると、先程のコードよりもずっと速く処理が終わることが分かるでしょう。これは、レビュー内の HTML 文字参照が既に変換されているからではありません。先程のコードを `batched=True` なしでもう一度実行しても、所要時間は殆ど変わりません。処理が速くなるのは、リスト内包表記が通常の `for` ループよりも高速であり、更に、要素を1件ずつではなくまとめて処理することでも効率が上がる為です。

`Dataset.map()` と `batched=True` の組み合わせは、[Chapter 6](/course/chapter6) で紹介する高速トークナイザ（fast tokenizer）の性能を引き出す上で欠かせません。高速トークナイザは、大量のテキストをすばやくトークナイズ出来ます。例えば、薬のレビューを全て高速トークナイザで処理するには、次のような関数を使えます。

```python
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-cased")


def tokenize_function(examples):
    return tokenizer(examples["review"], truncation=True)
```

[Chapter 3](/course/chapter3) で見た通り、トークナイザには1つ又は複数のサンプルを渡せる為、この関数は `batched=True` の有無にかかわらず使えます。この機会に、様々な選択肢の性能を比較してみましょう。ノートブックでは、計測したいコード行の前に `%time` を付ければ、1行の命令の時間を測れます。

```python no-format
%time tokenized_dataset = drug_dataset.map(tokenize_function, batched=True)
```

セル全体の実行時間を測りたい場合は、セルの先頭に `%%time` を置くことも出来ます。原典の著者が使用した環境では、この処理に10.8秒かかりました。これは、実行結果の「Wall time」の後に表示される数値です。

> [!TIP]
> **やってみよう！** 同じ命令を `batched=True` の有無で実行し、更に低速トークナイザ（`AutoTokenizer.from_pretrained()` メソッドに `use_fast=False` を追加）でも試して、自分のハードウェアでどのような数値が得られるか確認してみましょう。

バッチ処理の有無、高速トークナイザと低速トークナイザで得られた結果は次の通りです。

オプション         | 高速トークナイザ | 低速トークナイザ
:--------------:|:--------------:|:-------------:
`batched=True`  | 10.8s          | 4min41s
`batched=False` | 59.2s          | 5min3s

つまり、高速トークナイザと `batched=True` オプションの組み合わせは、バッチ処理なしの低速な組み合わせよりも30倍高速ということです。本当に驚くべきことです！これが、`AutoTokenizer` を使う時に高速トークナイザがデフォルトである（そして「高速」と呼ばれる）主な理由です。裏側ではトークナイズのコードが Rust で実行されており、Rust はコード実行の並列化が容易な言語である為、このような高速化が可能になっています。

並列化は、高速トークナイザがバッチ処理でほぼ6倍の高速化を達成出来る理由でもあります。単一のトークナイズ操作は並列化出来ませんが、多数のテキストを同時にトークナイズしたい場合は、実行を複数のプロセスに分割し、それぞれが自分の担当するテキストを処理すればよいのです。

`Dataset.map()` 自体にも、処理を並列化する機能があります。この機能は Rust で実装されている訳ではない為、低速トークナイザが高速トークナイザに追いつく程の高速化は期待出来ません。それでも、特に高速版が存在しないトークナイザを使う場合には役立ちます。マルチプロセッシングを有効にするには、`Dataset.map()` の `num_proc` 引数で使用するプロセス数を指定します。

```py
slow_tokenizer = AutoTokenizer.from_pretrained("bert-base-cased", use_fast=False)


def slow_tokenize_function(examples):
    return slow_tokenizer(examples["review"], truncation=True)


tokenized_dataset = drug_dataset.map(slow_tokenize_function, batched=True, num_proc=8)
```

時間を測りながら少し実験すれば、使うプロセスの最適な数が分かります。私たちの場合、8が最も良い高速化をもたらすようでした。マルチプロセッシングの有無で得られた数値は次の通りです。

オプション         | 高速トークナイザ | 低速トークナイザ
:--------------:|:--------------:|:-------------:
`batched=True`  | 10.8s          | 4min41s
`batched=False` | 59.2s          | 5min3s
`batched=True`, `num_proc=8`  | 6.52s          | 41.3s
`batched=False`, `num_proc=8` | 9.49s          | 45.2s

低速トークナイザでも、実行時間が大幅に短縮され、より実用的な水準になりましたが、高速トークナイザの性能も大幅に向上しました。但し、常にそうなるとは限りません。8以外の `num_proc` の値では、そのオプションなしで `batched=True` を使うほうが速いという結果がテストで示されました。一般に、`batched=True` と高速トークナイザの組み合わせに Python のマルチプロセッシングを使うことはお勧めしません。

> [!TIP]
> `num_proc` を使って処理を高速化するのは、通常は良い考えです。但し、使用している関数自体が既に何らかのマルチプロセッシングを行っていない場合に限ります。

1つのメソッドでこれだけのことが出来るのも驚きですが、まだあります！`Dataset.map()` と `batched=True` を使えば、データセット内の要素数を変更することも出来ます。これは、1つのサンプルから訓練用の特徴量を複数作りたい場面など、多くの状況で非常に便利です。[Chapter 7](/course/chapter7) で取り組むいくつかの NLP タスクの前処理でも必要になります。

> [!TIP]
> 機械学習では、サンプル（example）は通常、モデルに入力する特徴量（feature）の集合として定義されます。文脈によっては、これらの特徴量が `Dataset` の列の集合である場合もあれば、（この場合や質問応答のように）1つのサンプルから複数の特徴量が抽出され、1つの列に属する場合もあります。

仕組みを見ていきましょう！ここではサンプルをトークナイズし、最大長を128トークンに設定します。但し、最初の分割部分（チャンク）だけを返すのではなく、テキストを分割して出来た全てのチャンクを返すようにします。これには `return_overflowing_tokens=True` を指定します。

```py
def tokenize_and_split(examples):
    return tokenizer(
        examples["review"],
        truncation=True,
        max_length=128,
        return_overflowing_tokens=True,
    )
```

データセット全体に `Dataset.map()` を使う前に、1つのサンプルでテストしてみましょう。

```py
result = tokenize_and_split(drug_dataset["train"][0])
[len(inp) for inp in result["input_ids"]]
```

```python out
[128, 49]
```

訓練セットの最初のサンプルは、トークナイズすると指定した最大トークン数を超える為、2つの特徴量に分割されました。1つ目の長さは128、2つ目は49です。では、データセット内の全てのサンプルに対して同じ処理を行いましょう！

```py
tokenized_dataset = drug_dataset.map(tokenize_and_split, batched=True)
```

```python out
ArrowInvalid: Column 1 named condition expected length 1463 but got length 1000
```

おっと、うまくいきませんでした！何故でしょうか。エラーメッセージを見ると、列の長さが一致していないことが分かります。一方は1,463件、もう一方は1,000件です。`Dataset.map()` の[ドキュメント](https://huggingface.co/docs/datasets/package_reference/main_classes#datasets.Dataset.map)を読んだことがあれば、マッピング関数に渡されるサンプル数が関係していると思い当たるかもしれません。今回は、1,000件のサンプルを関数に渡したところ、1,463件の新しい特徴量が生成されました。その為、列の長さが一致しなくなったのです。

問題は、サイズの異なる2つのデータセットを混ぜようとしていることです。元のデータセットの列には1,000件の値があります。一方、`return_overflowing_tokens=True` によって長いレビューが分割される為、新しい列には1,463件の値が生成されます。`Dataset` ではこれは成り立たない為、古いデータセットの列を取り除くか、新しいデータセットと同じサイズにする必要があります。前者は `remove_columns` 引数で行えます。

```py
tokenized_dataset = drug_dataset.map(
    tokenize_and_split, batched=True, remove_columns=drug_dataset["train"].column_names
)
```

今度はエラーなく動作します。長さを比較すれば、新しいデータセットが元のデータセットよりもはるかに多くの要素を持つことを確認出来ます。

```py
len(tokenized_dataset["train"]), len(drug_dataset["train"])
```

```python out
(206772, 138514)
```

列の長さが一致しない問題は、元の列を新しい列と同じ長さにすることでも解決出来ます。その為には、`return_overflowing_tokens=True` を指定した時にトークナイザが返す `overflow_to_sample_mapping` フィールドを使います。このフィールドには、新しく生成された各特徴量のインデックスと、その特徴量がどの元サンプルから作られたかを示すインデックスの対応関係が格納されています。この対応関係を使い、各サンプルから生成された特徴量の数に合わせて元の列の値を複製すれば、列の長さを揃えられます。

```py
def tokenize_and_split(examples):
    result = tokenizer(
        examples["review"],
        truncation=True,
        max_length=128,
        return_overflowing_tokens=True,
    )
    # 新旧インデックスの対応関係を取り出します
    sample_map = result.pop("overflow_to_sample_mapping")
    for key, values in examples.items():
        result[key] = [values[i] for i in sample_map]
    return result
```

古い列を取り除かなくても、`Dataset.map()` で動作することが分かります。

```py
tokenized_dataset = drug_dataset.map(tokenize_and_split, batched=True)
tokenized_dataset
```

```python out
DatasetDict({
    train: Dataset({
        features: ['attention_mask', 'condition', 'date', 'drugName', 'input_ids', 'patient_id', 'rating', 'review', 'review_length', 'token_type_ids', 'usefulCount'],
        num_rows: 206772
    })
    test: Dataset({
        features: ['attention_mask', 'condition', 'date', 'drugName', 'input_ids', 'patient_id', 'rating', 'review', 'review_length', 'token_type_ids', 'usefulCount'],
        num_rows: 68876
    })
})
```

訓練用の特徴量の数は以前と同じですが、ここでは元のフィールドを全て保持しています。モデルの出力を後処理する際に、これらのフィールドが必要になる場合は、この方法を使うとよいでしょう。

これで、Datasets を使ってデータセットを様々な方法で前処理出来ることを見てきました。Datasets の処理関数は、モデルの訓練に必要なことの大半をカバーしますが、`DataFrame.groupby()` や可視化用の高レベル API など、より強力な機能を利用する為に Pandas へ切り替える必要がある場面もあるでしょう。

幸い、Datasets は Pandas、NumPy、PyTorch、TensorFlow、JAX といったライブラリと相互運用出来るよう設計されています。その仕組みを見ていきましょう。

## 検証セットの作成[[creating-a-validation-set]]

評価用のテストセットはありますが、開発中はテストセットを使わず、別に検証セットを作ることをお勧めします。検証セットでのモデルの性能に満足出来たら、テストセットで最終確認が出来ます。このプロセスにより、テストセットに過学習してしまい、実際のデータではうまく動かないモデルをデプロイするリスクを軽減出来ます。

Datasets には、`scikit-learn` でよく使われるデータ分割機能に基づいた `Dataset.train_test_split()` 関数があります。これを使って、訓練セットを `train` と `validation` の2つに分けましょう。再現性を確保する為、`seed` 引数も指定します。

```py
drug_dataset_clean = drug_dataset["train"].train_test_split(train_size=0.8, seed=42)
# デフォルトの "test" 分割の名前を "validation" に変更します
drug_dataset_clean["validation"] = drug_dataset_clean.pop("test")
# `DatasetDict` に "test" セットを追加します
drug_dataset_clean["test"] = drug_dataset["test"]
drug_dataset_clean
```

## データセットの保存[[saving-a-dataset]]

<Youtube id="blF9uxYcKHo"/>

Datasets は、ダウンロードした全てのデータセットとそれに対して行った操作をキャッシュしますが、データセットをディスクに保存したい場合もあります（キャッシュが削除される場合など）。下の表に示すように、Datasets にはデータセットを異なる形式で保存する3つの主要な関数が用意されています。

| データ形式 |        関数        |
| :---------: | :--------------------: |
|    Arrow    | `Dataset.save_to_disk()` |
|     CSV     |    `Dataset.to_csv()`    |
|    JSON     |   `Dataset.to_json()`    |

例えば、クリーニング済みのデータセットを Arrow 形式で保存してみましょう。

```py
drug_dataset_clean.save_to_disk("drug-reviews")
```

これにより、次のような構造のディレクトリが作られます。

```
drug-reviews/
├── dataset_dict.json
├── test
│   ├── dataset.arrow
│   ├── dataset_info.json
│   └── state.json
├── train
│   ├── dataset.arrow
│   ├── dataset_info.json
│   ├── indices.arrow
│   └── state.json
└── validation
    ├── dataset.arrow
    ├── dataset_info.json
    ├── indices.arrow
    └── state.json
```

各分割には、それぞれ専用の *dataset.arrow* テーブルと、*dataset_info.json* や *state.json* のメタデータが対応していることが分かります。Arrow 形式は、行と列からなる表形式のデータを保持し、大規模なデータセットの処理や転送を行う高性能なアプリケーション向けに最適化された形式だと考えてください。

データセットが保存出来たら、次のように `load_from_disk()` 関数を使って読み込むことが出来ます。

```py
from datasets import load_from_disk

drug_dataset_reloaded = load_from_disk("drug-reviews")
```
