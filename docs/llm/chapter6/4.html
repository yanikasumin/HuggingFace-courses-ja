正規化と事前トークン化

Transformer モデルで使われる最も一般的な3つのサブワードトークン化アルゴリズム（Byte-Pair Encoding [BPE]、WordPiece、Unigram）を詳しく見る前に、まず各トークナイザがテキストに適用する前処理を見ていきます。トークン化パイプラインのステップの概要は次の通りです。

トークナイザは、テキストを（そのモデルに応じて）サブトークンに分割する前に、正規化 と 事前トークン化 という2つのステップを実行します。

正規化

正規化ステップでは、不要な空白の除去、小文字化、アクセント記号の除去など、一般的なクリーンアップを行います。Unicode 正規化（NFC や NFKC など）に馴染みがある方もいるかもしれませんが、これもトークナイザが適用する場合があります。

🤗 Transformers の tokenizer には backend_tokenizer という属性があり、背後にある Tokenizers ライブラリのトークナイザにアクセス出来ます。

from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
print(type(tokenizer.backend_tokenizer))

```python out <class 'tokenizers.Tokenizer'>

`tokenizer` オブジェクトの `normalizer` 属性には `normalize_str()` メソッドがあり、正規化がどのように行われるかを確認出来ます。

```py
print(tokenizer.backend_tokenizer.normalizer.normalize_str("Héllò hôw are ü?"))

```python out 'hello how are u?'

（入力文の訳：こんにちは、お元気ですか。アクセント記号の付いた文字で書かれています。出力の訳：こんにちは、お元気ですか）

この例では `bert-base-uncased` チェックポイントを選んだ為、正規化では小文字化が行われ、アクセント記号が除去されました。

## 事前トークン化








次のセクションで見る通り、トークナイザは生のテキストだけでは学習出来ません。まず、テキストを単語のような小さな単位に分割する必要があります。そこで事前トークン化ステップの出番です。

[Chapter 2](/course/chapter2) で見たように、単語ベースのトークナイザは、生のテキストを空白と句読点で単に単語に分割出来ます。それらの単語が、トークナイザが学習中に学べるサブトークンの境界となります。

高速トークナイザが事前トークン化をどのように行うかを見るには、`tokenizer` オブジェクトの `pre_tokenizer` 属性の `pre_tokenize_str()` メソッドを使えます。

```py
tokenizer.backend_tokenizer.pre_tokenizer.pre_tokenize_str("Hello, how are  you?")

```python out [('Hello', (0, 5)), (',', (5, 6)), ('how', (7, 10)), ('are', (11, 14)), ('you', (16, 19)), ('?', (19, 20))]

（入力文の訳：こんにちは、お元気ですか。文中に二重の空白が含まれています）

トークナイザが既にオフセットを追跡していることに注目してください。これにより、前のセクションで使ったオフセットマッピングが得られます。ここでは、トークナイザは2つの空白を無視して1つに置き換えていますが、それを反映して `are` と `you` の間でオフセットがジャンプしています。

BERT トークナイザを使っている為、事前トークン化では空白と句読点で分割します。他のトークナイザでは、このステップのルールが異なる場合があります。例えば、GPT-2 トークナイザを使うと次のようになります。

```py
tokenizer = AutoTokenizer.from_pretrained("gpt2")
tokenizer.backend_tokenizer.pre_tokenizer.pre_tokenize_str("Hello, how are  you?")

こちらも空白と句読点で分割しますが、空白を保持して Ġ 記号に置き換える為、トークンをデコードすれば元の空白を復元出来ます。

```python out [('Hello', (0, 5)), (',', (5, 6)), ('Ġhow', (6, 10)), ('Ġare', (10, 14)), ('Ġ', (14, 15)), ('Ġyou', (15, 19)), ('?', (19, 20))]

（入力文の訳は、前の BERT トークナイザの例と同じです）

また、BERT トークナイザとは異なり、このトークナイザは二重の空白を無視しないことにも注意してください。

最後の例として、SentencePiece アルゴリズムに基づく T5 トークナイザを見てみましょう。

```py
tokenizer = AutoTokenizer.from_pretrained("t5-small")
tokenizer.backend_tokenizer.pre_tokenizer.pre_tokenize_str("Hello, how are  you?")

python out [('▁Hello,', (0, 6)), ('▁how', (7, 10)), ('▁are', (11, 14)), ('▁you?', (16, 20))]

（入力文の訳は、前の BERT トークナイザの例と同じです）

GPT-2 トークナイザと同様に、このトークナイザも空白を保持して特定のトークン（_）に置き換えますが、T5 トークナイザは空白でのみ分割し、句読点では分割しません。また、文の先頭（Hello の前）にデフォルトで空白が追加され、are と you の間の二重の空白が無視されていることにも注意してください。

いくつかの異なるトークナイザがテキストをどう処理するかを見てきたので、次は背後にあるアルゴリズム自体を探っていきます。まず、幅広く適用出来る SentencePiece を簡単に見てから、次の3つのセクションで、サブワードトークン化に使われる3つの主要なアルゴリズムの仕組みを調べます。

SentencePiece

SentencePiece はテキストの前処理の為のトークン化アルゴリズムで、次の3つのセクションで見るどのモデルとも併用出来ます。テキストを Unicode 文字のシーケンスとして扱い、空白を特殊文字 ▁ に置き換えます。Unigram アルゴリズムと組み合わせて使う場合（第7節 を参照）、事前トークン化ステップすら不要であり、空白文字を使わない言語（中国語や日本語など）でとても役立ちます。

SentencePiece のもう1つの主な特徴は、可逆なトークン化（reversible tokenization）です。空白に特別な処理をしない為、トークンのデコードは、単にトークンを連結し、_ を空白に置き換えるだけで行えます。その結果、正規化されたテキストが得られます。先に見た通り、BERT トークナイザは繰り返しの空白を除去する為、そのトークン化は可逆ではありません。

アルゴリズムの概要

以降のセクションでは、3つの主要なサブワードトークン化アルゴリズム、即ち BPE（GPT-2 などで使用）、WordPiece（BERT などで使用）、Unigram（T5 などで使用）を詳しく見ていきます。始める前に、それぞれの仕組みの簡単な概要を示します。今は意味が分からなくても、次の各セクションを読んだ後にこの表に戻ってきてください。

モデル BPE WordPiece Unigram
学習 小さな語彙から始めて、トークンをマージするルールを学習する 小さな語彙から始めて、トークンをマージするルールを学習する 大きな語彙から始めて、トークンを除去するルールを学習する学習ステップ

では、BPE に入っていきましょう！
