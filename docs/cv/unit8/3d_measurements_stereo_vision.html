はじめに

このセクションでは、ステレオビジョンの仕組みと、それを使って周囲の物体の3次元構造を求める方法を説明します。ステレオビジョンでは、同じシーンを異なる位置と視点から撮影した2枚以上の画像を使います。これらの画像は、複数のカメラを使うか、同じカメラの位置を変えることで得られます。

問題設定

物体の3D構造を求める仕組みを理解する為に、まずカメラが画像を作る時の幾何学的な関係を考えてみましょう。図1には、3D空間内の座標 (x, y, z) に在る点 P が示されています。この点から来た光はピンホールを通り、カメラの2D画像平面上に投影されます。

では、この2D画像と、画像上における点 P の画素座標だけが分かっているとします。そこから点 P の3D座標を特定出来るでしょうか。同じ画素に写る別の3D点は存在しないのでしょうか。実は、点 P とピンホールを結ぶ直線上に在る点は、全て画像上の同じ位置に投影されます。つまり、画像1枚だけでは点 P の奥行きを一意に決められません。

ここでは、物体を3D空間内の点の集まりとして表します。それぞれの点の3D座標が分かれば、物体全体の3D構造を求められます。

図1: 単一カメラによる画像形成

解法

次の情報が与えられていると仮定します。

  1. シーン内の点 P が写った1枚の画像
  2. 画像内における点 P の画素座標
  3. 画像を撮影したカメラの位置と向き。簡単の為、図1のように、ピンホールの位置に XYZ 座標系を置き、z 軸を画像平面に垂直に、x 軸と y 軸を画像平面に平行にすることも出来ます。
  4. 焦点距離や主点の位置といった、カメラの内部パラメータ。主点とは、光軸が画像平面と交わる点です。画像平面におけるその位置は通常 (Ox,Oy) と表記されます。

これらの情報が分かっていれば、画像上の点 P の位置とピンホールを通る3D空間内の直線を求められます。この直線は無限遠まで伸びています。画像形成の幾何学的な関係から、実際の点 P はこの直線上のどこかに在るはずです。

  1. 最初（画像が無い状態）では、点 P は3D空間内のどこにでも存在し得ました。
  2. 単一の画像を使うことで、点 P の存在し得る場所を3D空間内の1本の直線に絞り込みました。
  3. では、この3D直線上で点 P の正確な位置を特定出来るまで、候補を更に絞り込めるでしょうか。
  4. カメラを別の位置に動かしたと想像してください。座標系は以前の位置に固定したままにします。先ほど求めた3D直線も変わらず、点 P は依然としてこの直線上のどこかに在ります。
  5. この新しいカメラ位置から、同じシーンの点 P の画像をもう1枚撮影します。再び、この新しい画像における点 P の画素座標と、更新されたカメラのピンホールの位置を使って、点 P が存在するはずの3D直線を求めます。
  6. これで3D空間内に2本の直線があり、点 P はその両方の上に在ります。従って、点 P はこの2本の直線の交点上に存在するはずです。

3D空間内の2本の直線の交わり方には、次の3つの可能性が有ります。

  1. ちょうど1点で交わる
  2. 無数の点で交わる
  3. 交わらない

元のカメラ位置と移動後のカメラ位置の両方で点 P を撮影出来た場合、2本の3D直線は点 P で交わります。

但し、2本の直線が重なってしまう場合は例外です。例えば、移動後のカメラのピンホールが元の直線上に在ると、2本の直線が一致し、交点を1つに絞れません。それ以外のカメラ配置であれば、2本の直線は点 P に当たる1点で交わり、その位置を特定出来ます。

従って、同じ点 P を異なる位置から撮影した2枚の画像と、撮影時のカメラの位置・向き、カメラの内部パラメータが分かれば、点 P の3D空間内の位置を正確に求められます。

簡略化した解法

カメラの位置や向きには様々な選択肢が有りますが、配置を工夫すれば計算を簡単に出来、コンピュータや組み込みデバイスの処理負荷も減らせます。図2は、よく使われる配置の1つです。ここでは2台のカメラを使っていますが、1台のカメラを別々の位置に動かして2枚撮影する方法でも、同じ幾何学的な関係を扱えます。

図2: 2台のカメラによる画像形成

  1. 座標系の原点は、通常は左カメラである1台目のカメラのピンホールに置かれます。
  2. 座標系の Z 軸は、画像平面に垂直に定義されます。
  3. 座標系の X 軸と Y 軸は、画像平面に平行に定義されます。
  4. 2D画像にも X 方向と Y 方向が有ります。X は水平方向、Y は垂直方向です。画像平面におけるこれらの方向を、それぞれ u と v と呼ぶことにします。従って、点の画素座標は (u,v) の値で定義されます。
  5. 座標系の X 軸は、画像平面の水平方向、即ち u 方向に合わせて定義されます。
  6. 同様に、座標系の Y 軸は、画像平面の垂直方向、即ち v 方向に合わせて定義されます。
  7. 2台目のカメラ（より正確には2台目のカメラのピンホール）は、1台目のカメラの右側に、正の x 方向にベースラインと呼ばれる距離 b だけ離れて置かれます。従って、2台目のカメラのピンホールの x,y,z 座標は (b,0,0) です。
  8. 2台目のカメラの画像平面は、1台目のカメラの画像平面と平行に向けられます。
  9. 2台目の右カメラでは、画像平面の u 方向と v 方向を、1台目の左カメラの画像平面におけるそれぞれの方向に揃えます。
  10. 左右両方のカメラは、焦点距離や主点の位置といった同じ内部パラメータを持つと仮定します。

上記の配置のもとで、3Dの点を2Dの画像平面に対応付ける次の方程式が得られます。

  1. 左カメラ

    1. \(u_left = f_x * \frac{x}{z} + O_x\)
    2. \(v_left = f_y * \frac{y}{z} + O_y\)

  2. 右カメラ

    1. \(u_right = f_x * \frac{x-b}{z} + O_x\)
    2. \(v_right = f_y * \frac{y}{z} + O_y\)

上記の方程式で使われる様々な記号は、以下で定義されます。 * \(u_left\)、\(v_left\) は、左画像における点 P の画素座標を指します。 * \(u_right\)、\(v_right\) は、右画像における点 P の画素座標を指します。 * \(f_x\) と \(f_y\) は、それぞれ x 方向と y 方向の焦点距離をピクセル単位で表したものです。カメラの物理的な焦点距離は、ピンホール（レンズの光学中心）から画像平面までの距離で、1つの値として定まります。但し、画素が必ずしも正方形とは限らない為、ピクセル単位に換算すると x 方向と y 方向で値が異なる場合が有ります。 * x、y、z は点 P の3D座標です（cm、フィートなど、任意の単位が使えます）。 * \(O_x\) と \(O_y\) は、主点の画素座標を指します。 * b はベースラインと呼ばれ、左カメラと右カメラの間の距離を指します。b と x,y,z 座標には同じ単位が使われます（cm、フィートなど、任意の単位が使えます）。

ここまでに4つの方程式が得られました。一方、未知数は点 P の3D座標 x、y、z の3つです。焦点距離や主点の位置といったカメラの内部パラメータは、既知であると仮定します。方程式1.2と2.2から、左右の画像で v 座標が同じになることが分かります。

  1. \(v_left = v_right\)

方程式1.1、1.2、2.1を使うことで、点 P の x,y,z 座標を導出出来ます。

  1. \(x = \frac{b * (u_left - O_x)}{u_left - u_right}\)
  2. \(y = \frac{b * f_x * (v_left - O_y)}{ f_y * (u_left - u_right)}\)
  3. \(z = \frac{b * f_x}{u_left - u_right}\)

上記の x と y の値は左カメラに関するものであることに注意してください。座標系の原点が左カメラに揃えられている為です。上記の方程式は、2つの異なるカメラ位置から撮影された点 P の2枚の画像を使って、点 P の3D座標を求められることを示しています。z の値は深度値（depth）とも呼ばれます。

この手法を使えば、画像内の様々なピクセルの深度値と、実世界における x 座標と y 座標を求めることが出来ます。画像内の異なる点同士の実世界での距離も求められます。

デモ

セットアップ

ここからは実際に画像を撮影し、計算することで、これまでの仮定や式が成り立つか確かめます。撮影には OAK-D Lite（OAK は OpenCV AI Kit の略）というデバイスを使います。OAK-D Lite には3台のカメラが搭載されており、左右にモノクロ（白黒）カメラ、中央にカラーカメラが有ります。今回の実験では、左右のモノクロカメラを使います。

普通のスマートフォンでも実験出来ますが、OAK-D Lite には次のような利点が有ります。

  • OAK-D Lite では、焦点距離や主点の位置といった内部カメラパラメータが既知です。このデバイスはキャリブレーション済みで出荷され、これらのパラメータは Python API を使ってデバイスから読み取ることが出来ます。スマートフォンのカメラでは、内部パラメータを求める必要があり、カメラキャリブレーションを行うか、スマートフォンで撮影した画像のメタデータに含まれている場合に得られます。
  • これまでの説明では、左右のカメラの位置と向きが分かっていることを前提にしました。スマートフォンで撮影した場合、この情報を求めるのが難しく、追加のキャリブレーションが必要になることが有ります。一方、OAK-D Lite は左右のカメラの位置と向きが固定され、予めキャリブレーションされています。その配置も、先ほど説明した簡略化したモデルに非常に近いものです。但し、以下で説明するように、撮影した画像には平行化（rectification）という後処理が必要です。

平行化した左画像と右画像

左右のカメラでは内部パラメータや向きが少し異なる為、撮影した画像に平行化（rectification）という後処理を行います。この処理には 3x3 の行列変換を使います。

OAK-D Lite の API では、ステレオノードがこの計算を行い、平行化した左右の画像を出力します。詳しい処理とソースコードはこちらで確認出来ます。

この実装では、カメラの内部パラメータの補正に内部カメラ行列を、向きの補正に左右のカメラの回転行列（キャリブレーションパラメータの一部）を使います。左画像は、左カメラの内部パラメータが右カメラと同じであるかのように変換されます。その為、これ以降の計算では右カメラの内部パラメータ、即ち焦点距離452.9と主点 (298.85, 245.52) を使います。

異なる点の (x,y,z) 値を使って、点同士の3D距離も計算出来ます。公式は \(distance = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2 + (z_2 - z_1)^2}\) です。いくつかの点の間で計算した距離を、実際に測定した値と共に下の表にまとめました。誤差率 \(( \frac{(actual-measured) * 100}{actual}\)) も計算して表にまとめています。

計算値と実測値が非常によく一致し、誤差率は1.2%以下であることに気づきます。

まとめ

  1. ステレオビジョンの仕組みを学び、異なる視点から撮影した点 P の2枚の画像を使って、実世界での座標 (x, y, z) を求める方程式を確認しました。また、計算した値と実測値を比較しました。
  2. カメラの内部パラメータである焦点距離と主点は、カメラの位置と向きの情報と共に既知であると仮定しました。これはキャリブレーション済みステレオビジョン（calibrated stereo vision）とも呼ばれます。
  3. 興味深いことに、カメラの位置と向きが未知でも、点 P の3D座標を求めることは可能です。実際、カメラ同士の相対的な位置と向きは、画像自体から求めることが出来ます。これは未キャリブレーションのステレオビジョン（uncalibrated stereo vision）と呼ばれます！
