DeepSeek R1 論文を理解する

この章では、DeepSeek R1 の論文を読み解きます。まず全体を平易に説明し、続いて重要な概念と要点を一つずつ確認します。

DeepSeek R1 は言語モデルの学習を大きく進めた成果です。特に、強化学習によって推論能力を育てる点に特徴があります。論文では、新しい強化学習アルゴリズムである Group Relative Policy Optimization（GRPO）が提案されています。

次の章では、この知識をもとに GRPO を実際に実装します。

論文の当初の問いは、教師ありファインチューニングなしに、純粋な強化学習だけで推論能力が育つかどうかでした。

💡 ヒント

その時点までは、人気のある LLM はすべて何らかの教師ありファインチューニングを必要としていました。第11章で扱ったとおりです。

画期的な「Aha モーメント」

R1-Zero の学習で最も注目された発見の一つが、「Aha モーメント」と呼ばれる現象です。人間が問題を解いている途中で突然ひらめく感覚に近い現象です。仕組みは次のとおりです。

  1. 初めの試行：モデルが問題への最初の答えを試します
  2. 気づき：誤りや不整合がある可能性に気づきます
  3. 自己修正：気づきをもとに解き方を直します
  4. 説明：新しい解き方がなぜよいのかを説明できます

この発見は、学習データの暗記ではなく、学習そのものが起きていることを示します。人間が「ユーレカ」とひらめく瞬間に似ているため、多くの学習者の共感を呼んでいます。ここで少し立ち止まり、「Aha」モーメントがどのような感覚か想像してみましょう。

例えば、パズルを解いている場面を想像してください。

  • 最初の試み：「色からすると、このピースはここに入るはず」
  • 気づき：「でも待って、形がぴったり合わない」
  • 修正：「ああ、実際はあちらに入るんだ」
  • 説明：「この位置では、色も形のパターンも両方一致するから」

この能力は明示的にプログラムされたものではありません。RL 学習の中から自然に現れました。学習データの手順を暗記したのではなく、学習が起きていることを示す点が重要です。

「Aha モーメント」は、実際に動く様子を見ると理解しやすくなります。下のチャットでモデルに問題を解かせると、UI に思考の過程が表示されます。

Deepseek の R1 を試したい場合は、Hugging Chat も利用できます。

学習プロセス

R1 の学習は複数のフェーズで進みました。フェーズごとに役割と工夫を確認します。

最終的に得られるモデルは次の2つです。

  • DeepSeek-R1-Zero：純粋な強化学習だけで学習したモデルです。
  • DeepSeek-R1：DeepSeek-R1-Zero を土台に、教師ありファインチューニングを追加したモデルです。
特徴 DeepSeek-R1-Zero DeepSeek-R1
学習アプローチ 純粋な RL 複数フェーズ（SFT + RL）
ファインチューニング なし 教師ありファインチューニング
推論能力 創発的 強化済み
AIME の性能 71.0% 79.8%
主な特徴 強い推論能力だが可読性に課題 言語の一貫性と可読性が向上

DeepSeek-R1-Zero は、純粋な強化学習だけでも推論能力が育つ可能性を示しました。DeepSeek-R1 はその土台の上に立ち、推論性能と使いやすさの両方を重視した、よりバランスの取れたモデルです。

学習プロセスは次の4つのフェーズからなります。

  1. Cold Start フェーズ
  2. Reasoning RL フェーズ
  3. Rejection Sampling フェーズ
  4. Diverse RL フェーズ

以下、各フェーズを順に説明します。

Cold Start フェーズ（品質の基盤）

このフェーズの目的は、読みやすさと応答品質の土台を作ることです。R1-Zero で得た高品質なサンプルを集めた小規模なデータセットで、V3-Base モデルをファインチューニングします。

出発点は DeepSeek-V3-Base モデルです。開発チームは、R1-Zero から得た検証済みの高品質サンプルを数千件使い、教師ありファインチューニングを行いました。小規模でも品質の高いデータセットを使うことで、読みやすさと応答品質の確かな土台を作ります。

Reasoning RL フェーズ（能力の構築）

このフェーズでは、数学、コーディング、科学、論理など、さまざまな分野にわたる中核的な推論能力を育てます。使うのはルールベースの強化学習で、報酬は解が正しいかどうかと直接結びついています。

重要なのは、このフェーズのタスクがすべて「検証可能」であることです。モデルの答えが正しいかどうかを確認できます。数学であれば、数式ソルバーで答えを照合できます。

特に新しいのは、直接最適化する点です。別の報酬モデルを用意する必要がなく、学習の手順が簡素になります。

Rejection Sampling フェーズ（品質管理）

Rejection Sampling フェーズでは、モデルが生成したサンプルを品質管理の過程でふるいにかけます。品質の判定は DeepSeek-V3 が担い、純粋な推論タスクにとどまらず、幅広い範囲の出力を評価します。残ったデータは教師ありファインチューニングに使われます。複数の品質信号を組み合わせることで、高い水準の出力を確保できる点が工夫です。

Diverse RL フェーズ（幅広いアライメント）

最後のフェーズでは、複数の種類のタスクに取り組みます。方法は組み合わせ型です。答えが定まるタスクにはルールベースの報酬を使い、主観的なタスクは LLM のフィードバックで評価します。ねらいは、人間の選好に合わせることです。ルールベースの正確さと、言語モデルによる評価の柔軟性を組み合わせた報酬の仕組みで、その実現を目指します。

アルゴリズム： Group Relative Policy Optimization（GRPO）

学習の流れを理解したところで、モデルの学習に使われたアルゴリズムを見ていきます。

著者らは GRPO を、モデルのファインチューニングにおける画期的な進歩と位置づけています。

GRPO の新しさは、「選好の修正」に向けて方策を直接最適化できる点にあります。PPO のような従来の強化学習アルゴリズムと比べ、望ましい出力にモデルを合わせる道筋がより直接的で、効率もよくなります。以下では、GRPO の仕組みを3つの主要な構成要素に分けて説明します。

グループの形成： 複数の解を作る

最初のステップは直感的に理解できます。難しい問題に対して、学生が複数の解き方を試す様子に似ています。プロンプトが与えられると、モデルは答えを1つだけ出すのではありません。同じ問題への試行を複数作ります。通常は4通り、8通り、又は16通りです。

モデルに数学の問題の解き方を教える場面を想像してください。農場のニワトリを数える質問では、モデルは例えば次のような解を作るかもしれません。

  • ある解は、問題を段階に分けて解きます。まずニワトリの総数を数え、次に雄鶏を引き、最後に卵を産まない雌鶏を考慮します
  • 別の解は、異なるが同様に成り立つ解き方を使います
  • 試行の中には、誤りを含むものや、効率のよくない解もあります

これらの試行はすべてグループとして一緒に保持されます。複数の学生の解答を並べて比べ、そこから学ぶ形に似ています。

選好の学習： 良い解とは何かを理解する

GRPO の分かりやすさが際立つのは、この部分です。RLHF の他の手法では、解のよさを予測する別の報酬モデルが常に必要です。GRPO では、その必要がありません。任意の関数やモデルで解の品質を評価できます。例えば、長さを測る関数で短い応答に報酬を与えたり、数式ソルバーで数学の解の正確さに報酬を与えたりできます。

評価では、各解について次の点を見ます。

  • 最終的な答えは正しいか？
  • 解は適切な形式に従っているか（適切な XML タグを使うなど）？
  • 推論は提示された答えと一致しているか？

この方法で特に巧妙なのは、スコアの付け方です。絶対的なスコアだけを与えるのではありません。各グループの中で報酬を正規化します。グループ相対アドバンテージの推定には、次の簡潔で効果的な式を使います。

Advantage = (reward - mean(group_rewards)) / std(group_rewards)

この正規化は、AI における相対評価のようなものです。絶対的なスコアだけを見るのではなく、グループ内の他の解と比べてどの解が優れ、どの解が劣るのかを、モデルが理解できるようになります。

最適化： 経験から学ぶ

最後のステップでは、グループの評価から得た学びをもとに、モデルを改善します。方法は強力で、しかも安定しています。土台となる原則は次の2つです。

  1. 成功した解に似た出力を増やし、効果の低い解き方からは離れるようモデルを導きます
  2. 安全機構として KL ダイバージェンスのペナルティを入れ、モデルが一度に変わりすぎないようにします

この方法が従来の手法より安定する理由は、次のとおりです。

  • 2つずつ比べるのではなく、複数の解をまとめて見ます
  • グループ単位の正規化により、報酬の尺度（スケーリング）に起因する問題を防ぎやすくなります
  • KL ペナルティが安全網として働き、新しいことを学ぶ間も、すでに身につけたことが失われないようにします

💡 ヒント

GRPO の主要な革新は次のとおりです。 - 任意の関数やモデルから直接学習でき、別の報酬モデルに頼る必要がありません。 - 学習はグループ単位で行います。ペアワイズ比較のような従来の手法より安定し、効率的です。

内容は複雑ですが、要点は明確です。GRPO は、モデルに推論を学ばせるための、より効率的で安定した方法です。

GRPO アルゴリズムの疑似コード

GRPO の主要な構成要素を理解したところで、疑似コードでアルゴリズム全体を見ていきます。以下は簡略版ですが、重要な考え方は捉えています。

入力:
- initial_policy: 学習対象となる初期モデル
- reward_function: 出力を評価する関数
- training_prompts: 学習用プロンプトの集合
- group_size: プロンプトごとの生成数（通常 4〜16）

アルゴリズム GRPO:
1. 学習の各反復について:
   a. reference_policy = initial_policy とする（現在の方策のスナップショット）
   b. バッチ内の各プロンプトについて:
      i. initial_policy を使って group_size 件の異なる出力を生成する
      ii. reward_function を使って各出力の報酬を計算する
      iii. グループ内で報酬を正規化する:
           normalized_advantage = (reward - mean(rewards)) / std(rewards)
      iv. クリップした比を最大化するように方策を更新する:
          min(prob_ratio * normalized_advantage,
              clip(prob_ratio, 1-epsilon, 1+epsilon) * normalized_advantage)
          - kl_weight * KL(initial_policy || reference_policy)

          ここで prob_ratio は current_prob / reference_prob

出力: 最適化された方策モデル

このアルゴリズムでは、グループ単位のアドバンテージ推定と方策最適化を組み合わせています。安定性は、クリッピングと KL ダイバージェンスの制約で保ちます。

GRPO の限界と課題

GRPO は言語モデルの強化学習を大きく進めましたが、限界と課題もあります。ここでは、その点を理解しておきます。

  • 生成コスト：プロンプトごとに複数の補完（4〜16件）を生成するため、1〜2件だけを生成する手法と比べ、必要な計算量が増えます。
  • バッチサイズの制約：補完のグループをまとめて処理する必要があるため、実効的なバッチサイズが制限されます。学習の手順が複雑になり、学習が遅くなる場合もあります。
  • 報酬関数の設計：学習の質は、適切に設計された報酬関数に大きく依存します。設計が不十分な報酬は、意図しない振る舞いや、誤った目的への最適化につながることがあります。
  • グループサイズのトレードオフ：最適なグループサイズの選択には、解の多様性と計算コストのバランスを取る必要があります。サンプルが少なすぎると十分な多様性が得られない場合があり、多すぎると学習時間と必要なリソースが増えます。
  • KL ダイバージェンスの調整：KL ダイバージェンスのペナルティの適切なバランスを見つけるには、慎重な調整が必要です。高すぎるとモデルは十分に学習できず、低すぎると当初の能力から離れすぎるおそれがあります。

結論

DeepSeek R1 の論文は、言語モデル開発における重要な節目です。Group Relative Policy Optimization（GRPO）アルゴリズムは、純粋な強化学習でも強い推論能力が育つことを示しました。教師ありファインチューニングが不可欠だという従来の前提は、見直しを迫られています。

特に重要なのは、DeepSeek R1 が高い性能と実用性の両立を示した点です。実用性とは、費用対効果や利用しやすさです。パラメータ数1.5Bから70Bまで、異なる大きさへの蒸留が成功したことは、高度な AI 能力をより広く届ける道を示しています。

次のセクションでは、これらの概念を実際にどう実装するかを探ります。焦点は、自身の言語モデル開発プロジェクトで GRPO と RFTrans をどう活用するかです。

クイズ

1. DeepSeek R1 論文の主な革新は何ですか？

正解です。GRPO の主要な革新は、選好の修正に向けて直接最適化できる点にあります。従来の RL 手法より効率的です。
この論文の革新は、使われた計算リソースではなく、アルゴリズムのアプローチ（GRPO）にあります。
革新はモデルの大きさではなく、学習方法と GRPO アルゴリズムにあります。

2. DeepSeek R1 の学習プロセスの4つのフェーズは何ですか？

正解です。これらは論文で説明された4つのフェーズそのもので、各フェーズが学習パイプラインで特定の役割を果たします。
この論文では、異なる4つのフェーズを具体的に述べています。Cold Start（品質の基盤）、Reasoning RL（能力の構築）、Rejection Sampling（品質管理）、Diverse RL（幅広いアライメント）です。
この論文では、Cold Start、Reasoning RL、Rejection Sampling、Diverse RL のフェーズを含む、特定の4フェーズのプロセスを説明しています。

3. R1-Zero の学習における「Aha モーメント」現象とは何ですか？

正解です。論文では、初めの試行、誤りの認識、自己修正、改善の説明という4ステップの過程として説明されています。
「Aha モーメント」は、人間の問題解決におけるひらめきと同様に、モデルが自らの誤りに気づき、正す能力を指します。
「Aha モーメント」は学習の完了ではなく、問題解決の最中にモデルが誤りに気づき、自己修正する創発的な能力に関するものです。

4. GRPO のグループ形成はどのように機能しますか？

正解です！GRPO は同じ問題を解く複数の試行（通常は4、8、又は16通り）を生成し、それらをグループとして評価します。
GRPO は複数の異なるモデルのアンサンブルではなく、1つのモデルを使って複数の解の試行を生成します。
GRPO のグループ形成は、学習データを分割することではなく、同じ問題に対する複数の解を生成することです。

5. DeepSeek-R1-Zero と DeepSeek-R1 の主な違いは何ですか？

正解です！比較表のとおり、R1-Zero は純粋な RL 学習を使い、R1 は教師ありファインチューニングと RL を組み合わせた複数フェーズのアプローチを使い、その結果、言語の一貫性が向上しています。
違いはモデルの大きさではなく、学習アプローチ（純粋な RL 対 複数フェーズ）にあります。
主な違いは学習方法です。R1-Zero は純粋な RL、R1 は SFT と RL を組み合わせたアプローチです。
