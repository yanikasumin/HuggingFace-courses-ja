# DEtection TRansformer (DETR)
## アーキテクチャの概要
DETR は主に物体検出タスクに使われます。物体検出とは、画像の中の物体を検出する処理です。たとえば、モデルの入力は道路の画像で、出力は `[('car',X1,Y1,W1,H1),('pedestrian',X2,Y2,W2,H2)]` のようになります。ここで X、Y、W、H は、バウンディングボックスの位置を示す x、y 座標と、ボックスの幅と高さを表します。YOLO のような従来の物体検出モデルでは、アンカーボックスの事前設定など、人手で設計した要素を使います。物体の位置や形状について予め仮定を置く必要があり、その設定は後の学習にも影響します。また、重なり合うバウンディングボックスを取り除く後処理も必要で、その際の判定基準は慎重に選ばなければなりません。DEtection TRansformer、略して DETR は、特徴抽出のバックボーンの後に encoder-decoder Transformer を使ってバウンディングボックスを並列に直接予測することで検出器を簡素化し、後処理を最小限に抑えます。

![DETR のアーキテクチャ図](https://huggingface.co/datasets/hf-vision/course-assets/resolve/main/DETR.png)
DETR のモデルアーキテクチャは、他の画像ベースのネットワークと同様に CNN バックボーンから始まります。その出力を処理して Transformer encoder に入力すると、N 個の埋め込みが得られます。encoder の埋め込みは、学習された位置埋め込み（object queries と呼ばれます）に加えられ、Transformer decoder で使われて、更に N 個の埋め込みが生成されます。最後のステップとして、N 個の埋め込みはそれぞれ個別の feed forward 層に通され、バウンディングボックスの幅、高さ、座標と、物体のクラス（又は物体が存在するかどうか）を予測します。

## 主な特徴

### Encoder-Decoder
他の Transformer と同様に、Transformer encoder は CNN バックボーンの出力が列であることを想定しています。そのため、`[dimension, height, width]` サイズの特徴マップは縮小され、`[dimension, less than height x width]` に平坦化されます。
![Encoder の特徴マップ](https://huggingface.co/datasets/hf-vision/course-assets/resolve/main/DETR_FeatureMaps.png)
_**左**：特徴マップの256次元のうち、12次元を可視化したものです。各次元では、画像を縮小しながら、元の猫の画像から異なる特徴を抽出しています。猫の模様に強く反応する次元もあれば、ベッドシーツに強く反応する次元もあります。_
_**右**：元の特徴次元である 256 というサイズを保ったまま、幅と高さは更に縮小され、850 というサイズに平坦化されています。_
Transformer は入力要素の順序を入れ替えても、その関係を区別できないため、各埋め込みが画像のどの位置に対応するかをモデルに伝える必要があります。そのため、エンコーダーとデコーダーの両方に位置埋め込みを加えます。エンコーダーでは固定の位置エンコーディングを使い、デコーダーでは学習可能な位置エンコーディング（object queries）を使います。固定の位置エンコーディングは、元の Transformer 論文で使われたものと似ており、特徴次元ごとに異なる周波数の正弦波関数で定義されます。学習するパラメータを持たず、画像内の位置に応じて値が決まることで、位置情報をモデルに与えます。一方、学習可能な位置エンコーディングでは、位置ごとに異なる表現を持ち、その値を訓練を通じて学習します。

### 集合ベースの大域損失関数
人気のある物体検出モデルである YOLO では、損失関数はバウンディングボックス、objectness（すなわち、注目領域に物体が存在する確率）、クラスの損失から構成されます。損失は各グリッドセルに対する複数のバウンディングボックスについて計算され、その数は固定です。一方 DETR では、アーキテクチャは順序不変な方法で一意なバウンディングボックスを生成することが求められます（すなわち、出力における検出の順序は重要ではなく、バウンディングボックスは互いに異ならなければならず、すべて同じではいけません）。そのため、予測がどれほど良いかを評価するにはマッチングが必要です。

**二部マッチング（Bipartite Matching）**
二部マッチングは、正解のバウンディングボックスと予測されたボックスとの間で 1 対 1 のマッチングを計算する方法です。正解と予測されたバウンディングボックス、及びクラスとの間で最も類似度が高いマッチを見つけます。これにより、最も近い予測が対応する正解とマッチし、損失関数の中でボックスとクラスを適切に調整できます。マッチングを行わないと、正解の順序と揃っていない予測は、正しくても誤りとして扱われてしまいます。

## DETR の進化
### Deformable DETR
DETR には主に2つの課題があります。学習が収束するまでに時間がかかることと、小さな物体の検出精度が十分でないことです。
**Deformable Attention**
1つ目の課題は、注目するサンプリング点の数を減らす Deformable Attention によって解決します。従来のアテンションは画像全体を対象とするため計算効率が悪く、扱える画像の解像度にも大きな制約があります。これに対して Deformable Attention は、入力に応じて学習した各参照点の周囲から、一定数のサンプリング点だけを選んで注目します。たとえば犬の画像なら、犬の中心を参照点とし、耳や口、尻尾の付近をサンプリング点とする、といった具合です。

**Multi-scale Deformable Attention Module**
2つ目の課題は、マルチスケールの特徴マップを導入した YOLOv3 と同様の方法で解決します。畳み込みニューラルネットワークでは、浅い層で線などの細かい特徴を抽出し、深い層では車輪や耳など、より大きな特徴を抽出します。同様に、Deformable Attention の異なる層からは、解像度の異なる特徴マップが得られます。エンコーダーの複数の層からの出力をデコーダーにつなぐことで、様々な大きさの物体を検出できるようになります。

### Conditional DETR
Conditional DETR も、元の DETR で学習の収束に時間がかかる問題の解決を目指したモデルで、6.7倍以上速い収束を実現します。著者らは、object queries が特定の入力画像に依存しない、汎用的なものであることを発見しました。デコーダーで **Conditional Cross-Attention** を使うことで、バウンディングボックス回帰の対象となる領域を、クエリがより正確に特定できるようになります。
![Conditional DETR の decoder 層](https://huggingface.co/datasets/hf-vision/course-assets/resolve/main/DETR_DecoderLayer.png)
_左：DETR の Decoder 層。右：Conditional DETR の Decoder 層_
上の図では、元の DETR と Conditional DETR の decoder 層が比較されており、主な違いは cross-attention ブロックのクエリ入力です。著者らは、content query c<sub>q</sub>（decoder の self attention の出力）と spatial query p<sub>q</sub> を区別しています。元の DETR は単に両者を足し合わせます。Conditional DETR では両者は連結され、c<sub>q</sub> は物体の内容に注目し、p<sub>q</sub> はバウンディングボックスの領域に注目します。spatial query p<sub>q</sub> は、decoder の埋め込みと object queries の両方が同じ空間に射影され（それぞれ T と p<sub>s</sub> になります）、互いに掛け合わされた結果です。前の層の decoder の埋め込みにはバウンディングボックス領域のための情報が含まれ、object queries には各バウンディングボックスについて学習された参照点の情報が含まれます。そのため、それらの射影が組み合わさって、cross-attention が encoder 入力及び正弦波の位置埋め込みとの類似度を測れる表現となります。これは、object queries と固定の参照点だけを使う DETR よりも効果的です。

## DETR の推論

Hugging Face Hub にある既存の DETR モデルを使って、次のように推論できます。

```python
from transformers import DetrImageProcessor, DetrForObjectDetection
import torch
from PIL import Image
import requests

url = "http://images.cocodataset.org/val2017/000000039769.jpg"
image = Image.open(requests.get(url, stream=True).raw)

# モデルを初期化します
processor = DetrImageProcessor.from_pretrained(
    "facebook/detr-resnet-101", revision="no_timm"
)
model = DetrForObjectDetection.from_pretrained(
    "facebook/detr-resnet-101", revision="no_timm"
)

# 入力を前処理して推論します
inputs = processor(images=image, return_tensors="pt")
outputs = model(**inputs)

# 出力（バウンディングボックスとクラスのロジット）を COCO API 形式に変換します
# 0.9 超に対する non-max suppression
target_sizes = torch.tensor([image.size[::-1]])
results = processor.post_process_object_detection(
    outputs, target_sizes=target_sizes, threshold=0.9
)[0]

for score, label, box in zip(results["scores"], results["labels"], results["boxes"]):
    box = [round(i, 2) for i in box.tolist()]
    print(
        f"検出：{model.config.id2label[label.item()]}、信頼度："
        f"{round(score.item(), 3)}、位置：{box}"
    )
```

出力は次のとおりです。

```bash 
検出：cat、信頼度：0.998、位置：[344.06, 24.85, 640.34, 373.74]
検出：remote、信頼度：0.997、位置：[328.13, 75.93, 372.81, 187.66]
検出：remote、信頼度：0.997、位置：[39.34, 70.13, 175.56, 118.78]
検出：cat、信頼度：0.998、位置：[15.36, 51.75, 316.89, 471.16]
検出：couch、信頼度：0.995、位置：[-0.19, 0.71, 639.73, 474.17]
```

## DETR の PyTorch 実装
元の論文の DETR の実装は次のとおりです。
```python
import torch
from torch import nn
from torchvision.models import resnet50


class DETR(nn.Module):
    def __init__(
        self, num_classes, hidden_dim, nheads, num_encoder_layers, num_decoder_layers
    ):
        super().__init__()
        self.backbone = nn.Sequential(*list(resnet50(pretrained=True).children())[:-2])
        self.conv = nn.Conv2d(2048, hidden_dim, 1)
        self.transformer = nn.Transformer(
            hidden_dim, nheads, num_encoder_layers, num_decoder_layers
        )
        self.linear_class = nn.Linear(hidden_dim, num_classes + 1)
        self.linear_bbox = nn.Linear(hidden_dim, 4)
        self.query_pos = nn.Parameter(torch.rand(100, hidden_dim))
        self.row_embed = nn.Parameter(torch.rand(50, hidden_dim // 2))
        self.col_embed = nn.Parameter(torch.rand(50, hidden_dim // 2))

    def forward(self, inputs):
        x = self.backbone(inputs)
        h = self.conv(x)
        H, W = h.shape[-2:]
        pos = (
            torch.cat(
                [
                    self.col_embed[:W].unsqueeze(0).repeat(H, 1, 1),
                    self.row_embed[:H].unsqueeze(1).repeat(1, W, 1),
                ],
                dim=-1,
            )
            .flatten(0, 1)
            .unsqueeze(1)
        )
        h = self.transformer(
            pos + h.flatten(2).permute(2, 0, 1), self.query_pos.unsqueeze(1)
        )
        return self.linear_class(h), self.linear_bbox(h).sigmoid()
```
### `forward` 関数を 1 行ずつ見ていく
**バックボーン**
入力画像はまず ResNet バックボーンに通され、次に畳み込み層に通されます。これにより次元が `hidden_dim` に削減されます。
```python
x = self.backbone(inputs)
h = self.conv(x)
```
これらは `__init__` 関数で宣言されています。
```python
self.backbone = nn.Sequential(*list(resnet50(pretrained=True).children())[:-2])
self.conv = nn.Conv2d(2048, hidden_dim, 1)
```

**位置埋め込み**

論文では encoder と decoder でそれぞれ固定の埋め込みと訓練される埋め込みが使われていますが、実装では著者らは簡単のために両方に訓練される埋め込みを使いました。
```python
pos = (
    torch.cat(
        [
            self.col_embed[:W].unsqueeze(0).repeat(H, 1, 1),
            self.row_embed[:H].unsqueeze(1).repeat(1, W, 1),
        ],
        dim=-1,
    )
    .flatten(0, 1)
    .unsqueeze(1)
)
```
これらはここで `nn.Parameter` として宣言されています。行と列の埋め込みの組み合わせが、画像内の位置を示します。
```python
self.row_embed = nn.Parameter(torch.rand(50, hidden_dim // 2))
self.col_embed = nn.Parameter(torch.rand(50, hidden_dim // 2))
```
**テンソルの形状変更**
Transformer に入る前に、サイズ `(batch size, hidden_dim, H, W)` の特徴は `(hidden_dim, batch size, H*W)` に変形されます。これにより、Transformer への逐次入力となります。
```python
h.flatten(2).permute(2, 0, 1)
```
**Transformer**
`nn.Transformer` 関数は、第 1 引数を encoder への入力として受け取り、第 2 引数を encoder の入力として受け取ります。見て分かるように、encoder は位置埋め込みに加えられた変形済みの特徴を受け取り、decoder は decoder の位置埋め込みである `query_pos` を受け取ります。
```python
h = self.transformer(pos + h.flatten(2).permute(2, 0, 1), self.query_pos.unsqueeze(1))
```
**Feed-Forward Network**
最後に、サイズ `(query_pos_dim, batch size, hidden_dim)` のテンソルである出力は、2 つの線形層に通されます。
```python
return self.linear_class(h), self.linear_bbox(h).sigmoid()
```
1 つ目はクラスを予測します。`No Object` クラスのために追加のクラスが加えられます。
```python
self.linear_class = nn.Linear(hidden_dim, num_classes + 1)
```
2 つ目の線形層は、xy 座標、高さ、幅のための出力サイズ 4 でバウンディングボックスを予測します。
```python
self.linear_bbox = nn.Linear(hidden_dim, 4)
```
