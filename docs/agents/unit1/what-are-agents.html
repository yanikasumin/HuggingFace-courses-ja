エージェントとは何か？

このセクションを終えるころには、エージェントとは何か、AI の分野でどのように活用されているのかを理解出来るようになっているはずです。

エージェントとは何かを説明する為に、まず例え話から始めましょう。

全体像：エージェント Alfred

Alfred を紹介します。Alfred は エージェント です。

Alfred が 命令を受ける 所を想像してください。例えば「Alfred、コーヒーをお願い」といった命令です。

Alfred は 自然言語を理解出来る ので、私たちの依頼を直ぐに把握します。

依頼に応える前に、Alfred は 推論と計画 を行い、必要な手順とツールを検討します。

  1. キッチンへ行く
  2. コーヒーマシンを使う
  3. コーヒーを淹れる
  4. コーヒーを持って戻る

計画を立てたら、次は実際に 行動する必要が有ります。その為に、利用可能なツールの一覧から適切なものを選んで使うことが出来ます。

この場合、コーヒーを作る為にコーヒーマシンを使います。コーヒーマシンを起動してコーヒーを淹れます。

最後に、Alfred は淹れたてのコーヒーを私たちの所へ持ってきます。

これがエージェントです。推論し、計画し、環境とやり取り出来る AI モデル です。

エージェントと呼ばれるのは、agency（主体性）、つまり環境とやり取りする能力を持っているからです。

もう少し形式的に

全体像をつかんだ所で、より正確な定義を見てみましょう。

エージェントとは、ユーザーが定義した目的を達成する為に、AI モデルを活用して環境とやり取りするシステムです。推論、計画、アクションの実行（多くの場合、外部ツール経由）を組み合わせてタスクを果たします。

エージェントは主に2つの部分から成ると考えてください。

  1. 頭脳（AI モデル）

思考が全て行われる場所です。AI モデルが 推論と計画を担います。状況に基づいて どのアクションを取るかを決定します。

  1. 身体（能力とツール）

エージェントが持つ能力や、実行出来る操作の範囲を表します。

可能なアクションの範囲 は、エージェントが 何を備えているか に依存します。例えば、人間には翼がない為「飛ぶ」という アクション は実行出来ませんが、「歩く」「走る」「跳ぶ」「掴む」といった アクション は実行出来ます。

「主体性（Agency）」のスペクトラム

この定義に基づくと、エージェントの主体性には様々な段階が有り、その度合いは連続的に変化すると考えられます。

主体性レベル 説明 呼び名 パターンの例
☆☆☆ エージェントの出力がプログラムの流れに影響しない Simple processor process_llm_output(llm_response)
★☆☆ エージェントの出力が基本的な制御フローを決める Router if llm_decision(): path_a() else: path_b()
★★☆ エージェントの出力が関数の実行を決める Tool caller run_function(llm_chosen_tool, llm_chosen_args)
★★★ エージェントの出力が反復とプログラムの継続を制御する Multi-step Agent while llm_should_continue(): execute_next_step()
★★★ 或るエージェンティックなワークフローが別のワークフローを開始出来る Multi-Agent if llm_trigger(): execute_agent()

エージェントにはどんな AI モデルを使うのか？

エージェントで最もよく使われる AI モデルは LLM（大規模言語モデル）です。テキスト を入力として受け取り、テキスト を出力します。

よく知られた例として、OpenAI の GPT-4、Meta の Llama、Google の Gemini などが有ります。これらのモデルは膨大な量のテキストで訓練されており、高い汎化能力を持ちます。LLM については 次のセクション で詳しく学びます。

💡 ヒント

エージェントの中核モデルとして、他の入力を受け付けるモデルを使うことも出来ます。例えば Vision Language Model（VLM）は、LLM のようなものですが、画像も入力として理解出来ます。今は LLM に集中し、他の選択肢は後で議論します。

AI はどうやって環境に働きかけるのか？

LLM は素晴らしいモデルですが、テキストしか生成出来ません。

しかし、HuggingChat や ChatGPT のような有名なチャットアプリに画像の生成を頼むと、実際に生成出来ます。これはどういうことでしょうか？

答えは、HuggingChat や ChatGPT などの開発者が、LLM が画像を作成する為に使える追加機能（ツール と呼びます）を実装したからです。

ツールについては ツール のセクションで詳しく学びます。

エージェントはどんなタスクを実行出来るのか？

エージェントは、必要な ツール を実装して アクション を実行させることで、様々なタスクに対応出来ます。

例えば、コンピュータ上でパーソナルアシスタント（Siri のようなもの）として動作するエージェントを書き、「マネージャーにメールを送って、今日の会議を延期してもらえるよう頼んで」と依頼したとします。この時、メールを送信するコードを渡すことが出来ます。これが、メールを送る必要が有る時にエージェントが使える新しいツールになります。Python で書くと次のようになります。

def send_message_to(recipient, message):
    """Useful to send an e-mail message to a recipient"""
    ...

（docstring の訳：受信者にメールメッセージを送るのに便利です）

後で見るように、LLM は必要に応じてツールを実行するコードを生成し、望んだタスクを果たします。

send_message_to("Manager", "Can we postpone today's meeting?")

（呼び出しの訳：「Manager（マネージャー）」へ「今日の会議を延期出来ますか？」というメッセージを送ります）

ツールの設計は非常に重要で、エージェントの品質に大きな影響を与えます。タスクによっては非常に特殊なツールを仕立てる必要が有りますが、"web_search" のような汎用ツールで解決出来るものも有ります。

なお、アクションとツールは同じものではありません。例えば、1つのアクションを完了する為に複数のツールを使う場合が有ります。

エージェントが外部の環境とやり取り出来るようになれば、企業の業務や個人の日常生活にも活用出来ます。

例1: パーソナル仮想アシスタント

Siri、Alexa、Google アシスタントのような仮想アシスタントは、ユーザーのデジタル環境を使ってユーザーに代わってやり取りする時、エージェントとして動作します。

ユーザーのクエリを受け取り、コンテキストを分析し、データベースから情報を取得して、応答を提供したりアクションを開始したりします（リマインダーの設定、メッセージの送信、スマートデバイスの制御など）。

例2: カスタマーサービスチャットボット

多くの企業は、自然言語で顧客とやり取りするエージェントとしてチャットボットを導入しています。

これらのエージェントは、質問に答えたり、トラブルシューティングの手順にユーザーを案内したり、内部データベースに課題を登録したり、取引を完了させたり出来ます。

予め設定する目標には、顧客満足度の向上、待ち時間の短縮、売上コンバージョン率の向上などが有ります。こうしたエージェントは、顧客と直接やり取りし、対話から学びながら、時間の経過と共に応答を調整することで、エージェントの核となる原則を実践しています。

例3: ビデオゲームの AI ノンプレイヤーキャラクター

LLM を活用した AI エージェントは、ノンプレイヤーキャラクター（NPC）をより動的で予測不能なものに出来ます。

硬直したビヘイビアツリーに従う代わりに、文脈に応じて応答し、プレイヤーとのやり取りに適応し、よりニュアンスのある対話を生成出来ます。この柔軟性により、プレイヤーの行動と共に進化する、より生き生きとした魅力的なキャラクターを作り出せます。

まとめると、エージェントとは、中核の推論エンジンとして AI モデル（通常は LLM）を使うシステムで、次のことを行います。

  • 自然言語を理解する：人間の指示を意味の有る形で解釈し、応答する。
  • 推論し計画する：情報を分析し、意思決定を行い、問題を解決する戦略を立てる。
  • 環境とやり取りする：情報を集め、アクションを取り、そのアクションの結果を観察する。

エージェントとは何かをしっかりつかめたので、短い採点なしクイズで理解を固めましょう。そのあとは、エージェントの「頭脳」である LLM に踏み込みます。
