トークナイザは、NLP パイプラインの中核となるコンポーネントの1つです。役割は、テキストをモデルが処理出来る数値データに変換することです。モデルはテキストをそのまま扱えない為、トークナイザによる変換が欠かせません。このセクションでは、トークン化の仕組みを詳しく見ていきます。

NLP タスクで一般に処理されるデータは、生のテキストです。例えば次のようなテキストです。

```
Jim Henson was a puppeteer
```

（例文の訳：ジム・ヘンソンは人形遣いだった）

但し、モデルが処理出来るのは数値だけです。生のテキストを数値に変換する方法が必要になります。それを行うのがトークナイザで、方法は沢山あります。目標は、モデルにとって最も意味の有る表現を見つけると共に、可能な限り小さい表現にすることです。

いくつかのトークン化アルゴリズムを例に、仕組みやよくある疑問について見ていきましょう。

## 単語ベース[[word-based]]

<Youtube id="nhJxYji1aho"/>

トークン化の手法として最初に思い浮かぶのは、_単語ベース_ のものです。数少ないルールだけで構築出来、使い易く、そこそこ良い結果が得られることが多い手法です。下の図は、生のテキストを単語に分割し、それぞれに数値を割り当てる方法を示しています。

<div class="flex justify-center">
  <img class="block dark:hidden" src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter2/word_based_tokenization.svg" alt="単語ベースのトークン化の例。"/>
  <img class="hidden dark:block" src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter2/word_based_tokenization-dark.svg" alt="単語ベースのトークン化の例。"/>
</div>

テキストの分割方法はいくつかあります。例えば、Python の `split()` 関数を使えば、空白を区切りとしてテキストを単語ごとに分割出来ます。

```py
tokenized_text = "Jim Henson was a puppeteer".split()
print(tokenized_text)
```

```python out
['Jim', 'Henson', 'was', 'a', 'puppeteer']
```

単語ベースのトークナイザには、句読点の扱いについて追加のルールを設けたものもあります。こうしたトークナイザでは、語彙の総数がかなり多くなることがあります。語彙とは、コーパスに含まれる独立したトークンの総数のことです。

各単語には、0 から語彙のサイズまでの ID が割り当てられます。モデルはこれらの ID を使って各単語を識別します。

単語ベースのトークナイザで1つの言語を完全にカバーしようとすると、その言語の全ての単語に識別子が必要になり、膨大な数のトークンが発生します。例えば英語には 500,000 語以上の単語が有る為、各単語を入力 ID に対応づけるには、それだけの数の ID を管理しなければなりません。

更に、"dog" と "dogs" のような単語は別々に表現される為、モデルは最初、"dog" と "dogs" が似ていることを知る手段がありません。2つの単語は無関係なものとして識別されます。"run" と "running" のような似た単語についても同様で、モデルは最初は似ているとは見なしません。

最後に、語彙に含まれていない単語を表す為の専用トークンが必要です。これは「未知」トークンと呼ばれ、"[UNK]" や "&lt;unk&gt;" と表されることが多いものです。トークナイザがこのトークンを大量に生成しているのは、一般に良くない兆候です。単語の妥当な表現を取り出せず、情報が失われていることを意味するからです。語彙を構築する際には、未知トークンに置き換えられる単語を出来るだけ減らすことが目標です。

未知トークンを減らす方法の1つは、単語を更に細かく分割する _文字ベース_ のトークナイザを使うことです。

## 文字ベース[[character-based]]

<Youtube id="ssLq_EK2jLE"/>

文字ベースのトークナイザは、テキストを単語ではなく文字に分割します。主な利点は2つあります。

- 語彙がはるかに小さくなります。
- 全ての単語を文字から組み立てられる為、語彙外（未知）のトークンがはるかに少なくなります。

但し、ここでも空白や句読点に関して疑問が生じます。

<div class="flex justify-center">
  <img class="block dark:hidden" src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter2/character_based_tokenization.svg" alt="文字ベースのトークン化の例。"/>
  <img class="hidden dark:block" src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter2/character_based_tokenization-dark.svg" alt="文字ベースのトークン化の例。"/>
</div>

但し、この方法にも欠点があります。単語を文字単位に分割すると、各トークンが持つ意味の情報が少なくなる場合があります。一般に、単語には意味がありますが、個々の文字にはそれほど多くの意味がありません。但し、この違いは言語によって異なります。例えば中国語の文字は、ラテン系言語で使われる文字よりも多くの情報を持っています。

もう1つ考慮すべき点は、モデルが処理するトークンの量が非常に多くなることです。単語ベースのトークナイザなら1単語は1トークンで済みますが、文字単位に分割すると、同じ単語でも簡単に10トークン以上になります。

両方の良いところを取る為に、2つのアプローチを組み合わせた3つ目の手法、*サブワードトークン化* を使うことが出来ます。

## サブワードトークン化[[subword-tokenization]]

<Youtube id="zHvTiHr506c"/>

サブワードトークン化アルゴリズムは、頻繁に使われる単語はより小さいサブワードに分割せず、まれな単語は意味のあるサブワードに分解する、という原則に基づいています。

例えば "annoyingly" はまれな単語と見なされ、"annoying" と "ly" に分解出来ます。どちらも独立したサブワードとしては頻繁に現れる一方で、"annoying" と "ly" の組み合わせによって "annoyingly" の意味も保たれます。

サブワードトークン化アルゴリズムが "Let's do tokenization!" というシーケンスをどのようにトークン化するか、例を示します。

<div class="flex justify-center">
  <img class="block dark:hidden" src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter2/bpe_subword.svg" alt="サブワードトークン化アルゴリズム。"/>
  <img class="hidden dark:block" src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter2/bpe_subword-dark.svg" alt="サブワードトークン化アルゴリズム。"/>
</div>

このように分割したサブワードからは、単語の意味に関する多くの情報が得られます。例えば上の例では、"tokenization" が "token" と "ization" に分割されています。どちらも意味の有る単位で、長い単語をわずか2つのトークンで効率よく表現出来ます。これにより、小さい語彙で比較的良いカバー率が得られ、未知トークンもほぼゼロに出来ます。

このアプローチは、トルコ語のような膠着語で特に役立ちます。サブワードをつなぎ合わせることで、（ほぼ）任意の長さの複雑な単語を形成出来るからです。

## 読み込みと保存[[loading-and-saving]]

トークナイザの読み込みと保存は、モデルの場合と同じくらい簡単です。実際、同じ2つのメソッド、`from_pretrained()` と `save_pretrained()` が使われます。これらのメソッドは、トークナイザが使うアルゴリズム（モデルの *アーキテクチャ* のようなもの）と、その語彙（モデルの *重み* のようなもの）を読み込んだり保存したりします。

BERT と同じチェックポイントで訓練されたトークナイザも、モデルと同様の方法で読み込めます。但し `BertTokenizer` クラスを使います。

```py
from transformers import BertTokenizer

tokenizer = BertTokenizer.from_pretrained("bert-base-cased")
```

`AutoModel` と同様に、`AutoTokenizer` クラスはチェックポイント名に基づいてライブラリから適切なトークナイザクラスを取得し、任意のチェックポイントで直接使うことが出来ます。

```py
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-cased")
```

取得したトークナイザには、前のセクションと同様にテキストを直接渡せます。

```python
tokenizer("Using a Transformer network is simple")
```

```python out
{'input_ids': [101, 7993, 170, 11303, 1200, 2443, 1110, 3014, 102],
 'token_type_ids': [0, 0, 0, 0, 0, 0, 0, 0, 0],
 'attention_mask': [1, 1, 1, 1, 1, 1, 1, 1, 1]}
```

トークナイザの保存は、モデルの保存とまったく同じです。

```py
tokenizer.save_pretrained("directory_on_my_computer")
```

`token_type_ids` については[第3章](/course/chapter3)で詳しく取り上げ、`attention_mask` キーについてはこの後すぐ説明します。先ず、`input_ids` がどのように生成されるのかを見ていきましょう。その為に、トークナイザの処理を途中の段階ごとに確認出来るメソッドを見ていきます。

## エンコーディング[[encoding]]

<Youtube id="Yffk5aydLzg"/>

テキストを数値に変換することは、_エンコーディング_ と呼ばれます。エンコーディングは2段階のプロセスで行われます。先ずトークン化し、次に入力 ID へ変換します。

最初のステップでは、テキストを単語や単語の一部、句読点などに分割します。分割して得られる単位を *トークン* と呼びます。トークン化には様々な方法がありますが、モデルの事前学習時と同じ方法を使う必要があります。その為、モデル名を指定してトークナイザをインスタンス化します。

2つ目のステップでは、トークンを数値に変換します。こうして得られた数値からテンソルを作り、モデルに入力します。この変換に使うのが、トークナイザの持つ *語彙* です。語彙のデータは、`from_pretrained()` メソッドでトークナイザをインスタンス化する時にダウンロードされます。ここでも、モデルの事前学習時と同じ語彙を使う必要があります。

この2つのステップを理解する為に、それぞれの処理を分けて見ていきます。ここでは途中の結果を確認出来るよう、トークン化パイプラインの各処理を個別のメソッドで実行します。但し、実際に使う時は、セクション2で紹介したようにトークナイザを直接呼び出して下さい。

### トークン化[[tokenization]]

トークン化のプロセスは、トークナイザの `tokenize()` メソッドで行われます。

```py
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-cased")

sequence = "Using a Transformer network is simple"
tokens = tokenizer.tokenize(sequence)

print(tokens)
```

このメソッドは、トークンを表す文字列のリストを返します。

```python out
['Using', 'a', 'transform', '##er', 'network', 'is', 'simple']
```

このトークナイザはサブワードトークナイザです。語彙で表現出来るトークンが得られるまで、単語を分割します。この例では、`transformer` という単語が、語彙で表現出来る `transform` と `##er` の2つのトークンに分割されています。

### トークンから入力 ID へ[[from-tokens-to-input-ids]]

入力 ID への変換は、トークナイザの `convert_tokens_to_ids()` メソッドが担います。

```py
ids = tokenizer.convert_tokens_to_ids(tokens)

print(ids)
```

```python out
[7993, 170, 11303, 1200, 2443, 1110, 3014]
```

これらの出力は、適切なフレームワークのテンソルに変換すれば、この章の前半で見たように、モデルへの入力として使うことが出来ます。

> [!TIP]
> **試してみましょう！** 最後の2つのステップ（トークン化と入力 ID への変換）を、セクション2で使った入力文（"I've been waiting for a HuggingFace course my whole life." と "I hate this so much!"）に対して再現してみて下さい。前に得たのと同じ入力 ID が得られることを確認しましょう！

## デコーディング[[decoding]]

*デコーディング* はその逆で、語彙のインデックスから文字列を得ることです。これは `decode()` メソッドで次のように行えます。

```py
decoded_string = tokenizer.decode([7993, 170, 11303, 1200, 2443, 1110, 3014])
print(decoded_string)
```

```python out
'Using a Transformer network is simple'
```

`decode` メソッドは、インデックスをトークンに戻すだけでなく、同じ単語を構成していたトークンをまとめ直し、読み易い文に復元します。この機能は、新しいテキストを予測・生成するモデルで特に役立ちます。例えば、プロンプトに続くテキストの生成や、翻訳・要約のようなシーケンス・ツー・シーケンスのタスクで利用します。

ここまでで、トークナイザが扱える基本的な操作、つまりトークン化、ID への変換、ID から文字列への変換が理解出来たはずです。但し、これはまだ氷山の一角に過ぎません。次のセクションでは、ここまで紹介した方法の限界と、それを克服する方法を見ていきます。
