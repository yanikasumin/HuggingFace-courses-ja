実践演習： Unsloth で GRPO

この演習では、Unsloth を使って GRPO（Group Relative Policy Optimization）でモデルをファインチューニングし、モデルの推論能力を高めます。GRPO については、第3章で説明しました。

Unsloth は、LLM のファインチューニングを高速化するライブラリです。学習を速くし、必要な計算リソースも少なくできます。Unsloth は TRL に組み込んで使うため、前のセクションで学んだ内容を土台にできます。この演習では、その内容を Unsloth 固有の設定に合わせて進めます。

💡 ヒント

この演習は、無料の Google Colab（T4 GPU）で実行できます。上のリンク先のノートブックに沿って、自分で試しながら進めるのがおすすめです。

依存関係をインストールする

まず、必要なライブラリをインストールします。使うのは、ファインチューニングを高速化する Unsloth と、高速な推論を行う vLLM です。

pip install unsloth vllm
pip install --upgrade pillow

Unsloth をセットアップする

Unsloth には、Transformers に Unsloth の最適化を組み合わせるクラス FastLanguageModel があります。まず、これをインポートします。

from unsloth import FastLanguageModel

次に、Google の Gemma 3 1B Instruct モデルを読み込み、ファインチューニング用に設定します。

from unsloth import FastLanguageModel
import torch

max_seq_length = 1024  # より長い推論過程を扱う場合は値を増やす
lora_rank = 32  # ランクが大きいほど賢くなるが、遅くなる

model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="google/gemma-3-1b-it",
    max_seq_length=max_seq_length,
    load_in_4bit=True,  # LoRA 16bit の場合は False
    fast_inference=True,  # vLLM の高速推論を有効にする
    max_lora_rank=lora_rank,
    gpu_memory_utilization=0.6,  # メモリ不足の場合は減らす
)

model = FastLanguageModel.get_peft_model(
    model,
    r=lora_rank,  # 0 より大きい任意の数を選ぶ。推奨は 8, 16, 32, 64, 128
    target_modules=[
        "q_proj",
        "k_proj",
        "v_proj",
        "o_proj",
        "gate_proj",
        "up_proj",
        "down_proj",
    ],  # メモリ不足の場合は QKVO を外す
    lora_alpha=lora_rank,
    use_gradient_checkpointing="unsloth",  # 長いコンテキストのファインチューニングを有効にする
    random_state=3407,
)

このコードでは、メモリを節約するためにモデルを4ビット量子化で読み込みます。併せて、効率よくファインチューニングするために LoRA（Low-Rank Adaptation）を適用します。target_modules は、ファインチューニングの対象とする層を指定するパラメータです。use_gradient_checkpointing を有効にすると、より長いコンテキストでも学習できます。

💡 ヒント

この章では LoRA の詳細には触れません。詳しくは、第11章を参照してください。

データの準備

この演習では、小学校レベルの数学の問題を集めた GSM8K データセットを使います。データは、モデルが答えを出す前に推論を示すよう促す形式に整形します。

まず、プロンプトと答えの形式を定義します。

# モデルに特定の形式を使うよう指示するシステムプロンプトを定義する
SYSTEM_PROMPT = """
Respond in the following format:
<reasoning>
...
</reasoning>
<answer>
...
</answer>
"""

XML_COT_FORMAT = """\
<reasoning>
{reasoning}
</reasoning>
<answer>
{answer}
</answer>
"""

（プロンプトの訳：次の形式で応答してください）

次に、データセットを準備します。

import re
from datasets import load_dataset, Dataset


# さまざまな形式から答えを取り出すためのヘルパー関数
def extract_xml_answer(text: str) -> str:
    answer = text.split("<answer>")[-1]
    answer = answer.split("</answer>")[0]
    return answer.strip()


def extract_hash_answer(text: str) -> str | None:
    if "####" not in text:
        return None
    return text.split("####")[1].strip()


# GSM8K データセットを準備する関数
def get_gsm8k_questions(split="train") -> Dataset:
    data = load_dataset("openai/gsm8k", "main")[split]
    data = data.map(
        lambda x: {
            "prompt": [
                {"role": "system", "content": SYSTEM_PROMPT},
                {"role": "user", "content": x["question"]},
            ],
            "answer": extract_hash_answer(x["answer"]),
        }
    )
    return data


dataset = get_gsm8k_questions()

このように、GSM8K の回答から答えを取り出し、文字列として整形してデータセットを用意します。

報酬関数を定義する

前のページで説明したように、GRPO は報酬関数を使ってモデルの学習を導くことができます。基準には、長さや形式といった検証可能なものを使います。

この演習では、良い推論の様々な面を促す報酬関数をいくつか定義します。たとえば、整数の答えを出すことや、厳密な形式に従うことに対して報酬を与えます。

# 答えが正しいかをチェックする報酬関数
def correctness_reward_func(prompts, completions, answer, **kwargs) -> list[float]:
    responses = [completion[0]["content"] for completion in completions]
    q = prompts[0][-1]["content"]
    extracted_responses = [extract_xml_answer(r) for r in responses]
    print(
        "-" * 20,
        f"問題:\n{q}",
        f"\n正解:\n{answer[0]}",
        f"\nモデルの応答:\n{responses[0]}",
        f"\n抽出した答え:\n{extracted_responses[0]}",
    )
    return [2.0 if r == a else 0.0 for r, a in zip(extracted_responses, answer)]


# 答えが整数であるかをチェックする報酬関数
def int_reward_func(completions, **kwargs) -> list[float]:
    responses = [completion[0]["content"] for completion in completions]
    extracted_responses = [extract_xml_answer(r) for r in responses]
    return [0.5 if r.isdigit() else 0.0 for r in extracted_responses]


# 補完が厳密な形式に従っているかをチェックする報酬関数
def strict_format_reward_func(completions, **kwargs) -> list[float]:
    pattern = r"^<reasoning>\n.*?\n</reasoning>\n<answer>\n.*?\n</answer>\n$"
    responses = [completion[0]["content"] for completion in completions]
    matches = [re.match(pattern, r) for r in responses]
    return [0.5 if match else 0.0 for match in matches]


# 補完がより緩やかな形式に従っているかをチェックする報酬関数
def soft_format_reward_func(completions, **kwargs) -> list[float]:
    pattern = r"<reasoning>.*?</reasoning>\s*<answer>.*?</answer>"
    responses = [completion[0]["content"] for completion in completions]
    matches = [re.match(pattern, r) for r in responses]
    return [0.5 if match else 0.0 for match in matches]


# XML タグを数え、余分な内容にペナルティを与える報酬関数
def count_xml(text) -> float:
    count = 0.0
    if text.count("<reasoning>\n") == 1:
        count += 0.125
    if text.count("\n</reasoning>\n") == 1:
        count += 0.125
    if text.count("\n<answer>\n") == 1:
        count += 0.125
        count -= len(text.split("\n</answer>\n")[-1]) * 0.001
    if text.count("\n</answer>") == 1:
        count += 0.125
        count -= (len(text.split("\n</answer>")[-1]) - 1) * 0.001
    return count


def xmlcount_reward_func(completions, **kwargs) -> list[float]:
    contents = [completion[0]["content"] for completion in completions]
    return [count_xml(c) for c in contents]

各報酬関数の目的は、次のとおりです。

報酬関数 目的
correctness_reward_func モデルの答えが正解と一致したときに報酬を与えます
int_reward_func 数値の答えを出したときにモデルに報酬を与えます
strict_format_reward_func と soft_format_reward_func 指定された形式に従ったときにモデルに報酬を与えます
xmlcount_reward_func XML タグを適切に使った場合に報酬を与え、閉じタグの後にある余分な内容にはペナルティを与えます

GRPO で学習する

次に、モデル、トークナイザー、報酬関数を使って GRPO トレーナーを設定します。進め方は、前の演習と同じです。

from trl import GRPOConfig, GRPOTrainer

max_prompt_length = 256

training_args = GRPOConfig(
    learning_rate=5e-6,
    adam_beta1=0.9,
    adam_beta2=0.99,
    weight_decay=0.1,
    warmup_ratio=0.1,
    lr_scheduler_type="cosine",
    optim="paged_adamw_8bit",
    logging_steps=1,
    per_device_train_batch_size=1,
    gradient_accumulation_steps=1,  # よりスムーズな学習のためには 4 に増やす
    num_generations=6,  # メモリ不足の場合は減らす
    max_prompt_length=max_prompt_length,
    max_completion_length=max_seq_length - max_prompt_length,
    # num_train_epochs = 1, # フルの学習ランでは 1 に設定する
    max_steps=250,
    save_steps=250,
    max_grad_norm=0.1,
    report_to="none",  # Weights & Biases を使うこともできる
    output_dir="outputs",
)

trainer = GRPOTrainer(
    model=model,
    processing_class=tokenizer,
    reward_funcs=[
        xmlcount_reward_func,
        soft_format_reward_func,
        strict_format_reward_func,
        int_reward_func,
        correctness_reward_func,
    ],
    args=training_args,
    train_dataset=dataset,
)

GRPOConfig では、学習に関する様々なハイパーパラメータを設定します。

  • use_vllm：vLLM による高速推論を有効にします
  • learning_rate：モデルが学習する速さを制御します
  • num_generations：各プロンプトに対して生成する補完の数です
  • max_steps：実行する学習ステップの総数です

では、学習を開始しましょう。

trainer.train()

⚠️ 注意

学習には時間がかかる場合があります。報酬はすぐには増えないこともあります。改善が見られるまで150〜200ステップかかることもあるので、気長に待ってください。

モデルをテストする

学習が終わったら、モデルがどのように動作するかテストします。まず、LoRA の重みを保存します。

model.save_lora("grpo_saved_lora")

次に、新しい質問でモデルをテストします。

from vllm import SamplingParams

text = tokenizer.apply_chat_template(
    [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": "Calculate pi."},
    ],
    tokenize=False,
    add_generation_prompt=True,
)

sampling_params = SamplingParams(
    temperature=0.8,
    top_p=0.95,
    max_tokens=1024,
)
output = (
    model.fast_generate(
        text,
        sampling_params=sampling_params,
        lora_request=model.load_lora("grpo_saved_lora"),
    )[0]
    .outputs[0]
    .text
)

print(output)

モデルが指定した形式に従い、答えの前に推論を示すようになっているはずです。出力で確認してください。

モデルを保存する

Unsloth には、ファインチューニングしたモデルを保存する方法がいくつかあります。ここでは、最も一般的な方法を取り上げます。

# 16ビット精度で保存する
model.save_pretrained_merged("model", tokenizer, save_method="merged_16bit")

Hugging Face Hub にプッシュする

push_to_hub_merged メソッドを使うと、モデルを Hugging Face Hub にプッシュできます。このメソッドでは、複数の量子化形式でプッシュできます。

# Hugging Face Hub にプッシュする（トークンが必要）
model.push_to_hub_merged(
    "your-username/model-name", tokenizer, save_method="merged_16bit", token="your-token"
)

Unsloth は、llama.cpp で使う GGUF 形式での保存にも対応しています。

model.push_to_hub_gguf(
    "your-username/model-name",
    tokenizer,
    quantization_method=["q4_k_m", "q8_0", "q5_k_m"],
    token="your-token",
)

GGUF ファイルは、llama.cpp や、Jan、Open WebUI のような UI ベースのシステムで使えます。

結論

この演習では、次の方法を学びました。

  1. 高速なファインチューニングのために Unsloth をセットアップする
  2. GRPO 学習のためにデータを準備する
  3. モデルの学習を導くカスタム報酬関数を定義する
  4. GRPO を使ってモデルを学習する
  5. ファインチューニングしたモデルをテストする
  6. モデルを様々な形式で保存する

GRPO は、言語モデルを特定の振る舞いに合わせるための強力な手法です。Unsloth を使えば、限られたハードウェアでも GRPO を利用できます。複数の報酬関数を組み合わせると、モデルが特定の形式に従うよう導きながら、推論能力も高められます。
