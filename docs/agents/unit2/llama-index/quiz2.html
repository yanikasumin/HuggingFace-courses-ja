簡単なセルフチェック（採点なし）

えっ、またクイズですか？ その気持ちは分かります…… でも、この短い採点なしのクイズは、今学んだばかりの重要な概念を定着させる為のものです。

このクイズでは、効果的な AI エージェントを構築する上で欠かせない、エージェントのワークフローとインタラクションを扱います。

Q1：LlamaIndex の AgentWorkflow の目的は何ですか？

はい。AgentWorkflow は、1 つ以上のエージェントからなるシステムを手早く作成する為の主な方法です。
いいえ。AgentWorkflow は、それよりも幅広い機能を備えています。データに対する単純なクエリには QueryEngine を使います。
AgentWorkflow がツールを構築することはありません。ツールの構築は開発者の仕事です。
メモリと状態の管理は、AgentWorkflow の主な目的ではありません。

Q2：ワークフローの状態を追跡する為に使うオブジェクトはどれですか？

State は、ワークフローの状態管理に使う正しいオブジェクトではありません。
Context が、ワークフローの状態を追跡する為に使う正しいオブジェクトです。
WorkflowState は正しいオブジェクトではありません。
Management は、ワークフローの状態に使える有効なオブジェクトではありません。

Q3：エージェントに過去のインタラクションを記憶させたい場合、どのメソッドを使うべきですか？

.run(query_str) では会話履歴は保持されません。
chat() はワークフローで使える有効なメソッドではありません。
interact() は、エージェントとのインタラクションに使える有効なメソッドではありません。
コンテキストを渡して維持することで、状態を保持出来ます。

Q4：Agentic RAG の主な特徴は何ですか？

Agentic RAG は、ドキュメントベースのツールを含む、様々なツールを使うことが出来ます。
Agentic RAG は、質問に答える為にツールを使います。
Agentic RAG には、様々なツールを使って質問に答えられる柔軟さがあります。
Agentic RAG は Function Calling Agents に限定されません。

分かりましたか？ それでは、このユニットを簡単に振り返りましょう。
