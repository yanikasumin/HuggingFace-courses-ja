# モデルカードを作る[[building-a-model-card]]

<CourseFloatingBanner
    chapter={4}
    classNames="absolute z-10 right-0 top-0"
/>

モデルカードは、モデルリポジトリの中で、モデルファイルやトークナイザファイルと同じくらい重要なファイルと言えます。モデルの中心的な定義であり、コミュニティの仲間が再利用でき、結果を再現でき、ほかのメンバーが自分の成果物の土台にできる場を提供します。

学習と評価の過程を文書化すれば、モデルに何を期待できるかをほかの人が理解しやすくなります。また、使用したデータや行った前処理・後処理について十分な情報を提供することで、モデルが役立つ場面とそうでない場面、その制限やバイアス、背景を特定し、理解できるようになります。

そのため、モデルを明確に定義するモデルカードを作ることはとても重要なステップです。ここでは、その助けになるヒントを紹介します。モデルカードは、先ほど見た *README.md* ファイル（Markdown ファイル）を通じて作成します。

「モデルカード」という概念は、Google の研究の方向性から生まれたもので、Margaret Mitchell らによる論文 ["Model Cards for Model Reporting"](https://arxiv.org/abs/1810.03993) で初めて共有されました。ここに含まれる情報の多くはその論文に基づいています。再現性、再利用性、公平性を重んじる世界でモデルカードがなぜこれほど重要なのかを理解するためにも、ぜひ目を通してみてください。

モデルカードは通常、モデルの用途についてのごく簡単な概要から始まり、その後のセクションで詳細を述べます。

- モデルの説明
- 想定される用途と制限
- 使い方
- 制限とバイアス
- 学習データ
- 学習手順
- 評価結果

各セクションに何を書くべきかを見ていきましょう。

### モデルの説明[[model-description]]

モデルの説明では、モデルについての基本的な詳細を書きます。アーキテクチャ、バージョン、論文で紹介されたものかどうか、元の実装があるかどうか、著者、モデルについての一般的な情報などが含まれます。著作権の帰属はここに記載します。学習手順やパラメータについての一般的な情報、重要な免責事項もこのセクションで触れられます。

### 想定される用途と制限[[intended-uses-limitations]]

ここでは、モデルが想定しているユースケースを説明します。適用できる言語、分野、ドメインなどです。このセクションでは、モデルの適用範囲外であることが知られている領域や、性能が最適でない可能性が高い領域も文書化できます。

### 使い方[[how-to-use]]

このセクションには、モデルの使い方の例を含めます。`pipeline()` 関数の使い方、モデルとトークナイザのクラスの使い方、その他役立つと思われるコードを紹介できます。

### 学習データ[[training-data]]

このパートでは、モデルの学習に使ったデータセットを示します。データセットについての簡単な説明も歓迎されます。

### 学習手順[[training-procedure]]

このセクションでは、再現性の観点から有用な、学習に関するあらゆる側面を説明します。データに行った前処理や後処理、モデルを学習したエポック数、バッチサイズ、学習率などの詳細が含まれます。

### 変数と指標[[variable-and-metrics]]

ここでは、評価に使う指標と、測定するさまざまな要因を説明します。どの指標を、どのデータセットの、どの分割（split）に対して使ったかを示せば、ほかのモデルと性能を比較しやすくなります。これらは、想定するユーザーやユースケースといった前のセクションの内容を踏まえたものにします。

### 評価結果[[evaluation-results]]

最後に、評価データセットでモデルがどの程度の性能を発揮するかを示します。モデルが決定しきい値を使う場合は、評価で使った決定しきい値を示すか、想定される用途ごとに異なるしきい値での評価の詳細を示してください。

## 例[[example]]

よくできたモデルカードの例をいくつか紹介します。

- [`bert-base-cased`](https://huggingface.co/bert-base-cased)
- [`gpt2`](https://huggingface.co/gpt2)
- [`distilbert`](https://huggingface.co/distilbert-base-uncased)

さまざまな組織や企業の例がさらに [こちら](https://github.com/huggingface/model_card/blob/master/examples.md) にあります。

## 注意[[note]]

モデルカードは、モデルを公開する際の必須要件ではありません。作る場合も、上で説明したセクションをすべて含める必要はありません。ただし、モデルを明示的に文書化することは将来のユーザーにとって有益でしかないため、分かる範囲でできるだけ多くのセクションを埋めることをおすすめします。

## モデルカードのメタデータ[[model-card-metadata]]

Hugging Face Hub を少し探索したことがあれば、モデルが特定のカテゴリに属していることに気づいたはずです。タスク、言語、ライブラリなどで絞り込むことができます。モデルが属するカテゴリは、モデルカードのヘッダーに加えるメタデータに基づいて判定されます。

たとえば、[`camembert-base` のモデルカード](https://huggingface.co/camembert-base/blob/main/README.md) を見ると、モデルカードのヘッダーには次の行があります。

```
---
language: fr
license: mit
datasets:
- oscar
---
```

このメタデータは Hugging Face Hub によって解析され、このモデルはフランス語のモデルで、MIT ライセンスで、Oscar データセットで学習されたものとして識別されます。

[モデルカードの完全な仕様](https://github.com/huggingface/hub-docs/blame/main/modelcard.md) では、言語、ライセンス、タグ、データセット、指標、そしてモデルの学習時に得られた評価結果を指定できます。
