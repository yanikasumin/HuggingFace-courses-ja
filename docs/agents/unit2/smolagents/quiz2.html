Code Agents、Tool Calling Agents、Tools の各セクションの理解度を試す時間です。このクイズは任意で、採点されません。

Q1: smolagents で、@tool デコレータでツールを作成することと、Tool のサブクラスを作成することの主な違いは何ですか？

ツールを定義するこれら2つのアプローチの区別を最もよく表す記述はどれですか？

どちらのアプローチも、検索ベースやテキスト生成など、あらゆる種類のツールに使えます。
正解です。デコレータのアプローチはよりシンプルですが、サブクラス化により振る舞いをよりカスタマイズできます。
すべてのエージェント（シングルでもマルチでも）は、ツールの定義にどちらのアプローチも使えます。そのような制限はありません。
どちらの方法も、明確な docstring の恩恵を受けます。デコレータが docstring を置き換えるわけではなく、サブクラスも docstring を持てます。

Q2: CodeAgent は ReAct（Reason + Act）アプローチを使ってマルチステップのタスクをどう処理しますか？

CodeAgent がタスクを解くために一連のステップをどう実行するかを正しく表す記述はどれですか？

マルチエージェントシステムはタスクを分散できますが、CodeAgent 自体が ReAct を使って複数のステップを自分で処理できます。
この振る舞いは ToolCallingAgent の JSON ベースのアプローチに一致し、CodeAgent のものではありません。
正解です。これは、反復的な推論とコード実行を含む、CodeAgent が使う ReAct パターンを表しています。
ビジョン機能は smolagents でサポートされていますが、CodeAgent や ReAct アプローチのデフォルトの要件ではありません。

Q3: 次のうち、ツールを Hugging Face Hub で共有する主な利点はどれですか？

開発者が自分のカスタムツールをアップロードして共有する理由として最も適切なものを選んでください。

ツールを共有しても、検索やマルチステップのロジックが自動的に設定されるわけではありません。ツールを利用可能にするだけです。
はい。Hub で共有すると、誰もが（自分自身も含めて）ツールをダウンロードして素早く再利用できるようになります。
CodeAgents と ToolCallingAgents の両方が、共有されたツールを呼び出せます。エージェントタイプによる制限はありません。
ツールの共有によって、ツールの機能が変わったり、ビジョン機能が自動的に追加されたりすることはありません。

Q4: ToolCallingAgent は、アクションの実行方法の点で CodeAgent と異なります。正しい記述はどれですか？

ToolCallingAgent の仕組みを正確に表す選択肢を選んでください。

どちらのエージェントも、単独でもマルチエージェントシステムの一部としても使えます。
ToolCallingAgent は推論にメインの LLM を引き続き使います。検索エージェントだけに依存するわけではありません。
正解です。ToolCallingAgent は、ツール呼び出しの定義に JSON のアプローチを使います。
ToolCallingAgent は、CodeAgent と同様に、必要に応じて複数のステップを実行できます。

Q5: smolagents のデフォルトのツールボックスには何が含まれ、なぜ使うのですか？

smolagents のデフォルトのツールボックスの目的と内容を最もよく表す記述はどれですか？

正解です。デフォルトのツールボックスには、エージェントを構築する際に簡単に統合できる、こうした既製のツールが含まれます。
smolagents はビジョンベースの機能を統合できますが、デフォルトのツールボックスはビジョン専用というわけではありません。
デフォルトのツールボックスは、シングルでもマルチでも、あらゆるエージェントタイプで使えます。
検索ツールを構築することはできますが、デフォルトのツールボックスが高度な RAG 機能を自動的に提供するわけではありません。
