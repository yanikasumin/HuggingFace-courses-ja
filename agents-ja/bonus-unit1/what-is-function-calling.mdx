# Function-calling とは？

Function-calling は、**LLM が環境に対して操作を行うための仕組み**です。[GPT-4 で初めて導入され](https://openai.com/index/function-calling-and-other-api-updates/)、その後、他のモデルにも同様の仕組みが実装されました。

エージェントが使うツールと同じように、Function-calling もモデルに**外部の環境へ働きかける**能力を与えます。ただし、Function-calling の能力は**モデルが学習によって身につける**もので、他のエージェント手法よりも**プロンプトへの依存が小さい**のが特徴です。

ユニット 1 では、**エージェントにツールの使い方を学習させたわけではありません**。私たちはツールの一覧を渡しただけで、**モデルが学習済みの能力を応用して、それらのツールを使う計画を立てられる**ことに頼っていました。

**一方、ここではエージェントがツールを使えるよう、Function-calling のためのファインチューニング（訓練）を行います**。

## モデルはどうやって行動を起こすことを「学ぶ」のか？

ユニット 1 では、エージェントの一般的な処理の流れを学びました。ユーザーがエージェントにいくつかのツールを与えて質問や指示を入力すると、モデルは次の3つのステップを繰り返します。

1. *Think（考える）*：目的を達成するために、どんなアクションを取る必要があるか。
2. *Act（行動する）*：適切なパラメータを指定してツール呼び出しを組み立て、生成を止める。
3. *Observe（観察する）*：実行結果を受け取る。

API 経由でモデルと会話する場合、通常は次のようにユーザーとアシスタントのメッセージが交互に並びます。

```python
conversation = [
    {"role": "user", "content": "I need help with my order"},
    {"role": "assistant", "content": "I'd be happy to help. Could you provide your order number?"},
    {"role": "user", "content": "It's ORDER-123"},
]
```

Function-calling では、**会話に新しいロールが加わります**！

1. **Action** 用の新しいロール
2. **Observation** 用の新しいロール

[Mistral API](https://docs.mistral.ai/capabilities/function_calling/) を例に取ると、次のようになります。

```python
conversation = [
    {
        "role": "user",
        "content": "What's the status of my transaction T1001?"
    },
    {
        "role": "assistant",
        "content": "",
        "function_call": {
            "name": "retrieve_payment_status",
            "arguments": "{\"transaction_id\": \"T1001\"}"
        }
    },
    {
        "role": "tool",
        "name": "retrieve_payment_status",
        "content": "{\"status\": \"Paid\"}"
    },
    {
        "role": "assistant",
        "content": "Your transaction T1001 has been successfully paid."
    }
]
```

> …でも、関数呼び出し用の新しいロールがあると言いましたよね？

**そうとも言えますが、少し違います**。この例を含む多くの API では、モデルは実行したいアクションを `assistant` ロールのメッセージとして出力します。その後、チャットテンプレートによって、その内容が Function-calling 用の**特殊トークン**で表現されます。

- `[AVAILABLE_TOOLS]`：利用可能なツールの一覧の開始
- `[/AVAILABLE_TOOLS]`：利用可能なツールの一覧の終了
- `[TOOL_CALLS]`：ツールへの呼び出しを行う（つまり「Action」を取る）
- `[TOOL_RESULTS]`：アクションの結果を「Observe」する
- `[/TOOL_RESULTS]`：観測の終了（モデルがトークンの生成を再開できる）

Function-calling については、このコースでも後ほど取り上げます。先に詳しく学びたい場合は、[こちらの詳しいドキュメント](https://docs.mistral.ai/capabilities/function_calling/)をご覧ください。

Function-calling の仕組みが分かったところで、今度は**まだその機能を持たないモデルに Function-calling の機能を追加**してみましょう。対象は [google/gemma-2-2b-it](https://huggingface.co/google/gemma-2-2b-it) です。このモデルに新しい特殊トークンを追加します。

それを行うには、**まずファインチューニングと LoRA を理解する**必要があります。
