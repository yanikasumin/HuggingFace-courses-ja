## よいフォーラム投稿の書き方[[writing-a-good-forum-post]]

例として、独自の検索エンジンを作る為に、Wikipedia の記事から埋め込みを生成する場面を扱います。トークナイザとモデルは次のように読み込みます。

```python
from transformers import AutoTokenizer, AutoModel

model_checkpoint = "distilbert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint)
model = AutoModel.from_pretrained(model_checkpoint)
```

このトピックには、助けが必要なエラーメッセージが含まれています。一方で、書き方には次の問題があります。

1. タイトルから内容が分かりません。フォーラムを眺めている人は、本文まで読まなければトピックの内容を判断出来ません。
2. 本文には、エラーが_どこから_来ているのか、_どうすれば_再現出来るのかの情報が不足しています。
3. 何人かを直接タグ付けしており、口調もやや要求が強くなっています。

この書き方では、早い回答は期待出来ません。回答自体が得られない可能性もあります。改善方法を、タイトルの付け方から順に説明します。

### 内容の分かるタイトルを付ける[[choosing-a-descriptive-title]]

コードのバグについて助けを求める場合は、タイトルに十分な情報を含める必要があります。読み手が「自分に答えられる質問かどうか」をすばやく判断出来る為です。今回の例では、発生している例外の名前が分かっています。エラーがモデルのフォワードパス、つまり `model(**inputs)` の呼び出しで発生しているらしいという手がかりもあります。これらを伝えるタイトルとしては、例えば次のものが考えられます。

> AutoModel のフォワードパスで発生する IndexError の原因は？

このタイトルは、バグの発生箇所についての見当を読み手に伝えます。`IndexError` に遭遇したことがある人であれば、デバッグ方法を知っている可能性があります。タイトルは自由に付けられます。次のような書き方でも問題ありません。

> 何故モデルの実行時に IndexError が発生するのか？

次に、本文の改善方法を説明します。

### コードスニペットを整形する[[formatting-your-code-snippets]]

ソースコードを読む作業は、IDE の中でも手間がかかります。プレーンテキストとして貼り付けられたコードは、更に読みにくくなります。Hugging Face フォーラムは Markdown に対応しています。コードを掲載するときは、3つのバッククォートで囲み、コードブロックとして整形してください。ここでは、エラーメッセージをこの方法で整形します。本文も、最初の下書きより丁寧な文面に直します。

<div class="flex justify-center">
<img src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter8/forum-topic03.png" alt="コードが適切に整形された、改訂版のフォーラムトピック。" width="100%"/>
</div>

スクリーンショットのように、コードをバッククォートで囲むと、色付けされた整形済みのコードとして表示されます。単一のバッククォートを使えば、`distilbert-base-uncased` のようなインラインの変数も整形出来ます。トピックはこれで改善しましたが、エラーの内容を推測出来る人に頼るだけでは不十分です。トレースバックを省略せずに全て掲載し、読み手の作業を楽にします。

### トレースバックを全部載せる[[including-the-full-traceback]]

トレースバックの最後の行だけでデバッグ出来ることは多くあります。その為、スペースを「節約」しようとして、トピックに最後の行だけを載せたくなる場合があります。しかし、トレースバックの上部にある情報もデバッグには役立ちます。最後の行だけでは、他の人が問題を調べる作業はかえって_難しく_なります。

よい方法は、トレースバックの_全文_をコピーして貼り付け、読みやすく整形して掲載することです。トレースバックが長くなる場合は、ソースコードの説明の後に載せる方法もあります。ここではその方法を使います。フォーラムトピックは次のようになります。

</div>

情報量は大きく増えました。注意深い読み手であれば、トレースバックの次の行から、問題の原因が長い入力を渡したことにあると指摘出来るかもしれません。

> Token indices sequence length is longer than the specified maximum sequence length for this model (583 > 512).

エラーを引き起こした実際のコードを示せば、読み手は更に調べやすくなります。次に、そのコードを追加します。

### 再現可能な例を用意する[[providing-a-reproducible-example]]

他人のコードをデバッグするときは、まず報告された問題を再現し、トレースバックをたどってエラーの箇所を特定するのが通常の手順です。フォーラムで支援を受ける場合も、支援を提供する場合も同じです。エラーを再現する小さな例を用意出来ると、読み手の作業は大きく進みます。

再現例を作る過程で、問題の原因を自分で発見出来る場合も少なくありません。この例で欠けているのは、モデルに渡した_入力_です。入力を追加すると、次のような完成した例になります。
