これまでのセクションでは、`Interface` クラスを使ってデモを作成してきました。このセクションでは、**新しく開発された**低レベル API である `gradio.Blocks` を紹介します。

`Interface` と `Blocks` の違いは、次の通りです。

- ⚡ `Interface`：高レベル API です。入力と出力のリストを与えるだけで、機械学習のデモを作成出来ます。

- 🧱 `Blocks`：低レベル API です。アプリケーションのデータフローとレイアウトを完全に制御出来ます。`Blocks` は「積み木」を意味し、組み合わせることで非常に複雑な複数ステップのアプリケーションも構築出来ます。


### 何故 Blocks なのか？[[why-blocks-]]

`Interface` クラスを使うと、数行のコードで本格的な機械学習デモを作成出来ます。`Interface` API は非常に使いやすい一方で、柔軟性では `Blocks` API に劣ります。例えば、次のようなカスタマイズが必要になる場合があります：

- 関連するデモを、1つの Web アプリケーションの中で複数のタブにまとめる
- デモのレイアウトを変更する。例えば、入力と出力の配置場所を指定する
- 複数ステップのインターフェースを作る。或るモデルの出力を次のモデルの入力にしたり、データフローを柔軟に設計したりする
- ユーザーの入力に応じてコンポーネントのプロパティを変更する。例えば、ドロップダウンの選択肢や、コンポーネントの表示と非表示を切り替える

以下では、これらの概念を順に説明します。

### Blocks を使ってシンプルなデモを作る[[creating-a-simple-demo-using-blocks]]

Gradio をインストールした後、下記のコードを Python スクリプト、Jupyter ノートブック、又は Colab ノートブックで実行してください。

```py
import gradio as gr


def flip_text(x):
    return x[::-1]


demo = gr.Blocks()

with demo:
    gr.Markdown(
        """
    # Flip Text!
    Start typing below to see the output.
    """
    )
    input = gr.Textbox(placeholder="Flip this text")
    output = gr.Textbox()

    input.change(fn=flip_text, inputs=input, outputs=output)

demo.launch()
```

（コード内の見出しと案内文の訳：「テキストを反転！」／下に入力を始めると、出力が表示されます。プレースホルダの訳：このテキストを反転）

上記の単純な例には、Blocks の基礎となる概念が4つ含まれています：

1. Blocks では、`gr.Blocks()` の with ブロックの中で Python のオブジェクトを作成するだけで、Markdown、HTML、ボタン、操作可能なコンポーネントを組み合わせた Web アプリケーションを構築出来ます。
> [!TIP]
> Python の `with` 文に慣れていない場合は、Real Python の[チュートリアル](https://realpython.com/python-with-statement/)を参照してください。

コンポーネントを作成する順序は、そのまま Web アプリへの表示順になります。より複雑なレイアウトは後で説明します。

2. 通常の Python 関数は、コードのどこに定義しても構いません。`Blocks` を使うと、その関数をユーザーの入力で実行出来ます。例の関数は入力テキストを反転する単純なものですが、単純な計算から機械学習モデルの予測処理まで、任意の Python 関数を使えます。

3. `Blocks` コンポーネントには、イベントを割り当てられます。イベントを割り当てると、コンポーネントがクリックされたり値が変更されたりした時に、関数が実行されます。割り当てでは、3つのパラメータを渡します。`fn` は呼び出す関数、`inputs` は入力コンポーネント、`outputs` は出力コンポーネントです。入力や出力が複数の場合は、リストで指定します。

   上の例では、`input` という名前の `Textbox` の値が変わると、`flip_text()` 関数が実行されます。`input` の値は `flip_text()` の引数 `x` として渡され、関数の戻り値が2つ目の `Textbox` である `output` に反映されます。

   各コンポーネントがサポートするイベントの一覧は、Gradio の[ドキュメント](https://www.gradio.app/docs/)を参照してください。

4. Blocks は、定義したイベントトリガーに基づいて、コンポーネントがインタラクティブかどうかを自動で判断します。インタラクティブとは、ユーザーの入力を受け付ける状態を指します。上の例では、1つ目のテキストボックスの値は `flip_text()` 関数で使われる為、インタラクティブになります。2つ目のテキストボックスの値は入力として使われない為、インタラクティブにはなりません。この判断を上書きする場合は、コンポーネントの `interactive` パラメータに真偽値を渡します。例えば `gr.Textbox(placeholder="Flip this text", interactive=True)` のように指定します。

### デモのレイアウトをカスタマイズする[[customizing-the-layout-of-your-demo]]

`Blocks` でデモのレイアウトをカスタマイズする方法を説明します。デフォルトでは、`Blocks` は作成したコンポーネントを1列に縦に並べます。並べ方を変える場合は、`with gradio.Column():` で列を、`with gradio.Row():` で行を作成し、その中でコンポーネントを作成します。

`Column` の中で作成したコンポーネントは縦に並びます。これがデフォルトの配置でもあります。`Row` の中で作成したコンポーネントは、[Web 開発の flexbox モデル](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_Flexible_Box_Layout/Basic_Concepts_of_Flexbox)と同様に横に並びます。

タブは、`with gradio.Tabs()` コンテキストマネージャで作成出来ます。このコンテキストの中で `with gradio.TabItem(name_of_tab):` を使うと、タブを複数作成出来ます。`with gradio.TabItem(name_of_tab):` の中で作成したコンポーネントは、そのタブの中に表示されます。

次に、デモへ `flip_image()` 関数と、画像を反転するタブを追加します。下記は、2つのタブを持ち、Row も使った例です：

```py
import numpy as np
import gradio as gr

demo = gr.Blocks()


def flip_text(x):
    return x[::-1]


def flip_image(x):
    return np.fliplr(x)


with demo:
    gr.Markdown("Flip text or image files using this demo.")
    with gr.Tabs():
        with gr.TabItem("Flip Text"):
            with gr.Row():
                text_input = gr.Textbox()
                text_output = gr.Textbox()
            text_button = gr.Button("Flip")
        with gr.TabItem("Flip Image"):
            with gr.Row():
                image_input = gr.Image()
                image_output = gr.Image()
            image_button = gr.Button("Flip")

    text_button.click(flip_text, inputs=text_input, outputs=text_output)
    image_button.click(flip_image, inputs=image_input, outputs=image_output)

demo.launch()
```

（案内文の訳：このデモを使って、テキストや画像ファイルを反転します。タブ名の訳：「テキストを反転」「画像を反転」。ボタンの訳：反転）

### イベントと状態を探る[[exploring-events-and-state]]

`Blocks` では、レイアウトだけでなく、どのイベントで関数を呼び出すかも細かく制御出来ます。各コンポーネントと多くのレイアウトには、それぞれ対応するイベントが用意されています。

例えば、`Textbox` コンポーネントには2つのイベントがあります。`change()` はテキストボックス内の値が変わった時、`submit()` はテキストボックスにフォーカスした状態でユーザーが Enter キーを押した時に発生します。より複雑なコンポーネントには、更に多くのイベントがあります。例えば `Audio` コンポーネントには、音声ファイルの再生、クリア、一時停止など、操作ごとに別のイベントがあります。各コンポーネントが対応するイベントは、ドキュメントを参照してください。

イベントトリガーは、イベントのうち1つに設定しても、複数に設定しても、設定しなくても構いません。イベントトリガーを作成するには、コンポーネントのインスタンスに対して、イベント名を関数のように呼び出します。例えば `textbox.change(...)` や `btn.click(...)` です。

この関数は、前述の通り3つのパラメータを取ります：

- `fn`：実行する関数です。
- `inputs`：関数の入力パラメータとして値を渡すコンポーネントです。複数の場合はリストで指定します。各コンポーネントの値は、順番に対応する関数のパラメータへ割り当てられます。関数がパラメータを取らない場合は、None を指定出来ます。
- `outputs`：関数の戻り値で値を更新するコンポーネントです。複数の場合はリストで指定します。各戻り値は、順番に対応するコンポーネントの値になります。関数が何も返さない場合は、None を指定出来ます。

入力と出力に同じコンポーネントを使うことも出来ます。下記は、GPT モデルでテキスト補完を行う例です：

```py
import gradio as gr

api = gr.Interface.load("huggingface/EleutherAI/gpt-j-6B")


def complete_with_gpt(text):
    # テキストの最後の50文字をコンテキストとして使う
    return text[:-50] + api(text[-50:])


with gr.Blocks() as demo:
    textbox = gr.Textbox(placeholder="Type here and press enter...", lines=4)
    btn = gr.Button("Generate")

    btn.click(complete_with_gpt, textbox, textbox)

demo.launch()
```

（プレースホルダの訳：ここに入力して Enter を押してください…）

### 複数ステップのデモを作る[[creating-multi-step-demos]]

或る関数の出力を次の関数の入力として再利用する、_複数ステップのデモ_ が必要になる場合があります。`Blocks` では、この構成を簡単に作れます。1つのコンポーネントを、或るイベントトリガーの出力でありながら、別のイベントトリガーの入力に出来る為です。下記の例では、テキストコンポーネントがその役割を持ちます。このコンポーネントの値は音声認識モデルの結果であり、同時に感情分析モデルへも渡されます：

```py
from transformers import pipeline

import gradio as gr

asr = pipeline("automatic-speech-recognition", "facebook/wav2vec2-base-960h")
classifier = pipeline("text-classification")


def speech_to_text(speech):
    text = asr(speech)["text"]
    return text


def text_to_sentiment(text):
    return classifier(text)[0]["label"]


demo = gr.Blocks()

with demo:
    audio_file = gr.Audio(type="filepath")
    text = gr.Textbox()
    label = gr.Label()

    b1 = gr.Button("Recognize Speech")
    b2 = gr.Button("Classify Sentiment")

    b1.click(speech_to_text, inputs=audio_file, outputs=text)
    b2.click(text_to_sentiment, inputs=text, outputs=label)

demo.launch()
```

### コンポーネントのプロパティを更新する[[updating-component-properties]]

ここまでは、イベントで別のコンポーネントの値を更新する方法を説明しました。値以外のプロパティ、例えばテキストボックスの表示と非表示や、ラジオボタングループの選択肢を変更する場合は、関数から通常の値を返す代わりに、コンポーネントクラスの `update()` メソッドの戻り値を返します。

例で示すのが最も分かり易い方法です：

```py
import gradio as gr


def change_textbox(choice):
    if choice == "short":
        return gr.Textbox.update(lines=2, visible=True)
    elif choice == "long":
        return gr.Textbox.update(lines=8, visible=True)
    else:
        return gr.Textbox.update(visible=False)


with gr.Blocks() as block:
    radio = gr.Radio(
        ["short", "long", "none"], label="What kind of essay would you like to write?"
    )
    text = gr.Textbox(lines=2, interactive=True)

    radio.change(fn=change_textbox, inputs=radio, outputs=text)
    block.launch()
```

（ラベルの訳：どのようなエッセイを書きたいですか？選択肢の訳：「短い」「長い」「なし」）
