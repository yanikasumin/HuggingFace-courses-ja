主要な概念と用語

Model Context Protocol をより深く学ぶ前に、MCP の基盤をなす主要な概念と用語を理解しておくことが重要です。この節では、プロトコルを支える基本的な考え方を紹介し、コース全体を通じて MCP の実装を議論するための共通の語彙を提供します。

MCP は「AI アプリケーションのための USB-C」とよく説明されます。USB-C がさまざまな周辺機器をコンピューターに接続するための標準化された物理的・論理的インターフェースを提供するように、MCP は AI モデルを外部の機能に接続するための一貫したプロトコルを提供します。この標準化はエコシステム全体に利益をもたらします。

  • ユーザーは、AI アプリケーション間でよりシンプルで一貫した体験を享受できます
  • AI アプリケーション開発者は、成長し続けるツールやデータソースのエコシステムと簡単に統合できます
  • ツールやデータの提供者は、複数の AI アプリケーションで動作する実装を1つ作るだけで済みます
  • エコシステム全体として、相互運用性が高まり、イノベーションが促進され、断片化が減ります

統合問題

M×N 統合問題とは、標準化されたアプローチなしに、M 種類の AI アプリケーションを N 種類の外部ツールやデータソースに接続する際の課題を指します。

MCP がない場合（M×N 問題）

MCP のようなプロトコルがなければ、開発者は M×N 通りのカスタム統合、つまり AI アプリケーションと外部機能のありうる組み合わせごとに1つずつ統合を作らなければなりません。

各 AI アプリケーションは、各ツールやデータソースと個別に統合する必要があります。これは非常に複雑でコストのかかるプロセスであり、開発者にとって大きな摩擦となり、メンテナンスコストも高くなります。

モデルが複数、ツールも複数になると、統合の数は管理しきれないほど膨れ上がり、それぞれが独自のインターフェースを持つことになります。

MCP がある場合（M+N の解決策）

MCP は標準インターフェースを提供することで、これを M+N 問題に変えます。各 AI アプリケーションは MCP のクライアント側を一度だけ実装し、各ツールやデータソースはサーバー側を一度だけ実装します。これにより、統合の複雑さとメンテナンスの負担が劇的に減ります。

MCP のコア用語

MCP が解決する問題を理解したところで、MCP プロトコルを構成するコアな用語と概念を詳しく見ていきましょう。

💡 ヒント

MCP は HTTP や USB-C のような標準であり、AI アプリケーションを外部のツールやデータソースに接続するためのプロトコルです。そのため、MCP を効果的に機能させるには、標準的な用語を使うことが不可欠です。

アプリケーションを文書化したりコミュニティとやり取りしたりする際には、次の用語を使いましょう。

コンポーネント

HTTP におけるクライアントとサーバーの関係と同様に、MCP にもクライアントとサーバーがあります。

  • ホスト（Host）: エンドユーザーが直接操作するユーザー向けの AI アプリケーションです。例として、Anthropic の Claude Desktop、Cursor のような AI 強化 IDE、Hugging Face Python SDK のような推論ライブラリ、LangChain や smolagents のようなライブラリで構築されたカスタムアプリケーションがあります。ホストは MCP サーバーへの接続を開始し、ユーザーのリクエスト、LLM の処理、外部ツールの間の全体的なフローを統括します。

  • クライアント（Client）: ホストアプリケーション内のコンポーネントで、特定の MCP サーバーとの通信を管理します。各クライアントは単一のサーバーと 1:1 の接続を維持し、MCP 通信のプロトコルレベルの詳細を処理しながら、ホストのロジックと外部サーバーの間の仲介役として動作します。

  • サーバー（Server）: MCP プロトコルを通じて機能（ツール、リソース、プロンプト）を公開する外部のプログラムまたはサービスです。

⚠️ 注意

多くのコンテンツでは「クライアント」と「ホスト」が同じ意味で使われています。厳密には、ホストはユーザー向けのアプリケーションであり、クライアントはホストアプリケーション内のコンポーネントで、特定の MCP サーバーとの通信を管理します。

機能（Capabilities）

もちろん、アプリケーションの価値は、提供する機能の総和です。そのため、機能はアプリケーションの最も重要な部分です。MCP はあらゆるソフトウェアサービスと接続できますが、多くの AI アプリケーションで使われる一般的な機能がいくつかあります。

Capability Description Example
ツール（Tools） AI モデルが呼び出してアクションを実行したり、計算されたデータを取得したりできる実行可能な関数です。通常、アプリケーションのユースケースに関連します。 天気アプリケーションのツールは、特定の場所の天気を返す関数かもしれません。
リソース（Resources） 大きな計算を伴わずにコンテキストを提供する読み取り専用データソースです。 研究者アシスタントには、科学論文のリソースがあるかもしれません。
プロンプト（Prompts） ユーザー、AI モデル、利用可能な機能の間のやり取りをガイドする、事前に定義されたテンプレートやワークフローです。 要約プロンプトなどです。
サンプリング（Sampling） サーバーから開始される、クライアント/ホストへの LLM インタラクションのリクエストです。LLM が生成したコンテンツを確認し、さらなる判断を行う再帰的なアクションを可能にします。 ライティングアプリケーションが自分の出力を見直し、さらに洗練させようと判断することなどです。

まとめ

これらの主要な概念と用語を理解することが、MCP を効果的に扱うための基盤となります。次節以降では、この基盤の上に、Model Context Protocol を構成するアーキテクチャコンポーネント、通信プロトコル、機能を探っていきます。
