複数のシーケンスを扱う

前のセクションでは、短いシーケンスを1つだけ入力して推論する、最も単純な例を見てきました。しかし、既にいくつか疑問が浮かびます。

  • 複数のシーケンスをどう扱えばよいのでしょうか？
  • 長さの 異なる 複数のシーケンスをどう扱えばよいのでしょうか？
  • モデルを正しく動作させるには、語彙のインデックス以外にも入力が必要なのでしょうか？
  • 長過ぎるシーケンスというものは有るのでしょうか？

これらの疑問の背景にはどのような問題があり、🤗 Transformers API を使ってどう解決出来るのかを見ていきましょう。

モデルはバッチ入力を想定している

前の演習では、シーケンスが数値のリストに変換される様子を見ました。この数値のリストをテンソルに変換して、モデルに送ってみましょう。

import torch
from transformers import AutoTokenizer, AutoModelForSequenceClassification

checkpoint = "distilbert-base-uncased-finetuned-sst-2-english"
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
model = AutoModelForSequenceClassification.from_pretrained(checkpoint)

sequence = "I've been waiting for a HuggingFace course my whole life."

tokens = tokenizer.tokenize(sequence)
ids = tokenizer.convert_tokens_to_ids(tokens)
input_ids = torch.tensor(ids)
# この行は失敗します。
model(input_ids)

（入力文の訳：ずっと Hugging Face のコースを待ち望んでいました）

```python out IndexError: Dimension out of range (expected to be in range of [-1, 0], but got 1)

失敗してしまいました。何故でしょうか？セクション2のパイプラインの手順に従ったはずなのに。

問題は、単一のシーケンスをモデルに送ったことです。Transformers のモデルは、デフォルトで複数の文を想定しています。

ここでは、トークナイザを `sequence` に適用した時、裏側で行われていたことを全て再現しようとしました。しかしよく見ると、トークナイザは入力 ID のリストをテンソルに変換しただけでなく、その上に次元を1つ追加していたことが分かります。

```py
tokenized_inputs = tokenizer(sequence, return_tensors="pt")
print(tokenized_inputs["input_ids"])

```python out tensor([[ 101, 1045, 1005, 2310, 2042, 3403, 2005, 1037, 17662, 12172, 2607, 2026, 2878, 2166, 1012, 102]])

新しい次元を追加して、もう一度試してみましょう。

```py
import torch
from transformers import AutoTokenizer, AutoModelForSequenceClassification

checkpoint = "distilbert-base-uncased-finetuned-sst-2-english"
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
model = AutoModelForSequenceClassification.from_pretrained(checkpoint)

sequence = "I've been waiting for a HuggingFace course my whole life."

tokens = tokenizer.tokenize(sequence)
ids = tokenizer.convert_tokens_to_ids(tokens)

input_ids = torch.tensor([ids])
print("入力 ID:", input_ids)

output = model(input_ids)
print("ロジット:", output.logits)

入力 ID と、結果のロジットを表示します。出力は次の通りです。

```python out 入力 ID: [[ 1045, 1005, 2310, 2042, 3403, 2005, 1037, 17662, 12172, 2607, 2026, 2878, 2166, 1012]] ロジット: [[-2.7276, 2.8789]]

*バッチ処理* とは、複数の文を一度にモデルに通すことです。文が1つしかない場合は、単一のシーケンスでバッチを構築出来ます。

batched_ids = [ids, ids]

これは、同一のシーケンス2つからなるバッチです。

<p class="callout-title">💡 ヒント</p>

バッチ処理を使えば、複数の文をまとめてモデルに入力出来ます。複数のシーケンスからバッチを作ること自体は、1つのシーケンスから作る場合と同じくらい簡単です。但し、ここで2つ目の問題があります。複数の文は、長さが同じとは限りません。テンソルは矩形の形状でなければならない為、長さの異なる入力 ID のリストをそのままテンソルに変換することは出来ません。そこで、通常は *パディング* を使って長さを揃えます。

## 入力をパディングする

次のリストのリストは、テンソルに変換出来ません。

```py no-format
batched_ids = [
    [200, 200, 200],
    [200, 200]
]

これを回避する為に、パディング を使ってテンソルを長方形の形状にします。パディングとは、短いシーケンスに特殊な パディングトークン を追加し、バッチ内の全てのシーケンスの長さを揃える処理です。例えば、10単語の文が10個と20単語の文が1個有る場合、パディングによって全ての文の長さが20単語に揃います。この例では、結果のテンソルは次のようになります。

```py no-format padding_id = 100

batched_ids = [ [200, 200, 200], [200, 200, padding_id], ]

パディングトークンの ID は `tokenizer.pad_token_id` で取得出来ます。これを使って、2つの文を個別にモデルに通し、更にバッチにまとめて通してみましょう。

```py no-format
model = AutoModelForSequenceClassification.from_pretrained(checkpoint)

sequence1_ids = [[200, 200, 200]]
sequence2_ids = [[200, 200]]
batched_ids = [
    [200, 200, 200],
    [200, 200, tokenizer.pad_token_id],
]

print(model(torch.tensor(sequence1_ids)).logits)
print(model(torch.tensor(sequence2_ids)).logits)
print(model(torch.tensor(batched_ids)).logits)

```python out tensor([[ 1.5694, -1.3895]], grad_fn=) tensor([[ 0.5803, -0.4125]], grad_fn=) tensor([[ 1.5694, -1.3895], [ 1.3373, -1.2163]], grad_fn=)

バッチ処理で得られたロジットには問題があります。2行目は2番目の文のロジットと同じになるはずなのに、まったく異なる値になってしまいました！

これは、Transformer モデルの重要な構成要素であるアテンション層が、周囲のトークンの情報を使って各トークンを *文脈化* する為です。アテンション層はシーケンス内の全てのトークンに注意を向けるので、パディングトークンも計算に含めてしまいます。文を個別に処理した場合と、パディングしてバッチ処理した場合とで同じ結果を得るには、パディングトークンを無視させる必要があります。その為に使うのがアテンションマスクです。

## アテンションマスク

*アテンションマスク* は、入力 ID テンソルとまったく同じ形状で、0 と 1 で埋められたテンソルです。1 は対応するトークンに注意を向けるべきことを示し、0 は対応するトークンに注意を向けるべきでないこと（つまり、モデルのアテンション層に無視されるべきこと）を示します。

アテンションマスクを使って、前の例を完成させましょう。

```py no-format
batched_ids = [
    [200, 200, 200],
    [200, 200, tokenizer.pad_token_id],
]

attention_mask = [
    [1, 1, 1],
    [1, 1, 0],
]

outputs = model(torch.tensor(batched_ids), attention_mask=torch.tensor(attention_mask))
print(outputs.logits)

```python out tensor([[ 1.5694, -1.3895], [ 0.5803, -0.4125]], grad_fn=)

今度は、バッチ内の2番目の文についても同じロジットが得られました。

2番目のシーケンスでは、最後の位置にパディング ID が入っています。この位置に対応するアテンションマスクの値は 0 になっています。

<p class="callout-title">💡 ヒント</p>
**試してみましょう！** セクション2で使った2つの文（"I've been waiting for a HuggingFace course my whole life." と "I hate this so much!"）に対して、手動でトークン化を適用してみてください。モデルに通して、セクション2と同じロジットが得られることを確認しましょう。次に、パディングトークンを使って2つをバッチにまとめ、適切なアテンションマスクを作成してください。モデルに通した時に同じ結果が得られることを確認しましょう！

## より長いシーケンス

Transformer モデルでは、モデルに渡せるシーケンスの長さに制限があります。殆どのモデルは 512 又は 1024 トークンまでのシーケンスを処理出来、それより長いシーケンスを処理しようとするとクラッシュします。この問題への解決策は2つあります。

- サポートされるシーケンス長がより長いモデルを使う。
- シーケンスを切り捨てる。

モデルによって処理出来るシーケンスの長さは異なります。特に長い入力を扱う為に設計されたモデルとして、[Longformer](https://huggingface.co/docs/transformers/model_doc/longformer) や [LED](https://huggingface.co/docs/transformers/model_doc/led) があります。長い入力を扱うタスクでは、これらのモデルを検討してください。

それ以外の場合は、`max_sequence_length` パラメータを指定してシーケンスを切り捨てることをお勧めします。

```py
sequence = sequence[:max_sequence_length]
