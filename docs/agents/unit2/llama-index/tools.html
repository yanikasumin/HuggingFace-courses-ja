LlamaIndex でツールを使う

明確なツールのセットを定義することは、性能を左右する重要な要素です。 ユニット 1 で述べたように、ツールのインターフェースが分かりやすければ、LLM にとっても使いやすくなります。 人間のエンジニア向けのソフトウェア API と同じで、仕組みが理解しやすいツールほど、その力を引き出せるのです。

LlamaIndex のツールには、主に次の 4 種類があります。

  1. FunctionTool: 任意の Python 関数を、エージェントが使えるツールに変換します。関数の仕組みは自動で把握されます。
  2. QueryEngineTool: エージェントがクエリエンジンを使えるようにするツールです。エージェントはクエリエンジンを土台に構築されるため、ほかのエージェントをツールとして使うこともできます。
  3. Toolspecs: コミュニティが作成したツールのセットで、Gmail のような特定のサービス向けのツールを含むことがよくあります。
  4. Utility Tools: ほかのツールから得られる大量のデータを扱うのに役立つ、特殊なツールです。

以下では、それぞれを詳しく見ていきます。

FunctionTool を作成する

💡 ヒント

コードは、Google Colab で実行できる このノートブック で確認できます。

FunctionTool を使えば、任意の Python 関数を簡単にラップして、エージェントから利用できるようにできます。 ツールには同期関数・非同期関数のどちらでも渡せます。任意で name パラメータと description パラメータも指定できます。 名前と説明は特に重要です。エージェントが、ツールをいつ、どのように使えばよいかを理解する手がかりになるからです。 以下で FunctionTool の作成方法を見てから、実際に呼び出してみましょう。

from llama_index.core.tools import FunctionTool

def get_weather(location: str) -> str:
    """Useful for getting the weather for a given location."""
    print(f"Getting weather for {location}")
    return f"The weather in {location} is sunny"

tool = FunctionTool.from_defaults(
    get_weather,
    name="my_weather_tool",
    description="Useful for getting the weather for a given location.",
)
tool.call("New York")

💡 ヒント

関数呼び出しに対応したエージェントや LLM を使う場合、どのツールが選ばれるか（そして、そのツールへの引数がどう書かれるか）は、ツールの名前と、ツールの目的や引数についての説明に大きく左右されます。関数呼び出しの詳細は Function Calling Guide を参照してください。

QueryEngineTool を作成する

前のユニットで定義した QueryEngine は、QueryEngineTool クラスを使えば簡単にツールへ変換できます。 以下の例で、QueryEngine から QueryEngineTool を作成する方法を見てみましょう。

from llama_index.core import VectorStoreIndex
from llama_index.core.tools import QueryEngineTool
from llama_index.llms.huggingface_api import HuggingFaceInferenceAPI
from llama_index.embeddings.huggingface import HuggingFaceEmbedding
from llama_index.vector_stores.chroma import ChromaVectorStore

embed_model = HuggingFaceEmbedding("BAAI/bge-small-en-v1.5")

db = chromadb.PersistentClient(path="./alfred_chroma_db")
chroma_collection = db.get_or_create_collection("alfred")
vector_store = ChromaVectorStore(chroma_collection=chroma_collection)

index = VectorStoreIndex.from_vector_store(vector_store, embed_model=embed_model)

llm = HuggingFaceInferenceAPI(model_name="Qwen/Qwen2.5-Coder-32B-Instruct")
query_engine = index.as_query_engine(llm=llm)
tool = QueryEngineTool.from_defaults(query_engine, name="some useful name", description="some useful description")

Toolspecs を作成する

ToolSpecs は、互いに調和して動作するツールの集合だと考えてください。よく整理されたプロの道具箱のようなものです。 整備士の道具箱に、車両の修理で連携する相補的な道具が揃っているように、ToolSpec は特定の目的に向けた関連ツールを組み合わせます。 たとえば、経理エージェントの ToolSpec であれば、表計算の機能、メールの機能、計算ツールをうまく統合し、財務タスクを正確かつ効率的に処理できるでしょう。

Google Toolspec をインストールする LlamaHub に関するセクション で紹介したように、Google の toolspec は次のコマンドでインストールできます。 
pip install llama-index-tools-google

これで toolspec を読み込み、ツールのリストへ変換できます。

from llama_index.tools.google import GmailToolSpec

tool_spec = GmailToolSpec()
tool_spec_list = tool_spec.to_tool_list()

ツールをより詳しく確認するには、各ツールの metadata を見ます。

[(tool.metadata.name, tool.metadata.description) for tool in tool_spec_list]

LlamaIndex における Model Context Protocol（MCP）

LlamaIndex では、LlamaHub 上の ToolSpec を通じて MCP ツールも使えます。 MCP サーバーを起動すれば、次の実装でそのまま利用を開始できます。

MCP についてさらに深く知りたい場合は、無料の MCP コース を確認してください。

MCP Toolspec をインストールする LlamaHub に関するセクション で紹介したように、MCP の toolspec は次のコマンドでインストールできます。 
pip install llama-index-tools-mcp

from llama_index.tools.mcp import BasicMCPClient, McpToolSpec

# 127.0.0.1:8000 で MCP サーバーが動作しているものとします。MCP クライアントを使って、自分の MCP サーバーに接続することもできます。
mcp_client = BasicMCPClient("http://127.0.0.1:8000/sse")
mcp_tool = McpToolSpec(client=mcp_client)

# エージェントを取得する
agent = await get_agent(mcp_tool)

# エージェントのコンテキストを作成する
agent_context = Context(agent)

ユーティリティツール

API を直接クエリすると、過剰な量のデータが返ってくることがよくあります。その中には無関係なものが含まれていたり、LLM のコンテキストウィンドウに収まりきらなかったり、使用するトークン数が不必要に増えたりします。 以下では、主要な 2 つのユーティリティツールを確認します。

  1. OnDemandToolLoader: 既存の任意の LlamaIndex データローダー（BaseReader クラス）を、エージェントが使えるツールに変換するツールです。このツールは、データローダーの load_data を実行するために必要なパラメータすべてと、自然言語のクエリ文字列を使って呼び出せます。実行時には、まずデータローダーからデータを読み込み、インデックス化し（たとえばベクトルストアを使って）、そのうえで「オンデマンド」にクエリします。これら 3 つのステップはすべて、1 回のツール呼び出しの中で行われます。
  2. LoadAndSearchToolSpec: LoadAndSearchToolSpec は、既存の任意のツールを入力として受け取ります。ツールスペックとして to_tool_list を実装しており、この関数を呼び出すと、読み込み用ツールと検索用ツールの 2 つが返されます。読み込み用ツールを実行すると、内部のツールが呼び出され、その出力がインデックス化されます（デフォルトではベクトルインデックスを使います）。検索用ツールを実行すると、クエリ文字列を入力として受け取り、内部のインデックスを呼び出します。

💡 ヒント

toolspec とユーティリティツールは LlamaHub で見つけられます。
