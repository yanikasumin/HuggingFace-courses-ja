完全な学習ループ

ここでは、Trainer クラスを使わずに、現在の PyTorch で推奨されている方法に沿って学習ループをゼロから実装し、前のセクションと同じ結果を得る方法を見ていきます。セクション2のデータ処理は、すでに済んでいるものとします。先ず、必要な処理をまとめた短いコードを示します。

💡 ヒント

学習ループをゼロから実装する：このセクションは、これまでに学んだ内容を前提としています。PyTorch の学習ループの書き方や推奨される実装方法について詳しく知りたい場合は、🤗 Transformers の学習ドキュメント と カスタム学習クックブック を参照して下さい。

from datasets import load_dataset
from transformers import AutoTokenizer, DataCollatorWithPadding

raw_datasets = load_dataset("glue", "mrpc")
checkpoint = "bert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(checkpoint)


def tokenize_function(example):
    return tokenizer(example["sentence1"], example["sentence2"], truncation=True)


tokenized_datasets = raw_datasets.map(tokenize_function, batched=True)
data_collator = DataCollatorWithPadding(tokenizer=tokenizer)

学習の準備

学習ループを書く前に、いくつかのオブジェクトを定義する必要があります。先ずは、データをバッチ単位で順番に取り出す為のデータローダです。その前に、tokenized_datasets に少し後処理を加えます。これは、Trainer が自動で行っていた処理です。具体的には、次の3つの処理が必要です。

  • モデルが受け取らない列（sentence1 列や sentence2 列など）を削除する
  • 列名 label を labels に変更する（モデルが受け取る引数名は labels の為）
  • データセットの形式を設定し、リストではなく PyTorch テンソルを返すようにする

tokenized_datasets には、これらのステップに対応するメソッドがそれぞれ用意されています。

tokenized_datasets = tokenized_datasets.remove_columns(["sentence1", "sentence2", "idx"])
tokenized_datasets = tokenized_datasets.rename_column("label", "labels")
tokenized_datasets.set_format("torch")
tokenized_datasets["train"].column_names

結果として、モデルが受け付ける列だけが残っていることを確認出来ます。

["attention_mask", "input_ids", "labels", "token_type_ids"]

これで、データローダを簡単に定義出来ます。

from torch.utils.data import DataLoader

train_dataloader = DataLoader(
    tokenized_datasets["train"], shuffle=True, batch_size=8, collate_fn=data_collator
)
eval_dataloader = DataLoader(
    tokenized_datasets["validation"], batch_size=8, collate_fn=data_collator
)

データ処理に間違いが無いか手早く確認する為に、バッチを次のように調べられます。

for batch in train_dataloader:
    break
{k: v.shape for k, v in batch.items()}

```python out {'attention_mask': torch.Size([8, 65]), 'input_ids': torch.Size([8, 65]), 'labels': torch.Size([8]), 'token_type_ids': torch.Size([8, 65])}

学習用データローダでは `shuffle=True` を設定し、バッチ内の最も長い入力に合わせてパディングしています。その為、手元でコードを実行すると、テンソルの形状は上の例と少し異なる場合があります。

これでデータの前処理は全て完了しました（機械学習に取り組む人にとって、前処理を終えるのはうれしいことですが、そこまでたどり着くのも簡単ではありません）。次はモデルです。前のセクションとまったく同じようにモデルを作成します。

```py
from transformers import AutoModelForSequenceClassification

model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)

学習が問題なく進むことを確認する為に、バッチをこのモデルに渡してみます。

outputs = model(**batch)
print(outputs.loss, outputs.logits.shape)

```python out tensor(0.5441, grad_fn=) torch.Size([8, 2])

Transformers のモデルは全て、`labels` が与えられると損失を返します。ロジットも得られます（バッチ内の各入力につき2つなので、サイズ 8 x 2 のテンソルです）。

学習ループを書く準備はほぼ整いました。あと2つ、オプティマイザと学習率スケジューラが足りません。`Trainer` がやっていたことを手作業で再現するので、同じデフォルトを使います。`Trainer` が使うオプティマイザは `AdamW` です。これは Adam と同じですが、重み減衰による正則化の工夫が加わっています（Ilya Loshchilov と Frank Hutter による ["Decoupled Weight Decay Regularization"](https://arxiv.org/abs/1711.05101) を参照）。

```py
from torch.optim import AdamW

optimizer = AdamW(model.parameters(), lr=5e-5)

💡 ヒント

現代的な最適化のヒント：更に性能を高めたい場合は、次を試せます。 - 重み減衰ありの AdamW：AdamW(model.parameters(), lr=5e-5, weight_decay=0.01) - 8-bit Adam：bitsandbytes を使ったメモリ効率のよい最適化 - 学習率の調整：大きなモデルでは、低めの学習率（1e-5 〜 3e-5）がうまくいくことが多い

最適化のリソース：オプティマイザと学習戦略の詳細は Transformers 最適化ガイド を参照して下さい。

最後に、デフォルトの学習率スケジューラを設定します。このスケジューラは、学習率を最大値（5e-5）から 0 まで直線的に下げるものです。正しく設定するには、学習ステップの総数を知る必要があります。総ステップ数は、実行するエポック数に学習用バッチの数（学習用データローダの長さ）を掛けて求めます。Trainer のデフォルトは3エポックなので、ここでも同じ設定を使います。

from transformers import get_scheduler

num_epochs = 3
num_training_steps = num_epochs * len(train_dataloader)
lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)
print(num_training_steps)

```python out 1377

### 学習ループ

最後にもう1つ。GPU を使える環境なら使いたい所です（CPU では、学習に数分ではなく数時間掛かるかもしれません）。その為に、モデルとバッチを配置する `device` を定義します。

```py
import torch

device = torch.device("cuda") if torch.cuda.is_available() else torch.device("cpu")
model.to(device)
device

```python out device(type='cuda')

これで学習の準備が整いました。学習がどこまで進んだか分かるように、`tqdm` ライブラリを使って、全学習ステップの進捗を示すプログレスバーを追加します。

```py
from tqdm.auto import tqdm

progress_bar = tqdm(range(num_training_steps))

model.train()
for epoch in range(num_epochs):
    for batch in train_dataloader:
        batch = {k: v.to(device) for k, v in batch.items()}
        outputs = model(**batch)
        loss = outputs.loss
        loss.backward()

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

💡 ヒント

現代的な学習の最適化：学習ループを更に効率化するには、次を検討して下さい。

  • 勾配クリッピング：optimizer.step() の前に torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0) を追加する
  • 混合精度：torch.cuda.amp.autocast() と GradScaler を使って学習を高速化する
  • 勾配累積：複数のバッチにわたって勾配を蓄積し、大きなバッチサイズを擬似的に再現する
  • チェックポイント保存：定期的にモデルのチェックポイントを保存し、中断しても再開出来るようにする

実装ガイド：これらの最適化の詳しい例は、Transformers の効率的な学習ガイド と オプティマイザの一覧 を参照して下さい。

学習ループの核となる部分は、入門編で見たものとよく似ていることが分かります。学習状況を報告する処理は追加していない為、この学習ループだけではモデルの性能を把握出来ません。それには評価ループを追加する必要があります。

評価ループ

前と同じく、Evaluate ライブラリが提供する指標を使います。metric.compute() メソッドは既に見ましたが、add_batch() メソッドを使えば、評価ループの実行中に、指標の計算に必要な予測結果と正解ラベルをバッチごとに蓄積出来ます。全てのバッチを蓄積したら、metric.compute() で最終結果が得られます。評価ループでの実装は次の通りです。

💡 ヒント

評価のベストプラクティス：より高度な評価戦略と指標については、Evaluate のドキュメント と 包括的な評価クックブック を参照して下さい。

import evaluate

metric = evaluate.load("glue", "mrpc")
model.eval()
for batch in eval_dataloader:
    batch = {k: v.to(device) for k, v in batch.items()}
    with torch.no_grad():
        outputs = model(**batch)

    logits = outputs.logits
    predictions = torch.argmax(logits, dim=-1)
    metric.add_batch(predictions=predictions, references=batch["labels"])

metric.compute()

```python out

繰り返しになりますが、モデルヘッドの初期値やデータをシャッフルする順序はランダムに決まる為、実行するたびに結果が少し異なる場合があります。但し、おおむね同じくらいの値になるはずです。

### 🤗 Accelerate で学習ループを強化する








先程定義した学習ループは、単一の CPU や GPU では問題なく動作します。しかし [Accelerate](https://github.com/huggingface/accelerate) ライブラリを使えば、わずかな変更で複数の GPU や TPU を使った分散学習が可能になります。Accelerate は、分散学習、混合精度、デバイス配置に伴う複雑な処理を自動で行ってくれます。学習用と検証用のデータローダを作成する所から、自分で学習ループを書くと次のようになります。

<div class="callout callout-tip" markdown="block">
<p class="callout-title">💡 ヒント</p>
**Accelerate の詳細**：分散学習、混合精度、ハードウェア最適化の全ては [Accelerate のドキュメント](https://huggingface.co/docs/accelerate/) で学べます。実践的な例は [Transformers のドキュメント](https://huggingface.co/docs/transformers/main/en/accelerate) にあります。
</div>


```py
from accelerate import Accelerator
from torch.optim import AdamW
from transformers import AutoModelForSequenceClassification, get_scheduler

accelerator = Accelerator()

model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)
optimizer = AdamW(model.parameters(), lr=3e-5)

train_dl, eval_dl, model, optimizer = accelerator.prepare(
    train_dataloader, eval_dataloader, model, optimizer
)

num_epochs = 3
num_training_steps = num_epochs * len(train_dl)
lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)

progress_bar = tqdm(range(num_training_steps))

model.train()
for epoch in range(num_epochs):
    for batch in train_dl:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

先ず、必要なライブラリをインポートし、次の行で Accelerator オブジェクトを作成します。このオブジェクトが実行環境を確認し、適切な分散学習の設定を初期化します。デバイスへの配置は Accelerate が処理してくれる為、モデルをデバイスに移すコードは削除出来ます（残しておきたい場合は、device を accelerator.device に変更して下さい）。

最も重要なのは、データローダ、モデル、オプティマイザを accelerator.prepare() に渡す部分です。この処理で各オブジェクトが分散学習に適した形にラップされ、分散学習が正しく動作するようになります。あとは、バッチを device に移すコードを削除し（残す場合は accelerator.device を使うように変更します）、loss.backward() を accelerator.backward(loss) に置き換えるだけです。

💡 ヒント

⚠️ Cloud TPU による高速化の恩恵を受けるには、トークナイザの padding="max_length" 引数と max_length 引数を使って、サンプルを固定長にパディングすることをお勧めします。

そのままコピーして試せるように、Accelerate を使った完全な学習ループを載せておきます。

from accelerate import Accelerator
from torch.optim import AdamW
from transformers import AutoModelForSequenceClassification, get_scheduler

accelerator = Accelerator()

model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)
optimizer = AdamW(model.parameters(), lr=3e-5)

train_dl, eval_dl, model, optimizer = accelerator.prepare(
    train_dataloader, eval_dataloader, model, optimizer
)

num_epochs = 3
num_training_steps = num_epochs * len(train_dl)
lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)

progress_bar = tqdm(range(num_training_steps))

model.train()
for epoch in range(num_epochs):
    for batch in train_dl:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

このコードを train.py に保存すれば、どのような分散学習環境でも実行出来るようになります。実際に試すには、先ず次のコマンドを実行します。

accelerate config

表示されるいくつかの質問に答えると、回答内容が設定ファイルに保存されます。このファイルは、次のコマンドで使用されます。

accelerate launch train.py

これで分散学習が起動します。

ノートブックで試したい場合（例えば Colab で TPU を使ってテストする場合）は、コードを training_function() という関数の中に入れ、最後のセルで次のコードを実行します。

from accelerate import notebook_launcher

💡 ヒント

分散学習：マルチ GPU・マルチノード学習の包括的な解説は、Transformers 分散学習ガイド と 学習のスケーリングに関するクックブック を参照して下さい。

次のステップとベストプラクティス

学習ループをゼロから実装する方法を学んだ所で、本番環境で使う際に検討しておきたい点をいくつか紹介します。

モデルの評価：正解率だけでなく、常に複数の指標でモデルを評価して下さい。包括的な評価には Evaluate ライブラリを使います。

ハイパーパラメータ調整：体系的なハイパーパラメータ最適化には、Optuna や Ray Tune のようなライブラリの利用を検討して下さい。

モデルの監視：学習中は、学習時の指標や学習曲線、検証データでの性能を継続して記録して下さい。

モデルの共有：学習が終わったら、モデルを Hugging Face Hub で共有し、コミュニティが使えるようにして下さい。

効率化：大きなモデルでは、勾配チェックポイント、パラメータ効率のよいファインチューニング（LoRA、AdaLoRA）、量子化といった手法を検討して下さい。

カスタム学習ループによるファインチューニングの詳細な解説は以上です。ここで学んだスキルは、学習プロセスを完全に制御したい場合や、Trainer API の範囲を超えるカスタム学習ロジックを実装したい場合に役立ちます。

セクションクイズ

カスタム学習ループと応用的な学習手法について、理解度を確かめましょう。

1. Adam オプティマイザと AdamW オプティマイザの主な違いは何ですか？

学習率のスケジューリングは、オプティマイザの選択とは別物です。
正解です！AdamW では、重み減衰を勾配によるパラメータ更新とは別に適用するため、より効果的な正則化につながります。
AdamW は Transformer に限らず、あらゆるモデルアーキテクチャで使えます。
どちらのオプティマイザもメモリ要件は同程度です。

2. 学習ループにおける操作の正しい順序はどれですか？

惜しいですが、古い勾配が蓄積しないよう、次のフォワードパスの前に勾配をゼロにすべきです。
正解です！正しい順序は、損失の計算、勾配の計算、パラメータの更新、学習率の更新、そして勾配のクリアです。
損失から勾配を計算するには、バックワードパスはフォワードパスの後でなければなりません。
バックワードパスの前に勾配をゼロにすると、計算したばかりの勾配が消えてしまいます。

3. 🤗 Accelerate ライブラリは主に何を支援しますか？

Accelerate はモデルアーキテクチャ自体を最適化するものではありません。
Accelerate はハイパーパラメータ最適化を行いません。
正解です！Accelerate は分散学習に必要な複雑な処理を自動で行うため、同じコードを単一デバイスでも複数デバイスでもスムーズに動かせます。
Accelerate は PyTorch の中で動作し、フレームワーク間の変換は行いません。

4. 学習ループでバッチをデバイスに移動するのはなぜですか？

速度に影響することはありますが、主な理由は互換性です。
正解です！PyTorch では、演算を行うテンソル同士が同じデバイス上にある必要があります。
デバイスへの移動自体がメモリを節約するわけではありません。
DataLoader は特定のデバイス配置を要求しません。

5. 評価前に model.eval() は何をしますか？

model.eval() はパラメータを凍結しません。凍結するには requires_grad=False を設定します。
正解です！eval() モードではドロップアウトが無効になり、バッチ正規化では現在のバッチから統計量を計算するのではなく、学習中に蓄積された統計量を使います。
実際には、評価中は通常 torch.no_grad() を使って勾配計算を無効にします。
model.eval() は層の動作を変えるだけです。指標の計算は別途実装する必要があります。

6. 評価中の torch.no_grad() の目的は何ですか？

torch.no_grad() は予測を妨げるものではなく、勾配計算を止めるだけです。
正解です！評価には勾配が不要なので、無効にするとメモリと計算量を節約できます。
評価モードを有効にするのは torch.no_grad() ではなく model.eval() です。
再現性は乱数シードの設定で担保するもので、torch.no_grad() の役割ではありません。

7. 学習ループで 🤗 Accelerate を使うと何が変わりますか？

Accelerate では、既存の PyTorch コードへの変更は最小限で済みます。
正解です！主な変更はこの2点で、オブジェクトを accelerator.prepare() でラップし、分散学習を適切に行うために accelerator.backward() を使います。
Accelerate は利用可能なハードウェアを自動で検出します。
Accelerate でも同じオプティマイザとスケジューラが使えます。

💡 ヒント

要点： - 自分で実装した学習ループでは学習処理を完全に制御出来ますが、各処理の正しい順序（フォワード → バックワード → オプティマイザステップ → スケジューラステップ → 勾配をゼロにする）を理解する必要があります - 重み減衰ありの AdamW が、Transformer モデルに推奨されるオプティマイザです - 評価中は、正しい動作と効率の為に、常に model.eval() と torch.no_grad() を使って下さい - Accelerate を使えば、最小限のコード変更で分散学習が可能になります - デバイス管理（テンソルを CPU または GPU に移動すること）は、PyTorch の演算に不可欠です - 混合精度、勾配累積、勾配クリッピングといった現在よく使われる手法で、学習効率を大きく改善出来ます
