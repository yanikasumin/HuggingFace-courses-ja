このセクションでは、Transformer モデルで長い文書を短くまとめるタスクを扱います。このタスクを*テキスト要約*と呼びます。テキスト要約は、NLP のタスクの中でも難しいものの1つです。長い文章を理解する力と、文書の中心となる話題を捉えて一貫した文章を生成する力が求められます。要約が正しく出来れば、専門家が長い文書を細部まで読む負担は減ります。様々な業務の処理も速くなります。

## 多言語コーパスを準備する[[preparing-a-multilingual-corpus]]

バイリンガルの要約器を作る為に、[Multilingual Amazon Reviews Corpus](https://huggingface.co/datasets/amazon_reviews_multi) を使います。このコーパスは、6言語の Amazon 製品レビューで構成されます。通常は、多言語分類器のベンチマークに使われます。各レビューには短いタイトルが付いています。このタイトルを、モデルが学習する目標の要約として使えます。まず、英語とスペイン語のサブセットを Hugging Face Hub からダウンロードします。

当てはまる製品カテゴリは2つ有ります（`book` と `digital_ebook_purchase`）。両言語のデータセットを、これらの製品だけに絞ります。[Chapter 5](/course/chapter5) で見たように、`Dataset.filter()` 関数を使うと、データセットを効率的に切り分けられます。まず、その為の単純な関数を定義します。

```python
def filter_books(example):
    return (
        example["product_category"] == "book"
        or example["product_category"] == "digital_ebook_purchase"
    )
```

レビューは、厳密には本だけを扱っていません。カレンダーや、OneNote のような電子アプリケーションを指す場合も有ります。それでも、このドメインは要約モデルの学習に概ね適しています。次に、データ準備の最後の1つを行います。英語とスペイン語のレビューを、単一の `DatasetDict` オブジェクトにまとめます。🤗 Datasets には `concatenate_datasets()` 関数が有ります。この関数は、2つの `Dataset` オブジェクトを重ねてまとめます。

バイリンガルデータセットの作り方は、次の通りです。スプリットごとに、英語とスペイン語のデータセットを連結します。連結した結果はシャッフルします。シャッフルにより、モデルが単一の言語に過学習するのを防ぎます。

```python
from datasets import concatenate_datasets, DatasetDict

books_dataset = DatasetDict()

for split in english_books.keys():
    books_dataset[split] = concatenate_datasets(
        [english_books[split], spanish_books[split]]
    )
    books_dataset[split] = books_dataset[split].shuffle(seed=42)

# 例をいくつか確認します
show_samples(books_dataset)
```

## テキスト要約のためのモデル[[models-for-text-summarization]]

テキスト要約は、機械翻訳に似たタスクです。レビューのようなテキストを、入力の重要な特徴を捉えた短い文章に置き換える処理だからです。要約用の Transformer モデルの殆どは、[Chapter 1](/course/chapter1) で最初に扱ったエンコーダ・デコーダアーキテクチャを採用しています。例外も有ります。GPT ファミリーのモデルは、few-shot 設定でも要約に使えます。次の表は、要約用にファインチューニング出来る代表的な事前学習済みモデルです。

| Transformer モデル | 説明                                                                                                                                                                                                    | 多言語対応？ |
| :---------: | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-----------: |
|    [GPT-2](https://huggingface.co/gpt2-xl)    | 自己回帰型の言語モデルとして学習されていますが、入力テキストの末尾に "TL;DR" を追加することで GPT-2 に要約を生成させることができます。                                                                          |      ❌       |
|   [PEGASUS](https://huggingface.co/google/pegasus-large)   | 複数文のテキストでマスクされた文を予測する事前学習目的を使います。この事前学習目的はバニラな言語モデリングよりも要約に近く、人気のベンチマークで高いスコアを出しています。 |      ❌       |
|     [T5](https://huggingface.co/t5-base)      | すべてのタスクを text-to-text フレームワークで定式化する汎用的な Transformer アーキテクチャです。たとえば、モデルが文書を要約するための入力形式は `summarize: ARTICLE` です。                              |      ❌       |
|     [mT5](https://huggingface.co/google/mt5-base)     | T5 の多言語版で、101言語をカバーする多言語 Common Crawl コーパス（mC4）で事前学習されています。                                                                                                |      ✅       |
|    [BART](https://huggingface.co/facebook/bart-base)     | BERT と GPT-2 の事前学習方式を組み合わせ、変形した入力を復元するよう学習された、エンコーダとデコーダの両スタックを持つ新しい Transformer アーキテクチャです。                                    |      ❌       |
|  [mBART-50](https://huggingface.co/facebook/mbart-large-50)   | BART の多言語版で、50言語で事前学習されています。                                                                                                                                                     |      ✅       |

この表の通り、要約用の Transformer モデルの大部分は単一言語用です。殆どの NLP タスクでも同じです。英語やドイツ語のような「高リソース」言語では便利です。但し、世界で使われている何千もの他の言語にはあまり向いていません。

多言語 Transformer モデルは、この問題に対応します。例えば mT5 や mBART です。これらのモデルも言語モデリングで事前学習されています。但し、学習データが異なります。1つの言語のコーパスではなく、50を超える言語のテキストを合わせて学習しています。

ここでは mT5 を使います。これは T5 を基にしたアーキテクチャで、text-to-text フレームワークで事前学習されています。T5 では、全ての NLP タスクを `summarize:` のようなプロンプト接頭辞で表します。接頭辞により、モデルは生成するテキストをプロンプトに合わせます。この仕組みにより T5 は汎用性が高く、単一のモデルで多くのタスクを処理出来ます。下の図は、その例です。

## データの前処理[[preprocessing-the-data]]

<Youtube id="1m7BerpSq8A"/>

次に行うのは、レビューとタイトルのトークン化とエンコードです。まず、事前学習済みモデルのチェックポイントに対応するトークナイザを読み込みます。チェックポイントには `mt5-small` を使います。この規模なら、妥当な時間でファインチューニング出来ます。

```python
from transformers import AutoTokenizer

model_checkpoint = "google/mt5-small"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint)
```

> [!TIP]
> 💡 NLP プロジェクトの初期段階では、小さなデータサンプルで「小さい」モデルのクラスを学習するのが良い実践です。これにより、エンドツーエンドのワークフローに向けてより速くデバッグと反復が出来ます。結果に自信が持てたら、モデルのチェックポイントを変更するだけでいつでもモデルをスケールアップ出来ます！

mT5 トークナイザは、小さな例で次のように試せます。

```python
inputs = tokenizer("I loved reading the Hunger Games!")
inputs
```


ここでも、`input_ids` と `attention_mask` が有ります。どちらも [Chapter 3](/course/chapter3) の最初のファインチューニング実験で扱ったものです。次に、入力 ID をトークナイザの `convert_ids_to_tokens()` 関数で変換し、トークナイザの種類を確認します。

```python
tokenizer.convert_ids_to_tokens(inputs.input_ids)
```

```python out
['▁I', '▁', 'loved', '▁reading', '▁the', '▁Hung', 'er', '▁Games', '</s>']
```

（入力文の訳：「『ハンガー・ゲーム』を読むのが大好きでした！」）

特殊な Unicode 文字 `▁` と、シーケンス終端トークン `</s>` が有ります。これらは、SentencePiece トークナイザであることを示します。SentencePiece は、[Chapter 6](/course/chapter6) で扱った Unigram セグメンテーションアルゴリズムに基づきます。Unigram は多言語コーパスで特に有用です。アクセントや句読点に左右されず、日本語のように空白文字を持たない言語も扱える為です。

コーパスのトークン化では、要約に特有の点に注意します。ラベルもテキストです。ラベルが、モデルの最大コンテキストサイズを超える場合が有ります。そこで、レビューとタイトルの両方に切り捨てを適用し、長過ぎる入力をモデルに渡さないようにします。Transformers のトークナイザには `text_target` 引数が有ります。この引数を使うと、入力と並行してラベルをトークン化出来ます。mT5 での処理例は、次の通りです。

```python
max_input_length = 512
max_target_length = 30


def preprocess_function(examples):
    model_inputs = tokenizer(
        examples["review_body"],
        max_length=max_input_length,
        truncation=True,
    )
    labels = tokenizer(
        examples["review_title"], max_length=max_target_length, truncation=True
    )
    model_inputs["labels"] = labels["input_ids"]
    return model_inputs
```

このコードでは、まず `max_input_length` と `max_target_length` を定義します。これらの値は、レビューとタイトルの長さの上限です。レビュー本文は通常、タイトルよりずっと長い為、上限の値もそれに合わせて変えています。

`preprocess_function()` を定義すれば、コーパス全体のトークン化は `Dataset.map()` 関数で行えます。この関数は、コース全体で繰り返し使ってきたものです。

```python
tokenized_datasets = books_dataset.map(preprocess_function, batched=True)
```

コーパスの前処理は以上です。次に、要約でよく使う指標を説明します。機械が生成したテキストの品質を測る方法には、万能なものは有りません。

> [!TIP]
> 💡 上の `Dataset.map()` 関数で `batched=True` を使ったことに気づいたかもしれません。これは例を1,000件（既定）のバッチでエンコードし、Transformers の高速トークナイザのマルチスレッド機能を活用出来るようにします。可能な場合は、前処理を最大限に活用するため `batched=True` を使うようにしてください！


## テキスト要約の指標[[metrics-for-text-summarization]]

<Youtube id="TMshhnrEXlg"/>

要約や翻訳のようなテキスト生成タスクでは、性能の測定は単純ではありません。このコースで扱った他の殆どのタスクとは異なります。例えば、"I loved reading the Hunger Games" というレビューには、妥当な要約が複数有ります。"I loved the Hunger Games" でも、"Hunger Games is a great read" でもよいのです。

生成した要約とラベルとの完全一致を指標にする方法は、適切ではありません。人間でも、この指標では良い結果になりません。人によって文体が異なる為です。

要約で最もよく使われる指標の1つが、[ROUGE スコア](https://en.wikipedia.org/wiki/ROUGE_(metric)) です。ROUGE は、Recall-Oriented Understudy for Gisting Evaluation の略です。この指標では、生成した要約を参照要約の集合と比較します。参照要約は、通常は人間が作成します。ここでは、次の2つの要約を比較します。

```python
generated_summary = "I absolutely loved reading the Hunger Games"
reference_summary = "I loved reading the Hunger Games"
```

（入力文の訳：生成された要約は「『ハンガー・ゲーム』を読むのが本当に大好きでした」、参照要約は「『ハンガー・ゲーム』を読むのが大好きでした」という意味です。）

比較方法の1つは、重複する単語の数を数える方法です。この例では6です。但し、この方法は粗い為、ROUGE では使いません。ROUGE は、重複について*適合率*と*再現率*を計算します。

> [!TIP]
> 🙋 適合率と再現率を初めて聞いた場合でも心配いりません。明確な例を一緒に見て、全てを明らかにしていきます。これらの指標は通常、分類タスクで遭遇します。その文脈で適合率と再現率がどのように定義されているかを理解したい場合は、`scikit-learn` の[ガイド](https://scikit-learn.org/stable/auto_examples/model_selection/plot_precision_recall.html)をチェックすることをお勧めします。

ROUGE の再現率は、参照要約のうち、生成した要約に含まれている割合を表します。単語だけを比較する場合、再現率は次の式で計算出来ます。

$$ \mathrm{Recall} = \frac{\mathrm{Number\,of\,overlapping\, words}}{\mathrm{Total\, number\, of\, words\, in\, reference\, summary}} $$

上の単純な例では、再現率は6/6 = 1になります。参照要約の全ての単語が、生成した要約に含まれている為です。但し、再現率だけでは不十分です。生成した要約が "I really really loved reading the Hunger Games all night" でも、再現率は同じく完全になります。この要約は冗長で、質は低いと言えます。そこで、適合率も計算します。ROUGE の適合率は、生成した要約のうち、参照要約と関連する部分の割合を表します。

$$ \mathrm{Precision} = \frac{\mathrm{Number\,of\,overlapping\, words}}{\mathrm{Total\, number\, of\, words\, in\, generated\, summary}} $$

冗長な要約の適合率は 6/10 = 0.6 です。短い要約の適合率 6/7 = 0.86 より、かなり低くなります。通常は、適合率と再現率の両方を計算し、最後に、適合率と再現率の調和平均である F1 スコアを報告します。Datasets でこの計算を行うには、まず `rouge_score` パッケージをインストールします。

学習中に ROUGE スコアを計算するには、要約の生成が必要です。Transformers には、専用の `Seq2SeqTrainingArguments` クラスと `Seq2SeqTrainer` クラスが有ります。これらを使うと、生成と計算を自動で行えます。まず、実験のハイパーパラメータとその他の引数を定義します。

```python
from transformers import Seq2SeqTrainingArguments

batch_size = 8
num_train_epochs = 8
# エポックごとに学習損失を表示します
logging_steps = len(tokenized_datasets["train"]) // batch_size
model_name = model_checkpoint.split("/")[-1]

args = Seq2SeqTrainingArguments(
    output_dir=f"{model_name}-finetuned-amazon-en-es",
    evaluation_strategy="epoch",
    learning_rate=5.6e-5,
    per_device_train_batch_size=batch_size,
    per_device_eval_batch_size=batch_size,
    weight_decay=0.01,
    save_total_limit=3,
    num_train_epochs=num_train_epochs,
    predict_with_generate=True,
    logging_steps=logging_steps,
    push_to_hub=True,
)
```

ここでは、`predict_with_generate` 引数を設定します。この設定により、評価中に要約を生成し、エポックごとに ROUGE スコアを計算出来ます。[Chapter 1](/course/chapter1) で説明した通り、デコーダはトークンを1つずつ予測して推論を行います。この処理は、モデルの `generate()` メソッドが実装しています。`predict_with_generate=True` と設定すると、`Seq2SeqTrainer` は評価にこのメソッドを使います。学習率、エポック数、ウェイト減衰など、既定のハイパーパラメータの一部も調整しました。更に、`save_total_limit` オプションで、学習中に保存するチェックポイントを最大3つに制限しました。mT5 の「小さい」版でも、容量は約1 GB です。保存するコピーの数を制限すると、容量を節約出来ます。

`push_to_hub=True` 引数を設定すると、学習後にモデルを Hub へプッシュ出来ます。リポジトリの場所は、`output_dir` で定義し、ユーザープロファイルの下に置かれます。プッシュ先リポジトリの名前は、`hub_model_id` 引数で指定出来ます。組織へプッシュする場合は、この引数が必要です。例えば、モデルを [`huggingface-course` 組織](https://huggingface.co/huggingface-course) へプッシュした際には、`Seq2SeqTrainingArguments` に `hub_model_id="huggingface-course/mt5-finetuned-amazon-en-es"` を追加しました。

次に、学習中にモデルを評価する為の `compute_metrics()` 関数を Trainer に渡します。要約では、モデルの予測に `rouge_score.compute()` を呼ぶだけでは足りません。ROUGE スコアを計算する前に、出力とラベルをテキストに*デコード*する必要がある為です。次の関数は、このデコードを行います。更に、`nltk` の `sent_tokenize()` 関数を使い、要約の文を改行で区切ります。

```python
import numpy as np


def compute_metrics(eval_pred):
    predictions, labels = eval_pred
    # 生成された要約をテキストにデコードします
    decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)
    # ラベル内の -100 はデコードできないので置き換えます
    labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
    # 参照要約をテキストにデコードします
    decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)
    # ROUGE は各文の後に改行を想定します
    decoded_preds = ["\n".join(sent_tokenize(pred.strip())) for pred in decoded_preds]
    decoded_labels = ["\n".join(sent_tokenize(label.strip())) for label in decoded_labels]
    # ROUGE スコアを計算します
    result = rouge_score.compute(
        predictions=decoded_preds, references=decoded_labels, use_stemmer=True
    )
    # 中央値のスコアを取り出します
    result = {key: value.mid.fmeasure * 100 for key, value in result.items()}
    return {k: round(v, 4) for k, v in result.items()}
```

```python
from tqdm import tqdm
import numpy as np

generation_data_collator = DataCollatorForSeq2Seq(
    tokenizer, model=model, return_tensors="tf", pad_to_multiple_of=320
)

tf_generate_dataset = model.prepare_tf_dataset(
    tokenized_datasets["validation"],
    collate_fn=generation_data_collator,
    shuffle=False,
    batch_size=8,
    drop_remainder=True,
)


@tf.function(jit_compile=True)
def generate_with_xla(batch):
    return model.generate(
        input_ids=batch["input_ids"],
        attention_mask=batch["attention_mask"],
        max_new_tokens=32,
    )


all_preds = []
all_labels = []
for batch, labels in tqdm(tf_generate_dataset):
    predictions = generate_with_xla(batch)
    decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)
    labels = labels.numpy()
    labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
    decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)
    decoded_preds = ["\n".join(sent_tokenize(pred.strip())) for pred in decoded_preds]
    decoded_labels = ["\n".join(sent_tokenize(label.strip())) for label in decoded_labels]
    all_preds.extend(decoded_preds)
    all_labels.extend(decoded_labels)
```

ラベルと予測の文字列のリストが得られたら、ROUGE スコアの計算は簡単です。

## 🤗 Accelerate で mT5 をファインチューニングする[[fine-tuning-mt5-with-accelerate]]

Accelerate でのファインチューニングは、[Chapter 3](/course/chapter3) で扱ったテキスト分類の例とよく似ています。違いは主に2点です。学習中に要約を明示的に生成する必要がある点と、ROUGE スコアの計算方法を定義する必要がある点です。`Seq2SeqTrainer` では、この生成を Trainer 側が行っていました。ここでは、その実装方法を説明します。

### 学習に必要なものをすべて準備する[[preparing-everything-for-training]]

まず、各スプリットの `DataLoader` を作成します。PyTorch のデータローダはテンソルのバッチを想定します。その為、データセットの形式を `"torch"` に設定します。

```python
tokenized_datasets.set_format("torch")
```

データセットはテンソルだけで構成されました。次に、`DataCollatorForSeq2Seq` を再びインスタンス化します。その為にはモデルの新しい版が必要なので、キャッシュから再び読み込みます。

```python
model = AutoModelForSeq2SeqLM.from_pretrained(model_checkpoint)
```

その後、データコレータをインスタンス化し、これを使ってデータローダを定義出来ます。

```python
from torch.utils.data import DataLoader

batch_size = 8
train_dataloader = DataLoader(
    tokenized_datasets["train"],
    shuffle=True,
    collate_fn=data_collator,
    batch_size=batch_size,

eval_dataloader = DataLoader(
    tokenized_datasets["validation"], collate_fn=data_collator, batch_size=batch_size

```

次に、オプティマイザを定義します。他の例と同様に、殆どの問題でうまく機能する `AdamW` を使います。

```python

```

最後に、モデル、オプティマイザ、データローダを `accelerator.prepare()` メソッドに渡します。

```python

    model, optimizer, train_dataloader, eval_dataloader

```

> [!TIP]
> 🚨 TPU で学習する場合は、上のコードを全て専用の学習関数の中に移動する必要があります。詳細は [Chapter 3](/course/chapter3) を参照してください。

オブジェクトを準備したので、残りは3つです。

* 学習率スケジュールを定義すること。
* 評価の為に要約を後処理する関数を実装すること。
* モデルをプッシュ出来るリポジトリを Hub に作成すること。

学習率スケジュールには、前のセクションと同じ標準的な線形スケジュールを使います。

```python
from transformers import get_scheduler

num_update_steps_per_epoch = len(train_dataloader)
num_training_steps = num_train_epochs * num_update_steps_per_epoch

    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)
```

後処理には、生成した要約を改行で区切った文に分割する関数が必要です。ROUGE 指標は、この形式を想定しています。関数は、次のコードで実現出来ます。

```python
def postprocess_text(preds, labels):
    preds = [pred.strip() for pred in preds]
    labels = [label.strip() for label in labels]

    # ROUGE は各文の後に改行を想定します
    preds = ["\n".join(nltk.sent_tokenize(pred)) for pred in preds]
    labels = ["\n".join(nltk.sent_tokenize(label)) for label in labels]

    return preds, labels
```

この関数は、`Seq2SeqTrainer` の `compute_metrics()` 関数と似ています。先に定義した方法と同じです。

### 学習ループ[[training-loop]]

要約の学習ループは、これまでに扱った他の Accelerate の例と似ています。主なステップは、次の4つです。

1. 各エポックで `train_dataloader` の全ての例を反復してモデルを学習する。
2. 各エポックの終わりにモデルの要約を生成する。まずトークンを生成し、その後それら（及び参照要約）をテキストにデコードする。
3. 先程見たのと同じ手法で ROUGE スコアを計算する。
4. チェックポイントを保存し、全てを Hub にプッシュする。ここでは `Repository` オブジェクトの `blocking=False` 引数を使い、エポックごとのチェックポイントを*非同期*にプッシュします。非同期にすれば、GB サイズのモデルのアップロードを待たずに学習を続けられます。

これらのステップは、次のコードブロックで確認出来ます。

```python
from tqdm.auto import tqdm
import torch
import numpy as np

progress_bar = tqdm(range(num_training_steps))

for epoch in range(num_train_epochs):
    # 学習
    model.train()
    for step, batch in enumerate(train_dataloader):
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

    # 評価
    model.eval()
    for step, batch in enumerate(eval_dataloader):
        with torch.no_grad():
            generated_tokens = accelerator.unwrap_model(model).generate(
                batch["input_ids"],
                attention_mask=batch["attention_mask"],
            )

            generated_tokens = accelerator.pad_across_processes(
                generated_tokens, dim=1, pad_index=tokenizer.pad_token_id
            )
            labels = batch["labels"]

            # 最大長までパディングしていない場合は、ラベルもパディングする必要があります
            labels = accelerator.pad_across_processes(
                batch["labels"], dim=1, pad_index=tokenizer.pad_token_id
            )

            generated_tokens = accelerator.gather(generated_tokens).cpu().numpy()
            labels = accelerator.gather(labels).cpu().numpy()

            # ラベル内の -100 はデコードできないので置き換えます
            labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
            if isinstance(generated_tokens, tuple):
                generated_tokens = generated_tokens[0]
            decoded_preds = tokenizer.batch_decode(
                generated_tokens, skip_special_tokens=True
            )
            decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)

            decoded_preds, decoded_labels = postprocess_text(
                decoded_preds, decoded_labels
            )

            rouge_score.add_batch(predictions=decoded_preds, references=decoded_labels)

    # 指標を計算します
    result = rouge_score.compute()
    # ROUGE スコアの中央値を取り出します
    result = {key: value.mid.fmeasure * 100 for key, value in result.items()}
    result = {k: round(v, 4) for k, v in result.items()}
    print(f"エポック {epoch}:", result)

    # 保存とアップロード
    accelerator.wait_for_everyone()
    unwrapped_model = accelerator.unwrap_model(model)
    unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
    if accelerator.is_main_process:
        tokenizer.save_pretrained(output_dir)
        repo.push_to_hub(
            commit_message=f"Training in progress epoch {epoch}", blocking=False
        )
```
