LangGraph の理解度をテストする

簡単なクイズで LangGraph の理解度をテストしましょう。これまで扱った重要概念の定着に役立ちます。

このクイズは任意で、採点はされません。

Q1: LangGraph の主な目的は何ですか？

LangGraph が何のために設計されたものを最もよく表している文はどれですか？

LangGraph は、LLM を使うアプリケーションの制御フローを構築し、管理するために特別に設計されています。
これはむしろ LangChain の役割を表しています。LangChain は、モデルとのやり取りのための標準インターフェースを提供します。LangGraph は制御フローに重点を置きます。
LangGraph はエージェントとも連携しますが、LangGraph の主な目的は「オーケストレーション」です。

Q2: 「制御と自由」のトレードオフの観点では、LangGraph はどのような位置づけですか？

エージェント設計に対する LangGraph のアプローチを最もよく表している文はどれですか？

LangGraph は実際には自由よりも制御に重点を置いており、LLM のワークフローに構造を与えます。
LangGraph は、エージェントの実行に対する制御が必要なときに真価を発揮し、構造化されたワークフローによって予測可能な動作を実現します。

Q3: LangGraph において State はどのような役割を果たしますか？

LangGraph における State の説明として、最も正確なものを選んでください。

State は LangGraph においてユーザーが定義するクラスであり、LLM が生成するものではありません。そのフィールドはユーザーが定義し、値には LLM が入力したものが入る場合があります
State には、エラーの追跡よりもはるかに広い目的があります。ただし、それも役には立ちます。
State は LangGraph の中心であり、ステップ間の意思決定に必要な情報をすべて含みます。計算に必要なフィールドを用意しておけば、ノードがその値を変更して分岐を判断できます。
State は、外部 API を扱うものだけでなく、すべての LangGraph アプリケーションの基礎です。

Q4: LangGraph における条件付きエッジ（Conditional Edge）とは何ですか？

最も正確な説明を選んでください。

条件付きエッジにより、グラフは現在の State に基づいて動的なルーティングの判断を行え、ワークフローに分岐ロジックが生まれます。
条件付きエッジは、アプリケーションのフローを、その入力ではなく出力に基づいて制御します。
条件付きエッジは、ユーザーとのやり取りの要件ではなく、プログラム上の条件に基づきます。

Q5: LangGraph は、LLM のハルシネーションの問題への対処にどのように役立ちますか？

最も適切な答えを選んでください。

どのフレームワークでも LLM のハルシネーションを完全になくすことはできず、LangGraph も例外ではありません。
検証ステップ、確認ノード、エラー処理の経路を備えた構造化されたワークフローを作ることで、LangGraph はハルシネーションの影響を軽減するのに役立ちます。
LangGraph の構造化されたワークフローのアプローチは、速度と引き換えに、ハルシネーションの緩和に大きく役立ちます。
