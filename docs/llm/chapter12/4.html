TRL で GRPO を実装する

このページでは、Transformer Reinforcement Learning（TRL）ライブラリを使って Group Relative Policy Optimization（GRPO）を実装する方法を学びます。コードは最小限に絞り、実際に動かすことを中心に解説します。

GRPO の中心となる考え方が TRL の GRPOTrainer にどう組み込まれているかを、TRL 公式ドキュメントのコード例に沿って見ていきます。

💡 ヒント

この章は TRL の初心者向けです。既に TRL に慣れている方は、GRPO の Open R1 による実装もあわせて確認してください。

まず、GRPO アルゴリズムの重要な概念を思い出しましょう。

  • グループの形成：モデルは、プロンプトごとに複数の補完を生成します。
  • 選好の学習：モデルは、補完のグループを比べる報酬関数から学びます。
  • 学習の設定：モデルは、学習の進め方を決める設定を使います。

GRPO を実装するには、何が必要でしょうか？

  • プロンプトのデータセットを用意する。
  • 補完のリストを受け取り、報酬のリストを返す報酬関数を定義する。
  • GRPOConfig で学習の進め方を設定する。
  • GRPOTrainer を使ってモデルを学習する。

GRPO の学習を始める最小限の例は、次の通りです。

from trl import GRPOTrainer, GRPOConfig
from datasets import load_dataset

# 1. データセットを読み込む
dataset = load_dataset("your_dataset", split="train")


# 2. 簡単な報酬関数を定義する
def reward_func(completions, **kwargs):
    """例: 長い補完に報酬を与える"""
    return [float(len(completion)) for completion in completions]


# 3. 学習を設定する
training_args = GRPOConfig(
    output_dir="output",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=2,
    logging_steps=10,
)

# 4. 初期化して学習する
trainer = GRPOTrainer(
    model="your_model",  # 例: "Qwen/Qwen2-0.5B-Instruct"
    args=training_args,
    train_dataset=dataset,
    reward_funcs=reward_func,
)
trainer.train()

主要な構成要素

1. データセットの形式

データセットには、モデルが応答するプロンプトを含めます。GRPO トレーナーは、プロンプトごとに複数の補完を生成し、報酬関数でそれらを比較します。

2. 報酬関数

報酬関数は最も重要な要素です。モデルが何を学ぶかは、報酬関数で決まります。実践的な例を2つ示します。

# 例1: 補完の長さに基づく報酬
def reward_length(completions, **kwargs):
    return [float(len(completion)) for completion in completions]


# 例2: パターンへの一致に基づく報酬
import re


def reward_format(completions, **kwargs):
    pattern = r"^<think>.*?</think><answer>.*?</answer>$"
    return [1.0 if re.match(pattern, c) else 0.0 for c in completions]

3. 学習の設定

GRPOConfig の主なパラメータは、次の通りです。

training_args = GRPOConfig(
    # 必須パラメータ
    output_dir="output",
    num_train_epochs=3,
    num_generation=4,  # 各プロンプトに対して生成する補完の数
    per_device_train_batch_size=4,  # すべての生成を1つのデバイスバッチで取得したい
    # 任意だが便利
    gradient_accumulation_steps=2,
    learning_rate=1e-5,
    logging_steps=10,
    # GRPO 固有（任意）
    use_vllm=True,  # 生成を高速化
)

num_generation パラメータは GRPO で特に重要です。このパラメータはグループサイズ、つまりモデルがプロンプトごとに何件の異なる補完を生成するかを決めます。グループ単位で生成する点が、他の RL 手法との大きな違いです。

  • 小さ過ぎる場合（例：2〜3）：比べる対象の多様性が足りず、意味のある比較ができない場合があります
  • 推奨（4〜16）：多様性と計算効率のバランスが取れます
  • 大きな値：学習が改善する可能性がありますが、計算コストが大幅に増えます

グループサイズは、使える計算リソースとタスクの複雑さに合わせて選びます。簡単なタスクでは小さなグループ（4〜8）で十分な場合があります。複雑な推論タスクでは、大きなグループ（8〜16）が有効な場合があります。

成功のためのヒント

  1. メモリ管理：GPU メモリに合わせて per_device_train_batch_size と gradient_accumulation_steps を調整してください。
  2. 速度：モデルが対応している場合は、use_vllm=True を有効にすると生成を高速化できます。
  3. 監視：学習中に記録されるメトリクスを確認してください。 - reward：補完全体の平均報酬 - reward_std：報酬グループ内の標準偏差 - kl：参照モデルからの KL ダイバージェンス

報酬関数の設計

DeepSeek R1 論文では、報酬関数の設計について効果的な手法がいくつか示されています。いずれも、自分の GRPO 実装に応用できます。

1. 長さベースの報酬

長さに基づく報酬は、最も実装しやすい報酬の一つです。長い補完に報酬を与える形にできます。

def reward_len(completions, **kwargs):
    ideal_length = 20
    return [-abs(ideal_length - len(completion)) for completion in completions]

この報酬関数は、短過ぎる補完と長過ぎる補完の両方にペナルティを与えます。そのため、モデルは理想的な長さである20トークンに近い補完を生成するようになります。

2. 検証可能なタスクのためのルールベースの報酬

数学やコーディングなど、客観的に正しい答えがあるタスクでは、ルールに基づく報酬関数を実装できます。

def problem_reward(completions, answers, **kwargs):
    """検証可能な答えを持つ数学問題のための報酬関数
    completions: 評価する補完のリスト
    answers: データセットの問題に対する答えのリスト
    """

    rewards = []
    for completion, correct_answer in zip(completions, answers):
        # 補完から答えを取り出す
        try:
            # これは簡略化した例です。適切な解析が必要になります
            answer = extract_final_answer(completion)
            # 二値報酬: 正しければ1、誤っていれば0
            reward = 1.0 if answer == correct_answer else 0.0
            rewards.append(reward)
        except:
            # 答えを解析できない場合は、低い報酬を与える
            rewards.append(0.0)

    return rewards

3. 形式ベースの報酬

形式が正しいかどうかで報酬を与える方法もあります。この形式への報酬は、DeepSeek R1 の学習で重要な役割を果たしました。

def format_reward(completions, **kwargs):
    """望ましい形式に従った補完に報酬を与える"""
    # 例: 補完が think の後に answer が続く形式に従っているかをチェックする
    pattern = r"<think>(.*?)</think>\s*<answer>(.*?)</answer>"

    rewards = []
    for completion in completions:
        match = re.search(pattern, completion, re.DOTALL)
        if match:
            # 両方のセクションに十分な内容があるかをチェックする
            think_content = match.group(1).strip()
            answer_content = match.group(2).strip()

            if len(think_content) > 20 and len(answer_content) > 0:
                rewards.append(1.0)
            else:
                rewards.append(
                    0.5
                )  # 形式は正しいが内容が乏しい場合の部分的な報酬
        else:
            rewards.append(0.0)  # 形式が正しくない場合は報酬なし

    return rewards

これらの例は、DeepSeek R1 の学習プロセスに着想を得た報酬関数の実装例です。正しさ、形式、その組み合わせといった信号の使い方を示しています。
