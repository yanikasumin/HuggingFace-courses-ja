トークナイザは、NLP パイプラインの中核を担うコンポーネントです。その役割はただ1つ、テキストをモデルが処理出来る数値データへ変換することです。モデルが扱えるのは数値だけであり、テキストのままでは処理出来ません。このセクションでは、トークン化がどのような手順で行われるのかを詳しく見ていきます。

NLP のタスクで扱うデータは、通常は生のテキストです。例として、次のようなテキストを考えます。

```
Jim Henson was a puppeteer
```

（例文の訳：ジム・ヘンソンは人形遣いだった）

ところが、モデルが処理出来るのは数値だけです。そこで、生のテキストを数値へ変換する仕組みが必要になります。その変換を担うのがトークナイザです。変換の方法は1つではなく、様々なやり方があります。目指すのは、モデルにとって最も意味の有る表現であり、可能であれば最も小さい表現です。

以下では、トークン化のアルゴリズムをいくつか例に挙げながら、トークン化についてよく生じる疑問にも答えていきます。

## 単語ベース[[word-based]]

<Youtube id="nhJxYji1aho"/>

最初に思い浮かぶトークナイザは、_単語ベース_ のトークナイザでしょう。ルールは少なく、構築も利用も簡単で、多くの場合まずまずの結果が得られます。下の図では、生のテキストを単語に分割し、各単語に数値表現を割り当てる流れを示しています。

<div class="flex justify-center">
  <img class="block dark:hidden" src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter2/word_based_tokenization.svg" alt="単語ベースのトークン化の例。"/>
  <img class="hidden dark:block" src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter2/word_based_tokenization-dark.svg" alt="単語ベースのトークン化の例。"/>
</div>

テキストの分割方法は1つではありません。例えば、空白で区切る方法があります。Python の `split()` 関数を使うと、テキストを単語ごとに分割出来ます。

```py
tokenized_text = "Jim Henson was a puppeteer".split()
print(tokenized_text)
```

```python out
['Jim', 'Henson', 'was', 'a', 'puppeteer']
```

単語ベースのトークナイザには、句読点の処理について追加のルールを備えた変種もあります。この種のトークナイザでは、「語彙」がかなり大きくなることがあります。ここで語彙とは、コーパスに現れる独立したトークンの総数を指します。

各単語には ID が割り当てられます。ID は 0 から始まり、語彙のサイズまで続きます。モデルはこの ID で単語を識別します。

1つの言語を単語ベースのトークナイザで完全にカバーしようとすると、言語に含まれる単語の1つ1つに識別子が必要になり、トークンの数は膨大になります。例えば、英語の単語は 500,000 語を超えます。各単語を入力 ID に対応づけるには、その数だけ ID を管理しなければなりません。

更に、"dog" と "dogs" は別の単語として表現されます。この為、モデルには当初、両者が似ていると判断する手掛かりがありません。モデルは両者を無関係な単語として識別します。"run" と "running" のような似た単語の組についても同じで、当初は似ているものとは扱われません。

最後に、語彙に無い単語の為の専用トークンも必要です。「未知」トークンと呼ばれるもので、"[UNK]" や "&lt;unk&gt;" と書かれることが多くあります。トークナイザが未知トークンを大量に出力している場合、それは一般に良くない兆候です。単語について意味の通る表現を取り出せておらず、途中で情報が失われていることを示すからです。語彙を作る際の目標は、未知トークンへ置き換わってしまう単語を出来るだけ少なくすることです。

未知トークンの数を減らす方法の1つが、もう1段階細かい単位に分ける _文字ベース_ のトークナイザです。

## 文字ベース[[character-based]]

<Youtube id="ssLq_EK2jLE"/>

文字ベースのトークナイザは、テキストを単語ではなく文字へ分割します。利点は主に2つあります。

- 語彙がはるかに小さくなります。
- どの単語も文字から組み立てられる為、語彙外（未知）のトークンがはるかに少なくなります。

但し、ここでも空白と句読点をどう扱うかという疑問は残ります。

<div class="flex justify-center">
  <img class="block dark:hidden" src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter2/character_based_tokenization.svg" alt="文字ベースのトークン化の例。"/>
  <img class="hidden dark:block" src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter2/character_based_tokenization-dark.svg" alt="文字ベースのトークン化の例。"/>
</div>

但し、この方法も完璧ではありません。表現の単位が単語から文字へ変わると、直感的には意味が薄くなります。単語であればそれ自体に意味がありますが、文字1つでは大した意味を持たないからです。但し、この点は言語によって事情が異なります。例えば、中国語では、ラテン系の言語の文字に比べて、1文字が担う情報量が多くなります。

もう1つ考えておくべき点があります。モデルが処理するトークンの総量が非常に大きくなることです。単語ベースであれば1単語は1トークンで済みますが、文字へ変換すると、1つの単語が簡単に10個以上のトークンになります。

両者の長所を組み合わせる第3の手法が、*サブワードトークン化* です。

## サブワードトークン化[[subword-tokenization]]

<Youtube id="zHvTiHr506c"/>

サブワードトークン化のアルゴリズムは、次の原則に基づきます。よく使われる単語は、より小さいサブワードへは分割しません。一方、まれな単語は、意味のあるサブワードへ分解します。

例えば、"annoyingly" はまれな単語と考えられます。この単語は "annoying" と "ly" へ分解出来ます。"annoying" と "ly" は、それぞれ単独のサブワードとしては頻繁に現れます。同時に、2つを組み合わせた意味として "annoyingly" の意味も保たれます。

サブワードトークン化のアルゴリズムが、"Let's do tokenization!" という並びをどうトークン化するか、例を見てみましょう。

<div class="flex justify-center">
  <img class="block dark:hidden" src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter2/bpe_subword.svg" alt="サブワードトークン化アルゴリズム。"/>
  <img class="hidden dark:block" src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter2/bpe_subword-dark.svg" alt="サブワードトークン化アルゴリズム。"/>
</div>

得られるサブワードは、意味の面でも有用です。例えば、上の例では "tokenization" が "token" と "ization" に分割されています。2つとも意味を持つ単位であり、長い単語を2トークンだけで表す省スペースな表現になっています。この仕組みにより、語彙を小さく保ちながら比較的良い範囲をカバー出来、未知トークンはほぼ無くなります。

この手法は、トルコ語のような膠着語で特に有用です。膠着語では、サブワードをつなぎ合わせて、（ほぼ）任意の長さの複雑な単語を作ることが出来るからです。

### その他の手法も[[and-more]]

当然ながら、手法は他にも沢山あります。いくつか挙げると次の通りです。

- バイトレベル BPE（GPT-2 で使用）
- WordPiece（BERT で使用）
- SentencePiece や Unigram（いくつかの多言語モデルで使用）

これで、トークナイザの仕組みについて、API を使い始めるのに十分な知識が得られたはずです。

## 読み込みと保存[[loading-and-saving]]

トークナイザの読み込みと保存は、モデルと同じくらい簡単です。使うメソッドもモデルと同じで、`from_pretrained()` と `save_pretrained()` の2つです。これらのメソッドが読み込み・保存するのは、トークナイザが使うアルゴリズム（モデルの *アーキテクチャ* に当たるもの）と、その語彙（モデルの *重み* に当たるもの）です。

BERT と同じチェックポイントで訓練されたトークナイザの読み込みも、モデルの場合と同様に行えます。使うクラスが `BertTokenizer` になる点だけが異なります。

```py
from transformers import BertTokenizer

tokenizer = BertTokenizer.from_pretrained("bert-base-cased")
```

`AutoModel` の場合と同様に、`AutoTokenizer` クラスは、チェックポイント名に基づいて適切なトークナイザクラスをライブラリから取得します。その為、任意のチェックポイントで直接使うことが出来ます。

```py
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-cased")
```

読み込んだトークナイザは、前のセクションで見たように、そのまま使うことが出来ます。

```python
tokenizer("Using a Transformer network is simple")
```

```python out
{'input_ids': [101, 7993, 170, 11303, 1200, 2443, 1110, 3014, 102],
 'token_type_ids': [0, 0, 0, 0, 0, 0, 0, 0, 0],
 'attention_mask': [1, 1, 1, 1, 1, 1, 1, 1, 1]}
```

トークナイザの保存は、モデルの保存とまったく同じです。

```py
tokenizer.save_pretrained("directory_on_my_computer")
```

`token_type_ids` については[第3章](/course/chapter3)で詳しく扱います。`attention_mask` については、この後すぐ説明します。ここではまず、`input_ids` がどう生成されるのかを見ていきます。その為に、トークナイザの中間の処理を行うメソッドを確認します。

## エンコーディング[[encoding]]

<Youtube id="Yffk5aydLzg"/>

テキストを数値へ変換することを _エンコーディング_ と呼びます。エンコーディングは2段階で行われます。第1段階がトークン化、第2段階が入力 ID への変換です。

第1段階では、テキストを単語（又は単語の一部、句読点記号など）へ分割します。分割して得られた単位が *トークン* です。この分割を支配するルールは1つではありません。その為、モデルが事前学習された時と同じルールを使う必要があります。トークナイザをモデルの名前でインスタンス化するのは、そのルールを一致させる為です。

第2段階では、トークンを数値へ変換します。数値が揃えば、テンソルを構築してモデルへ渡すことが出来ます。変換に使うのは、トークナイザが持つ *語彙* です。語彙は、`from_pretrained()` メソッドでトークナイザをインスタンス化する時にダウンロードされる部分です。ここでも、モデルの事前学習時に使われた語彙と同じものを使う必要があります。

2つの段階をよりよく理解する為に、以下では段階ごとに分けて見ていきます。途中の結果を示す為に、トークン化パイプラインの一部だけを行うメソッドを使います。但し、通常の使い方では、セクション2で示したように、入力に対してトークナイザを直接呼び出してください。

### トークン化[[tokenization]]

トークン化の処理は、トークナイザの `tokenize()` メソッドが担います。

```py
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-cased")

sequence = "Using a Transformer network is simple"
tokens = tokenizer.tokenize(sequence)

print(tokens)
```

このメソッドの出力は、文字列のリスト、すなわちトークンのリストです。

```python out
['Using', 'a', 'transform', '##er', 'network', 'is', 'simple']
```

このトークナイザはサブワードトークナイザです。単語を、語彙で表せるトークンが得られるまで分割していきます。ここでは `transformer` が2つのトークン、`transform` と `##er` に分割されています。どちらも語彙で表せるトークンです。

### トークンから入力 ID へ[[from-tokens-to-input-ids]]

トークンから入力 ID への変換は、トークナイザの `convert_tokens_to_ids()` メソッドが処理します。

```py
ids = tokenizer.convert_tokens_to_ids(tokens)

print(ids)
```

```python out
[7993, 170, 11303, 1200, 2443, 1110, 3014]
```

これらの出力を適切なフレームワークのテンソルへ変換すれば、この章の前半で見たように、モデルへの入力として使えます。

> [!TIP]
> ✏️ **試してみましょう！** 最後の2つのステップ（トークン化と入力 ID への変換）を、セクション2で使った入力文（"I've been waiting for a HuggingFace course my whole life." と "I hate this so much!"）に対して再現してみてください。前に得たのと同じ入力 ID が得られることを確認しましょう！

## デコーディング[[decoding]]

*デコーディング* は逆向きの変換です。語彙のインデックスから文字列を得ます。`decode()` メソッドを使うと、次のように書けます。

```py
decoded_string = tokenizer.decode([7993, 170, 11303, 1200, 2443, 1110, 3014])
print(decoded_string)
```

```python out
'Using a Transformer network is simple'
```

`decode` メソッドの働きは、インデックスをトークンへ戻すだけではありません。同じ単語の一部だったトークンをまとめ直し、読める文を再構成します。この振る舞いは、新しいテキストを予測するモデルを使う時に非常に役立ちます。対象は、プロンプトから生成されるテキストや、翻訳・要約のようなシーケンス・ツー・シーケンスの問題です。

ここまでで、トークナイザが扱う基本操作は一通り分かったはずです。トークン化、ID への変換、そして ID から文字列への変換です。但し、これはまだ氷山の一角に過ぎません。次のセクションでは、この手法を限界まで押し進め、その限界をどう乗り越えるかを見ていきます。
