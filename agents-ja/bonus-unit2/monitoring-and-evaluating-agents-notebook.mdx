### 本番環境で追跡すべき代表的なメトリクス

1. **コスト：** smolagents の計装はトークン使用量を取得します。トークンあたりの価格を設定することで、大凡のコストに変換出来ます。
2. **レイテンシ：** 各ステップ、又は実行全体にかかる時間を観測します。
3. **ユーザーフィードバック：** ユーザーは直接フィードバック（いいね／よくない）を提供出来、エージェントの改善や修正に役立ちます。
4. **LLM-as-a-Judge：** 別の LLM を使って、エージェントの出力をほぼリアルタイムに評価します（毒性や正確さのチェックなど）。

#### 3. 追加の属性

スパンには、`user_id`、`tags`、`session_id`、カスタムメタデータなどの属性を追加出来ます。こうした情報をトレースに付け加えることで、ユーザーやセッションごとのアプリケーションの動作を分析したり、問題を調査したり、稼働状況を監視したりし易くなります。

```python
from smolagents import (CodeAgent, DuckDuckGoSearchTool, InferenceClientModel)

search_tool = DuckDuckGoSearchTool()
agent = CodeAgent(
    tools=[search_tool],
    model=InferenceClientModel()
)

with langfuse.start_as_current_span(
    name="Smolagent-Trace",
    ) as span:
    
    # ここでアプリケーションを実行する
    response = agent.run("What is the capital of Germany?")
 
    # スパンに追加の属性を渡す
    span.update_trace(
        input="What is the capital of Germany?",
        output=response,
        user_id="smolagent-user-123",
        session_id="smolagent-session-123456789",
        tags=["city-question", "testing-agents"],
        metadata={"email": "user@langfuse.com"},
        )
 
# 短命なアプリケーションではイベントをフラッシュする
langfuse.flush()
```

#### 4. ユーザーフィードバック

エージェントがユーザーインターフェースに組み込まれている場合、チャット画面の「いいね」「よくない」といった、ユーザーからの直接的なフィードバックを記録出来ます。以下は、[Gradio](https://gradio.app/) を使って、簡単なフィードバック機能付きのチャットを画面に組み込む例です。

以下のコードでは、ユーザーがチャットメッセージを送信すると、トレースを Langfuse に記録します。ユーザーが最後の回答にいいね／よくないを付けると、そのスコアをトレースに紐付けます。

```python
import gradio as gr
from smolagents import (CodeAgent, InferenceClientModel)
from langfuse import get_client

langfuse = get_client()

model = InferenceClientModel()
agent = CodeAgent(tools=[], model=model, add_base_tools=True)

trace_id = None

def respond(prompt, history):
    with langfuse.start_as_current_span(
        name="Smolagent-Trace"):
        
        # ここでアプリケーションを実行する
        output = agent.run(prompt)

        global trace_id
        trace_id = langfuse.get_current_trace_id()

    history.append({"role": "assistant", "content": str(output)})
    return history

def handle_like(data: gr.LikeData):
    # デモ用に、ユーザーフィードバックを 1（いいね）または 0（よくない）にマッピングする
    if data.liked:
        langfuse.create_score(
            value=1,
            name="user-feedback",
            trace_id=trace_id
        )
    else:
        langfuse.create_score(
            value=0,
            name="user-feedback",
            trace_id=trace_id
        )

with gr.Blocks() as demo:
    chatbot = gr.Chatbot(label="チャット", type="messages")
    prompt_box = gr.Textbox(placeholder="メッセージを入力してください...", label="メッセージ")

    # ユーザーがプロンプトで Enter を押したら 'respond' を実行する
    prompt_box.submit(
        fn=respond,
        inputs=[prompt_box, chatbot],
        outputs=chatbot
    )

    # ユーザーがメッセージの「いいね」ボタンをクリックしたら 'handle_like' を実行する
    chatbot.like(handle_like, None, None)

demo.launch()
```

#### 5. LLM-as-a-Judge

LLM-as-a-Judge は、エージェントの出力を自動的に評価するもう一つの方法です。別の LLM 呼び出しを設定し、出力の正確さ、毒性、スタイルなど、気になる任意の基準で評価させることが出来ます。

**ワークフロー：**
1. **評価テンプレート**を定義します。例えば「テキストに毒性が有るかチェックする」などです。
2. エージェントが出力を生成するたびに、その出力とテンプレートを「ジャッジ」LLM に渡します。
3. ジャッジ LLM が評価やラベルを返し、それをオブザーバビリティツールに記録します。

Langfuse の例：

![LLM-as-a-Judge の評価テンプレート](https://huggingface.co/datasets/agents-course/course-images/resolve/main/en/bonus-unit2/evaluator-template.png)
![LLM-as-a-Judge の評価器](https://huggingface.co/datasets/agents-course/course-images/resolve/main/en/bonus-unit2/evaluator.png)


```python
# 例: エージェントの出力に毒性があるかどうかをチェックする
from smolagents import (CodeAgent, DuckDuckGoSearchTool, InferenceClientModel)

search_tool = DuckDuckGoSearchTool()
agent = CodeAgent(tools=[search_tool], model=InferenceClientModel())

agent.run("Can eating carrots improve your vision?")
```

## オフライン評価

オンライン評価はライブフィードバックに不可欠ですが、**オフライン評価**、つまり開発前や開発中の体系的なチェックも必要です。これにより、変更を本番環境へ投入する前に、品質と信頼性を保つことが出来ます。

### データセットによる評価

オフライン評価では、通常は次の手順を行います。
1. ベンチマークデータセット（プロンプトと期待される出力のペア）を用意する
2. そのデータセットでエージェントを実行する
3. 出力を期待される結果と比較するか、追加の採点方法を使う

以下では、数学の質問と解答を含む [GSM8K データセット](https://huggingface.co/datasets/openai/gsm8k) でこのアプローチを示します。

#### データセットでエージェントを実行する

ヘルパー関数 `run_smolagent()` を定義します。この関数は次の処理を行います。
1. Langfuse のスパンを開始する
2. プロンプトでエージェントを実行する
3. Langfuse にトレース ID を記録する

その後、データセットの各アイテムをループしてエージェントを実行し、トレースをデータセットアイテムに紐付けます。必要に応じて、簡易な評価スコアを付けることも出来ます。


```python
from opentelemetry.trace import format_trace_id
from smolagents import (CodeAgent, InferenceClientModel, LiteLLMModel)
from langfuse import get_client
 
langfuse = get_client()


# 例: InferenceClientModel や LiteLLMModel を使うと、OpenAI、Anthropic、Gemini などのモデルにアクセスできる
model = InferenceClientModel()

agent = CodeAgent(
    tools=[],
    model=model,
    add_base_tools=True
)

dataset_name = "gsm8k_dataset_huggingface"
current_run_name = "smolagent-notebook-run-01" # この評価実行を識別する名前
 
# 'run_smolagent' を、計装済みのアプリケーション関数とする
def run_smolagent(question):
    with langfuse.start_as_current_generation(name="qna-llm-call") as generation:
        # LLM 呼び出しをシミュレートする
        result = agent.run(question)
 
        # トレースに入力と出力を記録する
        generation.update_trace(
            input= question,
            output=result,
        )
 
        return result
 
dataset = langfuse.get_dataset(name=dataset_name) # 用意済みのデータセットを取得する
 
for item in dataset.items:
 
    # item.run() コンテキストマネージャを使う
    with item.run(
        run_name=current_run_name,
        run_metadata={"model_provider": "Hugging Face", "temperature_setting": 0.7},
        run_description="Evaluation run for GSM8K dataset"
    ) as root_span: # root_span は、このアイテムと実行に対する新しいトレースのルートスパン
        # このブロック内の後続の langfuse 操作はすべてこのトレースに属する
 
        # アプリケーションのロジックを呼び出す
        generated_answer = run_smolagent(question=item.input["text"])
 
        print(item.input)
```

次の要素を変えて、同じ手順を繰り返すことが出来ます。
- モデル（OpenAI GPT、ローカル LLM など）
- ツール（検索ツールあり／なし）
- プロンプト（異なるシステムメッセージ）

その後、オブザーバビリティツールで並べて比較出来ます。
