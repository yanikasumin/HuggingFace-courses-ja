切り分けて、加工して

多くの場合、手元のデータはモデルの訓練にそのまま使える形には整っていません。このセクションでは、データセットをきれいに整えるために 🤗 Datasets が提供するさまざまな機能を探っていきます。

データを切り分けて加工する

Pandas と同様に、🤗 Datasets には Dataset オブジェクトや DatasetDict オブジェクトの内容を操作する関数がいくつも用意されています。Dataset.map() メソッドは Chapter 3 ですでに紹介しました。このセクションでは、それ以外に使える関数を見ていきます。

この例では、UC Irvine Machine Learning Repository で公開されている Drug Review Dataset を使います。これは、さまざまな薬に対する患者のレビューを、治療対象の症状と、患者の満足度を示す10段階の星評価とともに収めたものです。

まず、wget コマンドと unzip コマンドでデータをダウンロードして展開する必要があります。

!wget "https://archive.ics.uci.edu/ml/machine-learning-databases/00462/drugsCom_raw.zip"
!unzip drugsCom_raw.zip

TSV は、区切り文字にカンマではなくタブを使う CSV の一種にすぎません。そのため、load_dataset() 関数で csv ローディングスクリプトを使い、delimiter 引数を指定することで、これらのファイルを次のように読み込めます。

from datasets import load_dataset

data_files = {"train": "drugsComTrain_raw.tsv", "test": "drugsComTest_raw.tsv"}
# \t は Python におけるタブ文字です
drug_dataset = load_dataset("csv", data_files=data_files, delimiter="\t")

データ分析では、まず小さなランダムサンプルを取り出して、扱っているデータの傾向を手早く把握するのが一般的です。🤗 Datasets では、Dataset.shuffle() 関数と Dataset.select() 関数をつなげることでランダムサンプルを作れます。

drug_sample = drug_dataset["train"].shuffle(seed=42).select(range(1000))
# 最初の数件のサンプルをのぞいてみます
drug_sample[:3]

再現性のために、`Dataset.shuffle()` でシードを固定していることに注目してください。`Dataset.select()` はインデックスを順に取り出せる反復可能オブジェクト（iterable）を引数として受け取るため、シャッフル済みデータセットの最初の1,000件を取り出すために `range(1000)` を渡しています。このサンプルからでも、データセットの癖がいくつか既に見えてきます。

* `Unnamed: 0` 列は、各患者の匿名化された ID のように見えます。
* `condition` 列には、大文字と小文字のラベルが混在しています。
* レビューは長さがまちまちで、改行コード（`\r\n`）や、`&\#039;` のような HTML 文字参照が混ざっています。

🤗 Datasets を使ってこれらの問題にどう対処できるか見ていきましょう。`Unnamed: 0` 列が患者 ID を表しているという仮説を検証するには、`Dataset.unique()` 関数を使って、ID の数が各分割の行数と一致するかを確認できます。

```py
for split in drug_dataset.keys():
    assert len(drug_dataset[split]) == len(drug_dataset[split].unique("Unnamed: 0"))

仮説は正しそうです。では、Unnamed: 0 列の名前をもう少し解釈しやすいものに変えて、データセットを少し整えましょう。DatasetDict.rename_column() 関数を使えば、両方の分割にわたって一度に列名を変更できます。

drug_dataset = drug_dataset.rename_column(
    original_column_name="Unnamed: 0", new_column_name="patient_id"
)

次に、`Dataset.map()` を使って `condition` ラベルをすべて正規化します。[Chapter 3](/course/chapter3) でトークナイズを行ったときと同様に、`drug_dataset` の各分割のすべての行に適用できる単純な関数を定義できます。

```py
def lowercase_condition(example):
    return {"condition": example["condition"].lower()}


drug_dataset.map(lowercase_condition)

```python out AttributeError: 'NoneType' object has no attribute 'lower'

おっと、map 関数で問題が発生しました！エラーから、`condition` 列の一部のエントリが `None` であることが推測できます。文字列ではないので小文字化できません。これらの行は `Dataset.filter()` を使って取り除きましょう。この関数は `Dataset.map()` と似た仕組みで、データセットの1件のサンプルを受け取る関数を期待します。たとえば、次のような関数を定義できます。

```py
def filter_nones(x):
    return x["condition"] is not None

この関数を drug_dataset.filter(filter_nones) で実行することもできますが、ラムダ関数を使えば1行で書けます。Python のラムダ関数は、明示的に名前を付けずに定義できる小さな関数です。一般形は次のとおりです。

lambda <arguments> : <expression>

ここで lambda は Python の特殊なキーワードの1つです。<arguments> は関数の入力を定義するカンマ区切りの値のリスト／集合、<expression> は実行したい演算を表します。たとえば、数を2乗する単純なラムダ関数は、次のように定義できます。

lambda x : x * x

この関数を入力に適用するには、関数と入力を括弧で囲む必要があります。

(lambda x: x * x)(3)

```python out 9

同様に、引数をカンマで区切ることで、複数の引数を取るラムダ関数も定義できます。たとえば、三角形の面積は次のように計算できます。

```py
(lambda base, height: 0.5 * base * height)(4, 8)

```python out 16.0

ラムダ関数は、小さくて使い捨ての関数を定義したい場合に便利です（詳細については、Andre Burgaud による素晴らしい [Real Python のチュートリアル](https://realpython.com/python-lambda/)を読むことをおすすめします）。🤗 Datasets の文脈では、ラムダ関数を使って単純な map や filter の操作を定義できます。このテクニックを使って、データセット内の `None` エントリを取り除きましょう。

```py
drug_dataset = drug_dataset.filter(lambda x: x["condition"] is not None)

None エントリが取り除けたので、condition 列を正規化できます。

drug_dataset = drug_dataset.map(lowercase_condition)
# 小文字化が効いているか確認します
drug_dataset["train"]["condition"][:3]

```python out ['left ventricular dysfunction', 'adhd', 'birth control']

うまくいきました！ラベルが整ったところで、次はレビュー自体のクリーニングを見ていきましょう。

## 新しい列の作成

顧客レビューを扱う際の良い実践として、各レビューの単語数を確認することが挙げられます。レビューは "Great!" のように1語だけの場合もあれば、数千語に及ぶ長文の場合もあり、用途によってこれらの極端なケースへの対処は異なります。各レビューの単語数を数えるために、空白を区切りとして単語を数える簡易的な方法を使います。

各レビューの単語数を数える単純な関数を定義しましょう。

```py
def compute_review_length(example):
    return {"review_length": len(example["review"].split())}

lowercase_condition() 関数とは違い、compute_review_length() はデータセットの列名のいずれにも対応しないキーの辞書を返します。この場合、compute_review_length() を Dataset.map() に渡すと、データセットのすべての行に適用され、新しい review_length 列が作られます。

drug_dataset = drug_dataset.map(compute_review_length)
# 最初の訓練サンプルを確認します
drug_dataset["train"][0]

```python out {'patient_id': 206461, 'drugName': 'Valsartan', 'condition': 'left ventricular dysfunction', 'review': '"It has no side effect, I take it in combination of Bystolic 5 Mg and Fish Oil"', 'rating': 9.0, 'date': 'May 20, 2012', 'usefulCount': 27, 'review_length': 17}

期待どおり、訓練セットに `review_length` 列が追加されていることが分かります。この新しい列を `Dataset.sort()` で並べ替えると、極端な値がどうなっているかが見られます。

```py
drug_dataset["train"].sort("review_length")[:3]

予想どおり、1語だけのレビューも含まれています。感情分析ならそれでも構いませんが、症状を予測するには、十分な手掛かりが得られません。

最後に対処する必要があるのは、レビューに含まれる HTML 文字参照です。Python の `html` モジュールを使えば、次のようにこれらの文字をアンエスケープできます。

```py
import html

text = "I&#039;m a transformer called BERT"
html.unescape(text)

```python out "I'm a transformer called BERT"

`Dataset.map()` を使って、コーパス内のすべての HTML 文字をアンエスケープしましょう。

```python
drug_dataset = drug_dataset.map(lambda x: {"review": html.unescape(x["review"])})

見てのとおり、Dataset.map() メソッドはデータ処理にかなり役立ちます。しかも、その能力のほんの一部に触れただけです！

map() メソッドのスーパーパワー

Dataset.map() メソッドには batched 引数があり、True に設定すると、サンプルのバッチが一度に map 関数へ送られます（バッチサイズは設定可能で、デフォルトは1,000です）。たとえば、先ほどのすべての HTML をアンエスケープする map 関数は、実行に少し時間がかかりました（所要時間はプログレスバーで確認できます）。リスト内包表記を使って複数の要素を同時に処理すれば、これを高速化できます。

batched=True を指定すると、関数はデータセットのフィールドを持つ辞書を受け取りますが、各値は単一の値ではなく値のリストになります。Dataset.map() の戻り値も同様に、更新または追加したいフィールドを持つ辞書と、値のリストであるべきです。たとえば、すべての HTML 文字をアンエスケープする別の方法として、batched=True を使うと次のようになります。

new_drug_dataset = drug_dataset.map(
    lambda x: {"review": [html.unescape(o) for o in x["review"]]}, batched=True
)

このコードをノートブックで実行している場合、このコマンドが前のコマンドよりもずっと速く実行されることに気づくでしょう。しかもそれは、レビューが既に HTML アンエスケープ済みだからではありません。先ほどの処理を（batched=True を指定せずに）もう一度実行しても、以前と同じだけの時間がかかります。リスト内包表記は通常、同じコードを for ループで実行するよりも高速であり、要素に1つずつではなくまとめてアクセスすることでも性能が得られるためです。

Dataset.map() と batched=True の組み合わせは、Chapter 6 で出会う「高速（fast）」トークナイザの速度を引き出すうえで必須となります。高速トークナイザはテキストの大きなリストをすばやくトークナイズできます。たとえば、高速トークナイザで薬のレビューをすべてトークナイズするには、次のような関数が使えます。

from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-cased")


def tokenize_function(examples):
    return tokenizer(examples["review"], truncation=True)

Chapter 3 で見たとおり、トークナイザには1つまたは複数のサンプルを渡せるため、この関数は batched=True の有無にかかわらず使えます。この機会に、さまざまな選択肢の性能を比較してみましょう。ノートブックでは、計測したいコード行の前に %time を付ければ、1行の命令の時間を測れます。

```python no-format %time tokenized_dataset = drug_dataset.map(tokenize_function, batched=True)

セル全体の時間を測るには、セルの先頭に `%%time` を置くこともできます。この命令を実行したハードウェアでは10.8秒と表示されました（「Wall time」の後に書かれた数値です）。

<div class="callout callout-tip" markdown="block">
<p class="callout-title">💡 ヒント</p>
✏️ **やってみよう！** 同じ命令を `batched=True` の有無で実行し、さらに低速トークナイザ（`AutoTokenizer.from_pretrained()` メソッドに `use_fast=False` を追加）でも試して、自分のハードウェアでどのような数値が得られるか確認してみましょう。
</div>


バッチ処理の有無、高速トークナイザと低速トークナイザで得られた結果は次のとおりです。

オプション         | 高速トークナイザ | 低速トークナイザ
:--------------:|:--------------:|:-------------:
`batched=True`  | 10.8s          | 4min41s
`batched=False` | 59.2s          | 5min3s

つまり、高速トークナイザと `batched=True` オプションの組み合わせは、バッチ処理なしの低速な組み合わせよりも30倍高速ということです。本当に驚くべきことです！これが、`AutoTokenizer` を使うときに高速トークナイザがデフォルトである（そして「高速」と呼ばれる）主な理由です。裏側ではトークナイズのコードが Rust で実行されており、Rust はコード実行の並列化が容易な言語であるため、このような高速化が可能になっています。

並列化は、高速トークナイザがバッチ処理でほぼ6倍の高速化を達成できる理由でもあります。単一のトークナイズ操作は並列化できませんが、多数のテキストを同時にトークナイズしたい場合は、実行を複数のプロセスに分割し、それぞれが自分の担当するテキストを処理すればよいのです。

`Dataset.map()` 自体にも並列化の能力があります。Rust による裏付けはないため、低速トークナイザが高速トークナイザに追いつくことはありませんが、それでも役に立つことがあります（特に、高速版が存在しないトークナイザを使っている場合）。マルチプロセッシングを有効にするには、`num_proc` 引数を使って、`Dataset.map()` の呼び出しで使うプロセス数を指定します。

```py
slow_tokenizer = AutoTokenizer.from_pretrained("bert-base-cased", use_fast=False)


def slow_tokenize_function(examples):
    return slow_tokenizer(examples["review"], truncation=True)


tokenized_dataset = drug_dataset.map(slow_tokenize_function, batched=True, num_proc=8)

時間を測りながら少し実験すれば、使うプロセスの最適な数が分かります。私たちの場合、8が最も良い高速化をもたらすようでした。マルチプロセッシングの有無で得られた数値は次のとおりです。

オプション 高速トークナイザ 低速トークナイザ
batched=True 10.8s 4min41s
batched=False 59.2s 5min3s
batched=True, num_proc=8 6.52s 41.3s
batched=False, num_proc=8 9.49s 45.2s

低速トークナイザでも、実行時間が大幅に短縮され、より実用的な水準になりましたが、高速トークナイザの性能も大幅に向上しました。ただし、常にそうなるとは限りません。8以外の num_proc の値では、そのオプションなしで batched=True を使うほうが速いという結果がテストで示されました。一般に、batched=True と高速トークナイザの組み合わせに Python のマルチプロセッシングを使うことはおすすめしません。

💡 ヒント

num_proc を使って処理を高速化するのは、通常は良い考えです。ただし、使用している関数自体が既に何らかのマルチプロセッシングを行っていない場合に限ります。

これだけの機能が1つのメソッドに凝縮されているだけでもかなり素晴らしいのですが、まだあります！Dataset.map() と batched=True を使えば、データセット内の要素数を変更することもできます。これは、1つのサンプルから複数の訓練特徴量を作りたい場面など、多くの状況で非常に便利です。Chapter 7 で取り組むいくつかの NLP タスクの前処理でも必要になります。

```py

)

長さの不一致の問題は、古い列を新しい列と同じサイズにすることでも対処できると述べました。これを行うには、`return_overflowing_tokens=True` を設定したときにトークナイザが返す `overflow_to_sample_mapping` フィールドが必要です。これは、新しい特徴量のインデックスから、それが由来するサンプルのインデックスへのマッピングを与えます。`overflow_to_sample_mapping` を使うと、新しく生成された各特徴量が元のどのサンプルに対応するか分かります。この対応関係に従って元の列の値を複製すれば、新しい特徴量と同じ件数に揃えられます。

```py
def tokenize_and_split(examples):
    result = tokenizer(
        examples["review"],
        truncation=True,
        max_length=128,
        return_overflowing_tokens=True,
    )
    # 新旧インデックスの対応関係を取り出します
    sample_map = result.pop("overflow_to_sample_mapping")
    for key, values in examples.items():
        result[key] = [values[i] for i in sample_map]
    return result

古い列を取り除かなくても、Dataset.map() で動作することが分かります。

tokenized_dataset = drug_dataset.map(tokenize_and_split, batched=True)

## データセットの保存








🤗 Datasets は、ダウンロードしたすべてのデータセットとそれに対して行った操作をキャッシュしますが、データセットをディスクに保存したい場合もあります（キャッシュが削除される場合など）。下の表に示すように、🤗 Datasets にはデータセットを異なる形式で保存する3つの主要な関数が用意されています。

| データ形式 |        関数        |
| :---------: | :--------------------: |
|    Arrow    | `Dataset.save_to_disk()` |
|     CSV     |    `Dataset.to_csv()`    |
|    JSON     |   `Dataset.to_json()`    |
