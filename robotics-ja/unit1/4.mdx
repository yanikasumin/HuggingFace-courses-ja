# コード例: データセットを実際に扱う

このセクションでは、LeRobotDataset クラスを使い、Hugging Face のロボティクスデータセットを扱う方法を紹介します。簡単な例から始め、徐々に複雑な例へと進みます。自分のプロジェクトに合った方法を選び、コードをコピーして応用してください。

ここで重要なのは、表形式データ、視覚データ、メタデータを含む LeRobot 形式に準拠したデータセットなら、Hugging Face Hub 上にあるものをどれでも、わずか1行のコードで読み込めるということです。

ロボティクスデータを扱う際には、ある時点のデータだけでなく、複数の時点のデータをまとめて参照することがよくあります。なぜなら、多くのロボット学習アルゴリズムでは、時間の経過に伴う状態の変化を捉える必要があるからです。例えば、物体をつかむ際には、直前の数時点で何が起きたかを確認することで、現在の状況をより正確に把握できます。また、多くのアルゴリズムは、その瞬間の行動だけを決めるよりも、先の数ステップまで行動を計画できるほうがうまく機能します。

LeRobotDataset では「時間窓（temporal windowing）」という仕組みにより、複数時点のデータを簡単に取得できます。必要な時間オフセット（例: 現在のフレームとその前の2フレーム）を指定するだけで、対応するフレームを自動的に取得できます。エピソードの開始時や終了時に一部のフレームが存在しない場合も、自動的に処理されます。

![複数フレームのストリーミング](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/lerobotdataset-v3/streaming-multiple-frames.png)

> [!TIP]
> **時間窓の説明:** 
> - **観測の履歴**: `[-0.2, -0.1, 0.0]` で、200ms 前、100ms 前、現在の観測が得られます
> - **行動シーケンス**: `[0.0, 0.1, 0.2]` で、現在の行動と次の2つの行動（100ms 間隔）が得られます
> - **自動パディング**: エピソードの境界で欠けたフレームは自動的に処理されます。データセットは常に、要求した数のフレームを返し、必要なところではパディングを適用します
> - **マスク情報**: どのフレームが実際のデータで、どれがパディングなのかを判別できるため、適切に訓練できます

LeRobotDataset は PyTorch の `DataLoader` と組み合わせて利用でき、各サンプルを表す辞書を、訓練や推論に使えるバッチ化されたテンソルの辞書へ自動的にまとめる（collate）ことができます。また、データセットのストリーミングにも標準で対応しています。実装を1行変更するだけで、Hugging Face Hub 上の大規模なデータセットをストリーミングで利用できます。ストリーミングデータセットは、高速なバッチ処理（接続状況によりおよそ 80-100 it/s）と、フレームの十分なランダム化をサポートしています。これらは実用的な BC アルゴリズムにとって重要です。こうした機能がなければ、処理が遅くなったり、データの時間的な偏りが強く、独立同一分布（i.i.d.）の仮定から大きく外れた状態で学習することになったりします。この仕組みは、大量のメモリやストレージを用意しなくても大規模なデータセットを扱えるようにし、より多くの人が利用できる環境を提供するものです。

用途に応じた時間窓の設定例をいくつか紹介します。まずは全体をざっと確認し、1つ選んで試してみてください。後から別の設定に切り替える場合も、設定用の辞書を書き換えるだけで済みます。

**基本的な行動クローニング**（現在の観測から現在の行動を学ぶ）:

```python
# シンプル: 現在の観測 → 現在の行動
delta_timestamps = {
    "observation.images.up": [0.0],  # 現在のフレームのみ
    "action": [0.0]  # 現在の行動のみ
}

dataset = LeRobotDataset(
    "lerobot/svla_so101_pickplace", 
    delta_timestamps=delta_timestamps
)
```

</hfoption>
<hfoption id="history-bc">

**履歴ベースの BC**（より良い判断のために観測の履歴を使う）:

```python
# コンテキストとして観測の履歴を使う
delta_timestamps = {
    "observation.images.up": [-0.2, -0.1, 0.0],  # 200ms 分の履歴
    "action": [0.0]  # 現在の行動
}

dataset = LeRobotDataset(
    "lerobot/svla_so101_pickplace",
    delta_timestamps=delta_timestamps
)

sample = dataset[100]
# 画像の shape: [3, C, H, W] - 3つの過去フレーム
# 行動の shape: [action_dim] - 単一の現在の行動
```

</hfoption>

**アクションチャンキング**（より滑らかな制御のために行動シーケンスを予測する）:

```python
# 複数の未来の行動を一度に予測する
delta_timestamps = {
    "observation.images.up": [-0.1, 0.0],  # 直前 + 現在
    "action": [0.0, 0.1, 0.2, 0.3]  # 現在 + 3つの未来の行動
}

dataset = LeRobotDataset(
    "lerobot/svla_so101_pickplace",
    delta_timestamps=delta_timestamps
)

sample = dataset[100] 
# 画像の shape: [2, C, H, W] - 2つの観測フレーム
# 行動の shape: [4, action_dim] - 4つの行動予測
```

### 大規模データセットのストリーミング

> [!TIP]
> **ストリーミングを使う場面:**
> - **データセット > 利用可能なストレージ** - ディスクに収まらないデータセットをストリーミングする
> - **実験** - ダウンロードせずに、さまざまなデータセットを手早く試す
> - **クラウドでの訓練** - Hugging Face Hub からストリーミングして起動時間を短縮する
> - **安定したネット接続がある場合** - 訓練中は安定したインターネット接続が必要
>
> **性能:** ネットワーク接続が良好な場合、ストリーミングでも 80-100 it/s の処理速度を実現できます！ 初期化にかかる時間を除けば、平均的な処理性能はローカルに保存したデータセットと同程度です。

<hfoptions id="dataset-loading">
<hfoption id="download">

**データセットのダウンロード**（訓練が高速、ストレージが必要）:

```python
from lerobot.datasets.lerobot_dataset import LeRobotDataset

# データセットをローカルキャッシュにダウンロードする
dataset = LeRobotDataset("lerobot/svla_so101_pickplace")

# ダウンロード後は最も高速にアクセスできる
sample = dataset[100]
```

</hfoption>

**データセットのストリーミング**（ストレージ不要、インターネットが必要）:

```python
from lerobot.datasets.streaming_dataset import StreamingLeRobotDataset

# ダウンロードせずにデータをストリーミングする
streaming_dataset = StreamingLeRobotDataset(
    "lerobot/svla_so101_pickplace",
    delta_timestamps=delta_timestamps
)

# 通常のデータセットとまったく同じように動作する
sample = streaming_dataset[100]
```

## 訓練への統合

通常のデータセットもストリーミングデータセットも、PyTorch のデータローダーと簡単に組み合わせられます。そのため、どの LeRobotDataset でも、自分で作成した `torch` の訓練ループに容易に組み込めます。データセットから各フレームをテンソルとして取得できるので、データローダーからバッチを取り出してモデルを訓練する処理も簡単に実装できます。  

### PyTorch DataLoader
通常のデータセットもストリーミングデータセットも、PyTorch のデータローダーと簡単に組み合わせられます。そのため、どの LeRobotDataset でも、自分で作成した `torch` の訓練ループに容易に組み込めます。データセットから各フレームをテンソルとして取得できるので、データローダーからバッチを取り出してモデルを訓練する処理も簡単に実装できます。
```python
import torch
from torch.utils.data import DataLoader
# 訓練用の DataLoader を作成する
dataloader = DataLoader(
    dataset,
    batch_size=16,
    shuffle=True,
    num_workers=4
)

# 訓練ループ
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

for batch in dataloader:
    # デバイスへ移動する
    observations = batch["observation.state"].to(device)
```

## これが重要な理由

このシンプルな API の裏側では、多くの複雑な処理が行われています。
- ✅ **マルチモーダルの同期** - 画像とセンサーが完全に揃っている
- ✅ **効率的な保存** - 圧縮された動画、メモリマップド配列
- ✅ **時系列データの処理** - 観測／行動シーケンスへの簡単なアクセス  
- ✅ **スケーラビリティ** - 小規模なデータセットでも大規模なデータセットでも、同じコードが動作する

これに対して、従来のロボティクスのデータ処理では、たいてい次のものが必要でした。
- 各データ形式のためのカスタムパーサー
- モダリティ間での手作業の同期
- 時間窓のための複雑なバッファリング
- プラットフォーム固有の読み込みコード

LeRobotDataset は、これらすべてを**標準化し、単純化**します！
