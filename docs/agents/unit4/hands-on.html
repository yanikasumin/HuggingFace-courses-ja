ハンズオン

最終課題のエージェント作りを更に進めましょう。ここでは、作成したエージェントを審査に提出する方法を説明します。

データセット

このリーダーボードで使うデータセットは、GAIAの 検証セット（validation set） に含まれるレベル1の問題から選んだ20問で構成されています。

選ばれた問題は、回答に必要なツールとステップの数に基づいてフィルタリングされています。

GAIAベンチマークの現状を踏まえると、レベル1の問題で正答率30%を目標にするのは、妥当な課題だと考えています。

提出の流れ

では、どうすれば回答を提出出来るのでしょうか？

このユニットでは、問題を取得し、回答を送って採点してもらえるAPIを用意しました。APIエンドポイントの概要は次の通りです。実際に操作しながら試したい場合は、APIドキュメントを参照してください。

  • GET /questions：フィルタリングされた評価問題の全リストを取得します。
  • GET /random-question：リストからランダムに1問を取得します。
  • GET /files/{task_id}：指定したタスクIDに関連するファイルをダウンロードします。
  • POST /submit：エージェントの回答を提出し、スコアを計算して、リーダーボードを更新します。

提出された回答は、正解データ（ground truth）と 完全一致（EXACT MATCH） するかどうかで採点されます。その為、エージェントへのプロンプトの書き方が重要です。

GAIAチームは、エージェント向けのプロンプト例をこちらで公開しています。但し、このコースでは、提出する回答に「FINAL ANSWER」という文字列を含めないでください。エージェントには答えだけを返させ、余計な文字を含めないようにしてください。

テンプレートを自分流にアレンジしましょう！

APIの使い方を示す為、基本テンプレートを用意しました。これを出発点として利用出来ます。

このテンプレートは自由に、そして 積極的に 変更してください。機能を追加しても、構成を全面的に作り直してもかまいません。自分の進め方やアイデアに合うように工夫しましょう。

このテンプレートは、提出時にAPIへ送る次の3つの情報を用意します。

  • ユーザー名（Username）： Hugging Faceのユーザー名（ここではGradioログイン経由で取得）で、提出者を識別する為に使われます。
  • コードリンク（agent_code）： 提出内容を確認する為に使う、Hugging Face Spaceのソースコードを表示するURL（.../tree/main）です。Spaceは公開したままにしてください。
  • 回答（answers）： 採点の為にエージェントが生成した回答のリスト（{"task_id": ..., "submitted_answer": ...}）です。

まずは、このテンプレートを自分のHugging Faceアカウントに複製してみましょう。

リーダーボードはこちら

補足：このリーダーボードは、楽しみながら参加してもらう為のものです。スコアを十分に検証せずに投稿出来ることは承知しています。但し、裏付けとなる公開リンクの無い高スコアが多数投稿された場合は、リーダーボードを役立つものに保つ為、投稿内容の一部を確認・修正・削除することが有ります。 リーダーボードには、あなたのSpaceのソースコードへのリンクが表示されます。これは受講生向けのリーダーボードです。納得のいくスコアを獲得出来たら、Spaceは公開したままにしてください。
