GRPO は、別の価値モデル（Critic）を学習する代わりに、モデルが生成した応答を生成のグループ内で比較することで直接評価し、方策モデルを最適化します。このアプローチにより、計算コストが大幅に削減されます！

GRPO は、応答の正しさを判定できる、検証可能なあらゆるタスクに適用できます。たとえば数学の推論では、応答の正しさを正解と比較することで簡単に検証できます。

## GRPO アルゴリズム

GRPO の中核的な革新は、生成された複数の応答を同時に評価し、そこから学ぶアプローチです。別の報酬モデルに頼るのではなく、同じグループ内の出力を比較して、どれを強化すべきかを決定します。

アルゴリズムの各ステップを詳しく見ていきましょう。

### ステップ1： グループサンプリング

最初のステップは、各質問に対して複数の候補の答えを生成することです。これにより、互いに比較できる多様な出力の集合が作られます。

各質問 \\( q \\) に対して、モデルは、学習された方策から \\( G \\) 件の出力（グループサイズ）を生成します： { \\( {o_1, o_2, o_3, \dots, o_G}\pi_{\theta_{\text{old}}} \\) }。ここで \\( G=8 \\) とし、各 \\( o_i \\) はモデルからの1件の補完を表します。

#### 例

具体的にするために、簡単な算数の問題を見てみましょう。

**質問**

\\( q \\) : \\( \text{計算}\space2 + 2 \times 6 \\)

**出力**

\\( (G = 8) \\): \\( \{o_1:14 \text{ (正解)}, o_2:16 \text{ (不正解)}, o_3:10 \text{ (不正解)}, \ldots, o_8:14 \text{ (正解)}\} \\)

生成された答えの一部は正解（14）で、他は不正解（16 や 10）であることに注目してください。この多様性が、次のステップでは決定的に重要です。

### ステップ2： アドバンテージの計算

複数の応答が得られたら、どれが他より優れているかを決める方法が必要です。ここでアドバンテージの計算が登場します。

#### 報酬の分布

まず、生成された各応答に報酬スコアを割り当てます。この例では報酬モデルを使いますが、前のセクションで学んだとおり、報酬を返す任意の関数を使うこともできます。

正しさに基づいて、生成された各応答に RM スコア \\( r_i \\) を割り当てます *（例： 正しい応答には1、誤った応答には0）*。次に、各 \\( r_i \\) について、次のアドバンテージ値を計算します。

#### アドバンテージ値の式

GRPO の重要な洞察は、品質の絶対的な尺度は必要なく、同じグループ内の出力を比較できるということです。これは標準化によって行われます。

$$A_i = \frac{r_i - \text{mean}(\{r_1, r_2, \ldots, r_G\})}{\text{std}(\{r_1, r_2, \ldots, r_G\})}$$

#### 例

上記の算数の例を続けます。8件の応答があり、そのうち4件が正解で残りが不正解だと想像してください。すると次のようになります。

| 指標 | 値 |
|--------|-------|
| グループ平均 | \\( mean(r_i) = 0.5 \\) |
| 標準偏差 | \\( std(r_i) = 0.53 \\) |
| アドバンテージ値（正しい応答） | \\( A_i = \frac{1 - 0.5}{0.53}= 0.94 \\) |
| アドバンテージ値（誤った応答） | \\( A_i = \frac{0 - 0.5}{0.53}= -0.94 \\) |

#### 解釈

アドバンテージ値が計算できたところで、それが何を意味するかを理解しましょう。

この標準化（すなわち \\( A_i \\) による重み付け）により、モデルは各応答の相対的な性能を評価でき、最適化プロセスを、平均より優れた望ましい応答（高い報酬）へと導き、劣った応答を抑制します。たとえば、\\( A_i > 0 \\) であれば、その \\( o_i \\) はグループ内の平均水準より優れた応答です。\\( A_i < 0 \\) であれば、その応答の品質は平均未満（すなわち低品質／低性能）です。

上記の例では、\\( A_i = 0.94 \text{(正しい出力)} \\) であれば、最適化のステップ中にその生成確率が増加します。

アドバンテージ値が計算できたので、方策を更新する準備が整いました。

### ステップ3： 方策の更新

最後のステップは、これらのアドバンテージ値を使ってモデルを更新し、将来、良い応答を生成する可能性を高めることです。

方策更新の目的関数は次のとおりです。

$$J_{GRPO}(\theta) = \left[\frac{1}{G} \sum_{i=1}^{G} \min \left( \frac{\pi_{\theta}(o_i|q)}{\pi_{\theta_{old}}(o_i|q)} A_i \text{clip}\left( \frac{\pi_{\theta}(o_i|q)}{\pi_{\theta_{old}}(o_i|q)}, 1 - \epsilon, 1 + \epsilon \right) A_i \right)\right]- \beta D_{KL}(\pi_{\theta} \|\| \pi_{ref})$$

この式は一見すると威圧的に見えるかもしれませんが、それぞれ重要な目的を果たすいくつかの構成要素から成り立っています。一つずつ分解してみましょう。

## 目的関数の主要な構成要素

GRPO の更新関数は、安定して効果的な学習を保証するために、いくつかの手法を組み合わせています。各構成要素を調べていきましょう。

### 1. 確率比

確率比は次のように定義されます。

\\( \left(\frac{\pi_{\theta}(o_i|q)}{\pi_{\theta_{old}}(o_i|q)}\right) \\) 

直感的には、この式は、新しいモデルの応答確率が古いモデルの応答確率とどれだけ異なるかを比較し、期待される結果を改善する応答を優先する要素を組み込んでいます。

#### 解釈

- \\( \text{ratio} > 1 \\) であれば、新しいモデルは古いモデルよりも応答 \\( o_i \\) に高い確率を割り当てています。
- \\( \text{ratio} < 1 \\) であれば、新しいモデルは \\( o_i \\) に低い確率を割り当てています。

この比により、各ステップでモデルがどれだけ変化するかを制御できます。これが次の構成要素につながります。

### 2. クリップ関数

クリッピング関数は次のように定義されます。

\\( \text{clip}\left( \frac{\pi_{\theta}(o_i|q)}{\pi_{\theta_{old}}(o_i|q)}, 1 - \epsilon, 1 + \epsilon\right) \\) 

上記の比を \\( [1 - \epsilon, 1 + \epsilon] \\) の範囲内に制限することで、方策が古い方策から大きく離れすぎないようにします。言い換えれば、確率比がどれだけ増加できるかを制限し、新しいモデルを古いモデルから遠ざけすぎる更新を避けることで、安定性の維持を助けます。

#### 例（ε = 0.2）

このクリッピング関数をよりよく理解するために、2つの異なるシナリオを見てみましょう。

- **ケース1**： 新しい方策がある特定の応答に確率0.9を割り当て、古い方策が確率0.5を割り当てている場合、その応答は新しい方策によってより高い確率になるよう強化されています。ただし、その増加は制御された制限の範囲内に収まるよう、クリッピングによって抑えられます
	- \\( \text{Ratio}: \frac{\pi_{\theta}(o_i|q)}{\pi_{\theta_{old}}(o_i|q)} = \frac{0.9}{0.5} = 1.8  → \text{Clip}\space1.2 \\) （上限の1.2にクリップ）
- **ケース2**： 新しい方策がある応答を好まない場合（確率が0.2など低い場合）です。つまり、その応答が有益でないなら確率を増やすのは誤りであり、モデルはペナルティを受けます。
	- \\( \text{Ratio}: \frac{\pi_{\theta}(o_i|q)}{\pi_{\theta_{old}}(o_i|q)} = \frac{0.2}{0.5} = 0.4  →\text{Clip}\space0.8 \\) （下限の0.8にクリップ）

#### 解釈

- この式は、古いモデルが過小評価していた応答を、**結果を改善する場合に**、新しいモデルが優先するよう促します。
- 古いモデルがすでに高い確率で応答を優先していた場合、新しいモデルはそれを強化できますが、**制御された制限 \\( [1 - \epsilon, 1 + \epsilon] \\) の範囲内でのみ**可能です **\\( \text{(e.g., }\epsilon = 0.2, \space \text{so} \space [0.8-1.2]) \\)**。
- 古いモデルが性能の低い応答を過大評価していた場合、新しいモデルはその高い確率を維持することに**抑制**が働きます。
- したがって、直感的には、確率比を組み込むことで、目的関数は、方策への更新がアドバンテージ \\( A_i \\) に比例しつつ、急激な変化を防ぐよう調整されることを保証します。

クリッピング関数は急激な変化を防ぐ助けになりますが、モデルが元の振る舞いから乖離しすぎないようにする、もう一つの安全装置が必要です。

### 3. KL ダイバージェンス

KL ダイバージェンスの項は次のとおりです。

\\( \beta D_{KL}(\pi_{\theta} \|\| \pi_{ref}) \\)

KL ダイバージェンスの項において、\\( \pi_{ref} \\) は基本的に更新前のモデルの出力 `per_token_logps` であり、\\( \pi_{\theta} \\) は新しいモデルの出力 `new_per_token_logps` です。理論的には、KL ダイバージェンスは、最適化中にモデルが元の振る舞いから乖離しすぎることを防ぐために最小化されます。これは、報酬信号に基づいて性能を改善することと、一貫性を維持することのバランスを取る助けになります。この文脈では、KL ダイバージェンスを最小化することで、モデルが意味不明なテキストを生成したり、数学的推論の場合に極端に誤った答えを出したりするリスクを減らします。

#### 解釈

- KL ダイバージェンスのペナルティにより、モデルの出力は元の分布の近くに保たれ、極端な変化を防ぎます。
- 完全に非合理的な出力へ漂流する代わりに、モデルはある程度の探索を許しながら、理解を洗練させていきます

#### 数学的な定義

数学的な詳細に興味がある方のために、正式な定義を見てみましょう。

KL 距離は次のように定義されることを思い出してください。
$$D_{KL}(P \|\| Q) = \sum_{x \in X} P(x) \log \frac{P(x)}{Q(x)}$$
RLHF では、関心のある2つの分布は、多くの場合、新しいモデルバージョンの分布 P(x) と、参照方策の分布 Q(x) です。

#### β パラメータの役割

係数 \\( \beta \\) は、KL ダイバージェンスの制約をどれだけ強く強制するかを制御します。

-  **β が大きい（KL ペナルティが強い）**
    - 方策の更新に対する制約が強くなります。モデルは参照分布の近くにとどまります。
    - 適応が遅くなる可能性があります。モデルはより良い応答を探索するのに苦労するかもしれません。
- **β が小さい（KL ペナルティが弱い）**
    - 方策を更新する自由度が増します。モデルは参照からより大きく乖離できます。
    - 適応が速い反面、不安定になるリスクがあります。モデルが報酬ハッキング的な振る舞いを学習するかもしれません。
	- 過剰最適化のリスク： 報酬モデルに欠陥がある場合、方策が意味不明な出力を生成するかもしれません。
- **原論文** [DeepSeekMath](https://arxiv.org/abs/2402.03300) では、この \\( \beta= 0.04 \\) と設定されました

GRPO の構成要素を理解したところで、それらが完全な例の中でどう連動するかを見てみましょう。

## GRPO の具体例

GRPO の理解を固めるために、最初から最後まで完全な例を見ていきましょう。

### 問題例

$$\text{Q: 計算}\space2 + 2 \times 6$$

### ステップ1： グループサンプリング

まず、モデルから複数の応答を生成します。

\\( (G = 8) \\) 件の応答を生成します。そのうち \\( 4 \\) 件が正解（\\( 14, \text{reward=} 1 \\)）で、\\( 4 \\) 件が不正解 \\( \text{(reward= 0)} \\) です。したがって次のようになります。

$${o_1:14(正解), o_2:10 (不正解), o_3:16 (不正解), ... o_G:14(正解)}$$

### ステップ2： アドバンテージの計算

次に、どの応答が平均より優れているかを判断するために、アドバンテージ値を計算します。

| 統計量 | 値 |
|-----------|-------|
| グループ平均 | \\( mean(r_i) = 0.5 \\) |
| 標準偏差 | \\( std(r_i) = 0.53 \\) |
| アドバンテージ値（正しい応答） | \\( A_i = \frac{1 - 0.5}{0.53}= 0.94 \\) |
| アドバンテージ値（誤った応答） | \\( A_i = \frac{0 - 0.5}{0.53}= -0.94 \\) |

### ステップ3： 方策の更新

最後に、正しい応答を強化するようモデルを更新します。

- 正しい出力 \\( o_1 \\) に対する古い方策（\\( \pi_{\theta_{old}} \\)）の確率が \\( 0.5 \\) で、新しい方策で \\( 0.7 \\) に増加したとします。すると次のようになります。
$$\text{Ratio}: \frac{0.7}{0.5} = 1.4  →\text{after Clip}\space1.2 \space (\epsilon = 0.2)$$
- その後、目的関数が再び重み付けされると、モデルは正しい出力の生成を強化する傾向を持ち、\\( \text{KL Divergence} \\) が参照方策からの乖離を制限します。

理論的な理解が得られたところで、GRPO がコードでどう実装できるかを見てみましょう。

## 実装例

実践的な例として、すべてをまとめましょう。次のコードは、PyTorch で GRPO を実装する方法を示しています。

### 1. モデルの読み込みと応答の生成

まず、モデルを読み込み、与えられた質問に対して複数の応答を生成する必要があります。

```python
import torch
import torch.nn.functional as F
from transformers import AutoModelForCausalLM, AutoTokenizer

# モデルとトークナイザを読み込む
model_name = "Qwen/Qwen2-Math-1.5B"
model = AutoModelForCausalLM.from_pretrained(model_name)
tokenizer = AutoTokenizer.from_pretrained(model_name)
model.eval()

# 利用可能ならモデルを GPU に移動する
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model.to(device)

# 入力プロンプト
prompt = "Solve y = 2x + 1 for x = 2, y = "  # 正解: 5
inputs = tokenizer(prompt, return_tensors="pt", padding=True)
input_ids = inputs["input_ids"].to(device)  # 形状: (1, prompt_len)
attention_mask = inputs["attention_mask"].to(device)

# ステップ1: 8件の応答を生成する（B = 2グループ、G = グループあたり4件の応答）
batch_size, num_generations = 2, 4
outputs = model.generate(
    input_ids=input_ids,  # 形状: (1, prompt_len)
    attention_mask=attention_mask,
    max_new_tokens=1,  # seq_len = 1（応答あたり1トークン）
    num_return_sequences=batch_size * num_generations,  # 合計8件の応答
    do_sample=True,
    top_k=10,
    temperature=0.7,
    pad_token_id=tokenizer.eos_token_id,
    return_dict_in_generate=True,
    output_scores=True,
)
```

この初期生成（ステップ実行前）は、次のような出力を返します。

```text
Output 1: 5.0
Output 2: 6.0
Output 3: 7.0
Output 4: 5.0
Output 5: 10.0
Output 6: 2.0
Output 7: 5.0
Output 8: 5.0
```

### 2. 報酬の計算

次に、どの応答が正しいかを判断し、それに応じた報酬を割り当てる必要があります。

GRPO では、同じサンプルプロンプトに対して、複数の補完を生成します。たとえば、`"Solve y = 2x + 1 for x = 2, y = "` と `Solve y = 2x + 1 for x = 4, y = "` というプロンプトに対して、与えられたプロンプトごとの生成出力のグループが2つあるとします。一つは
- `[5, 6, 7, 5]` で、もう一つは
- `[10, 2, 9, 9]` で、正解は5と9です。

なお、実際にはこれらの報酬スコアは、応答の正しさに基づいて報酬を割り当てるルールベースの報酬関数、あるいは応答の正しさに基づいて報酬を割り当てるよう学習できるより複雑なニューラルネットワークベースのモデル、またはその両方の混合によって得られます。しかし、簡単のため、ここでは応答が正しければ報酬を1、誤っていれば0とします。したがって次のようになります。
```python
reward_1 = [1, 0, 0, 1]
reward_2 = [0, 0, 1, 1]
```
次に、報酬のグループごとの平均と標準偏差を求めます。

```python
# 形状: (B * G,) = (8,)。4件の生成からなるグループが2つあり、それらを平坦化するため
rewards = torch.tensor([1, 0, 0, 1, 0, 0, 1, 1], dtype=torch.float32)
num_generations = 4

# グループ化した報酬: 形状 (B, G) = (2, 4)
rewards_grouped = rewards.view(-1, num_generations)

# グループごとの平均: 形状 (B,) = (2,)
mean_grouped_rewards = rewards_grouped.mean(dim=1)

# グループごとの標準偏差: 形状 (B,) = (2,)
std_grouped_rewards = rewards_grouped.std(dim=1)

# 報酬に合わせてブロードキャストし、正規化する: 形状 (B * G,) = (8,)
# なぜブロードキャストが必要か？ グループ内の各応答のアドバンテージ値を計算する必要があるため
mean_grouped_rewards = mean_grouped_rewards.repeat_interleave(num_generations, dim=0)
std_grouped_rewards = std_grouped_rewards.repeat_interleave(num_generations, dim=0)
```
出力は次のようになります。
```text
グループ化した報酬: tensor([[1., 0., 0., 1.],
                        [0., 0., 1., 1.]])
グループごとの平均: tensor([0.5000, 0.5000])
グループごとの標準偏差: tensor([0.5774, 0.5774])
ブロードキャストした平均: tensor([0.5000, 0.5000, 0.5000, 0.5000, 0.5000, 0.5000, 0.5000, 0.5000])
ブロードキャストした標準偏差: tensor([0.5774, 0.5774, 0.5774, 0.5774, 0.5774, 0.5774, 0.5774, 0.5774])
```
これで、各応答のアドバンテージ値を計算できます。
```python
# アドバンテージ: 形状 (B * G,) = (8,)
advantages = (rewards - mean_grouped_rewards) / (std_grouped_rewards + 1e-8)
```
出力は次のようになります。
```text
アドバンテージ: tensor([ 0.8659, -0.8660, -0.8660,  0.8659, -0.8660, -0.8660,  0.8659,  0.8659])
```
これは上記のアドバンテージの式から来ています。つまり次のとおりです。
```text
reward_1 = [1, 0, 0, 1] の場合:
1 - 0.5 / 0.5774 ≈ 0.8659
0 - 0.5 / 0.5774 ≈ -0.8660
reward_2 = [0, 0, 1, 1] の場合: 同様に計算できます。
```
ただし、ここの形状は `(B*G,) = (8,)` ですが、実際にはロジットの形状に合わせるために `(B, G) = (2, 4)` の形状が必要です。そのため、ロジットの形状に合わせて、アドバンテージのテンソルを `(B*G, 1) = (8, 1)` の形状に unsqueeze する必要があります。
```python
# ロジットの形状に合わせるため、形状 (B * G, 1) = (8, 1)
advantages = advantages.unsqueeze(1)
```
出力は次のようになります。
```text
アドバンテージ: tensor([[ 0.8659],
                    [-0.8660],
                    [-0.8660],
                    [ 0.8659],
                    [-0.8660],
                    [-0.8660],
                    [ 0.8659],
                    [ 0.8659]])
```
これで準備ができました。アドバンテージ値に基づいて方策モデルを更新する次のステップに進みましょう。

### 3. 方策の更新
最後に、アドバンテージ値を使ってモデルを更新します。

```python
# 新しい方策と古い方策の間の確率比を計算する
ratio = torch.exp(
    new_per_token_logps - per_token_logps
)  # 形状: (B*G, seq_len)。seq_len は出力の長さ、すなわち生成されたトークンの数。ここでは簡単のため 1 と仮定する # (8, 1)
```

なお、`per_token_logps` は、生成された出力をモデルに渡してロジットを取得し、softmax 関数 `F.softmax(logits, dim=-1)` を適用して確率を得ることで取得できます。

```python
# クリッピング関数
eps = self.cliprange  # 例: 0.2
pg_losses1 = -advantages * ratio  # 形状: (B*G, seq_len)  #(8, 1)
pg_losses2 = -advantages * torch.clamp(
    ratio, 1.0 - eps, 1.0 + eps
)  # 形状: (B*G, seq_len) #(8, 1)
pg_loss_max = torch.max(pg_losses1, pg_losses2)  # 形状: (B*G, seq_len) #(8, 1)


# KL ペナルティと組み合わせる # 形状: (B*G, seq_len) #(8, 1)
per_token_loss = pg_loss_max + self.beta * per_token_kl
```

`per_token_kl` は、次のように計算することもできます。

```python
# 形状: (B*G, seq_len) #(8, 1)
per_token_kl = F.kl_div(
    F.log_softmax(new_per_token_logps, dim=-1),
    F.softmax(per_token_logps, dim=-1),
    reduction="none",
).sum(dim=-1, keepdim=True)
```

完全な例は[こちら](./basic_example.py)にあります。GRPO は優れた TRL チームによっても実装されています。詳細は [TRL/GRPO_trainer](https://github.com/huggingface/trl/blob/main/trl/trainer/grpo_trainer.py) の実装をチェックしてください。

## まとめと次のステップ

おめでとうございます！Group Relative Policy Optimization（GRPO）について学びました。ここまでで扱った内容を振り返りましょう。

1. GRPO は、別の価値モデルを必要とせずに、グループ内の複数の出力を比較して、どれが他より優れているかを判断します。
2. アドバンテージの計算では、報酬を標準化して、どの応答が平均以上か平均以下かを特定します。
3. 方策の更新では、クリッピングされた目的関数と KL ダイバージェンスのペナルティを使い、安定した学習を保証します。

このアプローチは、正しさを客観的に検証できる数学的推論タスクで特に強力です。GRPO の手法は、別の Critic モデルを必要とする従来の RLHF アプローチと比べて、より効率的な学習を可能にします。

GRPO の探求を続ける際は、異なるグループサイズ、報酬関数、KL ペナルティの係数を試して、それらがモデルの性能にどう影響するかを確認してみてください。
