学習曲線を理解する

Trainer API とカスタム学習ループを使ったファインチューニングの方法を学んだので、次はその結果の読み取り方を見ていきましょう。学習曲線は、学習中のモデルの性能を評価したり、性能が低下する前に問題の兆候を見つけたりするのに役立つツールです。

このセクションでは、正解率曲線と損失曲線の読み取り方、曲線の形からモデルの振る舞いをどう判断するか、そして学習中によく起こる問題への対処法を学びます。

学習曲線とは

学習曲線は、学習中のモデルの性能指標を時間の経過と共に可視化したものです。監視すべき最も重要な曲線は次の2つです。

  • 損失曲線：学習ステップやエポックごとに、モデルの誤差（損失）がどう変化するかを示します
  • 正解率曲線：学習ステップやエポックごとに、正しく予測出来た割合を示します

これらの曲線を見ると、モデルが順調に学習しているかどうかを判断出来、性能を改善する為の調整にも役立ちます。Transformers では、こうした指標をバッチごとに計算し、ディスクにログとして記録します。その後、Weights & Biases のようなライブラリを使って曲線を可視化すれば、学習中のモデルの性能がどう変化しているかを確認出来ます。

損失曲線

損失曲線は、モデルの誤差が時間と共にどう減少するかを示します。学習がうまくいった場合の典型的な例では、下のような曲線が見られます。

  • 初期の損失が高い：モデルは最適化されていない状態から始まる為、最初のうちは予測がよくありません
  • 損失の減少：学習が進むにつれて、損失は概ね減少していくはずです
  • 収束：やがて損失は低い値で安定し、モデルがデータのパターンを学習したことを示します

前の章と同様に、Trainer API を使ってこれらの指標を追跡し、ダッシュボードで可視化出来ます。以下は Weights & Biases でそれを行う例です。

# Trainer で学習中の損失を追跡する例
from transformers import Trainer, TrainingArguments
import wandb

# 実験追跡のために Weights & Biases を初期化
wandb.init(project="transformer-fine-tuning", name="bert-mrpc-analysis")

training_args = TrainingArguments(
    output_dir="./results",
    eval_strategy="steps",
    eval_steps=50,
    save_steps=100,
    logging_steps=10,  # 10ステップごとに指標をログに記録
    num_train_epochs=3,
    per_device_train_batch_size=16,
    per_device_eval_batch_size=16,
    report_to="wandb",  # ログを Weights & Biases に送信
)

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    data_collator=data_collator,
    processing_class=tokenizer,
    compute_metrics=compute_metrics,
)

# 学習し、指標を自動でログに記録
trainer.train()

正解率曲線

正解率曲線は、時間の経過に伴う正しい予測の割合を示します。損失曲線とは異なり、正解率曲線はモデルが学習するにつれて概ね上昇し、通常は損失曲線よりも多くのステップを含みます。

  • 低く始まる：モデルはまだデータのパターンを学習していない為、初期の正解率は低いはずです
  • 学習と共に上昇：モデルがデータのパターンを学習出来るなら、正解率は学習が進むにつれて概ね向上するはずです
  • 横ばいの部分（プラトー）が現れることが有る：正解率は滑らかに上昇するのではなく、階段状に上昇することがよくあります。これは、モデルの予測が正解のラベルに近づいていく過程で起こります

💡 ヒント

正解率曲線が「階段状」になる理由：連続的な損失とは異なり、正解率は離散的な予測と真のラベルを比較して計算されます。モデルの確信度の小さな改善では最終的な予測が変わらないことがあり、しきい値を超えるまで正解率は横ばいのままになります。

収束

収束とは、モデルの性能が安定し、損失曲線と正解率曲線が横ばいになることです。これは、モデルがデータのパターンを学習し、使用出来る状態になった兆候です。簡単に言えば、学習のたびにモデルの性能が安定することを目指します。

モデルが収束したら、新しいデータに対して予測を行い、評価指標を使ってモデルの性能を確かめられます。

学習曲線のパターンを解釈する

曲線の形の違いからは、モデルの学習における様々な側面が分かります。最も一般的なパターンとその意味を見ていきましょう。

健全な学習曲線

うまくいった学習では、通常、下のような形の曲線が見られます。

上の図を見てみましょう。損失曲線（左）とそれに対応する正解率曲線（右）の両方が描かれています。これらの曲線にはそれぞれ異なる特徴があります。

損失曲線は、モデルの損失が時間と共にどう変化するかを示します。最初は損失が大きく、学習が進むにつれて徐々に減少します。これは、モデルの性能が改善していることを示します。損失は予測値と正解値の間の誤差を表す為、損失が減る程、モデルがより正確な予測を行っていると考えられます。

次に正解率曲線に目を向けましょう。これは時間の経過に伴うモデルの正解率を表します。正解率曲線は低い値から始まり、学習が進むにつれて上昇します。正解率は、正しく分類された事例の割合を測るものです。従って、正解率曲線の上昇は、モデルがより多くの正しい予測を行っていることを意味します。

2つの曲線の大きな違いは、損失曲線が滑らかに減少するのに対し、正解率曲線には横ばいになる部分（プラトー）が現れることです。正解率は連続的に増えるのではなく、階段状に上昇します。これは、正解率の計算方法によるものです。損失は、最終的な予測がまだ間違っていても、モデルの出力が正解値に近づけば減少します。一方、正解率が上がるのは、予測が正解となるしきい値を超えた時だけです。

例えば、猫（0）と犬（1）を区別する二値分類器で、モデルが犬の画像（真の値は1）に対して 0.3 と予測した場合、これは 0 に丸められ、不正解の分類となります。次のステップで 0.4 と予測しても、まだ不正解です。0.4 は 0.3 よりも 1 に近いため損失は減少していますが、正解率は変わらず、プラトーが生まれます。正解率がジャンプするのは、モデルが 0.5 より大きな値を予測し、それが 1 に丸められる時だけです。

💡 ヒント

健全な曲線の特徴： - 損失の滑らかな低下：学習損失と検証損失の両方が着実に減少する - 学習データと検証データでの性能が近い：両方のデータで計算した評価指標の差が小さい - 収束：曲線が横ばいになり、モデルがパターンを学習したことを示す

実践例

学習曲線の実践例をいくつか見ていきましょう。まず、学習中に曲線を確認する方法を紹介し、その後、曲線に現れる様々なパターンを詳しく説明します。

学習中

学習中（trainer.train() を実行している間）は、次の主な指標を確認出来ます。

  1. 損失の収束：損失はまだ減少していますか、それとも横ばいですか？
  2. 過学習の兆候：学習損失が減少する一方で、検証損失が増え始めていませんか？
  3. 学習率：曲線が激しく変動していませんか（学習率が高過ぎる可能性）？ あるいは、殆ど変化していませんか（学習率が低過ぎる可能性）？
  4. 安定性：問題を示す急なスパイクや落ち込みはありませんか？

学習後

学習プロセスが完了したら、曲線全体を分析してモデルの性能を把握出来ます。

  1. 最終性能：モデルは許容出来る性能レベルに到達しましたか？
  2. 効率：より少ないエポックでも同じ性能を達成出来たでしょうか？
  3. 汎化：学習性能と検証性能はどの程度近いですか？
  4. 傾向：追加の学習で性能が改善しそうですか？

💡 ヒント

W&B ダッシュボードの機能：Weights & Biases は、見やすく、操作も出来る学習曲線のグラフを自動で作成します。次のことが出来ます。 - 複数の実行を並べて比較する - カスタム指標と可視化を追加する
- 異常な振る舞いに対するアラートを設定する - 結果をチームと共有する

詳しくは Weights & Biases のドキュメント を参照してください。

過学習

過学習は、モデルが学習データに過度に適合し、検証データなどの学習に使っていないデータに対して、うまく予測出来なくなる現象です。

症状：

  • 学習損失が減少し続ける一方で、検証損失が増加するか横ばいになる
  • 学習正解率と検証正解率の差が大きい
  • 学習正解率が検証正解率よりはるかに高い

過学習への対処法： - 正則化：ドロップアウト、重み減衰、その他の正則化手法を追加する - 早期終了：検証性能の改善が止まったら学習を止める - データ拡張：学習データの多様性を増やす - モデルの複雑さを下げる：より小さいモデルを使うか、パラメータ数を減らす

下のサンプルでは、過学習を防ぐ為に早期終了を使います。early_stopping_patience を 3 に設定しています。これは、検証損失が3エポック連続で改善しなければ、学習が停止されるという意味です。

# 早期終了で過学習を検出する例
from transformers import EarlyStoppingCallback

training_args = TrainingArguments(
    output_dir="./results",
    eval_strategy="steps",
    eval_steps=100,
    save_strategy="steps",
    save_steps=100,
    load_best_model_at_end=True,
    metric_for_best_model="eval_loss",
    greater_is_better=False,
    num_train_epochs=10,  # 大きく設定するが、早期に停止する
)

# 過学習を防ぐために早期終了を追加
trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    data_collator=data_collator,
    processing_class=tokenizer,
    compute_metrics=compute_metrics,
    callbacks=[EarlyStoppingCallback(early_stopping_patience=3)],
)

2. 過小適合

過小適合は、モデルが単純過ぎて、データに含まれるパターンを捉えられない時に起こります。これにはいくつかの原因があります。

  • モデルが小さ過ぎるか、パターンを学習する能力が不足している
  • 学習率が低過ぎて、学習が遅い
  • データセットが小さ過ぎるか、解こうとしている問題の特徴を十分に反映していない
  • モデルが適切に正則化されていない

症状： - 学習損失と検証損失の両方が高いまま - モデルの性能が学習の早い段階で横ばいになる - 学習正解率が期待より低い

過小適合への対処法： - モデルの表現能力を高める：より大きいモデルを使うか、パラメータ数を増やす - 長く学習する：エポック数を増やす - 学習率を調整する：異なる学習率を試す - データ品質を確認する：データが適切に前処理されているか確認する

下のサンプルでは、モデルがデータのパターンを学習出来るか確認する為に、より多くのエポックで学習します。

from transformers import TrainingArguments

training_args = TrainingArguments(
    output_dir="./results",
    -num_train_epochs=5,
    +num_train_epochs=10,
)

3. 乱れた学習曲線

乱れた学習曲線は、モデルが効果的に学習出来ていない時に現れます。これにはいくつかの原因があります。

  • 学習率が高過ぎて、パラメータを更新する時に最適値を飛び越えてしまう
  • バッチサイズが小さ過ぎて、モデルの学習が遅い
  • モデルが適切に正則化されておらず、学習データに過学習してしまう
  • データセットが適切に前処理されておらず、モデルがノイズを学習してしまう

症状： - 損失や正解率の頻繁な変動 - 曲線のばらつきが大きいか、不規則に変動する - 性能が一定の傾向を示さず、上下を繰り返す

学習データと検証データの両方の曲線に、不安定な変動が見られます。

乱れた曲線への対処法： - 学習率を下げる：ステップサイズを小さくして学習を安定させる - バッチサイズを増やす：より大きなバッチを使って勾配のばらつきを抑える - 勾配クリッピング：勾配爆発を防ぐ - データ前処理の改善：一貫したデータ品質を確保する

下のサンプルでは、学習率を下げ、バッチサイズを増やします。

from transformers import TrainingArguments

training_args = TrainingArguments(
    output_dir="./results",
    -learning_rate=1e-5,
    +learning_rate=1e-4,
    -per_device_train_batch_size=16,
    +per_device_train_batch_size=32,
)

要点

機械学習を効果的に実践するには、学習曲線を理解することが欠かせません。学習曲線を見ると、モデルの学習がどこまで進んでいるかを直ぐに確認出来、いつ学習を止めるか、ハイパーパラメータをどう調整するか、別の方法を試すべきかといった判断に役立ちます。練習を重ねるうちに、順調な学習曲線がどのような形になるか、問題が起きた時にどう対処すればよいかを直感的に理解出来るようになります。

💡 ヒント

要点： - 学習曲線は、モデルの学習進捗を理解する為の不可欠なツールです - 損失曲線と正解率曲線の両方を監視してください。但し、両者には異なる特徴があることを忘れないでください - 過学習は、学習性能と検証性能が乖離していく形で現れます - 過小適合では、学習データと検証データの両方で性能が低くなります - Weights & Biases のようなツールを使えば、学習曲線の追跡と分析が簡単になります - 早期終了と適切な正則化で、よくある学習の問題の殆どに対処出来ます

次のステップ：自分でファインチューニングを行い、学習曲線を分析してみましょう。異なるハイパーパラメータを試し、曲線の形がどう変わるか観察してください。こうした実践を重ねることが、学習の進み具合を直感的に読み取る力を身につける最良の方法です。

セクションクイズ

学習曲線の読み方と、学習状況の分析について理解度を確認しましょう。

1. 学習損失が減少しているのに検証損失が増え始めた場合、それは通常何を意味しますか？

学習損失が減少する一方で検証損失が増加している場合、これは成功ではなく、問題が起きていることを示しています。
正解です！これは過学習の典型的な兆候です。モデルは学習データではよい性能を示しますが、未知の検証データでは性能が悪くなります。
学習率が低いと学習が遅くなりますが、学習性能と検証性能の乖離は生じません。
小さいデータセットが過学習の一因になることはありますが、この特定のパターン自体が、データセットのサイズによらず過学習の定義そのものです。

2. 正解率曲線が滑らかに上昇せず、「階段状」やプラトーのようなパターンを示すことが多いのはなぜですか？

階段状のパターンは正常で想定内のものであり、誤りではありません。
正解です！損失とは異なり、正解率は予測が正しいかどうかで決まります。そのため、モデルの確信度が少し高まっても、予測がしきい値を超えて変わらない限り、正解率は変わらないことがあります。
モデルが順調に学習しているときでも、階段状の正解率曲線は正常です。
バッチサイズは学習の安定性に影響しますが、正解率という指標が本質的に離散的であることの説明にはなりません。

3. 乱れて大きく変動する学習曲線が観察された場合、最善のアプローチはどれですか？

学習率を上げると、変動はおそらく更に悪化します。
正解です！低い学習率と大きなバッチサイズは、通常、より安定した学習につながります。
乱れた曲線は、ハイパーパラメータの調整で直せることがよくあります。
それは時期尚早です。乱れた曲線は通常、ハイパーパラメータの調整で直せます。

4. 早期終了の使用を検討すべきなのはどのような場合ですか？

早期終了は有用ですが、常に必要とは限りません。特に、他の正則化手法がうまく機能している場合は、早期終了を使わなくてもよいことがあります。
正解です！早期終了は、モデルの汎化性能がそれ以上改善しなくなった時点で学習を止めることで、過学習を防ぐのに役立ちます。
学習損失が急速に減少し、検証性能もよければ、学習を続けたほうがよい場合があります。
早期終了は有用な手法であり、過学習を防ぐことで最終的なモデルの性能を改善することがよくあります。

5. モデルが過小適合している可能性を示すのはどれですか？

これは過小適合ではなく、過学習を表しています。
正解です！過小適合は、モデルにパターンを学習する能力が不足しているときに起こり、学習データと検証データの両方で性能が悪くなります。
滑らかな曲線は一般によいものであり、過小適合を示すものではありません。
これは実際にはよい兆候であり、問題ではありません。
