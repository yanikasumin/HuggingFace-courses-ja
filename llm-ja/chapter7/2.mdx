最初に取り上げる応用はトークン分類です。この汎用的なタスクは、「文中の各トークンにラベルを割り当てる」問題として定式化できるものすべてを包含します。例として次のようなものがあります。

- **固有表現認識（NER）**: 文中のエンティティ（人名、地名、組織名など）を見つけます。エンティティの種類ごとに1つのクラスと、「エンティティではない」場合の1つのクラスを用意することで、各トークンへのラベル割り当てとして定式化できます。
- **品詞タグ付け（POS）**: 文中の各単語が、特定の品詞（名詞、動詞、形容詞など）のどれに対応するかを付けます。
- **チャンキング**: 同じエンティティに属するトークンを見つけます。このタスクは（POS や NER と組み合わせることもできます）、通常、チャンクの先頭にあるトークンには1つのラベル（通常は `B-`）、チャンクの内部にあるトークンには別のラベル（通常は `I-`）、どのチャンクにも属さないトークンには3つ目のラベル（通常は `O`）を割り当てる形で定式化できます。

## データの準備[[preparing-the-data]]

まず何よりも、トークン分類に適したデータセットが必要です。このセクションでは、Reuters のニュース記事を含む [CoNLL-2003 データセット](https://huggingface.co/datasets/conll2003)を使います。

> [!TIP]
> 💡 データセットが、対応するラベルとともに単語に分割されたテキストで構成されている限り、ここで説明するデータ処理の手順を自分のデータセットにも適用できます。`Dataset` に独自のカスタムデータを読み込む方法を復習したい場合は、[Chapter 5](/course/chapter5)を参照してください。

### データの処理[[processing-the-data]]

<Youtube id="iY2AZYdZAr0"/>

通常どおり、テキストは、モデルが理解できるようトークン ID に変換する必要があります。[Chapter 6](/course/chapter6/) で見たように、トークン分類タスクの場合に大きく異なるのは、入力が事前にトークン化されていることです。幸い、トークナイザ API はこれに簡単に対応できます。特別なフラグで `tokenizer` に知らせるだけです。

まず、`tokenizer` オブジェクトを作成しましょう。先に述べたように BERT の事前学習済みモデルを使うので、関連するトークナイザをダウンロードしてキャッシュすることから始めます。

```python
from transformers import AutoTokenizer

model_checkpoint = "bert-base-cased"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint)
```

`model_checkpoint` は、[Hub](https://huggingface.co/models) にある好みのモデルに置き換えることも、事前学習済みモデルとトークナイザを保存したローカルフォルダに置き換えることもできます。唯一の制約は、トークナイザが 🤗 Tokenizers ライブラリに支えられていて、高速バージョンが利用できることです。高速バージョンを持つすべてのアーキテクチャは、[この大きな表](https://huggingface.co/transformers/#supported-frameworks)で確認できます。使用している `tokenizer` オブジェクトが本当に 🤗 Tokenizers に支えられているかどうかは、その `is_fast` 属性を見れば確認できます。

```py
tokenizer.is_fast
```

```python out
True
```

事前にトークン化された入力をトークン化するには、通常どおり `tokenizer` を使い、`is_split_into_words=True` を追加するだけです。

```py
inputs = tokenizer(raw_datasets["train"][0]["tokens"], is_split_into_words=True)
inputs.tokens()
```

```python out
['[CLS]', 'EU', 'rejects', 'German', 'call', 'to', 'boycott', 'British', 'la', '##mb', '.', '[SEP]']
```

見てのとおり、トークナイザはモデルが使う特殊トークン（先頭の `[CLS]` と末尾の `[SEP]`）を追加し、ほとんどの単語はそのままにしました。ただし、単語 `lamb` は2つのサブワード、`la` と `##mb` にトークン化されました。これにより、入力とラベルの間に不一致が生じます。ラベルのリストは9要素しかないのに、入力は12トークンになっています。特殊トークンへの対応は簡単です（先頭と末尾にあることが分かっているため）。しかし、すべてのラベルが適切な単語に対応するよう揃える必要もあります。

幸い、高速トークナイザを使っているため、🤗 Tokenizers の強力な機能を利用できます。つまり、各トークンを対応する単語へ簡単にマッピングできます（[Chapter 6](/course/chapter6/3) で見たとおりです）。

```py
inputs.word_ids()
```

```python out
[None, 0, 1, 2, 3, 4, 5, 6, 7, 7, 8, None]
```

少し作業すれば、ラベルのリストをトークンに合わせて拡張できます。適用する1つ目のルールは、特殊トークンに `-100` というラベルを付けることです。これは、デフォルトでは `-100` が、使用する損失関数（交差エントロピー）で無視されるインデックスだからです。次に、各トークンには、それが含まれる単語を開始したトークンと同じラベルを付けます。同じエンティティの一部だからです。単語の内部にあって先頭ではないトークンについては、`B-` を `I-` に置き換えます（そのトークンはエンティティを開始しないため）。

```python
def align_labels_with_tokens(labels, word_ids):
    new_labels = []
    current_word = None
    for word_id in word_ids:
        if word_id != current_word:
            # 新しい単語の先頭
            current_word = word_id
            label = -100 if word_id is None else labels[word_id]
            new_labels.append(label)
        elif word_id is None:
            # 特殊トークン
            new_labels.append(-100)
        else:
            # 前のトークンと同じ単語
            label = labels[word_id]
            # ラベルが B-XXX なら I-XXX に変更する
            if label % 2 == 1:
                label += 1
            new_labels.append(label)

    return new_labels
```

最初の文で試してみましょう。

```py
labels = raw_datasets["train"][0]["ner_tags"]
word_ids = inputs.word_ids()
print(labels)
print(align_labels_with_tokens(labels, word_ids))
```

```python out
[3, 0, 7, 0, 0, 0, 7, 0, 0]
[-100, 3, 0, 7, 0, 0, 0, 7, 0, 0, 0, -100]
```

見てのとおり、この関数は、先頭と末尾の2つの特殊トークンに `-100` を追加し、2つのトークンに分割された単語のために新しい `0` を追加しました。

> [!TIP]
> ✏️ **試してみましょう！** 一部の研究者は、単語ごとに1つのラベルだけを割り当て、ある単語に属する他のサブトークンには `-100` を割り当てることを好みます。これは、多くのサブトークンに分割される長い単語が損失に大きく寄与するのを避けるためです。このルールに従い、先ほどの関数を変更して、ラベルを入力 ID に揃えるようにしてください。

データセット全体を前処理するには、すべての入力をトークン化し、すべてのラベルに `align_labels_with_tokens()` を適用する必要があります。高速トークナイザの速度を活かすには、多数のテキストを同時にトークン化するのが最適です。そこで、サンプルのリストを処理する関数を書き、`batched=True` オプションを指定して `Dataset.map()` メソッドを使います。前の例と唯一異なる点は、トークナイザへの入力がテキストのリスト（この場合は単語のリストのリスト）の場合、`word_ids()` 関数に、単語 ID が欲しいサンプルのインデックスを渡す必要があることです。そのため、それも追加しています。

```py
def tokenize_and_align_labels(examples):
    tokenized_inputs = tokenizer(
        examples["tokens"], truncation=True, is_split_into_words=True
    )
    all_labels = examples["ner_tags"]
    new_labels = []
    for i, labels in enumerate(all_labels):
        word_ids = tokenized_inputs.word_ids(i)
        new_labels.append(align_labels_with_tokens(labels, word_ids))

    tokenized_inputs["labels"] = new_labels
    return tokenized_inputs
```

入力へのパディングはまだ行っていません。バッチを作成するときにデータコレータで行います。

これで、データセットの他の分割に対しても、すべての前処理を一度に適用できます。

```py
tokenized_datasets = raw_datasets.map(
    tokenize_and_align_labels,
    batched=True,
    remove_columns=raw_datasets["train"].column_names,
)
```

一番大変な部分は終わりました！データの前処理が済んだので、実際の学習は [Chapter 3](/course/chapter3) で行ったことと非常によく似たものになります。

### モデルの定義[[defining-the-model]]

トークン分類の問題を扱っているので、`TFAutoModelForTokenClassification` クラスを使います。このモデルを定義する際に覚えておくべき主な点は、ラベルの数に関する情報を渡すことです。最も簡単な方法は、`num_labels` 引数でその数を渡すことですが、このセクションの冒頭で見たような立派な推論ウィジェットを機能させたい場合は、正しいラベルの対応を設定する方がよいでしょう。

ラベルの対応は、2つの辞書 `id2label` と `label2id` で設定します。これらには、ID からラベルへのマッピングと、その逆のマッピングが含まれます。

```py
id2label = {i: label for i, label in enumerate(label_names)}
label2id = {v: k for k, v in id2label.items()}
```

これで、これらを `TFAutoModelForTokenClassification.from_pretrained()` メソッドに渡すことができ、モデルの設定に組み込まれて、適切に保存され Hub にアップロードされます。

```py
from transformers import TFAutoModelForTokenClassification

model = TFAutoModelForTokenClassification.from_pretrained(
    model_checkpoint,
    id2label=id2label,
    label2id=label2id,
)
```

ログイン後、モデルをコンパイルするために必要なものをすべて準備できます。🤗 Transformers には便利な `create_optimizer()` 関数があり、重み減衰と学習率減衰の適切な設定を備えた `AdamW` オプティマイザが得られます。どちらも、組み込みの `Adam` オプティマイザと比べてモデルの性能を向上させます。

```python
from transformers import create_optimizer
import tensorflow as tf

# これによる恩恵を受けない GPU を使っている場合は、この行をコメントアウトする
tf.keras.mixed_precision.set_global_policy("mixed_float16")

# 学習ステップ数は、データセットのサンプル数をバッチサイズで割ってから、
# 総エポック数を掛けたもの。ここでの tf_train_dataset はバッチ化済みの tf.data.Dataset であり、
# 元の Hugging Face の Dataset ではないため、その len() はすでに num_samples // batch_size になっている。
num_epochs = 3
num_train_steps = len(tf_train_dataset) * num_epochs

optimizer, schedule = create_optimizer(
    init_lr=2e-5,
    num_warmup_steps=0,
    num_train_steps=num_train_steps,
    weight_decay_rate=0.01,
)
model.compile(optimizer=optimizer)
```

`compile()` に `loss` 引数を渡していないことにも注意してください。これは、モデルが内部で損失を計算できるためです。損失なしでコンパイルし、入力辞書の中にラベルを含めて渡す（データセットでもそのようにしています）と、モデルはその内部損失を使って学習します。この損失は、選択したタスクとモデルの種類に適したものになります。

次に、学習中にモデルを Hub にアップロードする `PushToHubCallback` を定義し、そのコールバックでモデルを fit します。

```python
from transformers.keras_callbacks import PushToHubCallback

callback = PushToHubCallback(output_dir="bert-finetuned-ner", tokenizer=tokenizer)

model.fit(
    tf_train_dataset,
    validation_data=tf_eval_dataset,
    callbacks=[callback],
    epochs=num_epochs,
)
```

```py
import numpy as np


def compute_metrics(eval_preds):
    logits, labels = eval_preds
    predictions = np.argmax(logits, axis=-1)

    # 無視されるインデックス（特殊トークン）を取り除き、ラベルに変換する
    true_labels = [[label_names[l] for l in label if l != -100] for label in labels]

        [label_names[p] for (p, l) in zip(prediction, label) if l != -100]
        for prediction, label in zip(predictions, labels)
    ]
    all_metrics = metric.compute(predictions=true_predictions, references=true_labels)
    return {
        "precision": all_metrics["overall_precision"],
        "recall": all_metrics["overall_recall"],
        "f1": all_metrics["overall_f1"],
        "accuracy": all_metrics["overall_accuracy"],
    }
```

### モデルの定義[[defining-the-model]]

トークン分類の問題を扱っているので、`AutoModelForTokenClassification` クラスを使います。このモデルを定義する際に覚えておくべき主な点は、ラベルの数に関する情報を渡すことです。最も簡単な方法は、`num_labels` 引数でその数を渡すことですが、このセクションの冒頭で見たような立派な推論ウィジェットを機能させたい場合は、正しいラベルの対応を設定する方がよいでしょう。

### 学習のための準備[[preparing-everything-for-training]]

まず、データセットから `DataLoader` を構築する必要があります。`data_collator` を `collate_fn` として再利用し、学習セットはシャッフルしますが、検証セットはシャッフルしません。

```py
from torch.utils.data import DataLoader

train_dataloader = DataLoader(
    tokenized_datasets["train"],
    shuffle=True,
    collate_fn=data_collator,
    batch_size=8,
)
eval_dataloader = DataLoader(
    tokenized_datasets["validation"], collate_fn=data_collator, batch_size=8
)
```

次に、モデルを再びインスタンス化します。前のファインチューニングを継続するのではなく、BERT の事前学習済みモデルから再び開始するためです。

```py
model = AutoModelForTokenClassification.from_pretrained(
    model_checkpoint,
    id2label=id2label,
    label2id=label2id,
)
```

次にオプティマイザが必要です。古典的な `AdamW` を使います。これは `Adam` に似ていますが、重み減衰の適用方法に修正が加えられたものです。

```py
from torch.optim import AdamW

optimizer = AdamW(model.parameters(), lr=2e-5)
```

これらのオブジェクトがすべて揃ったら、`accelerator.prepare()` メソッドに渡すことができます。

```py
from accelerate import Accelerator

accelerator = Accelerator()
model, optimizer, train_dataloader, eval_dataloader = accelerator.prepare(
    model, optimizer, train_dataloader, eval_dataloader
)
```

> [!TIP]
> 🚨 TPU で学習する場合は、このセルより上にあるコードをすべて、専用の学習関数の中に移動する必要があります。詳細は [Chapter 3](/course/chapter3) を参照してください。

`train_dataloader` を `accelerator.prepare()` に渡したので、その長さを使って学習ステップ数を計算できます。このメソッドは長さを変えるため、必ずデータローダを準備した後にこれを行うことを忘れないでください。学習率から 0 までの古典的な線形スケジュールを使います。

```py
from transformers import get_scheduler

num_train_epochs = 3
num_update_steps_per_epoch = len(train_dataloader)
num_training_steps = num_train_epochs * num_update_steps_per_epoch

lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)
```

最後に、モデルを Hub に push するには、作業フォルダに `Repository` オブジェクトを作成する必要があります。まず、まだログインしていない場合は Hugging Face にログインしてください。リポジトリ名は、モデルに付けたいモデル ID から決めます（`repo_name` は自由に置き換えてかまいません。ユーザー名を含む必要があるだけで、それは `get_full_repo_name()` 関数が行います）。

```py

repo_name = get_full_repo_name(model_name)
repo_name
```

```python out

```


### 学習ループ[[training-loop]]

これで完全な学習ループを書く準備ができました。評価部分を単純化するために、予測とラベルを受け取り、`metric` オブジェクトが期待するように文字列のリストに変換する `postprocess()` 関数を定義します。

```py
def postprocess(predictions, labels):
    predictions = predictions.detach().cpu().clone().numpy()
    labels = labels.detach().cpu().clone().numpy()

    # 無視されるインデックス（特殊トークン）を取り除き、ラベルに変換する
    true_labels = [[label_names[l] for l in label if l != -100] for label in labels]
    true_predictions = [
        [label_names[p] for (p, l) in zip(prediction, label) if l != -100]
        for prediction, label in zip(predictions, labels)
    ]
    return true_labels, true_predictions
```

次に学習ループを書くことができます。学習の進み具合を追うプログレスバーを定義した後、ループは3つの部分で構成されます。

- 学習そのもの。`train_dataloader` への古典的なイテレーションで、モデルへの順伝播を行い、次に逆伝播とオプティマイザのステップを行います。
- 評価。モデルからバッチの出力を得た後に、目新しい点があります。2つのプロセスが入力とラベルを異なる形状にパディングしている可能性があるため、`gather()` メソッドを呼び出す前に、`accelerator.pad_across_processes()` を使って予測とラベルを同じ形状にする必要があります。これを行わないと、評価はエラーになるか、永遠にハングしてしまいます。その後、結果を `metric.add_batch()` に送り、評価ループが終わったら `metric.compute()` を呼び出します。
- 保存とアップロード。まずモデルとトークナイザを保存し、次に `repo.push_to_hub()` を呼び出します。`blocking=False` 引数を使って、🤗 Hub ライブラリに非同期プロセスで push するよう指示している点に注意してください。これにより、学習は通常どおり継続し、この（時間のかかる）命令はバックグラウンドで実行されます。

学習ループの完全なコードは次のとおりです。

```py
from tqdm.auto import tqdm
import torch

progress_bar = tqdm(range(num_training_steps))

for epoch in range(num_train_epochs):
    # 学習
    model.train()
    for batch in train_dataloader:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

    # 評価
    model.eval()
    for batch in eval_dataloader:
        with torch.no_grad():
            outputs = model(**batch)

        predictions = outputs.logits.argmax(dim=-1)
        labels = batch["labels"]

        # gather のためには予測とラベルのパディングが必要
        predictions = accelerator.pad_across_processes(predictions, dim=1, pad_index=-100)
        labels = accelerator.pad_across_processes(labels, dim=1, pad_index=-100)

        predictions_gathered = accelerator.gather(predictions)
        labels_gathered = accelerator.gather(labels)

        true_predictions, true_labels = postprocess(predictions_gathered, labels_gathered)
        metric.add_batch(predictions=true_predictions, references=true_labels)

    results = metric.compute()
    print(
        f"epoch {epoch}:",
        {
            key: results[f"overall_{key}"]
            for key in ["precision", "recall", "f1", "accuracy"]
        },
    )

    # 保存とアップロード
    accelerator.wait_for_everyone()
    unwrapped_model = accelerator.unwrap_model(model)
    unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
    if accelerator.is_main_process:
        tokenizer.save_pretrained(output_dir)
        repo.push_to_hub(
            commit_message=f"Training in progress epoch {epoch}", blocking=False
        )
```

🤗 Accelerate で保存されたモデルを初めて見る場合のために、それに付随する3行のコードを少し見てみましょう。

```py
accelerator.wait_for_everyone()
unwrapped_model = accelerator.unwrap_model(model)
unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
```

1行目は自明です。すべてのプロセスに、続行する前に全員がその段階に到達するまで待つよう指示します。これは、保存する前にすべてのプロセスで同じモデルが存在することを確実にするためです。次に `unwrapped_model` を取得します。これは定義したベースモデルです。`accelerator.prepare()` メソッドはモデルを分散学習用に変更するため、`save_pretrained()` メソッドはもう存在しません。`accelerator.unwrap_model()` メソッドはその手順を元に戻します。最後に、`save_pretrained()` を呼び出しますが、そのメソッドに `torch.save()` の代わりに `accelerator.save()` を使うよう指示します。

これが済めば、`Trainer` で学習したモデルとかなり似た結果を出すモデルが得られるはずです。このコードで学習したモデルは、[*huggingface-course/bert-finetuned-ner-accelerate*](https://huggingface.co/huggingface-course/bert-finetuned-ner-accelerate)で確認できます。学習ループへの調整を試したい場合は、上に示したコードを直接編集して実装できます！

```py
from transformers import pipeline

# これは自分のチェックポイントに置き換える
model_checkpoint = "huggingface-course/bert-finetuned-ner"
token_classifier = pipeline(

)
token_classifier("My name is Sylvain and I work at Hugging Face in Brooklyn.")
```
