事前学習済みモデルを共有する

{:else}

{/if}

ここでは、事前学習済みモデルを 🤗 Hub で共有するための最も簡単な方法を紹介します。モデルの公開や更新を容易にするツールやユーティリティを、順に見ていきましょう。

モデルを学習させたすべてのユーザーに、コミュニティで共有することをおすすめします。非常に特殊なデータセットで学習したモデルであっても、共有すればほかの人の時間と計算リソースを節約でき、役立つ学習済みモデルをほかの人が利用できるようになります。そして、ほかの人が行った作業から恩恵を受けることもできます。

新しいモデルリポジトリを作成する方法は3つあります。

  • push_to_hub API を使う
  • huggingface_hub Python ライブラリを使う
  • Web インターフェースを使う

リポジトリを作成したら、Git と Git LFS を使ってファイルをアップロードできます。以降のセクションでは、モデルリポジトリの作成とファイルのアップロード方法を順に説明します。

push_to_hub API を使う

{#if fw === 'pt'}

{:else}

{/if}

Hub にファイルをアップロードする最も簡単な方法は、push_to_hub API を活用することです。

先に進む前に、huggingface_hub API があなたを識別し、書き込み権限のある名前空間を把握できるよう、認証トークンを生成する必要があります。transformers がインストールされた環境にいることを確認してください（セットアップ を参照）。ノートブック環境では、次の関数でログインできます。

from huggingface_hub import notebook_login

notebook_login()

ターミナルでは次を実行します。

huggingface-cli login

どちらの場合も、Hub へのログインに使うものと同じユーザー名とパスワードの入力を求められます。まだ Hub のプロフィールがない場合は、こちら で作成してください。

これで認証トークンがキャッシュフォルダに保存されました。リポジトリを作成しましょう。

{#if fw === 'pt'}

Trainer API を使ってモデルを学習したことがあるなら、Hub にアップロードする最も簡単な方法は、TrainingArguments を定義するときに push_to_hub=True を設定することです。

from transformers import TrainingArguments

training_args = TrainingArguments(
    "bert-finetuned-mrpc", save_strategy="epoch", push_to_hub=True
)

trainer.train() を呼び出すと、Trainer はモデルが保存されるたび（ここではエポックごと）に、あなたの名前空間のリポジトリへモデルをアップロードします。そのリポジトリの名前は、選んだ出力ディレクトリと同じ名前（ここでは bert-finetuned-mrpc）になりますが、hub_model_id = "a_different_name" で別の名前を選ぶこともできます。

所属している組織にモデルをアップロードするには、hub_model_id = "my_organization/my_repo_name" のように渡すだけです。

学習が終わったら、最後に trainer.push_to_hub() を実行して、モデルの最終バージョンをアップロードします。使ったハイパーパラメータや評価結果を報告するメタデータとともに、モデルカードも生成されます。そのようなモデルカードの内容の例がこちらです。

{:else}

Keras でモデルを学習している場合、Hub にアップロードする最も簡単な方法は、model.fit() の呼び出し時に PushToHubCallback を渡すことです。

from transformers import PushToHubCallback

callback = PushToHubCallback(
    "bert-finetuned-mrpc", save_strategy="epoch", tokenizer=tokenizer
)

続いて、model.fit() の呼び出しに callbacks=[callback] を加えます。するとコールバックは、モデルが保存されるたび（ここではエポックごと）に、あなたの名前空間のリポジトリへモデルをアップロードします。そのリポジトリの名前は、選んだ出力ディレクトリと同じ名前（ここでは bert-finetuned-mrpc）になりますが、hub_model_id = "a_different_name" で別の名前を選ぶこともできます。

所属している組織にモデルをアップロードするには、hub_model_id = "my_organization/my_repo_name" のように渡すだけです。

{/if}

より低レベルでは、モデル、トークナイザ、設定オブジェクトの push_to_hub() メソッドを使って、Model Hub に直接アクセスできます。このメソッドは、リポジトリの作成と、モデルとトークナイザのファイルのリポジトリへのプッシュの両方を行います。後述する API とは異なり、リポジトリ作成やファイルのプッシュを手作業で行う必要はありません。

仕組みを把握するため、まずモデルとトークナイザを初期化しましょう。

{#if fw === 'pt'}

from transformers import AutoModelForMaskedLM, AutoTokenizer

checkpoint = "camembert-base"

model = AutoModelForMaskedLM.from_pretrained(checkpoint)
tokenizer = AutoTokenizer.from_pretrained(checkpoint)

{:else}

from transformers import TFAutoModelForMaskedLM, AutoTokenizer

checkpoint = "camembert-base"

model = TFAutoModelForMaskedLM.from_pretrained(checkpoint)
tokenizer = AutoTokenizer.from_pretrained(checkpoint)

{/if}

これらを使って自由に作業できます。トークナイザにトークンを追加したり、モデルを学習したり、ファインチューニングしたりしてください。得られたモデル、重み、トークナイザが思いどおりに仕上がったら、model オブジェクトで直接使える push_to_hub() メソッドを活用できます。

model.push_to_hub("dummy-model")

これにより、自分のユーザー名に対応する名前空間に新しいリポジトリ dummy-model が作成され、モデルファイルが配置されます。 トークナイザについても同じことを行い、すべてのファイルがこのリポジトリで利用できるようにします。

tokenizer.push_to_hub("dummy-model")

組織に所属している場合は、organization 引数を指定するだけで、その組織の名前空間にアップロードできます。

tokenizer.push_to_hub("dummy-model", organization="huggingface")

特定の Hugging Face トークンを使いたい場合も、push_to_hub() メソッドに指定できます。

tokenizer.push_to_hub("dummy-model", organization="huggingface", use_auth_token="<TOKEN>")

では Model Hub に行って、新しくアップロードしたモデルを見てみましょう。https://huggingface.co/user-or-organization/dummy-model.

「Files and versions」タブをクリックすると、次のスクリーンショットに表示されているファイルが見えるはずです。

ここまで見てきたように、push_to_hub() メソッドはいくつかの引数を受け付けるため、特定のリポジトリや組織の名前空間へのアップロードや、別の認証トークンの使用が可能です。何ができるかを把握するために、🤗 Transformers ドキュメント で直接確認できるメソッド仕様を参照してください。

push_to_hub() メソッドは、Hugging Face Hub への直接の API を提供する huggingface_hub Python パッケージに支えられています。これは 🤗 Transformers や allenlp のようないくつかの機械学習ライブラリに統合されています。この章では 🤗 Transformers との統合に焦点を当てますが、自分のコードやライブラリへの統合も簡単です。

新しく作成したリポジトリにファイルをアップロードする方法は、最後のセクションへ進んで確認してください。

huggingface_hub Python ライブラリを使う

huggingface_hub Python ライブラリは、モデルハブとデータセットハブのためのツール群を提供するパッケージです。Hub 上のリポジトリの情報を取得したり管理したりといった一般的なタスクを、シンプルなメソッドとクラスで実行できます。また、Git を基盤とするシンプルな API によって、リポジトリのコンテンツを管理したり、Hub をプロジェクトやライブラリに統合したりできます。

push_to_hub API を使う場合と同様に、認証トークンがキャッシュに保存されている必要があります。そのためには、前のセクションで触れたように、CLI の login コマンドを使う必要があります（Google Colab で実行する場合は、これらのコマンドの前に ! 文字を付けることを忘れないでください）。

huggingface-cli login

huggingface_hub パッケージは、私たちの目的に役立つメソッドとクラスをいくつか提供します。まず、リポジトリの作成や削除などを管理するためのメソッドがあります。

```python no-format from huggingface_hub import ( # ユーザー管理 login, logout, whoami,

# リポジトリの作成と管理
create_repo,
delete_repo,
update_repo_visibility,

# コンテンツに関する情報の取得・変更のためのメソッド
list_models,
list_datasets,
list_metrics,
list_repo_files,
upload_file,
delete_file,

)

また、ローカルリポジトリを管理するための `Repository` クラスも用意されています。これらのメソッドとそのクラスは、次のセクションで詳しく見ていきます。

`create_repo` メソッドは、Hub に新しいリポジトリを作成するために使えます。

```py
from huggingface_hub import create_repo

create_repo("dummy-model")

これにより、あなたの名前空間に dummy-model リポジトリが作成されます。組織の名前空間に作成したい場合は、organization 引数で組織名を指定できます。

from huggingface_hub import create_repo

create_repo("dummy-model", organization="huggingface")

これにより、huggingface 名前空間に dummy-model リポジトリが作成されます（その組織に所属していることが前提です）。 役立つかもしれない他の引数には次のものがあります。

  • private: リポジトリを非公開にするかどうかを指定します。True にすると非公開になります。
  • token: キャッシュに保存された認証トークンの代わりに、指定したトークンを使用する場合に指定します。
  • repo_type: モデルではなく dataset や space を作成したい場合に使います。指定できる値は "dataset" と "space" です。

リポジトリを作成したら、ファイルを追加しましょう。3つの方法は次のセクションをご覧ください。

Web インターフェースを使う

Web インターフェースは、Hub で直接リポジトリを管理するためのツールを提供します。インターフェースを使えば、リポジトリの作成、ファイルの追加（大きなファイルでも）、モデルの探索、差分の可視化などが簡単に行えます。

新しいリポジトリを作成するには、huggingface.co/new にアクセスします。

まず、リポジトリの所有者を指定します。あなた自身か、所属している組織のいずれかです。組織を選ぶと、モデルはその組織のページに掲載され、組織のメンバー全員がリポジトリに貢献できるようになります。

次に、モデルの名前を入力します。これがリポジトリの名前にもなります。最後に、モデルを公開するか非公開にするかを指定できます。非公開のモデルは公には表示されません。

モデルリポジトリを作成すると、次のようなページが表示されます。

このリポジトリにモデルのファイルが保存・公開されます。ファイルを追加し始めるには、Web インターフェースから直接 README ファイルを追加できます。

README ファイルは Markdown です。自由に書いてください。この章の第3パートでは、モデルカードの作成方法を説明します。モデルカードは、そのモデルで何ができるかをほかのユーザーに伝えるものであり、モデルの価値を高めるうえで非常に重要です。

「Files and versions」タブを見ると、まだファイルはあまりありません。作成したばかりの README.md と、大きなファイルを追跡する .gitattributes ファイルだけです。

次に、新しいファイルを追加する方法を見ていきます。

モデルファイルをアップロードする

Hugging Face Hub でファイルを管理するシステムは、通常のファイルについては Git、大きなファイルについては Git LFS（Git Large File Storage の略）に基づいています。

次のセクションでは、Hub にファイルをアップロードする3つの異なる方法を説明します。huggingface_hub を通す方法と、git コマンドを使う方法です。

upload_file による方法

upload_file を使う方法では、システムに Git と Git LFS がインストールされている必要はありません。HTTP の POST リクエストを使って、ファイルを 🤗 Hub に直接プッシュします。この方法の制限は、5GB を超えるサイズのファイルを扱えないことです。 ファイルが 5GB を超える場合は、以下で詳しく説明する他の2つの方法のいずれかに従ってください。

API は次のように使えます。

from huggingface_hub import upload_file

upload_file(
    "<path_to_file>/config.json",
    path_in_repo="config.json",
    repo_id="<namespace>/dummy-model",
)

これにより、<path_to_file> にある config.json ファイルが、dummy-model リポジトリのルートに config.json としてアップロードされます。 役立つかもしれない他の引数には次のものがあります。

  • token: キャッシュに保存された認証トークンの代わりに、指定したトークンを使用する場合に指定します。
  • repo_type: モデルではなく dataset や space にアップロードしたい場合に使います。指定できる値は "dataset" と "space" です。

Repository クラス

Repository クラスを使うと、ローカルの Git リポジトリを Python から操作できます。Git の複雑な操作の多くが抽象化されており、必要な処理を簡単なメソッド呼び出しで実行できます。

このクラスを使うには Git と Git LFS がインストールされている必要があるため、始める前に Git LFS がインストールされ（インストール手順は こちら を参照）、セットアップされていることを確認してください。

まず、作成したリポジトリをローカルフォルダにクローンしましょう。

from huggingface_hub import Repository

repo = Repository("<path_to_dummy_folder>", clone_from="<namespace>/dummy-model")

これにより、作業ディレクトリに <path_to_dummy_folder> フォルダが作成されました。このフォルダには .gitattributes ファイルだけが含まれています。create_repo でリポジトリをインスタンス化したときに作成されるファイルはそれだけだからです。

ここからは、従来の Git のメソッドをいくつか活用できます。

repo.git_pull()
repo.git_add()
repo.git_commit()
repo.git_push()
repo.git_tag()

ほかにもあります。利用できるすべてのメソッドの概要については、こちら で確認できる Repository のドキュメントをご覧になることをおすすめします。

現在、Hub にプッシュしたいモデルとトークナイザがあります。リポジトリのクローンは無事にできたので、そのリポジトリ内にファイルを保存できます。

まず、最新の変更をプルして、ローカルのクローンが最新であることを確認します。

repo.git_pull()

それが終わったら、モデルとトークナイザのファイルを保存します。

model.save_pretrained("<path_to_dummy_folder>")
tokenizer.save_pretrained("<path_to_dummy_folder>")

<path_to_dummy_folder> には、モデルとトークナイザのファイルがすべて含まれました。通常の Git のワークフローに従って、ファイルをステージングエリアに追加し、コミットして、Hub にプッシュします。

repo.git_add()
repo.git_commit("Add model and tokenizer files")
repo.git_push()

おめでとうございます。Hub に初めてファイルをプッシュできました。

Git ベースの方法

この方法では、Git と Git LFS を直接操作してファイルをアップロードします。これまでの方法では難しさのほとんどが抽象化されていましたが、この方法にはいくつか注意点があるため、より複雑なユースケースに沿って進めます。

この方法を使うには Git と Git LFS がインストールされている必要があるため、始める前に Git LFS がインストールされ（インストール手順はこちらを参照）、セットアップされていることを確認してください。

まず Git LFS を初期化します。

git lfs install

Updated git hooks.
Git LFS initialized.

それが終わったら、最初のステップはモデルリポジトリをクローンすることです。

git clone https://huggingface.co/<namespace>/<your-model-id>

私のユーザー名は lysandre で、モデル名には dummy を使ったため、私の場合はコマンドは次のようになります。

git clone https://huggingface.co/lysandre/dummy

作業ディレクトリに dummy という名前のフォルダができました。そのフォルダに cd して、中身を見てみましょう。

cd dummy && ls

README.md

create_repo メソッドを使ってリポジトリを作成したばかりであれば、このフォルダには隠しファイルの .gitattributes だけが含まれているはずです。前のセクションの指示に従って Web インターフェースでリポジトリを作成した場合は、ここに示すように、隠しファイルの .gitattributes とともに README.md ファイルが1つ含まれています。

設定ファイル、語彙ファイル、あるいは数メガバイト未満の基本的にあらゆるファイルといった通常サイズのファイルの追加は、Git ベースのシステムで通常行うのとまったく同じ方法で行います。しかし、より大きなファイルは、huggingface.co にプッシュするために Git LFS を通じて登録しなければなりません。

Python に少し戻って、ダミーリポジトリにコミットしたいモデルとトークナイザを生成しましょう。

{#if fw === 'pt'}

from transformers import AutoModelForMaskedLM, AutoTokenizer

checkpoint = "camembert-base"

tokenizer = AutoTokenizer.from_pretrained(checkpoint)

# モデルを使って自由に作業します。学習させたり、ファインチューニングしたり…

model.save_pretrained("<path_to_dummy_folder>")
tokenizer.save_pretrained("<path_to_dummy_folder>")

💡 ヒント

✏️ Web インターフェースからリポジトリを作成すると、.gitattributes ファイルは自動的に設定され、.bin や .h5 といった特定の拡張子を持つファイルを大きなファイルとして扱うため、こちらで必要な設定なしに Git LFS がそれらを追跡します。

git add .
