DEtection TRansformer (DETR)

アーキテクチャの概要

DETR は主に物体検出タスクに使われます。物体検出とは、画像の中の物体を検出する処理です。たとえば、モデルの入力は道路の画像で、出力は [('car',X1,Y1,W1,H1),('pedestrian',X2,Y2,W2,H2)] のようになります。ここで X、Y、W、H は、バウンディングボックスの位置を示す x、y 座標と、ボックスの幅と高さを表します。 YOLO のような従来の物体検出モデルは、anchor box の事前分布のような手作業で作られた特徴で構成されます。これには物体の位置と形状の初期推測が必要で、下流の訓練に影響します。その後、重なり合うバウンディングボックスを取り除くための後処理が行われますが、そのフィルタリングのヒューリスティクスは慎重に選ぶ必要があります。 DEtection TRansformer、略して DETR は、特徴抽出のバックボーンの後に encoder-decoder Transformer を使ってバウンディングボックスを並列に直接予測することで検出器を簡素化し、後処理を最小限に抑えます。

DETR のモデルアーキテクチャは、他の画像ベースのネットワークと同様に CNN バックボーンから始まります。その出力を処理して Transformer encoder に入力すると、N 個の埋め込みが得られます。encoder の埋め込みは、学習された位置埋め込み（object queries と呼ばれます）に加えられ、Transformer decoder で使われて、さらに N 個の埋め込みが生成されます。最後のステップとして、N 個の埋め込みはそれぞれ個別の feed forward 層に通され、バウンディングボックスの幅、高さ、座標と、物体のクラス（または物体が存在するかどうか）を予測します。

主な特徴

Encoder-Decoder

他の Transformer と同様に、Transformer encoder は CNN バックボーンの出力が列であることを想定しています。そのため、[dimension, height, width] サイズの特徴マップは縮小され、[dimension, less than height x width] に平坦化されます。 左: 特徴マップの 256 次元のうち 12 次元を可視化したものです。各次元は、元の画像を縮小しながら、元の猫の画像の何らかの特徴を抽出しています。猫の模様に強く注目している次元もあれば、ベッドシーツに強く注目している次元もあります。 右: 元の特徴次元である 256 というサイズを保ったまま、幅と高さはさらに縮小され、850 というサイズに平坦化されています。 Transformer は順序に対して不変であるため、埋め込みが画像のどこに由来するかをモデルに思い出させるために、encoder と decoder の両方に位置埋め込みが加えられます。encoder では固定の位置エンコーディングが使われ、decoder では学習された位置エンコーディング（object queries）が使われます。固定エンコーディングは、元の Transformer 論文で使われたものと似ており、エンコーディングは異なる特徴次元で異なる周波数の正弦波関数によって定義されます。学習されるパラメータを持たず、画像上の位置でインデックスされることで、位置の感覚を与えます。学習されるエンコーディングも位置でインデックスされますが、各位置は個別のエンコーディングを持ち、それが訓練を通じて学習され、モデルが理解できる方法で位置を示します。

集合ベースの大域損失関数

人気のある物体検出モデルである YOLO では、損失関数はバウンディングボックス、objectness（すなわち、注目領域に物体が存在する確率）、クラスの損失から構成されます。損失は各グリッドセルに対する複数のバウンディングボックスについて計算され、その数は固定です。一方 DETR では、アーキテクチャは順序不変な方法で一意なバウンディングボックスを生成することが求められます（すなわち、出力における検出の順序は重要ではなく、バウンディングボックスは互いに異ならなければならず、すべて同じではいけません）。そのため、予測がどれほど良いかを評価するにはマッチングが必要です。

Bipartite Matching 二部マッチングは、正解のバウンディングボックスと予測されたボックスとの間で 1 対 1 のマッチングを計算する方法です。正解と予測されたバウンディングボックス、およびクラスとの間で最も類似度が高いマッチを見つけます。これにより、最も近い予測が対応する正解とマッチし、損失関数の中でボックスとクラスを適切に調整できます。マッチングを行わないと、正解の順序と揃っていない予測は、正しくても誤りとして扱われてしまいます。

DETR の進化

Deformable DETR

DETR の主な問題の 2 つは、収束までの過程が長く遅いことと、小さい物体の検出が最適でないことです。 Deformable Attention 1 つ目の問題は、注目するサンプリング点の量を減らす deformable attention を使うことで解決されます。従来のアテンションは大域的なアテンションのために非効率で、画像が持てる解像度を大きく制限します。このモデルは、各参照点の周囲にある固定された量のサンプリング点にのみ注目し、参照点は入力に基づいてモデルが学習します。たとえば犬の画像では、参照点は犬の中心にあり、サンプリング点は耳、口、尻尾などの近くにある、といった具合です。

Multi-scale Deformable Attention Module 2 つ目の問題は、マルチスケールの特徴マップを導入した YOLOv3 と同様の方法で解決されます。畳み込みニューラルネットワークでは、早い層はより小さい詳細（例: 線）を抽出し、後の層はより大きい詳細（例: 車輪、耳）を抽出します。同様に、deformable attention の異なる層は異なるレベルの解像度をもたらします。これらの層のうちのいくつかの出力を encoder から decoder へつなぐことで、モデルは多種多様なサイズの物体を検出できます。

Conditional DETR

Conditional DETR も、元の DETR の訓練の収束が遅い問題の解決を目指しており、6.7 倍を超える速さの収束を実現します。著者らは、object queries が一般的であり、入力画像に固有ではないことを発見しました。decoder で Conditional Cross-Attention を使うことで、クエリはバウンディングボックス回帰のための領域をより良く特定できます。 左: DETR の Decoder 層。右: Conditional DETR の Decoder 層 上の図では、元の DETR と Conditional DETR の decoder 層が比較されており、主な違いは cross-attention ブロックのクエリ入力です。著者らは、content query cq（decoder の self attention の出力）と spatial query pq を区別しています。元の DETR は単に両者を足し合わせます。Conditional DETR では両者は連結され、cq は物体の内容に注目し、pq はバウンディングボックスの領域に注目します。 spatial query pq は、decoder の埋め込みと object queries の両方が同じ空間に射影され（それぞれ T と ps になります）、互いに掛け合わされた結果です。前の層の decoder の埋め込みにはバウンディングボックス領域のための情報が含まれ、object queries には各バウンディングボックスについて学習された参照点の情報が含まれます。そのため、それらの射影が組み合わさって、cross-attention が encoder 入力および正弦波の位置埋め込みとの類似度を測れる表現となります。これは、object queries と固定の参照点だけを使う DETR よりも効果的です。

DETR の推論

Hugging Face Hub にある既存の DETR モデルを使って、次のように推論できます。

from transformers import DetrImageProcessor, DetrForObjectDetection
import torch
from PIL import Image
import requests

url = "http://images.cocodataset.org/val2017/000000039769.jpg"
image = Image.open(requests.get(url, stream=True).raw)

# モデルを初期化します
processor = DetrImageProcessor.from_pretrained(
    "facebook/detr-resnet-101", revision="no_timm"
)
model = DetrForObjectDetection.from_pretrained(
    "facebook/detr-resnet-101", revision="no_timm"
)

# 入力を前処理して推論します
inputs = processor(images=image, return_tensors="pt")
outputs = model(**inputs)

# 出力（バウンディングボックスとクラスのロジット）を COCO API 形式に変換します
# 0.9 超に対する non-max suppression
target_sizes = torch.tensor([image.size[::-1]])
results = processor.post_process_object_detection(
    outputs, target_sizes=target_sizes, threshold=0.9
)[0]

for score, label, box in zip(results["scores"], results["labels"], results["boxes"]):
    box = [round(i, 2) for i in box.tolist()]
    print(
        f"検出: {model.config.id2label[label.item()]}、信頼度: "
        f"{round(score.item(), 3)}、位置: {box}"
    )

DETR の PyTorch 実装

元の論文の DETR の実装は次のとおりです。

import torch
from torch import nn
from torchvision.models import resnet50


class DETR(nn.Module):
    def __init__(
        self, num_classes, hidden_dim, nheads, num_encoder_layers, num_decoder_layers
    ):
        super().__init__()
        self.backbone = nn.Sequential(*list(resnet50(pretrained=True).children())[:-2])
        self.conv = nn.Conv2d(2048, hidden_dim, 1)
        self.transformer = nn.Transformer(
            hidden_dim, nheads, num_encoder_layers, num_decoder_layers
        )
        self.linear_class = nn.Linear(hidden_dim, num_classes + 1)
        self.linear_bbox = nn.Linear(hidden_dim, 4)
        self.query_pos = nn.Parameter(torch.rand(100, hidden_dim))
        self.row_embed = nn.Parameter(torch.rand(50, hidden_dim // 2))
        self.col_embed = nn.Parameter(torch.rand(50, hidden_dim // 2))

    def forward(self, inputs):
        x = self.backbone(inputs)
        h = self.conv(x)
        H, W = h.shape[-2:]
        pos = (
            torch.cat(
                [
                    self.col_embed[:W].unsqueeze(0).repeat(H, 1, 1),
                    self.row_embed[:H].unsqueeze(1).repeat(1, W, 1),
                ],
                dim=-1,
            )
            .flatten(0, 1)
            .unsqueeze(1)
        )
        h = self.transformer(
            pos + h.flatten(2).permute(2, 0, 1), self.query_pos.unsqueeze(1)
        )
        return self.linear_class(h), self.linear_bbox(h).sigmoid()

forward 関数を 1 行ずつ見ていく

Backbone 入力画像はまず ResNet バックボーンに通され、次に畳み込み層に通されます。これにより次元が hidden_dim に削減されます。

x = self.backbone(inputs)
h = self.conv(x)

これらは __init__ 関数で宣言されています。

self.backbone = nn.Sequential(*list(resnet50(pretrained=True).children())[:-2])
self.conv = nn.Conv2d(2048, hidden_dim, 1)

位置埋め込み

論文では encoder と decoder でそれぞれ固定の埋め込みと訓練される埋め込みが使われていますが、実装では著者らは簡単のために両方に訓練される埋め込みを使いました。

pos = (
    torch.cat(
        [
            self.col_embed[:W].unsqueeze(0).repeat(H, 1, 1),
            self.row_embed[:H].unsqueeze(1).repeat(1, W, 1),
        ],
        dim=-1,
    )
    .flatten(0, 1)
    .unsqueeze(1)
)

これらはここで nn.Parameter として宣言されています。行と列の埋め込みの組み合わせが、画像内の位置を示します。

self.row_embed = nn.Parameter(torch.rand(50, hidden_dim // 2))
self.col_embed = nn.Parameter(torch.rand(50, hidden_dim // 2))

Resize Transformer に入る前に、サイズ (batch size, hidden_dim, H, W) の特徴は (hidden_dim, batch size, H*W) に変形されます。これにより、Transformer への逐次入力となります。

h.flatten(2).permute(2, 0, 1)

Transformer nn.Transformer 関数は、第 1 引数を encoder への入力として受け取り、第 2 引数を encoder の入力として受け取ります。見て分かるように、encoder は位置埋め込みに加えられた変形済みの特徴を受け取り、decoder は decoder の位置埋め込みである query_pos を受け取ります。

h = self.transformer(pos + h.flatten(2).permute(2, 0, 1), self.query_pos.unsqueeze(1))

Feed-Forward Network 最後に、サイズ (query_pos_dim, batch size, hidden_dim) のテンソルである出力は、2 つの線形層に通されます。

return self.linear_class(h), self.linear_bbox(h).sigmoid()

1 つ目はクラスを予測します。No Object クラスのために追加のクラスが加えられます。

self.linear_class = nn.Linear(hidden_dim, num_classes + 1)

2 つ目の線形層は、xy 座標、高さ、幅のための出力サイズ 4 でバウンディングボックスを予測します。

self.linear_bbox = nn.Linear(hidden_dim, 4)
