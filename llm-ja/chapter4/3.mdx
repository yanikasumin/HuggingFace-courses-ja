ここでは、事前学習済みモデルを 🤗 Hub で共有するための最も簡単な方法を紹介します。モデルの公開や更新を容易にするツールやユーティリティを、順に見ていきましょう。

<Youtube id="9yY3RB_GSPM"/>

モデルを学習したら、ぜひコミュニティで共有してください。特殊なデータセットで学習したモデルでも、公開することで、ほかの人の時間や計算リソースを節約できます。また、学習済みモデルなどの役立つ成果物を利用してもらえます。自分もほかの人が公開した成果物を利用できるので、お互いに助け合えます。

新しいモデルリポジトリを作成する方法は3つあります。

- `push_to_hub` API を使う
- `huggingface_hub` Python ライブラリを使う
- Web インターフェースを使う

リポジトリを作成したら、Git と Git LFS を使ってファイルをアップロードできます。以降のセクションでは、モデルリポジトリの作成とファイルのアップロード方法を順に説明します。


## `push_to_hub` API を使う[[using-the-pushtohub-api]]

{#if fw === 'pt'}

<Youtube id="Zh0FfmVrKX0"/>

{:else}

<Youtube id="pUh5cGmNV8Y"/>

{/if}

Hub にファイルをアップロードする最も簡単な方法は、`push_to_hub` API を活用することです。

まず、認証トークンを生成する必要があります。このトークンを使って、`huggingface_hub` API はユーザーを識別し、どの名前空間への書き込み権限があるかを確認します。作業する環境に `transformers` がインストールされていることも確認してください（[セットアップ](/course/chapter0) を参照）。ノートブックを使っている場合は、次の関数でログインできます。

```python
from huggingface_hub import notebook_login

notebook_login()
```

ターミナルでは次を実行します。

```bash
huggingface-cli login
```

どちらの場合も、Hub へのログインに使うものと同じユーザー名とパスワードの入力を求められます。まだ Hub のプロフィールがない場合は、[こちら](https://huggingface.co/join) で作成してください。

これで認証トークンがキャッシュフォルダに保存されました。リポジトリを作成しましょう。

{#if fw === 'pt'}

`Trainer` API を使ってモデルを学習したことがあるなら、Hub にアップロードする最も簡単な方法は、`TrainingArguments` を定義するときに `push_to_hub=True` を設定することです。

```py
from transformers import TrainingArguments

training_args = TrainingArguments(
    "bert-finetuned-mrpc", save_strategy="epoch", push_to_hub=True
)
```

`trainer.train()` を呼び出すと、`Trainer` はモデルが保存されるたびに、あなたの名前空間にあるリポジトリへモデルをアップロードします。ここではエポックごとにアップロードされます。リポジトリには、指定した出力ディレクトリと同じ名前（ここでは `bert-finetuned-mrpc`）が付けられます。別の名前にしたい場合は、`hub_model_id = "a_different_name"` を指定できます。

所属する組織の名前空間にモデルをアップロードしたい場合は、`hub_model_id = "my_organization/my_repo_name"` のように組織名とリポジトリ名を指定します。

学習が終わったら、最後に `trainer.push_to_hub()` を実行して、モデルの最終バージョンをアップロードします。同時に、使用したハイパーパラメータや評価結果などのメタデータを含むモデルカードも生成されます。モデルカードには、たとえば次のような内容が記載されます。

<div class="flex justify-center">
  <img src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter4/model_card.png" alt="自動生成されたモデルカードの例。" width="100%"/>
</div>

{:else}

Keras でモデルを学習している場合、Hub にアップロードする最も簡単な方法は、`model.fit()` の呼び出し時に `PushToHubCallback` を渡すことです。

```py
from transformers import PushToHubCallback

callback = PushToHubCallback(
    "bert-finetuned-mrpc", save_strategy="epoch", tokenizer=tokenizer
)
```

次に、`model.fit()` を呼び出すときに `callbacks=[callback]` を追加します。すると、モデルが保存されるたびに、コールバックがあなたの名前空間にあるリポジトリへモデルをアップロードします。ここではエポックごとにアップロードされます。リポジトリには、指定した出力ディレクトリと同じ名前（ここでは `bert-finetuned-mrpc`）が付けられます。別の名前にしたい場合は、`hub_model_id = "a_different_name"` を指定できます。

所属する組織の名前空間にモデルをアップロードしたい場合は、`hub_model_id = "my_organization/my_repo_name"` のように組織名とリポジトリ名を指定します。

{/if}

モデル、トークナイザ、設定オブジェクトには、Model Hub を直接操作するための `push_to_hub()` メソッドも用意されています。このメソッドは、リポジトリの作成と、モデルやトークナイザのファイルのアップロードをまとめて行います。後で紹介する API とは異なり、リポジトリの作成やファイルのプッシュを自分で行う必要はありません。

仕組みを把握するため、まずモデルとトークナイザを初期化しましょう。

{#if fw === 'pt'}
```py
from transformers import AutoModelForMaskedLM, AutoTokenizer

checkpoint = "camembert-base"

model = AutoModelForMaskedLM.from_pretrained(checkpoint)
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
```
{:else}
```py
from transformers import TFAutoModelForMaskedLM, AutoTokenizer

checkpoint = "camembert-base"

model = TFAutoModelForMaskedLM.from_pretrained(checkpoint)
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
```
{/if}

これらのモデルとトークナイザは自由に変更できます。たとえば、トークナイザにトークンを追加したり、モデルを学習させたり、ファインチューニングしたりできます。モデルやその重み、トークナイザが満足のいく状態になったら、`model` オブジェクトの `push_to_hub()` メソッドを使ってアップロードできます。

```py
model.push_to_hub("dummy-model")
```

これにより、自分のユーザー名に対応する名前空間に新しいリポジトリ `dummy-model` が作成され、モデルファイルが配置されます。トークナイザについても同じことを行い、すべてのファイルがこのリポジトリで利用できるようにします。

```py
tokenizer.push_to_hub("dummy-model")
```

組織に所属している場合は、`organization` 引数を指定するだけで、その組織の名前空間にアップロードできます。

```py
tokenizer.push_to_hub("dummy-model", organization="huggingface")
```

特定の Hugging Face トークンを使いたい場合も、`push_to_hub()` メソッドに指定できます。

```py
tokenizer.push_to_hub("dummy-model", organization="huggingface", use_auth_token="<TOKEN>")
```

では、Model Hub で新しくアップロードしたモデルを確認しましょう。URL は *https://huggingface.co/user-or-organization/dummy-model* です。

「Files and versions」タブをクリックすると、次のスクリーンショットに表示されているファイルが見えるはずです。

`push_to_hub()` メソッドには、いくつかの引数があります。これらを使うと、アップロード先のリポジトリや組織の名前空間を指定したり、別の認証トークンを使ったりできます。詳しい引数や使い方は、[🤗 Transformers ドキュメント](https://huggingface.co/transformers/model_sharing) で確認してください。

`push_to_hub()` メソッドの内部では、Hugging Face Hub を直接操作するための API を提供する Python パッケージ [`huggingface_hub`](https://github.com/huggingface/huggingface_hub) が使われています。このパッケージは、🤗 Transformers や [`allenlp`](https://github.com/allenai/allennlp) など、いくつかの機械学習ライブラリに組み込まれています。この章では 🤗 Transformers との連携を中心に説明しますが、自分のコードやライブラリに組み込むことも簡単です。

新しく作成したリポジトリにファイルをアップロードする方法は、最後のセクションへ進んで確認してください。

## `huggingface_hub` Python ライブラリを使う[[using-the-huggingfacehub-python-library]]

`huggingface_hub` Python ライブラリは、モデルハブとデータセットハブのためのツール群を提供するパッケージです。Hub 上のリポジトリの情報を取得したり管理したりといった一般的なタスクを、シンプルなメソッドとクラスで実行できます。また、Git を基盤とするシンプルな API によって、リポジトリのコンテンツを管理したり、Hub をプロジェクトやライブラリに統合したりできます。

`push_to_hub` API と同じく、`huggingface_hub` を使う場合も認証トークンをキャッシュに保存しておく必要があります。前のセクションで紹介した CLI の `login` コマンドを実行してください。Google Colab で実行する場合は、コマンドの先頭に `!` を付けます。

```bash
huggingface-cli login
```

`huggingface_hub` パッケージは、私たちの目的に役立つメソッドとクラスをいくつか提供します。まず、リポジトリの作成や削除などを管理するためのメソッドがあります。

```python no-format
from huggingface_hub import (
    # ユーザー管理
    login,
    logout,
    whoami,

    # リポジトリの作成と管理
    create_repo,
    delete_repo,
    update_repo_visibility,

    # コンテンツに関する情報の取得・変更のためのメソッド
    list_models,
    list_datasets,
    list_metrics,
    list_repo_files,
    upload_file,
    delete_file,
)
```


また、ローカルリポジトリを管理するための `Repository` クラスも用意されています。ここで紹介したメソッドと `Repository` クラスの使い方は、以降のセクションで詳しく説明します。

`create_repo` メソッドは、Hub に新しいリポジトリを作成するために使えます。

```py
from huggingface_hub import create_repo

create_repo("dummy-model")
```

これにより、あなたの名前空間に `dummy-model` リポジトリが作成されます。組織の名前空間に作成したい場合は、`organization` 引数で組織名を指定できます。

```py
from huggingface_hub import create_repo

create_repo("dummy-model", organization="huggingface")
```

これにより、`huggingface` 名前空間に `dummy-model` リポジトリが作成されます。但し、その組織に所属している必要があります。ほかにも、次のような便利な引数があります。

- `private`: リポジトリを非公開にするかどうかを指定します。`True` にすると非公開になります。
- `token`: キャッシュに保存された認証トークンの代わりに、指定したトークンを使用する場合に指定します。
- `repo_type`: モデルではなく `dataset` や `space` を作成したい場合に使います。指定できる値は `"dataset"` と `"space"` です。

リポジトリを作成したら、ファイルを追加しましょう。3つの方法は次のセクションをご覧ください。

新しいリポジトリを作成するには、[huggingface.co/new](https://huggingface.co/new) にアクセスします。

## モデルファイルをアップロードする[[uploading-the-model-files]]

Hugging Face Hub でファイルを管理するシステムは、通常のファイルについては Git、大きなファイルについては Git LFS（[Git Large File Storage](https://git-lfs.github.com/) の略）に基づいています。

次のセクションでは、Hub にファイルをアップロードする3つの異なる方法を説明します。`huggingface_hub` を通す方法と、git コマンドを使う方法です。

### `upload_file` による方法[[the-uploadfile-approach]]

`upload_file` を使う方法では、システムに Git と Git LFS がインストールされている必要はありません。HTTP POST リクエストを使って、ファイルを 🤗 Hub に直接プッシュします。この方法の制限は、5GB を超えるサイズのファイルを扱えないことです。ファイルが 5GB を超える場合は、以下で詳しく説明する他の2つの方法のいずれかに従ってください。

API は次のように使えます。

```py
from huggingface_hub import upload_file

upload_file(
    "<path_to_file>/config.json",
    path_in_repo="config.json",
    repo_id="<namespace>/dummy-model",
)
```

このコードを実行すると、`<path_to_file>` にある `config.json` ファイルが、`dummy-model` リポジトリのルートに同じ名前でアップロードされます。ほかにも、次のような便利な引数があります。

- `token`: キャッシュに保存された認証トークンの代わりに、指定したトークンを使用する場合に指定します。
- `repo_type`: モデルではなく `dataset` や `space` にアップロードしたい場合に使います。指定できる値は `"dataset"` と `"space"` です。


### `Repository` クラス[[the-repository-class]]

`Repository` クラスを使うと、ローカルの Git リポジトリを Python から操作できます。Git の複雑な操作の多くが抽象化されており、必要な処理を簡単なメソッド呼び出しで実行できます。

このクラスを使うには、Git と Git LFS が必要です。始める前に両方をインストールし、Git LFS の設定も済ませてください。Git LFS のインストール手順は [こちら](https://git-lfs.github.com/) で確認できます。

まず、作成したリポジトリをローカルフォルダにクローンしましょう。

```py
from huggingface_hub import Repository

repo = Repository("<path_to_dummy_folder>", clone_from="<namespace>/dummy-model")
```

このコードを実行すると、作業ディレクトリに `<path_to_dummy_folder>` フォルダが作成されます。中にあるのは `.gitattributes` ファイルだけです。これは、`create_repo` でリポジトリを作成した時点では、ほかのファイルが作成されないためです。

ここからは、通常の Git 操作に相当する次のメソッドを使えます。

```py
repo.git_pull()
repo.git_add()
repo.git_commit()
repo.git_push()
repo.git_tag()
```

このほかにも、さまざまなメソッドがあります。利用できるメソッドの一覧や概要は、[こちら](https://github.com/huggingface/huggingface_hub/tree/main/src/huggingface_hub#advanced-programmatic-repository-management) の `Repository` ドキュメントで確認できます。

Hub にアップロードしたいモデルとトークナイザは、すでに用意できています。リポジトリのクローンも完了したので、次はその中にファイルを保存しましょう。

まず、最新の変更をプルして、ローカルのクローンが最新であることを確認します。

```py
repo.git_pull()
```

それが終わったら、モデルとトークナイザのファイルを保存します。

```py
model.save_pretrained("<path_to_dummy_folder>")
tokenizer.save_pretrained("<path_to_dummy_folder>")
```

`<path_to_dummy_folder>` には、モデルとトークナイザのファイルがすべて含まれました。通常の Git のワークフローに従って、ファイルをステージングエリアに追加し、コミットして、Hub にプッシュします。

```py
repo.git_add()
repo.git_commit("Add model and tokenizer files")
repo.git_push()
```

おめでとうございます。Hub に初めてファイルをプッシュできました。

### Git ベースの方法[[the-git-based-approach]]

この方法では、Git と Git LFS を直接操作してファイルをアップロードします。これまで紹介した方法では面倒な処理が自動化されていましたが、今回は自分で操作する必要があります。いくつか注意点もあるので、少し複雑なケースを例に手順を説明します。

この方法を使うには、Git と Git LFS が必要です。始める前に両方をインストールし、Git LFS の設定も済ませてください。[Git LFS](https://git-lfs.github.com/) のリンク先でインストール手順を確認できます。

まず Git LFS を初期化します。

```bash
git lfs install
```

```bash
Updated git hooks.
Git LFS initialized.
```

それが終わったら、最初のステップはモデルリポジトリをクローンすることです。

```bash
git clone https://huggingface.co/<namespace>/<your-model-id>
```

私のユーザー名は `lysandre` で、モデル名には `dummy` を使っています。そのため、実行するコマンドは次のようになります。

```
git clone https://huggingface.co/lysandre/dummy
```

作業ディレクトリに *dummy* という名前のフォルダができました。そのフォルダに `cd` して、中身を見てみましょう。

```bash
cd dummy && ls
```

```bash
README.md
```

`create_repo` メソッドを使ってリポジトリを作成したばかりであれば、このフォルダには隠しファイルの `.gitattributes` だけが含まれているはずです。前のセクションの指示に従って Web インターフェースでリポジトリを作成した場合は、ここに示すように、隠しファイルの `.gitattributes` とともに *README.md* ファイルが1つ含まれています。

設定ファイルや語彙ファイルなど、数メガバイト未満のファイルなら、通常の Git と同じ方法で追加できます。基本的に、このサイズのファイルはすべて同じように扱えます。一方、大きなファイルを *huggingface.co* にプッシュする場合は、Git LFS に登録する必要があります。

Python に少し戻って、ダミーリポジトリにコミットしたいモデルとトークナイザを生成しましょう。

{#if fw === 'pt'}
```py
from transformers import AutoModelForMaskedLM, AutoTokenizer

checkpoint = "camembert-base"

model = AutoModelForMaskedLM.from_pretrained(checkpoint)
tokenizer = AutoTokenizer.from_pretrained(checkpoint)

# モデルを使って自由に作業します。学習させたり、ファインチューニングしたり…

model.save_pretrained("<path_to_dummy_folder>")
tokenizer.save_pretrained("<path_to_dummy_folder>")
```

> [!TIP]
> ✏️ Web インターフェースからリポジトリを作成すると、*.gitattributes* ファイルが自動的に設定されます。これにより、*.bin* や *.h5* などの拡張子を持つファイルは大きなファイルとして扱われ、追加の設定をしなくても Git LFS によって追跡されます。

ここからは、通常の Git リポジトリと同じように操作できます。まず、`git add` コマンドを使って、すべてのファイルを Git のステージングエリアに追加します。

```bash
git add .
```

続いて、現在ステージングされているファイルを確認できます。

```bash
git status
```
