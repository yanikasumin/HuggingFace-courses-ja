メトリック深度と相対深度の単眼深度推定： 概要。Depth Anything V2 のファインチューニング 👐 📚

モデルの進化

過去10年間で、単眼深度推定モデルは目覚ましい進歩を遂げてきました。その進化を目で追ってみましょう。

出発点は、このような基本的なモデルでした。

そして、より洗練されたモデルへと進歩しました。

そして現在、最先端のモデルである Depth Anything V2 があります。

素晴らしいですね。

今日は、これらのモデルの仕組みを解き明かし、複雑な概念を分かりやすくします。さらに、カスタムデータセットを使って自前のモデルをファインチューニングします。「でも待って、」と思うかもしれません。「最新のモデルがどんな環境でもあれほど良い性能を出すのに、なぜ自前のデータセットでモデルをファインチューニングする必要があるの？」

ここにニュアンスや具体性が関わってきます。これこそ、まさにこの記事の焦点です。単眼深度推定の細部を探求したい方は、このまま読み進めてください。

基礎

「ところで、深度とは正確には何なの？」典型的には、各ピクセルが、カメラやセンサーからそのピクセルに対応する空間内の点までの距離を表す、単一チャンネルの画像です。しかし、これらの距離は絶対値の場合も相対値の場合もあることが分かっています。なんと！ - 絶対深度（Absolute Depth）: 各ピクセルの値が物理的な距離（メートルやセンチメートルなど）に直接対応します。 - 相対深度（Relative Depth）: ピクセルの値は、実世界の測定単位に言及することなく、どの点が近く、どの点が遠いかを示します。相対深度は逆転していることが多く、つまり数値が小さいほどその点は遠くにあります。

これらの概念については、あとでもう少し詳しく探ります。

「では、単眼（monocular）とは何を意味するの？」簡単に言えば、写真1枚だけを使って深度を推定する必要がある、ということです。その何が難しいのでしょうか。次を見てください。

ご覧のように、3D空間を2D平面に投影すると、遠近法のために曖昧さが生じることがあります。これに対処するために、ステレオビジョン、Structure from Motion、そしてより広い分野である写真測量（Photogrammetry）のような、複数の画像を使った深度推定の精密な数学的手法があります。さらに、レーザースキャナー（LiDAR など）のような技術も深度の測定に使えます。

相対深度と絶対（メトリック）深度の推定： その意義は？

相対深度推定の必要性を際立たせる課題をいくつか探ってみましょう。そして、より科学的に、いくつかの論文も参照しましょう。

メトリック深度を予測する利点は、コンピュータビジョンやロボティクスにおける多くの下流の応用、たとえばマッピング、計画、ナビゲーション、物体認識、3D再構成、画像編集にとって実用的に役立つことです。しかし、複数のデータセットにわたって単一のメトリック深度推定モデルを訓練すると、性能が低下することが多く、特に屋内と屋外の画像のように深度スケールの差が大きい画像を含むコレクションでは顕著です。その結果、現在の MDE モデルは通常、特定のデータセットに過学習し、他のデータセットへはうまく汎化しません。

この image-to-image タスクのアーキテクチャは典型的には、U-Net のようなエンコーダ・デコーダモデルにさまざまな変更を加えたものです。形式的には、これはピクセル単位の回帰問題です。数メートルから数百メートルまでの範囲で、各ピクセルの距離を正確に予測することが、ニューラルネットワークにとっていかに難しいか想像してみてください。
そこで、あらゆるシナリオで正確な距離を予測する万能モデルから離れるという発想に行き着きます。代わりに、どの物体が他の物体や私たちに対して遠くにあり、どれが近くにあるかを示すことでシーンの形状と構造を捉えながら、深度を大まかに（相対的に）予測するモデルを開発しましょう。正確な距離が必要であれば、このタスクについて既に理解していることを活かして、この相対モデルを特定のデータセットでファインチューニングできます。

注意しなければならない細部は、さらにあります。

モデルは、異なるカメラやカメラ設定で撮影された画像を扱わなければならないだけでなく、シーン全体のスケールの大きな変動に適応することも学ばなければなりません。

異なるスケールとは別に、先ほど述べたように、大きな問題はカメラ自体にあります。カメラは世界の見え方が大きく異なる場合があるのです。

焦点距離の変化が、背景の距離の知覚をいかに劇的に変えるか注目してください！

最後に、多くのデータセットには絶対深度マップが全くなく、相対的なものしかありません（たとえば、カメラキャリブレーションの不足のため）。さらに、深度を得る方法ごとに、それぞれ利点、欠点、バイアス、問題があります。

私たちは3つの大きな課題を特定します。1) 本質的に異なる深度の表現： 直接深度表現と逆深度表現。2) スケールの曖昧さ： 一部のデータソースでは、深度は未知のスケールまでしか与えられません。3) シフトの曖昧さ： 一部のデータセットは、未知のスケールまでの視差と、未知のベースラインと後処理による主点の水平シフトの関数である全体的な視差シフトまでの視差しか提供しません

視差（Disparity）とは、2つの異なる視点から見たときの物体の見かけの位置の差を指し、ステレオビジョンで深度を推定するのによく使われます。

要するに、インターネット上にあるばらばらの深度マップをただ集めて、ピクセル単位の MSE のようなものでモデルを訓練することはできない、と納得していただけたかと思います。

では、これらすべての変動をどうやって均一化するのでしょうか。違いからできるだけ抽象化し、これらすべてのデータセットから共通点、すなわちシーンの形状と構造、物体同士の比例関係、何が近く何が遠いか、をどうやって抽出するのでしょうか。

スケール・シフト不変損失 😎

簡単に言えば、訓練に使いたいすべての深度マップと、指標の評価に使う深度マップに対して、何らかの正規化を行う必要があります。ここにアイデアがあります。環境のスケールやさまざまなシフトを考慮しない損失関数を作りたいのです。残るタスクは、このアイデアを数学的な言葉に翻訳することです。

具体的には、深度値はまず \( d = \frac{1}{t} \) によって視差空間に変換され、次に各深度マップについて \( 0 \sim 1 \) に正規化されます。複数データセットの共同訓練を可能にするために、各サンプルの未知のスケールとシフトを無視するアフィン不変損失を採用します： $$\mathcal{L}1 = \frac{1}{HW} \sum \rho(d_i^}^{HW, d_i),$$ ここで \( d_i^ \) と \( d_i \) はそれぞれ予測と正解です。また \( \rho \) はアフィン不変の平均絶対誤差損失です： \( \rho(d_i^, d_i) = \left| \hat{d}_i^ - \hat{d}_i \right| \)。ここで \( \hat{d}_i^* \) と \( \hat{d}_i \) は、予測 \( d_i^* \) と正解 \( d_i \) をスケーリングしシフトしたバージョンです： $$\hat{d}i = \frac{d_i - t(d)}{s(d)},$$ ここで \( t(d) \) と \( s(d) \) は、予測と正解を平行移動ゼロ・スケール1に揃えるために使われます： $$t(d) = \mathrm{median}(d), \quad s(d) = \frac{1}{HW} \sum \left| d_i - t(d) \right|.$$}^{HW

実際には、スケールとシフトを取り除くのに役立つ方法や関数は他にも数多くあります。損失関数へのさまざまな追加もあり、たとえばピクセルの値自体ではなく、それがどれだけ速く変化するかに焦点を当てる勾配損失（gradient loss）（名前の由来はまさにそれです）があります。これについては MiDaS の論文で詳しく読めます。有用な文献のリストは末尾に含めます。最も面白い部分、つまりカスタムデータセットを使った絶対深度のファインチューニングに進む前に、指標について簡単に議論しましょう。

指標

深度推定では、性能を評価するためにいくつかの標準的な指標が使われます。MAE（平均絶対誤差）、RMSE（二乗平均平方根誤差）、そして距離の大きな隔たりを滑らかにするためのそれらの対数バリエーションなどです。さらに、次も考慮してください。 - 絶対相対誤差（Absolute Relative Error, AbsRel）: この指標は MAE に似ていますが、パーセンテージで表され、予測した距離が真の距離から平均して何パーセント異なるかを測ります。
\(\text{AbsRel} = \frac{1}{N} \sum_{i=1}^{N} \frac{|d_i - \hat{d}_i|}{d_i}\) - 閾値精度（Threshold Accuracy, \(\delta_1\)): これは、予測ピクセルが真のピクセルから25%以内しか異ならないピクセルの割合を測ります。
\(\delta_1 = \text{ proportion of predicted depths where } \max\left(\frac{d_i}{\hat{d}_i}, \frac{\hat{d}_i}{d_i}\right) < 1.25\)

重要な考慮事項

私たちのすべてのモデルとベースラインについて、誤差を測定する前に、画像ごとに予測と正解のスケールとシフトを揃えます。

確かに、相対深度を予測するよう訓練しているのに、絶対値を持つデータセットで品質を測りたい場合、そしてこのデータセットでのファインチューニングや絶対値自体には関心がない場合、損失関数と同様に、スケールとシフトを計算から除外し、すべてを統一した尺度に標準化できます。

指標の計算方法4つ

これらの方法を理解すると、論文の指標を分析する際の混乱を避けるのに役立ちます。

  1. ゼロショット相対深度推定
    • あるデータセットの集合で相対深度を予測するよう訓練し、他のデータセットで品質を測ります。深度は相対的なものなので、大きく異なるスケールは問題にならず、他のデータセットでの指標は通常、訓練データセットのテストセットと同様に高いままです。

  1. ゼロショット絶対深度推定
    • 万能な相対モデルを訓練し、次に絶対深度を予測するための良いデータセットでそれをファインチューニングし、別のデータセットで絶対深度予測の品質を測ります。この場合の指標は前の方法に比べて悪くなる傾向があり、異なる環境にわたって絶対深度をうまく予測することの難しさを際立たせます。

  1. ファインチューニング済み（インドメイン）絶対深度推定
    • 前の方法と似ていますが、今度は絶対深度予測のファインチューニングに使ったデータセットのテストセットで品質を測ります。これは最も実用的なアプローチの1つです。

  1. ファインチューニング済み（インドメイン）相対深度推定
    • 相対深度を予測するよう訓練し、訓練データセットのテストセットで品質を測ります。最も正確な名前ではないかもしれませんが、考え方は単純です。

Depth Anything V2 の背後にある重要なアイデア

Depth Anything V2 は深度推定のための強力なモデルであり、いくつかの革新的な概念のおかげで目覚ましい結果を達成しています。

  • 異種データに対する万能な訓練手法: MiDaS の2020年の論文で導入されたこの手法により、さまざまなタイプのデータセットにわたる堅牢な訓練が可能になります。
  • DPT アーキテクチャ: 「Vision Transformers for Dense Prediction」の論文が提示するこのアーキテクチャは、本質的には Vision Transformer（ViT）エンコーダを持つ U-Net に、いくつかの変更を加えたものです。

  • DINOv2 エンコーダ: 大規模なデータセットで自己教師あり手法により事前訓練されたこの標準的な ViT は、強力で汎用的な特徴抽出器として機能します。近年、CV の研究者たちは NLP における GPT や BERT のような基盤モデルを作ることを目指してきました。DINOv2 はその方向への重要な一歩です。
  • 合成データの使用: 訓練パイプラインは、以下の画像で非常によく説明されています。このアプローチにより、著者たちは深度マップにおけるこれほどの明瞭さと正確さを達成できました。結局のところ、考えてみれば、合成データから得られるラベルは真の「正解（ground truth）」なのです。

                Resize(
                    width=net_w,
                    height=net_h,
                    resize_target=True if mode == "train" else False,
                    keep_aspect_ratio=True,
                    ensure_multiple_of=14,
                    resize_method="lower_bound",
                    image_interpolation_method=cv2.INTER_CUBIC,
                ),
                NormalizeImage(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]),
                PrepareForNet(),
            ]
            + ([Crop(size[0])] if self.mode == "train" else [])
        )

        # 論文では水平反転のみ
        self.augs = A.Compose(
            [
                A.HorizontalFlip(),
                A.ColorJitter(hue=0.1, contrast=0.1, brightness=0.1, saturation=0.1),
                A.GaussNoise(var_limit=25),
            ]
        )

    def __getitem__(self, item):
        path = self.paths[item]
        image, depth = self.h5_loader(path)

        if self.mode == "train":
            augmented = self.augs(image=image, mask=depth)
            image = augmented["image"] / 255.0
            depth = augmented["mask"]
        else:
            image = image / 255.0

        sample = self.transform({"image": image, "depth": depth})

        sample["image"] = torch.from_numpy(sample["image"])
        sample["depth"] = torch.from_numpy(sample["depth"])

        # データセットにはノイズなどのために有効な深度のマスクが含まれている場合がある
        #         sample['valid_mask'] = ...

        return sample

    def __len__(self):
        return len(self.paths)

    def h5_loader(self, path):
        h5f = h5py.File(path, "r")
        rgb = np.array(h5f["rgb"])
        rgb = np.transpose(rgb, (1, 2, 0))
        depth = np.array(h5f["depth"])
        return rgb, depth

注意すべき点をいくつか挙げます。 - 元の NYU-D データセットには407kのサンプルが含まれていますが、私たちは40kのサブセットを使っています。これは最終的なモデルの品質にわずかに影響します。 - 論文の著者らは、データ拡張として水平反転のみを使いました。 - 深度マップ内の一部の点が正しく処理されず、「不良ピクセル」になる場合があります。一部のデータセットには、画像と深度マップに加えて、有効なピクセルと無効なピクセルを区別するマスクが含まれています。このマスクは、不良ピクセルを損失と指標の計算から除外するために必要です。

  • 訓練中は、短い方の辺が518ピクセルになるよう画像をリサイズしてから切り取ります。検証では、深度マップの切り取りやリサイズはしません。代わりに、予測された深度マップをアップサンプリングし、元の解像度で指標を計算します。

ステップ6: データローダーの準備

def get_dataloaders(batch_size):

    train_dataset = NYU(train_paths, mode="train")
    val_dataset = NYU(val_paths, mode="val")

    train_dataloader = torch.utils.data.DataLoader(
        train_dataset, batch_size=batch_size, shuffle=True, num_workers=4, drop_last=True
    )

    val_dataloader = torch.utils.data.DataLoader(
        val_dataset,
        batch_size=1,  # パディングなしで動的な解像度の評価を行うため
        shuffle=False,
        num_workers=4,
        drop_last=True,
    )

    return train_dataloader, val_dataloader

ステップ7: 指標の評価

def eval_depth(pred, target):
    assert pred.shape == target.shape

    thresh = torch.max((target / pred), (pred / target))

    d1 = torch.sum(thresh < 1.25).float() / len(thresh)

    diff = pred - target
    diff_log = torch.log(pred) - torch.log(target)

    abs_rel = torch.mean(torch.abs(diff) / target)

    rmse = torch.sqrt(torch.mean(torch.pow(diff, 2)))
    mae = torch.mean(torch.abs(diff))

    silog = torch.sqrt(
        torch.pow(diff_log, 2).mean() - 0.5 * torch.pow(diff_log.mean(), 2)
    )

    return {
        "d1": d1.detach(),
        "abs_rel": abs_rel.detach(),
        "rmse": rmse.detach(),
        "mae": mae.detach(),
        "silog": silog.detach(),
    }

私たちの損失関数は SiLog です。絶対深度で訓練する際には、相対深度の訓練で使ったスケールへの不変性などの手法は忘れるべきだと思えるかもしれません。しかし、実際にはそれは完全には正しくなく、程度は小さいものの、ある種の「スケール正則化」を使いたい場合がよくあります。パラメータ λ=0.5 は、全体の一貫性と局所的な正確さのバランスを取るのに役立ちます。

ステップ9: 訓練関数

def train_fn():

    set_seed(seed)
    ddp_kwargs = DistributedDataParallelKwargs(find_unused_parameters=True)
    accelerator = Accelerator(
        mixed_precision=mixed_precision,
        kwargs_handlers=[ddp_kwargs],
    )

    # 論文ではデコーダをランダムに初期化し、エンコーダの事前訓練済み重みのみを使う。その後、全体をファインチューニングする
    # ここでは ViT-S エンコーダ
    model = DepthAnythingV2(**{**model_configs[model_encoder], "max_depth": max_depth})
    model.load_state_dict(
        {k: v for k, v in torch.load(model_weights_path).items() if "pretrained" in k},
        strict=False,
    )

    optim = torch.optim.AdamW(
        [
            {
                "params": [
                    param
                    for name, param in model.named_parameters()
                    if "pretrained" in name
                ],
                "lr": lr,
            },
            {
                "params": [
                    param
                    for name, param in model.named_parameters()
                    if "pretrained" not in name
                ],
                "lr": lr * 10,
            },
        ],
        lr=lr,
        weight_decay=weight_decay,
    )

    criterion = SiLogLoss()  # 著者らの損失関数

    train_dataloader, val_dataloader = get_dataloaders(batch_size)

    scheduler = transformers.get_cosine_schedule_with_warmup(
        optim,
        len(train_dataloader) * warmup_epochs,
        num_epochs * scheduler_rate * len(train_dataloader),
    )

    model, optim, train_dataloader, val_dataloader, scheduler = accelerator.prepare(
        model, optim, train_dataloader, val_dataloader, scheduler
    )

    if load_state:
        accelerator.wait_for_everyone()
        accelerator.load_state(state_path)

    best_val_absrel = 1000

    for epoch in range(1, num_epochs):

        model.train()
        train_loss = 0
        for sample in tqdm(
            train_dataloader, disable=not accelerator.is_local_main_process
        ):
            optim.zero_grad()

            img, depth = sample["image"], sample["depth"]

            pred = model(img)
            # マスク
            loss = criterion(pred, depth, (depth <= max_depth) & (depth >= 0.001))

            accelerator.backward(loss)
            optim.step()
            scheduler.step()

            train_loss += loss.detach()

        train_loss /= len(train_dataloader)
        train_loss = accelerator.reduce(train_loss, reduction="mean").item()

        model.eval()
        results = {"d1": 0, "abs_rel": 0, "rmse": 0, "mae": 0, "silog": 0}
        for sample in tqdm(val_dataloader, disable=not accelerator.is_local_main_process):

            img, depth = sample["image"].float(), sample["depth"][0]

            with torch.no_grad():
                pred = model(img)
                # 元の解像度で評価する
                pred = F.interpolate(
                    pred[:, None], depth.shape[-2:], mode="bilinear", align_corners=True
                )[0, 0]

            valid_mask = (depth <= max_depth) & (depth >= 0.001)

            cur_results = eval_depth(pred[valid_mask], depth[valid_mask])

            for k in results.keys():
                results[k] += cur_results[k]

        for k in results.keys():
            results[k] = results[k] / len(val_dataloader)
            results[k] = round(accelerator.reduce(results[k], reduction="mean").item(), 3)

        accelerator.wait_for_everyone()
        accelerator.save_state(state_path, safe_serialization=False)

        if results["abs_rel"] < best_val_absrel:
            best_val_absrel = results["abs_rel"]
            unwrapped_model = accelerator.unwrap_model(model)
            if accelerator.is_local_main_process:
                torch.save(unwrapped_model.state_dict(), save_model_path)

        accelerator.print(
            f"epoch_{epoch},  train_loss = {train_loss:.5f}, val_metrics = {results}"
        )


# 追伸。ある構成をテストしている際に、損失が nan になるエラーに遭遇しました。
# これは、0 での割り算を防ぐために予測に小さなイプシロンを加えることで修正されます

論文では、著者らはデコーダをランダムに初期化し、エンコーダの重みのみを使います。その後、モデル全体をファインチューニングします。その他の注目すべき点は次のとおりです。 - デコーダとエンコーダで異なる学習率を使う。エンコーダの学習率は低くします。ランダムに初期化されたデコーダとは異なり、既に優れた重みを大きく変えたくはないためです。 - 著者らは論文で多項式スケジューラを使いましたが、私は好みでウォームアップ付きのコサインスケジューラを使いました。 - マスクでは、先に述べたように、「depth >= 0.001」という条件を使うことで、深度マップのブラックホールを避けます - 訓練サイクルでは、リサイズされた深度マップに対して損失を計算します。検証では、予測をアップサンプリングし、元の解像度で指標を計算します。 - そして、HF accelerate を使うと、カスタムの PyTorch コードを分散コンピューティング用にいかに簡単にラップできるか見てください。
