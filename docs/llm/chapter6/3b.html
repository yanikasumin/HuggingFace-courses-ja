from transformers import pipeline

question_answerer = pipeline("question-answering")

🤗 Transformers is backed by the three most popular deep learning libraries — Jax, PyTorch, and TensorFlow — with a seamless integration
between them. It's straightforward to train your models with one before loading them for inference with the other.
"""
question = "Which deep learning libraries back 🤗 Transformers?"
question_answerer(question=question, context=context)

## 質問応答にモデルを使う

他のパイプラインと同様に、まず入力をトークン化してからモデルに通します。`question-answering` パイプラインでデフォルトで使われるチェックポイントは [`distilbert-base-cased-distilled-squad`](https://huggingface.co/distilbert-base-cased-distilled-squad) です（名前の "squad" は、モデルがファインチューニングされたデータセットに由来します。SQuAD データセットについては [Chapter 7](/course/chapter7/7) で詳しく説明します）。

質問と文脈をペアとして、質問を先にしてトークン化することに注意してください。

質問応答用のモデルは、これまで見てきたモデルとは少し異なる仕組みで動作します。上の図を例にすると、モデルは回答の開始トークンのインデックス（ここでは21）と、回答が終わるトークンのインデックス（ここでは24）を予測するよう学習されています。

その為、これらのモデルはロジットのテンソルを1つではなく2つ返します。1つは回答の開始トークンに対応するロジット用、もう1つは回答の終了トークンに対応するロジット用です。この場合は66トークンを含む入力が1つだけなので、次のようになります。

start_logits = outputs.start_logits
end_logits = outputs.end_logits
print(start_logits.shape, end_logits.shape)

{#if fw === 'pt'}

```python out torch.Size([1, 66]) torch.Size([1, 66])

{:else}

```python out
(1, 66) (1, 66)

これらのロジットを確率に変換する為に softmax 関数を適用しますが、その前に、文脈の一部ではないインデックスを確実にマスクする必要があります。入力は [CLS] question [SEP] context [SEP] なので、質問のトークンと [SEP] トークンをマスクする必要があります。但し [CLS] トークンは保持します。一部のモデルは、回答が文脈に含まれていないことを示す為にそれを使う為です。

後で softmax を適用する為、マスクしたいロジットを大きな負の数に置き換えるだけで済みます。ここでは -10000 を使います。

{#if fw === 'pt'}

import torch

sequence_ids = inputs.sequence_ids()
# 文脈のトークン以外をすべてマスクする
mask = [i != 1 for i in sequence_ids]
# [CLS] トークンのマスクを解除する
mask[0] = False
mask = torch.tensor(mask)[None]

start_logits[mask] = -10000
end_logits[mask] = -10000

{:else}

import tensorflow as tf

sequence_ids = inputs.sequence_ids()
# 文脈のトークン以外をすべてマスクする
mask = [i != 1 for i in sequence_ids]
# [CLS] トークンのマスクを解除する
mask[0] = False
mask = tf.constant(mask)[None]

start_logits = tf.where(mask, -10000, start_logits)
end_logits = tf.where(mask, -10000, end_logits)

{/if}

予測したくない位置に対応するロジットを適切にマスク出来たので、softmax を適用出来ます。

{#if fw === 'pt'}

start_probabilities = torch.nn.functional.softmax(start_logits, dim=-1)[0]
end_probabilities = torch.nn.functional.softmax(end_logits, dim=-1)[0]

{:else}

start_probabilities = tf.math.softmax(start_logits, axis=-1)[0].numpy()
end_probabilities = tf.math.softmax(end_logits, axis=-1)[0].numpy()

{/if}

この段階で、開始確率と終了確率の argmax を取ることも出来ますが、終了インデックスより大きい開始インデックスになってしまう可能性がある為、もう少し注意が必要です。start_index <= end_index を満たす各 start_index と end_index の組み合わせの確率を計算し、確率が最も高いタプル (start_index, end_index) を取ります。

事象「回答が start_index から始まる」と「回答が end_index で終わる」が独立であると仮定すると、回答が start_index から始まって end_index で終わる確率は次の通りです。

$$\mathrm{start_probabilities}[\mathrm{start_index}] \times \mathrm{end_probabilities}[\mathrm{end_index}]$$

従って、全てのスコアを計算するには、start_index <= end_index の範囲で積 (\mathrm{start_probabilities}[\mathrm{start_index}] \times \mathrm{end_probabilities}[\mathrm{end_index}]) を全て計算するだけです。

まず、可能な積を全て計算しましょう。

scores = start_probabilities[:, None] * end_probabilities[None, :]

{#if fw === 'pt'}

次に、start_index > end_index の値を 0 に設定してマスクします（他の確率は全て正の数です）。torch.triu() 関数は、引数として渡された2次元テンソルの上三角部分を返す為、そのマスキングを行ってくれます。

scores = torch.triu(scores)

{:else}

次に、start_index > end_index の値を 0 に設定してマスクします（他の確率は全て正の数です）。np.triu() 関数は、引数として渡された2次元テンソルの上三角部分を返す為、そのマスキングを行ってくれます。

import numpy as np

scores = np.triu(scores)

{/if}

あとは最大値のインデックスを取得するだけです。PyTorch は平坦化されたテンソルでのインデックスを返す為、start_index と end_index を得るには床除算 // と剰余 % の演算を使う必要があります。

max_index = scores.argmax().item()
start_index = max_index // scores.shape[1]
end_index = max_index % scores.shape[1]
print(scores[start_index, end_index])

まだ完全には終わっていませんが、少なくとも回答の正しいスコアは既に得られています（前のセクションの最初の結果と比較すれば確認出来ます）。

## 長い文脈の処理

以前に例として使った質問と長い文脈をトークン化しようとすると、`question-answering` パイプラインで使われる最大長（384）を超えるトークン数が得られます。

```py
inputs = tokenizer(question, long_context)
print(len(inputs["input_ids"]))

```python out 461

その為、入力をその最大長で切り詰める必要があります。これを行う方法はいくつかありますが、切り詰めたいのは質問ではなく文脈だけです。文脈は2番目の文なので、`"only_second"` の切り詰め戦略を使います。

その場合に生じる問題は、質問への回答が切り詰められた文脈に含まれていない可能性があることです。例えば、ここでは回答が文脈の末尾寄りにある質問を選んだ為、切り詰めるとその回答が含まれなくなります。

```py
inputs = tokenizer(question, long_context, max_length=384, truncation="only_second")
print(tokenizer.decode(inputs["input_ids"]))

つまり、モデルは正しい回答を選ぶのが難しくなります。これを解決する為に、`question-answering` パイプラインでは最大長を指定して文脈をより小さいチャンクに分割出来ます。また、回答を含む箇所がチャンクの境界で分断されないように、隣接するチャンクには一部重複する範囲を設けます。

`return_overflowing_tokens=True` を追加すれば、トークナイザ（高速・低速を問わず）にこの処理を行わせることが出来、重なりの量は `stride` 引数で指定出来ます。小さい文を使った例を示します。

```py

    sentence, truncation=True, return_overflowing_tokens=True, max_length=6, stride=2
)

for ids in inputs["input_ids"]:
    print(tokenizer.decode(ids))

（入力文の訳：この文はそれ程長くありませんが、それでも分割します）

さて、長い文脈に戻りましょう。デフォルトでは、`question-answering` パイプラインは前述の通り最大長384とストライド128を使います。これらはモデルがファインチューニングされた方法に対応しています（パイプラインの呼び出し時に `max_seq_len` と `stride` 引数を渡せば、これらのパラメータを調整出来ます）。

従って、トークン化の際にもこれらのパラメータを使います。パディング（サンプルを同じ長さにしてテンソルを構築出来るようにする為）も追加し、オフセットも要求します。

    scores = start_probs[:, None] * end_probs[None, :]
    idx = torch.triu(scores).argmax().item()

    start_idx = idx // scores.shape[1]
    end_idx = idx % scores.shape[1]
    score = scores[start_idx, end_idx].item()
    candidates.append((start_idx, end_idx, score))
