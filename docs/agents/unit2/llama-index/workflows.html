LlamaIndex でエージェントワークフローを作成する

LlamaIndex のワークフローを使うと、コードを順序立てられた管理しやすいステップへ構造化できます。

ワークフローは、Events によってトリガーされる Steps を定義することで作成します。各ステップは、さらに次のステップをトリガーする Events を自ら発行します。 RAG タスク向けの LlamaIndex ワークフローを示す Alfred の例を見てみましょう。

ワークフローには、次のような重要な利点があります。

  • コードを独立したステップへ明確に整理できる
  • 柔軟な制御フローを実現するイベント駆動アーキテクチャ
  • ステップ間で型安全に通信できる
  • 状態管理が組み込まれている
  • シンプルなエージェント連携から複雑なエージェント連携まで対応できる

お察しのとおり、ワークフローは、エージェントの自律性を活かしながら、ワークフロー全体の制御も維持できる、絶妙なバランスを実現します。

では、自分でワークフローを作成する方法を学びましょう。

基本的なワークフローの作成

Workflow パッケージをインストールする LlamaHub に関するセクション で紹介したように、Workflow パッケージは次のコマンドでインストールできます。 
pip install llama-index-utils-workflow

Workflow を継承したクラスを定義し、関数に @step デコレータを付けることで、1 ステップのワークフローを作成できます。 あわせて、ワークフローの開始と終了を示すための特殊なイベントである StartEvent と StopEvent も必要です。

from llama_index.core.workflow import StartEvent, StopEvent, Workflow, step

class MyWorkflow(Workflow):
    @step
    async def my_step(self, ev: StartEvent) -> StopEvent:
        # ここで何らかの処理を行う
        return StopEvent(result="Hello, world!")


w = MyWorkflow(timeout=10, verbose=False)
result = await w.run()

ご覧のとおり、w.run() を呼び出すことでワークフローを実行できます。

複数のステップをつなげる

複数のステップをつなげるには、ステップ間でデータを運ぶカスタムイベントを作成します。 そのためには、ステップ間で受け渡される Event を追加し、最初のステップの出力を 2 番目のステップへ渡せるようにします。

from llama_index.core.workflow import Event

class ProcessingEvent(Event):
    intermediate_result: str

class MultiStepWorkflow(Workflow):
    @step
    async def step_one(self, ev: StartEvent) -> ProcessingEvent:
        # 初期データを処理する
        return ProcessingEvent(intermediate_result="Step 1 complete")

    @step
    async def step_two(self, ev: ProcessingEvent) -> StopEvent:
        # 中間結果を使う
        final_result = f"Finished processing: {ev.intermediate_result}"
        return StopEvent(result=final_result)

w = MultiStepWorkflow(timeout=10, verbose=False)
result = await w.run()
result

ここでは型ヒントが重要です。ワークフローが正しく実行されることを保証する役割を果たします。もう少し複雑な例にしてみましょう。

ループと分岐

型ヒントはワークフローの最も強力な部分です。これにより分岐、ループ、合流を作成でき、より複雑なワークフローを実現できます。

和集合演算子 | を使ってループを作成する例を示します。 以下の例では、LoopEvent がステップへの入力として受け取られ、出力として返すこともできる様子が分かります。

from llama_index.core.workflow import Event
import random


class ProcessingEvent(Event):
    intermediate_result: str


class LoopEvent(Event):
    loop_output: str


class MultiStepWorkflow(Workflow):
    @step
    async def step_one(self, ev: StartEvent | LoopEvent) -> ProcessingEvent | LoopEvent:
        if random.randint(0, 1) == 0:
            print("Bad thing happened")
            return LoopEvent(loop_output="Back to step one.")
        else:
            print("Good thing happened")
            return ProcessingEvent(intermediate_result="First step complete.")

    @step
    async def step_two(self, ev: ProcessingEvent) -> StopEvent:
        # 中間結果を使う
        final_result = f"Finished processing: {ev.intermediate_result}"
        return StopEvent(result=final_result)


w = MultiStepWorkflow(verbose=False)
result = await w.run()
result

状態管理

状態管理は、ワークフローの状態を追跡し、すべてのステップが同じ状態にアクセスできるようにしたい場合に役立ちます。 ステップ関数のパラメータに Context の型ヒントを追加することで実現できます。

from llama_index.core.workflow import Context, StartEvent, StopEvent


@step
async def query(self, ctx: Context, ev: StartEvent) -> StopEvent:
    # クエリをコンテキストに保存する
    await ctx.store.set("query", "What is the capital of France?")

    # コンテキストとイベントを使って何らかの処理を行う
    val = ...

    # コンテキストからクエリを取り出す
    query = await ctx.store.get("query")

    return StopEvent(result=val)

これで、LlamaIndex で基本的なワークフローを作成する方法が分かりました。

ワークフローにはさらに複雑なニュアンスもあります。詳細は LlamaIndex のドキュメント で学べます。

ただし、ワークフローを作成する別の方法もあります。AgentWorkflow クラスを使う方法です。このクラスを使ってマルチエージェントワークフローを作成する方法を見てみましょう。

AgentWorkflow でワークフローを自動化する

手動でワークフローを作成する代わりに、AgentWorkflow クラスを使ってマルチエージェントワークフローを作成できます。 AgentWorkflow は Workflow Agents を使い、それぞれの専門能力に応じて連携したりタスクを引き継いだりできる、1 つ以上のエージェントからなるシステムを作成できるようにします。 これにより、異なるエージェントがタスクの異なる側面を担当する、複雑なエージェントシステムを構築できます。 エージェントのクラスは、llama_index.core.agent からではなく、llama_index.core.agent.workflow からインポートします。 AgentWorkflow のコンストラクタでは、1 つのエージェントをルートエージェントとして指定しなければなりません。 ユーザーメッセージが届くと、まずルートエージェントへ振り分けられます。

各エージェントは、次のいずれかを行えます。

  • 自分のツールを使ってリクエストを直接処理する
  • そのタスクにより適した別のエージェントへ引き継ぐ
  • ユーザーへ応答を返す

マルチエージェントワークフローの作成方法を見てみましょう。

from llama_index.core.agent.workflow import AgentWorkflow, ReActAgent
from llama_index.llms.huggingface_api import HuggingFaceInferenceAPI

# ツールをいくつか定義する
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b

def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b

llm = HuggingFaceInferenceAPI(model_name="Qwen/Qwen2.5-Coder-32B-Instruct")

# FunctionTool を使わずに関数を直接渡すことができる。関数と docstring から名前と説明が解析される
multiply_agent = ReActAgent(
    name="multiply_agent",
    description="Is able to multiply two integers",
    system_prompt="A helpful assistant that can use a tool to multiply numbers.",
    tools=[multiply],
    llm=llm,
)

addition_agent = ReActAgent(
    name="add_agent",
    description="Is able to add two integers",
    system_prompt="A helpful assistant that can use a tool to add numbers.",
    tools=[add],
    llm=llm,
)

# ワークフローを作成する
workflow = AgentWorkflow(
    agents=[multiply_agent, addition_agent],
    root_agent="multiply_agent",
)

# システムを実行する
response = await workflow.run(user_msg="Can you add 5 and 3?")

エージェントツールは、先ほど触れたワークフローの状態を変更することもできます。ワークフローを開始する前に、すべてのエージェントが利用できる初期状態の dict を渡せます。 状態はワークフローコンテキストの state キーに保存されます。そして、新しいユーザーメッセージごとに付加される state_prompt へ注入されます。

前の例を変更して、関数呼び出しの回数を数えるカウンタを注入してみましょう。

from llama_index.core.workflow import Context

# ツールをいくつか定義する
async def add(ctx: Context, a: int, b: int) -> int:
    """Add two numbers."""
    # カウンタを更新する
    cur_state = await ctx.store.get("state")
    cur_state["num_fn_calls"] += 1
    await ctx.store.set("state", cur_state)

    return a + b

async def multiply(ctx: Context, a: int, b: int) -> int:
    """Multiply two numbers."""
    # カウンタを更新する
    cur_state = await ctx.store.get("state")
    cur_state["num_fn_calls"] += 1
    await ctx.store.set("state", cur_state)

    return a * b

...

workflow = AgentWorkflow(
    agents=[multiply_agent, addition_agent],
    root_agent="multiply_agent",
    initial_state={"num_fn_calls": 0},
    state_prompt="Current state: {state}. User message: {msg}",
)

# コンテキスト付きでワークフローを実行する
ctx = Context(workflow)
response = await workflow.run(user_msg="Can you add 5 and 3?", ctx=ctx)

# 状態を取り出して確認する
state = await ctx.store.get("state")
print(state["num_fn_calls"])
