完全な学習ループ

ここでは、Trainer クラスを使わずに、PyTorch の現代的なベストプラクティスに沿って学習ループをゼロから実装し、前のセクションと同じ結果を得る方法を見ていきます。前提として、セクション2のデータ処理は済んでいるものとします。必要なものをまとめた短いコードがこちらです。

💡 ヒント

🏗️ ゼロからの学習: このセクションはこれまでの内容を前提としています。PyTorch の学習ループとベストプラクティスの詳しいガイドは、🤗 Transformers の学習ドキュメント と カスタム学習クックブック を参照してください。

from datasets import load_dataset
from transformers import AutoTokenizer, DataCollatorWithPadding

raw_datasets = load_dataset("glue", "mrpc")
checkpoint = "bert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(checkpoint)


def tokenize_function(example):
    return tokenizer(example["sentence1"], example["sentence2"], truncation=True)


tokenized_datasets = raw_datasets.map(tokenize_function, batched=True)
data_collator = DataCollatorWithPadding(tokenizer=tokenizer)

学習の準備

学習ループを実際に書く前に、いくつかオブジェクトを定義する必要があります。最初は、バッチを反復処理するためのデータローダです。ただし、データローダを定義する前に、tokenized_datasets に少し後処理を施す必要があります。Trainer が自動でやってくれていた処理です。具体的には、次のことが必要です。

  • モデルが想定していない値の列（sentence1 列や sentence2 列など）を削除する
  • 列 label を labels にリネームする（モデルは引数名が labels であることを想定しているため）
  • データセットの形式を設定し、リストではなく PyTorch テンソルを返すようにする

tokenized_datasets には、これらのステップに対応するメソッドがそれぞれ用意されています。

tokenized_datasets = tokenized_datasets.remove_columns(["sentence1", "sentence2", "idx"])
tokenized_datasets = tokenized_datasets.rename_column("label", "labels")
tokenized_datasets.set_format("torch")
tokenized_datasets["train"].column_names

結果として、モデルが受け付ける列だけが残っていることを確認できます。

["attention_mask", "input_ids", "labels", "token_type_ids"]

これで、データローダを簡単に定義できます。

from torch.utils.data import DataLoader

train_dataloader = DataLoader(
    tokenized_datasets["train"], shuffle=True, batch_size=8, collate_fn=data_collator
)
eval_dataloader = DataLoader(
    tokenized_datasets["validation"], batch_size=8, collate_fn=data_collator
)

データ処理に間違いがないか手早く確認するために、バッチを次のように調べられます。

for batch in train_dataloader:

{k: v.shape for k, v in batch.items()}

学習用データローダでは `shuffle=True` を設定し、バッチ内の最大長に合わせてパディングしているため、実際の形状はおそらく少し異なります。

これでデータの前処理が完了しました（機械学習の実務では、前処理をここまで終えるのもなかなか大変です）。次はモデルです。前のセクションとまったく同じようにインスタンス化します。

```py
from transformers import AutoModelForSequenceClassification

model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)

学習が問題なく進むことを確認するために、バッチをこのモデルに渡してみます。

outputs = model(**batch)
print(outputs.loss, outputs.logits.shape)

```python out tensor(0.5441, grad_fn=) torch.Size([8, 2])

🤗 Transformers のモデルはすべて、`labels` が与えられると損失を返します。ロジットも得られます（バッチ内の各入力につき2つなので、サイズ 8 x 2 のテンソルです）。

学習ループを書く準備はほぼ整いました。あと2つ、オプティマイザと学習率スケジューラが足りません。`Trainer` がやっていたことを手作業で再現するので、同じデフォルトを使います。`Trainer` が使うオプティマイザは `AdamW` です。これは Adam と同じですが、重み減衰による正則化の工夫が加わっています（Ilya Loshchilov と Frank Hutter による ["Decoupled Weight Decay Regularization"](https://arxiv.org/abs/1711.05101) を参照）。

```py
from torch.optim import AdamW

optimizer = AdamW(model.parameters(), lr=5e-5)

💡 ヒント

💡 現代的な最適化のヒント: さらに性能を高めたい場合は、次を試せます。 - 重み減衰ありの AdamW: AdamW(model.parameters(), lr=5e-5, weight_decay=0.01) - 8-bit Adam: bitsandbytes を使ったメモリ効率のよい最適化 - 学習率の調整: 大きなモデルでは、低めの学習率（1e-5 〜 3e-5）がうまくいくことが多い

🚀 最適化のリソース: オプティマイザと学習戦略の詳細は 🤗 Transformers 最適化ガイド を参照してください。

最後に、デフォルトの学習率スケジューラは、最大値（5e-5）から 0 まで線形に減衰させるだけのものです。これを正しく定義するには、実行する学習ステップ数を知る必要があります。ステップ数は、実行したいエポック数に学習バッチ数（学習用データローダの長さ）を掛けたものです。Trainer のデフォルトは3エポックなので、それに従います。

from transformers import get_scheduler

num_epochs = 3
num_training_steps = num_epochs * len(train_dataloader)
lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)
print(num_training_steps)

```python out 1377

### 学習ループ

最後にもう1つ。GPU を使える環境なら使いたいところです（CPU では、学習に数分ではなく数時間かかるかもしれません）。そのために、モデルとバッチを配置する `device` を定義します。

```py
import torch

device = torch.device("cuda") if torch.cuda.is_available() else torch.device("cpu")
model.to(device)
device

```python out device(type='cuda')

これで学習の準備が整いました。学習がいつ終わるか見当をつけるために、`tqdm` ライブラリを使って、学習ステップ数分のプログレスバーを追加します。

```py
from tqdm.auto import tqdm

progress_bar = tqdm(range(num_training_steps))

model.train()
for epoch in range(num_epochs):
    for batch in train_dataloader:
        batch = {k: v.to(device) for k, v in batch.items()}
        outputs = model(**batch)
        loss = outputs.loss
        loss.backward()

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

💡 ヒント

💡 現代的な学習の最適化: 学習ループをさらに効率化するには、次を検討してください。

  • 勾配クリッピング: optimizer.step() の前に torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0) を追加する
  • 混合精度: torch.cuda.amp.autocast() と GradScaler を使って学習を高速化する
  • 勾配累積: 複数のバッチにわたって勾配を蓄積し、大きなバッチサイズを擬似的に再現する
  • チェックポイント保存: 定期的にモデルのチェックポイントを保存し、中断しても再開できるようにする

🔧 実装ガイド: これらの最適化の詳しい例は、🤗 Transformers の効率的な学習ガイド と オプティマイザの一覧 を参照してください。

学習ループの核となる部分は、入門編で見たものとよく似ていることがわかります。学習状況を報告する処理は追加していないため、この学習ループだけではモデルの性能を把握できません。それには評価ループを追加する必要があります。

評価ループ

前と同じく、🤗 Evaluate ライブラリが提供する指標を使います。metric.compute() メソッドはすでに見ましたが、add_batch() メソッドを使えば、評価ループの実行中に、指標の計算に必要な予測結果と正解ラベルをバッチごとに蓄積できます。すべてのバッチを蓄積したら、metric.compute() で最終結果が得られます。評価ループでの実装は次のとおりです。

💡 ヒント

📊 評価のベストプラクティス: より高度な評価戦略と指標については、🤗 Evaluate のドキュメント と 包括的な評価クックブック を参照してください。

import evaluate

metric = evaluate.load("glue", "mrpc")
model.eval()
for batch in eval_dataloader:
    batch = {k: v.to(device) for k, v in batch.items()}
    with torch.no_grad():
        outputs = model(**batch)

    logits = outputs.logits
    predictions = torch.argmax(logits, dim=-1)
    metric.add_batch(predictions=predictions, references=batch["labels"])

metric.compute()

```python out

繰り返しになりますが、モデルヘッドの初期化とデータのシャッフルのランダム性があるため、結果は少し異なります。ただし、だいたい同じくらいの値になるはずです。

### 🤗 Accelerate で学習ループを強化する








先ほど定義した学習ループは、単一の CPU や GPU では問題なく動作します。しかし [🤗 Accelerate](https://github.com/huggingface/accelerate) ライブラリを使えば、わずかな変更で複数の GPU や TPU での分散学習が可能になります。分散学習、混合精度、デバイス配置の複雑な処理は、🤗 Accelerate が自動で引き受けてくれます。学習用と検証用のデータローダの作成から始めると、手作業の学習ループは次のようになります。

<div class="callout callout-tip" markdown="block">
<p class="callout-title">💡 ヒント</p>
⚡ **Accelerate の詳細**: 分散学習、混合精度、ハードウェア最適化のすべては [🤗 Accelerate のドキュメント](https://huggingface.co/docs/accelerate/) で学べます。実践的な例は [Transformers のドキュメント](https://huggingface.co/docs/transformers/main/en/accelerate) にあります。
</div>


```py
from accelerate import Accelerator
from torch.optim import AdamW
from transformers import AutoModelForSequenceClassification, get_scheduler

accelerator = Accelerator()

model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)
optimizer = AdamW(model.parameters(), lr=3e-5)

train_dl, eval_dl, model, optimizer = accelerator.prepare(
    train_dataloader, eval_dataloader, model, optimizer
)

num_epochs = 3
num_training_steps = num_epochs * len(train_dl)
lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)

progress_bar = tqdm(range(num_training_steps))

model.train()
for epoch in range(num_epochs):
    for batch in train_dl:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

最初に追加する行は import 文です。次に追加する行では Accelerator オブジェクトをインスタンス化します。これが環境を確認し、適切な分散セットアップを初期化します。デバイス配置は 🤗 Accelerate が処理してくれるので、モデルをデバイスに載せる行は削除できます（残したい場合は、device の代わりに accelerator.device を使うよう変更してください）。

作業の中心は、データローダ、モデル、オプティマイザを accelerator.prepare() に渡す行です。これにより各オブジェクトが分散学習に適した形でラップされ、分散学習が意図どおりに動作します。残りの変更は、バッチを device に載せる行の削除（これも残したい場合は accelerator.device を使うよう変更できます）と、loss.backward() を accelerator.backward(loss) に置き換えることです。

💡 ヒント

⚠️ Cloud TPU による高速化の恩恵を受けるには、トークナイザの padding="max_length" 引数と max_length 引数を使って、サンプルを固定長にパディングすることをおすすめします。

コピー＆ペーストして試せるように、🤗 Accelerate を使った完全な学習ループを載せておきます。

from accelerate import Accelerator
from torch.optim import AdamW
from transformers import AutoModelForSequenceClassification, get_scheduler

accelerator = Accelerator()

model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)
optimizer = AdamW(model.parameters(), lr=3e-5)

train_dl, eval_dl, model, optimizer = accelerator.prepare(
    train_dataloader, eval_dataloader, model, optimizer
)

num_epochs = 3
num_training_steps = num_epochs * len(train_dl)
lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)

progress_bar = tqdm(range(num_training_steps))

model.train()
for epoch in range(num_epochs):
    for batch in train_dl:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

セクションクイズ

カスタム学習ループと高度な学習テクニックの理解度をテストしましょう。

1. Adam オプティマイザと AdamW オプティマイザの主な違いは何ですか？

学習率のスケジューリングは、オプティマイザの選択とは別物です。
正解です！AdamW は重み減衰を勾配ベースのパラメータ更新から分離しており、よりよい正則化につながります。
AdamW は Transformer に限らず、あらゆるモデルアーキテクチャで使えます。
どちらのオプティマイザもメモリ要件は同程度です。

2. 学習ループにおける操作の正しい順序はどれですか？

惜しいですが、古い勾配が蓄積しないよう、次のフォワードパスの前に勾配をゼロにすべきです。
正解です！正しい順序は、損失の計算、勾配の計算、パラメータの更新、学習率の更新、そして勾配のクリアです。
損失から勾配を計算するには、バックワードパスはフォワードパスの後でなければなりません。
バックワードパスの前に勾配をゼロにすると、計算したばかりの勾配が消えてしまいます。

3. 🤗 Accelerate ライブラリは主に何を支援しますか？

Accelerate はモデルアーキテクチャ自体を最適化するものではありません。
Accelerate はハイパーパラメータ最適化を行いません。
正解です！Accelerate は分散学習の複雑さを引き受け、コードを単一デバイスでも複数デバイスでもシームレスに動作させます。
Accelerate は PyTorch の中で動作し、フレームワーク間の変換は行いません。

4. 学習ループでバッチをデバイスに移動するのはなぜですか？

速度に影響することはありますが、主な理由は互換性です。
正解です！PyTorch では、演算を行うテンソル同士が同じデバイス上にある必要があります。
デバイスへの移動自体がメモリを節約するわけではありません。
DataLoader は特定のデバイス配置を要求しません。

5. 評価前に model.eval() は何をしますか？

model.eval() はパラメータを凍結しません。凍結するには requires_grad=False を設定します。
正解です！eval() モードではドロップアウトが無効になり、バッチ正規化では現在のバッチから統計量を計算するのではなく、学習中に蓄積された統計量を使います。
実際には、評価中は通常 torch.no_grad() を使って勾配計算を無効にします。
model.eval() は層の動作を変えるだけです。指標の計算は別途実装する必要があります。

6. 評価中の torch.no_grad() の目的は何ですか？

torch.no_grad() は予測を妨げるものではなく、勾配計算を止めるだけです。
正解です！評価には勾配が不要なので、無効にするとメモリと計算量を節約できます。
評価モードを有効にするのは torch.no_grad() ではなく model.eval() です。
再現性は乱数シードの設定で担保するもので、torch.no_grad() の役割ではありません。

7. 学習ループで 🤗 Accelerate を使うと何が変わりますか？

Accelerate では、既存の PyTorch コードへの変更は最小限で済みます。
正解です！主な変更はこの2点で、オブジェクトを accelerator.prepare() でラップし、分散学習を適切に行うために accelerator.backward() を使います。
Accelerate は利用可能なハードウェアを自動で検出します。
Accelerate でも同じオプティマイザとスケジューラが使えます。

💡 ヒント

💡 要点: - 手動の学習ループでは完全な制御が可能ですが、正しい順序（フォワード → バックワード → オプティマイザステップ → スケジューラステップ → 勾配をゼロにする）を理解する必要があります - 重み減衰ありの AdamW が、Transformer モデルに推奨されるオプティマイザです - 評価中は、正しい動作と効率のために、常に model.eval() と torch.no_grad() を使ってください - 🤗 Accelerate を使えば、最小限のコード変更で分散学習が可能になります - デバイス管理（テンソルを GPU/CPU に移動すること）は、PyTorch の演算に不可欠です - 混合精度、勾配累積、勾配クリッピングといった現代的なテクニックで、学習効率を大きく改善できます
