# Unit 1 のまとめ

## Model Context Protocol（MCP）

MCP は、AI モデルを外部のツール、データソース、環境に接続する為に設計された標準化されたプロトコルです。相互運用性とリアルタイム情報へのアクセスを可能にすることで、既存の AI システムの制約を解消します。

## 主要な概念

### クライアント・サーバーアーキテクチャ
MCP は、クライアントがユーザーとサーバー間の通信を管理するクライアント・サーバーモデルに従います。このアーキテクチャはモジュール性を促進し、既存のホストに変更を加えることなく新しいサーバーを簡単に追加出来ます。

### コンポーネント
#### ホスト（Host）
エンドユーザーが操作する、ユーザー向けの AI アプリケーションです。

##### クライアント（Client）
ホストアプリケーション内のコンポーネントで、特定の MCP サーバーとの通信を管理します。クライアントはサーバーと 1:1 の接続を維持し、プロトコルレベルの詳細を処理します。

#### サーバー（Server）
MCP プロトコルを通じてツール、データソース、サービスへのアクセスを提供する外部のプログラム又はサービスです。サーバーは、既存の機能を包み込む軽量なプログラムとして動作します。

### 機能（Capabilities）
#### ツール（Tools）
アクションを実行出来る関数です（例：メッセージの送信、API のクエリ）。ツールは通常、モデルが制御します。副作用を伴うアクションを実行出来る為、ユーザーの承認が必要です。

#### リソース（Resources）
大きな計算を伴わずにコンテキストを取得する為の読み取り専用データソースです。リソースへのアクセスは通常、アプリケーションが制御します。REST API の GET エンドポイントと同様に、データの取得を目的として設計されています。

#### プロンプト（Prompts）
ユーザー、AI モデル、利用可能な機能の間のやり取りをガイドする、事前に定義されたテンプレートやワークフローです。プロンプトはユーザーが制御するもので、やり取りのコンテキストを設定します。

#### サンプリング（Sampling）
サーバーから開始される LLM 処理へのリクエストです。サーバー駆動のエージェント的な振る舞いや、再帰的・複数ステップのやり取りを可能にします。サンプリング操作には通常、ユーザーの承認が必要です。

### 通信プロトコル
MCP プロトコルは、クライアントとサーバー間の通信のメッセージフォーマットとして JSON-RPC 2.0 を使用します。2つの主要なトランスポート機構がサポートされています。stdio（ローカル通信用）と HTTP+SSE（リモート通信用）です。メッセージにはリクエスト、レスポンス、通知が含まれます。

### ディスカバリプロセス
MCP では、クライアントが一覧取得用のメソッド（例：`tools/list`）を通じて、利用可能なツール、リソース、プロンプトを動的に見つけられます。この仕組みにより、サーバーが提供する機能を予めプログラム内に書き込んでおかなくても、クライアントは各サーバーの機能に対応出来ます。

### MCP SDK
MCP クライアントとサーバーを実装する為の公式 SDK が、様々なプログラミング言語で提供されています。これらの SDK はプロトコルレベルの通信、機能の登録、エラーハンドリングを処理し、開発プロセスを簡素化します。

### Gradio との統合
Gradio を使えば、Web インターフェースを簡単に作成すると共に、その機能を MCP プロトコルを通じて公開出来ます。これにより、人も AI モデルも同じアプリケーションの機能を利用出来るようになります。Gradio と MCP を組み合わせることで、人が操作し易いインターフェースと AI が利用出来るツールの両方を、少ないコードで提供出来ます。

### Hugging Face の MCP 拡張
- Hugging Face が提供するホスト型 MCP サーバーは、VS Code、Cursor、Zed、Claude Desktop など、より多くのクライアントに対応するようになりました。
- モデル、データセット、Spaces、論文を検索出来る、厳選された組み込みツールが用意されています。
- `https://huggingface.co/settings/mcp` からワンクリックで設定スニペットを取得出来ます。
- 設定から MCP 対応の Gradio Spaces を追加し、アシスタントから直接利用出来ます。
