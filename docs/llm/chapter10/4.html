データセットにアノテーションを付ける

いよいよ、Argilla の UI からデータセットへのアノテーション作業を始めます。

アノテーションガイドラインでチームの認識を揃える

データセットのアノテーションを始める前に、ガイドラインを作成することが重要です。特にチームで作業する場合、タスクや各ラベルの使い方について認識を揃え、疑問や判断の食い違いが生じた際に解決するための指針として役立ちます。

Argilla では、UI のデータセット設定ページでガイドラインや質問の説明を編集でき、認識合わせに役立てられます。

良いガイドラインの書き方についてもっと深く知りたい場合は、このブログ記事 と、そこで挙げられている参考文献を読むことをおすすめします。

アノテーション作業を割り当てる

データセット設定ページでは、アノテーション作業の割り当て設定（distribution settings）も変更できます。チームで作業するときに、より効率的にアノテーションできるようになります。送信済みレスポンスの最小数のデフォルト値は 1 です。つまり、レコードに送信済みレスポンスが1つ付けば、そのレコードは完了とみなされ、データセットの進捗にカウントされます。

レコードごとに複数の送信済みレスポンスが欲しい場合もあります。たとえば、タスクにおけるアノテーター間の一致度を分析したい場合です。その場合は、この設定をより大きな数に変更してください。ただし、アノテーターの総数以下にする必要があります。タスクを一人で行う場合は、この設定は 1 のままにします。

レコードにアノテーションを付ける

💡 ヒント

💡 Argilla を Hugging Face Space にデプロイしている場合、チームメンバーは Hugging Face の OAuth でログインできます。そうでない場合は、このガイド に従ってユーザーを作成する必要があるかもしれません。

データセットを開くと、最初の質問には提案ラベルがすでに表示されています。これは、前のセクションで label という名前の質問をデータセットの label_text 列にマッピングしたためで、既存のラベルを確認して修正するだけで済みます。

トークン分類については、提案を含めていないため、すべてのラベルを手動で追加する必要があります。スパンアノテーションの後は、次のような表示になるかもしれません。

各レコードのアノテーション中には、次の操作を選べます。 - レスポンスを送信する（そのレコードのアノテーションが終わったら）。 - 下書きとして保存する（あとで戻ってきたい場合）。 - 破棄する（そのレコードをデータセットに含めるべきでない場合や、レスポンスを付けない場合）。

次のセクションでは、それらのアノテーションをエクスポートして使う方法を学びます。
