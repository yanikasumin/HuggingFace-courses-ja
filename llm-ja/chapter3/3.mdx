🤗 Transformers には `Trainer` クラスが用意されており、Transformers が提供するどの事前学習済みモデルでも、推奨される手法に沿って自分のデータセットでファインチューニング出来ます。前のセクションのデータ前処理が全て終われば、`Trainer` を定義する為に残されたステップはわずかです。

最も大変なのはおそらく、`Trainer.train()` を実行する環境の準備です。CPU では非常に低速になる為です。GPU が用意出来ない場合は、[Google Colab](https://colab.research.google.com/) で無料の GPU や TPU を利用出来ます。

> [!TIP]
> **学習リソース**：学習に入る前に、包括的な [Transformers 学習ガイド](https://huggingface.co/docs/transformers/main/en/training) に目を通し、[ファインチューニングのクックブック](https://huggingface.co/learn/cookbook/en/fine_tuning_code_llm_on_single_gpu) の実践的な例も確認しておきましょう。

以下のコード例は、前のセクションの例を既に実行していることを前提としています。必要な準備を簡単に振り返っておきましょう。

```py
from datasets import load_dataset
from transformers import AutoTokenizer, DataCollatorWithPadding

raw_datasets = load_dataset("glue", "mrpc")
checkpoint = "bert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(checkpoint)


def tokenize_function(example):
    return tokenizer(example["sentence1"], example["sentence2"], truncation=True)


tokenized_datasets = raw_datasets.map(tokenize_function, batched=True)
data_collator = DataCollatorWithPadding(tokenizer=tokenizer)
```

### 学習[[training]]

`Trainer` を定義する前に、最初のステップとして `TrainingArguments` クラスを定義します。これには、`Trainer` が学習と評価に使用する全てのハイパーパラメータが含まれます。必須の引数は、学習済みモデルの保存先ディレクトリを指定するものだけです。途中で作成されるチェックポイントもここに保存されます。その他は全てデフォルトのままに出来ます。基本的なファインチューニングには十分なはずです。

```py
from transformers import TrainingArguments

training_args = TrainingArguments("test-trainer")
```

学習中にモデルを Hub に自動的にアップロードしたい場合は、`TrainingArguments` に `push_to_hub=True` を渡します。詳細は [第4章](/course/chapter4/3) で説明します。

> [!TIP]
> **高度な設定**：利用可能な全ての学習引数と最適化戦略の詳細については、[TrainingArguments ドキュメント](https://huggingface.co/docs/transformers/main/en/main_classes/trainer#transformers.TrainingArguments) と [学習設定のクックブック](https://huggingface.co/learn/cookbook/en/fine_tuning_code_llm_on_single_gpu) を確認して下さい。

2つ目のステップは、モデルの定義です。[前の章](/course/chapter2) と同様に、`AutoModelForSequenceClassification` クラスを使用し、ラベルは2つとします。

```py
from transformers import AutoModelForSequenceClassification

model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)
```

[第2章](/course/chapter2) とは異なり、この事前学習済みモデルをインスタンス化すると警告が表示されることに気づくでしょう。これは、BERT が文ペアの分類で事前学習されていない為です。事前学習済みモデルのヘッドは破棄され、代わりにシーケンス分類に適した新しいヘッドが追加されています。警告は、一部の重みが使用されなかったこと（破棄された事前学習ヘッドに対応するもの）と、その他の重みがランダムに初期化されたこと（新しいヘッド用のもの）を示しています。警告の最後には、モデルを学習させるよう促すメッセージが表示されます。まさにこれからそれを行います。

モデルが用意出来たら、これまでに構築した全てのオブジェクト、即ち `model`、`training_args`、学習データセットと検証データセット、`data_collator`、`processing_class` を渡して `Trainer` を定義出来ます。`processing_class` パラメータは比較的新しく追加されたもので、処理に使用するトークナイザを `Trainer` に伝えます。

```py
from transformers import Trainer

trainer = Trainer(
    model,
    training_args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    data_collator=data_collator,
    processing_class=tokenizer,
)
```

トークナイザを `processing_class` として渡すと、`Trainer` が使用するデフォルトの `data_collator` は `DataCollatorWithPadding` になります。この場合、`data_collator=data_collator` の行は省略出来ますが、ここでは処理パイプラインの重要な部分を示す為に含めています。

> [!TIP]
> **更に学ぶ**：`Trainer` クラスとそのパラメータについて詳しくは、[Trainer API ドキュメント](https://huggingface.co/docs/transformers/main/en/main_classes/trainer) を参照して下さい。より高度な使い方は、[学習クックブックのレシピ](https://huggingface.co/learn/cookbook/en/fine_tuning_code_llm_on_single_gpu) でも紹介されています。

データセットでモデルをファインチューニングするには、`Trainer` の `train()` メソッドを呼び出すだけです。

```py
trainer.train()
```

これによりファインチューニングが開始され（GPU では数分掛かります）、500ステップごとに学習損失が報告されます。しかし、モデルの性能がどの程度良いか（又は悪いか）は分かりません。その理由は次の通りです。

1. `TrainingArguments` の `eval_strategy` を `"steps"`（`eval_steps` ごとに評価）又は `"epoch"`（各エポックの末尾に評価）に設定して、学習中に評価を行うよう `Trainer` に指示しなかった為です。
2. 評価時にメトリクスを計算する為の `compute_metrics()` 関数を `Trainer` に渡していなかった為です（この関数が無い場合、評価では損失しか出力されず、モデルの性能を直感的に把握出来ません）。


### 評価[[evaluation]]

便利な `compute_metrics()` 関数を作り、次の学習で使う方法を見ていきましょう。この関数は、`predictions` フィールドと `label_ids` フィールドを持つ名前付きタプルである `EvalPrediction` オブジェクトを受け取ります。戻り値は、メトリクス名を文字列のキー、その値を浮動小数点数とする辞書でなければなりません。モデルの予測結果を取得するには、`Trainer.predict()` メソッドを使います。

```py
predictions = trainer.predict(tokenized_datasets["validation"])
print(predictions.predictions.shape, predictions.label_ids.shape)
```

```python out
(408, 2) (408,)
```

`predict()` メソッドの出力は、3つのフィールド `predictions`、`label_ids`、`metrics` を持つ、別の名前付きタプルです。`metrics` フィールドには、渡されたデータセットに対する損失と、時間に関するメトリクス（予測に掛かった時間の合計と平均）が含まれるだけです。`compute_metrics()` 関数を完成させて `Trainer` に渡すと、このフィールドには `compute_metrics()` が返したメトリクスも含まれるようになります。

見ての通り、`predictions` は形状が 408 x 2 の二次元配列です（408 は、渡したデータセットの要素の数です）。これらは、`predict()` に渡したデータセットの各要素に対するロジットです（[前の章](/course/chapter2) で見た通り、全ての Transformer モデルはロジットを返します）。これらをラベルと比較出来る予測に変換するには、第2軸で最大値のインデックスを取得する必要があります。

```py
import numpy as np

preds = np.argmax(predictions.predictions, axis=-1)
```

これで、`preds` をラベルと比較出来ます。`compute_metric()` 関数を構築するには、[Evaluate](https://github.com/huggingface/evaluate/) ライブラリのメトリクスを利用します。`evaluate.load()` 関数を使えば、MRPC データセット用のメトリクスも、データセットを読み込む時と同じように簡単に読み込めます。返されるオブジェクトには、メトリクスの計算に使用出来る `compute()` メソッドがあります。

```py
import evaluate

metric = evaluate.load("glue", "mrpc")
metric.compute(predictions=preds, references=predictions.label_ids)
```

```python out
{'accuracy': 0.8578431372549019, 'f1': 0.8996539792387542}
```

> [!TIP]
> 様々な評価メトリクスと戦略については、[Evaluate ドキュメント](https://huggingface.co/docs/evaluate/) を参照して下さい。

実行結果は毎回同じとは限りません。モデルのヘッドがランダムに初期化される為、メトリクスの値が変わることが有るからです。ここでは、モデルの検証データセットに対する正解率が85.78%、F1 スコアが89.97であることが分かります。これらは、GLUE ベンチマークの MRPC データセットで結果を評価する為に使用される2つのメトリクスです。

[BERT 論文](https://arxiv.org/pdf/1810.04805.pdf) の表では、ベースモデルの F1 スコアが88.9と報告されていました。これは `uncased` モデルの結果であり、現在使用しているのは `cased` モデルである為、より良い結果が得られたことが説明出来ます。

総てをまとめると、`compute_metrics()` 関数は次のようになります。

```py
def compute_metrics(eval_preds):
    metric = evaluate.load("glue", "mrpc")
    logits, labels = eval_preds
    predictions = np.argmax(logits, axis=-1)
    return metric.compute(predictions=predictions, references=labels)
```

この `compute_metrics()` 関数を使えば、各エポックの終了時にメトリクスを報告出来ます。新しい `Trainer` を次のように定義します。

```py
training_args = TrainingArguments("test-trainer", eval_strategy="epoch")
model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)

trainer = Trainer(
    model,
    training_args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    data_collator=data_collator,
    processing_class=tokenizer,
    compute_metrics=compute_metrics,
)
```

`eval_strategy` を `"epoch"` に設定した新しい `TrainingArguments` と、新しいモデルを作成している点に注意して下さい。そうしなければ、既に学習済みのモデルの学習を継続することになってしまいます。新しい学習実行を開始するには、次を実行します。

```py
trainer.train()
```

今度は、学習損失に加えて、各エポックの末尾に検証損失とメトリクスが報告されます。なお、モデルのヘッドはランダムに初期化される為、正解率や F1 スコアは先程の結果と多少異なることが有りますが、大凡同じ範囲になるはずです。

### 高度な学習機能[[advanced-training-features]]

`Trainer` には、現在の深層学習で推奨される手法を簡単に取り入れられる機能が数多く備わっています。

**混合精度学習**：学習引数で `fp16=True` を使用すると、学習が高速化し、メモリ使用量が削減されます。

```py
training_args = TrainingArguments(
    "test-trainer",
    eval_strategy="epoch",
    fp16=True,  # 混合精度を有効化
)
```

**勾配累積**：GPU メモリが限られている場合でも、実効バッチサイズを大きく出来ます。

```py
training_args = TrainingArguments(
    "test-trainer",
    eval_strategy="epoch",
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,  # 実効的なバッチサイズ = 4 * 4 = 16
)
```

**学習率スケジューリング**：`Trainer` はデフォルトで線形減衰を使用しますが、カスタマイズも可能です。

```py
training_args = TrainingArguments(
    "test-trainer",
    eval_strategy="epoch",
    learning_rate=2e-5,
    lr_scheduler_type="cosine",  # 異なるスケジューラを試してみてください
)
```

> [!TIP]
> **パフォーマンスの最適化**：分散学習、メモリの最適化、ハードウェア固有の最適化など、より高度な学習テクニックについては、[Transformers のパフォーマンスガイド](https://huggingface.co/docs/transformers/main/en/performance) を参照して下さい。

`Trainer` は、複数の GPU や TPU でもそのまま動作し、分散学習の為の多くのオプションを提供します。対応している機能については、第10章で詳しく説明します。

これで、`Trainer` API を使用したファインチューニングの入門は終わりです。代表的な NLP タスクにファインチューニングを適用する例は [第7章](/course/chapter7) で紹介しますが、今は、純粋な PyTorch の学習ループで同じことを行う方法を見ていきましょう。

> [!TIP]
> **その他の例**：様々な実行例をまとめた [Transformers のノートブック](https://huggingface.co/docs/transformers/main/en/notebooks) もご覧下さい。

> [!TIP]
> **重要なポイント：**
> - `Trainer` API は、学習に必要な複雑な処理の多くを引き受ける高レベルのインターフェースを提供します
> - 適切なデータ処理の為に、`processing_class` でトークナイザを指定します
> - `TrainingArguments` は、学習率、バッチサイズ、評価戦略、最適化など、学習の全ての側面を制御します
> - `compute_metrics` を使うと、学習損失に加えて独自の評価メトリクスも計算出来ます
> - 混合精度（`fp16=True`）や勾配累積などの機能を使うと、学習効率が大幅に向上する場合があります
