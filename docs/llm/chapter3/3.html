Trainer API でモデルをファインチューニングする

🤗 Transformers には Trainer クラスが用意されており、提供されている事前学習済みモデルを、現代的なベストプラクティスで自分のデータセットに対してファインチューニングできます。前のセクションのデータ前処理がすべて終われば、Trainer を定義するために残されたステップはわずかです。最も大変なのはおそらく、Trainer.train() を実行する環境の準備です。CPU では非常に低速になるためです。GPU が用意できない場合は、Google Colab で無料の GPU や TPU を利用できます。

💡 ヒント

📚 学習リソース: 学習に入る前に、包括的な 🤗 Transformers 学習ガイド に目を通し、ファインチューニングのクックブック の実践的な例も確認しておきましょう。

以下のコード例は、前のセクションの例を既に実行していることを前提としています。必要なものの簡単なまとめは次のとおりです。

from datasets import load_dataset
from transformers import AutoTokenizer, DataCollatorWithPadding

raw_datasets = load_dataset("glue", "mrpc")
checkpoint = "bert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(checkpoint)


def tokenize_function(example):
    return tokenizer(example["sentence1"], example["sentence2"], truncation=True)


tokenized_datasets = raw_datasets.map(tokenize_function, batched=True)
data_collator = DataCollatorWithPadding(tokenizer=tokenizer)

学習

Trainer を定義する前に、最初のステップとして TrainingArguments クラスを定義します。これには、Trainer が学習と評価に使用するすべてのハイパーパラメータが含まれます。指定が必須な引数は、学習したモデルが保存されるディレクトリ1つだけです。途中で作成されるチェックポイントもここに保存されます。その他はすべてデフォルトのままにできます。基本的なファインチューニングには十分なはずです。

from transformers import TrainingArguments

training_args = TrainingArguments("test-trainer")

学習中にモデルを Hub に自動的にアップロードしたい場合は、TrainingArguments に push_to_hub=True を渡します。詳細は 第4章 で説明します。

💡 ヒント

🚀 高度な設定: 利用可能なすべての学習引数と最適化戦略の詳細については、TrainingArguments ドキュメント と 学習設定のクックブック を確認してください。

2つ目のステップは、モデルの定義です。前の章 と同様に、AutoModelForSequenceClassification クラスを使用し、ラベルは2つとします。

from transformers import AutoModelForSequenceClassification

model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)

第2章 とは異なり、この事前学習済みモデルをインスタンス化すると警告が表示されることに気づくでしょう。これは、BERT が文ペアの分類で事前学習されていないためです。事前学習済みモデルのヘッドは破棄され、代わりにシーケンス分類に適した新しいヘッドが追加されています。警告は、一部の重みが使用されなかったこと（破棄された事前学習ヘッドに対応するもの）と、その他の重みがランダムに初期化されたこと（新しいヘッド用のもの）を示しています。最後に、モデルの学習を促す内容で締めくくられています。まさにこれからそれを行います。

モデルが用意できたら、これまでに構築したすべてのオブジェクト、すなわち model、training_args、学習データセットと検証データセット、data_collator、processing_class を渡して Trainer を定義できます。processing_class パラメータは比較的新しく追加されたもので、処理に使用するトークナイザを Trainer に伝えます。

from transformers import Trainer

trainer = Trainer(
    model,
    training_args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    data_collator=data_collator,
    processing_class=tokenizer,
)

トークナイザを processing_class として渡すと、Trainer が使用するデフォルトの data_collator は DataCollatorWithPadding になります。この場合、data_collator=data_collator の行は省略できますが、ここでは処理パイプラインの重要な部分を示すために含めています。

💡 ヒント

📖 さらに学ぶ: Trainer クラスとそのパラメータの包括的な詳細については、Trainer API ドキュメント を参照し、学習クックブックのレシピ で高度な使用パターンも確認してください。

データセットでモデルをファインチューニングするには、Trainer の train() メソッドを呼び出すだけです。

trainer.train()

これによりファインチューニングが開始され（GPU では数分かかります）、500ステップごとに学習損失が報告されます。しかし、モデルの性能がどの程度良いか（または悪いか）はわかりません。その理由は次のとおりです。

  1. TrainingArguments の eval_strategy を "steps"（eval_steps ごとに評価）または "epoch"（各エポックの末尾に評価）に設定して、学習中に評価を行うよう Trainer に指示しなかったためです。
  2. 評価時にメトリクスを計算するための compute_metrics() 関数を Trainer に提供しなかったためです（提供しなければ、評価では損失が出力されるだけであり、あまり直感的な数値ではありません）。

評価

便利な compute_metrics() 関数の構築方法と、次回の学習での使用方法を見ていきましょう。この関数は EvalPrediction オブジェクト（predictions フィールドと label_ids フィールドを持つ名前付きタプル）を受け取り、文字列をキー、浮動小数点数を値とする辞書を返さなければなりません（文字列は返されるメトリクスの名前、浮動小数点数はその値です）。モデルから予測を得るには、Trainer.predict() コマンドを使用できます。

predictions = trainer.predict(tokenized_datasets["validation"])
print(predictions.predictions.shape, predictions.label_ids.shape)

```python out (408, 2) (408,)

`predict()` メソッドの出力は、3つのフィールド `predictions`、`label_ids`、`metrics` を持つ、別の名前付きタプルです。`metrics` フィールドには、渡されたデータセットに対する損失と、時間に関するメトリクス（予測にかかった時間の合計と平均）が含まれるだけです。`compute_metrics()` 関数を完成させて `Trainer` に渡すと、このフィールドには `compute_metrics()` が返したメトリクスも含まれるようになります。

見てのとおり、`predictions` は形状が 408 x 2 の二次元配列です（408 は、渡したデータセットの要素の数です）。これらは、`predict()` に渡したデータセットの各要素に対するロジットです（[前の章](/course/chapter2) で見たとおり、すべての Transformer モデルはロジットを返します）。これらをラベルと比較できる予測に変換するには、第2軸で最大値のインデックスを取得する必要があります。

```py
import numpy as np

preds = np.argmax(predictions.predictions, axis=-1)

これで、preds をラベルと比較できます。compute_metric() 関数を構築するには、🤗 Evaluate ライブラリのメトリクスを利用します。MRPC データセットに関連付けられたメトリクスは、データセットを読み込んだときと同じくらい簡単に、evaluate.load() 関数で読み込めます。返されるオブジェクトには、メトリクスの計算に使用できる compute() メソッドがあります。

import evaluate

metric = evaluate.load("glue", "mrpc")
metric.compute(predictions=preds, references=predictions.label_ids)

```python out

得られる正確な結果は異なる場合があります。モデルヘッドのランダムな初期化により、達成されるメトリクスが変わる可能性があるためです。ここでは、モデルの検証セットに対する正解率が85.78%、F1 スコアが89.97であることがわかります。これらは、GLUE ベンチマークの MRPC データセットで結果を評価するために使用される2つのメトリクスです。[BERT 論文](https://arxiv.org/pdf/1810.04805.pdf) の表では、ベースモデルの F1 スコアが88.9と報告されていました。これは `uncased` モデルの結果であり、現在使用しているのは `cased` モデルであるため、より良い結果が得られたことが説明できます。

すべてをまとめると、`compute_metrics()` 関数は次のようになります。

```py
def compute_metrics(eval_preds):
    metric = evaluate.load("glue", "mrpc")
    logits, labels = eval_preds
    predictions = np.argmax(logits, axis=-1)
    return metric.compute(predictions=predictions, references=labels)

この compute_metrics() 関数を使って、各エポックの末尾にメトリクスを報告する新しい Trainer の定義は次のとおりです。

training_args = TrainingArguments("test-trainer", eval_strategy="epoch")
model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)

trainer = Trainer(
    model,
    training_args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    data_collator=data_collator,
    processing_class=tokenizer,
    compute_metrics=compute_metrics,
)

eval_strategy を "epoch" に設定した新しい TrainingArguments と、新しいモデルを作成している点に注意してください。そうしなければ、すでに学習済みのモデルの学習を継続することになってしまいます。新しい学習実行を開始するには、次を実行します。

trainer.train()

今度は、学習損失に加えて、各エポックの末尾に検証損失とメトリクスが報告されます。なお、得られる正解率と F1 スコアの具体的な値は、モデルのヘッドのランダムな初期化のため、得られた結果と多少異なる場合がありますが、おおよそ同じ範囲になるはずです。

高度な学習機能

Trainer には、現代の深層学習のベストプラクティスを手軽に利用できる、多くの組み込み機能が備わっています。

混合精度学習: 学習引数で fp16=True を使用すると、学習が高速化し、メモリ使用量が削減されます。

training_args = TrainingArguments(
    "test-trainer",
    eval_strategy="epoch",
    fp16=True,  # 混合精度を有効化
)

勾配累積: GPU メモリが限られている場合に、実効的により大きなバッチサイズを実現します。

training_args = TrainingArguments(
    "test-trainer",
    eval_strategy="epoch",
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,  # 実効的なバッチサイズ = 4 * 4 = 16
)

学習率スケジューリング: Trainer はデフォルトで線形減衰を使用しますが、カスタマイズも可能です。

training_args = TrainingArguments(
    "test-trainer",
    eval_strategy="epoch",
    learning_rate=2e-5,
    lr_scheduler_type="cosine",  # 異なるスケジューラを試してみてください
)

セクションクイズ

Trainer API とファインチューニングの概念に関する理解度をテストしましょう。

1. Trainer の processing_class パラメータの目的は何ですか？

モデルアーキテクチャは、モデルを読み込む際に指定するものであり、Trainer で指定するものではありません。
比較的最近追加された processing_class パラメータは、Trainer に使用するトークナイザを指定するためのものです。
バッチサイズは TrainingArguments で設定するものであり、processing_class で設定するものではありません。
評価の頻度は、TrainingArguments の eval_strategy で制御します。

2. 学習中の評価の頻度を制御する TrainingArguments パラメータはどれですか？

TrainingArguments に eval_frequency パラメータは存在しません。
eval_strategy は 'epoch'、'steps'、'no' に設定でき、評価のタイミングを制御します。
eval_steps は評価間のステップ数を設定しますが、評価を行うかどうか、いつ行うかを決定するのは eval_strategy です。
現代の TrainingArguments に do_eval パラメータは存在しません。

3. TrainingArguments の fp16=True は何を有効にしますか？

fp16 は浮動小数点精度を指し、整数精度ではありません。
混合精度学習では、順伝播に16ビット浮動小数点数、勾配に32ビット浮動小数点数を使用し、速度の向上とメモリ使用量の削減を実現します。
fp16 はエポック数とは何の関係もありません。
GPU の数は fp16 パラメータで制御されるものではありません。

4. Trainer における compute_metrics 関数の役割は何ですか？

損失の計算はモデルが自動的に処理するものであり、compute_metrics が行うものではありません。
compute_metrics は予測とラベルを受け取り、評価用のメトリクスを返します。
オプティマイザの選択は compute_metrics が処理するものではありません。
データの前処理は学習前に行われるものであり、評価中に compute_metrics が行うものではありません。

5. Trainer に eval_dataset を提供しないとどうなりますか？

eval_dataset がなくても学習は進行できますが、評価メトリクスは得られません。
Trainer は検証用の分割を自動的には作成しません。
評価は任意です。評価なしで学習することもできますが、検証メトリクスは表示されません。
Trainer が学習データを自動的に評価に使用することはありません。単に評価を行わないだけです。

6. 勾配累積とは何ですか？また、どのように有効にしますか？

勾配累積に、勾配をディスクに保存することは含まれません。
これにより、複数の順伝播にわたって勾配を累積することで、より大きなバッチサイズをシミュレートできます。
fp16 は学習を高速化できますが、勾配累積は別のテクニックです。
それは勾配クリッピングの説明であり、勾配累積ではありません。

💡 ヒント

💡 重要なポイント: - Trainer API は、学習の複雑さの大部分を処理する高レベルインターフェースを提供します - 適切なデータ処理のために、processing_class でトークナイザを指定します - TrainingArguments は、学習率、バッチサイズ、評価戦略、最適化など、学習のすべての側面を制御します - compute_metrics により、学習損失だけでなくカスタムの評価メトリクスも使用できます - 混合精度（fp16=True）や勾配累積などの現代的な機能により、学習効率が大幅に向上します
