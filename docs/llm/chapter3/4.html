完全な学習ループ

ここでは、Trainer クラスを使わず、PyTorch の学習ループをゼロから実装して、前のセクションと同じ結果を得る方法を見ていきます。書き方は、現在の PyTorch で推奨されている方法に沿います。セクション2のデータ処理は済んでいるものとし、まず必要なものを短いコードでまとめます。

💡 ヒント

🏗️ 学習ループをゼロから実装する：このセクションは前の内容を前提としています。PyTorch の学習ループと推奨される書き方については、🤗 Transformers の学習ドキュメント と カスタム学習クックブック が参考になります。

from datasets import load_dataset
from transformers import AutoTokenizer, DataCollatorWithPadding

raw_datasets = load_dataset("glue", "mrpc")
checkpoint = "bert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(checkpoint)


def tokenize_function(example):
    return tokenizer(example["sentence1"], example["sentence2"], truncation=True)


tokenized_datasets = raw_datasets.map(tokenize_function, batched=True)
data_collator = DataCollatorWithPadding(tokenizer=tokenizer)

学習の準備

学習ループを書く前に、いくつかのオブジェクトを用意します。最初は、バッチ単位でデータを順に取り出すデータローダです。但し、その前に tokenized_datasets へ少し後処理を加えます。Trainer が自動で済ませていた処理です。具体的には、次の3つを行います。

  • モデルが想定していない列（sentence1 列や sentence2 列など）を削除する
  • 列 label の名前を labels に変える（モデルが受け取る引数の名前が labels の為）
  • データセットの形式を指定し、リストではなく PyTorch テンソルが返るようにする

tokenized_datasets には、これらの処理に対応するメソッドがそれぞれ有ります。

tokenized_datasets = tokenized_datasets.remove_columns(["sentence1", "sentence2", "idx"])
tokenized_datasets = tokenized_datasets.rename_column("label", "labels")
tokenized_datasets.set_format("torch")
tokenized_datasets["train"].column_names

実行すると、モデルが受け付ける列だけが残っていることを確認出来ます。

["attention_mask", "input_ids", "labels", "token_type_ids"]

これで、データローダを簡単に定義出来ます。

from torch.utils.data import DataLoader

train_dataloader = DataLoader(
    tokenized_datasets["train"], shuffle=True, batch_size=8, collate_fn=data_collator
)
eval_dataloader = DataLoader(
    tokenized_datasets["validation"], batch_size=8, collate_fn=data_collator
)

データ処理に間違いが無いかは、バッチを取り出して次のように調べると手早く確認出来ます。

for batch in train_dataloader:
    break
{k: v.shape for k, v in batch.items()}

```python out {'attention_mask': torch.Size([8, 65]), 'input_ids': torch.Size([8, 65]), 'labels': torch.Size([8]), 'token_type_ids': torch.Size([8, 65])}

学習用データローダでは `shuffle=True` を設定し、パディングはバッチ内で最も長い入力に合わせています。手元で実行すると、テンソルの形状が上の例と少し異なる場合が有ります。

これでデータの前処理は全て終わりました。前処理を終えられるのは、機械学習に取り組む人にとって満足感の有ることですが、たどり着くまでがなかなか大変です。次はモデルを用意します。作り方は前のセクションと全く同じです。

```py
from transformers import AutoModelForSequenceClassification

model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)

学習が順調に進むかを確認する為、バッチをこのモデルに渡してみます。

outputs = model(**batch)
print(outputs.loss, outputs.logits.shape)

```python out tensor(0.5441, grad_fn=) torch.Size([8, 2])

Transformers のモデルは全て、`labels` を渡すと損失を返します。併せてロジットも得られます。各入力につき2つずつ出る為、全体ではサイズ 8 x 2 のテンソルです。

学習ループを書く準備はほぼ整いました。残るのはオプティマイザと学習率スケジューラの2つです。ここでは `Trainer` の動きを手作業で再現するので、既定もそれに合わせます。`Trainer` が使うオプティマイザは `AdamW` です。Adam を基に、重み減衰による正則化の工夫を加えたものになります（Ilya Loshchilov と Frank Hutter による ["Decoupled Weight Decay Regularization"](https://arxiv.org/abs/1711.05101) を参照）。

```py
from torch.optim import AdamW

optimizer = AdamW(model.parameters(), lr=5e-5)

💡 ヒント

💡 現代的な最適化のヒント：更に性能を高めたい場合は、次を試せます。 - 重み減衰ありの AdamW：AdamW(model.parameters(), lr=5e-5, weight_decay=0.01) - 8-bit Adam：bitsandbytes を使ったメモリ効率のよい最適化 - 学習率の調整：大きなモデルでは、低めの学習率（1e-5 〜 3e-5）がうまくいくことが多いです

🚀 最適化のリソース：オプティマイザと学習戦略の詳細は Transformers 最適化ガイド を参照してください。

最後に学習率スケジューラです。既定のスケジューラは、学習率を最大値（5e-5）から 0 まで直線的に下げます。これを設定するには学習ステップの総数が要ります。総数は、エポック数に学習用バッチの数（学習用データローダの長さ）を掛けたものです。Trainer の既定は3エポックなので、ここでも同じ設定にします。

from transformers import get_scheduler

num_epochs = 3
num_training_steps = num_epochs * len(train_dataloader)
lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)
print(num_training_steps)

```python out 1377

### 学習ループ

もう1つ、デバイスの指定が残っています。GPU を使えるなら使いたい所です。CPU では、学習に数分ではなく数時間掛かる場合が有る為です。モデルとバッチを置く先として、`device` を定義します。

```py
import torch

device = torch.device("cuda") if torch.cuda.is_available() else torch.device("cpu")
model.to(device)
device

```python out device(type='cuda')

これで学習を始められます。進み具合が分かるよう、`tqdm` ライブラリでプログレスバーを付け、全学習ステップに対する進捗を表示します。

```py
from tqdm.auto import tqdm

progress_bar = tqdm(range(num_training_steps))

model.train()
for epoch in range(num_epochs):
    for batch in train_dataloader:
        batch = {k: v.to(device) for k, v in batch.items()}
        outputs = model(**batch)
        loss = outputs.loss
        loss.backward()

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

💡 ヒント

💡 現代的な学習の最適化：学習ループを更に効率化するには、次を検討してください。

  • 勾配クリッピング：optimizer.step() の前に torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0) を追加する
  • 混合精度：torch.cuda.amp.autocast() と GradScaler を使って学習を高速化する
  • 勾配累積：複数のバッチにわたって勾配を蓄積し、大きなバッチサイズを擬似的に再現する
  • チェックポイント保存：定期的にモデルのチェックポイントを保存し、中断しても再開出来るようにする

🔧 実装ガイド：これらの最適化の詳しい例は、Transformers の効率的な学習ガイド と オプティマイザの一覧 を参照してください。

学習ループの中心部分は、入門編で見たものとよく似ています。但し、ここでは学習状況を報告する処理を入れていない為、このループだけではモデルの性能が分かりません。性能を見るには、評価ループを追加します。

評価ループ

評価には、前と同じく Evaluate ライブラリの指標を使います。metric.compute() メソッドは既に見ました。これに加え、add_batch() メソッドを使うと、予測ループを回しながらバッチごとに予測と正解ラベルを蓄積出来ます。全バッチを蓄積し終えたら、metric.compute() で最終結果を得ます。評価ループは次のように実装します。

💡 ヒント

📊 評価のベストプラクティス：より高度な評価戦略と指標については、Evaluate のドキュメント と 包括的な評価クックブック を参照してください。

import evaluate

metric = evaluate.load("glue", "mrpc")
model.eval()
for batch in eval_dataloader:
    batch = {k: v.to(device) for k, v in batch.items()}
    with torch.no_grad():
        outputs = model(**batch)

    logits = outputs.logits
    predictions = torch.argmax(logits, dim=-1)
    metric.add_batch(predictions=predictions, references=batch["labels"])

metric.compute()

```python out

結果は、実行のたびに少し異なる場合が有ります。モデルヘッドの初期値と、データをシャッフルする順序がランダムに決まる為です。但し、大凡同じくらいの値になるはずです。

### 🤗 Accelerate で学習ループを強化する








先程定義した学習ループは、単一の CPU や GPU であれば問題なく動きます。これを複数の GPU や TPU による分散学習に対応させるには、[Accelerate](https://github.com/huggingface/accelerate) ライブラリを使えば、わずかな変更で済みます。分散学習や混合精度、デバイス配置といった複雑な処理は、Accelerate が自動で引き受けます。学習用と検証用のデータローダを作る所から、手書きの学習ループは次のようになります。

<div class="callout callout-tip" markdown="block">
<p class="callout-title">💡 ヒント</p>
⚡ **Accelerate の詳細**：分散学習、混合精度、ハードウェア最適化の全ては [Accelerate のドキュメント](https://huggingface.co/docs/accelerate/) で学べます。実践的な例は [Transformers のドキュメント](https://huggingface.co/docs/transformers/main/en/accelerate) にあります。
</div>


```py
from accelerate import Accelerator
from torch.optim import AdamW
from transformers import AutoModelForSequenceClassification, get_scheduler

accelerator = Accelerator()

model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)
optimizer = AdamW(model.parameters(), lr=3e-5)

train_dl, eval_dl, model, optimizer = accelerator.prepare(
    train_dataloader, eval_dataloader, model, optimizer
)

num_epochs = 3
num_training_steps = num_epochs * len(train_dl)
lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)

progress_bar = tqdm(range(num_training_steps))

model.train()
for epoch in range(num_epochs):
    for batch in train_dl:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

追加するのは、まずインポート文です。次に Accelerator オブジェクトを作成します。このオブジェクトが環境を確認し、分散学習に必要な設定を初期化します。デバイスへの配置は Accelerate が担う為、モデルをデバイスへ移す行は削除出来ます。残したい場合は、device の代わりに accelerator.device を使ってください。

作業の中心は、データローダとモデル、オプティマイザを accelerator.prepare() に渡す行です。この行で各オブジェクトが適切な入れ物にラップされ、分散学習が想定通りに動くようになります。あとは、バッチを device に移す行を削除し（残す場合は accelerator.device を使うよう直します）、loss.backward() を accelerator.backward(loss) に置き換えるだけです。

💡 ヒント

⚠️ Cloud TPU の高速化を活かすには、トークナイザの padding="max_length" 引数と max_length 引数で、サンプルを固定長にパディングすることをお勧めします。

そのままコピーして試せるように、Accelerate を使った完全な学習ループを載せておきます。

from accelerate import Accelerator
from torch.optim import AdamW
from transformers import AutoModelForSequenceClassification, get_scheduler

accelerator = Accelerator()

model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)
optimizer = AdamW(model.parameters(), lr=3e-5)

train_dl, eval_dl, model, optimizer = accelerator.prepare(
    train_dataloader, eval_dataloader, model, optimizer
)

num_epochs = 3
num_training_steps = num_epochs * len(train_dl)
lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)

progress_bar = tqdm(range(num_training_steps))

model.train()
for epoch in range(num_epochs):
    for batch in train_dl:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

このコードを train.py というスクリプトにまとめれば、どの分散環境でも実行出来ます。自分の分散環境で試すには、まず次のコマンドを実行します。

accelerate config

いくつかの質問に答えると、その内容が設定ファイルに書き出されます。この設定ファイルを使うのが、次のコマンドです。

accelerate launch train.py

これで分散学習が起動します。

ノートブックで試す場合（例えば Colab の TPU でテストする場合）は、コードを training_function() という関数に入れ、最後のセルで次を実行します。

from accelerate import notebook_launcher

notebook_launcher(training_function)

その他の例は Accelerate リポジトリ にあります。

🌐 分散学習：マルチ GPU・マルチノード学習の包括的な解説は、Transformers 分散学習ガイド と 学習のスケーリングに関するクックブック を参照してください。

次のステップとベストプラクティス

学習ループをゼロから実装する方法は以上です。最後に、本番で使う際に検討しておきたい点をいくつか挙げます。

モデルの評価：正解率だけでなく、常に複数の指標でモデルを評価してください。包括的な評価には Evaluate ライブラリを使います。

ハイパーパラメータ調整：体系的なハイパーパラメータ最適化には、Optuna や Ray Tune のようなライブラリの利用を検討してください。

モデルの監視：学習の全期間を通して、学習指標と学習曲線、検証性能を記録し続けてください。

モデルの共有：学習が終わったら、モデルを Hugging Face Hub で共有し、コミュニティが使えるようにしてください。

効率化：大きなモデルでは、勾配チェックポイント、パラメータ効率のよいファインチューニング（LoRA、AdaLoRA）、量子化といった手法を検討してください。

カスタム学習ループによるファインチューニングの解説は以上です。ここで学んだスキルは、学習プロセスを完全に制御したい場合や、Trainer API の範囲を超えるカスタム学習ロジックを実装したい場合に役立ちます。

セクションクイズ

カスタム学習ループと応用的な学習手法について、理解度を確かめましょう。

1. Adam オプティマイザと AdamW オプティマイザの主な違いは何ですか？

学習率のスケジューリングは、オプティマイザの選択とは別物です。
正解です！AdamW では、重み減衰を勾配によるパラメータ更新とは別に適用するため、より効果的な正則化につながります。
AdamW は Transformer に限らず、あらゆるモデルアーキテクチャで使えます。
どちらのオプティマイザもメモリ要件は同程度です。

2. 学習ループにおける操作の正しい順序はどれですか？

惜しいですが、古い勾配が蓄積しないよう、次のフォワードパスの前に勾配をゼロにすべきです。
正解です！正しい順序は、損失の計算、勾配の計算、パラメータの更新、学習率の更新、そして勾配のクリアです。
損失から勾配を計算するには、バックワードパスはフォワードパスの後でなければなりません。
バックワードパスの前に勾配をゼロにすると、計算したばかりの勾配が消えてしまいます。

3. 🤗 Accelerate ライブラリは主に何を支援しますか？

Accelerate はモデルアーキテクチャ自体を最適化するものではありません。
Accelerate はハイパーパラメータ最適化を行いません。
正解です！Accelerate は分散学習に必要な複雑な処理を自動で行うため、同じコードを単一デバイスでも複数デバイスでもスムーズに動かせます。
Accelerate は PyTorch の中で動作し、フレームワーク間の変換は行いません。

4. 学習ループでバッチをデバイスに移動するのはなぜですか？

速度に影響することはありますが、主な理由は互換性です。
正解です！PyTorch では、演算を行うテンソル同士が同じデバイス上にある必要があります。
デバイスへの移動自体がメモリを節約するわけではありません。
DataLoader は特定のデバイス配置を要求しません。

5. 評価前に model.eval() は何をしますか？

model.eval() はパラメータを凍結しません。凍結するには requires_grad=False を設定します。
正解です！eval() モードではドロップアウトが無効になり、バッチ正規化では現在のバッチから統計量を計算するのではなく、学習中に蓄積された統計量を使います。
実際には、評価中は通常 torch.no_grad() を使って勾配計算を無効にします。
model.eval() は層の動作を変えるだけです。指標の計算は別途実装する必要があります。

6. 評価中の torch.no_grad() の目的は何ですか？

torch.no_grad() は予測を妨げるものではなく、勾配計算を止めるだけです。
正解です！評価には勾配が不要なので、無効にするとメモリと計算量を節約できます。
評価モードを有効にするのは torch.no_grad() ではなく model.eval() です。
再現性は乱数シードの設定で担保するもので、torch.no_grad() の役割ではありません。

7. 学習ループで 🤗 Accelerate を使うと何が変わりますか？

Accelerate では、既存の PyTorch コードへの変更は最小限で済みます。
正解です！主な変更はこの2点で、オブジェクトを accelerator.prepare() でラップし、分散学習を適切に行うために accelerator.backward() を使います。
Accelerate は利用可能なハードウェアを自動で検出します。
Accelerate でも同じオプティマイザとスケジューラが使えます。

💡 ヒント

💡 要点： - 自分で実装した学習ループでは学習処理を完全に制御出来ますが、各処理の正しい順序（フォワード → バックワード → オプティマイザステップ → スケジューラステップ → 勾配をゼロにする）を理解する必要があります - 重み減衰ありの AdamW が、Transformer モデルに推奨されるオプティマイザです - 評価中は、正しい動作と効率の為に、常に model.eval() と torch.no_grad() を使ってください - Accelerate を使えば、最小限のコード変更で分散学習が可能になります - デバイス管理（テンソルを CPU または GPU に移動すること）は、PyTorch の演算に不可欠です - 混合精度、勾配累積、勾配クリッピングといった現在よく使われる手法で、学習効率を大きく改善出来ます
