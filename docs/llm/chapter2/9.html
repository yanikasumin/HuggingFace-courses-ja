章末クイズ

1. 言語モデリングのパイプラインでは、処理はどのような順序で進みますか？

モデルはテキストをそのまま理解できません。まずトークナイザがテキストをトークン化し、モデルが理解できる ID に変換する必要があります。
モデルの予測がそのままテキストになることはありません。予測をテキストに戻すには、トークナイザを使う必要があります。
トークナイザは、トークン化とデトークン化の両方に使えます。

2. ベースの Transformer モデルが出力するテンソルは、何次元で、それぞれ何を表しますか？

違います。モデルが出力するテンソルには、もう1つ隠れサイズという次元があります。
違います。Transformer モデルはすべてバッチを扱います。シーケンスが1つだけでも、バッチサイズは1になります。

4. モデルヘッドとは何ですか？

そのような構成要素はありません。
セルフアテンションにも「ヘッド」と呼ばれる仕組みがありますが、ここでいうタスク適応用のモデルヘッドとは別のものです。
そのとおりです。タスク適応用のモデルヘッド（単にヘッドとも呼ばれます）には、言語モデリングヘッド、質問応答ヘッド、シーケンス分類ヘッドなど、さまざまな形があります。

5. AutoModel とは何ですか？

それは AutoTrain という製品と混同していませんか？
そのとおりです。AutoModel は、初期化に使うチェックポイントさえ分かれば、正しいアーキテクチャを返せます。
複数の言語を扱えるチェックポイントやモデルはありますが、言語に応じてチェックポイントを自動で選ぶ組み込みのツールはありません。タスクに最適なチェックポイントは Model Hub で探してください！

6. 長さの異なるシーケンスをまとめてバッチ処理する際に、必要となる手法はどれですか？

はい、切り捨てはシーケンス長を調整し、データを矩形のテンソルにまとめるための方法の1つです。ただし、それだけでしょうか？
他の手法を使えば長方形のテンソルを返せますが、テンソルとして返すこと自体は、シーケンスをまとめてバッチ化する役には立ちません。
はい、パディングはシーケンス長を揃え、データを矩形のテンソルにまとめるための方法の1つです。ただし、それだけでしょうか？
そのとおりです！長さの異なるシーケンスを扱うとき、アテンションマスクは非常に重要です。ただし、意識すべき手法はそれだけではありません。

10. 次のコードに問題はありますか？

from transformers import AutoTokenizer, AutoModel

tokenizer = AutoTokenizer.from_pretrained("bert-base-cased")
model = AutoModel.from_pretrained("gpt2")

encoded = tokenizer("Hey!", return_tensors="pt")
result = model(**encoded)
残念ながら、モデルと、別のチェックポイントで学習されたトークナイザを組み合わせるのは、たいてい良い考えではありません。モデルは、このトークナイザが出力するトークン ID に対応する表現を学習していません。そのため、仮に実行できたとしても、有意味な予測結果は期待できないでしょう。
正解です！
確かに、モデルへの入力はすべてバッチである必要があります。ただし、シーケンスが1つしかないので、それを切り捨てたりパディングしたりしても必ずしも意味がありません。切り捨てとパディングは、文のリストをまとめてバッチ化するための手法です。
