Hugging Face Hub でプルリクエストエージェントを作る

MCP コースの Unit 3 へようこそ！

このユニットでは、ディスカッションやコメントをもとに Hugging Face のモデルリポジトリへ自動でタグ付けするプルリクエストエージェントを作ります。MCP と Webhook リスナー、自動化ワークフローをどう組み合わせるかを示す、実践的なアプリケーションです。

💡 ヒント

このユニットでは、MCP サーバーが Hugging Face Hub からのリアルタイムイベントに応答し、リポジトリのメタデータを改善するプルリクエストを自動で作成するという、実世界のユースケースを取り上げます。

このユニットで学ぶこと

このユニットでは、次のことを行います。

  • Hugging Face Hub API と連携する MCP サーバーを作る
  • ディスカッションイベントに応答する Webhook リスナーを実装する
  • モデルリポジトリ向けの自動タグ付けワークフローを構築する
  • Webhook 駆動のアプリケーション一式を Hugging Face Spaces にデプロイする

このユニットを終える頃には、ディスカッションを監視し、プルリクエストを通じてリポジトリのメタデータを自動で改善できる、動作する PR エージェントが手元にできあがります。

前提条件

このユニットに進む前に、次の点を確認してください。

  • Unit 1 と Unit 2 を修了しているか、MCP の概念に馴染みがあること
  • Python、FastAPI、Webhook の概念に慣れていること
  • Hugging Face Hub のワークフローとプルリクエストの基本を理解していること
  • 次の開発環境が用意できていること:
  • Python 3.11+
  • API アクセスが可能な Hugging Face アカウント

プルリクエストエージェントのプロジェクト

タグ付けエージェントは、MCP サーバー、Webhook リスナー、エージェントのロジック、デプロイ基盤という4つの主要コンポーネントで構成します。このエージェントは、ディスカッションやコメントをもとにモデルリポジトリにタグ付けできます。モデルの作者は、自分でリポジトリにタグ付けしなくても、そのまま使える PR を受け取れるので、時間を節約できます。

上の図には、モデルのタグを読み取って更新できる MCP サーバーがあります。Hugging Face Hub から Webhook を受け取れる Webhook リスナーがあります。ディスカッションやコメントを分析し、モデルのタグを更新する PR を作成するエージェントがあります。そして、MCP サーバーを Hugging Face Spaces にデプロイできるデプロイ基盤があります。

プロジェクト概要

このアプリケーションを作るには、次のファイルが必要です。

ファイル 役割 説明
mcp_server.py MCP サーバーの本体 モデルのタグを読み取って更新するツールを持つ FastMCP ベースのサーバー
app.py Webhook リスナーとエージェント Webhook を受け取り、ディスカッションを処理して PR を作成する FastAPI アプリ
requirements.txt 依存関係 FastMCP、FastAPI、huggingface-hub を含む Python パッケージ
pyproject.toml プロジェクト設定 uv による依存関係管理を備えた、モダンな Python パッケージング
Dockerfile デプロイ Hugging Face Spaces 向けのコンテナ設定
env.example 設定テンプレート 必要な環境変数とシークレット
cleanup.py ユーティリティ 開発とテスト後の片付けに使うヘルパースクリプト

これらのファイルを1つずつ見て、それぞれの役割を理解していきましょう。

MCP サーバー（mcp_server.py）

アプリケーションの心臓部です。次のツールを提供する FastMCP サーバーです。

  • モデルリポジトリから現在のタグを読み取る
  • Hub へのプルリクエストで新しいタグを追加する
  • エラーハンドリングと検証

ここで MCP サーバーを実装します。このプロジェクトの作業の大部分はここです。Gradio アプリと FastAPI アプリは MCP サーバーと Webhook リスナーのテストに使い、すでに利用できる状態になっています。

Webhook との連携

Hugging Face Webhooks Guide に沿って、このエージェントは次のことを行います。

  • ディスカッションのコメントイベントを待ち受ける
  • セキュリティのために Webhook の署名を検証する
  • メンションとタグの提案を処理する
  • プルリクエストを自動で作成する

エージェントの機能

エージェントはディスカッションの内容を分析して、次のことを行います。

  • 明示的なタグの言及（tag: pytorch、#transformers）を抽出する
  • 自然言語から暗黙的なタグを認識する
  • 既知の ML/AI カテゴリに照らしてタグを検証する
  • 適切なプルリクエストの説明文を生成する

デプロイと本番運用

  • Hugging Face Spaces へのコンテナ化されたデプロイ
  • シークレットのための環境変数管理
  • Webhook 応答のためのバックグラウンドタスク処理
  • テストと監視のための Gradio インターフェース

Webhook 連携の概要

この PR エージェントは、Hugging Face のディスカッションボットが使うのと同じ Webhook 基盤を利用します。Webhook がリアルタイム応答を可能にする仕組みは次のとおりです。

Webhook のフローは次のように動作します。

  1. イベントの発生: ユーザーがモデルリポジトリのディスカッションにコメントを作成する
  2. Webhook の配信: Hugging Face がエンドポイントに POST リクエストを送る
  3. 認証: セキュリティのために Webhook シークレットを検証する
  4. 処理: エージェントがコメントを分析し、タグの提案を探す
  5. アクション: 関連するタグが見つかれば、プルリクエストを作成する
  6. 応答: PR の作成はバックグラウンドで行い、Webhook には即座に応答する

さあ、始めましょう！

Hugging Face のリポジトリを自動で改善できる、本番投入可能な PR エージェントを作る準備はできましたか。まずプロジェクト構成をセットアップし、MCP サーバーの実装を理解するところから始めましょう。
