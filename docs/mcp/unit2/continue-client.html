ローカルモデル・オープンソースモデルで MCP を使う

このセクションでは、Ollama のようなローカルツールと連携する AI コーディングアシスタント構築ツール Continue を使って、MCP をローカルモデルやオープンソースモデルと接続します。

Continue のセットアップ

Continue は VS Code マーケットプレイスからインストールできます。

💡 ヒント

Continue には JetBrains 用の拡張機能もあります。

VS Code 拡張機能

  1. Visual Studio Marketplace の Continue 拡張機能ページ で Install をクリックする
  2. VS Code で Continue 拡張機能ページが開くので、そこで再度 Install をクリックする
  3. 左サイドバーに Continue のロゴが表示されます。使いやすくするために、Continue を右サイドバーに移動しましょう

Continue の設定が完了したら、次にローカルモデルを取得するために Ollama をセットアップします。

ローカルモデル

Continue と互換性のあるローカルモデルを実行する方法は数多くあります。人気のある選択肢は Ollama、Llama.cpp、LM Studio の3つです。Ollama は、大規模言語モデル（LLM）をローカルで簡単に実行できるオープンソースツールです。Llama.cpp は LLM を実行するための高性能な C++ ライブラリで、OpenAI 互換サーバーも含まれます。LM Studio は、ローカルモデルを実行するためのグラフィカルインターフェースを提供します。

Hugging Face Hub からローカルモデルにアクセスでき、主要なローカル推論アプリすべてのコマンドとクイックリンクを取得できます。

llamacpp

Llama.cpp は、LLM を提供するための軽量な OpenAI API 互換 HTTP サーバーである `llama-server` を提供します。[Llama.cpp リポジトリ](https://github.com/ggml-org/llama.cpp) の手順に従ってソースからビルドすることも、システム向けのビルド済みバイナリがあればそれを使うこともできます。詳細は [Llama.cpp のドキュメント](https://github.com/ggerganov/llama.cpp) を参照してください。 `llama-server` が用意できたら、次のようなコマンドで Hugging Face のモデルを実行できます。 
llama-server -hf unsloth/Devstral-Small-2505-GGUF:Q4_K_M

lmstudio

LM Studio は、Mac、Windows、Linux 向けのアプリケーションで、グラフィカルインターフェースを使ってオープンソースモデルをローカルで簡単に実行できます。始めるには: 1. [ここをクリックして LM Studio でモデルを開く](lmstudio://open_from_hf?model=unsloth/Devstral-Small-2505-GGUF)。 2. モデルのダウンロードが完了したら、"Local Server" タブに移動し、"Start Server" をクリックします。

ollama

Ollama を使うには、[インストール](https://ollama.com/download) して、`ollama run` コマンドで実行したいモデルをダウンロードします。 たとえば、[Devstral-Small](https://huggingface.co/unsloth/Devstral-Small-2505-GGUF?local-app=ollama) モデルは次のコマンドでダウンロードして実行できます。 
ollama run hf.co/unsloth/Devstral-Small-2505-GGUF:Q4_K_M
このモデルのサイズは約14GB なので、実行するマシンに十分な空き RAM があることを確認してください。そうでない場合、「model requires more system memory than is available」のようなエラーが表示されることがあります。

💡 ヒント

Continue はさまざまなローカルモデルプロバイダーをサポートしています。Ollama、Llama.cpp、LM Studio のほかにも、他のプロバイダーを使えます。サポートされるプロバイダーの完全なリストと詳細な設定オプションについては、Continue のドキュメント を参照してください。

ツール呼び出しが組み込み機能として備わっているモデルを使うことが重要です。たとえば Codestral、Qwen、Llama 3.1x です。

  1. ワークスペースのトップレベルに .continue/models というフォルダを作成する
  2. モデルプロバイダーを設定するファイルをこのフォルダに追加する。例: local-models.yaml
  3. Ollama、Llama.cpp、LM Studio のどれを使うかに応じて、次の設定を追加する

llamacpp

これは、`llama-server` で提供される `llama.cpp` モデル用の設定です。`model` フィールドは、提供するモデルと一致させる必要があります。 
name: Llama.cpp model
version: 0.0.1
schema: v1
models:
  - provider: llama.cpp
    model: unsloth/Devstral-Small-2505-GGUF
    apiBase: http://localhost:8080
    defaultCompletionOptions:
      contextLength: 8192 # モデルに合わせて調整する
    name: Llama.cpp Devstral-Small
    roles:
      - chat
      - edit

lmstudio

これは、LM Studio 経由で提供されるモデル用の設定です。モデルの識別子は、LM Studio に読み込まれているものと一致させる必要があります。 
name: LM Studio Model
version: 0.0.1
schema: v1
models:
  - provider: lmstudio
    model: unsloth/Devstral-Small-2505-GGUF
    name: LM Studio Devstral-Small
    apiBase: http://localhost:1234/v1
    roles:
      - chat
      - edit

ollama

これは、Ollama モデル用の設定です。 
name: Ollama Devstral model
version: 0.0.1
schema: v1
models:
  - provider: ollama
    model: unsloth/devstral-small-2505-gguf:Q4_K_M
    defaultCompletionOptions:
      contextLength: 8192
    name: Ollama Devstral-Small
    roles:
      - chat
      - edit

デフォルトでは、各モデルには最大コンテキスト長があり、この場合は 128000 トークンです。このセットアップでは、複数の MCP リクエストを実行するためにそのコンテキストウィンドウをより大きく使い、より多くのトークンを処理できる必要があります。

仕組み

ツールのハンドシェイク

ツールは、モデルが外部世界とインターフェースするための強力な手段を提供します。ツールは、名前と引数スキーマを持つ JSON オブジェクトとしてモデルに提供されます。たとえば、filepath 引数を持つ read_file ツールは、モデルに特定のファイルの内容をリクエストする能力を与えます。

次のハンドシェイクは、エージェントがツールを使う方法を説明しています。

  1. Agent モードでは、利用可能なツールが user チャットリクエストと一緒に送信される
  2. モデルは、レスポンスにツール呼び出しを含めることを選択できる
  3. ユーザーが許可を与える。そのツールのポリシーが Automatic に設定されている場合、このステップはスキップされる
  4. Continue は、組み込み機能、またはそのツールを提供する MCP サーバーを使ってツールを呼び出す
  5. Continue は結果をモデルに送り返す
  6. モデルが応答し、場合によっては別のツール呼び出しを行い、ステップ2に戻る

Continue は複数のローカルモデルプロバイダーをサポートしています。タスクごとに異なるモデルを使ったり、必要に応じてモデルを切り替えたりできます。このセクションではローカルファーストのソリューションに焦点を当てますが、Continue は OpenAI、Anthropic、Microsoft/Azure、Mistral などの人気プロバイダーとも連携します。独自のモデルプロバイダーを実行することもできます。

ローカルモデルと MCP の統合

すべてがセットアップできたので、既存の MCP サーバーを追加しましょう。以下は、アシスタントで使う新しい MCP サーバーをセットアップする簡単な例です。

  1. ワークスペースのトップレベルに .continue/mcpServers というフォルダを作成する
  2. このフォルダに playwright-mcp.yaml というファイルを追加する
  3. playwright-mcp.yaml に次の内容を書き込んで保存する
name: Playwright mcpServer
version: 0.0.1
schema: v1
mcpServers:
  - name: Browser search
    command: npx
    args:
      - "@playwright/mcp@latest"

では、次のコマンドをプロンプトとして入力し、MCP サーバーをテストしましょう。

1. Using playwright, navigate to https://news.ycombinator.com.

2. Extract the titles and URLs of the top 4 posts on the homepage.

3. Create a file named hn.txt in the root directory of the project.

4. Save this list as plain text in the hn.txt file, with each line containing the title and URL separated by a hyphen.

Do not output code or instructions—just complete the task and confirm when it is done.

結果として、現在の作業ディレクトリに hn.txt というファイルが生成されます。

まとめ

Continue を Llama 3.1 のようなローカルモデルや MCP サーバーと組み合わせることで、コードとデータをプライベートに保ちながら最先端の AI 機能を活用できる、強力な開発ワークフローが実現しました。

このセットアップにより、Web 自動化からファイル管理まで、専用のツールで AI アシスタントをカスタマイズする柔軟性が得られ、すべてローカルマシン上で動作します。開発ワークフローを次のレベルに引き上げる準備はできましたか？ Continue Hub の MCP 探索ページ でさまざまな MCP サーバーを試すことから始めて、ローカル AI がコーディング体験をどう変えるか発見しましょう。
