01 / Why this project

技術を学ぶことと、
英語を読むことは違う。

英語の読解に費やす時間を減らし、技術そのものを考える時間を増やしたい。

機械学習を独学するなかで、Hugging Face の教材を使おうとしました。内容は充実しているのに、日本語で通して学ぶ環境が十分にない。新しい概念を理解することと、英語の文章を逐一読み解くことを、同時に求められる点に不便を感じました。

もちろん、英語の論文や公式ドキュメントを読む力は重要です。しかし、最初からそれを学習の条件にする必要はありません。まず日本語で基本的な仕組みを理解し、必要になったときに原典へ進める。そのための入口を作ることが、このサイトの目的です。

Hugging Face とは
世界中の開発者や研究者が、機械学習モデルやデータセットを公開・共有するプラットフォームと、その開発を支えるオープンソースライブラリ群を提供する企業です。モデルを探す「Hub」、プログラムから利用する「Transformers」などを通じて、研究成果を実際の開発に結び付けています。このサイトは、その Hugging Face が公開する学習コースを翻訳したものです。

03 / Your first session

読むだけで終わらせないために

初学者にも勧められる理由は、説明のすぐ後にコードと実習が用意されていることです。最初から難しい開発環境を用意する必要はありません。まずは小さなプログラムを実行してみてください。

STEP 01

Python に慣れる

変数、関数、繰り返し処理、リストや辞書を読めることが目安です。初心者は日本語で読める無料教材から始められます。

東京大学「Python プログラミング入門」 ↗
STEP 02

ブラウザで実行する

Google Colab なら、パソコンに Python をインストールせずにコードを試せます。無料枠には利用制限があり、GPU の利用は保証されません。

Google Colab を開く ↗
STEP 03

最初の教材を開く

LLM コースの第0章では、Colab とローカルの仮想環境の両方について説明しています。迷ったら、最初は Colab を選んでください。

LLM コース：作業環境の準備 →

Colab での最初の操作

① Colab で新しいノートブックを作る。② コードセルに以下を入力して実行する。③ エラーが出なければ次の教材へ進む。

# 新しいコードセルで実行
!pip install transformers datasets

print(transformers.__version__)

このサイトの使い方

各コースの目次から章を選び、前後のページへ順番に移動できます。クイズがあるページでは、その場で答え合わせができます。

本文のコードはこのサイト上では実行できません。Colab などにコピーして試してください。分からない用語はページ上部の検索欄や用語集で調べ、必要なときは各ページの「公式ページで読む」から英語原典に戻れます。

読むだけなら Hugging Face の登録は不要です。モデルの取得条件や公開作業によってはアカウントやアクセストークンが必要になります。

05 / Translation & review

機械翻訳を、そのまま公開しない。

本サイトは、Muse、ChatGPT、制作者の3者で作成しました。AI に翻訳を任せるだけでは、意味の取り違えや日本語として不自然な表現が残ります。そのため、原典の版を固定し、翻訳、審査、修正、再検証を繰り返しています。

01 / TRANSLATIONMuse — 翻訳・修正・検証

英語原典の取得、MDX ファイルの翻訳、指摘の照合と修正、コード・リンクなどの構造検証を担当。

02 / REVIEWChatGPT — 訳文の審査

原典との意味の対応、日本語の自然さ、専門用語、表記・組版を確認し、該当行と修正案を提示。

03 / EDITORIAL POLICY霞ヶ関京 — 方針と最終判断

翻訳の目的、文章の基準、専門用語の扱い、公開方針などを決定。日本語の技術解説としての品質を重視。

Review cycle / 実際の制作手順

01 · MUSE原典の版を固定Git のコミットを指定
02 · MUSE翻訳文を作成コード・数式・URL を保護
03 · CHATGPT4観点でレビュー自然さ／意味／用語／組版
04 · MUSE指摘を原文と照合根拠を確認して修正
05 · BOTH再検証・再審査構造チェックと合否判定
↶　未解消の問題があれば、照合と修正に戻る。合格後にサイトへ反映する。

日本語の文章は、日本語として組み立てる

英文の構造をそのまま移すと、文法的には正しくても読みにくい文章になります。長い一文を分け、主語と述語の関係を明らかにし、漢字・仮名の使い分けや改行を整えます。手本にしているのは『とほほのWWW入門』のような、平明な技術解説です。

ただし Transformer や Tokenizer などの用語は、無理に和訳しません。公式ドキュメントや実務で通用する表記を優先し、説明文の自然さと技術的な正確性を両立させます。

レビューの指摘も、そのまま信用しない

レビューでは「ファイル名・行番号・現行文の引用・問題点・修正案」を一組として記録します。指摘の引用が実ファイルに存在するかを調べ、原文の意味と合う場合に限って修正します。修正後は、アンカー、コード、リンク、画像などが意図せず変わっていないかを機械的に確認します。

原典に誤りがある場合も、翻訳者の判断で内容をひそかに書き換えることは避けています。翻訳に使った原典の版や作業経過は、README と 作業記録で公開しています。
