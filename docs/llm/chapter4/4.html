モデルカードを作る

モデルカードは、モデルリポジトリ内のモデルやトークナイザのファイルと同じくらい重要といえるでしょう。モデルについて説明する基本的な文書で、コミュニティの他の人がモデルを再利用したり、結果を再現したり、そのモデルを土台に新しい成果物を作ったりする際に役立ちます。

モデルの学習方法と評価方法を記録すると、どのような結果が期待出来るかを他の人が理解し易くなります。また、使ったデータや前処理・後処理についても十分に説明すれば、モデルの制限やバイアスに加え、どのような場面で役立ち、どのような場面では役立たないのかも把握出来ます。

その為、モデルについて明確に説明するモデルカードの作成は、とても重要です。ここでは、作成時に役立つポイントを紹介します。モデルカードは、先程紹介した Markdown 形式の README.md ファイルに記述します。

「モデルカード」という考え方は Google の研究から生まれ、Margaret Mitchell らの論文 "Model Cards for Model Reporting" で初めて発表されました。ここで説明する内容の多くも、この論文に基づいています。再現性、再利用性、公平性が重視される中で、モデルカードが重要な理由を理解する為にも、是非読んでみてください。

モデルカードは通常、モデルの用途についてのごく簡単な概要から始まり、その後のセクションで詳細を述べます。

  • モデルの説明
  • 想定される用途と制限
  • 使い方
  • 制限とバイアス
  • 学習データ
  • 学習手順
  • 評価結果

各セクションに何を書くべきかを見ていきましょう。

モデルの説明

ここには、モデルの基本情報を記載します。例えば、アーキテクチャ、バージョン、論文で発表されたモデルかどうか、元の実装が利用出来るかどうか、開発者などです。著作権の帰属先もここに明記します。学習手順やパラメータの概要、重要な免責事項を載せることも出来ます。

想定される用途と制限

ここでは、モデルの想定用途と、利用出来る言語・分野・領域を説明します。また、適用範囲外と分かっている領域や、十分な性能を発揮出来ない可能性が高い領域も記載出来ます。

使い方

ここでは、モデルの使い方を例と共に紹介します。pipeline() 関数を使う方法、モデルやトークナイザのクラスを使う方法の他、利用者の参考になるコードを載せてもかまいません。

学習データ

このパートでは、モデルの学習に使ったデータセットを示します。データセットの概要も併せて説明するとよいでしょう。

学習手順

ここでは、他のユーザーが学習を再現出来るように、必要な手順や条件を詳しく記録します。例えば、データの前処理と後処理、学習したエポック数、バッチサイズ、学習率などです。

変数と評価指標

ここでは、評価に使う指標と、何を測定するかを説明します。どの評価指標を使い、どのデータセットのどの分割（検証用やテスト用など）で評価したかを示すと、他のモデルと性能を比較し易くなります。評価指標や測定対象は、前のセクションで説明した想定ユーザーや用途を踏まえて決めます。

評価結果

最後に、評価用データセットでモデルがどの程度の性能を発揮するかを示します。モデルが決定しきい値を使う場合は、評価時に使ったしきい値を示すか、想定される用途に応じてしきい値を変えた場合の評価結果を詳しく記載してください。

例

よく出来たモデルカードの例をいくつか紹介します。

  • bert-base-cased
  • gpt2
  • distilbert

様々な組織や企業が作成したモデルカードの例も、こちら で確認出来ます。

注意

モデルを公開する時、モデルカードは必須ではありません。また、作成する場合でも、ここで紹介した全てのセクションを含める必要はありません。

但し、モデルについて詳しい説明を残しておけば、あとから利用する人の助けになります。自分が把握していて記載出来る範囲で、出来るだけ多くのセクションを埋めることをお勧めします。

モデルカードのメタデータ

Hugging Face Hub を少し探索したことがあれば、モデルが特定のカテゴリに属していることに気づいたはずです。タスク、言語、ライブラリなどで絞り込むことが出来ます。モデルが属するカテゴリは、モデルカードのヘッダーに加えるメタデータに基づいて判定されます。

例えば、camembert-base のモデルカード のヘッダーには、次のような行があります。

---
language: fr
license: mit
datasets:
- oscar
---

Hugging Face Hub はこのメタデータを読み取り、フランス語に対応し、MIT ライセンスで提供され、Oscar データセットで学習されたモデルだと判別します。

モデルカードの完全な仕様 に従って、言語、ライセンス、タグ、データセット、評価指標に加え、学習中に得られた評価結果も指定出来ます。
