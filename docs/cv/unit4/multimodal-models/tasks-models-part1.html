マルチモーダルタスクとマルチモーダルモデル

このセクションでは、画像とテキストを組み合わせた様々なマルチモーダルタスクと、それに対応するモデルを紹介します。まず、前のセクションで学んだ「マルチモーダル」の意味を簡単に復習しましょう。私たち人間は、視覚や聴覚、触覚など、様々な感覚から情報を受け取り、周囲の世界を理解しています。複数の感覚を組み合わせて理解出来ることは、単一のモダリティだけを扱う従来の AI モデルには無い強みです。

マルチモーダルモデルは、この人間の認知の仕組みを参考に、テキスト、画像、音声、センサーデータなど、様々な情報を統合することで、人間との能力の差を縮めようとしています。複数のモダリティを組み合わせると、世界をより多面的且つ細かく理解出来るようになり、幅広いタスクや応用が可能になります。

タスクの例

特定のモデルを見る前に、画像とテキストを含む多様なタスクを理解することが重要です。これらのタスクには、以下が含まれます（これらに限りません）：

  • 視覚的質問応答（VQA）と視覚的推論（Visual Reasoning）：写真を見て、その内容についての質問に答えるコンピュータを想像してください。これが視覚的質問応答（VQA）です。例えば、「この車を運転しているのは誰？」という質問に答えられるよう、画像から情報を読み取ることを学習します。一方、視覚的推論は、単に物体を認識するだけでなく、物体同士の関係を推論したり、比較したり、場面全体の状況を理解したりして、正確な答えを導く為の重要な能力です。探偵が写真の中の手がかりを読み解くようなものですが、コンピュータならそれをはるかに速く、正確に行える可能性があります。

  • ドキュメント視覚的質問応答（DocVQA）：地図や契約書などの文書に含まれる文字とレイアウトをコンピュータが理解し、文書の画像についての質問に直接答えるタスクです。コンピュータービジョンによる画像処理と、自然言語処理によるテキストの理解を組み合わせることで、人間のように文書を読み、質問に答えられるようにします。AI によって文書検索を高度化し、画像として保存された文書から、これまで活用し難かった情報も取り出せるようにする技術だと考えてください。

  • 画像キャプション生成（Image captioning）：画像キャプション生成は、視覚情報と言語を結びつける技術です。画像を分析して細かな情報を取り出し、場面を理解した上で、その様子を説明する1〜2文の文章を作ります。例えば、穏やかな海に沈む夕日、ブランコで笑う子ども、にぎやかな街の通りなどを文章で描写出来ます。コンピュータービジョンと言語処理を組み合わせることで、コンピュータが写真を1枚ずつ読み取り、周囲の世界を言葉で説明出来るようになります。

  • 画像・テキスト検索（Image-Text Retrieval）：画像・テキスト検索は、画像とその説明文を対応付けて検索する技術です。例えば、図書館で本の表紙の絵や短い要約を手がかりに、特定の本を探すようなものです。画像と文章の両方の意味を理解出来る検索エンジンを使うことで、画像検索や自動キャプション生成、視覚障害者が画像の内容を文章で把握する為の支援など、様々な応用が可能になります。

  • 視覚的グラウンディング（Visual grounding）：視覚的グラウンディングは、言葉による説明と画像の中の物体や領域を対応付ける技術です。文章が画像のどの部分を指しているのかを理解することで、AI モデルは自然言語の説明に基づいて物体や領域の位置を特定出来ます。例えば、「果物かごの中の赤いリンゴはどこ？」と質問すると、AI が画像の中の該当するリンゴを直ぐにハイライトします。これが視覚的グラウンディングの働きです。

  • テキストからの画像生成（Text-to-Image generation）：テキストからの画像生成は、文章による説明をもとに画像を作る技術です。言葉を理解して画像を描く、魔法の絵筆のようなものだと考えると分かり易いでしょう。言語理解と画像生成を組み合わせることで、写実的な風景から夢のような抽象画まで、様々な画像を文章から生成出来ます。

視覚的質問応答（VQA）と視覚的推論

VQA 及び視覚的推論モデルの入力（画像＋テキスト）と出力（テキスト）の例[1]

視覚的質問応答（VQA）

  • 入力： 画像と質問のペア（画像とそれについての質問）。
  • 出力：
    • 多肢選択の場合：予め定義された選択肢の中で、正解に対応するラベル。
    • 自由形式の場合：画像と質問に基づいて生成した、自由な形式の自然言語の回答。
  • タスク：画像についての質問に答えることです。多くの VQA モデルは、予め用意された答えから選ぶ分類問題として扱います。上の例も参考にしてください。

視覚的推論

  • 入力： 特定の視覚的推論タスクによって異なります：
    • VQA 形式のタスク：画像と質問のペア。
    • マッチングタスク：画像とテキストの文。
    • 含意（entailment）タスク：画像とテキストのペア（複数の文を含むことも有る）。
    • サブクエスチョンタスク：画像と、知覚に関連する追加のサブクエスチョンを伴う主要な質問。
  • 出力： タスクによって異なります：
    • VQA：画像についての質問への答え。
    • マッチング：テキストが画像について正しいかどうかの真／偽。
    • 含意：画像がテキストを意味的に含意するかの予測。
    • サブクエスチョン：知覚に関連するサブクエスチョンへの答え。
  • タスク： 画像について様々な推論タスクを実行する。参考として上の例をご覧ください。

一般に、VQA と視覚的推論はどちらも 視覚的質問応答（VQA） タスクとして扱われます。VQA タスクで人気のモデルをいくつか挙げます：

  • BLIP-VQA： Salesforce AI が開発した、視覚的質問応答（VQA）タスクの為の大規模な事前学習済みモデルです。「Bootstrapping Language-Image Pre-training」（BLIP）アプローチを使い、ノイズの多いウェブデータとキャプション生成の両方を活用して、様々な視覚言語タスクで最先端の性能を達成しています。BLIP は Hugging Face で次のように使えます：
from PIL import Image
from transformers import pipeline

vqa_pipeline = pipeline(
    "visual-question-answering", model="Salesforce/blip-vqa-capfilt-large"
)

image = Image.open("elephant.jpeg")
question = "Is there an elephant?"

vqa_pipeline(image, question, top_k=1)

（入力文の訳：「象はいますか？」）

  • DePlot： プロットやチャートをテキストの要約に変換するよう学習された、ワンショットの視覚言語推論モデルです。これにより、LLM と統合して、人間が書いた新しいクエリでもデータについての複雑な質問に答えられます。DePlot は、プロットから表への変換タスクを標準化し、Pix2Struct アーキテクチャを活用することで、1つの例と LLM へのプロンプトだけで、チャート QA で従来の SOTA を上回っています。DePlot は Hugging Face で次のように使えます：
from transformers import Pix2StructProcessor, Pix2StructForConditionalGeneration
import requests
from PIL import Image

processor = Pix2StructProcessor.from_pretrained("google/deplot")
model = Pix2StructForConditionalGeneration.from_pretrained("google/deplot")

url = "https://raw.githubusercontent.com/vis-nlp/ChartQA/main/ChartQA%20Dataset/val/png/5090.png"
image = Image.open(requests.get(url, stream=True).raw)

inputs = processor(
    images=image,
    text="Generate underlying data table of the figure below:",
    return_tensors="pt",
)
predictions = model.generate(**inputs, max_new_tokens=512)
print(processor.decode(predictions[0], skip_special_tokens=True))

（入力文の訳：「下の図の基になるデータ表を生成してください」）

  • ViLT： 視覚・言語 Transformer（ViLT）モデルで、畳み込みや領域の教師なしに Transformer アーキテクチャを利用し、画像についての自然言語の質問に答える為に VQAv2 データセットでファインチューニングされたものです。ベースの ViLT モデルは大きなアーキテクチャ（B32 サイズ）を誇り、画像とテキストの共同学習を活用することで、様々な視覚言語タスク、特に VQA で効果的となり、競争力の有る性能を達成しています。ViLT は Hugging Face で次のように使えます：
from transformers import ViltProcessor, ViltForQuestionAnswering
import requests
from PIL import Image

# 画像と質問を準備する
url = "http://images.cocodataset.org/val2017/000000039769.jpg"
image = Image.open(requests.get(url, stream=True).raw)
text = "How many cats are there?"

processor = ViltProcessor.from_pretrained("dandelin/vilt-b32-finetuned-vqa")
model = ViltForQuestionAnswering.from_pretrained("dandelin/vilt-b32-finetuned-vqa")

# 入力を準備する
encoding = processor(image, text, return_tensors="pt")

# フォワードパス
outputs = model(**encoding)
logits = outputs.logits
idx = logits.argmax(-1).item()
print("予測された回答：", model.config.id2label[idx])

（入力文の訳：「猫は何匹いますか？」）

ドキュメント視覚的質問応答（DocVQA）

DocVQA モデルの入力（画像＋テキスト）と出力（テキスト）の例。[2]

  • 入力：
    • ドキュメント画像：文字、レイアウト、視覚要素を含む、スキャンした文書やデジタル形式の文書の画像。
    • ドキュメントについての質問：テキスト形式で提示された自然言語の質問。

  • タスク：

    • 分析と理解：DocVQA モデルは、内容を完全に理解する為に、ドキュメント内の視覚情報とテキスト情報の両方を処理しなければなりません。
    • 推論と推測：モデルは、関連する結論を導く為に、視覚要素、テキスト、質問の間の関係を確立する必要があります。
    • 自然言語の答えを生成する：モデルは、自然言語のテキスト形式で、質問に対して明確で簡潔且つ正確な答えを生成しなければなりません。参考として上の例をご覧ください。

  • 出力： 質問への答え：クエリに直接答え、ドキュメントで見つかった情報を正確に反映するテキストの応答。

次に、Hugging Face の人気の DocVQA モデルをいくつか見てみましょう：

  • LayoutLM： ドキュメント画像を理解する為に、テキストとそのレイアウトの両方を共同で分析する事前学習済みニューラルネットワークです。従来の NLP モデルとは異なり、フォントサイズ、位置、近接性といった要素を考慮して、単語とドキュメントの文脈における意味との関係を学習します。これにより、フォームの理解、レシートの分析、ドキュメント分類などのタスクに優れ、スキャンされたドキュメントから情報を抽出する強力なツールとなっています。LayoutLM は Hugging Face で次のように使えます：
from transformers import pipeline
from PIL import Image

pipe = pipeline("document-question-answering", model="impira/layoutlm-document-qa")

question = "What is the purchase amount?"
image = Image.open("your-document.png")

pipe(image=image, question=question)

## [{'answer': '20,000$'}]

（入力文の訳：「購入金額は幾らですか？」）

  • Donut： OCR フリーのドキュメント理解 Transformer としても知られ、従来の光学文字認識（OCR）を介さず、ドキュメント画像を直接分析して内容を理解する最先端の画像処理モデルです。視覚エンコーダ（Swin Transformer）とテキストデコーダ（BART）を組み合わせて情報を抽出し、テキストの説明を生成します。ドキュメント分類、フォームの理解、視覚的質問応答などのタスクに優れています。その独自の強みは「エンドツーエンド」な性質にあり、別々の OCR ステップが持ち込む潜在的なエラーを避け、効率的な処理で優れた精度を達成します。Donut モデルは Hugging Face で次のように使えます：
from transformers import pipeline
from PIL import Image

pipe = pipeline(
    "document-question-answering", model="naver-clova-ix/donut-base-finetuned-docvqa"
)

question = "What is the purchase amount?"
image = Image.open("your-document.png")

pipe(image=image, question=question)

## [{'answer': '20,000$'}]

（入力文の訳は、前の LayoutLM の例と同じです）

  • Nougat： 何百万もの学術論文で学習された視覚 Transformer モデルで、スキャンされた PDF を直接「読み」、数式や表のような複雑な要素も理解しながら、その内容を構造化されたマークアップ言語で出力出来ます。従来の光学文字認識を介さず、意味を保ちながら高い精度を達成し、PDF に蓄えられた科学的知識をより利用し易くします。Nougat は Donut と同じアーキテクチャ、つまり画像 Transformer エンコーダと自己回帰型テキスト Transformer デコーダを使って、科学論文の PDF を Markdown に変換し、アクセスし易くします。Nougat モデルは Hugging Face で次のように使えます：
from huggingface_hub import hf_hub_download
import re
from PIL import Image

from transformers import NougatProcessor, VisionEncoderDecoderModel
from datasets import load_dataset
import torch

processor = NougatProcessor.from_pretrained("facebook/nougat-base")
model = VisionEncoderDecoderModel.from_pretrained("facebook/nougat-base")

device = "cuda" if torch.cuda.is_available() else "cpu"
model.to(device)
# モデルのために PDF 画像を準備する
filepath = hf_hub_download(
    repo_id="hf-internal-testing/fixtures_docvqa",
    filename="nougat_paper.png",
    repo_type="dataset",
)
image = Image.open(filepath)
pixel_values = processor(image, return_tensors="pt").pixel_values

# 転写を生成する（ここでは 30 トークンだけ生成する）
outputs = model.generate(
    pixel_values.to(device),
    min_length=1,
    max_new_tokens=30,
    bad_words_ids=[[processor.tokenizer.unk_token_id]],
)

sequence = processor.batch_decode(outputs, skip_special_tokens=True)[0]
sequence = processor.post_process_generation(sequence, fix_markdown=False)
# 注: ここでは \n 文字を出力するために repr を使っているが、そのまま sequence を print してもよい
print(repr(sequence))

画像キャプション生成

画像キャプション生成モデルの入力（画像）と出力（テキスト）の例。[1]

  • 入力：
    • 画像：様々な形式（JPEG、PNG など）の画像。
    • 事前学習済みの画像特徴抽出器（任意）：畳み込みニューラルネットワーク（CNN）など、画像から意味の有る特徴を抽出出来る事前学習済みニューラルネットワーク。
  • 出力： テキストのキャプション：入力画像の内容を正確に説明する1文又は1段落。物体、行動、関係、全体の文脈を捉えます。参考として上の例をご覧ください。
  • タスク：画像の自然言語による説明を自動生成すること。これには、（1）画像の視覚的内容（物体、行動、関係）を理解すること、（2）この情報を意味の有る表現にエンコードすること、（3）この表現を、首尾一貫した、文法的に正しく情報量の多い文や句へデコードすることが含まれます。

次に、Hugging Face の人気の画像キャプション生成モデルをいくつか見てみましょう：

  • ViT-GPT2： 画像キャプションを生成する為の PyTorch モデルで、視覚特徴抽出の為の Vision Transformer（ViT）とテキスト生成の為の GPT-2 を組み合わせて構築されています。COCO データセットで学習されており、画像の細かな特徴を捉える ViT の能力と、自然な文章を生成する GPT-2 の能力を活かして、画像の内容を正確且つ詳しく説明するキャプションを作ります。このオープンソースモデルは、画像理解とキャプション生成のタスクに効果的なソリューションを提供します。ViT-GPT2 は Hugging Face で次のように使えます：
from transformers import pipeline

image_to_text = pipeline("image-to-text", model="nlpconnect/vit-gpt2-image-captioning")

image_to_text("https://ankur3107.github.io/assets/images/image-captioning-example.png")

# [{'generated_text': 'a soccer game with a player jumping to catch the ball '}]

（出力の訳：「ボールを捕ろうと跳んでいる選手がいるサッカーの試合」）

  • BLIP-Image-Captioning： BLIP を基にした最先端の画像キャプション生成モデルです。BLIP は、視覚言語の理解と生成を統一する為に、クリーンなウェブデータとノイズの多いウェブデータの両方で事前学習されたフレームワークです。ノイズの多いキャプションを除去するブートストラップ処理を使い、画像キャプション生成、画像・テキスト検索、VQA などのタスクで性能を向上させています。ViT-L をバックボーンに採用したこの大規模版（large）は、画像の内容を正確且つ詳しく説明するキャプションの生成に優れています。BLIP 画像キャプション生成モデルは Hugging Face で次のように使えます：
import requests
from PIL import Image
from transformers import BlipProcessor, BlipForConditionalGeneration

processor = BlipProcessor.from_pretrained("Salesforce/blip-image-captioning-large")
model = BlipForConditionalGeneration.from_pretrained(
    "Salesforce/blip-image-captioning-large"
)

img_url = "https://storage.googleapis.com/sfr-vision-language-research/BLIP/demo.jpg"
raw_image = Image.open(requests.get(img_url, stream=True).raw).convert("RGB")

# 条件付き画像キャプション生成
text = "a photography of"
inputs = processor(raw_image, text, return_tensors="pt")

out = model.generate(**inputs)
print(processor.decode(out[0], skip_special_tokens=True))

# 無条件の画像キャプション生成
inputs = processor(raw_image, return_tensors="pt")

out = model.generate(**inputs)
print(processor.decode(out[0], skip_special_tokens=True))

（入力文の訳：「〜の写真」という文の書き出しに当たる断片です）

  • git-base： microsoft/git-base は GIT（GenerativeImage2Text）モデルのベースサイズ版です。GIT は、画像のテキスト説明を生成するよう学習された Transformer デコーダです。画像トークンとテキストトークンの両方を入力として受け取り、画像とこれまでのテキストの両方に基づいて次のテキストトークンを予測します。その為、画像や動画のキャプション生成などのタスクに適しています。microsoft/git-base-coco や microsoft/git-base-textcaps のようなファインチューニング済みバージョンが特定のデータセット向けに存在し、ベースモデルはさらなるカスタマイズの出発点となります。git-base モデルは Hugging Face で次のように使えます：
from transformers import AutoProcessor, AutoModelForCausalLM
import requests
from PIL import Image

processor = AutoProcessor.from_pretrained("microsoft/git-base-coco")
model = AutoModelForCausalLM.from_pretrained("microsoft/git-base-coco")

url = "http://images.cocodataset.org/val2017/000000039769.jpg"
image = Image.open(requests.get(url, stream=True).raw)

pixel_values = processor(images=image, return_tensors="pt").pixel_values

generated_ids = model.generate(pixel_values=pixel_values, max_length=50)
generated_caption = processor.batch_decode(generated_ids, skip_special_tokens=True)[0]
print(generated_caption)

Hugging Face transformers ライブラリで画像キャプション生成モデルを学習して使う方法は、こちらで詳しく学べます。

画像・テキスト検索

テキストから画像への検索の入力（テキストクエリ）と出力（画像）の例。[1]

  • 入力：
    • 画像：様々な形式（JPEG、PNG など）の画像。
    • テキスト：通常、画像に関連付けられたキャプション、説明、キーワードの形の自然言語テキスト。
  • 出力：
    • 関連する画像：テキストクエリが与えられると、システムはそのテキストに最も関連する画像の順位付きリストを返す。
    • 関連するテキスト：画像クエリが与えられると、システムはその画像を最もよく説明するテキストの説明やキャプションの順位付きリストを返す。
  • タスク：
    • 画像からテキストへの検索：画像を入力として、その内容を正確に説明するテキストの説明やキャプションを取得する。
    • テキストから画像への検索：テキストクエリが与えられた時、テキストで言及された概念や実体と視覚的に一致する画像を取得する。

画像・テキスト検索で最も人気のモデルの1つが CLIP です。

  • CLIP（Contrastive Language-Image Pretraining）： 共有埋め込み空間を活用することで、画像・テキスト検索に優れています。対照学習により、大規模な画像とテキストのデータセットで事前学習され、モデルが多様な概念を共通の空間へマッピング出来るようになります。CLIP は事前学習時に対照学習アプローチを活用し、画像とテキストを共有埋め込み空間へマッピングすることを学習します。この共有空間により、2つのモダリティ間の直接比較が可能になり、効率的で正確な検索タスクが実現します。画像・テキスト検索では、画像とテキストを共有埋め込み空間にエンコードすることで CLIP を適用出来、画像とテキストクエリの類似度は、それぞれの埋め込みの近さで測られます。このモデルの汎用性は、タスク固有のファインチューニングなしに意味的な関係を把握出来る能力から生まれ、コンテンツベースの画像検索から、画像への自然言語クエリの解釈まで、幅広い応用で効率的に使えます。CLIP を Hugging Face で画像・テキスト検索に使う方法は次の通りです：
from PIL import Image
import requests

from transformers import CLIPProcessor, CLIPModel

model = CLIPModel.from_pretrained("openai/clip-vit-base-patch32")
processor = CLIPProcessor.from_pretrained("openai/clip-vit-base-patch32")

url = "http://images.cocodataset.org/val2017/000000039769.jpg"
image = Image.open(requests.get(url, stream=True).raw)

inputs = processor(
    text=["a photo of a cat", "a photo of a dog"],
    images=image,
    return_tensors="pt",
    padding=True,
)

outputs = model(**inputs)
logits_per_image = outputs.logits_per_image  # これは画像・テキストの類似度スコア
probs = logits_per_image.softmax(
    dim=1
)  # softmax を取ってラベルの確率を得ることができる

（入力文の訳：「猫の写真」「犬の写真」）

Hugging Face で CLIP を画像・テキスト検索に使う方法は、こちらで詳しく学べます。

視覚的グラウンディング

入力（画像＋テキスト）と出力（バウンディングボックス）の例。（a）フレーズグラウンディング、（b）表現理解。[1]

  • 入力：

    • 画像：シーンや物体の視覚的表現。
    • 自然言語クエリ：画像の特定の部分を指すテキストの説明や質問。

  • 出力： バウンディングボックス又はセグメンテーションマスク：クエリで説明された物体や領域に対応する、画像内の空間領域。通常は座標やハイライトされた領域として表されます。

  • タスク： 関連する物体や領域の位置を特定する：モデルは、クエリに一致する画像の部分を正しく特定しなければなりません。これには、画像の視覚的内容とクエリの言語的意味の両方の理解が必要です。

次に、Hugging Face の人気の視覚的グラウンディング（物体検出）モデルをいくつか見てみましょう。

  • OWL-ViT： OWL-ViT（Vision Transformer for Open-World Localization）は、標準的な Vision Transformer アーキテクチャの上に構築され、大規模な画像・テキストのペアで学習された強力な物体検出モデルです。「オープンボキャブラリ」な検出に優れ、テキストの説明に基づき、学習データに存在しない物体も特定出来ます。対照的な事前学習とファインチューニングを活用し、ゼロショット（テキスト誘導）検出タスクとワンショット（画像誘導）検出タスクの両方で優れた性能を達成し、画像内の柔軟な検索と特定の為の多用途なツールとなっています。OWL-ViT は Hugging Face で次のように使えます：
import requests
from PIL import Image
import torch

from transformers import OwlViTProcessor, OwlViTForObjectDetection

processor = OwlViTProcessor.from_pretrained("google/owlvit-base-patch32")
model = OwlViTForObjectDetection.from_pretrained("google/owlvit-base-patch32")

url = "http://images.cocodataset.org/val2017/000000039769.jpg"
image = Image.open(requests.get(url, stream=True).raw)
texts = [["a photo of a cat", "a photo of a dog"]]
inputs = processor(text=texts, images=image, return_tensors="pt")
outputs = model(**inputs)

# バウンディングボックス予測をリスケールするための対象画像サイズ（高さ、幅）[batch_size, 2]
target_sizes = torch.Tensor([image.size[::-1]])
# 出力（バウンディングボックスとクラスのロジット）を COCO API へ変換する
results = processor.post_process_object_detection(
    outputs=outputs, threshold=0.1, target_sizes=target_sizes
)

i = 0  # 対応するテキストクエリについて、最初の画像の予測を取得する
text = texts[i]
boxes, scores, labels = results[i]["boxes"], results[i]["scores"], results[i]["labels"]

# 検出された物体とリスケールされたボックス座標を出力する
for box, score, label in zip(boxes, scores, labels):
    box = [round(i, 2) for i in box.tolist()]
    print(
        f"検出した物体：{text[label]}、信頼度：{round(score.item(), 3)}、位置：{box}"
    )

（入力文の訳：「猫の写真」「犬の写真」）

  • Grounding DINO[3]： Transformer ベースの物体検出器（DINO）と、画像の領域と言語表現の対応付けを学ぶ事前学習（grounded pre-training）を組み合わせた、最先端のゼロショット物体検出モデルです。画像と人間の言語入力（カテゴリ名や説明など）の両方を理解出来る為、学習データになかった物体でも特定出来ます。そのアーキテクチャは、テキストと画像のバックボーン、特徴エンハンサ、言語誘導型クエリ選択、クロスモダリティデコーダを組み合わせ、COCO や LVIS のようなベンチマークで優れた結果を達成しています。本質的に、Grounding DINO は視覚情報を取り込み、テキストの説明と結びつけ、その理解を使ってまったく新しいカテゴリの中でも物体を特定します。

Grounding DINO モデルは、Google Colab のこちらで試せます。

テキストからの画像生成

テキスト・画像生成の為の自己回帰モデルと拡散モデルの図。[1]

  • 自己回帰モデル： これらのモデルは、このタスクを、言語モデルが文を生成するのと同様に、テキストの説明を画像トークンの列へ変換するものとして扱います。パズルのピースのように、VQ-VAE のような画像トークナイザで作られたこれらのトークンは、基本的な画像特徴を表します。このモデルはエンコーダ・デコーダアーキテクチャを使います。エンコーダはテキストプロンプトから情報を抽出し、デコーダはその情報に誘導されながら、一度に1つの画像トークンを予測し、最終的な画像をピクセル単位で徐々に構築します。このアプローチは高い制御性と詳細さを可能にしますが、長く複雑なプロンプトの取り扱いに課題があり、拡散モデルのような代替手法より遅くなることが有ります。生成プロセスは上の図 (a) に示されています。

  • Stable Diffusion モデル： Stable Diffusion モデルは「潜在拡散（Latent Diffusion）」の手法を使います。テキストプロンプトと、パラメータを固定した CLIP テキストエンコーダの情報を手がかりに、ノイズを段階的に取り除きながら画像を生成します。UNet バックボーンと CLIP エンコーダを備えた軽量なアーキテクチャにより GPU を使った画像生成が可能で、潜在空間に焦点を当てることでメモリ消費を減らします。この独自の構成は多様な芸術的表現を可能にし、テキスト入力を写実的で想像力豊かなビジュアルへ変換します。生成プロセスは上の図 (b) に示されています。

次に、Hugging Face でテキスト・画像生成モデルをどう使うかを見てみましょう。

diffusers ライブラリをインストールします：

pip install diffusers --upgrade

更に、transformers、safetensors、accelerate と、invisible watermark もインストールしてください：

pip install invisible_watermark transformers accelerate safetensors

ベースモデルを使うだけなら、次のように実行出来ます：

from diffusers import DiffusionPipeline
import torch

pipe = DiffusionPipeline.from_pretrained(
    "stabilityai/stable-diffusion-xl-base-1.0",
    torch_dtype=torch.float16,
    use_safetensors=True,
    variant="fp16",
)
pipe.to("cuda")

prompt = "An astronaut riding a unicorn"

images = pipe(prompt=prompt).images[0]

（プロンプトの訳：「ユニコーンに乗る宇宙飛行士」）

テキスト・画像生成モデルについてもっと知りたい方は、Hugging Face の Diffusers コース を参照してください。

視覚言語の事前学習済みモデルを見てみよう

Transformer ベースの視覚言語モデルの一般的なフレームワーク。[1]

画像・テキストのペアが与えられると、視覚言語モデルはまず、テキストエンコーダと視覚エンコーダでそれぞれテキスト特徴と視覚特徴を抽出します。テキスト特徴と視覚特徴は次にマルチモーダル融合モジュールに送られ、クロスモーダルな表現を生成します。その後、任意でデコーダに送られて最終的な出力を生成します。

この一般的なフレームワークの図は上の図に示されています。多くの場合、画像／テキストのバックボーン、マルチモーダル融合モジュール、デコーダの間に明確な境界はありません。
