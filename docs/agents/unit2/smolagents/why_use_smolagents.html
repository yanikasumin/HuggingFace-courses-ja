smolagents を使う理由

このモジュールでは、smolagents を使う利点と欠点を確認し、自分のニーズに合ったフレームワークかどうかを、必要な情報を踏まえて判断出来るようにします。

smolagents とは？

smolagents は、シンプルでありながら強力な AI エージェント構築フレームワークです。LLM に agency（主体性）を持たせ、検索や画像生成などを通じて実世界とやり取り出来るようにします。

Unit 1 で学んだように、AI エージェントは、「観測」に基づいて「思考」を生成し、「アクション」を実行する為に LLM を使うプログラムです。smolagents でこれがどう実装されているかを見ていきましょう。

smolagents の主な利点

  • シンプルさ： コードの複雑さと抽象化を最小限に抑え、フレームワークを理解しやすく、導入や拡張がし易い
  • 柔軟な LLM サポート： Hugging Face のツールや外部 API との統合を通じて、あらゆる LLM で動作する
  • コードファーストのアプローチ： アクションをコードで直接書く Code Agent を主要な機能としてサポートし、パースの必要をなくしてツール呼び出しを簡素化する
  • HF Hub との統合： Hugging Face Hub とシームレスに統合され、Gradio Spaces をツールとして使える

smolagents を使うべき時

これらの利点を踏まえて、他のフレームワークではなく smolagents を使うべきなのはどんな時でしょうか。

smolagents が理想的なのは、次のような場合です。

  • 軽量で最小限のソリューションが必要な時。
  • 複雑な設定なしに素早く実験したい時。
  • アプリケーションのロジックがシンプルな時。

コードと JSON のアクション

他のフレームワークではエージェントがアクションを JSON で書きますが、smolagents はコードによるツール呼び出しに焦点を当てており、実行プロセスを簡素化しています。ツールを呼び出すコードを構築する為に JSON をパースする必要がなく、出力をそのまま実行出来るからです。

smolagents のエージェントタイプ

smolagents のエージェントはマルチステップエージェントとして動作します。

各 MultiStepAgent は次を行います。

  • 1回の思考
  • 1回のツール呼び出しと実行

smolagents は、主要なエージェントタイプである CodeAgent に加えて、ツール呼び出しを JSON で書く ToolCallingAgent もサポートしています。

各エージェントタイプについては、続くセクションで詳しく見ていきます。

💡 ヒント

smolagents では、ツールは Python 関数をラップする @tool デコレータ、又は Tool クラスを使って定義します。

smolagents におけるモデルの統合

smolagents は柔軟な LLM 統合をサポートしており、一定の条件を満たす任意の呼び出し可能なモデルを使えます。フレームワークには、モデル接続を簡素化する為の事前定義クラスがいくつか用意されています。

  • TransformersModel: シームレスな統合の為に、ローカルの transformers パイプラインを実装します。
  • InferenceClientModel: Hugging Face のインフラを通じたサーバーレス推論の呼び出し、又は増え続けるサードパーティの推論プロバイダー経由の呼び出しをサポートします。
  • LiteLLMModel: 軽量なモデルインタラクションの為に LiteLLM を活用します。
  • OpenAIServerModel: OpenAI API インターフェースを提供する任意のサービスに接続します。
  • AzureOpenAIServerModel: 任意の Azure OpenAI デプロイメントとの統合をサポートします。

この柔軟性により、開発者は自分の具体的なユースケースに最も適したモデルとサービスを選ぶことが出来、実験も容易になります。
