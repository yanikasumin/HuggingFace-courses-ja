これまでは主に、事前学習済みモデルを使ってきました。事前学習の重みを再利用し、新しい用途向けにファインチューニングする方法です。Chapter 1 で見た通り、この方法を一般に 転移学習 と呼びます。転移学習は、ラベル付きデータが少ない実際の用途の殆どで、Transformer モデルを活用する有効な方法です。

この章では、別の方法を取ります。新しいモデルを完全にゼロから学習する方法です。データが大量に有り、そのデータが利用可能なモデルの事前学習データと大きく異なる場合に適しています。但し、言語モデルの事前学習には多くの計算リソースが必要です。既存モデルのファインチューニングと比べると、かなり多くなります。

新しいモデルを学習する意味が有る例には、楽譜のデータ、DNA のような分子配列、プログラミング言語のデータセットが有ります。プログラミング言語は近年、注目を集めています。OpenAI の Codex モデルを基盤とする TabNine や GitHub の Copilot のように、長いコード列を生成出来るツールが登場した為です。テキスト生成のタスクに最も適しているのは、GPT-2 のような自己回帰型の言語モデル、つまり因果言語モデルです。

このセクションでは、コード生成モデルの縮小版を作ります。対象は、完全な関数やクラスではありません。Python コードの一部を使い、1行の補完に焦点を当てます。Python でデータを扱う作業では、Python のデータサイエンススタックを頻繁に使います。このスタックは、matplotlib、seaborn、pandas、scikit-learn といったライブラリで構成されます。これらのフレームワークでは、特定のコマンドを調べる場合がよく有ります。モデルにこれらの呼び出しを補完させると便利です。

Chapter 6 では、Python のソースコードを処理する為の効率的なトークナイザを作りました。但し、モデルの事前学習に使う大規模なデータセットは、まだ用意出来ていません。ここでは、GitHub のリポジトリから集めた Python コードのコーパスに、このトークナイザを適用します。その後、Trainer API と 🤗 Accelerate を使ってモデルを学習します。

データを集める

Python のコードは、GitHub のようなコードリポジトリに大量に有ります。全ての Python リポジトリをスクレイピングすれば、データセットを作れます。この方法は、大規模な GPT-2 モデルを事前学習する為に Transformers の教科書 で採用されました。著者らは、約2,000万件の Python ファイルを含む約180 GB の GitHub ダンプ codeparrot からデータセットを構築し、Hugging Face Hub で共有しました。

但し、コーパス全体での学習は、時間と計算リソースを大量に消費します。必要なのは、Python のデータサイエンススタックに関係する部分だけです。そこで、まず codeparrot データセットを、このスタックのライブラリのいずれかを含むファイルだけに絞ります。

データセットは大きい為、ダウンロードは避けます。代わりに、ストリーミング機能を使って、その場で絞り込みます。先程挙げたライブラリを使っているコードサンプルを絞り込む関数が、次の関数です。

def any_keyword_in_string(string, keywords):
    for keyword in keywords:
        if keyword in string:
            return True
    return False

次の2つの例で試します。

example_1 = "import numpy as np"
example_2 = "import pandas as pd"

    any_keyword_in_string(example_1, filters), any_keyword_in_string(example_2, filters)
)

これを使って、データセットをストリーミングしながら目的の要素を絞り込む関数を作れます。

```py
from collections import defaultdict
from tqdm import tqdm
from datasets import Dataset


def filter_streaming_dataset(dataset, filters):
    filtered_dict = defaultdict(list)
    total = 0
    for sample in tqdm(iter(dataset)):
        total += 1
        if any_keyword_in_string(sample["content"], filters):
            for k, v in sample.items():
                filtered_dict[k].append(v)
    print(f"フィルタリング後のデータの割合: {len(filtered_dict['content'])/total:.2%}")
    return Dataset.from_dict(filtered_dict)

あとは、この関数をストリーミングデータセットに適用するだけです。

## データセットを準備する








最初の手順は、データのトークン化です。トークン化すると、データを学習に使えます。主な目的は、短い関数呼び出しの自動補完です。その為、コンテキストサイズは比較的小さく出来ます。コンテキストサイズを小さくすると、モデルを速く学習でき、必要なメモリも大幅に減ります。アプリケーションでより多くのコンテキストが必要な場合は、この数値を大きくしてください。例えば、関数定義のあるファイルをもとに、モデルにユニットテストを書かせる場合です。但し、その分 GPU メモリの使用量も増えます。

ここでは、コンテキストサイズを128トークンに固定します。GPT-2 の 1,024 や GPT-3 の 2,048 より小さい値です。

殆どのドキュメントは、128トークンよりはるかに長いものです。入力を最大長で単純に切り捨てると、データセットの大部分が失われます。そこで、`return_overflowing_tokens` オプションを使います。このオプションで入力全体をトークン化し、[Chapter 6](/course/chapter6/4) で行ったように複数のチャンクに分割します。`return_length` オプションも使います。各チャンクの長さを自動で取得する為です。最後のチャンクは、コンテキストサイズより小さくなる場合が多くなります。これらの断片は除去します。パディングの問題を避ける為です。データは十分に有る為、除去しても問題有りません。

この操作では、Datasets の `Dataset.map()` 関数の特徴を使います。入力と出力が1対1に対応しなくてもよい点です。[section 3](/course/chapter7/3) で見た通り、入力バッチより多い要素を持つバッチも、少ない要素を持つバッチも作成出来ます。この特徴は、データ拡張やデータの絞り込みなど、要素数を変える操作で便利です。今回の処理では、各要素を指定したコンテキストサイズのチャンクにトークン化し、各ドキュメントから多くのサンプルを作成します。既存の列はサイズが競合する為、削除する必要があります。保持する場合は、列を適切に複製し、`Dataset.map()` の呼び出しの中で返します。

```py
def tokenize(element):
    outputs = tokenizer(
        element["content"],
        truncation=True,
        max_length=context_length,
        return_overflowing_tokens=True,
        return_length=True,
    )
    input_batch = []
    for length, input_ids in zip(outputs["length"], outputs["input_ids"]):
        if length == context_length:
            input_batch.append(input_ids)
    return {"input_ids": input_batch}


tokenized_datasets = raw_datasets.map(
    tokenize, batched=True, remove_columns=raw_datasets["train"].column_names
)
tokenized_datasets

## 🤗 Accelerate で学習する

`Trainer` を使ったモデルの学習方法は、これまで説明しました。ある程度のカスタマイズは可能です。但し、学習ループを完全に制御したい場合や、標準的な学習処理にはない特殊な処理を組み込みたい場合も有ります。そのような場合には Accelerate が適しています。このセクションでは、Accelerate を使ってモデルを学習する手順を説明します。学習ループには、一工夫も加えます。








関心が有るのは、主にデータサイエンスライブラリに対する的確な自動補完です。その為、これらのライブラリを多く使う学習サンプルには、より大きな重みを与えます。こうしたサンプルは、`plt`、`pd`、`sk`、`fit`、`predict` といったキーワードで識別出来ます。これらは、`matplotlib.pyplot`、`pandas`、`sklearn` の最も頻繁なインポート名です。sklearn の fit/predict パターンでも有ります。これらがそれぞれ単一のトークンとして表現される場合は、入力シーケンスに含まれているかを簡単に確認出来ます。トークンには空白の接頭辞が付く場合も有ります。その為、トークナイザの語彙では、空白付きの形も確認します。動作を検証する為に、複数のトークンに分割されるはずのテスト用トークンを1つ追加します。

この確認は正しく動作しています。次に、入力シーケンス、ロジット、先程選んだキートークンを入力として受け取るカスタム損失関数を書きます。

まず、ロジットと入力を揃えます。次のトークンが現在のトークンのラベルになる為、ラベルは入力シーケンスを右に1つずらしたものです。モデルは最初のトークンについては予測を行いません。その為、ラベルは入力シーケンスの2番目のトークンから始めます。次に、最後のロジットを切り取ります。入力シーケンス全体の後に続くトークンのラベルは存在しない為です。これで、サンプルごとの損失を計算し、各サンプル内の全てのキーワードの出現回数を数えられます。最後に、出現回数を重みとして、全てのサンプルの重み付き平均を計算します。キーワードを含まないサンプルを全て捨てないよう、重みには1を加えます。

```py
from torch.nn import CrossEntropyLoss
import torch


def keytoken_weighted_loss(inputs, logits, keytoken_ids, alpha=1.0):
    # トークン < n が n を予測するようにシフトする
    shift_labels = inputs[..., 1:].contiguous()
    shift_logits = logits[..., :-1, :].contiguous()
    # トークンごとの損失を計算する
    loss_fct = CrossEntropyLoss(reduce=False)
    loss = loss_fct(shift_logits.view(-1, shift_logits.size(-1)), shift_labels.view(-1))
    # 形状を変えて、サンプルごとに損失を平均する
    loss_per_sample = loss.view(shift_logits.size(0), shift_logits.size(1)).mean(axis=1)
    # 重み付けを計算してスケールする
    weights = torch.stack([(inputs == kt).float() for kt in keytoken_ids]).sum(
        axis=[0, 2]
    )
    weights = alpha * (1.0 + weights)
    # 重み付き平均を計算する
    weighted_loss = (loss_per_sample * weights).mean()
    return weighted_loss

この新しい損失関数で学習を始める前に、幾つか準備が必要です。

  • データをバッチ単位で読み込むデータローダが必要です。
  • 重み減衰のパラメータを設定する必要があります。
  • 定期的に評価したいので、評価コードを関数にまとめておくのがよいでしょう。

データローダから始めます。データセットの形式を "torch" に設定し、適切なバッチサイズで PyTorch の DataLoader に渡します。

次に、パラメータをグループ化します。グループ化により、オプティマイザは、どのパラメータに追加の重み減衰を適用するかを判断出来ます。通常、全てのバイアスと LayerNorm の重みは、重み減衰の対象から外れます。方法は次の通りです。

weight_decay = 0.1


def get_grouped_params(model, no_decay=["bias", "LayerNorm.weight"]):
    params_with_wd, params_without_wd = [], []
    for n, p in model.named_parameters():
        if any(nd in n for nd in no_decay):
            params_without_wd.append(p)
        else:
            params_with_wd.append(p)
    return [
        {"params": params_with_wd, "weight_decay": weight_decay},
        {"params": params_without_wd, "weight_decay": 0.0},
    ]

学習中は、検証セットでモデルを定期的に評価します。その為の関数も書きます。この関数は、評価用データローダを一巡し、全てのプロセスにわたって損失を集めます。

def evaluate():
    model.eval()
    losses = []
    for step, batch in enumerate(eval_dataloader):
        with torch.no_grad():
            outputs = model(batch["input_ids"], labels=batch["input_ids"])

        losses.append(accelerator.gather(outputs.loss))
    loss = torch.mean(torch.cat(losses))
    try:
        perplexity = torch.exp(loss)
    except OverflowError:
        perplexity = float("inf")
    return loss.item(), perplexity.item()

損失とパープレキシティの値は非常に高いものです。但し、まだモデルを学習していない為、これは想定通りです。これで、学習スクリプトの中核である学習ループを書く準備が整いました。学習ループでは、データローダを反復し、バッチをモデルに渡します。得られたロジットで、カスタム損失関数を評価出来ます。損失は、勾配累積のステップ数で割ってスケールします。ステップを集約した時に、損失が大きくならないようにする為です。最適化の前には、収束を良くする為に勾配もクリッピングします。最後に、数ステップごとに新しい `evaluate()` 関数で、評価セットに対するモデルの評価を行います。

```py
from tqdm.notebook import tqdm

gradient_accumulation_steps = 8
eval_steps = 5_000

model.train()
completed_steps = 0
for epoch in range(num_train_epochs):
    for step, batch in tqdm(
        enumerate(train_dataloader, start=1), total=num_training_steps
    ):
        logits = model(batch["input_ids"]).logits
        loss = keytoken_weighted_loss(batch["input_ids"], logits, keytoken_ids)
        if step % 100 == 0:
            accelerator.print(
                {
                    "samples": step * samples_per_step,
                    "steps": completed_steps,
                    "loss/train": loss.item() * gradient_accumulation_steps,
                }
            )
        loss = loss / gradient_accumulation_steps
        accelerator.backward(loss)
        if step % gradient_accumulation_steps == 0:
            accelerator.clip_grad_norm_(model.parameters(), 1.0)
            optimizer.step()
            lr_scheduler.step()
            optimizer.zero_grad()
            completed_steps += 1
        if (step % (eval_steps * gradient_accumulation_steps)) == 0:
            eval_loss, perplexity = evaluate()
            accelerator.print({"loss/eval": eval_loss, "perplexity": perplexity})
            model.train()
            accelerator.wait_for_everyone()
            unwrapped_model = accelerator.unwrap_model(model)
            unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
            if accelerator.is_main_process:
                tokenizer.save_pretrained(output_dir)
                repo.push_to_hub(
                    commit_message=f"Training in progress step {step}", blocking=False
                )
