ログインすると、ユーザー名とパスワードの入力を求められます。認証が済むと、トークンが *~/.cache/huggingface/* の下に保存されます。ログイン後は、次の関数でテンプレートリポジトリをコピー出来ます。

```python
from distutils.dir_util import copy_tree
from huggingface_hub import Repository, snapshot_download, create_repo, get_full_repo_name


def copy_repository_template():
    # リポジトリをクローンし、ローカルパスを取り出す
    template_repo_id = "lewtun/distilbert-base-uncased-finetuned-squad-d5716d28"
    commit_hash = "be3eaffc28669d7932492681cd5f3e8905e358b4"
    template_repo_dir = snapshot_download(template_repo_id, revision=commit_hash)
    # Hub 上に空のリポジトリを作成する
    model_name = template_repo_id.split("/")[1]
    create_repo(model_name, exist_ok=True)
    # 空のリポジトリをクローンする
    new_repo_id = get_full_repo_name(model_name)
    new_repo_dir = model_name
    repo = Repository(local_dir=new_repo_dir, clone_from=new_repo_id)
    # ファイルをコピーする
    copy_tree(template_repo_dir, new_repo_dir)
    # Hub にプッシュする
    repo.push_to_hub()
```

`copy_repository_template()` を呼び出すと、テンプレートリポジトリのコピーが自分のアカウントの下に作成されます。

## 🤗 Transformers の pipeline をデバッグする[[debugging-the-pipeline-from-transformers]]

Transformer モデルのデバッグは、次の場面を例に進めます。同僚と質問応答プロジェクトに取り組んでいるとします。目的は、eコマースサイトの顧客が消費財に関する答えを見つけられるようにすることです。同僚から次のメッセージが届きます。

> やあ！Hugging Face コースの [Chapter 7](/course/chapter7/7) のテクニックを使って実験してみたら、SQuAD でかなり良い結果が出たよ！このモデルをプロジェクトの出発点に出来ると思う。Hub 上のモデル ID は "lewtun/distillbert-base-uncased-finetuned-squad-d5716d28" だよ。気軽に試してみて :)

最初に行うのは、🤗 Transformers の `pipeline` でモデルを読み込むことです。

```python
model_checkpoint = get_full_repo_name("distillbert-base-uncased-finetuned-squad-d5716d28")
```

トレースバックには多くの情報が含まれています。読み方で重要なのは、_下から上へ_読むことです。通常の文章とは逆の順序ですが、トレースバックには `pipeline` がモデルとトークナイザをダウンロードするときの関数呼び出しの順序が示されています。`pipeline` の内部の動作については [Chapter 2](/course/chapter2) を参照してください。

> [!TIP]
> 🚨 Google Colab のトレースバックでは、"6 frames" の周囲に青いボックスが表示されます。これは、トレースバックを「フレーム」単位に圧縮して表示する Colab の機能です。エラーの発生源が見つからない場合は、小さな2つの矢印をクリックし、トレースバック全体を展開してください。

トレースバックの最後の行には、最後のエラーメッセージと、発生した例外の名前が表示されます。今回の例外の種類は `OSError` で、システムに関係するエラーを表します。エラーメッセージを読むと、モデルの *config.json* ファイルに問題があり、修正方法として2つの提案が示されています。

同僚にファイルの追加を依頼する方法があります。もう一つの方法は、事前学習済みモデルの設定を使う方法です。モデル ID から、使用された事前学習済みモデルは [`distilbert-base-uncased`](https://huggingface.co/distilbert-base-uncased) であると分かります。このモデルの設定をダウンロードして自分のリポジトリへプッシュすれば、問題が解決する可能性があります。ここでは後者の方法を試します。モデルの設定は、[Chapter 2](/course/chapter2) で扱った `AutoConfig` クラスでダウンロード出来ます。

```python
from transformers import AutoConfig

config = AutoConfig.from_pretrained(pretrained_checkpoint)
```

> [!WARNING]
> 🚨 この方法には注意点があります。同僚がファインチューニングの前に `distilbert-base-uncased` の設定を変更していた場合、その変更は反映されません。実際の作業では、まず同僚に確認する必要があります。このセクションでは、デフォルトの設定を使ったものとして進めます。

設定は、`push_to_hub()` 関数でモデルリポジトリへプッシュ出来ます。


モデルを読み込めました。ここまでの内容をまとめます。

- Python のエラーメッセージは_トレースバック_と呼ばれます。トレースバックは下から上へ読みます。最後の行には、問題の発生源を特定する為の情報が含まれていることが通常です。
- 最後の行だけでは情報が不足する場合は、トレースバックを上へたどり、ソースコードのどこでエラーが発生したかを確認します。
- エラーメッセージから原因が分からない場合は、似た問題への解決策をオンラインで検索します。
- `huggingface_hub` ライブラリには、Hub 上のリポジトリの操作とデバッグに使えるツールが一式用意されています。

pipeline のデバッグ方法は以上です。次に、モデル自体のフォワードパスで発生するエラーを扱います。こちらは原因の特定がより難しい例です。

## モデルのフォワードパスをデバッグする[[debugging-the-forward-pass-of-your-model]]

`pipeline` は、予測を手早く生成する用途には適しています。一方で、モデルのロジットに直接アクセスしたい場合もあります。例えば、独自の後処理を適用する場合です。この場合に発生するエラーを見る為に、まず `pipeline` からモデルとトークナイザを取り出します。

```python
tokenizer = reader.tokenizer
model = reader.model
```

次に、質問文を用意します。内容は、対応しているフレームワークを尋ねる文です。

```python
question = "Which frameworks can I use?"
```

[Chapter 7](/course/chapter7) で扱った手順は次の通りです。入力をトークン化し、開始トークンと終了トークンのロジットを取り出し、答えの範囲をデコードします。

```python
import torch

inputs = tokenizer(question, context, add_special_tokens=True)
input_ids = inputs["input_ids"][0]
outputs = model(**inputs)
answer_start_scores = outputs.start_logits
answer_end_scores = outputs.end_logits
# スコアが最大になる位置を、回答の開始位置として選ぶ
answer_start = torch.argmax(answer_start_scores)
# スコアが最大になる位置を基に、回答の終了位置を求める
answer_end = torch.argmax(answer_end_scores) + 1
answer = tokenizer.convert_tokens_to_string(
    tokenizer.convert_ids_to_tokens(input_ids[answer_start:answer_end])
)
print(f"質問: {question}")
print(f"回答: {answer}")
```

エラーメッセージには、`'list' object has no attribute 'size'` と表示されています。トレースバックには、`model(**inputs)` の行を指す `-->` 矢印もあります。Python デバッガで対話的にデバッグする方法もありますが、ここでは `inputs` の一部を出力して中身を確認します。

```python

```

```python out

```

出力は通常の Python の `list` に見えます。型を確認します。

```python

```


型は Python の `list` でした。原因を確認します。[Chapter 2](/course/chapter2) で扱ったように、🤗 Transformers の `AutoModelForXxx` クラスは_テンソル_を対象に動作します。テンソルは PyTorch と TensorFlow のデータ形式です。テンソルの次元を取り出す操作には、例えば PyTorch の `Tensor.size()` があります。トレースバックに戻り、例外が発生した行を確認します。
