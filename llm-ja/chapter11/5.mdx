# 評価

SFT 又は LoRA を使った SFT でファインチューニングしたモデルは、標準的なベンチマークで評価すべきです。機械学習エンジニアは、対象とする分野に合った評価を一通り揃え、維持しておく必要があります。このページでは、代表的なベンチマークと、それらを使ってモデルを評価する方法を見ていきます。特定のユースケースに合わせたカスタムベンチマークの作り方も扱います。

## 自動ベンチマーク

自動ベンチマークは、言語モデルの能力を様々なタスクにわたって標準化された方法で測る仕組みです。モデルの性能を知る出発点としては有用ですが、評価はこれだけで完結しません。包括的な評価戦略の一部として位置付けることが大切です。

## 自動ベンチマークの理解

自動ベンチマークは通常、タスクと評価メトリクスが予め定義された、厳選されたデータセットで構成されます。測る対象は、基本的な言語理解から複雑な推論まで、モデル能力の様々な側面にわたります。

自動ベンチマークの主な利点は標準化です。異なるモデル同士を一貫した条件で比較出来、再現可能な結果が得られます。

但し、ベンチマークでよい成績を出したからといって、実際の用途でも同じように有効だとは限りません。学術的なベンチマークで優れたモデルでも、特定のドメインの用途や実際のユースケースでは苦戦することがあります。

## 汎用知識のベンチマーク

[MMLU](https://huggingface.co/datasets/cais/mmlu)（Massive Multitask Language Understanding）は、科学から人文科学まで57の科目にわたる知識をテストします。範囲は包括的ですが、特定のドメインで必要となる専門性の深さを反映しているとは限りません。

TruthfulQA は、モデルが一般的な誤解を再生産する傾向を評価します。但し、誤情報の形は様々であり、その全てを捉えられる訳ではありません。

## 推論のベンチマーク

[BBH](https://huggingface.co/datasets/lukaemon/bbh)（Big Bench Hard）と [GSM8K](https://huggingface.co/datasets/openai/gsm8k) は、複雑な推論タスクに焦点を当てています。BBH は論理的思考と計画をテストし、GSM8K は特に数学の問題解決を対象とします。分析能力の評価には役立ちますが、実際の場面で必要となる繊細な推論までは捉え切れないことがあります。

## 言語理解

[HELM](https://github.com/stanford-crfm/helm) は、言語モデルを総合的に評価するフレームワークです。HELM のようなベンチマークを使うと、常識、世界知識、推論といった側面から言語処理能力を把握出来ます。但し、自然な会話の複雑さやドメイン固有の専門用語を完全には表せないことがあります。

## ドメイン固有のベンチマーク

数学、コーディング、チャットといった特定のドメインに焦点を当てたベンチマークをいくつか見てみましょう。

[MATH ベンチマーク](https://huggingface.co/papers/2103.03874) は、数学的推論のもう1つの重要な評価ツールです。代数、幾何、数論、数え上げ、確率などを含む数学コンペティションからの 12,500 問で構成されます。MATH が特に難しいのは、多段階の推論、形式的な数学表記の理解、解法を段階的に生成する能力が必要な点です。単純な算術タスクとは異なり、MATH の問題は高度な問題解決戦略と数学概念の応用を求めることが多くあります。

[HumanEval ベンチマーク](https://github.com/openai/human-eval) は、コーディングに焦点を当てた評価データセットで、164 のプログラミング問題で構成されます。モデルが、与えられたプログラミング課題を解く Python コードを生成し、そのコードが正しく動作するかを評価します。HumanEval の特徴は、参照解との表面的な類似度ではなく、テストケースを実際に実行して機能的に正しいかを確認する点です。問題は、基本的な文字列操作から、より複雑なアルゴリズムやデータ構造まで多岐にわたります。

[Alpaca Eval](https://tatsu-lab.github.io/alpaca_eval/) は、指示に従う言語モデルの品質を評価する為に設計された自動評価フレームワークです。判定者として GPT-4 を使い、有用性、正直さ、無害性といった様々な観点でモデルの出力を評価します。このフレームワークは 805 件の厳選されたプロンプトのデータセットを含み、Claude、GPT-4 など複数の参照モデルに対して応答を評価出来ます。Alpaca Eval が特に便利なのは、人間のアノテータを必要とせずに一貫性のある大規模な評価を提供しながら、従来の評価指標では捉え難いモデル性能の細かな違いも評価出来る点です。

## 代替の評価手法

標準ベンチマークには限界がある為、多くの組織が代替の評価方法を開発してきました。

### LLM-as-Judge

或る言語モデルを使って別のモデルの出力を評価する方法が、ますます普及しています。従来の指標よりも細かな点まで踏み込んだフィードバックが得られる一方で、評価する側のモデル自体にも偏りや限界があります。

### 評価アリーナ

[Chatbot Arena](https://lmarena.ai/) のような評価アリーナは、クラウドソーシングで集めたフィードバックによって LLM を評価する仕組みです。ユーザーは、名前を伏せた2つの LLM に質問し、どちらの応答がよいかに投票します。多様で難しい質問が集まる為、実際の利用傾向やユーザーの好みを反映した評価が得られます。クラウドソーシングによる投票と専門家による評価がよく一致することも、研究で示されています。

但し、限界もあります。利用者層の偏り、プロンプト分布の偏り、安全性よりも有用性に評価が寄り易いことなどです。

### カスタムベンチマークスイート

組織では、固有のニーズとユースケースに合わせたベンチマークスイートを自前で開発することがよくあります。ドメイン固有の知識テストや、実際のデプロイ条件を反映した評価シナリオが含まれることもあります。

## カスタム評価

標準ベンチマークは有用なベースラインを提供しますが、それだけを評価方法にすべきではありません。より包括的なアプローチの作り方は次の通りです。

1. 関連する標準ベンチマークから始めてベースラインを確立し、他のモデルと比較出来るようにする

2. そのユースケース特有の要件と課題を特定する。モデルは実際にどんなタスクを行うのか。どんな種類のエラーが最も問題になるのか

3. 実際のユースケースを反映したカスタム評価データセットを開発する。例えば次のようなものを含められます：
   - ドメインにおける実際のユーザーのクエリ
   - 遭遇したことのある一般的なエッジケース
   - 特に難しいシナリオの例

4. 多層的な評価戦略の実装を検討する：
   - 素早いフィードバックの為の自動メトリクス
   - 微妙な違いを捉える為の人間による評価
   - 専門的な用途の為のドメイン専門家によるレビュー
   - 管理された環境での A/B テスト

## カスタム評価の実装

このセクションでは、ファインチューニングしたモデルの評価を実装します。標準ベンチマークでの評価には [`lighteval`](https://github.com/huggingface/lighteval) を使います。このライブラリには幅広いタスクが組み込まれています。評価したいタスクと評価のパラメータを定義するだけです。  

LightEval のタスクは、特定の形式で定義されます。

```
{suite}|{task}|{num_few_shot}|{auto_reduce}
```

| パラメータ | 説明 |
|-----------|-------------|
| `suite` | ベンチマークスイート（例: 'mmlu'、'truthfulqa'） |
| `task` | スイート内の特定のタスク（例: 'abstract_algebra'） |
| `num_few_shot` | プロンプトに含める例の数（ゼロショットの場合は 0） |
| `auto_reduce` | プロンプトが長過ぎる場合に Few-shot の例を自動で減らすかどうか（0 又は 1） |

例：`"mmlu|abstract_algebra|0|0"` は、MMLU の abstract algebra タスクをゼロショット推論で評価します。

## 評価パイプラインの例

ファインチューニングしたモデルの評価パイプラインを構築してみましょう。医療ドメインに関連するサブタスクのセットでモデルを評価します。 

Lighteval と VLLM バックエンドを使って、特定の1つのドメインに関連する自動ベンチマークで評価する完全な例がこちらです。

```bash
lighteval accelerate \
    "pretrained=your-model-name" \
    "mmlu|anatomy|0|0" \
    "mmlu|high_school_biology|0|0" \
    "mmlu|high_school_chemistry|0|0" \
    "mmlu|professional_medicine|0|0" \
    --max_samples 40 \
    --batch_size 1 \
    --output_path "./results" \
    --save_generations true
```

結果は表形式で表示されます。

```
|                  Task                  |Version|Metric|Value |   |Stderr|
|----------------------------------------|------:|------|-----:|---|-----:|
|all                                     |       |acc   |0.3333|±  |0.1169|
|leaderboard:mmlu:_average:5             |       |acc   |0.3400|±  |0.1121|
|leaderboard:mmlu:anatomy:5              |      0|acc   |0.4500|±  |0.1141|
|leaderboard:mmlu:high_school_biology:5  |      0|acc   |0.1500|±  |0.0819|
```

Lighteval には、より詳細な評価タスクの為の Python API も含まれており、結果をより柔軟に扱うのに便利です。詳細は [Lighteval のドキュメント](https://huggingface.co/docs/lighteval/using-the-python-api)を確認してください。

> [!TIP]
> ✏️ **試してみましょう！** lighteval で、ファインチューニングしたモデルを特定のタスクで評価してみましょう。
