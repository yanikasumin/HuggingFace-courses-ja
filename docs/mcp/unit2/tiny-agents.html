Hugging Face Hub と MCP で Tiny Agents を構築する

Gradio で MCP サーバーを構築し、MCP クライアントの作成方法を学んだので、感情分析ツールとシームレスにやり取りできるエージェントを構築して、エンドツーエンドアプリケーションを完成させましょう。このセクションは、前のセクションで構築した Gradio 感情分析サーバーのようなサービスに接続できる MCP クライアントをデプロイする非常にシンプルな方法を示すプロジェクト Tiny Agents を基にしています。

Unit 2 のこの最終演習では、Gradio ベースの感情分析サーバーを含む、あらゆる MCP サーバーと通信できる TypeScript (JS) と Python の MCP クライアントの実装方法を順を追って説明します。これにより、エンドツーエンドの MCP アプリケーションフローが完成します。感情分析ツールを公開する Gradio MCP サーバーの構築から、そのツールを他の機能と併せて使える柔軟なエージェントの作成までです。

インストール

Tiny Agents を構築するために必要なパッケージをインストールしましょう。

💡 ヒント

Claude Desktop をはじめとする一部の MCP クライアントは、まだ SSE ベースの MCP サーバーをサポートしていません。その場合は、mcp-remote のようなツールを使えます。まず Node.js をインストールしてください。次に、自分の MCP クライアント設定に次を追加します。

Tiny Agent はコマンドライン環境で MCP サーバーを実行できます。そのためには、npm をインストールし、npx でサーバーを実行する必要があります。これらは Python と JavaScript の両方で必要です。

npm で npx をインストールしましょう。npm がインストールされていない場合は、npm のドキュメント を確認してください。

# npx をインストール
npm install -g npx

次に、mcp-remote パッケージをインストールする必要があります。

npm i mcp-remote

typescript

JavaScript では、`tiny-agents` パッケージをインストールする必要があります。 
npm install @huggingface/tiny-agents

python

Python では、必要なコンポーネントをすべて取得するために、`mcp` extra 付きの最新版 `huggingface_hub` をインストールする必要があります。 
pip install "huggingface_hub[mcp]>=0.32.0"

コマンドラインでの Tiny Agents MCP クライアント

Unit 1 の例を繰り返して、基本的な Tiny Agent を作成しましょう。Tiny Agents は、JSON 設定ファイルに基づいてコマンドラインから MCP クライアントを作成できます。

typescript

基本的な Tiny Agent を使ったプロジェクトをセットアップしましょう。 
mkdir my-agent
touch my-agent/agent.json
cd my-agent
JSON ファイルは次のようになります。 
{
    "model": "Qwen/Qwen2.5-72B-Instruct",
    "provider": "novita",
    "servers": [
        {
            "type": "stdio",
            "command": "npx",
            "args": [
                "mcp-remote",
                "http://localhost:7860/gradio_api/mcp/sse"
            ]
        }
    ]
}
次のコマンドでエージェントを実行できます。 
npx @huggingface/tiny-agents run agent.json

python

基本的な Tiny Agent を使ったプロジェクトをセットアップしましょう。 
mkdir my-agent
touch my-agent/agent.json
cd my-agent
JSON ファイルは次のようになります。 
{
    "model": "Qwen/Qwen2.5-72B-Instruct",
    "provider": "novita",
    "servers": [
        {
            "type": "stdio",
            "command": "npx",
            "args": [
                "mcp-remote", 
                "http://localhost:7860/gradio_api/mcp/sse"
            ]
        }
    ]
}
次のコマンドでエージェントを実行できます。 
tiny-agents run agent.json

ここでは、Gradio MCP サーバーに接続できる基本的な Tiny Agent が用意されています。モデル、プロバイダー、サーバー設定が含まれています。

フィールド 説明
model エージェントに使うオープンソースモデル
provider エージェントに使う推論プロバイダー
servers エージェントに使うサーバー。Gradio MCP サーバーには mcp-remote サーバーを使います

💡 ヒント

Tiny Agents では、ローカルで動作するオープンソースモデルも使えます。ローカル推論サーバーを起動すると、次のようになります。

{
    "model": "Qwen/Qwen3-32B",
    "endpointUrl": "http://localhost:1234/v1",
    "servers": [
        {
            "type": "stdio",
            "command": "npx",
            "args": [
                "mcp-remote",
                "http://localhost:1234/v1/mcp/sse"
            ]
        }
    ]
}

ここでは、ローカルモデルに接続できる Tiny Agent が用意されています。モデルとサーバー設定、そしてエンドポイント URL http://localhost:1234/v1 が含まれています。エンドポイントは OpenAI 互換のエンドポイントである必要があります。

カスタム Tiny Agents MCP クライアント

Tiny Agents と Gradio MCP サーバーの両方を理解したところで、それらがどのように連携するかを見てみましょう！ MCP の美点は、エージェントが MCP 互換のあらゆるサーバー（このユニットの前半で構築した Gradio ベースの感情分析サーバーを含む）とやり取りするための標準化された方法を提供することです。

Tiny Agents で Gradio サーバーを使う

Tiny Agent を、このユニットの前半で構築した Gradio 感情分析サーバーに接続するには、サーバーのリストに追加するだけです。エージェント設定の変更方法は次のとおりです。

typescript

const agent = new Agent({
    provider: process.env.PROVIDER ?? "novita",
    model: process.env.MODEL_ID ?? "Qwen/Qwen2.5-72B-Instruct",
    apiKey: process.env.HF_TOKEN,
    servers: [
        // ... 既存のサーバー ...
        {
            command: "npx",
            args: [
                "mcp-remote",
                "http://localhost:7860/gradio_api/mcp/sse"  // 自分の Gradio MCP サーバー
            ]
        }
    ],
});

python

import os

from huggingface_hub import Agent

agent = Agent(
    model="Qwen/Qwen2.5-72B-Instruct",
    provider="novita",
    servers=[
        {
            "command": "npx",
            "args": [
                "mcp-remote",
                "http://localhost:7860/gradio_api/mcp/sse"  # 自分の Gradio MCP サーバー
            ]
        }
    ],
)

これで、エージェントは感情分析ツールを他のツールと併せて使えるようになりました！ たとえば、次のようなことができます。 1. ファイルシステムサーバーを使ってファイルからテキストを読み取る 2. Gradio サーバーを使ってその感情を分析する 3. 結果をファイルに書き戻す

デプロイ時の考慮事項

Gradio MCP サーバーを Hugging Face Spaces にデプロイする際は、エージェント設定内のサーバー URL を、デプロイした Space を指すように更新する必要があります。

{
    command: "npx",
    args: [
        "mcp-remote",
        "https://YOUR_USERNAME-mcp-sentiment.hf.space/gradio_api/mcp/sse"
    ]
}

これにより、エージェントはローカルだけでなく、どこからでも感情分析ツールを使えるようになります！

まとめ: 完成したエンドツーエンド MCP アプリケーション

このユニットでは、MCP の基礎の理解から、完全なエンドツーエンドアプリケーションの構築まで進みました。

  1. 感情分析ツールを公開する Gradio MCP サーバーを作成した
  2. MCP クライアントを使ってこのサーバーに接続する方法を学んだ
  3. そのツールとやり取りできる TypeScript と Python の小さなエージェントを構築した

これは Model Context Protocol の力を示しています。使い慣れたフレームワーク（Gradio など）を使って専用ツールを作成し、標準化されたインターフェース（MCP）を通じて公開することで、エージェントにそれらのツールを他の機能と併せてシームレスに使わせることができます。

構築した完全なフローにより、エージェントは次のことが可能になります。 - 複数のツールプロバイダーに接続する - 利用可能なツールを動的に発見する - カスタムの感情分析ツールを使う - ファイルシステムアクセスや Web ブラウジングなどの他の機能と組み合わせる

このモジュール式のアプローチこそが、柔軟な AI アプリケーションの構築において MCP を非常に強力なものにしている理由です。
