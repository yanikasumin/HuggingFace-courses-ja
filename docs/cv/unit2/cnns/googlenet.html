GoogLeNet

この章では、GoogLeNet と呼ばれる畳み込みアーキテクチャを見ていきます。

概要

Inception アーキテクチャは、分類や検出などのコンピュータビジョンのタスクのために設計された畳み込みニューラルネットワーク（CNN）であり、その効率性で際立っています。パラメータ数は700万未満で、前任者たちよりも大幅にコンパクトで、AlexNet より9倍小さく、VGG16 より22倍小さいです。このアーキテクチャは ImageNet 2014 チャレンジで注目を集め、Google による適応版である GoogLeNet（LeNet へのオマージュとして名付けられました）が、従来の主要手法よりも少ないパラメータを使いながら性能の新たな基準を打ち立てました。

アーキテクチャの革新

Inception アーキテクチャの登場以前は、AlexNet や VGG などのモデルが、より深いネットワーク構造の利点を示していました。しかし、深いネットワークは通常、計算ステップが増え、過学習や勾配消失問題などの課題につながります。Inception アーキテクチャはその解決策を提供し、浮動小数点パラメータの数を減らしながら複雑な CNN の訓練を可能にします。

Inception の「Network In Network」モジュール

AlexNet や VGG のような従来のネットワークでは、基本ブロックは畳み込み層そのものでした。しかし、Lin ら（2013年）は Network In Network の概念を導入し、単一の畳み込みが必ずしも正しい基本構成ブロックとは限らないと主張しました。もっと複雑であるべきだというのです。そこで Inception モデルの著者たちは、それに着想を得て、有名な映画「インセプション」（夢の中の夢）にちなんで名付けられた Inception モジュールという、より複雑な構成ブロックを採用することにしました。

Inception モジュールは、複数のスケールで特徴を抽出するために、異なるカーネルサイズの畳み込みフィルタを適用することにこだわります。任意の入力特徴マップに対して、\(1 \times 1\) 畳み込み、3x3 畳み込み、5x5 畳み込みを並列に適用します。畳み込みに加えて、最大プーリング演算も適用されます。4つの演算すべてに、空間次元が同じになるようなパディングとストライドが設定されます。これらの特徴が連結され、次のステージへの入力となります。図1をご覧ください。

図1： 素朴な Inception モジュール

図のように、5x5 のような大きなカーネルサイズで複数のスケールの畳み込みを適用すると、パラメータ数が大幅に増える可能性があります。この問題は、入力特徴のサイズ（チャンネル数）が大きくなるほど顕著になります。そのため、こうした「Inception モジュール」をネットワークの深くに積み重ねていくと、計算量が大幅に増大します。単純な解決策は、計算の要求が増えそうな箇所では特徴の数を減らすことです。計算量の多さの主な原因は畳み込み層です。計算量の安い \(1 \times 1\) 畳み込みを 3x3 や 5x5 の畳み込みの直前に置くことで、特徴の次元を削減します。例で見てみましょう。

\( S \times S \times 128 \) の特徴マップを、5x5 畳み込みで \( S \times S \times 256 \) に変換したいとします。パラメータ数（バイアスを除く）は 5*5*128*256 = 819,200 です。しかし、まず \(1 \times 1\) 畳み込みで特徴の次元を64まで削減すると、パラメータ数（バイアスを除く）は \( 1\times 1\times 128\times 64 + 5\times 5\times 64\times 256 = 8,192 + 409,600 = 417,792 \) となります。つまり、パラメータ数がほぼ半分に減りました！

また、出力特徴マップと連結する前に、最大プーリングの出力特徴も削減したいところです。そこで、最大プーリング層の後にもう1つ \( 1\times 1 \) 畳み込みを追加します。各 \( 1\times 1 \) 畳み込みの後には ReLU 活性化も追加し、モジュールの非線形性と複雑さを高めます。図2をご覧ください。

図2： Inception モジュール

また、複数のスケールでの畳み込みを並列に実行することで、ネットワークを深くすることなく演算を増やせるため、本質的に勾配消失問題が緩和されます。

平均プーリング

AlexNet や VGG のような従来のネットワークでは、最終層はいくつかの全結合層でした。これらの全結合層はユニット数が多いため、ネットワークのパラメータの大部分を占めます。たとえば、VGG16 のパラメータの89%は最後の3つの全結合層にあります。AlexNet のパラメータの95%は最後の全結合層にあります。この必要性は、畳み込み層は必ずしも十分に複雑ではないという前提に起因すると考えられます。

しかし、Inception ブロックが手元にあれば、全結合層は不要で、空間次元に沿った単純な平均プーリングで十分なはずです。これも Network in Network 論文から導かれたものでした。ただし、GoogLeNet には全結合層が1つ含まれています。著者たちは top-1 精度が 0.6% 向上したと報告しています。

GoogLeNet では、全結合層にあるパラメータは全体の15%だけです。

補助分類器

計算量を節約する \( 1 \times 1 \) 畳み込みの導入と、複数の全結合層の平均プーリングへの置き換えにより、このネットワークのパラメータは大幅に削減され、より多くの層を追加してネットワークを深くできます。しかし、層を積み重ねると勾配消失の問題が生じ得ます。勾配が入力側の層へ逆伝播するうちに小さくなり、ゼロに近づいてしまうのです。

論文では補助分類器（auxiliary classifier）が導入されています。中間の層からいくつかの小さな分類器を分岐させ、これらの分類器の損失を（重みを小さくして）全体の損失に加えます。これにより、入力に近い層も適度な大きさの勾配を受け取れるようになります。

補助分類器は以下から構成されます。 - フィルタサイズ \( 5 \times 5 \)、ストライド3の平均プーリング層。 - 次元削減のための128個のフィルタを持つ \( 1 \times 1 \) 畳み込みと、整流線形活性化（ReLU）。 - 1024個のユニットと整流線形活性化を持つ全結合層。 - 出力の70%を落とす比率のドロップアウト層。 - 分類器として softmax 損失を持つ線形層。

これらの補助分類器は推論時には取り除かれます。なお、補助分類器の使用による利得はわずかです（0.5%）。

図3： 補助分類器

アーキテクチャ - GoogLeNet

GoogLeNet の完全なアーキテクチャを下の図に示します。Inception ブロック内部を含むすべての畳み込みは ReLU 活性化を使います。まず2つの畳み込みと最大プーリングのブロックから始まります。続いて、2つの Inception モジュール（3a と 3b）のブロックと最大プーリングが来ます。その後、5つの Inception ブロック（4a、4b、4c、4d、4e）のブロックと最大プーリングが続きます。補助分類器は 4a と 4d の出力から取り出されます。次に2つの Inception ブロック（5a と 5b）が続きます。その後、平均プーリングと128ユニットの全結合層が使われます。

図4： GoogLeNet の完全なアーキテクチャ

コード

import torch
import torch.nn as nn


class BaseConv2d(nn.Module):
    def __init__(self, in_channels, out_channels, **kwargs):
        super(BaseConv2d, self).__init__()
        self.conv = nn.Conv2d(in_channels, out_channels, **kwargs)
        self.relu = nn.ReLU()

    def forward(self, x):
        x = self.conv(x)
        x = self.relu(x)
        return x


class InceptionModule(nn.Module):
    def __init__(self, in_channels, n1x1, n3x3red, n3x3, n5x5red, n5x5, pool_proj):
        super(InceptionModule, self).__init__()

        self.b1 = nn.Sequential(
            nn.Conv2d(in_channels, n1x1, kernel_size=1),
            nn.ReLU(True),
        )

        self.b2 = nn.Sequential(
            BaseConv2d(in_channels, n3x3red, kernel_size=1),
            BaseConv2d(n3x3red, n3x3, kernel_size=3, padding=1),
        )

        self.b3 = nn.Sequential(
            BaseConv2d(in_channels, n5x5red, kernel_size=1),
            BaseConv2d(n5x5red, n5x5, kernel_size=5, padding=2),
        )

        self.b4 = nn.Sequential(
            nn.MaxPool2d(3, stride=1, padding=1),
            BaseConv2d(in_channels, pool_proj, kernel_size=1),
        )

    def forward(self, x):
        y1 = self.b1(x)
        y2 = self.b2(x)
        y3 = self.b3(x)
        y4 = self.b4(x)
        return torch.cat([y1, y2, y3, y4], 1)


class AuxiliaryClassifier(nn.Module):
    def __init__(self, in_channels, num_classes, dropout=0.7):
        super(AuxiliaryClassifier, self).__init__()
        self.pool = nn.AvgPool2d(5, stride=3)
        self.conv = BaseConv2d(in_channels, 128, kernel_size=1)
        self.relu = nn.ReLU(True)
        self.flatten = nn.Flatten()
        self.fc1 = nn.Linear(2048, 1024)
        self.dropout = nn.Dropout(dropout)
        self.fc2 = nn.Linear(1024, num_classes)

    def forward(self, x):
        x = self.pool(x)
        x = self.conv(x)
        x = self.flatten(x)
        x = self.fc1(x)
        x = self.relu(x)
        x = self.dropout(x)
        x = self.fc2(x)
        return x


class GoogLeNet(nn.Module):
    def __init__(self, use_aux=True):
        super(GoogLeNet, self).__init__()

        self.use_aux = use_aux
        ## ブロック 1
        self.conv1 = BaseConv2d(3, 64, kernel_size=7, stride=2, padding=3)
        self.lrn1 = nn.LocalResponseNorm(5, alpha=0.0001, beta=0.75)
        self.maxpool1 = nn.MaxPool2d(3, stride=2, padding=1)

        ## ブロック 2
        self.conv2 = BaseConv2d(64, 64, kernel_size=1)
        self.conv3 = BaseConv2d(64, 192, kernel_size=3, padding=1)
        self.lrn2 = nn.LocalResponseNorm(5, alpha=0.0001, beta=0.75)
        self.maxpool2 = nn.MaxPool2d(3, stride=2, padding=1)

        ## ブロック 3
        self.inception3a = InceptionModule(192, 64, 96, 128, 16, 32, 32)
        self.inception3b = InceptionModule(256, 128, 128, 192, 32, 96, 64)
        self.maxpool3 = nn.MaxPool2d(3, stride=2, padding=1)

        ## ブロック 4
        self.inception4a = InceptionModule(480, 192, 96, 208, 16, 48, 64)
        self.inception4b = InceptionModule(512, 160, 112, 224, 24, 64, 64)
        self.inception4c = InceptionModule(512, 128, 128, 256, 24, 64, 64)
        self.inception4d = InceptionModule(512, 112, 144, 288, 32, 64, 64)
        self.inception4e = InceptionModule(528, 256, 160, 320, 32, 128, 128)
        self.maxpool4 = nn.MaxPool2d(3, stride=2, padding=1)

        ## ブロック 5
        self.inception5a = InceptionModule(832, 256, 160, 320, 32, 128, 128)
        self.inception5b = InceptionModule(832, 384, 192, 384, 48, 128, 128)

        ## 補助分類器
        if self.use_aux:
            self.aux1 = AuxiliaryClassifier(512, 1000)
            self.aux2 = AuxiliaryClassifier(528, 1000)

        ## ブロック 6
        self.avgpool = nn.AvgPool2d(7, stride=1)
        self.dropout = nn.Dropout(0.4)
        self.fc = nn.Linear(1024, 1000)

    def forward(self, x):
        ## ブロック 1
        x = self.conv1(x)
        x = self.maxpool1(x)
        x = self.lrn1(x)

        ## ブロック 2
        x = self.conv2(x)
        x = self.conv3(x)
        x = self.lrn2(x)
        x = self.maxpool2(x)

        ## ブロック 3
        x = self.inception3a(x)
        x = self.inception3b(x)
        x = self.maxpool3(x)

        ## ブロック 4
        x = self.inception4a(x)
        if self.use_aux:
            aux1 = self.aux1(x)
        x = self.inception4b(x)
        x = self.inception4c(x)
        x = self.inception4d(x)
        if self.use_aux:
            aux2 = self.aux2(x)
        x = self.inception4e(x)
        x = self.maxpool4(x)

        ## ブロック 5
        x = self.inception5a(x)
        x = self.inception5b(x)

        ## ブロック 6
        x = self.avgpool(x)
        x = torch.flatten(x, 1)
        x = self.dropout(x)
        x = self.fc(x)

        if self.use_aux:
            return x, aux1, aux2
        else:
            return x
