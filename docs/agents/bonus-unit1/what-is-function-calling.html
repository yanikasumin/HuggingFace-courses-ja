Function-calling とは？

Function-calling は、LLM が環境に対して操作を行う為の仕組みです。GPT-4 で初めて導入され、その後、他のモデルにも同様の仕組みが実装されました。

エージェントが使うツールと同じように、Function-calling もモデルに外部の環境へ働きかける能力を与えます。但し、Function-calling の能力はモデルが学習によって身につけるもので、他のエージェント手法よりもプロンプトへの依存が小さいのが特徴です。

ユニット 1 では、エージェントにツールの使い方を学習させた訳ではありません。私たちはツールの一覧を渡しただけで、モデルが学習済みの能力を応用して、それらのツールを使う計画を立てられることに頼っていました。

一方、ここではエージェントがツールを使えるよう、Function-calling の為のファインチューニング（訓練）を行います。

モデルはどうやって行動を起こすことを「学ぶ」のか？

ユニット 1 では、エージェントの一般的な処理の流れを学びました。ユーザーがエージェントにいくつかのツールを与えて質問や指示を入力すると、モデルは次の3つのステップを繰り返します。

  1. Think（考える）：目的を達成する為に、どんなアクションを取る必要が有るか。
  2. Act（行動する）：適切なパラメータを指定してツール呼び出しを組み立て、生成を止める。
  3. Observe（観察する）：実行結果を受け取る。

API 経由でモデルと会話する場合、通常は次のようにユーザーとアシスタントのメッセージが交互に並びます。

conversation = [
    {"role": "user", "content": "I need help with my order"},
    {"role": "assistant", "content": "I'd be happy to help. Could you provide your order number?"},
    {"role": "user", "content": "It's ORDER-123"},
]

（会話の訳：ユーザー「注文について助けて欲しいのですが」／アシスタント「喜んでお手伝いします。注文番号を教えて頂けますか？」／ユーザー「ORDER-123 です」）

Function-calling では、会話に新しいロールが加わります！

  1. Action 用の新しいロール
  2. Observation 用の新しいロール

Mistral API を例に取ると、次のようになります。

conversation = [
    {
        "role": "user",
        "content": "What's the status of my transaction T1001?"
    },
    {
        "role": "assistant",
        "content": "",
        "function_call": {
            "name": "retrieve_payment_status",
            "arguments": "{\"transaction_id\": \"T1001\"}"
        }
    },
    {
        "role": "tool",
        "name": "retrieve_payment_status",
        "content": "{\"status\": \"Paid\"}"
    },
    {
        "role": "assistant",
        "content": "Your transaction T1001 has been successfully paid."
    }
]

（会話の訳：ユーザー「取引 T1001 の状況はどうなっていますか？」／アシスタントが retrieve_payment_status（支払い状況を取得する関数）を呼び出し、ツールから「支払い済み」という結果が返る／アシスタント「お客様の取引 T1001 は正常に支払われました」）

…でも、関数呼び出し用の新しいロールが有ると言いましたよね？

そうとも言えますが、少し違います。この例を含む多くの API では、モデルは実行したいアクションを assistant ロールのメッセージとして出力します。その後、チャットテンプレートによって、その内容が Function-calling 用の特殊トークンで表現されます。

  • [AVAILABLE_TOOLS]：利用可能なツールの一覧の開始
  • [/AVAILABLE_TOOLS]：利用可能なツールの一覧の終了
  • [TOOL_CALLS]：ツールへの呼び出しを行う（つまり「Action」を取る）
  • [TOOL_RESULTS]：アクションの結果を「Observe」する
  • [/TOOL_RESULTS]：観測の終了（モデルがトークンの生成を再開出来る）

Function-calling については、このコースでも後程取り上げます。先に詳しく学びたい場合は、こちらの詳しいドキュメントをご覧ください。

Function-calling の仕組みが分かった所で、今度はまだその機能を持たないモデルに Function-calling の機能を追加してみましょう。対象は google/gemma-2-2b-it です。このモデルに新しい特殊トークンを追加します。

それを行うには、まずファインチューニングと LoRA を理解する必要があります。
