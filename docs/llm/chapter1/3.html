Transformer は何ができるのか？

このセクションでは、Transformer モデルに何ができるのかを見ていき、🤗 Transformers ライブラリの最初のツールである pipeline() 関数を使ってみます。

サンプルをローカルで実行したい場合は、セットアップを参照してください。

Transformer はあらゆるところに！

Transformer モデルは、自然言語処理（NLP）、コンピュータビジョン、音声処理など、さまざまなモダリティの幅広いタスクを解くために使われています。Hugging Face と Transformer モデルを利用し、モデルを共有することでコミュニティにも貢献している企業や組織には、たとえば次のようなところがあります。

🤗 Transformers ライブラリは、そうした共有モデルを作成し、利用するための機能を提供します。Model Hubには、誰でもダウンロードして使える数百万もの事前学習済みモデルが集まっています。自分のモデルを Hub にアップロードすることもできます！

💡 ヒント

⚠️ Hugging Face Hub は Transformer モデルだけに限られません。誰でも、好きな種類のモデルやデータセットを共有できます！すべての機能を使うには、huggingface.co アカウントを作成しましょう！

Transformer モデルの内部の仕組みに入る前に、興味深い NLP の問題を解くためにどう使えるのか、いくつか例を見てみましょう。

パイプラインを使う

🤗 Transformers ライブラリで最も基本的なオブジェクトが pipeline() 関数です。モデルと必要な前処理・後処理のステップをつなぐことで、任意のテキストを直接入力して、わかりやすい答えを得ることができます。

from transformers import pipeline

classifier = pipeline("sentiment-analysis")
classifier("I've been waiting for a HuggingFace course my whole life.")

```python out [{'label': 'POSITIVE', 'score': 0.9598047137260437}]

複数の文を渡すこともできます！

```python
classifier(
    ["I've been waiting for a HuggingFace course my whole life.", "I hate this so much!"]
)

```python out [{'label': 'POSITIVE', 'score': 0.9598047137260437}, {'label': 'NEGATIVE', 'score': 0.9994558095932007}]

デフォルトでは、このパイプラインは英語の感情分析向けにファインチューニングされた特定の事前学習済みモデルを選択します。モデルは `classifier` オブジェクトを作成するときにダウンロードされ、キャッシュされます。コマンドを再実行すると、代わりにキャッシュされたモデルが使われるので、モデルを改めてダウンロードする必要はありません。

テキストをパイプラインに渡すときには、主に3つのステップがあります。

1. テキストが、モデルが理解できる形式に前処理されます。
2. 前処理された入力がモデルに渡されます。
3. モデルの予測結果を後処理し、人間が解釈しやすい形式に変換します。

## さまざまなモダリティで利用できるパイプライン

`pipeline()` 関数は複数のモダリティに対応しており、テキスト、画像、音声、さらにはマルチモーダルなタスクにも使えます。このコースではテキストのタスクに焦点を当てますが、Transformer アーキテクチャの可能性を理解するうえで役立つので、ここではその概要を簡単に紹介します。

利用できるものの一覧は次のとおりです。

### テキストパイプライン

- `text-generation`: プロンプトからテキストを生成する
- `text-classification`: テキストをあらかじめ定義したカテゴリに分類する
- `summarization`: 重要な情報を保ちながら、テキストをより短い文にまとめる
- `translation`: テキストをある言語から別の言語に翻訳する
- `zero-shot-classification`: 特定のラベルで事前に学習することなく、テキストを分類する
- `feature-extraction`: テキストのベクトル表現を抽出する

### 画像パイプライン

- `image-to-text`: 画像のテキストによる説明を生成する
- `image-classification`: 画像の中の物体を識別する
- `object-detection`: 画像の中の物体の位置を特定し、識別する

### 音声パイプライン

- `automatic-speech-recognition`: 音声をテキストに変換する
- `audio-classification`: 音声をカテゴリに分類する
- `text-to-speech`: テキストを音声に変換する

### マルチモーダルパイプライン

- `image-text-to-text`: テキストプロンプトに基づいて画像に応答する

これらのパイプラインのいくつかを、もう少し詳しく見ていきましょう！

## ゼロショット分類

まずは、ラベル付けされていないテキストを分類するという、より難しいタスクに取り組みます。テキストへのアノテーションには通常、時間がかかり専門知識も必要なので、これは実世界のプロジェクトでよくあるシナリオです。この用途には `zero-shot-classification` パイプラインが非常に強力です。使用するラベルを自分で指定できるので、事前学習済みモデルのラベルに頼る必要がありません。モデルが文を positive と negative の2つのラベルを使って分類できることは既に見ましたが、それ以外の任意のラベルの集合を使ってテキストを分類することもできます。

```python
from transformers import pipeline

classifier = pipeline("zero-shot-classification")
classifier(
    "This is a course about the Transformers library",
    candidate_labels=["education", "politics", "business"],
)

```python out {'sequence': 'This is a course about the Transformers library', 'labels': ['education', 'business', 'politics'], 'scores': [0.8445963859558105, 0.111976258456707, 0.043427448719739914]}

このパイプラインが _ゼロショット_ と呼ばれるのは、使うために自分のデータでモデルをファインチューニングする必要がないからです。希望するラベルのリストに対して、確率スコアを直接返すことができます！

## テキスト生成

次に、パイプラインを使ってテキストを生成する方法を見てみましょう。基本的な考え方は、プロンプトを与えると、モデルが続きのテキストを生成して自動で補完するというものです。これは、多くのスマートフォンにある予測変換の機能に似ています。テキスト生成にはランダム性が含まれるので、下に示す結果とまったく同じ結果が得られなくても普通のことです。

```python
from transformers import pipeline

generator = pipeline("text-generation")
generator("In this course, we will teach you how to")

```python out [{'generated_text': 'In this course, we will teach you how to understand and use ' 'data flow and data interchange when handling user data. We ' 'will be working with one or more of the most commonly used ' 'data flows — data flows of various types, as seen by the ' 'HTTP'}]

生成されるシーケンスの数は `num_return_sequences` 引数で、出力テキストの全体の長さは `max_length` 引数で制御できます。

<p class="callout-title">💡 ヒント</p>

</div>


## Hub の任意のモデルをパイプラインで使う

これまでの例では、そのタスク向けのデフォルトモデルを使いましたが、特定のタスクに向けて、Hub の中から特定のモデルを選んでパイプラインで使うこともできます。たとえばテキスト生成です。[Model Hub](https://huggingface.co/models)に移動し、左側の対応するタグをクリックすると、そのタスクでサポートされるモデルだけが表示されます。[こちらのページ](https://huggingface.co/models?pipeline_tag=text-generation)のようなページが表示されるはずです。

[`HuggingFaceTB/SmolLM2-360M`](https://huggingface.co/HuggingFaceTB/SmolLM2-360M)モデルを試してみましょう！前と同じパイプラインに読み込む方法は次のとおりです。

```python
from transformers import pipeline

generator = pipeline("text-generation", model="HuggingFaceTB/SmolLM2-360M")
generator(
    "In this course, we will teach you how to",
    max_length=30,
    num_return_sequences=2,
)

```python out [{'generated_text': 'In this course, we will teach you how to manipulate the world and ' 'move your mental and physical capabilities to your advantage.'}, {'generated_text': 'In this course, we will teach you how to become an expert and ' 'practice realtime, and with a hands on experience on both real ' 'time and real'}]

言語のタグをクリックするとモデル検索を絞り込むことができ、別の言語でテキストを生成するモデルを選ぶこともできます。Model Hub には、複数の言語に対応した多言語モデルのチェックポイントもあります。

モデルをクリックして選択すると、オンラインで直接試せるウィジェットが表示されます。これにより、ダウンロードする前にモデルの能力をすばやく試すことができます。

### Inference Providers

Hugging Face の[ウェブサイト](https://huggingface.co/docs/inference-providers/en/index)では、Inference Providers を通じてモデルをブラウザ上で直接試せます。任意のテキストを入力し、モデルがどのように処理するかをその場で確認できます。

ウィジェットを動かしている Inference Providers は、有料プロダクトとしても提供されており、自分のワークフローで必要になったときに便利です。詳しくは[料金ページ](https://huggingface.co/docs/inference-providers/en/pricing)を参照してください。

## マスク補完

次に試すパイプラインは `fill-mask` です。このタスクの考え方は、与えられたテキストの空白を埋めることです。

```python
from transformers import pipeline

unmasker = pipeline("fill-mask")
unmasker("This course will teach you all about <mask> models.", top_k=2)

```python out [{'sequence': 'This course will teach you all about mathematical models.', 'score': 0.19619831442832947, 'token': 30412, 'token_str': ' mathematical'}, {'sequence': 'This course will teach you all about computational models.', 'score': 0.04052725434303284, 'token': 38163, 'token_str': ' computational'}]

`top_k` 引数は、表示したい候補の数を制御します。ここでモデルが補完しているのは特殊な単語 `<mask>` で、これはしばしば *マスクトークン* と呼ばれます。モデルによっては異なるマスクトークンを使う場合もあるので、他のモデルを調べるときは、そのモデルが使用するマスクトークンを確認するのがよい習慣です。確認する方法の1つは、ウィジェットで使われているマスクトークンを調べることです。

<div class="callout callout-tip" markdown="block">
<p class="callout-title">💡 ヒント</p>
✏️ **試してみましょう！** Hub で `bert-base-cased` モデルを検索し、Inference API ウィジェットでそのマスクトークンを確認してください。このモデルは、上記の `pipeline` の例の文に対して何を予測するでしょうか？
</div>


## 固有表現認識

固有表現認識（NER）は、入力テキストのどの部分が人物、場所、組織といったエンティティに対応するかを、モデルが見つけ出すタスクです。例を見てみましょう。

```python
from transformers import pipeline

ner = pipeline("ner", aggregation_strategy="simple")
ner("My name is Sylvain and I work at Hugging Face in Brooklyn.")

```python out [{'entity_group': 'PER', 'score': 0.99816, 'word': 'Sylvain', 'start': 11, 'end': 18}, {'entity_group': 'ORG', 'score': 0.97960, 'word': 'Hugging Face', 'start': 33, 'end': 45}, {'entity_group': 'LOC', 'score': 0.99321, 'word': 'Brooklyn', 'start': 49, 'end': 57} ]

ここではモデルは、Sylvain が人物（PER）、Hugging Face が組織（ORG）、Brooklyn が場所（LOC）であることを正しく識別しました。

パイプライン作成関数に `aggregation_strategy="simple"` オプションを渡すと、文の中で同じエンティティに対応する部分同士をまとめるよう、パイプラインに指示できます。ここではモデルは、名前が複数の単語から構成されているにもかかわらず、"Hugging" と "Face" を1つの組織として正しくまとめました。実際、次の章でわかるように、前処理では単語がさらに小さい部分に分割されることさえあります。たとえば `Sylvain` は、`S`、`##yl`、`##va`、`##in` の4つのピースに分割されます。後処理のステップでは、パイプラインはこれらのピースをきれいにまとめ直しました。

<p class="callout-title">💡 ヒント</p>

</div>

## 要約

要約とは、原文に含まれる重要な情報をできる限り残しながら、文章を短くまとめるタスクです。例を示します。

```python
from transformers import pipeline

summarizer = pipeline("summarization")
summarizer(
    """
    America has changed dramatically during recent years. Not only has the number of 
    graduates in traditional engineering disciplines such as mechanical, civil, 
    electrical, chemical, and aeronautical engineering declined, but in most of 
    the premier American universities engineering curricula now concentrate on 
    and encourage largely the study of engineering science. As a result, there 
    are declining offerings in engineering subjects dealing with infrastructure, 
    the environment, and related issues, and greater concentration on high 
    technology subjects, largely supporting increasingly complex scientific 
    developments. While the latter is important, it should not be at the expense 
    of more traditional engineering.

    Rapidly developing economies such as China and India, as well as other 
    industrial countries in Europe and Asia, continue to encourage and advance 
    the teaching of engineering. Both China and India, respectively, graduate 
    six and eight times as many traditional engineers as does the United States. 
    Other industrial countries at minimum maintain their output, while America 
    suffers an increasingly serious decline in the number of engineering graduates 
    and a lack of well-educated engineers.
"""
)

```python out [{'summary_text': ' America has changed dramatically during recent years . The ' 'number of engineering graduates in the U.S. has declined in ' 'traditional engineering disciplines such as mechanical, civil ' ', electrical, chemical, and aeronautical engineering . Rapidly ' 'developing economies such as China and India, as well as other ' 'industrial countries in Europe and Asia, continue to encourage ' 'and advance engineering .'}]

テキスト生成と同様に、結果に対して `max_length` や `min_length` を指定できます。

## 翻訳

翻訳では、タスク名に言語ペアを指定すれば（`"translation_en_to_fr"` のように）デフォルトモデルを使うこともできますが、最も簡単な方法は、[Model Hub](https://huggingface.co/models)で使いたいモデルを選ぶことです。ここでは、フランス語から英語への翻訳を試してみます。

```python
from transformers import pipeline

translator = pipeline("translation", model="Helsinki-NLP/opus-mt-fr-en")
translator("Ce cours est produit par Hugging Face.")

```python out [{'translation_text': 'This course is produced by Hugging Face.'}]

テキスト生成や要約と同様に、結果に対して `max_length` や `min_length` を指定できます。

## 画像と音声のパイプライン

テキスト以外にも、Transformer モデルは画像や音声を扱うことができます。いくつか例を示します。

### 画像分類

```python
from transformers import pipeline

image_classifier = pipeline(
    task="image-classification", model="google/vit-base-patch16-224"
)
result = image_classifier(
    "https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/pipeline-cat-chonk.jpeg"
)
print(result)

### 自動音声認識

```python
from transformers import pipeline

transcriber = pipeline(
    task="automatic-speech-recognition", model="openai/whisper-large-v3"
)
result = transcriber(
    "https://huggingface.co/datasets/Narsil/asr_dummy/resolve/main/mlk.flac"
)
print(result)

複数のソースからデータを組み合わせる

Transformer モデルの強力な応用の1つは、複数のソースからデータを組み合わせて処理できることです。これは特に、次のような場合に役立ちます。

  1. 複数のデータベースやリポジトリを横断して検索する
  2. 異なる形式（テキスト、画像、音声）の情報を統合する
  3. 関連情報の統一的なビューを作成する

たとえば、次のようなシステムを構築できます。 - テキストや画像といった複数のモダリティにわたって、データベース内の情報を検索する。 - 異なるソースからの結果を、1つの首尾一貫した応答にまとめる。たとえば、音声ファイルとテキストによる説明から。 - ドキュメントとメタデータのデータベースの中から、最も関連性の高い情報を提示する。
