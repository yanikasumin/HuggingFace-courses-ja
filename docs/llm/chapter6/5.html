バイトペアエンコーディングによるトークン化

バイトペアエンコーディング（Byte-Pair Encoding、BPE）は、もともとテキストを圧縮するアルゴリズムとして開発され、その後 OpenAI が GPT モデルの事前学習時のトークン化に採用しました。GPT、GPT-2、RoBERTa、BART、DeBERTa など、多くの Transformer モデルで使われています。

💡 ヒント

💡 この節では BPE を深く掘り下げ、完全な実装を示すところまで扱います。トークン化アルゴリズムの概要だけ知りたい場合は、最後まで読み飛ばしても構いません。

学習アルゴリズム

BPE の学習は、まずコーパスで使われている単語の集合（重複なし）を求めることから始まります（正規化と事前トークン化のステップが終わったあとの話です）。次に、それらの単語を構成する記号をすべて集めて語彙を構築します。ごく簡単な例として、コーパスが次の5つの単語を使っているとしましょう。

"hug", "pug", "pun", "bun", "hugs"

すると基本語彙は ["b", "g", "h", "n", "p", "s", "u"] になります。実際のコーパスでは、基本語彙には少なくともすべての ASCII 文字が含まれ、おそらく Unicode 文字もいくつか含まれるでしょう。トークン化したいテキストに学習コーパスにない文字が含まれていると、その文字は未知語トークンに変換されます。多くの NLP モデルが絵文字を含むコンテンツの分析を苦手とするのは、このためです。

💡 ヒント

GPT-2 と RoBERTa のトークナイザ（両者はかなり似ています）には、この問題への賢い対処法があります。単語を Unicode 文字で書かれたものとして見るのではなく、バイトで書かれたものとして見るのです。この方法なら基本語彙のサイズは小さく（256）抑えられますが、思いつく限りのあらゆる文字が含まれ、未知語トークンに変換されることはありません。この手法は バイトレベル BPE と呼ばれます。

基本語彙が得られたら、目的の語彙サイズに到達するまで新しいトークンを追加していきます。追加の仕方を決めるのが マージ です。マージとは、既存の語彙の2つの要素を結びつけて新しい要素を作るルールのことです。学習の初期には2文字のトークンが生まれ、学習が進むにつれて、より長いサブワードが生まれていきます。

トークナイザの学習中、BPE アルゴリズムは各ステップで既存トークンの最も頻繁なペアを探します（ここで「ペア」とは、単語の中で連続する2つのトークンのことです）。最も頻繁なペアがマージされ、次のステップで同じ手順を繰り返します。

先ほどの例に戻りましょう。単語の頻度が次のようだったとします。

("hug", 10), ("pug", 5), ("pun", 12), ("bun", 4), ("hugs", 5)

つまり "hug" はコーパスに10回、"pug" は5回、"pun" は12回、"bun" は4回、"hugs" は5回現れたということです。学習は、各単語を文字（初期語彙を構成する文字）に分割することから始めます。こうすると各単語をトークンのリストとして見られます。

("h" "u" "g", 10), ("p" "u" "g", 5), ("p" "u" "n", 12), ("b" "u" "n", 4), ("h" "u" "g" "s", 5)

次にペアを見ていきます。ペア ("h", "u") は "hug" と "hugs" に現れるので、コーパス全体で15回現れます。しかし、最も出現頻度が高いのは ("u", "g") のペアです。これは "hug"、"pug"、"hugs" に現れ、コーパス全体で合計20回現れます。

したがって、トークナイザが学ぶ最初のマージルールは ("u", "g") -> "ug" です。これは "ug" が語彙に追加され、コーパスのすべての単語でこのペアがマージされることを意味します。この段階が終わると、語彙とコーパスは次のようになります。

Vocabulary: ["b", "g", "h", "n", "p", "s", "u", "ug"]
Corpus: ("h" "ug", 10), ("p" "ug", 5), ("p" "u" "n", 12), ("b" "u" "n", 4), ("h" "ug" "s", 5)

ここで、2文字より長いトークンを生むペアが現れています。たとえばペア ("h", "ug") です（コーパスに15回現れます）。しかし、この段階で最も頻繁なペアは ("u", "n") で、コーパスに16回現れます。そのため、2番目に学ぶマージルールは ("u", "n") -> "un" です。これを語彙に追加し、既存のすべての出現箇所をマージすると、次のようになります。

Vocabulary: ["b", "g", "h", "n", "p", "s", "u", "ug", "un"]
Corpus: ("h" "ug", 10), ("p" "ug", 5), ("p" "un", 12), ("b" "un", 4), ("h" "ug" "s", 5)

今度は最も頻繁なペアが ("h", "ug") になったので、マージルール ("h", "ug") -> "hug" を学びます。これで初めての3文字トークンが得られます。マージ後のコーパスは次のとおりです。

Vocabulary: ["b", "g", "h", "n", "p", "s", "u", "ug", "un", "hug"]
Corpus: ("hug", 10), ("p" "ug", 5), ("p" "un", 12), ("b" "un", 4), ("hug" "s", 5)

この調子で、目的の語彙サイズに到達するまで続けます。

💡 ヒント

トークン化アルゴリズム

トークン化は学習プロセスに密接に沿っており、新しい入力は次のステップでトークン化されます。

  1. 正規化
  2. 事前トークン化
  3. 単語を個々の文字に分割
  4. 学習したマージルールを順番に適用

学習で使った例を取り上げましょう。学んだマージルールは3つです。

("u", "g") -> "ug"
("u", "n") -> "un"
("h", "ug") -> "hug"

単語 "bug" は ["b", "ug"] とトークン化されます。一方 "mug" は ["[UNK]", "ug"] とトークン化されます。文字 "m" が基本語彙に含まれていないためです。同様に、単語 "thug" は ["[UNK]", "hug"] とトークン化されます。文字 "t" は基本語彙に含まれておらず、マージルールを適用すると、まず "u" と "g" がマージされ、次に "h" と "ug" がマージされるためです。

💡 ヒント

✏️ やってみよう！ 単語 "unhug" はどのようにトークン化されると思いますか？

BPE の実装

では、BPE アルゴリズムの実装を見ていきましょう。これは大きなコーパスで実際に使えるような最適化されたバージョンではありません。アルゴリズムをもう少しよく理解してもらうためにコードを示すことが目的です。

まずコーパスが必要です。いくつかの文からなる簡単なものを作りましょう。

corpus = [
    "This is the Hugging Face Course.",
    "This chapter is about tokenization.",
    "This section shows several tokenizer algorithms.",
    "Hopefully, you will be able to understand how they are trained and generate tokens.",
]

次に、このコーパスを単語へ事前トークン化する必要があります。GPT-2 のような BPE トークナイザを再現するので、事前トークン化には gpt2 トークナイザを使います。

from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("gpt2")

次に、事前トークン化を行いながら、コーパス内の各単語の頻度を数えます。

from collections import defaultdict

word_freqs = defaultdict(int)

for text in corpus:
    words_with_offsets = tokenizer.backend_tokenizer.pre_tokenizer.pre_tokenize_str(text)
    new_words = [word for word, offset in words_with_offsets]
    for word in new_words:
        word_freqs[word] += 1

print(word_freqs)

学習を始められるよう、各単語を個々の文字に分割しておきます。

splits = {word: [c for c in word] for word in word_freqs.keys()}

学習の準備ができました。各ペアの頻度を計算する関数を書きましょう。学習の各ステップで必要になります。

def compute_pair_freqs(splits):
    pair_freqs = defaultdict(int)
    for word, freq in word_freqs.items():
        split = splits[word]
        if len(split) == 1:
            continue
        for i in range(len(split) - 1):
            pair = (split[i], split[i + 1])
            pair_freqs[pair] += freq
    return pair_freqs

初期分割のあとで、この辞書の一部がどうなっているか見てみましょう。

pair_freqs = compute_pair_freqs(splits)

つまり、最初に学ぶマージは `('Ġ', 't') -> 'Ġt'` で、`'Ġt'` を語彙に追加します。

```python
merges = {("Ġ", "t"): "Ġt"}

続けるには、このマージを splits 辞書に適用する必要があります。そのための関数も書きましょう。

def merge_pair(a, b, splits):
    for word in word_freqs:
        split = splits[word]
        if len(split) == 1:
            continue

        i = 0
        while i < len(split) - 1:
            if split[i] == a and split[i + 1] == b:
                split = split[:i] + [a + b] + split[i + 2 :]
            else:
                i += 1
        splits[word] = split
    return splits

vocab_size = 50

新しいテキストをトークン化するには、事前トークン化して分割し、学んだすべてのマージルールを適用します。

```python
def tokenize(text):
    pre_tokenize_result = tokenizer._tokenizer.pre_tokenizer.pre_tokenize_str(text)
    pre_tokenized_text = [word for word, offset in pre_tokenize_result]
    splits = [[l for l in word] for word in pre_tokenized_text]
    for pair, merge in merges.items():
        for idx, split in enumerate(splits):
            i = 0
            while i < len(split) - 1:
                if split[i] == pair[0] and split[i + 1] == pair[1]:
                    split = split[:i] + [merge] + split[i + 2 :]
                else:
                    i += 1
            splits[idx] = split

    return sum(splits, [])

アルファベットに含まれる文字で構成されたテキストなら、どれでも試すことができます。

tokenize("This is not a token.")

python out ['This', 'Ġis', 'Ġ', 'n', 'o', 't', 'Ġa', 'Ġtoken', '.']

⚠️ 注意

⚠️ この実装は未知の文字を処理する仕組みがないため、未知の文字があるとエラーになります。GPT-2 には実際には未知語トークンは存在しません（バイトレベル BPE を使うと未知の文字が生じようがないため）。しかしここでは、可能なすべてのバイトを初期語彙に含めていないため、この問題が起こりえます。BPE のこの側面は本節の範囲を超えるため、詳細は省略します。
