# 強化学習と LLM におけるその役割の紹介

最初のページへようこそ！

強化学習（RL）のエキサイティングな世界への旅を始め、RL が、皆さんが日常的に使っているような言語モデルの学習方法をどう変革しているのかを見ていきましょう。

> [!TIP]
> この章では、言語モデルのための強化学習に焦点を当てます。しかし強化学習は、言語モデル以外にも多くの応用がある広い分野です。強化学習についてもっと学びたい方は、[Deep Reinforcement Learning コース](https://huggingface.co/courses/deep-rl-course/en/unit1/introduction)をチェックしてください。

このページでは、RL に初めて触れる方にも分かりやすく、親しみやすい形で紹介します。核となる考え方を分解し、RL が大規模言語モデル（LLM）の分野でなぜこれほど重要になっているのかを見ていきます。

## 強化学習（RL）とは何か？

犬を訓練するところを想像してみてください。「お座り」を教えたいとします。「お座り！」と言って、犬が座ったら、おやつをあげて褒めます。座らなかったら、そっと誘導したり、もう一度試したりします。やがて犬は、座ることとポジティブな報酬（おやつと褒め言葉）を結びつけて覚え、「お座り！」と言われたら座る可能性が高くなります。強化学習では、このフィードバックを**報酬（reward）**と呼びます。

これが、強化学習の基本的な考え方です！犬の代わりに**言語モデル**があり（強化学習ではこれを**エージェント（agent）**と呼びます）、あなたの代わりにフィードバックを与える**環境（environment）**があります。

![RL の用語とプロセス](https://huggingface.co/reasoning-course/images/resolve/main/grpo/3.jpg)

RL の重要な要素を分解してみましょう。

### エージェント

学習者です。犬の例では、犬がエージェントです。LLM の文脈では、LLM 自体が学習させたいエージェントになります。エージェントは意思決定を行い、環境とその報酬から学びます。

### 環境

エージェントが生活し、相互作用する世界です。犬にとっての環境は、家と飼い主です。LLM にとっての環境はもう少し抽象的で、対話するユーザーであったり、設定したシミュレーションのシナリオであったりします。環境はエージェントにフィードバックを提供します。

### 行動

エージェントが環境の中で取れる選択肢です。犬の行動は「座る」「立つ」「吠える」などです。LLM にとっての行動は、文中の単語を生成すること、質問に対してどの答えを返すかを選ぶこと、会話でどう応答するかを決めることなどです。

### 報酬

エージェントが行動を取った後に、環境がエージェントに与えるフィードバックです。報酬は通常、数値で表されます。

**正の報酬**は、おやつや褒め言葉のようなものです。「よくできました、その調子！」とエージェントに伝えます。

**負の報酬**（ペナルティ）は、そっと「ダメ」と言うようなものです。「それはちょっと違う、別の方法を試して」と伝えます。犬にとっては、おやつが報酬です。

LLM にとっての報酬は、特定のタスクで LLM がどれだけうまくやれているかを反映するよう設計されます。たとえば、応答がどれだけ役立つか、真実か、無害か、といったものです。

### 方策

エージェントが行動を選ぶための戦略です。「お座り！」と言われたら何をすべきかについての、犬の理解のようなものです。RL では、方策こそが学習し、改善したい対象そのものです。方策は、異なる状況でどの行動を取るかをエージェントに指示する規則の集合、または関数です。最初はランダムかもしれませんが、エージェントが学習するにつれて、より高い報酬につながる行動を選ぶのが上手くなっていきます。

## RL のプロセス：試行錯誤

![RL のプロセス](https://huggingface.co/reasoning-course/images/resolve/main/grpo/1.jpg)

強化学習は、試行錯誤のプロセスを通じて行われます。

| ステップ | プロセス | 説明 |
|------|---------|-------------|
| 1. 観察 | エージェントが環境を観察する | エージェントは現在の状態と周囲に関する情報を取り込む |
| 2. 行動 | エージェントが現在の方策に基づいて行動を取る | 学習した戦略（方策）を使って、エージェントは次に何をするかを決める |
| 3. フィードバック | 環境がエージェントに報酬を与える | エージェントは、その行動がどれだけ良かったか悪かったかのフィードバックを受け取る |
| 4. 学習 | エージェントが報酬に基づいて方策を更新する | エージェントは戦略を調整する。高い報酬につながった行動を強化し、低い報酬につながった行動を避ける |
| 5. 反復 | プロセスを繰り返す | このサイクルが続き、エージェントは意思決定を継続的に改善していく |

自転車の乗り方を覚えることを考えてみてください。最初はぐらついて転ぶかもしれません（負の報酬！）。しかし、バランスを取ってスムーズにペダルを漕げると、気持ちがいい（正の報酬！）。このフィードバックに基づいて、少し傾いたり、速く漕いだりしながら行動を調整し、やがて上手に乗れるようになります。RL も似ています。相互作用とフィードバックを通じて学ぶことです。

## 大規模言語モデル（LLM）における RL の役割

では、なぜ RL は大規模言語モデルにとってそれほど重要なのでしょうか？

本当に優れた LLM の学習は難しいものです。インターネット上の膨大な量のテキストで学習すれば、文の次の単語を予測するのが非常に上手くなります。流暢で文法的に正しいテキストを生成する方法は、こうして学ばれるのです。[第2章](/course/chapter2/1)で学んだとおりです。

しかし、流暢なだけでは十分ではありません。LLM には、単に単語を上手くつなげる以上のことが求められます。次のようなものであってほしいのです。

* **役立つこと：** 有用で関連性のある情報を提供する。
* **無害であること：** 有害、偏見的、または有害なコンテンツの生成を避ける。
* **人間の選好に合っていること：** 人間が自然で、役立ち、魅力的に感じる方法で応答する。

LLM の事前学習の手法は、主にテキストデータから次の単語を予測することに依存しており、これらの側面では不十分な場合があります。

教師あり学習は構造化された出力を生成するのに優れていますが、役立ち、無害で、人間の選好に合った応答を生成するのにはあまり効果的でない場合があります。教師あり学習については[第11章](/course/chapter11/1)で探ります。

ファインチューニングされたモデルは、流暢で構造化されたテキストを生成しても、事実として誤っていたり、偏見を含んでいたり、ユーザーの質問に役立つ形で答えられていなかったりすることがあります。

**ここで強化学習の出番です！** RL は、事前学習された LLM をファインチューニングして、求める品質をよりよく達成するための方法を提供します。流暢に吠える方法を知っているだけの犬ではなく、行儀が良く、役立つパートナーになるよう、LLM の犬に追加の訓練を施すようなものです！

## 人間のフィードバックによる強化学習（RLHF）

言語モデルをアラインするための非常に人気のある手法が、**人間のフィードバックによる強化学習（RLHF）** です。RLHF では、人間のフィードバックを RL における「報酬」信号の代理として使います。その仕組みは次のとおりです。

1. **人間の選好を得る：** 人間に、同じ入力プロンプトに対して LLM が生成した異なる応答を比較してもらい、どちらの応答を好むかを教えてもらいます。たとえば、「フランスの首都はどこですか？」という質問に対する2つの異なる答えを人間に見せて、「どちらの答えが優れていますか？」と尋ねます。

2. **報酬モデルを学習する：** この人間の選好データを使って、**報酬モデル**と呼ばれる別のモデルを学習します。この報酬モデルは、人間がどのような応答を好むかを予測することを学びます。役立ち度、無害さ、人間の選好との一致に基づいて応答にスコアを付けることを学びます。

3. **RL で LLM をファインチューニングする：** ここで、報酬モデルを LLM エージェントの環境として使います。LLM は応答（行動）を生成し、報酬モデルがその応答にスコアを付けます（報酬を提供します）。本質的には、（人間の選好から学習した）報酬モデルが良いと考えるテキストを生成するよう LLM を学習させているのです。

![RL の基本概念](https://huggingface.co/reasoning-course/images/resolve/main/grpo/2.jpg)

全体的な観点から、LLM で RL を使う利点を見てみましょう。

| 利点 | 説明 |
|---------|-------------|
| 制御の改善 | RL により、LLM が生成するテキストの種類をより細かく制御できます。役立つ、創造的、簡潔であるといった特定の目標に沿ったテキストを生成するよう導けます。 |
| 人間の価値観とのアライメントの強化 | 特に RLHF は、複雑で主観的な場合が多い人間の選好に LLM を合わせるのに役立ちます。「良い答えとは何か」の規則を書き下すのは難しいですが、人間は応答を簡単に判断し、比較できます。RLHF により、モデルはこれらの人間の判断から学べます。 |
| 望ましくない振る舞いの軽減 | RL は、有毒な言語の生成、誤情報の拡散、偏見の表出といった、LLM の否定的な振る舞いを減らすために使えます。これらの振る舞いにペナルティを与える報酬を設計することで、モデルをそれらを避ける方向に促せます。 |

人間のフィードバックによる強化学習は、OpenAI の GPT-4、Google の Gemini、DeepSeek の R1 など、現在最も人気のある LLM の多くを学習するために使われてきました。RLHF には、複雑さや洗練度が異なる幅広い手法があります。この章では、人間の選好に合った、役立ち、無害な LLM の学習に効果的であることが示されている RLHF の手法、Group Relative Policy Optimization（GRPO）に焦点を当てます。

## GRPO（Group Relative Policy Optimization）を気にかけるべき理由

RLHF には多くの手法がありますが、このコースが GRPO に焦点を当てるのは、GRPO が言語モデルのための強化学習における大きな進歩を表しているためです。

RLHF の他の人気のある手法を2つ簡単に見てみましょう。

- Proximal Policy Optimization（PPO）
- Direct Preference Optimization（DPO）

Proximal Policy Optimization（PPO）は、RLHF において最初期に高い効果を上げた手法の一つです。別の報酬モデルからの報酬に基づいて、方策勾配法を使って方策を更新します。

Direct Preference Optimization（DPO）は後に、選好データを直接使うことで別の報酬モデルを不要にする、よりシンプルな手法として開発されました。本質的には、選ばれた応答と棄却された応答の間の分類タスクとして問題を設定するものです。

> [!TIP]
> DPO と PPO はそれ自体が複雑な強化学習アルゴリズムであり、このコースでは扱いません。もっと詳しく知りたい方は、次のリソースをチェックしてください。
>
> - [Proximal Policy Optimization](https://huggingface.co/docs/trl/main/en/ppo_trainer)
> - [Direct Preference Optimization](https://huggingface.co/docs/trl/main/en/dpo_trainer)

DPO や PPO とは異なり、GRPO は類似したサンプルをグループ化し、グループとして比較します。このグループベースのアプローチは、他の手法と比較して、より安定した勾配と優れた収束特性を提供します。

GRPO は DPO のような選好データを使わず、モデルまたは関数からの報酬信号を使って、類似したサンプルのグループを比較します。

GRPO は報酬信号の取得方法が柔軟で、報酬モデルを使うこともできますが（PPO のように）、厳密には必須ではありません。これは、GRPO が応答の品質を評価できる任意の関数やモデルからの報酬信号を組み込めるためです。

たとえば、長さの関数を使って短い応答に報酬を与えたり、数式ソルバーを使って解の正しさを検証したり、事実の正しさの関数を使って、より事実として正確な応答に報酬を与えたりできます。この柔軟性により、GRPO はさまざまな種類のアライメントタスクに特に汎用的に使えます。
