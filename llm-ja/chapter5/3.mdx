## データを切り分けて加工する[[slicing-and-dicing-our-data]]

🤗 Datasets には、Pandas と同様に、`Dataset` オブジェクトや `DatasetDict` オブジェクトの内容を操作する関数が用意されています。`Dataset.map()` メソッドは [Chapter 3](/course/chapter3) で既に取り上げました。このセクションでは、その他の関数を見ていきます。

この例では、[Drug Review Dataset](https://archive.ics.uci.edu/ml/datasets/Drug+Review+Dataset+%28Drugs.com%29) を使います。[UC Irvine Machine Learning Repository](https://archive.ics.uci.edu/ml/index.php) で公開されているデータセットで、様々な薬に対する患者のレビューと、治療対象の症状、患者の満足度を示す10点満点の星評価が収められています。

まず、データをダウンロードして展開します。`wget` コマンドと `unzip` コマンドを使います。

```py
!wget "https://archive.ics.uci.edu/ml/machine-learning-databases/00462/drugsCom_raw.zip"
!unzip drugsCom_raw.zip
```

TSV は、区切り文字にカンマではなくタブを使う CSV の一種です。その為、`load_dataset()` 関数で `csv` ローディングスクリプトを使い、`delimiter` 引数を指定すれば、これらのファイルを読み込めます。

```py
from datasets import load_dataset

data_files = {"train": "drugsComTrain_raw.tsv", "test": "drugsComTest_raw.tsv"}
# \t は Python におけるタブ文字です
drug_dataset = load_dataset("csv", data_files=data_files, delimiter="\t")
```

データ分析では、まず小さなランダムサンプルを取り出し、扱っているデータがどのようなものかを手早く把握するのが良い方法です。🤗 Datasets では、`Dataset.shuffle()` 関数と `Dataset.select()` 関数をつなげるとランダムサンプルを作れます。

```py
drug_sample = drug_dataset["train"].shuffle(seed=42).select(range(1000))
# 最初の数件のサンプルをのぞいてみます
drug_sample[:3]
```

ここでは再現性の為に、`Dataset.shuffle()` のシードを固定しています。`Dataset.select()` にはインデックスの反復可能オブジェクト（iterable）を渡します。シャッフル後のデータセットから最初の1,000件を取り出す為に、`range(1000)` を渡しています。

このサンプルだけでも、データセットには既にいくつかの癖があることが分かります。

* `Unnamed: 0` 列は、各患者の匿名化された ID のように見えます。
* `condition` 列には、大文字と小文字のラベルが混在しています。
* レビューは長さがまちまちで、改行コード（`\r\n`）や、`&\#039;` のような HTML 文字参照が混ざっています。

これらの問題に 🤗 Datasets でどう対処するかを見ていきます。まず、`Unnamed: 0` 列が患者 ID であるという仮説を検証します。`Dataset.unique()` 関数を使い、ID の数が各分割の行数と一致するかを確認します。

```py
for split in drug_dataset.keys():
    assert len(drug_dataset[split]) == len(drug_dataset[split].unique("Unnamed: 0"))
```

仮説は正しそうです。次に、データセットを少し整えます。`Unnamed: 0` 列の名前を、意味の分かる名前に変えます。`DatasetDict.rename_column()` 関数を使うと、両方の分割の列名を一度に変更出来ます。

```py
drug_dataset = drug_dataset.rename_column(
    original_column_name="Unnamed: 0", new_column_name="patient_id"
)
drug_dataset
```

> [!TIP]
> **やってみよう！** `Dataset.unique()` 関数を使って、訓練セットとテストセットに含まれる薬と症状が、それぞれ何種類あるか調べてみましょう。

次に、`Dataset.map()` を使って `condition` ラベルを正規化します。[Chapter 3](/course/chapter3) でトークナイズを行った時と同様に、`drug_dataset` の各分割の全ての行に適用する単純な関数を定義します。

```py
def lowercase_condition(example):
    return {"condition": example["condition"].lower()}


drug_dataset.map(lowercase_condition)
```

```python out
AttributeError: 'NoneType' object has no attribute 'lower'
```

おっと、`Dataset.map()` で問題が起きました。エラーから、`condition` 列には `None` が含まれていることが分かります。`None` は文字列ではない為、小文字に変換出来ません。そこで、`Dataset.filter()` を使って該当する行を取り除きます。`Dataset.filter()` は `Dataset.map()` と似た関数で、データセットのサンプルを1件受け取る関数を指定します。明示的に書くと、次のようになります。

```py
def filter_nones(x):
    return x["condition"] is not None
```

この関数は `drug_dataset.filter(filter_nones)` として実行出来ますが、ラムダ関数を使えば1行で書けます。ラムダ関数とは、名前を付けずに定義出来る小さな関数です。Python での一般形は次の通りです。

```
lambda <arguments> : <expression>
```

ここで `lambda` は Python の特殊な[キーワード](https://docs.python.org/3/reference/lexical_analysis.html#keywords)の1つです。`<arguments>` は関数が受け取る引数を表し、複数ある場合はカンマで区切って並べます。`<expression>` は実行したい計算や処理を表します。

例えば、数を2乗する単純なラムダ関数は、次のように定義出来ます。

```
lambda x : x * x
```

この関数を入力に適用するには、関数と入力を括弧で囲む必要があります。

```py
(lambda x: x * x)(3)
```

```python out
9
```

同様に、引数をカンマで区切ることで、複数の引数を取るラムダ関数も定義出来ます。例えば、三角形の面積は次のように計算出来ます。

```py
(lambda base, height: 0.5 * base * height)(4, 8)
```

```python out
16.0
```

ラムダ関数は、小さくて一度だけ使う関数を定義する場合に便利です。詳しくは、Andre Burgaud による [Real Python のチュートリアル](https://realpython.com/python-lambda/) が参考になります。🤗 Datasets では、ラムダ関数で `map()` や `filter()` の簡単な処理を定義出来ます。この方法で、データセット内の `None` を取り除きます。

```py
drug_dataset = drug_dataset.filter(lambda x: x["condition"] is not None)
```

`None` エントリが取り除けたので、`condition` 列を正規化出来ます。

```py
drug_dataset = drug_dataset.map(lowercase_condition)
# 小文字化が効いているか確認します
drug_dataset["train"]["condition"][:3]
```

```python out
['left ventricular dysfunction', 'adhd', 'birth control']
```

うまくいきました。ラベルが整いました。次に、レビュー自体を整える方法を見ていきます。

## 新しい列の作成[[creating-new-columns]]

顧客レビューを扱う時は、各レビューの単語数を調べておくのが良い方法です。レビューには \"Great!\" のように1語だけのものもあれば、数千語に及ぶ長文もあります。極端な長さのレビューへの対処は用途によって異なります。各レビューの単語数は、テキストを空白で区切る方法で大まかに数えます。

単語数を数える単純な関数は次の通りです。

```py
def compute_review_length(example):
    return {"review_length": len(example["review"].split())}
```

`lowercase_condition()` 関数とは違い、`compute_review_length()` 関数は、既存の列名には無い `review_length` というキーを持つ辞書を返します。`Dataset.map()` にこの関数を渡すと、データセットの全ての行に適用され、新しい `review_length` 列が作られます。

```py
drug_dataset = drug_dataset.map(compute_review_length)
# 最初の訓練サンプルを確認します
drug_dataset["train"][0]
```


> データセットに新しい列を追加する別の方法として、`Dataset.add_column()` 関数があります。列を Python のリストや NumPy 配列として渡すことが出来、`Dataset.map()` が分析に適さない場面で便利です。

次に、単語数が30未満のレビューを取り除きます。`Dataset.filter()` 関数を使います。`condition` 列の処理と同様に、単語数がしきい値を超えることを条件に指定します。

```py
drug_dataset = drug_dataset.filter(lambda x: x["review_length"] > 30)
```

```py
import html
```

```python
drug_dataset = drug_dataset.map(lambda x: {"review": html.unescape(x["review"])})
```

`Dataset.map()` メソッドはデータ処理にかなり役立ちます。ここまでで触れたのは、その能力のほんの一部です。

## `map()` メソッドのスーパーパワー[[the-map-methods-superpowers]]

`Dataset.map()` メソッドには `batched` 引数があります。`True` に設定すると、複数のサンプルがまとめてマップ関数に渡されます。バッチサイズは変更出来ますが、デフォルトは1,000です。先程の HTML 文字参照を変換する処理には少し時間がかかりました。所要時間は進捗バーで確認出来ます。リスト内包表記で複数の要素をまとめて処理すると、この処理を高速化出来ます。

`batched=True` を指定すると、関数はデータセットのフィールドをキーとする辞書を受け取ります。但し、各値が単一の値ではなく、値のリストになります。戻り値も同じ形にします。更新又は追加するフィールドをキーとし、各値をリストにします。

`batched=True` を使って全ての HTML 文字参照を変換する例は次の通りです。

```python
new_drug_dataset = drug_dataset.map(
    lambda x: {"review": [html.unescape(o) for o in x["review"]]}, batched=True
)
```

このコードをノートブックで実行すると、先程のコードよりもずっと速く終わります。速くなる理由は、レビューの HTML 文字参照が既に変換済みだからではありません。`batched=True` なしで先程のコードを再実行しても、所要時間は殆ど変わりません。リスト内包表記は通常の `for` ループより高速です。更に、要素を1件ずつではなくまとめて扱うことでも効率が上がります。

`Dataset.map()` と `batched=True` の組み合わせは、[Chapter 6](/course/chapter6) で紹介する高速トークナイザ（fast tokenizer）の速さを引き出す上で欠かせません。高速トークナイザは大量のテキストをすばやくトークナイズ出来ます。薬のレビューを全て高速トークナイザで処理する関数は、例えば次の通りです。

```python
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-cased")


def tokenize_function(examples):
    return tokenizer(examples["review"], truncation=True)
```

[Chapter 3](/course/chapter3) で見た通り、トークナイザには1つ又は複数のサンプルを渡せます。その為、この関数は `batched=True` の有無にかかわらず使えます。この機会に、各選択肢の性能を比較します。ノートブックでは、計測したい行の前に `%time` を付けると、1行の実行時間を測れます。

```python no-format
%time tokenized_dataset = drug_dataset.map(tokenize_function, batched=True)
```

セル全体の時間を測る場合は、セルの先頭に `%%time` を置きます。このコードを実行したハードウェアでは、この命令に10.8秒かかりました。「Wall time」の後に表示される数値です。

> [!TIP]
> **やってみよう！** 同じ命令を `batched=True` の有無で実行し、更に低速トークナイザ（`AutoTokenizer.from_pretrained()` メソッドに `use_fast=False` を追加）でも試して、自分のハードウェアでどのような数値が得られるか確認してみましょう。

バッチ処理の有無と、高速トークナイザと低速トークナイザの組み合わせで得られた結果は次の通りです。

オプション         | 高速トークナイザ | 低速トークナイザ
:--------------:|:--------------:|:-------------:
`batched=True`  | 10.8s          | 4min41s
`batched=False` | 59.2s          | 5min3s

つまり、高速トークナイザに `batched=True` を組み合わせると、バッチ処理なしの低速トークナイザより30倍高速です。これが、`AutoTokenizer` で高速トークナイザがデフォルトになっている主な理由であり、「高速」と呼ばれる理由です。裏側ではトークナイズのコードが Rust で実行されます。Rust はコードの実行を並列化し易い言語であり、この高速化はその為に可能になっています。

並列化は、高速トークナイザがバッチ処理でほぼ6倍速くなる理由でもあります。単一のトークナイズ操作は並列化出来ません。多数のテキストを同時にトークナイズする場合は、実行を複数のプロセスに分け、各プロセスが担当分のテキストを処理出来ます。

`Dataset.map()` 自体にも並列化の機能があります。Rust による実装ではない為、低速トークナイザが高速トークナイザに追いつく程にはなりません。それでも役立つ場合があります。特に、高速版が存在しないトークナイザを使う場合です。マルチプロセッシングを使うには、`Dataset.map()` の `num_proc` 引数で使用するプロセス数を指定します。

```py
slow_tokenizer = AutoTokenizer.from_pretrained("bert-base-cased", use_fast=False)


def slow_tokenize_function(examples):
    return slow_tokenizer(examples["review"], truncation=True)


tokenized_dataset = drug_dataset.map(slow_tokenize_function, batched=True, num_proc=8)
```

最適なプロセス数は、時間を測りながら少し実験すると分かります。この検証では8が最も良い結果でした。マルチプロセッシングの有無で得られた数値は次の通りです。

オプション         | 高速トークナイザ | 低速トークナイザ
:--------------:|:--------------:|:-------------:
`batched=True`  | 10.8s          | 4min41s
`batched=False` | 59.2s          | 5min3s
`batched=True`, `num_proc=8`  | 6.52s          | 41.3s
`batched=False`, `num_proc=8` | 9.49s          | 45.2s

低速トークナイザの数値は大幅に改善し、実用的な水準になりました。高速トークナイザの性能も大幅に向上しています。但し、常にそうなるとは限りません。`num_proc` に8以外の値を指定したテストでは、そのオプションなしで `batched=True` を使う方が速い結果でした。一般に、高速トークナイザと `batched=True` の組み合わせでは、Python のマルチプロセッシングは使わない方がよいでしょう。

> [!TIP]
> `num_proc` を使って処理を高速化するのは、通常は良い考えです。但し、使用している関数自体が既に何らかのマルチプロセッシングを行っていない場合に限ります。

1つのメソッドにこれだけの機能が集まっていますが、更にまだあります。`Dataset.map()` と `batched=True` を使うと、データセットの要素数を変更出来ます。1つのサンプルから訓練用の特徴量を複数作る場合など、多くの場面で便利な機能です。[Chapter 7](/course/chapter7) で取り組むいくつかの NLP タスクの前処理でも必要になります。

> [!TIP]
> 機械学習では、サンプル（example）は通常、モデルに入力する特徴量（feature）の集合として定義されます。文脈によっては、これらの特徴量が `Dataset` の列の集合である場合もあれば、（この場合や質問応答のように）1つのサンプルから複数の特徴量が抽出され、1つの列に属する場合もあります。

仕組みは次の通りです。サンプルをトークナイズし、最大長を128にします。但し、最初のチャンクだけではなく、分割で出来た全てのチャンクを返します。その為に `return_overflowing_tokens=True` を指定します。

```py
def tokenize_and_split(examples):
    return tokenizer(
        examples["review"],
        truncation=True,
        max_length=128,
        return_overflowing_tokens=True,
    )
```

データセット全体に `Dataset.map()` を適用する前に、1つのサンプルでテストします。

```py
result = tokenize_and_split(drug_dataset["train"][0])
[len(inp) for inp in result["input_ids"]]
```

```python out
[128, 49]
```

訓練セットの最初のサンプルは、指定した最大トークン数を超えた為、2つの特徴量に分かれました。1つ目の長さは128、2つ目は49です。次に、データセットの全ての要素に同じ処理を適用します。

```py
tokenized_dataset = drug_dataset.map(tokenize_and_split, batched=True)
```

```python out
ArrowInvalid: Column 1 named condition expected length 1463 but got length 1000
```

うまくいきませんでした。エラーメッセージが手掛かりになります。列の長さが一致していません。一方は1,463で、もう一方は1,000です。`Dataset.map()` の[ドキュメント](https://huggingface.co/docs/datasets/package_reference/main_classes#datasets.Dataset.map)にもある通り、関係するのはマップ関数に渡されるサンプルの数です。ここでは1,000件のサンプルから1,463件の新しい特徴量が生成され、形が合わなくなりました。

問題は、大きさの異なる2つのデータセットを混ぜようとしていることです。元のデータセットの列の要素数は1,000件です。一方、構築中の新しいデータセットの要素数は1,463件です。長いレビューが `return_overflowing_tokens=True` によって複数のサンプルに分かれる為です。`Dataset` ではこれは成り立ちません。古いデータセットの列を取り除くか、古い列を新しいデータセットと同じ大きさにする必要があります。取り除く方法は `remove_columns` 引数で指定出来ます。

```py
tokenized_dataset = drug_dataset.map(
    tokenize_and_split, batched=True, remove_columns=drug_dataset["train"].column_names
)
```

今度はエラーなく動作します。長さを比べると、新しいデータセットの要素数が元のデータセットより大幅に増えていることが確認出来ます。

```py
len(tokenized_dataset["train"]), len(drug_dataset["train"])
```

```python out
(206772, 138514)
```

長さが一致しない問題は、古い列を新しい列と同じ大きさにしても解決出来ます。その為には、`return_overflowing_tokens=True` を指定した時にトークナイザが返す `overflow_to_sample_mapping` フィールドを使います。このフィールドは、新しい特徴量のインデックスと、その特徴量の元になったサンプルのインデックスとの対応です。この対応を使い、元のデータセットの各キーを、適切な大きさの値のリストに対応付けます。各サンプルの値は、そのサンプルが生成する新しい特徴量の数だけ繰り返します。

```py
def tokenize_and_split(examples):
    result = tokenizer(
        examples["review"],
        truncation=True,
        max_length=128,
        return_overflowing_tokens=True,
    )
    # 新旧インデックスの対応関係を取り出します
    sample_map = result.pop("overflow_to_sample_mapping")
    for key, values in examples.items():
        result[key] = [values[i] for i in sample_map]
    return result
```

古い列を取り除かなくても、`Dataset.map()` が動作することが分かります。

```py
tokenized_dataset = drug_dataset.map(tokenize_and_split, batched=True)
tokenized_dataset
```

```python out

        num_rows: 206772
    })
    test: Dataset({
        features: ['attention_mask', 'condition', 'date', 'drugName', 'input_ids', 'patient_id', 'rating', 'review', 'review_length', 'token_type_ids', 'usefulCount'],
```

訓練用の特徴量の数は前と同じですが、ここでは元のフィールドを全て保持しています。モデルを適用した後の後処理でこれらのフィールドが必要な場合は、この方法が向いています。

## 検証セットの作成[[creating-a-validation-set]]

評価に使えるテストセットは既にあります。但し、開発中はテストセットには触れず、別に検証セットを作るのが良い方法です。検証セットでのモデルの性能に満足出来たら、テストセットで最終的な確認をします。この進め方により、テストセットに過学習し、実際のデータでは失敗するモデルをデプロイ（展開）してしまう危険を減らせます。

🤗 Datasets には、`scikit-learn` でよく知られた機能に基づく `Dataset.train_test_split()` 関数があります。これを使って、訓練セットを `train` と `validation` の2つに分割します。再現性の為、`seed` 引数を設定します。

```py
drug_dataset_clean = drug_dataset["train"].train_test_split(train_size=0.8, seed=42)
# デフォルトの "test" 分割の名前を "validation" に変更します
drug_dataset_clean["validation"] = drug_dataset_clean.pop("test")
# `DatasetDict` に "test" セットを追加します
drug_dataset_clean["test"] = drug_dataset["test"]
drug_dataset_clean
```

## データセットの保存[[saving-a-dataset]]

<Youtube id="blF9uxYcKHo"/>

🤗 Datasets は、ダウンロードしたデータセットと、それに対して行った操作を全てキャッシュします。但し、データセットをディスクに保存したい場合もあります。キャッシュが削除される場合などです。下の表の通り、🤗 Datasets にはデータセットを異なる形式で保存する主な関数が3つあります。

| データ形式 |        関数        |
| :---------: | :--------------------: |
|    Arrow    | `Dataset.save_to_disk()` |
|     CSV     |    `Dataset.to_csv()`    |
|    JSON     |   `Dataset.to_json()`    |

例として、整えたデータセットを Arrow 形式で保存します。

```py
drug_dataset_clean.save_to_disk("drug-reviews")
```

これにより、次のような構造のディレクトリが作られます。

```
drug-reviews/
├── dataset_dict.json
├── test
│   ├── dataset.arrow
│   ├── dataset_info.json
│   └── state.json
├── train
│   ├── dataset.arrow
│   ├── dataset_info.json
│   ├── indices.arrow
│   └── state.json
└── validation
    ├── dataset.arrow
    ├── dataset_info.json
    ├── indices.arrow
    └── state.json
```

各分割には、それぞれ専用の *dataset.arrow* テーブルと、*dataset_info.json* と *state.json* のメタデータが対応しています。Arrow 形式は、列と行からなる派手な表と捉えると分かり易いでしょう。大規模なデータセットを処理し、転送する高性能なアプリケーションの構築に最適化されています。
