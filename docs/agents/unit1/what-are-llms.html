LLM とは何か？

前のセクションでは、各エージェントには 中核となる AI モデル が必要であり、LLM がこの目的で最も一般的な AI モデルのタイプであることを学びました。

ここでは、LLM とは何か、そして LLM がエージェントをどう動かしているかを学びます。

このセクションでは、LLM の使い方について簡潔な技術的説明を提供します。さらに深く掘り下げたい場合は、無料の自然言語処理コース をご覧ください。

大規模言語モデルとは何か？

LLM は、人間の言語を理解し生成すること に長けた AI モデルの一種です。膨大な量のテキストデータで訓練されており、言語のパターン、構造、さらにはニュアンスまで学ぶことができます。これらのモデルは通常、数百万規模のパラメータで構成されます。

今日の LLM のほとんどは、Transformer アーキテクチャ上に構築されて います。これは "Attention" アルゴリズムに基づく深層学習アーキテクチャで、2018 年に Google から BERT が発表されて以来、大きな注目を集めています。

Transformer には3つのタイプがあります。

  1. エンコーダ（Encoders）
    エンコーダベースの Transformer は、テキスト（またはその他のデータ）を入力として受け取り、そのテキストの密な表現（埋め込み）を出力します。
  • 例: Google の BERT
  • ユースケース: テキスト分類、セマンティック検索、固有表現認識
  • 典型的なサイズ: 数百万のパラメータ
  1. デコーダ（Decoders）
    デコーダベースの Transformer は、シーケンスを完成させるために、トークンを1つずつ新しいトークンとして生成すること に焦点を当てます。
  • 例: Meta の Llama
  • ユースケース: テキスト生成、チャットボット、コード生成
  • 典型的なサイズ: 数十億（10^9）のパラメータ
  1. Seq2Seq（エンコーダ–デコーダ）
    シーケンス・ツー・シーケンスの Transformer は、エンコーダとデコーダを 組み合わせた ものです。エンコーダがまず入力シーケンスをコンテキスト表現に処理し、次にデコーダが出力シーケンスを生成します。
  • 例: T5、BART
  • ユースケース: 翻訳、要約、パラフレーズ
  • 典型的なサイズ: 数百万のパラメータ

大規模言語モデルにはさまざまな形式がありますが、LLM は通常、数十億のパラメータを持つデコーダベースのモデルです。よく知られた LLM をいくつか挙げます。

モデル 提供元
Deepseek-R1 DeepSeek
GPT4 OpenAI
Llama 3 Meta (Facebook AI Research)
SmolLM2 Hugging Face
Gemma Google
Mistral Mistral

LLM の根底にある原理はシンプルでありながら非常に効果的です。その目的は、前のトークンのシーケンスが与えられたときに、次のトークンを予測すること です。「トークン」は LLM が扱う情報の単位です。「トークン」は「単語」のようなものと考えることができますが、効率上の理由から LLM は単語全体を使いません。

たとえば、英語には推定60万語の単語がありますが、LLM の語彙は約32,000トークン程度かもしれません（Llama 2 がその例です）。トークン化は、組み合わせ可能なサブワード単位で行われることがよくあります。

たとえば、トークン "interest" と "ing" を組み合わせて "interesting" を作ったり、"ed" を追加して "interested" を作ったりできることを考えてみてください。

下のインタラクティブなプレイグラウンドで、さまざまなトークナイザを試すことができます。

各 LLM には、モデル固有の 特殊トークン があります。LLM はこれらのトークンを使って、生成の構造化されたコンポーネントを開始・終了します。たとえば、シーケンス、メッセージ、応答の開始や終了を示します。さらに、モデルに渡す入力プロンプトも特殊トークンで構造化されています。その中で最も重要なのが シーケンス終了トークン（End of sequence token、EOS） です。

特殊トークンの形式は、モデル提供元によって大きく異なります。

下の表は、特殊トークンの多様性を示しています。

モデル（Model） 提供元（Provider） EOS トークン（EOS Token） 機能（Functionality）
GPT4 OpenAI <|endoftext|> メッセージ本文の終了
Llama 3 Meta (Facebook AI Research) <|eot_id|> シーケンスの終了
Deepseek-R1 DeepSeek <｜end▁of▁sentence｜> メッセージ本文の終了
SmolLM2 Hugging Face <|im_end|> 指示またはメッセージの終了
Gemma Google <end_of_turn> 会話ターンの終了

💡 ヒント

これらの特殊トークンを暗記する必要はありませんが、その多様性と、LLM のテキスト生成において果たす役割を理解することが重要です。特殊トークンについてさらに知りたい場合は、モデルの Hub リポジトリでその設定を確認できます。たとえば、SmolLM2 モデルの特殊トークンは、その tokenizer_config.json で確認できます。

次トークン予測を理解する

LLM は 自己回帰的（autoregressive） であると言われます。これは、1回の処理の出力が次の処理の入力になる ことを意味します。このループは、モデルが次のトークンを EOS トークンと予測するまで続き、その時点でモデルは停止できます。

言い換えれば、LLM は EOS に到達するまでテキストをデコードします。では、1回のデコーディングループでは何が起こるのでしょうか？

エージェントを学ぶ目的では全体のプロセスはかなり技術的になり得るので、ここでは簡単な概要を示します。

  • 入力テキストが トークン化 されると、モデルは、入力シーケンス内の各トークンの意味と位置についての情報を捉えたシーケンスの表現を計算します。
  • この表現がモデルに入力され、モデルは、語彙内の各トークンがシーケンスの次のトークンになる尤度をランク付けするスコアを出力します。

これらのスコアに基づいて、文を完成させるトークンを選択する戦略が複数あります。

  • 最も簡単なデコーディング戦略は、常に最大スコアのトークンを取ることです。

この Space で SmolLM2 を使って、デコーディングプロセスを自分で操作できます（このモデルでは、EOS トークンである <|im_end|> に到達するまでデコードすることを覚えておいてください）。

  • しかし、より高度なデコーディング戦略もあります。たとえば、beam search は複数の候補シーケンスを探索し、個々のトークンのスコアが低くても、合計スコアが最大になるものを見つけます。

デコーディングについてさらに知りたい場合は、NLP コース をご覧ください。

Attention is all you need（必要なのはアテンションだけ）

Transformer アーキテクチャの重要な側面は Attention（アテンション） です。次の単語を予測する際、文中のすべての単語が等しく重要なわけではありません。"The capital of France is ..." という文では、"France" や "capital" のような単語が最も大きな意味を持ちます。

次のトークンを予測するために最も関連性の高い単語を特定するこのプロセスは、非常に効果的であることが証明されています。

LLM の基本原理である「次のトークンを予測する」ことは GPT-2 以来一貫していますが、ニューラルネットワークのスケーリングや、ますます長いシーケンスでアテンション機構を機能させる点では、大きな進歩がありました。

LLM とやり取りしたことがあれば、context length（コンテキスト長） という用語に馴染みがあるでしょう。これは、LLM が処理できるトークンの最大数と、その最大の attention span（注意の範囲） を指します。

LLM へのプロンプトが重要である

LLM の唯一の仕事は、すべての入力トークンを見て次のトークンを予測し、どのトークンが「重要」かを選ぶことであることを考えると、入力シーケンスの文言は非常に重要です。

LLM に提供する入力シーケンスは プロンプト と呼ばれます。プロンプトを注意深く設計することで、LLM の生成を望ましい出力へと導きやすく なります。

LLM はどう訓練されるのか？

LLM は大規模なテキストデータセットで訓練され、自己教師あり学習またはマスク言語モデリングの目的を通じて、シーケンス内の次の単語を予測することを学びます。

この教師なし学習から、モデルは言語の構造と テキストの根底にあるパターンを学び、未知のデータへ汎化できるように なります。

この最初の 事前学習（pre-training） のあと、LLM は教師あり学習の目的でファインチューニングされ、特定のタスクを実行できます。たとえば、会話構造やツールの使用に向けて訓練されるモデルもあれば、分類やコード生成に焦点を当てるモデルもあります。

LLM はどう使えるのか？

主に2つの選択肢があります。

  1. ローカルで実行する（十分なハードウェアがある場合）。

  2. クラウド/API を使う（例: Hugging Face Serverless Inference API 経由）。

このコースを通じて、主に Hugging Face Hub 上の API 経由でモデルを使います。後ほど、自分のハードウェア上でこれらのモデルをローカルで実行する方法も探ります。

LLM は AI エージェントでどう使われるのか？

LLM は AI エージェントの重要なコンポーネントであり、人間の言語を理解し生成するための基盤を提供します。

ユーザーの指示を解釈し、会話のコンテキストを維持し、計画を定義し、使うツールを決めることができます。

これらのステップはこのユニットでさらに詳しく探りますが、今のところ理解すべきなのは、LLM が エージェントの頭脳 であるということです。
