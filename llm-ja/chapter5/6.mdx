## 埋め込みを用いたセマンティック検索[[using-embeddings-for-semantic-search]]

[第1章](/course/chapter1) で見たように、Transformer ベースの言語モデルは、テキストの各トークンを *埋め込みベクトル* で表します。個々の埋め込みをプーリング（集約）すると、文や段落を1つのベクトルで表せます。場合によっては、ドキュメント全体も同様に表せます。類似したドキュメントの検索は、この埋め込みを使います。クエリの埋め込みとコーパス内の各ドキュメントの埋め込みについて、内積による類似度（又は別の類似度指標）を計算し、値の大きいドキュメントを返します。

このセクションで作るのは、埋め込みを使うセマンティック検索エンジンです。セマンティック検索には、従来の方法に比べていくつかの利点があります。従来の方法は、クエリに含まれるキーワードとドキュメントを照合する方式です。

## データセットの読み込みと準備[[loading-and-preparing-the-dataset]]

まず、GitHub の issue をまとめたデータセットをダウンロードします。いつものように `load_dataset()` 関数を使います。

```py
from datasets import load_dataset

issues_dataset = load_dataset("lewtun/github-issues", split="train")
issues_dataset
```


ここでは `load_dataset()` で既定の `train` 分割を指定しています。その為、戻り値は `DatasetDict` ではなく `Dataset` です。最初に行うのは、プルリクエストの除外です。プルリクエストはユーザーの質問への回答にはあまり使われず、検索結果にノイズを混ぜる原因にもなります。除外には、これまでも使った `Dataset.filter()` 関数を使います。併せて、コメントのない行も除外します。コメントがなければ、ユーザーの質問への答えは得られない為です。

```py
issues_dataset = issues_dataset.filter(
    lambda x: (x["is_pull_request"] == False and len(x["comments"]) > 0)
)
issues_dataset
```


```py
columns = issues_dataset.column_names

```

```py
def concatenate_text(examples):
```

## テキスト埋め込みの作成[[creating-text-embeddings]]

[第2章](/course/chapter2) で見たように、トークン埋め込みは `AutoModel` クラスで取得出来ます。必要なのは、モデルの読み込みに使う適切なチェックポイントの選択だけです。

埋め込みの作成に特化したライブラリとして、`sentence-transformers` があります。このライブラリの[ドキュメント](https://www.sbert.net/examples/applications/semantic-search/README.html#symmetric-vs-asymmetric-semantic-search)によると、短いクエリの答えを issue のコメントのような比較的長いドキュメントから探す処理は、*非対称セマンティック検索* に当たります。チェックポイントは、ドキュメント内の[モデル概要表](https://www.sbert.net/docs/pretrained_models.html#model-overview)でセマンティック検索の性能が最も高いとされる `multi-qa-mpnet-base-dot-v1` を使います。トークナイザも、同じチェックポイントから読み込みます。

{#if fw === 'pt'}

```py
from transformers import AutoTokenizer, AutoModel

model_ckpt = "sentence-transformers/multi-qa-mpnet-base-dot-v1"
tokenizer = AutoTokenizer.from_pretrained(model_ckpt)
model = AutoModel.from_pretrained(model_ckpt)
```

埋め込みの計算を高速化する為、モデルと入力を GPU に置きます。ここで準備しておきます。

```py
import torch

device = torch.device("cuda")
model.to(device)
```

{:else}

```py
from transformers import AutoTokenizer, TFAutoModel

model_ckpt = "sentence-transformers/multi-qa-mpnet-base-dot-v1"
tokenizer = AutoTokenizer.from_pretrained(model_ckpt)
model = TFAutoModel.from_pretrained(model_ckpt, from_pt=True)
```

`from_pretrained()` メソッドの引数に `from_pt=True` を設定している点に注目してください。理由は、`multi-qa-mpnet-base-dot-v1` チェックポイントに PyTorch の重みしか無い為です。`from_pt=True` を設定すると、TensorFlow 形式への変換が自動で行われます。このように、Transformers ではフレームワーク間の切り替えが非常に簡単です。

{/if}

前に述べた通り、GitHub の issue から作ったコーパスの各エントリは、1つのベクトルで表す必要があります。その為には、トークン埋め込みを何らかの方法でプーリングします。平均化も方法の1つです。よく使われる方法の1つが、モデルの出力に対する *CLS プーリング* です。これは、特殊トークン `[CLS]` に対応する最終隠れ状態を取り出す方法です。次の関数で実装出来ます。

```py
def cls_pooling(model_output):
    return model_output.last_hidden_state[:, 0]
```

次に、ヘルパー関数を作成します。この関数は、ドキュメントのリストをトークナイズし、テンソルを GPU に配置してモデルに入力し、最後に出力へ CLS プーリングを適用します。

{#if fw === 'pt'}

```py
def get_embeddings(text_list):
    encoded_input = tokenizer(
        text_list, padding=True, truncation=True, return_tensors="pt"
    )
    encoded_input = {k: v.to(device) for k, v in encoded_input.items()}
    model_output = model(**encoded_input)
    return cls_pooling(model_output)
```

関数が正しく動くか、コーパスの最初のテキストを渡して確認します。出力の形状も併せて確認します。

```py
embedding = get_embeddings(comments_dataset["text"][0])

```

## FAISS による効率的な類似検索[[using-faiss-for-efficient-similarity-search]]

埋め込みベクトルのデータセットが出来ました。次に必要なのは、その中から似たベクトルを探す仕組みです。ここでは、Datasets で利用出来る *FAISS インデックス* というデータ構造を使います。[FAISS](https://faiss.ai/)（Facebook AI Similarity Search の略）は、埋め込みベクトルの高速な検索とクラスタリングの為のアルゴリズムを提供するライブラリです。

FAISS の基本的な考え方は、インデックスと呼ばれる特殊なデータ構造を作ることです。インデックスがあれば、入力した埋め込みに類似する埋め込みを探せます。Datasets での作成は簡単です。`Dataset.add_faiss_index()` 関数を使い、インデックス化する列を指定します。

```py
embeddings_dataset.add_faiss_index(column="embeddings")
```

これで、`Dataset.get_nearest_examples()` 関数による最近傍検索が出来るようになりました。インデックスから近いベクトルを探す検索です。まず、質問文を埋め込みベクトルに変換して試します。

{#if fw === 'pt'}

```py
question = "How can I load a dataset offline?"
question_embedding = get_embeddings([question]).cpu().detach().numpy()
question_embedding.shape
```

```python out
torch.Size([1, 768])
```

{:else}

```py
question = "How can I load a dataset offline?"
question_embedding = get_embeddings([question]).numpy()
question_embedding.shape
```


ドキュメントと同様に、クエリも768次元のベクトルで表せました。このベクトルをコーパス全体と比較すれば、最も類似する埋め込みが見つかります。

```py
scores, samples = embeddings_dataset.get_nearest_examples(
    "embeddings", question_embedding, k=5
)
```

`Dataset.get_nearest_examples()` 関数の戻り値は組です。クエリと各ドキュメントの類似度を示すスコアと、対応するサンプルです。ここでのサンプルは、類似度が高い上位5件です。これらを `pandas.DataFrame` にまとめると、並べ替えが簡単になります。

```py
import pandas as pd

samples_df = pd.DataFrame.from_dict(samples)
samples_df["scores"] = scores

```

1. (online machine)
\`\`\`
import datasets

data.save_to_disk(/YOUR/DATASET/DIR)
\`\`\`
2. copy the dir from online to the offline machine
3. (offline machine)
\`\`\`
import datasets
data = datasets.load_from_disk(/SAVED/DATA/DIR)
