## Transformer はあらゆる所に！[[transformers-are-everywhere]]

Transformer モデルは、自然言語処理（NLP）、コンピュータビジョン、音声処理など、様々なモダリティの幅広いタスクを解く為に使われています。Hugging Face と Transformer モデルを活用する企業・組織の中には、自社のモデルを公開してコミュニティに貢献している所もあります。例えば、次の企業・組織です。

<img src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter1/companies.PNG" alt="Hugging Face を利用している企業" width="100%">

[Transformers ライブラリ](https://github.com/huggingface/transformers)は、そうした共有モデルを作成し、利用する為の機能を提供します。[Model Hub](https://huggingface.co/models)には、誰でもダウンロードして使える数百万もの事前学習済みモデルが集まっています。自分のモデルを Hub にアップロードすることも出来ます。

> [!TIP]
> ⚠️ Hugging Face Hub は Transformer モデルだけに限られません。誰でも、好きな種類のモデルやデータセットを共有出来ます。全ての機能を使うには、<a href="https://huggingface.co/join">huggingface.co アカウントを作成</a>しましょう！

Transformer モデルの内部の仕組みに入る前に、興味深い NLP の問題を解く為にどう使えるのか、いくつか例を見てみましょう。

## パイプラインを使う[[working-with-pipelines]]

<Youtube id="tiZFewofSLM" />

Transformers ライブラリで最も基本的なオブジェクトが `pipeline()` 関数です。モデルと必要な前処理・後処理のステップをつなぐことで、任意のテキストを直接入力して、分かり易い答えを得ることが出来ます。

```python
from transformers import pipeline

classifier = pipeline("sentiment-analysis")
classifier("I've been waiting for a HuggingFace course my whole life.")
```

（入力文の訳：ずっと Hugging Face のコースを待ち望んでいました）

```python out
[{'label': 'POSITIVE', 'score': 0.9598047137260437}]
```

複数の文を渡すことも出来ます。

```python
classifier(
    ["I've been waiting for a HuggingFace course my whole life.", "I hate this so much!"]
)
```

（追加された文の訳：これは本当に大嫌いです！）

```python out
[{'label': 'POSITIVE', 'score': 0.9598047137260437},
 {'label': 'NEGATIVE', 'score': 0.9994558095932007}]
```

デフォルトでは、このパイプラインは英語の感情分析向けにファインチューニングされた特定の事前学習済みモデルを選択します。モデルは `classifier` オブジェクトを作成する時にダウンロードされ、キャッシュされます。コマンドを再実行すると、代わりにキャッシュされたモデルが使われるので、モデルを改めてダウンロードする必要はありません。

テキストをパイプラインに渡す時には、主に3つのステップがあります。

1. テキストが、モデルが理解出来る形式に前処理されます。
2. 前処理された入力がモデルに渡されます。
3. モデルの予測結果を後処理し、人間が解釈し易い形式に変換します。

## 様々なモダリティで利用出来るパイプライン

`pipeline()` 関数は複数のモダリティに対応しており、テキスト、画像、音声、更にはマルチモーダルなタスクにも使えます。このコースではテキストのタスクに焦点を当てますが、Transformer アーキテクチャの可能性を理解する上で役立つので、ここではその概要を簡単に紹介します。

利用出来るものの一覧は次の通りです。

> [!TIP]
> パイプラインの完全で最新のリストは、[Transformers ドキュメント](https://huggingface.co/docs/hub/en/models-tasks)を参照してください。

### テキストパイプライン

- `text-generation`：プロンプトからテキストを生成する
- `text-classification`：テキストを予め定義したカテゴリに分類する
- `summarization`：重要な情報を保ちながら、テキストをより短い文にまとめる
- `translation`：テキストを或る言語から別の言語に翻訳する
- `zero-shot-classification`：特定のラベルで事前に学習することなく、テキストを分類する
- `feature-extraction`：テキストのベクトル表現を抽出する

### 画像パイプライン

- `image-to-text`：画像のテキストによる説明を生成する
- `image-classification`：画像の中の物体を識別する
- `object-detection`：画像の中の物体の位置を特定し、識別する

### 音声パイプライン

- `automatic-speech-recognition`：音声をテキストに変換する
- `audio-classification`：音声をカテゴリに分類する
- `text-to-speech`：テキストを音声に変換する

### マルチモーダルパイプライン

- `image-text-to-text`：テキストプロンプトに基づいて画像に応答する

これらのパイプラインのいくつかを、もう少し詳しく見ていきましょう！

## ゼロショット分類[[zero-shot-classification]]

まずは、ラベルの付いていないテキストを分類する、少し難しいタスクに取り組みます。実際のプロジェクトでも、ラベルの付いていないテキストを扱うことは珍しくありません。ラベル付けには時間が掛かり、専門知識も必要だからです。

この用途には `zero-shot-classification` パイプラインが非常に強力です。使用するラベルを自分で指定出来るので、事前学習済みモデルのラベルに頼る必要がありません。モデルが文を positive と negative の2つのラベルを使って分類出来ることは既に見ましたが、それ以外の任意のラベルの集合を使ってテキストを分類することも出来ます。

```python
from transformers import pipeline

classifier = pipeline("zero-shot-classification")
classifier(
    "This is a course about the Transformers library",
    candidate_labels=["education", "politics", "business"],
)
```

（入力文の訳：これは Transformers ライブラリについてのコースです。候補ラベルは「教育」「政治」「ビジネス」です）

```python out
{'sequence': 'This is a course about the Transformers library',
 'labels': ['education', 'business', 'politics'],
 'scores': [0.8445963859558105, 0.111976258456707, 0.043427448719739914]}
```

このパイプラインが _ゼロショット_ と呼ばれるのは、使う為に自分のデータでモデルをファインチューニングする必要が無いからです。希望するラベルのリストに対して、確率スコアを直接返すことが出来ます。

> [!TIP]
> **試してみましょう！** 自分で用意した文とラベルで色々試して、モデルがどう振る舞うか確認してみてください。

## テキスト生成[[text-generation]]

次に、パイプラインを使ってテキストを生成する方法を見てみましょう。基本的な考え方は、プロンプトを与えると、モデルが続きのテキストを生成して自動で補完するというものです。これは、多くのスマートフォンに在る予測変換の機能に似ています。

テキスト生成にはランダム性が含まれるので、下に示す結果とまったく同じ結果が得られなくても普通のことです。

```python
from transformers import pipeline

generator = pipeline("text-generation")
generator("In this course, we will teach you how to")
```

（プロンプトの訳：「このコースでは、〜の方法を教えます」という文の途中までです）

```python out
[{'generated_text': 'In this course, we will teach you how to understand and use '
                    'data flow and data interchange when handling user data. We '
                    'will be working with one or more of the most commonly used '
                    'data flows — data flows of various types, as seen by the '
                    'HTTP'}]
```

（出力の訳：このコースでは、ユーザーデータを扱う時のデータフローとデータ交換を理解し、使う方法を教えます。最もよく使われるデータフローの1つ以上を扱います。HTTP から見た、様々な種類のデータフローです）

生成されるシーケンスの数は `num_return_sequences` 引数で、出力テキストの全体の長さは `max_length` 引数で制御出来ます。

> [!TIP]
> **試してみましょう！** `num_return_sequences` と `max_length` 引数を使って、それぞれ15ワードからなる文を2つ生成してみてください。

## Hub の任意のモデルをパイプラインで使う[[using-any-model-from-the-hub-in-a-pipeline]]

これまでの例では、タスクごとに用意されたデフォルトモデルを使いました。Hub から好きなモデルを選び、パイプラインで使うことも出来ます。例えばテキスト生成です。

[Model Hub](https://huggingface.co/models)に移動し、左側の対応するタグをクリックすると、そのタスクでサポートされるモデルだけが表示されます。[こちらのページ](https://huggingface.co/models?pipeline_tag=text-generation)のようなページが表示されるはずです。

[`HuggingFaceTB/SmolLM2-360M`](https://huggingface.co/HuggingFaceTB/SmolLM2-360M)モデルを試してみましょう！前と同じパイプラインに読み込む方法は次の通りです。

```python
from transformers import pipeline

generator = pipeline("text-generation", model="HuggingFaceTB/SmolLM2-360M")
generator(
    "In this course, we will teach you how to",
    max_length=30,
    num_return_sequences=2,
)
```

（プロンプトの訳は、前のテキスト生成の例と同じです）

```python out
[{'generated_text': 'In this course, we will teach you how to manipulate the world and '
                    'move your mental and physical capabilities to your advantage.'},
 {'generated_text': 'In this course, we will teach you how to become an expert and '
                    'practice realtime, and with a hands on experience on both real '
                    'time and real'}]
```

（出力の訳：1つ目は「このコースでは、世界を操り、精神的・身体的な能力を自分に有利なように動かす方法を教えます」。2つ目は「このコースでは、専門家になり、リアルタイムで実践する方法を、実地体験と共に教えます。リアルタイムと実際の……」です）

言語のタグをクリックするとモデル検索を絞り込むことができ、別の言語でテキストを生成するモデルを選ぶことも出来ます。Model Hub には、複数の言語に対応した多言語モデルのチェックポイントもあります。

モデルをクリックして選択すると、オンラインで直接試せるウィジェットが表示されます。これにより、ダウンロードする前にモデルの能力をすばやく試すことが出来ます。

> [!TIP]
> **試してみましょう！** フィルターを使って、別の言語向けのテキスト生成モデルを探してみてください。ウィジェットで自由に試して、パイプラインで使ってみましょう！

### Inference Providers[[inference-providers]]

Hugging Face の[ウェブサイト](https://huggingface.co/docs/inference-providers/en/index)では、Inference Providers を通じてモデルをブラウザ上で直接試せます。任意のテキストを入力し、モデルがどのように処理するかをその場で確認出来ます。

ウィジェットの動作を支える Inference Providers は、有料サービスとしても利用出来ます。自分のアプリケーションや作業の流れにモデルの推論機能を組み込みたい時に役立ちます。詳しくは[料金ページ](https://huggingface.co/docs/inference-providers/en/pricing)を参照してください。

## マスク補完[[mask-filling]]

次に試すパイプラインは `fill-mask` です。このタスクの考え方は、与えられたテキストの空白を埋めることです。

```python
from transformers import pipeline

unmasker = pipeline("fill-mask")
unmasker("This course will teach you all about <mask> models.", top_k=2)
```

（入力文の訳：このコースでは <mask> モデルについて全てを学べます）

```python out
[{'sequence': 'This course will teach you all about mathematical models.',
  'score': 0.19619831442832947,
  'token': 30412,
  'token_str': ' mathematical'},
 {'sequence': 'This course will teach you all about computational models.',
  'score': 0.04052725434303284,
  'token': 38163,
  'token_str': ' computational'}]
```

（出力の訳：補完された文は「このコースでは数学的モデルについて全てを学べます」と「このコースでは計算的モデルについて全てを学べます」です）

`top_k` 引数は、表示したい候補の数を制御します。

ここでモデルが補完しているのは特殊な単語 `<mask>` で、これはしばしば *マスクトークン* と呼ばれます。モデルによってマスクトークンが異なる場合が有る為、別のモデルを使う際は、どのトークンを使うか確認しましょう。モデルのウィジェットでも確認出来ます。

> [!TIP]
> **試してみましょう！** Hub で `bert-base-cased` モデルを検索し、Inference API ウィジェットでそのマスクトークンを確認してください。このモデルは、上記の `pipeline` の例の文に対して何を予測するでしょうか？

## 固有表現認識[[named-entity-recognition]]

固有表現認識（NER）は、入力テキストのどの部分が人物、場所、組織といったエンティティに対応するかを、モデルが見つけ出すタスクです。例を見てみましょう。

```python
from transformers import pipeline

ner = pipeline("ner", aggregation_strategy="simple")
ner("My name is Sylvain and I work at Hugging Face in Brooklyn.")
```

（入力文の訳：私の名前は Sylvain で、ブルックリンの Hugging Face で働いています）

```python out
[{'entity_group': 'PER', 'score': 0.99816, 'word': 'Sylvain', 'start': 11, 'end': 18}, 
 {'entity_group': 'ORG', 'score': 0.97960, 'word': 'Hugging Face', 'start': 33, 'end': 45}, 
 {'entity_group': 'LOC', 'score': 0.99321, 'word': 'Brooklyn', 'start': 49, 'end': 57}
]
```

ここではモデルは、Sylvain が人物（PER）、Hugging Face が組織（ORG）、Brooklyn が場所（LOC）であることを正しく識別しました。

パイプライン作成関数に `aggregation_strategy="simple"` オプションを渡すと、文の中で同じエンティティに対応する部分同士をまとめるよう、パイプラインに指示出来ます。ここではモデルは、名前が複数の単語から構成されているにもかかわらず、"Hugging" と "Face" を1つの組織として正しくまとめました。

実際、次の章で分かるように、前処理では単語が更に小さい部分に分割されることさえあります。例えば `Sylvain` は、`S`、`##yl`、`##va`、`##in` の4つのピースに分割されます。後処理のステップでは、パイプラインはこれらのピースをきれいにまとめ直しました。

> [!TIP]
> **試してみましょう！** 英語の品詞タグ付け（通常 POS と略されます）が出来るモデルを Model Hub で検索してください。このモデルは、上記の例の文に対して何を予測するでしょうか？

## 質問応答[[question-answering]]

`question-answering` パイプラインは、与えられたコンテキストの情報を使って質問に答えます。

```python
from transformers import pipeline

question_answerer = pipeline("question-answering")
question_answerer(
    question="Where do I work?",
    context="My name is Sylvain and I work at Hugging Face in Brooklyn",
)
```

（質問の訳：私はどこで働いていますか？コンテキストの文の訳は、固有表現認識の例と同じです）

```python out
{'score': 0.6385916471481323, 'start': 33, 'end': 45, 'answer': 'Hugging Face'}
```

このパイプラインは、与えられたコンテキストから情報を抽出することで動作しており、答えを生成している訳ではない点に注意してください。

## 要約[[summarization]]

要約とは、原文に含まれる重要な情報を出来る限り残しながら、文章を短くまとめるタスクです。例を示します。

```python
from transformers import pipeline

summarizer = pipeline("summarization")
summarizer(
    """
    America has changed dramatically during recent years. Not only has the number of 
    graduates in traditional engineering disciplines such as mechanical, civil, 
    electrical, chemical, and aeronautical engineering declined, but in most of 
    the premier American universities engineering curricula now concentrate on 
    and encourage largely the study of engineering science. As a result, there 
    are declining offerings in engineering subjects dealing with infrastructure, 
    the environment, and related issues, and greater concentration on high 
    technology subjects, largely supporting increasingly complex scientific 
    developments. While the latter is important, it should not be at the expense 
    of more traditional engineering.

    Rapidly developing economies such as China and India, as well as other 
    industrial countries in Europe and Asia, continue to encourage and advance 
    the teaching of engineering. Both China and India, respectively, graduate 
    six and eight times as many traditional engineers as does the United States. 
    Other industrial countries at minimum maintain their output, while America 
    suffers an increasingly serious decline in the number of engineering graduates 
    and a lack of well-educated engineers.
"""
)
```

（入力文の訳）

アメリカは近年、劇的に変化しました。機械、土木、電気、化学、航空といった伝統的な工学分野の卒業生の数が減っただけでなく、アメリカの主要大学の多くでは、工学カリキュラムが工学科学（エンジニアリングサイエンス）の学習に重点を置き、それを推奨するようになりました。その結果、インフラや環境、それらに関連する問題を扱う工学科目の開講は減り、ますます複雑になる科学の発展を支えるハイテク分野への集中が進んでいます。後者も重要ですが、より伝統的な工学を犠牲にしてよい訳ではありません。

中国やインドのような急速に発展する経済圏や、ヨーロッパやアジアの他の工業国は、工学教育を推奨し、発展させ続けています。中国とインドはそれぞれ、アメリカの6倍と8倍の数の伝統的工学の卒業生を輩出しています。他の工業国は少なくとも現在の水準を維持している一方で、アメリカは工学卒業生の数の深刻な減少と、十分な教育を受けた技術者の不足に苦しんでいます。

```python out
[{'summary_text': ' America has changed dramatically during recent years . The '
                  'number of engineering graduates in the U.S. has declined in '
                  'traditional engineering disciplines such as mechanical, civil '
                  ', electrical, chemical, and aeronautical engineering . Rapidly '
                  'developing economies such as China and India, as well as other '
                  'industrial countries in Europe and Asia, continue to encourage '
                  'and advance engineering .'}]
```

（出力の訳）

アメリカは近年、劇的に変化しました。アメリカでは、機械、土木、電気、化学、航空といった伝統的な工学分野の卒業生の数が減少しています。中国やインドのような急速に発展する経済圏や、ヨーロッパやアジアの他の工業国は、工学を推奨し、発展させ続けています。

テキスト生成と同様に、結果に対して `max_length` や `min_length` を指定出来ます。

## 翻訳[[translation]]

翻訳では、タスク名に言語ペアを指定すれば（`"translation_en_to_fr"` のように）デフォルトモデルを使うことも出来ますが、最も簡単な方法は、[Model Hub](https://huggingface.co/models)で使いたいモデルを選ぶことです。ここでは、フランス語から英語への翻訳を試してみます。

```python
from transformers import pipeline

translator = pipeline("translation", model="Helsinki-NLP/opus-mt-fr-en")
translator("Ce cours est produit par Hugging Face.")
```

```python out
[{'translation_text': 'This course is produced by Hugging Face.'}]
```

（入力文はフランス語で「このコースは Hugging Face が制作しています」という意味で、出力はその英語訳です）

テキスト生成や要約と同様に、結果に対して `max_length` や `min_length` を指定出来ます。

> [!TIP]
> **試してみましょう！** 他の言語の翻訳モデルを検索し、先程の文をいくつかの異なる言語に翻訳してみてください。

## 画像と音声のパイプライン

テキスト以外にも、Transformer モデルは画像や音声を扱うことが出来ます。いくつか例を示します。

### 画像分類

```python
from transformers import pipeline

image_classifier = pipeline(
    task="image-classification", model="google/vit-base-patch16-224"
)
result = image_classifier(
    "https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/pipeline-cat-chonk.jpeg"
)
print(result)
```

```python out
[{'label': 'lynx, catamount', 'score': 0.43350091576576233},
 {'label': 'cougar, puma, catamount, mountain lion, painter, panther, Felis concolor',
  'score': 0.034796204417943954},
 {'label': 'snow leopard, ounce, Panthera uncia',
  'score': 0.03240183740854263},
 {'label': 'Egyptian cat', 'score': 0.02394474856555462},
 {'label': 'tiger cat', 'score': 0.02288915030658245}]
```

### 自動音声認識

```python
from transformers import pipeline

transcriber = pipeline(
    task="automatic-speech-recognition", model="openai/whisper-large-v3"
)
result = transcriber(
    "https://huggingface.co/datasets/Narsil/asr_dummy/resolve/main/mlk.flac"
)
print(result)
```

## 複数のソースからデータを組み合わせる

Transformer モデルの強力な応用の1つは、複数のソースからデータを組み合わせて処理出来ることです。これは特に、次のような場合に役立ちます。

1. 複数のデータベースやリポジトリを横断して検索する
2. 異なる形式（テキスト、画像、音声）の情報を統合する
3. 関連情報の統一的なビューを作成する

例えば、次のようなシステムを構築出来ます。
- テキストや画像といった複数のモダリティにわたって、データベース内の情報を検索する。
- 異なるソースから得た情報を組み合わせ、矛盾の無い1つの回答にまとめる。例えば、音声ファイルとテキストによる説明を組み合わせて回答を作成する。
- ドキュメントとメタデータのデータベースの中から、最も関連性の高い情報を提示する。
