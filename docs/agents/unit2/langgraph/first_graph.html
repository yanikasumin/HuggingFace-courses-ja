初めての LangGraph を構築する

基本的な構成要素を理解したところで、それらを使って実際に動作する最初のグラフを構築してみましょう。ここでは Alfred のメール処理システムを実装します。Alfred が行う処理は次のとおりです。

  1. 受信メールを読む
  2. スパムか正規のメールかを分類する
  3. 正規のメールについては返信の下書きを作成する
  4. 正規のメールの場合は Mr. Wayne に内容を知らせる（実際には画面に出力するだけ）

この例では、LLM による意思決定を含むワークフローを LangGraph でどのように構成するかを示します。ツールを使っていないため、これをエージェントとみなすことはできませんが、このセクションではエージェントそのものよりも LangGraph フレームワークの学習に重点を置きます。

💡 ヒント

コードは、Google Colab で実行できる このノートブック で確認できます。

ワークフロー

構築するワークフローは次のとおりです。

環境のセットアップ

まず、必要なパッケージをインストールします。

%pip install langgraph langchain_openai

次に、必要なモジュールをインポートします。

import os
from typing import TypedDict, List, Dict, Any, Optional
from langgraph.graph import StateGraph, START, END
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

ステップ 1：State を定義する

メール処理のワークフローの中で Alfred が追跡する必要がある情報を定義しましょう。

class EmailState(TypedDict):
    # 処理対象のメール
    email: Dict[str, Any]  # 件名、送信者、本文などを含みます

    # メールのカテゴリ（問い合わせ、苦情など）
    email_category: Optional[str]

    # メールがスパムと判定された理由
    spam_reason: Optional[str]

    # 分析と判定の結果
    is_spam: Optional[bool]

    # 返信の生成
    email_draft: Optional[str]

    # 処理に関するメタデータ
    messages: List[Dict[str, Any]]  # 分析のために LLM とのやり取りを記録します

💡 ヒント： State は、重要な情報をすべて追跡できるよう十分に包括的にしつつ、不要な詳細で肥大化させないようにしてください。

ステップ 2：ノードを定義する

次に、ノードとなる処理関数を作成します。

# LLM を初期化します
model = ChatOpenAI(temperature=0)

def read_email(state: EmailState):
    """Alfred が受信メールを読み取り、記録します"""
    email = state["email"]

    # ここで初期の前処理を行う場合があります
    print(f"Alfred が {email['sender']} から届いたメール（件名：{email['subject']}）を処理しています。")

    # ここでは State の変更は不要です
    return {}

def classify_email(state: EmailState):
    """Alfred が LLM を使って、メールがスパムか正規のものかを判定します"""
    email = state["email"]

    # LLM へのプロンプトを用意します
    prompt = f"""
    As Alfred the butler, analyze this email and determine if it is spam or legitimate.

    Email:
    From: {email['sender']}
    Subject: {email['subject']}
    Body: {email['body']}

    First, determine if this email is spam. If it is spam, explain why.
    If it is legitimate, categorize it (inquiry, complaint, thank you, etc.).
    """

    # LLM を呼び出します
    messages = [HumanMessage(content=prompt)]
    response = model.invoke(messages)

    # 応答を解析するシンプルなロジックです（実際のアプリでは、より堅牢な解析が必要です）
    response_text = response.content.lower()
    is_spam = "spam" in response_text and "not spam" not in response_text

    # スパムの場合は理由を取り出します
    spam_reason = None
    if is_spam and "reason:" in response_text:
        spam_reason = response_text.split("reason:")[1].strip()

    # 正規のメールの場合はカテゴリを判定します
    email_category = None
    if not is_spam:
        categories = ["inquiry", "complaint", "thank you", "request", "information"]
        for category in categories:
            if category in response_text:
                email_category = category
                break

    # 追跡用にメッセージを更新します
    new_messages = state.get("messages", []) + [
        {"role": "user", "content": prompt},
        {"role": "assistant", "content": response.content}
    ]

    # State の更新内容を返します
    return {
        "is_spam": is_spam,
        "spam_reason": spam_reason,
        "email_category": email_category,
        "messages": new_messages
    }

def handle_spam(state: EmailState):
    """Alfred がスパムメールにメモを付けて破棄します"""
    print(f"Alfred がこのメールをスパムとして分類しました。理由：{state['spam_reason']}")
    print("このメールをスパムフォルダに移動しました。")

    # このメールの処理はこれで完了です
    return {}

def draft_response(state: EmailState):
    """Alfred が正規のメールへの返信の下書きを作成します"""
    email = state["email"]
    category = state["email_category"] or "general"

    # LLM へのプロンプトを用意します
    prompt = f"""
    As Alfred the butler, draft a polite preliminary response to this email.

    Email:
    From: {email['sender']}
    Subject: {email['subject']}
    Body: {email['body']}

    This email has been categorized as: {category}

    Draft a brief, professional response that Mr. Hugg can review and personalize before sending.
    """

    # LLM を呼び出します
    messages = [HumanMessage(content=prompt)]
    response = model.invoke(messages)

    # 追跡用にメッセージを更新します
    new_messages = state.get("messages", []) + [
        {"role": "user", "content": prompt},
        {"role": "assistant", "content": response.content}
    ]

    # State の更新内容を返します
    return {
        "email_draft": response.content,
        "messages": new_messages
    }

def notify_mr_hugg(state: EmailState):
    """Alfred が Mr. Hugg にメールについて知らせ、下書きの返信を提示します"""
    email = state["email"]

    print("\n" + "="*50)
    print(f"旦那様、{email['sender']} からメールが届いています。")
    print(f"件名：{email['subject']}")
    print(f"カテゴリ：{state['email_category']}")
    print("\nご確認いただくため、返信の下書きをご用意しました：")
    print("-"*50)
    print(state["email_draft"])
    print("="*50 + "\n")

    # このメールの処理はこれで完了です
    return {}

ステップ 3：ルーティングロジックを定義する

分類のあとにどの経路を取るかを決める関数が必要です。

def route_email(state: EmailState) -> str:
    """スパム判定の結果に基づいて次のステップを決定します"""
    if state["is_spam"]:
        return "spam"
    else:
        return "legitimate"

💡 注記： このルーティング関数は、分類ノードのあとにどのエッジをたどるかを決めるために LangGraph から呼び出されます。戻り値は、条件付きエッジのマッピングのキーのいずれかと一致しなければなりません。

ステップ 4：StateGraph を作成し、エッジを定義する

ここで、すべてを接続します。

# グラフを作成します
email_graph = StateGraph(EmailState)

# ノードを追加します
email_graph.add_node("read_email", read_email)
email_graph.add_node("classify_email", classify_email)
email_graph.add_node("handle_spam", handle_spam)
email_graph.add_node("draft_response", draft_response)
email_graph.add_node("notify_mr_hugg", notify_mr_hugg)

# エッジの開始点を設定します
email_graph.add_edge(START, "read_email")
# エッジを追加してフローを定義します
email_graph.add_edge("read_email", "classify_email")

# classify_email からの条件分岐を追加します
email_graph.add_conditional_edges(
    "classify_email",
    route_email,
    {
        "spam": "handle_spam",
        "legitimate": "draft_response"
    }
)

# 最後のエッジを追加します
email_graph.add_edge("handle_spam", END)
email_graph.add_edge("draft_response", "notify_mr_hugg")
email_graph.add_edge("notify_mr_hugg", END)

# グラフをコンパイルします
compiled_graph = email_graph.compile()

LangGraph が提供する特別な END ノードを使っている点に注目してください。これは、ワークフローが完了する終端の状態を示します。

ステップ 5：アプリケーションを実行する

正規のメールとスパムメールでグラフをテストしてみましょう。

# 正規のメールの例
legitimate_email = {
    "sender": "john.smith@example.com",
    "subject": "Question about your services",
    "body": "Dear Mr. Hugg, I was referred to you by a colleague and I'm interested in learning more about your consulting services. Could we schedule a call next week? Best regards, John Smith"
}

# スパムメールの例
spam_email = {
    "sender": "winner@lottery-intl.com",
    "subject": "YOU HAVE WON $5,000,000!!!",
    "body": "CONGRATULATIONS! You have been selected as the winner of our international lottery! To claim your $5,000,000 prize, please send us your bank details and a processing fee of $100."
}

# 正規のメールを処理します
print("\n正規のメールを処理しています...")
legitimate_result = compiled_graph.invoke({
    "email": legitimate_email,
    "is_spam": None,
    "spam_reason": None,
    "email_category": None,
    "email_draft": None,
    "messages": []
})

# スパムメールを処理します
print("\nスパムメールを処理しています...")
spam_result = compiled_graph.invoke({
    "email": spam_email,
    "is_spam": None,
    "spam_reason": None,
    "email_category": None,
    "email_draft": None,
    "messages": []
})

ステップ 6：Langfuse でメール振り分けエージェントを検査する 📡

Alfred はメール振り分けエージェントを調整するなかで、実行結果のデバッグを繰り返すことに疲れてきました。エージェントはその性質上、動作を予測しにくく、内部で何が起きているかを調べるのも簡単ではありません。しかし、究極のスパム検出エージェントを構築して本番環境に導入するには、その後の監視や分析に備えて、実行内容を確実に追跡できる仕組み（トレーサビリティ）が必要です。

そのために Alfred は、Langfuse のような可観測性ツールを使って、エージェントをトレースして監視できます。

まず、pip で Langfuse をインストールします。 

%pip install -q langfuse

次に、pip で LangChain をインストールします（Langfuse を使うには LangChain が必要です）。

%pip install langchain

次に、Langfuse の API キーとホストアドレスを環境変数として追加します。Langfuse の認証情報は、Langfuse Cloud に登録するか、Langfuse をセルフホスト することで取得できます。

import os

# プロジェクト設定ページからプロジェクト用のキーを取得してください: https://cloud.langfuse.com
os.environ["LANGFUSE_PUBLIC_KEY"] = "pk-lf-..." 
os.environ["LANGFUSE_SECRET_KEY"] = "sk-lf-..."
os.environ["LANGFUSE_HOST"] = "https://cloud.langfuse.com" # 🇪🇺 EU 地域
# os.environ["LANGFUSE_HOST"] = "https://us.cloud.langfuse.com" # 🇺🇸 US 地域

次に、Langfuse の callback_handler を設定し、グラフの呼び出しに langfuse_callback を追加することで、エージェントに計測を組み込みます：config={"callbacks": [langfuse_handler]}。

from langfuse.langchain import CallbackHandler

# LangGraph/Langchain 向けに Langfuse の CallbackHandler を初期化します（トレーシング用）
langfuse_handler = CallbackHandler()

# 正規のメールを処理します
legitimate_result = compiled_graph.invoke(
    input={"email": legitimate_email, "is_spam": None, "spam_reason": None, "email_category": None, "draft_response": None, "messages": []},
    config={"callbacks": [langfuse_handler]}
)

これで Alfred のエージェントが Langfuse に接続されました 🔌。LangGraph の実行が Langfuse に記録され、エージェントの動作の全体像を把握できるようになります。このセットアップにより、過去の実行を振り返り、メール振り分けエージェントをさらに改良する準備が整いました。

グラフを可視化する

LangGraph ではワークフローを可視化でき、その構造をよりよく理解し、デバッグするのに役立ちます。

compiled_graph.get_graph().draw_mermaid_png()

これにより、ノード同士がどのようにつながっているか、また取りうる条件分岐の経路を示す図が生成されます。

構築したもの

完成したメール処理ワークフローは、次の処理を行います。

  1. 受信メールを受け取る
  2. LLM を使って、スパムか正規のメールかを分類する
  3. スパムメールは破棄する
  4. 正規のメールについては返信の下書きを作成し、Mr. Hugg に通知する

この例から、LangGraph を使えば、明確で構造化された処理の流れを保ちながら、LLM を含む複雑なワークフローを組み立てて管理できることがわかります。

重要なポイント

  • State 管理：メール処理のあらゆる側面を追跡できる包括的な State を定義しました
  • ノードの実装：LLM とやり取りする機能的なノードを作成しました
  • 条件付きルーティング：メールの分類に基づく分岐ロジックを実装しました
  • 終端状態：ワークフローの完了地点を示すために END ノードを使いました
