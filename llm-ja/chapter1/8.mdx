これまで、テキスト分類や要約といった個別のタスクを通して、Transformer アーキテクチャを学んできました。しかし、大規模言語モデルが最もよく使われるのはテキスト生成です。この章では、テキスト生成を掘り下げます。

このページでは、LLM の推論の中核となる概念を学び、モデルがどのようにテキストを生成するのか、推論プロセスに関わる主要な要素をひととおり押さえていきます。

## 基本を理解する

まずは基本から始めましょう。推論とは、学習済みの LLM を使って、与えられた入力プロンプトから人間らしいテキストを生成するプロセスのことです。言語モデルは学習で得た知識を使い、応答を1単語ずつ組み立てていきます。モデルは数十億のパラメータから学習した確率を活用して、シーケンスの次のトークンを予測・生成します。このように1つずつ生成していくからこそ、LLM は一貫性があり文脈に沿ったテキストを生み出せるのです。

## Attention の役割

Attention 機構こそが、LLM に文脈を理解し、一貫した応答を生成する能力を与えています。次の単語を予測するとき、文中のすべての単語が同じ重みを持つわけではありません。たとえば *"The capital of France is ..."* という文では、"France" と "capital" という単語が、次に "Paris" が来るべきだと判断するうえで決定的に重要です。このように関連する情報に焦点を当てる能力が、Attention と呼ばれるものです。

<img src="https://huggingface.co/datasets/agents-course/course-images/resolve/main/en/unit1/AttentionSceneFinal.gif" alt="Attention の仕組みを示す GIF" width="60%">

次のトークンを予測するために関連性の高い単語を見つけ出すこのプロセスは、非常に効果的であることが実証されています。次のトークンを予測するという LLM の学習の基本原理は、BERT や GPT-2 の頃から概ね変わっていませんが、ニューラルネットワークのスケーリングや、より長いシーケンスをより低いコストで Attention 機構に扱わせる技術には、大きな進歩がありました。

> [!TIP]
> つまり、Attention 機構は、LLM が文脈に沿った、一貫性のあるテキストを生成するための鍵です。これこそが、現代の LLM を従来の言語モデルと分ける要素です。

### コンテキスト長とアテンションの対象範囲

Attention の仕組みを理解したところで、LLM が実際にどれだけの文脈を扱えるのかを見ていきましょう。ここで関係してくるのが、コンテキスト長、つまりモデルが一度に注意を向けられる範囲（attention span）です。

コンテキスト長とは、LLM が一度に処理できるトークン（単語、または単語の一部）の最大数のことです。モデルのワーキングメモリのサイズだと考えてください。

もっとも、この能力は次のような実用上の要因によって制限されます。
- モデルのアーキテクチャとサイズ
- 利用可能な計算リソース
- 入力と、求める出力の複雑さ

理想的には無制限のコンテキストをモデルに与えたいところですが、ハードウェアの制約と計算コストのために現実的ではありません。そのため、モデルごとに、能力と効率のバランスを取って異なるコンテキスト長が設計されています。

> [!TIP]
> コンテキスト長は、応答を生成する際にモデルが一度に考慮できるトークンの最大数です。

### プロンプティングの技術

LLM に情報を渡すとき、私たちは入力を工夫して、LLM が望ましい出力を生成するよう導きます。これを _プロンプティング_ と呼びます。

LLM が情報をどう処理するかを理解すると、より良いプロンプトを作れるようになります。モデルの主な仕事は、各入力トークンの重要度を分析して次のトークンを予測することなので、入力シーケンスの言い回しが非常に重要になります。

> [!TIP]
> プロンプトを丁寧に設計すると、**LLM が望ましい出力を生成するよう導く**のが容易になります。

## 2段階の推論プロセス

基本的な要素を理解したところで、LLM が実際にどのようにテキストを生成するのかを見ていきましょう。このプロセスは、プリフィルとデコードという2つの主要なフェーズに分けられます。この2つのフェーズは組み立てラインのように連携し、それぞれが一貫したテキストを生み出すうえで重要な役割を果たします。

### プリフィルフェーズ

プリフィルフェーズは、料理の下ごしらえのような段階です。最初の材料をすべて処理して、使える状態に整えます。このフェーズには、次の3つの重要なステップがあります。

1. **トークン化**: 入力テキストをトークンに変換します（トークンは、モデルが理解できる基本的な構成要素だと考えてください）
2. **埋め込みへの変換**: トークンを、その意味を捉えた数値表現に変換します
3. **初期処理**: 埋め込みをモデルのニューラルネットワークに通し、文脈の深い理解を形成します

このフェーズでは、すべての入力トークンを一度に処理する必要があるため、計算負荷が高くなります。応答を書き始める前に、段落全体を読んで理解するようなものだと考えてください。

### デコードフェーズ

プリフィルフェーズで入力が処理されたら、デコードフェーズに移ります。実際のテキスト生成が行われるのはこのフェーズです。モデルは、自己回帰（autoregressive）と呼ばれるプロセスで、1トークンずつ生成していきます（新しいトークンは、それ以前のすべてのトークンに依存します）。

デコードフェーズでは、新しいトークンのたびに次の重要なステップが実行されます。
1. **Attention の計算**: それ以前のすべてのトークンを振り返り、文脈を理解します
2. **確率の計算**: 次のトークンの候補それぞれの尤度を求めます
3. **トークンの選択**: これらの確率に基づいて次のトークンを選びます
4. **継続判定**: 生成を続けるか止めるかを判断します

このフェーズでは、生成済みのすべてのトークンとその関係を保持し続ける必要があるため、メモリ負荷が高くなります。

### トークン選択を理解する：確率からトークンの選択へ

モデルが次のトークンを選ぶときは、まず語彙にあるすべての単語について、ロジットと呼ばれる生の確率が得られます。では、この確率をどうやって実際の選択に結びつけるのでしょうか。順を追って見ていきましょう。

![画像](https://huggingface.co/reasoning-course/images/resolve/main/inference/1.png)

1. **生のロジット**: 次の単語の候補それぞれに対する、モデルの最初の「直感」のようなものだと考えてください
2. **Temperature（温度）の調整**: 創造性のダイヤルのようなものです。値を高く（>1.0）すると選択はよりランダムで創造的になり、低く（<1.0）するとより集中的で決定的になります
3. **Top-p（Nucleus）サンプリング**: 可能なすべての単語を対象にするのではなく、確率の合計が選んだしきい値（例: 上位90%）に達するまでの、最も確からしい単語だけを見ます
4. **Top-k フィルタリング**: 最も確からしい次の単語の上位 k 個だけを対象とする、もう1つのアプローチです

### 繰り返しを抑えるためのペナルティ

LLM によくある課題の1つは、同じ話を何度も繰り返す話し手のように、繰り返しに陥りやすいことです。これに対処するため、2種類のペナルティを使います。

1. **Presence Penalty**: すでに出現したトークンに対して、出現回数にかかわらず一律に適用されるペナルティです。モデルが同じ単語を再利用するのを防ぎます
2. **Frequency Penalty**: トークンが使われた回数に応じて大きくなるペナルティです。単語が出現するほど、再び選ばれにくくなります

![画像](https://huggingface.co/reasoning-course/images/resolve/main/inference/2.png)

これらのペナルティはトークン選択の早い段階で適用され、他のサンプリング戦略より先に生の確率を調整します。モデルに新しい語彙を探るよう促す、穏やかな後押しだと考えてください。

### 生成の長さを制御する：境界を設定する

良い物語に適切なペースと長さが必要なように、LLM がどれだけのテキストを生成するかを制御する方法が必要です。これは実用上とても重要です。ツイート程度の長さの応答を生成する場合でも、ブログ記事をまるごと生成する場合でも同様です。

生成の長さは、いくつかの方法で制御できます。
1. **トークン数の制限**: トークン数の最小値と最大値を設定します
2. **停止シーケンス**: 生成の終了を示す特定のパターンを定義します
3. **シーケンス終了の検出**: モデルが自然に応答を締めくくれるようにします

たとえば、1つの段落だけを生成したい場合は、最大100トークンに設定し、"\n\n" を停止シーケンスとして使うといった方法があります。これにより、内容のまとまりを保ちながら、用途に適した長さの出力を得られます。

![画像](https://huggingface.co/reasoning-course/images/resolve/main/inference/3.png)

### ビームサーチ：先読みで一貫性を高める

これまで見てきた戦略は1トークンずつ判断を下すものでしたが、ビームサーチはより全体的なアプローチを取ります。各ステップで1つの選択に決めてしまうのではなく、複数の可能な経路を同時に探索します。何手も先を読むチェスのプレイヤーのようなものです。

![画像](https://huggingface.co/reasoning-course/images/resolve/main/inference/4.png)

仕組みは次のとおりです。
1. 各ステップで、複数の候補シーケンスを保持します（通常は5〜10個）
2. 各候補について、次のトークンの確率を計算します
3. シーケンスと次のトークンの組み合わせのうち、最も有望なものだけを残します
4. 望む長さ、または停止条件に達するまで、このプロセスを続けます
5. 全体の確率が最も高いシーケンスを選択します

## 実践的な課題と最適化

LLM の推論についての探求を締めくくるにあたって、モデルをデプロイする際に直面する実践的な課題と、性能を測定・最適化する方法を見ていきましょう。

### 主要な性能指標

LLM を扱う際、実装の方針を左右する重要な指標が4つあります。

1. **Time to First Token (TTFT)**: 最初の応答がどれだけ速く得られるかを示します。ユーザー体験にとって重要で、主にプリフィルフェーズの影響を受けます
2. **Time Per Output Token (TPOT)**: 後続のトークンをどれだけ速く生成できるかを示します。全体の生成速度を決める指標です
3. **スループット**: 同時に何件のリクエストを処理できるかを示します。スケーリングとコスト効率に影響します
4. **VRAM 使用量**: GPU メモリがどれだけ必要かを示します。実世界のアプリケーションでは、これが主な制約になることがよくあります

### コンテキスト長の課題

LLM の推論における最も大きな課題の1つは、コンテキスト長を効果的に管理することです。コンテキストが長いほど多くの情報を提供できますが、大きなコストが伴います。

- **メモリ使用量**: コンテキスト長に対して2次関数的に増加します
- **処理速度**: コンテキストが長くなるにつれて線形に低下します
- **リソース配分**: VRAM 使用量の慎重なバランス調整が必要です

[Qwen2.5-1M](https://huggingface.co/Qwen/Qwen2.5-14B-Instruct-1M) のような最近のモデルは、100万トークンという驚異的なコンテキストウィンドウを提供しますが、その代償として推論時間は大幅に長くなります。大切なのは、自分のユースケースに合ったバランスを見つけることです。

### KV キャッシュによる最適化

これらの課題に対処する最も強力な最適化の1つが、KV（Key-Value）キャッシュです。この手法は、中間計算の結果を保存して再利用することで、推論速度を大きく改善します。この最適化により：

- 繰り返しの計算が減ります
- 生成速度が向上します
- 長いコンテキストでの生成が現実的になります

トレードオフとして追加のメモリ使用量が必要になりますが、性能面のメリットは通常、そのコストを大きく上回ります。

## まとめ

LLM の推論を理解することは、これらの強力なモデルを効果的にデプロイし、最適化するうえで欠かせません。このページでは、次の主要な要素を取り上げました。

- Attention と文脈の基本的な役割
- 2段階の推論プロセス
- 生成を制御するためのさまざまなサンプリング戦略
- 実践的な課題と最適化

これらの概念を押さえておくことで、LLM を効果的かつ効率的に活用するアプリケーションを構築する力が身につきます。

LLM の推論は急速に進化している分野であり、新しい手法や最適化が定期的に登場しています。好奇心を持ち続け、自分のユースケースに最適な方法が見つかるまで、さまざまなアプローチを試し続けてください。
