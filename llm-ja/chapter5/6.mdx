## 埋め込みを用いたセマンティック検索[[using-embeddings-for-semantic-search]]

[第1章](/course/chapter1) で見たように、Transformer ベースの言語モデルは、テキストの各トークンを *埋め込みベクトル* で表します。個々の埋め込みベクトルをプーリング（集約）すると、文や段落、場合によってはドキュメント全体も1つのベクトルで表せます。検索したいテキストの埋め込みとコーパス内の各ドキュメントの埋め込みについて、内積による類似度（又は別の類似度指標）を計算し、類似度の高いドキュメントを返すことで、内容が似たドキュメントを探せます。

このセクションでは、埋め込みを使ってセマンティック検索エンジンを作ります。セマンティック検索には、クエリに含まれるキーワードとドキュメントを照合する従来の検索方法に比べ、いくつかの利点があります。

## データセットの読み込みと準備[[loading-and-preparing-the-dataset]]

まず、GitHub の issue をまとめたデータセットをダウンロードします。いつものように `load_dataset()` 関数を使いましょう。

```py
from datasets import load_dataset

issues_dataset = load_dataset("lewtun/github-issues", split="train")
issues_dataset
```

```python out
Dataset({
    features: ['url', 'repository_url', 'labels_url', 'comments_url', 'events_url', 'html_url', 'id', 'node_id', 'number', 'title', 'user', 'labels', 'state', 'locked', 'assignee', 'assignees', 'milestone', 'comments', 'created_at', 'updated_at', 'closed_at', 'author_association', 'active_lock_reason', 'pull_request', 'body', 'performed_via_github_app', 'is_pull_request'],
    num_rows: 2855

```

ここでは `load_dataset()` でデフォルトの `train` 分割を指定した為、`DatasetDict` ではなく `Dataset` が返ります。まず、プルリクエストを除外しましょう。プルリクエストはユーザーの質問に答える際にはあまり役立たず、検索結果にノイズが混じる原因にもなる為です。これまでにも使った `Dataset.filter()` 関数で、該当する行を除外出来ます。ついでに、コメントのない行も除外しましょう。コメントがなければ、ユーザーの質問への答えも得られない為です。

```py
issues_dataset = issues_dataset.filter(
    lambda x: (x["is_pull_request"] == False and len(x["comments"]) > 0)
)
issues_dataset
```


データセットには多くの列がありますが、その大半は検索エンジンの構築には必要ありません。検索に役立つ情報が特に多いのは `title`、`body`、`comments` の3列です。また、`html_url` からは元の issue にアクセス出来ます。`Dataset.remove_columns()` 関数を使って、残りの列を削除しましょう。

```py
columns = issues_dataset.column_names
columns_to_keep = ["title", "body", "html_url", "comments"]
columns_to_remove = set(columns_to_keep).symmetric_difference(columns)
issues_dataset = issues_dataset.remove_columns(columns_to_remove)
issues_dataset
```

```python out
Dataset({
    features: ['html_url', 'title', 'comments', 'body'],
    num_rows: 771
})
```

埋め込みを作成する際には、各コメントに issue のタイトルと本文を付け加えます。これらには、コメントを理解する上で役立つ文脈情報が含まれていることが多い為です。現在、`comments` 列には各 issue のコメントがリストとして格納されています。

そこで、この列を展開（explode）し、1行に1件のコメントが入るようにします。これにより、各行が `(html_url, title, body, comment)` の組に対応する形になります。Pandas の [`DataFrame.explode()` 関数](https://pandas.pydata.org/pandas-docs/stable/reference/api/pandas.DataFrame.explode.html)を使えば、リスト形式の列の各要素を別々の行に展開し、他の列の値はそのまま複製出来ます。実際に試す為、まず Pandas の `DataFrame` 形式でデータを取り出しましょう。


> [!TIP]
> **やってみよう！** Pandas を使わずに、`Dataset.map()` を使って `issues_dataset` の `comments` 列の各コメントを、1件につき1行となるように展開出来るか試してみましょう。少し手強い課題です。Datasets ドキュメントの[「Batch mapping」](https://huggingface.co/docs/datasets/about_map_batch#batch-mapping)のセクションが役立つかもしれません。

1行に1つのコメントが入ったので、コメントごとの単語数を含む新しい `comments_length` 列を作成しましょう。

```py
comments_dataset = comments_dataset.map(
    lambda x: {"comment_length": len(x["comments"].split())}
)
```

この新しい列を使えば、短いコメントを除外出来ます。短いコメントには、"cc @lewtun" や "Thanks!" のように、検索には役立たないものが多くあります。何語以下のコメントを除外するかに決まった基準はありませんが、まずは15語程度を目安にするとよさそうです。

```py
comments_dataset = comments_dataset.filter(lambda x: x["comment_length"] > 15)
comments_dataset
```

```python out

})
```

データセットを少し整えたところで、issue のタイトル、本文、コメントを連結して、新しい `text` 列にまとめましょう。いつものように、`Dataset.map()` に渡せる単純な関数を書きます。

```py
def concatenate_text(examples):
    return {
        "text": examples["title"]
        + " \n "
        + examples["body"]
        + " \n "
        + examples["comments"]
    }


comments_dataset = comments_dataset.map(concatenate_text)
```

これでようやく、埋め込みを作成する準備が整いました！見ていきましょう。

## テキスト埋め込みの作成[[creating-text-embeddings]]

[第2章](/course/chapter2) で見たように、`AutoModel` クラスを使えばトークン埋め込みを取得出来ます。あとは、モデルの読み込みに使う適切なチェックポイントを選ぶだけです。

幸い、埋め込みの作成に特化した `sentence-transformers` というライブラリがあります。このライブラリの[ドキュメント](https://www.sbert.net/examples/applications/semantic-search/README.html#symmetric-vs-asymmetric-semantic-search)によると、今回のように短いクエリの答えを issue のコメントなど比較的長いドキュメントから探す処理は、*非対称セマンティック検索* に当たります。また、ドキュメント内の[モデル概要表](https://www.sbert.net/docs/pretrained_models.html#model-overview)では、`multi-qa-mpnet-base-dot-v1` チェックポイントがセマンティック検索で最も高い性能を示している為、これを使います。トークナイザも同じチェックポイントから読み込みます。

{#if fw === 'pt'}

```py
from transformers import AutoTokenizer, AutoModel

model_ckpt = "sentence-transformers/multi-qa-mpnet-base-dot-v1"
tokenizer = AutoTokenizer.from_pretrained(model_ckpt)
model = AutoModel.from_pretrained(model_ckpt)
```

モデルと入力を GPU に置けば、埋め込みの計算を高速化出来ます。ここでその準備をしておきましょう。

```py
import torch

device = torch.device("cuda")
model.to(device)
```

{:else}

```py
from transformers import AutoTokenizer, TFAutoModel

model_ckpt = "sentence-transformers/multi-qa-mpnet-base-dot-v1"
tokenizer = AutoTokenizer.from_pretrained(model_ckpt)
model = TFAutoModel.from_pretrained(model_ckpt, from_pt=True)
```

`from_pretrained()` メソッドの引数として `from_pt=True` を設定していることに注目してください。これは、`multi-qa-mpnet-base-dot-v1` チェックポイントには PyTorch の重みしか無い為で、`from_pt=True` を設定すれば自動的に TensorFlow 形式に変換してくれます。見ての通り、Transformers ではフレームワーク間の切り替えが非常に簡単です！

{/if}

前に述べたように、GitHub の issue から作ったコーパスの各エントリを1つのベクトルで表したいので、トークン埋め込みを何らかの方法でプーリングする必要があります。平均化もその方法の1つです。よく使われる方法の1つに、モデルの出力に対する *CLS プーリング* があります。これは、特殊トークン `[CLS]` に対応する最終隠れ状態を取り出す方法です。次の関数で実装出来ます。

```py
def cls_pooling(model_output):
    return model_output.last_hidden_state[:, 0]
```

次に、ドキュメントのリストをトークナイズし、テンソルを GPU に配置して、モデルに入力し、最後に出力に CLS プーリングを適用するヘルパー関数を作成します。

{#if fw === 'pt'}

```py
def get_embeddings(text_list):
    encoded_input = tokenizer(
        text_list, padding=True, truncation=True, return_tensors="pt"
    )
    encoded_input = {k: v.to(device) for k, v in encoded_input.items()}
    model_output = model(**encoded_input)
    return cls_pooling(model_output)
```

コーパスの最初のテキストを関数に渡し、正しく動くかどうかと、出力の形状を確認しましょう。

```py
embedding = get_embeddings(comments_dataset["text"][0])
embedding.shape
```

```python out
torch.Size([1, 768])
```

素晴らしい。コーパスの最初のエントリを768次元のベクトルに変換出来ました！`Dataset.map()` を使って `get_embeddings()` 関数をコーパスの各行に適用出来るので、次のように新しい `embeddings` 列を作成しましょう。

```py
embeddings_dataset = comments_dataset.map(
    lambda x: {"embeddings": get_embeddings(x["text"]).detach().cpu().numpy()[0]}

```

## FAISS による効率的な類似検索[[using-faiss-for-efficient-similarity-search]]

埋め込みベクトルを格納したデータセットが出来たので、次はその中から似たベクトルを探す仕組みが必要です。ここでは、Datasets で利用出来る *FAISS インデックス* というデータ構造を使います。[FAISS](https://faiss.ai/)（Facebook AI Similarity Search の略）は、埋め込みベクトルを高速に検索・クラスタリングする為のアルゴリズムを提供するライブラリです。

FAISS の基本的な考え方は、インデックスと呼ばれる特殊なデータ構造を作成し、入力した埋め込みに類似する埋め込みを見つけられるようにすることです。Datasets で FAISS インデックスを作成するのは簡単です。`Dataset.add_faiss_index()` 関数を使い、データセットのどの列をインデックス化するかを指定します。

```py
embeddings_dataset.add_faiss_index(column="embeddings")
```

これで、`Dataset.get_nearest_examples()` 関数を使って、インデックスから近いベクトルを探す最近傍検索が出来るようになりました。まず、質問文を埋め込みベクトルに変換して試してみましょう。

{#if fw === 'pt'}

```py
question = "How can I load a dataset offline?"
question_embedding = get_embeddings([question]).cpu().detach().numpy()
question_embedding.shape
```

```python out
torch.Size([1, 768])
```

{:else}

```py
question = "How can I load a dataset offline?"
question_embedding = get_embeddings([question]).numpy()
question_embedding.shape
```

```python out
(1, 768)
```

{/if}

（クエリの訳：「データセットをオフラインで読み込むにはどうすればよいですか？」）

ドキュメントと同様に、クエリを表す768次元のベクトルが得られました。これをコーパス全体と比較して、最も類似する埋め込みを見つけることが出来ます。

```py
scores, samples = embeddings_dataset.get_nearest_examples(
    "embeddings", question_embedding, k=5
)
```

`Dataset.get_nearest_examples()` 関数は、クエリと各ドキュメントの類似度を示すスコアと、それに対応するサンプル（ここでは類似度が高い上位5件）を組にして返します。これらを `pandas.DataFrame` にまとめ、簡単に並べ替えられるようにしましょう。

```py
import pandas as pd

samples_df = pd.DataFrame.from_dict(samples)
samples_df["scores"] = scores
samples_df.sort_values("scores", ascending=False, inplace=True)
```

では、先頭から数行を順に見て、クエリと検索対象のコメントがどのくらい一致しているか確認してみましょう。

```py
for _, row in samples_df.iterrows():
```
