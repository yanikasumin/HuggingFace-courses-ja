ビッグデータ？🤗 Datasets にお任せ！

近年では、BERT や GPT-2 のような Transformer モデルをゼロから事前学習する場合など、数ギガバイト規模のデータセットを扱うことも珍しくありません。こうした場合、データを読み込むこと自体が難題になることがあります。例えば、GPT-2 の事前学習に使われた WebText コーパスは、800万件を超えるドキュメントと40 GB のテキストから構成されており、これをノートパソコンの RAM に読み込もうとすれば、ノートパソコンが悲鳴を上げてしまうでしょう！

幸い、🤗 Datasets はこうした制約を克服出来るよう設計されています。データセットをメモリマップドファイルとして扱うことでメモリ管理の問題からユーザーを解放し、コーパス内のデータをストリーミングすることでハードドライブの容量制限からも解放してくれます。

このセクションでは、825 GB という巨大なコーパスである the Pile を使って、Datasets のこれらの機能を探っていきます。さっそく始めましょう！

Pile とは？

Pile は、大規模言語モデルの訓練の為に EleutherAI が作成した英語テキストコーパスです。科学論文、GitHub のコードリポジトリ、フィルタリングされた Web テキストなど、多様なデータセットを含んでいます。訓練コーパスは 14 GB のチャンクで入手出来、個別の構成要素もいくつかダウンロード出来ます。

まず、PubMed Abstracts データセットを見てみましょう。これは PubMed に掲載された1500万件の生物医学系出版物の抄録を集めたコーパスです。このデータセットは JSON Lines 形式で保存され、zstandard ライブラリで圧縮されています。その為、まずこのライブラリをインストールする必要があります。

## メモリマッピングの魔法

Python でメモリ使用量を測る簡単な方法として、[`psutil`](https://psutil.readthedocs.io/en/latest/) ライブラリがあります。`pip` で次のようにインストール出来ます。

```python
!pip install psutil

このライブラリの Process クラスを使うと、現在のプロセスのメモリ使用量を次のように確認出来ます。

import psutil

# Process.memory_info はバイト単位で表されるので、メガバイトに変換します
print(f"RAM 使用量: {psutil.Process().memory_info().rss / (1024 * 1024):.2f} MB")

```python out RAM 使用量: 5678.33 MB

ここで `rss` 属性は resident set size（常駐セットサイズ）を指し、プロセスが RAM 上で占有しているメモリの割合です。この測定値には Python インタプリタや読み込んだライブラリが使うメモリも含まれる為、データセットの読み込みに実際に使われたメモリ量はもう少し小さくなります。比較の為に、`dataset_size` 属性でデータセットのディスク上の大きさを見てみましょう。結果は先程と同様にバイト単位で表されるので、手動でギガバイトに変換する必要があります。

```py
print(f"データセットのサイズ（バイト）: {pubmed_dataset.dataset_size}")
size_gb = pubmed_dataset.dataset_size / (1024**3)
print(f"データセットのサイズ（キャッシュファイル）: {size_gb:.2f} GB")

```python out データセットのサイズ（バイト）: 20979437051 データセットのサイズ（キャッシュファイル）: 19.54 GB

素晴らしいことに、このデータセットは 20 GB 近い大きさですが、それを大幅に下回る量の RAM で読み込み、内容にアクセス出来ています！

<div class="callout callout-tip" markdown="block">
<p class="callout-title">💡 ヒント</p>
**やってみよう！** Pile の[サブセット](https://the-eye.eu/public/AI/pile_preliminary_components/)の中から、自分のノートパソコンやデスクトップの RAM より大きいものを1つ選んで Datasets で読み込み、使用された RAM の量を測ってみましょう。正確に測るには、新しいプロセスで実行するのがよいでしょう。各サブセットの解凍後のサイズは、[the Pile の論文](https://arxiv.org/abs/2101.00027)の表1に載っています。
</div>


Pandas に慣れている人には、この結果は意外かもしれません。Wes Kinney の有名な[経験則](https://wesmckinney.com/blog/apache-arrow-pandas-internals/)では、通常、データセットのサイズの5倍から10倍の RAM が必要とされるからです。では、Datasets はこのメモリ管理の問題をどう解決しているのでしょうか。Datasets は各データセットを[メモリマップドファイル](https://en.wikipedia.org/wiki/Memory-mapped_file)として扱います。これは RAM とファイルシステム上のストレージを対応付ける仕組みであり、データセット全体をメモリに読み込まなくても、その要素にアクセスして操作出来ます。

メモリマップドファイルは複数のプロセス間で共有も出来る為、`Dataset.map()` のようなメソッドを、データセットを移動したりコピーしたりすることなく並列化出来ます。これらの機能は全て、裏側では [Apache Arrow](https://arrow.apache.org) のメモリ形式と [`pyarrow`](https://arrow.apache.org/docs/python/index.html) ライブラリによって実現されており、データの読み込みと処理を非常に高速にしています。（Apache Arrow の詳細や Pandas との比較については、[Dejan Simic のブログ記事](https://towardsdatascience.com/apache-arrow-read-dataframe-with-zero-memory-69634092b1a)を参照してください。）実際に確かめる為に、PubMed Abstracts データセットの全ての要素をたどる簡単な速度テストをしてみましょう。

```py
import timeit

code_snippet = """batch_size = 1000

for idx in range(0, len(pubmed_dataset), batch_size):
    _ = pubmed_dataset[idx:idx + batch_size]
"""

time = timeit.timeit(stmt=code_snippet, number=1, globals=globals())
print(
    f"{len(pubmed_dataset)} 件のサンプル（約 {size_gb:.1f} GB）を "
    f"{time:.1f} 秒で走査しました。処理速度: {size_gb/time:.3f} GB/秒"
)

```python out '15518009 件のサンプル（約 19.5 GB）を 64.2 秒で走査しました。処理速度: 0.304 GB/秒'

ここでは Python の `timeit` モジュールを使って、`code_snippet` の実行時間を測りました。通常、データセットは1秒あたり数百 MB から数 GB の速度でたどることが出来ます。この処理速度は大半の用途には十分ですが、ノートパソコンのハードドライブにすら保存出来ない程大きなデータセットを扱わなければならない場合もあります。

例えば、Pile 全体をダウンロードしようとすると、825 GB の空きディスク容量が必要になります！こうした場合に備えて、Datasets にはストリーミング機能が用意されています。データセット全体をダウンロードせずに、必要な要素をその都度ダウンロードして利用出来ます。その仕組みを見ていきましょう。

<div class="callout callout-tip" markdown="block">
<p class="callout-title">💡 ヒント</p>
Jupyter ノートブックでは、[`%%timeit` マジック関数](https://ipython.readthedocs.io/en/stable/interactive/magics.html#magic-timeit)を使ってセルの時間を測ることも出来ます。
</div>


## データセットのストリーミング

データセットのストリーミングを有効にするには、`load_dataset()` 関数に `streaming=True` 引数を渡すだけです。例えば、PubMed Abstracts データセットを今度はストリーミングモードで読み込んでみましょう。

```py
pubmed_dataset_streamed = load_dataset(
    "json", data_files=data_files, split="train", streaming=True
)

この章でこれまで見てきた Dataset とは異なり、streaming=True を指定すると IterableDataset オブジェクトが返されます。その名の通り、IterableDataset の要素にアクセスするには、データセットを反復処理する必要があります。ストリーミングされたデータセットの最初の要素には、次のようにアクセス出来ます。

next(iter(pubmed_dataset_streamed))

```python out {'meta': {'pmid': 11409574, 'language': 'eng'}, 'text': 'Epidemiology of hypoxaemia in children with acute lower respiratory infection.\nTo determine the prevalence of hypoxaemia in children aged under 5 years suffering acute lower respiratory infections (ALRI), the risk factors for hypoxaemia in children under 5 years of age with ALRI, and the association of hypoxaemia with an increased risk of dying in children of the same age ...'}

ストリーミングされたデータセットの要素は `IterableDataset.map()` を使ってその場で処理出来ます。これは、訓練時に入力をトークナイズする必要が有る場合に便利です。手順は、[第3章](/course/chapter3) でデータセットをトークナイズした時に使ったものとまったく同じで、唯一の違いは出力が1つずつ返されることです。

```py
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("distilbert-base-uncased")
tokenized_dataset = pubmed_dataset_streamed.map(lambda x: tokenizer(x["text"]))
next(iter(tokenized_dataset))

```python out

ストリーミングされたデータセットでも `IterableDataset.shuffle()` を使ってシャッフル出来ます。ただし、`Dataset.shuffle()` とは異なり、シャッフルの対象は指定された `buffer_size` 件分のバッファ内に在る要素に限られます。

```py
shuffled_dataset = pubmed_dataset_streamed.shuffle(buffer_size=10_000, seed=42)
next(iter(shuffled_dataset))

```python out {'meta': {'pmid': 11410799, 'language': 'eng'}, 'text': 'Randomized study of dose or schedule modification of granulocyte colony-stimulating factor in platinum-based chemotherapy for elderly patients with lung cancer ...'}
