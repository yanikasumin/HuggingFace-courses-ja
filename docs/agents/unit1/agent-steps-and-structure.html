思考・アクション・観察のサイクルを通して AI エージェントを理解する

前のセクションでは次を学びました。

  • ツールがシステムプロンプトでエージェントにどう提供されるか。
  • AI エージェントが「推論」し、計画し、環境とやり取りできるシステムであること。

このセクションでは、完全な AI エージェントのワークフローを探ります。これは思考・アクション・観察として定義したサイクルです。

そのあと、これらの各ステップにさらに深く踏み込みます。

中核コンポーネント

エージェントの仕事は、思考（Thought）→ 行動（Act）→ 観察（Observe） の連続したサイクルです。

これらのアクションを一緒に分解してみましょう。

  1. 思考（Thought）: エージェントの LLM 部分が、次のステップが何であるべきかを決定する。
  2. アクション（Action）: エージェントが、関連する引数でツールを呼び出してアクションを取る。
  3. 観察（Observation）: モデルがツールからの応答を振り返る。

思考・アクション・観察のサイクル

3つのコンポーネントは、連続したループで一緒に動作します。プログラミングの例えを使うと、エージェントは while ループ を使います。ループは、エージェントの目的が果たされるまで続きます。

視覚的には、次のようになります。

多くのエージェントフレームワークでは、ルールとガイドラインがシステムプロンプトに直接埋め込まれており、すべてのサイクルが定義された論理に従うことが保証されます。

簡略化したバージョンでは、システムプロンプトは次のようになるでしょう。

ここでは、システムメッセージで次を定義したことが分かります。

  • エージェントの振る舞い。
  • 前のセクションで説明した、エージェントがアクセスできるツール。
  • LLM の指示に組み込む、思考・アクション・観察のサイクル。

プロセスの各ステップに深く入る前に、小さな例を通してプロセスを理解しましょう。

Alfred、天気エージェント

天気エージェントの Alfred を作成しました。

ユーザーが Alfred に「ニューヨークの現在の天気は？」と尋ねます。

Alfred の仕事は、天気 API ツールを使ってこのクエリに答えることです。

サイクルは次のように展開します。

思考（Thought）

内部推論:

クエリを受け取ると、Alfred の内部対話は次のようになるかもしれません。

「ユーザーはニューヨークの現在の天気情報を必要としています。天気データを取得するツールにアクセスできます。まず、最新の詳細を得るために天気 API を呼び出す必要があります。」

このステップは、エージェントが問題をステップに分解する様子を示しています。まず、必要なデータを集めることです。

アクション（Action）

ツールの使用:

推論と、Alfred が get_weather ツールを知っているという事実に基づいて、Alfred は天気 API ツールを呼び出す JSON 形式のコマンドを準備します。たとえば、最初のアクションは次のようになるでしょう。

Thought: I need to check the current weather for New York.

{ "action": "get_weather", "action_input": { "location": "New York" } }

ここで、アクションは呼び出すツール（例: get_weather）と渡すパラメータ（"location": "New York"）を明確に指定しています。

観察（Observation）

環境からのフィードバック:

ツール呼び出しのあと、Alfred は観察を受け取ります。これは API からの生の天気データかもしれません。たとえば次のようなものです。

"Current weather in New York: partly cloudy, 15°C, 60% humidity."（ニューヨークの現在の天気: ところどころ曇り、15°C、湿度60%）

この観察は、追加のコンテキストとしてプロンプトに追加されます。現実世界のフィードバックとして機能し、アクションが成功したかどうかを確認し、必要な詳細を提供します。

更新された思考

振り返り:

観察を手にすると、Alfred は内部推論を更新します。

「ニューヨークの天気データが得られたので、ユーザー向けの回答をまとめられます。」

最終アクション

Alfred は、私たちが指示したとおりの形式で最終応答を生成します。

Thought: I have the weather data now. The current weather in New York is partly cloudy with a temperature of 15°C and 60% humidity."

Final answer : The current weather in New York is partly cloudy with a temperature of 15°C and 60% humidity.

この最終アクションは、回答をユーザーに送り返し、ループを閉じます。

この例で分かることは次のとおりです。

  • エージェントは目的が果たされるまでループを繰り返します:

Alfred のプロセスは循環的です。思考から始まり、ツールを呼び出して行動し、最後に結果を観察します。観察がエラーや不完全なデータを示していた場合、Alfred はアプローチを修正するためにサイクルに再び入ることができました。

  • ツールの統合:

ツール（天気 API など）を呼び出す能力により、Alfred は 静的な知識を超えてリアルタイムデータを取得でき、これは多くの AI エージェントにとって不可欠な側面です。

  • 動的な適応:

各サイクルにより、エージェントは新しい情報（観察）を推論（思考）に取り込むことができ、最終回答が十分な情報に基づいて正確であることが保証されます。

この例は、ReAct サイクル（次のセクションで展開する概念）の背後にある中核概念を示しています。思考、アクション、観察の相互作用により、AI エージェントは複雑なタスクを反復的に解決できます。

これらの原則を理解し応用することで、タスクについて推論するだけでなく、外部ツールを効果的に利用してタスクを完了する エージェントを設計できます。その間ずっと、環境からのフィードバックに基づいて出力を継続的に改善し続けます。

では次に、プロセスの個別のステップとして、思考、アクション、観察にさらに深く踏み込みましょう。
