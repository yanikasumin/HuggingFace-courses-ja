Bonus Unit 2: エージェントのオブザーバビリティと評価

💡 ヒント

コードは、Google Colab で実行できるこのノートブックで確認できます。

このノートブックでは、オープンソースのオブザーバビリティツールを使って、AI エージェントの内部ステップ（トレース）を監視し、パフォーマンスを評価する方法を学びます。

エージェントの振る舞いを観測し、評価できることは、次のために不可欠です。 - タスクが失敗したり、最適でない結果を出したりしたときの問題のデバッグ - コストとパフォーマンスのリアルタイム監視 - 継続的なフィードバックによる信頼性と安全性の向上

Step 0: 必要なライブラリをインストールする

エージェントの実行、監視、評価に必要なライブラリがいくつかあります。

%pip install langfuse 'smolagents[telemetry]' openinference-instrumentation-smolagents datasets 'smolagents[gradio]' gradio --upgrade

Step 1: エージェントに計装する

このノートブックでは、オブザーバビリティツールとして Langfuse を使いますが、OpenTelemetry 互換の他のサービスでも構いません。以下のコードは、Langfuse（または任意の OTel エンドポイント）向けの環境変数の設定方法と、smolagent への計装方法を示しています。

Note: LlamaIndex や LangGraph を使っている場合は、それぞれの計装方法のドキュメントがこちらとこちらにあります。

まず、Langfuse の認証情報を環境変数に設定します。Langfuse API キーは、Langfuse Cloud にサインアップするか、Langfuse をセルフホスティングして取得してください。

import os
# プロジェクト設定ページからプロジェクトのキーを取得する: https://cloud.langfuse.com
os.environ["LANGFUSE_PUBLIC_KEY"] = "pk-lf-..." 
os.environ["LANGFUSE_SECRET_KEY"] = "sk-lf-..." 
os.environ["LANGFUSE_HOST"] = "https://cloud.langfuse.com" # 🇪🇺 EU リージョン
# os.environ["LANGFUSE_HOST"] = "https://us.cloud.langfuse.com" # 🇺🇸 US リージョン

推論呼び出しに使う Hugging Face トークンも設定する必要があります。

# Hugging Face やその他のトークン/シークレットを環境変数に設定する
os.environ["HF_TOKEN"] = "hf_..."

環境変数を設定したら、Langfuse クライアントを初期化できます。get_client() は、環境変数で指定された認証情報を使って Langfuse クライアントを初期化します。

from langfuse import get_client

langfuse = get_client()

# 接続を確認する
if langfuse.auth_check():
    print("Langfuse client is authenticated and ready!")
else:
    print("Authentication failed. Please check your credentials and host.")

次に、SmolagentsInstrumentor() を設定して、smolagent に計装し、トレースを Langfuse へ送信します。

from openinference.instrumentation.smolagents import SmolagentsInstrumentor

SmolagentsInstrumentor().instrument()

Step 2: 計装をテストする

1+1 を計算する、smolagents のシンプルな CodeAgent です。実行して、計装が正しく動作しているか確認します。すべて正しく設定されていれば、オブザーバビリティのダッシュボードにログやスパンが表示されます。

from smolagents import InferenceClientModel, CodeAgent

# 計装をテストするためのシンプルなエージェントを作成する
agent = CodeAgent(
    tools=[],
    model=InferenceClientModel()
)

agent.run("1+1=")

Langfuse のトレースダッシュボード（または選択したオブザーバビリティツール）を確認し、スパンとログが記録されていることを確かめてください。

Step 3: より複雑なエージェントを観測し、評価する

計装が動作することを確認できたので、次はより複雑なクエリを試し、高度なメトリクス（トークン使用量、レイテンシ、コストなど）がどう追跡されるか見てみましょう。

from smolagents import (CodeAgent, DuckDuckGoSearchTool, InferenceClientModel)

search_tool = DuckDuckGoSearchTool()
agent = CodeAgent(tools=[search_tool], model=InferenceClientModel())

agent.run("How many Rubik's Cubes could you fit inside the Notre Dame Cathedral?")

トレースの構造

多くのオブザーバビリティツールは、各ステップを表すスパンを含むトレースを記録します。ここでのトレースには、エージェントの実行全体と、次のサブスパンが含まれます。 - ツール呼び出し（DuckDuckGoSearchTool） - LLM 呼び出し（InferenceClientModel）

これらを調べることで、どこに時間がかかっているか、トークンが何個使われているかなどが正確に分かります。

トレースへのリンク

オンライン評価

前のセクションでは、オンライン評価とオフライン評価の違いを学びました。ここでは、本番環境でエージェントを監視し、ライブで評価する方法を見ていきます。

本番環境で追跡すべき代表的なメトリクス

  1. コスト — smolagents の計装はトークン使用量を取得します。トークンあたりの価格を設定することで、おおよそのコストに変換できます。
  2. レイテンシ — 各ステップ、または実行全体にかかる時間を観測します。
  3. ユーザーフィードバック — ユーザーは直接フィードバック（いいね／よくない）を提供でき、エージェントの改善や修正に役立ちます。
  4. LLM-as-a-Judge — 別の LLM を使って、エージェントの出力をほぼリアルタイムに評価します（毒性や正確さのチェックなど）。

以下で、これらのメトリクスの例を示します。

以下は、Qwen2.5-Coder-32B-Instruct の呼び出しにおける使用量を示すスクリーンショットです。コストのかかるステップを確認し、エージェントを最適化するのに役立ちます。

3. 追加の属性

スパンに追加の属性を渡すこともできます。user_id、tags、session_id、カスタムメタデータなどが含まれます。こうした詳細でトレースを充実させることは、異なるユーザーやセッションにまたがるアプリケーションの振る舞いの分析、デバッグ、監視に重要です。

from smolagents import (CodeAgent, DuckDuckGoSearchTool, InferenceClientModel)

search_tool = DuckDuckGoSearchTool()
agent = CodeAgent(
    tools=[search_tool],
    model=InferenceClientModel()
)

with langfuse.start_as_current_span(
    name="Smolagent-Trace",
    ) as span:

    # ここでアプリケーションを実行する
    response = agent.run("What is the capital of Germany?")

    # スパンに追加の属性を渡す
    span.update_trace(
        input="What is the capital of Germany?",
        output=response,
        user_id="smolagent-user-123",
        session_id="smolagent-session-123456789",
        tags=["city-question", "testing-agents"],
        metadata={"email": "user@langfuse.com"},
        )

# 短命なアプリケーションではイベントをフラッシュする
langfuse.flush()

4. ユーザーフィードバック

エージェントがユーザーインターフェースに組み込まれている場合、ユーザーの直接フィードバック（チャット UI のいいね／よくないなど）を記録できます。以下は、シンプルなフィードバック機能を持つチャットを埋め込む、Gradio を使った例です。

以下のコードでは、ユーザーがチャットメッセージを送信すると、トレースを Langfuse に記録します。ユーザーが最後の回答にいいね／よくないを付けると、そのスコアをトレースに紐付けます。

import gradio as gr
from smolagents import (CodeAgent, InferenceClientModel)
from langfuse import get_client

langfuse = get_client()

model = InferenceClientModel()
agent = CodeAgent(tools=[], model=model, add_base_tools=True)

trace_id = None

def respond(prompt, history):
    with langfuse.start_as_current_span(
        name="Smolagent-Trace"):

        # ここでアプリケーションを実行する
        output = agent.run(prompt)

        global trace_id
        trace_id = langfuse.get_current_trace_id()

    history.append({"role": "assistant", "content": str(output)})
    return history

def handle_like(data: gr.LikeData):
    # デモ用に、ユーザーフィードバックを 1（いいね）または 0（よくない）にマッピングする
    if data.liked:
        langfuse.create_score(
            value=1,
            name="user-feedback",
            trace_id=trace_id
        )
    else:
        langfuse.create_score(
            value=0,
            name="user-feedback",
            trace_id=trace_id
        )

with gr.Blocks() as demo:
    chatbot = gr.Chatbot(label="Chat", type="messages")
    prompt_box = gr.Textbox(placeholder="Type your message...", label="Your message")

    # ユーザーがプロンプトで Enter を押したら 'respond' を実行する
    prompt_box.submit(
        fn=respond,
        inputs=[prompt_box, chatbot],
        outputs=chatbot
    )

    # ユーザーがメッセージの「いいね」ボタンをクリックしたら 'handle_like' を実行する
    chatbot.like(handle_like, None, None)

demo.launch()

ユーザーフィードバックは、オブザーバビリティツールに次のように記録されます。

5. LLM-as-a-Judge

LLM-as-a-Judge は、エージェントの出力を自動的に評価するもう一つの方法です。別の LLM 呼び出しを設定し、出力の正確さ、毒性、スタイルなど、気になる任意の基準で評価させることができます。

ワークフロー: 1. 評価テンプレートを定義します。たとえば「テキストに毒性があるかチェックする」などです。 2. エージェントが出力を生成するたびに、その出力とテンプレートを「ジャッジ」LLM に渡します。 3. ジャッジ LLM が評価やラベルを返し、それをオブザーバビリティツールに記録します。

Langfuse の例:

# 例: エージェントの出力に毒性があるかどうかをチェックする
from smolagents import (CodeAgent, DuckDuckGoSearchTool, InferenceClientModel)

search_tool = DuckDuckGoSearchTool()
agent = CodeAgent(tools=[search_tool], model=InferenceClientModel())

agent.run("Can eating carrots improve your vision?")

この例の回答は「not toxic（有害でない）」と判定されていることが分かります。

6. オブザーバビリティメトリクスの概要

これらのメトリクスはすべて、ダッシュボードでまとめて可視化できます。これにより、多くのセッションにわたってエージェントのパフォーマンスを素早く把握し、品質メトリクスの経時変化を追跡できます。

オフライン評価

オンライン評価はライブフィードバックに不可欠ですが、オフライン評価、つまり開発前や開発中の体系的なチェックも必要です。これにより、変更を本番環境へ投入する前に、品質と信頼性を保つことができます。

データセットによる評価

オフライン評価では、通常は次の手順を行います。 1. ベンチマークデータセット（プロンプトと期待される出力のペア）を用意する 2. そのデータセットでエージェントを実行する 3. 出力を期待される結果と比較するか、追加の採点方法を使う

以下では、数学の質問と解答を含む GSM8K データセット でこのアプローチを示します。

import pandas as pd
from datasets import load_dataset

# Hugging Face から GSM8K を取得する
dataset = load_dataset("openai/gsm8k", 'main', split='train')
df = pd.DataFrame(dataset)
print("First few rows of GSM8K dataset:")
print(df.head())

次に、実行を追跡するために Langfuse にデータセットエンティティを作成します。そして、データセットの各アイテムをシステムに追加します。（Langfuse を使わない場合は、分析用に自分のデータベースやローカルファイルへ保存すればよいでしょう。）

from langfuse import get_client
langfuse = get_client()

langfuse_dataset_name = "gsm8k_dataset_huggingface"

# Langfuse にデータセットを作成する
langfuse.create_dataset(
    name=langfuse_dataset_name,
    description="GSM8K benchmark dataset uploaded from Huggingface",
    metadata={
        "date": "2025-03-10", 
        "type": "benchmark"
    }
)

for idx, row in df.iterrows():
    langfuse.create_dataset_item(
        dataset_name=langfuse_dataset_name,
        input={"text": row["question"]},
        expected_output={"text": row["answer"]},
        metadata={"source_index": idx}
    )
    if idx >= 9: # デモ用に最初の 10 件だけをアップロードする
        break

データセットでエージェントを実行する

ヘルパー関数 run_smolagent() を定義します。この関数は次の処理を行います。 1. Langfuse のスパンを開始する 2. プロンプトでエージェントを実行する 3. Langfuse にトレース ID を記録する

その後、データセットの各アイテムをループしてエージェントを実行し、トレースをデータセットアイテムに紐付けます。必要に応じて、簡易な評価スコアを付けることもできます。

from opentelemetry.trace import format_trace_id
from smolagents import (CodeAgent, InferenceClientModel, LiteLLMModel)
from langfuse import get_client

langfuse = get_client()


# 例: InferenceClientModel や LiteLLMModel を使うと、OpenAI、Anthropic、Gemini などのモデルにアクセスできる
model = InferenceClientModel()

agent = CodeAgent(
    tools=[],
    model=model,
    add_base_tools=True
)

dataset_name = "gsm8k_dataset_huggingface"
current_run_name = "smolagent-notebook-run-01" # この評価実行を識別する名前

# 'run_smolagent' を、計装済みのアプリケーション関数とする
def run_smolagent(question):
    with langfuse.start_as_current_generation(name="qna-llm-call") as generation:
        # LLM 呼び出しをシミュレートする
        result = agent.run(question)

        # トレースに入力と出力を記録する
        generation.update_trace(
            input= question,
            output=result,
        )

        return result

dataset = langfuse.get_dataset(name=dataset_name) # 用意済みのデータセットを取得する

for item in dataset.items:

    # item.run() コンテキストマネージャを使う
    with item.run(
        run_name=current_run_name,
        run_metadata={"model_provider": "Hugging Face", "temperature_setting": 0.7},
        run_description="Evaluation run for GSM8K dataset"
    ) as root_span: # root_span は、このアイテムと実行に対する新しいトレースのルートスパン
        # このブロック内の後続の langfuse 操作はすべてこのトレースに属する

        # アプリケーションのロジックを呼び出す
        generated_answer = run_smolagent(question=item.input["text"])

        print(item.input)

異なる次の要素で、このプロセスを繰り返すことができます。 - モデル（OpenAI GPT、ローカル LLM など） - ツール（検索あり vs. 検索なし） - プロンプト（異なるシステムメッセージ）

その後、オブザーバビリティツールで並べて比較できます。
