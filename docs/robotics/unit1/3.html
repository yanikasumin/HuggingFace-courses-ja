LeRobotDataset

LeRobotDataset は、ロボット学習研究に特有のニーズに応えるために設計された、標準化されたデータセット形式です。このセクションでは、LeRobotDataset がどのような問題を解決するのか、どう構成されているのか、データを読み込む際に最初に何を確認すればよいのかを説明します。

この形式を使うと、センサーやモーターの計測値、複数のカメラ映像、遠隔操作の状態など、異なる種類のロボティクスデータを統一的かつ簡単に扱えます。また、LeRobotDataset は収集したデータに関する基本情報も保存します。具体的には、タスクの説明文、使用したロボットの種類、画像データとロボットの状態データそれぞれの記録頻度（fps）、使用したカメラの種類・解像度・フレームレートなどです。

💡 ヒント

なぜ専用の形式なのか？ 従来の ML データセット（ImageNet のようなもの）は単純です。画像1枚にラベル1つです。しかしロボティクスデータは、はるかに複雑です。 - マルチモーダル: 画像＋センサーの読み取り値＋行動が、すべて同期している - 時系列: 観測と行動が時間の経過に沿って順番に記録され、前後のデータが密接に関連している - エピソード単位: データは軌跡／エピソードごとに整理される - 高次元: 複数のカメラ視点（つまり複数の画像）、関節の状態、力など

LeRobotDataset は、この複雑さをすべてシームレスに処理します！

LeRobotDataset は、マルチモーダルな時系列データを扱う統一インターフェースを提供し、PyTorch と Hugging Face のエコシステムとシームレスに連携します。

LeRobotDataset は拡張やカスタマイズが可能で、LeRobot で公開されている、さまざまな種類のロボットのデータにすでに対応しています。その対象は、SO-100 や ALOHA-2 などのマニピュレータから、ヒューマノイドの腕や手、シミュレーションで生成されたデータセット、さらには自動運転のデータまで多岐にわたります。

この形式は、効率よくモデルを訓練でき、さまざまなデータ型にも柔軟に対応できるよう設計されており、再現性と使いやすさの向上にも役立ちます。

データセットクラスの設計

データセットクラスの設計方針について詳しく知りたい場合は、こちら をご覧ください。 LeRobotDataset の設計上の重要な特徴は、内部のデータ保存方式と、ユーザーが利用する API を分離していることです。これにより、データを効率よく保存しながら、ユーザーには直感的でそのまま利用できる形式で提供できます。

これは2つの層に分けて考えると分かりやすいでしょう。一つは高速処理と大規模データへの対応を重視したコンパクトなディスク上の保存構造、もう一つは訓練にすぐ使えるテンソルを返す、シンプルで使いやすい Python インターフェースです。

データセットは常に、3つの主要な構成要素に整理されます。

  • 表形式データ: 関節の状態や行動など、低次元で高頻度に記録されるデータは、メモリマップを利用できる効率的なファイル形式で保存されます。通常、こうしたデータの処理は Hugging Face の実績ある datasets ライブラリに任せることで、メモリ使用量を抑えながら高速にアクセスできます。
  • 視覚データ: 大量のカメラデータを効率よく扱うため、各フレームを連結し、MP4 形式の動画として保存します。同じエピソードのフレームは必ず同一の動画にまとめ、動画ファイルはカメラごとに整理します。さらに、ファイルシステムへの負荷を抑えるため、同じカメラから得られた動画も複数のサブディレクトリに分けて保存します。
  • メタデータ: データセットの構造を記述する JSON ファイル群です。表形式データと視覚データを関連付ける、リレーショナルデータベースのような役割を果たします。メタデータには、各特徴のスキーマ、フレームレート、正規化に使う統計量、エピソードの開始位置と終了位置などが記録されます。

ディスク上のデータセットを見るときは、この3つの分類を意識してください。目にするもののほぼすべては、この3つで説明できます。

数百万もの軌跡（個々のカメラフレームに換算すると数億から数十億）を含む大規模なデータセットにも対応できるよう、異なるエピソードのデータを共通の上位構造にまとめて保存します。

具体的には、1つのデータファイル（parquet 形式）や動画ファイル（MP4 形式）に、複数のエピソードをまとめて保存することがあります。これによりファイル数を減らし、I/O を高速化できます。一方、各エピソードの開始位置と終了位置を把握するには、メタデータを参照する必要があります。つまり、メタデータが各エピソードの保存場所を示す「地図」の役割を果たします。これは、リレーショナルデータベースで共通のキーを使い、複数のテーブルに分かれた情報を関連付けて取得する仕組みに似ています。

LeRobotDataset のディレクトリ構造は、例えば次のようになります。

  • meta/info.json: 中心となるメタデータファイルです。完全なデータセットスキーマを含み、すべての特徴（例: observation.state、action）、その形状とデータ型を定義します。また、データセットの秒間フレーム数（fps）、キャプチャ時点の LeRobot のバージョン、データファイルや動画ファイルの場所を特定するためのパステンプレートといった、重要な情報も保持します。
  • meta/stats.json: データセット全体にわたる各特徴の集約統計（平均、標準偏差、最小値、最大値）を保持するファイルです。ほとんどのポリシーモデルのデータ正規化に使われ、dataset.meta.stats を介して外部からもアクセスできます。
  • meta/tasks.jsonl: 自然言語のタスク説明から整数のタスクインデックスへの対応付けを含むファイルです。タスク条件付きのポリシー訓練に役立ちます。
  • meta/episodes/*: このディレクトリには、各エピソードの長さ、対応するタスク、データセット内での保存位置を示すポインタなど、エピソードごとのメタデータが格納されます。大規模なデータセットにも対応できるよう、これらの情報は1つの巨大な JSON ファイルにまとめず、複数のファイルに分けて保存されます。
  • data/*: 各フレームに対応する主要な表形式データが、メモリマップを使って高速にアクセスできる parquet ファイルに保存されます。処理効率を高め、大規模なデータセットにも対応できるよう、複数のエピソードのデータを連結して大きなファイルにまとめます。また、各ディレクトリにファイルが集中しすぎないよう、複数のサブディレクトリに分けて配置します。通常、1つのファイルには複数のエピソードのデータが含まれます。
  • videos/*: 視覚的な観測データを記録したすべての MP4 動画ファイルが格納されます。data/ ディレクトリと同様に、複数のエピソードの映像を連結し、1つの MP4 ファイルにまとめます。これによりデータセット内のファイル数を大幅に減らせるため、一般的なファイルシステムでも効率よく管理できます。

読み方ガイド: まず meta/info.json でスキーマと fps を確認し、次に meta/stats.json で正規化に使う統計量を調べます。最後に data/ と videos/ のファイルをそれぞれ1つずつ開き、メタデータと実際のデータがどのように対応しているかを確かめてみてください。

💡 ヒント

保存の効率: エピソードをより大きなファイルに連結することで、LeRobotDataset はファイルシステムを遅くしうる「小さなファイルの問題」を避けます。100万エピソードのデータセットでも、ディスク上の実ファイルは数百程度かもしれません！

補足: メタデータファイルはデータベースのインデックスのように働くため、動画ファイル全体を読み込まなくても、特定のエピソードへ高速にアクセスできます。
