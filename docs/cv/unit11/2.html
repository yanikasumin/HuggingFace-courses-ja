ゼロショット学習

前の章でゼロショット学習の概要を紹介しました。ここでは、ゼロショット学習（ZSL）について更に詳しく説明します。この章で学ぶ内容は次の通りです。 - 様々な種類の ZSL の定義と、それらの違い。
- 意味埋め込み（semantic embeddings）を用いる ZSL の詳しい例 [1]。

ゼロショット学習と一般化ゼロショット学習の違い

ゼロショット学習と一般化ゼロショット学習（GZSL）は、画像分類モデルが訓練に含まれていないラベルを分類しなければならない機械学習アルゴリズムの種類に属します。ZSL と GZSL は非常によく似ており、主な違いはモデルの評価方法にあります [2]。

ZSL では、未知のクラスの画像をどれだけ正しく分類出来るかだけを評価します。その為、テストデータセットには未知のクラスの画像しか含まれません。

一方、GZSL では、既知のクラスと未知のクラスの両方の画像でモデルを評価します。こちらの方が、実際の利用場面に近い条件です。GZSL では、入力画像が既知のクラスに属するのか、それとも新しいクラスに属するのかも判断しなければならない為、一般に ZSL より難しくなります。

帰納的ゼロショット学習とトランスダクティブゼロショット学習の違い

訓練データの種類に基づいて、ゼロショット学習には2つの種類が有ります。

帰納的（inductive）ZSL では、既知のクラスだけを含むデータセットでモデルを訓練し、未知のクラスのデータには一切アクセスしません。訓練データから共通するパターンを学び、それを未知のクラスの画像の分類にも応用出来るようにします。この方法では、訓練時に既知のクラスと未知のクラスのデータを明確に分け、訓練データから学んだ知識を未知のクラスにも応用出来るかを重視します。

トランスダクティブ（transductive）ZSL では、訓練時に未知のクラスについての情報も一部利用出来ます。通常は、未知のクラスの属性や、ラベルの付いていないサンプルを使用します。但し、サンプルの正解ラベルは使用しません。こうした未知のデータの構造に関する追加情報を活用することで、より汎化性能の高いモデルを訓練します。

次のセクションでは、Google による古典的な研究論文 [1] の主要な考え方をもとに、帰納的 ZSL の例を紹介します。

意味埋め込みを使ったゼロショット学習の例

前の章で説明したように、うまく機能する ZSL モデルを作るには、画像とクラスラベルだけでは不十分です。画像だけを手がかりに未知のクラスを分類することは、ほぼ不可能です。そこで ZSL では、意味属性や意味埋め込みなどの補助情報を使い、未知のクラスの画像を分類出来るようにします。

詳しい仕組みを説明する前に、まずは意味埋め込みについて簡単に紹介します。

意味埋め込みとは？

意味埋め込み（semantic embeddings）とは、データの意味や解釈に関する情報をベクトルで表したものです。例えば、話し言葉を通じて伝わる情報も意味情報の一種です。意味情報には、単語や文が直接表す意味だけでなく、文脈や文化によって生じる含意も含まれます。

埋め込みとは、意味情報を実数のベクトルに変換する処理のことです。意味埋め込みには、Word2Vec [3] や GloVe [4] のような教師なし機械学習モデルで学習したものがよく使われます。単語、句、文などのテキスト情報は、決められた手順によって数値ベクトルに変換出来ます。これらのベクトルは高次元の空間に配置され、単語どうしの距離や方向が意味の関係を表します。その為、ベクトルに対する数学的な演算を通じて、単語の使われ方や同義語、文脈などを機械が捉えられるようになります。

意味埋め込みによるゼロショット学習の実現

訓練時には、ZSL モデルは、既知のクラスの画像から得た視覚的特徴と、対応する意味埋め込みとの関係を学習します。目標は、画像の視覚的特徴を射影したベクトルと、そのクラスの意味埋め込みとの距離を出来るだけ小さくすることです。こうして、画像と意味情報の対応関係をモデルに学習させます。

モデルは画像の特徴を意味空間に射影する方法を学んでいる為、未知のクラスの画像にも同じ処理を適用出来ます。まず、未知のクラスの画像から特徴を取り出し、意味空間に射影してベクトルを求めます。次に、そのベクトルと未知のクラスの意味埋め込みを比較し、最も近いものを探します。最も近かった意味埋め込みに対応する未知のクラスが、その画像の予測ラベルになります。

まとめると、意味埋め込みは ZSL の中心となる技術であり、モデルが分類出来る対象を広げる役割を果たします。この方法を使えば、ラベル付きデータセットがなくても、現実世界に存在する膨大な数のカテゴリを柔軟且つ効率的に分類出来るようになります。

CLIP との比較

ZSL と CLIP（Contrastive Language–Image Pre-training）[5] には、訓練データに含まれていなかったカテゴリの画像も認識・分類出来るようにするという共通の目標が有ります。但し、CLIP は新しい学習方法と汎化の仕組みを取り入れることで、ZSL の基本原理を大きく発展させ、応用範囲も広げています。

ZSL と CLIP の関係は次のように説明出来ます。

  • ZSL と CLIP はどちらも、訓練時に見たことのないクラスに画像を分類することを目指します。但し、従来の ZSL では、既知のクラスと未知のクラスの違いを埋める為に、予め定義された意味埋め込みや属性に依存することが有ります。一方、CLIP は自然言語の記述から直接学習する為、タスクごとに専用の埋め込みを用意しなくても、幅広いタスクに汎化出来ます。

  • CLIP は、テキストと画像の両方から学習するマルチモーダル学習の代表例です。分類性能を高める為に補助情報を使うという点で、ZSL と共通しています。CLIP はこの考え方を更に発展させ、生のテキストと画像から直接学習することで、画像の内容と言語による説明との関係を理解し、表現出来るようにしています。

ゼロショット学習の評価用データセット

ZSL では毎年新しい手法が提案されていますが、研究によって評価方法が異なる為、どの手法が優れているのかを判断するのは簡単ではありません。その為、様々な ZSL 手法を比較する際には、共通の評価方法と標準化されたデータセットを使うことが望まれます。従来の ZSL 手法を比較した研究は [6] で紹介されています。

ZSL の評価によく使われるデータセットは次の通りです。

  • Animal with Attributes (AwA)

転移学習アルゴリズム、特に属性ベースの分類をベンチマークする為のデータセット [7]。50の動物クラスの画像30475枚で構成され、各画像に6種類の特徴表現が付いています。

  • Caltech-UCSD-Birds-200-2011（CUB）

鳥を細かい種類に分類する為のデータセットです。200の鳥のサブカテゴリに属する画像11788枚を含みます。各画像には、1つのサブカテゴリラベル、15の部位の位置情報、312のバイナリ属性、1つのバウンディングボックスが付いています。また、各画像について10文の説明文が Amazon の Mechanical Turk を通じて収集されています。これらの説明文は、サブカテゴリを特定出来る情報を含まないよう、注意深く作られています。

  • Sun database（SUN）

最初の大規模なシーン属性データベース。このデータセットは、899カテゴリの画像130519枚で構成され、高レベルのシーン理解ときめ細かいシーン認識に使えます。

  • Attribute Pascal and Yahoo dataset（aPY）

動物、物体、乗り物という3つの大きなカテゴリをもとに、大まかに分類したデータセットです。これらは更に合計32のサブカテゴリに分けられ、15339枚の画像が含まれています。

  • ILSVRC2012/ILSVRC2010（ImNet-2）

ImageNet Large Scale Visual Recognition Challenge（ILSVRC）は、大規模な物体検出や画像分類のタスクにおいて、各種アルゴリズムの性能を評価する為のものです [8]。
