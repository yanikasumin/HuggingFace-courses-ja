Using a 3D Renderer to Generate Synthetic Data

合成訓練データとして使うコンピュータ生成画像を作るとき、理想的には、画像が可能な限りリアルに見えることが望ましいです。 Blender Cycles や Unity のような物理ベースレンダラー（PBR）は、非常にリアルで、現実世界とまったく同じように見え、感じられる画像を作る助けとなります。

つやのあるリンゴの画像を作っていると想像してみてください。そのリンゴに色を付けるとき、リアルに見せたいですよね？ そこで登場するのが PBR と呼ばれるものです。

では、分解して説明しましょう。

色と光（Colors and Light）:

  • 光が物体に当たると、さまざまな方法で物体と相互作用します。PBR はこの相互作用を解明し、シミュレーションしようとするものです。
  • 光がリンゴにどう当たるか考えてみてください。光が直接当たる部分は明るくなり、光が遮られたり届きにくかったりする部分は暗くなります。

素材（Materials）:

  • 素材によって光への反応は異なります。たとえば、つやのある金属の表面は、柔らかくマットな布よりも光を強く反射します。
  • PBR は物体の素材を考慮します。そのため、金属の花瓶をレンダリングすれば、ふわふわのテディベアとは異なる光の反射をします。

テクスチャ（Textures）:

  • PBR はテクスチャを使って、物体表面の凹凸、傷、小さな溝などの細部を加えます。現実世界では完全に滑らかなものはほとんどないため、これによって物がよりリアルに見えます。

リアリズム（Realism）:

  • PBR は、物を可能な限り現実に近づけることを目指します。そのために、現実における光の振る舞い、素材ごとに異なる光との相互作用の仕方、表面の小さな不完全さを考慮します。

光の層（Layers of Light）:

  • コップの水を見ていると想像してみてください。PBR は、光が水をどのように通過し、見えるものをどのように歪めるかをシミュレーションしようとします。
  • 光が物体の各部分と相互作用する多層のあり方を考慮することで、レンダリングされた画像をよりリアルにします。

PBR はワークフローもシンプルにします。適切な見た目を得るために多くのパラメータを手作業で調整する代わりに、 標準化された素材とライティングモデルのセットを使えます。 これにより、プロセスはより直感的で使いやすくなります。

では、コンピュータビジョンで使われるような AI モデルの訓練について考えてみましょう。 コンピュータに画像内の物体を認識するよう教えるなら、現実世界のシナリオを忠実に模倣した 多様な画像セットがあると有益です。PBR は、コンピュータビジョンモデルの訓練に効果的に使えるほど リアルに見える合成データの生成を助けます。

PBR に使える 3D レンダリングエンジンはいくつかあり、Blender Cycles や Unity などがあります。ここでは、オープンソースでリソースも豊富な Blender に焦点を当てます。

Blender

Blender は、アニメーション映画、視覚効果、アート、3D ゲームなどの制作に使われる、強力なオープンソースの 3D コンピュータグラフィックスソフトウェアです。 幅広い機能を備えており、アーティスト、アニメーター、開発者にとって多用途なツールとなっています。 まずは、象の合成画像をレンダリングする基本的な例を見ていきましょう。

必須の手順は次のとおりです。

  • 象のモデルを作成します。下に示したものは、フォトグラメトリを用いて Metascan アプリで作成されました。 フォトグラメトリは、通常の写真を 3D モデルに変換する方法です。おもちゃをさまざまな角度からたくさん写真に撮り、 その写真を使ってコンピュータ版を作るようなものです。
  • 背景を作成します。これは複数ステップのプロセスでした。詳しい説明はこちら を参照してください。
  • ライティングとカメラの位置を調整します。
  • 象がフレーム（つまりカメラの視界）に収まるよう、象の位置と回転を修正します。

Blender で生成された象の画像がこちらです。

完全なフォトリアリズムではありませんが、おそらく象の個体数をモニタリングするモデルを訓練するには十分に近いでしょう。もちろん、そのためには 合成象画像の大規模なデータセットを作成する必要があります！Blender の Python 環境 bpy を使えば、 象の位置と回転をランダム化しながら大量の画像をレンダリングできます。 セグメンテーション、深度、法線、姿勢推定に役立つスクリプトを使うこともできます。

素晴らしい！では、どうやって始めればよいでしょうか？

残念ながら、Blender にはかなり急な学習曲線があります。どのステップもそれほど複雑ではありませんが、 これらすべてを解明しようとせずにデータセットをレンダリングできたら素敵だと思いませんか？ 幸いなことに、BlenderProc というライブラリがあり、リアルな合成データをレンダリングするために必要なスクリプトがすべて揃っていて、 アノテーションも含め、Blender の上に構築されています。

BlenderProc

BlenderProc のパイプラインは、Denninger らによる BlenderProc で紹介されたもので、Blender の上に構築されたモジュール式パイプラインです。 セグメンテーション、深度、法線、姿勢推定など、さまざまなユースケースの画像生成に使えます。

畳み込みニューラルネットワークの訓練用に、リアルに見える画像を生成する助けとなるよう、特に作られています。
合成データ生成に最適な選択肢となる性質は次のとおりです。

  • Procedural Generation: 手続き型の手法を用いて、バリエーションのある複雑な 3D シーンを自動で作成できます。
  • Simulation: 物理シミュレーションを含むシミュレーションの統合をサポートし、リアリズムを高められます。
  • Large-Scale Generation: 大規模なシーン生成を効率的に扱えるよう設計されており、多様なアプリケーションに適しています。
  • Automation and Scalability:
  • Scripting: Python スクリプトを使って生成プロセスを自動化し、BlenderProc を特定のニーズに合わせて調整したり、パラメータを設定したりできます。
  • Parallel Processing: 並列処理をサポートしてスケーラビリティを確保し、大量のシーンを効率的に生成できます。

BlenderProc は pip でインストールできます。

pip install blenderProc

あるいは、公式の BlenderProc リポジトリ を Git でクローンすることもできます。

git clone https://github.com/DLR-RM/BlenderProc

BlenderProc は Blender の Python 環境（bpy）の中で実行しなければなりません。Blender API にアクセスする唯一の方法だからです。

blenderproc run <your_python_script>
